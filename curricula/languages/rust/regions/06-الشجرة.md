# الإقليم ٠٦ — الشجرة

> البذرة الثالثة والأخيرة من الإقليم ٠١: `12 + 30 * 2` تعطي **٨٤**.
>
> وهي ليست خطأ برمجةٍ يُصلَح بحارس. `Vec<Token>` تسلسلٌ مسطّح، **والأسبقية علاقةُ
> تعشيش**. فالمطلوب شكلٌ يحملها.
>
> وهنا تقابل أوّل حاجزٍ حقيقيّ في نظام أنواع Rust: **النوع الذي يحوي نفسه**.

## البذرة: نوعٌ يحوي نفسه

اكتب الشجرة كما تُكتب في أي لغةٍ ذات جامعٍ للقمامة:

```rust
enum Expr {
    Num(i64),
    Add(Expr, Expr),
    Mul(Expr, Expr),
}
```

<!-- err: E0072 -->

```
error[E0072]: recursive type `Expr` has infinite size
 --> e01.rs:1:1
  |
1 | enum Expr {
  | ^^^^^^^^^
2 |     Num(i64),
3 |     Add(Expr, Expr),
  |         ---- recursive without indirection
  |
help: insert some indirection (e.g., a `Box`, `Rc`, or `&`) to break the cycle
  |
3 |     Add(Box<Expr>, Expr),
  |         ++++    +
```

**«infinite size»** حرفيّة: حجم `Expr` = ٨ + حجم `Expr` + حجم `Expr`. معادلةٌ بلا
حلٍّ منتهٍ.

وفي C تكتب `struct Expr { struct Expr *l; }` ولا يشتكي أحد — لأنك كتبت **مؤشّراً**
بيدك. **وRust تطلب منك الشيء نفسه**، وتسمّي ما تريده: `Box` أو `Rc` أو `&`.

## `Box` — مؤشّرٌ يملك

`Box<T>` مؤشّرٌ بحجم كلمةٍ إلى قيمةٍ في الكومة، **يحرّرها حين يموت**:

```rust
use std::mem::size_of;

#[derive(Debug)]
enum Expr {
    Num(i64),
    Add(Box<Expr>, Box<Expr>),
    Mul(Box<Expr>, Box<Expr>),
}

fn leaves(e: &Expr) -> i64 {
    match e {
        Expr::Num(n) => *n,
        Expr::Add(a, b) | Expr::Mul(a, b) => leaves(a) + leaves(b),
    }
}

fn main() {
    println!("i64               : {}", size_of::<i64>());
    println!("Box<Expr>         : {}", size_of::<Box<Expr>>());
    println!("Option<Box<Expr>> : {}", size_of::<Option<Box<Expr>>>());
    println!("Expr              : {}", size_of::<Expr>());

    let e = Expr::Add(
        Box::new(Expr::Num(12)),
        Box::new(Expr::Mul(Box::new(Expr::Num(30)), Box::new(Expr::Num(2)))),
    );
    println!("{e:?}  ·  مجموع أوراقها {}", leaves(&e));
}
```

<!-- out -->

```
i64               : 8
Box<Expr>         : 8
Option<Box<Expr>> : 8
Expr              : 24
Add(Num(12), Mul(Num(30), Num(2)))  ·  مجموع أوراقها 44
```

**والسطر الثالث هو المكسب المخبّأ:** `Option<Box<Expr>>` ثمانٍ كذلك. `Box` مضمونٌ
ألّا يكون صفراً، **فالصفر مساحةٌ شاغرة يسكنها `None`**.

فقائمةٌ مربوطة في Rust `Option<Box<Node>>` بحجم مؤشّرٍ واحد — كـ`NULL` في C،
**ومطابقتها إلزامية.**

## الشجرة تحمل الأسبقية

نفس الأرقام، وشجرتان:

<!-- part: 06-two-trees -->

```rust
fn eval(e: &Expr) -> i64 {
    match e {
        Expr::Num(n) => *n,
        Expr::Add(a, b) => eval(a) + eval(b),
        Expr::Mul(a, b) => eval(a) * eval(b),
    }
}

fn main() {
    // 12 + (30 * 2)
    let tree = Expr::Add(
        Box::new(Expr::Num(12)),
        Box::new(Expr::Mul(Box::new(Expr::Num(30)), Box::new(Expr::Num(2)))),
    );
    println!("{tree:?}");
    println!("= {}", eval(&tree));

    // (12 + 30) * 2  — ما كان يفعله المفكِّك المسطّح
    let flat = Expr::Mul(
        Box::new(Expr::Add(Box::new(Expr::Num(12)), Box::new(Expr::Num(30)))),
        Box::new(Expr::Num(2)),
    );
    println!("= {}", eval(&flat));
}
```

توقّع الرقمين.

المخرَج:

```
Add(Num(12), Mul(Num(30), Num(2)))
= 72
= 84
```

**٨٤ لم تكن خطأ حساب.** كانت الشجرة الثانية بالضبط — والمفكِّك المسطّح كان يبنيها
ضمناً وهو يمشي من اليسار.

**والأسبقية الآن في الشكل.** لا جدول أولويات ولا عدّاد أقواس: من بنى الشجرة
صحيحةً حصل على الجواب صحيحاً.

## المطابقة تعبر الصندوق

`Expr::Add(a, b)` تعطيك `&Box<Expr>`، و`eval` تطلب `&Expr`. فلماذا تعمل؟

<!-- part: 06-deref -->

```rust
use std::mem::size_of_val;

fn main() {
    let t = Expr::Add(Box::new(Expr::Num(12)), Box::new(Expr::Num(30)));

    if let Expr::Add(a, _) = &t {
        let as_box: &Box<Expr> = a;
        let as_expr: &Expr = a;
        println!("&Box<Expr> = {} بايت", size_of_val(as_box));
        println!("&Expr      = {} بايت", size_of_val(as_expr));
    }

    let boxed = Box::new(Expr::Num(7));
    let inner: Expr = *boxed;

    println!("{inner:?}  ·  {}", eval(&t));
}
```

<!-- out: هنا `Expr` بشكلين اثنين فقط، فحجمه ١٦ -->

```
&Box<Expr> = 8 بايت
&Expr      = 16 بايت
Num(7)  ·  42
```

**الاسم الواحد قبل نوعين**، والرقمان يثبتان أنهما نوعان: ثمانٍ للصندوق نفسه،
وستّ عشرة لما فيه.

اسمُ هذا **إكراه فكّ الإشارة** (deref coercion): حيث يُنتظر `&U` ويوجد `&T`
و`T: Deref<Target=U>`، يُدخِل المترجم `*` عنك. ولهذا تعمل طرق `str` على `String`
كذلك.

**و`*boxed` تنقل القيمة من الكومة إلى المكدّس** وتحرّر الصندوق. الصندوق يملك، فله
أن يعطي.

## المُحلِّل: القاعدة تصير دالّة

كل قاعدةٍ في القواعد النحوية دالّةٌ تستدعي التي تحتها:

<!-- part -->

```rust
impl<'a> Parser<'a> {
    /// تعبير := حدّ  { '+' حدّ }
    fn expr(&mut self) -> Expr {
        let mut left = self.term();
        while let Some(Token::Sym('+')) = self.peek() {
            self.at += 1;
            let right = self.term();
            left = Expr::Add(Box::new(left), Box::new(right));
        }
        left
    }

    /// حدّ := عامل { '*' عامل }
    fn term(&mut self) -> Expr {
        let mut left = self.factor();
        while let Some(Token::Sym('*')) = self.peek() {
            self.at += 1;
            let right = self.factor();
            left = Expr::Mul(Box::new(left), Box::new(right));
        }
        left
    }
}
```

**الأسبقية مكتوبةٌ في من يستدعي من.** `expr` تستدعي `term`، فيبتلع `term` كل
الضروب قبل أن يرى `expr` العلامة `+`.

فلو عكستَ الاستدعاءين لعكستَ الأسبقية. **ولا ثالث لهما**: لا جدول ولا رقم أولوية —
شكلُ الاستدعاء هو الجدول.

## الملفّ كاملاً: ٧٢

<!-- part: 06-parser -->

```rust
fn main() {
    let toks = vec![
        Token::Num(12), Token::Sym('+'),
        Token::Num(30), Token::Sym('*'), Token::Num(2),
    ];

    let mut p = Parser { toks: &toks, at: 0 };
    let tree = p.expr();

    println!("{tree:?}");
    println!("12 + 30 * 2 = {}", eval(&tree));
}
```

المخرَج:

```
Add(Num(12), Mul(Num(30), Num(2)))
12 + 30 * 2 = 72
```

**والبذرة الثالثة مُغلَقة.** والثلاث التي فُتحت في الإقليم ٠١ صارت كلّها مغلقة:
النصّ الذي يجب أن يبقى، والذعر الذي يكذب، والأسبقية التي لا تحملها البنية.

## العمق يقتل المكدّس

`Drop` تنزل في الشجرة **بالاستدعاء الذاتيّ**. فماذا لو كانت الشجرة قائمةً بطول
مئتي ألف؟

```rust
struct Node {
    v: i64,
    next: Option<Box<Node>>,
}

struct List {
    head: Option<Box<Node>>,
}

fn build(n: usize) -> List {
    let mut head = None;
    for i in 0..n {
        head = Some(Box::new(Node { v: i as i64, next: head }));
    }
    List { head }
}

fn sum(l: &List) -> i64 {
    let mut acc = 0;
    let mut cur = l.head.as_deref();
    while let Some(n) = cur {
        acc += n.v;
        cur = n.next.as_deref();
    }
    acc
}

fn main() {
    let n = 200_000;
    let l = build(n);
    println!("بُنيت {n} عقدة، ومجموعها {}", sum(&l));
    drop(l);
    println!("حُرِّرت");
}
```

<!-- out: الخروج بإشارةٍ لا برسالة ذعرٍ عادية -->

```
بُنيت 200000 عقدة، ومجموعها 19999900000

thread 'main' has overflowed its stack
fatal runtime error: stack overflow, aborting
```

**البناء نجح، والجمع نجح، والتحرير سقط.** `drop` للعقدة الأولى تستدعي `drop`
للثانية، فالثالثة… مئتا ألف إطارٍ على مكدّسٍ حجمه ثمانية ميغابايت.

وهذا أثرٌ لا تراه في لغةٍ ذات جامعٍ للقمامة، لأن التحرير هناك ليس استدعاءً ذاتياً
عند نقطةٍ تعرفها. **والسطر «حُرِّرت» لم يُطبع**، فالانهيار وقع داخل `drop(l)`.

## و`Drop` مكتوبٌ بيدك يحلّها

اكتب التحرير حلقةً بدل استدعاءٍ ذاتيّ:

<!-- part: 06-iterative-drop -->

```rust
impl Drop for List {
    fn drop(&mut self) {
        let mut cur = self.head.take();
        while let Some(mut n) = cur {
            cur = n.next.take();
        }
    }
}
```

<!-- out: نفس البرنامج، ومعه هذا التنفيذ -->

```
بُنيت 200000 عقدة، وأوّلها 199999
حُرِّرت
```

`take` تأخذ ما في `Option` وتترك `None` — وهي `mem::replace` التي رأيتها في إقليم
المِلكية بثوبٍ آخر.

**والحيلة أن كل عقدةٍ تُفصَل قبل أن تموت**: `n.next.take()` تجعل `n` بلا ابن،
فيكون تحريرها ورقةً لا شجرة. والحلقة تنزل بمتغيّرٍ واحد بدل إطارٍ لكل عقدة.

## ولا تُخرِج قيمةً من نوعٍ له `Drop`

المحاولة الأولى الطبيعية تصطدم بقاعدةٍ لم تقابلها بعد:

```rust
impl Drop for List {
    fn drop(&mut self) {
        let mut cur = mem::replace(self, List::Nil);
        while let List::Cons(_, mut next) = cur {
            cur = mem::replace(&mut *next, List::Nil);
        }
    }
}
```

<!-- err: E0509 -->

```
error[E0509]: cannot move out of type `List`, which implements the `Drop` trait
  --> e06.rs:11:45
   |
11 |         while let List::Cons(_, mut next) = cur {
   |                                 --------    ^^^ cannot move out of here
   |                                 |
   |                                 data moved here because `next` has type `Box<List>`, which does not implement the `Copy` trait
```

**السبب مباشر:** `Drop::drop` ستعمل على القيمة كاملة، فلا يجوز أن تُنتزع منها
قطعة. والنوع الذي له `Drop` يفقد النقل الجزئيّ الذي رأيته في إقليم المِلكية.

ولهذا فُصلت `Node` عن `List` في الحلّ أعلاه: **`List` هي التي تنفّذ `Drop`،
و`Node` نوعٌ عاديّ يُنقَل منه بحرّية.**

## الفهرس بدل المؤشّر

`Box` ليس التمثيل الوحيد. الشجرة تسكن متّجهاً واحداً، والأبناء **أرقام**:

<!-- part: 06-arena -->

```rust
#[derive(Clone, Copy)]
enum Node {
    Num(i64),
    Add(u32, u32),
    Mul(u32, u32),
}

struct Arena(Vec<Node>);

impl Arena {
    fn push(&mut self, n: Node) -> u32 {
        self.0.push(n);
        (self.0.len() - 1) as u32
    }
    fn eval(&self, i: u32) -> i64 {
        match self.0[i as usize] {
            Node::Num(n) => n,
            Node::Add(a, b) => self.eval(a) + self.eval(b),
            Node::Mul(a, b) => self.eval(a) * self.eval(b),
        }
    }
}
```

<!-- out: بمخصِّصٍ عادّ — انظر `appendix/counting-allocator.md` -->

```
Box   : 4 تخصيصاً  ·  = 72
Arena : 1 تخصيصاً  ·  = 72
حجم Node = 16
```

**أربعةٌ مقابل واحد** على شجرةٍ من خمس عقد. وعلى ملفٍّ فيه مليون عقدة يصير الفرق
مليون استدعاءٍ للمخصِّص، وذاكرةً متناثرة بدل شريطٍ متّصل.

| | الصندوق | الساحة |
|---|---|---|
| التخصيص | لكل عقدة | لكل نموّ متّجه |
| الموقع | متناثر | متجاور — ودّيٌّ للمخبأ |
| `Copy` | ممنوع | `Node` بحجم ١٦ ويُنسخ |
| التحرير | استدعاءٌ ذاتيّ | `Vec` واحدة |
| الثمن | — | **الفهرس لا يحرسه المترجم** |

**والثمن في السطر الأخير:** `u32` قد تشير إلى عقدةٍ خاطئة أو خارج الحدّ، والمترجم
لا يعرف. صار الأمان مسؤوليّتك — وهو نفس ما تفعله في C، **بفارقٍ واحد**: خروجُك
عن حدّ `Vec` يذعر ولا يقرأ ذاكرةً غريبة.

## بذرة

المفكِّك صار كاملاً: يقرأ، ويحلّل، ويحسب، ويفشل بأدب.

وفيه الآن شيءٌ يتكرّر: `eval` تطابق على `Expr`، وطباعته تحتاج `Debug`، وموازنته
تحتاج `PartialEq`. **وكلّها اشتُقّت بسطرٍ واحد `#[derive(...)]`** — ولم تسأل كيف.

وأثقل من ذلك: `Iterator` أعطت المفكِّك `for` و`collect` و`map` مجّاناً في الإقليم
٠١، **و`Display` جعلت خطأك يُطبَع بلغتك في الإقليم ٠٥**.

فما هذه الأشياء؟ **الإقليم القادم عن السمة** — العقد الذي تعلنه أنت، وكيف يختار
المترجم بينه وبين نظيره: مرّةً وقت الترجمة بلا كلفة، ومرّةً وقت التشغيل بجدولٍ في
الكلمة الثانية.
