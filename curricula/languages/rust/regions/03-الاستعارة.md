# الإقليم ٠٣ — الاستعارة

> البذرة التي خرجتَ بها: `next` في مفكِّكك تأخذ `&mut self` وتحرّك `pos`. فمن
> يجوز أن ينظر إلى النصّ في تلك اللحظة؟
>
> هنا تفكّك البديهية الثانية: **كاتبٌ واحد أو قرّاءٌ كثيرون**. وسترى أنها ليست
> قيداً على الذاكرة وحدها — هي التي تمنع منطقاً خاطئاً كنتَ تكتبه في C ويعمل.

## البذرة: أن تقرأ ما يتغيّر

حلقةٌ تمرّ على الرموز وتضيف واحداً عند العامل. اكتبها كما تُكتب في أي لغة:

```rust
fn main() {
    let mut tokens = vec!["12", "+", "30"];
    for t in &tokens {
        if *t == "+" {
            tokens.push("!");
        }
    }
    println!("{tokens:?}");
}
```

<!-- err: E0502 -->

```
error[E0502]: cannot borrow `tokens` as mutable because it is also borrowed as immutable
 --> b01.rs:5:13
  |
3 |     for t in &tokens {
  |              -------
  |              |
  |              immutable borrow occurs here
  |              immutable borrow later used here
4 |         if *t == "+" {
5 |             tokens.push("!");
  |             ^^^^^^^^^^^^^^^^ mutable borrow occurs here
```

في C++ يُترجَم نظيرها، ثم تُبطِل `push_back` المكرِّرات إن أعادت التخصيص فيصير
`t` مؤشّراً إلى ذاكرةٍ محرَّرة. وفي Java يُترجَم ويُلقي
`ConcurrentModificationException` **عند التشغيل**.

**والفرق ليس في الكشف — الثلاثة تكشف. الفرق في متى، وبأي ثمنٍ في وقت التشغيل.**

## القاعدة، بحرفها

مرجعان قابلان للتعديل إلى شيءٍ واحد:

```rust
fn main() {
    let mut src = String::from("12 + 30");
    let a = &mut src;
    let b = &mut src;
    a.push('!');
    b.push('?');
}
```

<!-- err: E0499 -->

```
error[E0499]: cannot borrow `src` as mutable more than once at a time
 --> b02.rs:4:13
  |
3 |     let a = &mut src;
  |             -------- first mutable borrow occurs here
4 |     let b = &mut src;
  |             ^^^^^^^^ second mutable borrow occurs here
5 |     a.push('!');
  |     - first borrow later used here
```

القاعدة سطران: **أي عددٍ من `&T`، أو `&mut T` واحدة، ولا يجتمعان.**

**وهذا هو تعريف سباق البيانات بالضبط** — كاتبٌ مع أيٍّ آخر على موضعٍ واحد. فمُنع
السباق في الكود ذي الخيط الواحد قبل أن تسمع بالخيوط. (وسترى في إقليم الخيوط أن
هذه القاعدة نفسها هي كل ما احتاجته اللغة.)

## آخر استعمال، لا آخر قوس

توقّع: هل يُترجَم هذا؟

```rust
fn main() {
    let mut src = String::from("12 + 30");

    let view = &src;
    println!("قبل: {view}");

    src.push_str(" * 2");
    println!("بعد: {src}");
}
```

<!-- out -->

```
قبل: 12 + 30
بعد: 12 + 30 * 2
```

`view` استعارةُ قراءة، و`push_str` تعديل. ومع ذلك مرّ.

**لأن الاستعارة تنتهي عند آخر استعمالٍ لها**، لا عند نهاية النطاق. و`view`
استُعمل آخر مرّةٍ في `println!` الأولى، فمات هناك في حساب المترجم.

اسمُ هذا `NLL` — أعمارٌ غير معجميّة. وقبله كانت Rust ترفض هذا البرنامج، **وكان
الناس يضيفون أقواساً حول الاستعارات ليقتلوها**.

## وحرّك سطراً واحداً

نفس المتغيّرات، وترتيبٌ آخر:

```rust
fn main() {
    let mut src = String::from("12 + 30");

    let view = &src;
    src.push_str(" * 2");
    println!("{view}");
}
```

<!-- err: E0502 -->

```
error[E0502]: cannot borrow `src` as mutable because it is also borrowed as immutable
 --> b04.rs:5:5
  |
4 |     let view = &src;
  |                ---- immutable borrow occurs here
5 |     src.push_str(" * 2");
  |     ^^^^^^^^^^^^^^^^^^^^ mutable borrow occurs here
6 |     println!("{view}");
  |                ---- immutable borrow later used here
```

**اقرأ السطر الأخير من الرسالة:** المترجم يشير إلى `println!` — أي إلى **الاستعمال
اللاحق** الذي أبقى الاستعارة حيّة عبر التعديل.

فحين تقابل `E0502` فالسؤال الأوّل: **أين آخر استعمالٍ للمرجع؟** وأكثر ما يُحلّ
منها يُحلّ بتقديم ذلك الاستعمال أو بنسخ ما تحتاجه منه.

## الطريقة تبتلع البنية كلّها

هنا يبدأ الألم الحقيقيّ. مفكِّكٌ يسجّل أطوال الحروف:

```rust
impl Lexer {
    fn rest(&self) -> &str {
        &self.src[self.pos..]
    }

    fn mark_all(&mut self) {
        for c in self.rest().chars() {
            self.seen.push(c.len_utf8());
        }
    }
}
```

<!-- err: E0502 -->

```
error[E0502]: cannot borrow `self.seen` as mutable because it is also borrowed as immutable
  --> b06.rs:14:13
   |
13 |         for c in self.rest().chars() {
   |                  -------------------
   |                  |
   |                  immutable borrow occurs here
   |                  immutable borrow later used here
14 |             self.seen.push(c.len_utf8());
   |             ^^^^^^^^^^^^^^^^^^^^^^^^^^^^ mutable borrow occurs here
```

`rest` تقرأ `self.src` وحدها، و`push` تكتب في `self.seen` وحدها. **وهما حقلان
مختلفان.**

لكن توقيع `rest` يقول `&self` — أي «أستعير البنية كلّها». والمترجم يصدّق التوقيع
ولا يفتح الجسد. **فالحدّ هنا حدُّ الدالّة، وهذا قرارٌ متعمَّد**: لو نظر في الأجساد
لصار كل تغييرٍ في جسد دالّةٍ كسراً محتملاً لمستدعيها.

## التفكيك يفتح البنية

الجواب أن تفتح البنية إلى حقولها، فيرى المترجم أنها منفصلة:

```rust
struct Lexer {
    src: String,
    pos: usize,
    seen: Vec<usize>,
}

impl Lexer {
    fn mark_all(&mut self) {
        let Lexer { src, pos, seen } = self;
        for c in src[*pos..].chars() {
            seen.push(c.len_utf8());
        }
    }
}

fn main() {
    let mut lx = Lexer { src: String::from("سعر 12"), pos: 0, seen: vec![] };
    lx.mark_all();
    println!("{:?}", lx.seen);
}
```

<!-- out: على "سعر 12" -->

```
[2, 2, 2, 1, 1, 1]
```

تفكيك `self` يعطي `src: &String` و`pos: &usize` و`seen: &mut Vec<usize>` —
**ثلاث استعاراتٍ لثلاثة حقول**، لا واحدةً للبنية.

**والاستعارة المجزّأة تعمل داخل الجسد الواحد فقط.** ولهذا يُرى في Rust كثيراً:
دوالُّ حرّة تأخذ الحقول التي تحتاجها بدل طرقٍ تأخذ `&mut self`. وهو أسلوبٌ يبدو
غريباً حتى تعرف من أين جاء.

## الشريحة لا تنقسم بالفهرسة

عنصران من متّجهٍ واحد:

```rust
fn main() {
    let mut v = vec![1, 2, 3, 4];
    let a = &mut v[0];
    let b = &mut v[3];
    *a += 10;
    *b += 10;
}
```

<!-- err: E0499 -->

```
error[E0499]: cannot borrow `v` as mutable more than once at a time
 --> b08.rs:4:18
  |
3 |     let a = &mut v[0];
  |                  - first mutable borrow occurs here
4 |     let b = &mut v[3];
  |                  ^ second mutable borrow occurs here
5 |     *a += 10;
  |     -------- first borrow later used here
  |
  = help: use `.split_at_mut(position)` to obtain two mutable non-overlapping sub-slices
```

`0` و`3` موضعان مختلفان، وأنت تعرف ذلك. **والمترجم لا يعرفه**: الفهرس قيمةٌ في
وقت التشغيل، وإثبات اختلافها يحتاج ما لا يملكه.

**واقرأ سطر `help`:** الرسالة تسمّي لك الدالّة التي تحلّها.

## `split_at_mut` — الحلّ في المكتبة

```rust
fn main() {
    let mut v = vec![1, 2, 3, 4];
    let (left, right) = v.split_at_mut(2);
    left[0] += 10;
    right[1] += 10;
    println!("{left:?} {right:?}");
}
```

<!-- out -->

```
[11, 2] [3, 14]
```

استعارةٌ واحدة دخلت، وشريحتان قابلتان للتعديل خرجتا. **والتوقيع وحده هو الإثبات**:
`fn split_at_mut(&mut self, mid) -> (&mut [T], &mut [T])`.

وداخلها `unsafe`: مؤشّرٌ خام وحسابُ إزاحة. **فالمكتبة أخذت العبء ووقّعت عليه**،
والمستعمل يبقى في الآمن. وهذا هو النمط الذي تراه في كل مكانٍ في `std` — و`unsafe`
كلمةٌ تُفتّش لأنها قليلة.

## ثلاث حلقات، وثلاث قصص

`for` على متّجهٍ ثلاث صور. توقّع الأسطر الأربعة:

```rust
fn main() {
    let mut v = vec![String::from("12"), String::from("30")];

    for t in &v {
        println!("قراءة {t}");
    }

    for t in &mut v {
        t.push('!');
    }

    for t in v {
        println!("مِلكية {t}");
    }
}
```

المخرَج:

```
قراءة 12
قراءة 30
مِلكية 12!
مِلكية 30!
```

`&v` تعطي `&String` — تقرأ. و`&mut v` تعطي `&mut String` — تعدّل في مكانها. و`v`
تعطي `String` — **تأكل المتّجه**، ولا سطر بعدها يستعمله.

**والصورة الثالثة هي التي تفسّر `into_iter`**: نفس السمة، وثلاثة تنفيذاتٍ لها،
والفرق كلّه في نوع العنصر.

## `&mut` ليس `Copy`

المرجع القابل للتعديل ينتقل كما تنتقل `String`:

```rust
fn main() {
    let mut y = 0u64;
    let q = &mut y;
    let p = q;
    bump(p);
    bump(q);
}
```

<!-- err: E0382 -->

```
error[E0382]: borrow of moved value: `q`
  --> b12.rs:17:10
   |
14 |     let q = &mut y;
   |         - move occurs because `q` has type `&mut u64`, which does not implement the `Copy` trait
15 |     let p = q;
   |             - value moved here
16 |     bump(p);
17 |     bump(q);
   |          ^ value borrowed here after move
```

**ولو كان `Copy` لانهارت القاعدة كلّها**: نسختان من `&mut` كاتبان اثنان.

ومع ذلك `bump(q); bump(q);` تعمل. لأن تمرير `&mut` إلى دالّةٍ **إعادةُ استعارة**
ضمنية: تُنشَأ استعارةٌ جديدة أقصر عمراً، وتنتهي بانتهاء الاستدعاء، فيعود الأصل
صالحاً. (`&T` يبقى `Copy` — القرّاء كثيرون بلا حدّ.)

## الحارس بلا وزن

كل ما في هذا الإقليم يقع **في المترجم**. قِس أثره:

```rust
use std::cell::RefCell;
use std::mem::size_of;

fn main() {
    println!("u64          : {}", size_of::<u64>());
    println!("&u64         : {}", size_of::<&u64>());
    println!("&mut u64     : {}", size_of::<&mut u64>());
    println!("*mut u64     : {}", size_of::<*mut u64>());
    println!("RefCell<u64> : {}", size_of::<RefCell<u64>>());
}
```

<!-- out -->

```
u64          : 8
&u64         : 8
&mut u64     : 8
*mut u64     : 8
RefCell<u64> : 16
```

`&mut u64` بحجم `*mut u64` بالضبط: **مؤشّرٌ عارٍ**. لا عدّاد، ولا علم، ولا فحصٌ
عند التشغيل.

و`RefCell<u64>` ستّ عشرة: ثمانٍ للقيمة وثمانٍ **لعدّاد الاستعارة**. فهي القاعدة
نفسها منقولةً إلى وقت التشغيل، ولها وزنٌ تقيسه.

**هذا الفرق هو ما تشتريه بقبول الرفض في وقت الترجمة.**

## المفكِّك: توقيعٌ يقيّدك

عد إلى `rest`. اكتبها بالحذف — بلا `'a` مكتوبة:

```rust
impl<'a> Lexer<'a> {
    fn rest(&self) -> &str {
        &self.src[self.pos..]
    }
}

fn main() {
    let src = String::from("سعر 12 + 30");
    let mut lx = Lexer { src: &src, pos: 0 };

    let r = lx.rest();
    lx.pos += 1;
    println!("{r}");
}
```

<!-- err: E0506 -->

```
error[E0506]: cannot assign to `lx.pos` because it is borrowed
  --> b14.rs:17:5
   |
16 |     let r = lx.rest();
   |             -- `lx.pos` is borrowed here
17 |     lx.pos += 1;
   |     ^^^^^^^^^^^ `lx.pos` is assigned to here but it was already borrowed
18 |     println!("{r}");
   |                - borrow later used here
```

الحذف ربط المُرجَع بـ`&self`. **فصار كل نصٍّ يخرج من المفكِّك يقفله ما دام حيّاً**
— ومفكِّكٌ لا يتقدّم لا يفكّك شيئاً.

## والتوقيع الذي يحرّرك

حرفان اثنان يفكّان القفل:

```rust
struct Lexer<'a> {
    src: &'a str,
    pos: usize,
}

impl<'a> Lexer<'a> {
    fn rest(&self) -> &'a str {
        &self.src[self.pos..]
    }

    fn next_word(&mut self) -> Option<&'a str> {
        let rest = self.rest();
        let start = rest.len() - rest.trim_start().len();
        let rest = &rest[start..];
        if rest.is_empty() {
            return None;
        }
        let end = rest.find(' ').unwrap_or(rest.len());
        self.pos += start + end;
        Some(&rest[..end])
    }
}

fn main() {
    let src = String::from("سعر 12 + 30");
    let mut lx = Lexer { src: &src, pos: 0 };

    let a = lx.next_word();
    let b = lx.next_word();
    println!("{a:?} {b:?}");
    println!("pos = {}", lx.pos);
}
```

<!-- out -->

```
Some("سعر") Some("12")
pos = 9
```

`&'a str` تربط المُرجَع **بالنصّ**، لا بالمفكِّك. فالرمز الخارج يعيش بحياة `src`،
والمفكِّك حرٌّ يتقدّم بعده.

**وهذا هو السطر الذي مررتَ به في الإقليم ٠١ وقلتُ لك إنه جوهريّ.** الآن معك رمز
الرفض الذي كان سيقع لولاه.

## بذرة

كل ما في هذا الإقليم كان عن **مدى** الاستعارة. وقد رأيتَ أن `'a` في التوقيع
تغيّر البرنامج من مرفوضٍ إلى مقبول.

فبقي السؤال: **ما `'a` بالضبط؟** ومتى يكتبها المترجم عنك، ومتى يعجز فيسألك؟
ولماذا `&'a str` في المُرجَع بينما `&self` بلا اسم؟

**الإقليم القادم عن الأعمار**، وفيه تُغلق البذرة الأولى من الإقليم ٠١ إغلاقاً
تامّاً.
