# الإقليم ١١ — الحدّ

> عشرة أقاليم، ولم تكتب `unsafe` مرّةً واحدة. و`split_at_mut` التي أنقذتك في
> الإقليم ٠٣ مبنيّةٌ عليها. و`Vec` و`Arc` و`String` كذلك.
>
> **فالمكتبة التي تحرسك مبنيّةٌ بما لا يحرسها.** هنا تكتبها بيدك، وترى ما تعِد به
> وما لا تعِد، **وتكتب سلوكاً غير معرَّفٍ عمداً لترى بعينك كيف يتغيّر الجواب.**

## البذرة: ما لا يستطيع المترجم إثباته

اكتب `split_at_mut` بالكود الآمن:

```rust
fn my_split_at_mut(v: &mut [i32], mid: usize) -> (&mut [i32], &mut [i32]) {
    let len = v.len();
    assert!(mid <= len);
    (&mut v[..mid], &mut v[mid..])
}
```

<!-- err: E0499 -->

```
error[E0499]: cannot borrow `*v` as mutable more than once at a time
 --> j01.rs:4:26
  |
1 | fn my_split_at_mut(v: &mut [i32], mid: usize) -> (&mut [i32], &mut [i32]) {
  |                       - let's call the lifetime of this reference `'1`
...
4 |     (&mut v[..mid], &mut v[mid..])
  |     ---------------------^--------
  |     |     |              |
  |     |     |              second mutable borrow occurs here
  |     |     first mutable borrow occurs here
  |     returning this value requires that `*v` is borrowed for `'1`
  |
  = help: use `.split_at_mut(position)` to obtain two mutable non-overlapping sub-slices
```

**والكود صحيح.** الشريحتان لا تتقاطعان — أنت تعرف ذلك، والقارئ يعرفه، والمترجم لا
يستطيع إثباته لأن `mid` قيمةٌ في وقت التشغيل.

فالرفض هنا **حدُّ ما يُثبَت، لا حدُّ ما يصحّ**. وهذا هو الموضع الذي وُجدت له
`unsafe`: أن تقول «أنا أضمن ما لا تستطيع أنت إثباته».

## المؤشّر الخام: بناؤه آمن، وقراءته لا

```rust
fn main() {
    let x = 42i32;
    let p: *const i32 = &x;
    let q = p.wrapping_add(1_000_000);

    println!("بناء المؤشّرين لم يحتج شيئاً: {p:p} {q:p}");

    println!("{}", *p);
}
```

<!-- err: E0133 -->

```
error[E0133]: dereference of raw pointer is unsafe and requires unsafe block
 --> j03.rs:8:20
  |
8 |     println!("{}", *p);
  |                    ^^ dereference of raw pointer
  |
  = note: raw pointers may be null, dangling or unaligned; they can violate aliasing rules and cause data races: all of these are undefined behavior
```

**ولاحظ أين وقع الرفض.** بناء `p` مرّ، وحسابُ `q` — مؤشّرٌ إلى ذاكرةٍ لا تملكها —
مرّ كذلك. **المؤشّر الخام رقمٌ، وحملُ الرقم لا يضرّ.**

والضرر عند القراءة. فهناك وحدها يطلب المترجم توقيعك.

## ما تُبيحه الكلمة، وما لا تُبيحه

```rust
fn main() {
    let mut v = vec![1, 2, 3];
    let p: *mut i32 = v.as_mut_ptr();

    unsafe {
        *p = 100;
        println!("عبر المؤشّر: {} {}", *p, *p.add(2));
    }

    println!("{v:?}");
}
```

<!-- out -->

```
عبر المؤشّر: 100 3
[100, 2, 3]
```

`unsafe` تُبيح **خمسةً لا سادس لها**:

| # | ما تُبيحه |
|---|---|
| ١ | فكّ إشارة مؤشّرٍ خام |
| ٢ | استدعاء دالّةٍ `unsafe` (ومنها كل `extern`) |
| ٣ | الوصول إلى حقل `union` |
| ٤ | تنفيذ سمةٍ `unsafe` (مثل `Send` و`Sync` يدوياً) |
| ٥ | الوصول إلى `static` قابلٍ للتعديل |

**وما عدا ذلك يبقى كما هو.** المِلكية تعمل، والأعمار تعمل، وقاعدة الاستعارة تعمل
داخل الكتلة وخارجها.

## والقاعدة لا تُطفَأ

أضِف إلى البرنامج السابق مخالفةً عاديّة:

```rust
fn main() {
    let mut v = vec![1, 2, 3];
    let p: *mut i32 = v.as_mut_ptr();

    unsafe {
        *p = 100;
    }

    let r = &mut v;
    let s = &mut v;
    r.push(4);
    s.push(5);
}
```

<!-- err: E0499 -->

```
error[E0499]: cannot borrow `v` as mutable more than once at a time
  --> j04.rs:11:13
   |
10 |     let r = &mut v;
   |             ------ first mutable borrow occurs here
11 |     let s = &mut v;
   |             ^^^^^^ second mutable borrow occurs here
12 |     r.push(4);
   |     - first borrow later used here
```

**الكتلة مرّت، وما بعدها سقط.**

فـ`unsafe` **ليست مفتاحاً يُطفئ المترجم**. هي إعلانٌ بأنك ستستعمل خمس عملياتٍ
بعينها، **وأنك مسؤولٌ عن شروطها**. وما دون ذلك محروسٌ كما كان.

## الواجهة الآمنة تبتلع العقد

وهذا هو النمط الذي تراه في كل `std`: **`unsafe` في الداخل، ودالّةٌ آمنة في
الخارج.**

<!-- part: 11-split2 -->

```rust
/// شريحةٌ تُقسَم إلى نصفين قابلين للتعديل.
///
/// # الأمان
/// داخلها `unsafe`، **وواجهتها آمنة**: `assert` تضمن الشرط الوحيد الذي
/// يعتمد عليه العقد، والشريحتان لا تتقاطعان بحكم الحساب.
fn split2(v: &mut [i32], mid: usize) -> (&mut [i32], &mut [i32]) {
    let len = v.len();
    assert!(mid <= len, "mid={mid} خارج الطول {len}");
    let ptr = v.as_mut_ptr();
    unsafe {
        (
            slice::from_raw_parts_mut(ptr, mid),
            slice::from_raw_parts_mut(ptr.add(mid), len - mid),
        )
    }
}
```

<!-- out: بعد السطر الأوّل رسالةُ ذعرٍ من الاستدعاء الثاني -->

```
[11, 2, 3, 14]
خارج الحدّ ⇒ ذعرٌ لا فساد: true
```

**`assert` هي الثمن.** فحصٌ واحد في وقت التشغيل يحوّل شرطاً في رأسك إلى شرطٍ
مضمون، فتصير الواجهة آمنةً لكل مدخَل.

**والذعر عند `mid=9` ليس عيباً — هو الوعد.** المخالفة تُوقف البرنامج ولا تفسد
الذاكرة، وهذا كل الفرق بينها وبين نظيرتها في C.

> وتوثيق `# الأمان` عرفٌ لا تُلزِمك به اللغة، **ويُلزِمك به كل مراجعٍ**: من كتب
> `unsafe` بلا أن يكتب الشرط الذي يضمنه لم يُتمّ عمله.

## سلوكٌ غير معرَّف، بيدك

اكسر عقداً عمداً، وشغّل بالبناءين:

<!-- runs: 11-ub -->

```rust
use std::hint::unreachable_unchecked;

/// العقد: لا تُستدعى إلا بـ`x <= 5`. وكسرُه سلوكٌ غير معرَّف.
unsafe fn small(x: u32) -> u32 {
    if x > 5 {
        unsafe { unreachable_unchecked() }
    }
    x * 10
}

fn main() {
    let arg: u32 = std::env::args().count() as u32 + 8;
    println!("المدخَل: {arg}");
    println!("الجواب: {}", unsafe { small(arg) });
}
```

**برنامجٌ واحد، وجوابان.** بلا `-O`:

<!-- shell -->

<!-- out: `rustc --edition 2024 11-ub.rs && ./11-ub` -->

```
المدخَل: 9

thread 'main' panicked at j05.rs:6:18:
unsafe precondition(s) violated: hint::unreachable_unchecked must never be reached

This indicates a bug in the program. This Undefined Behavior check is optional,
and cannot be relied on for safety.
```

ومع `-O`:

<!-- shell -->

<!-- out: `rustc --edition 2024 -O 11-ub.rs && ./11-ub` -->

```
المدخَل: 9
الجواب: 90
```

**٩ أكبر من ٥، والدالّة أعطت ٩٠.** فقد صدّق المُحسِّن وعدَك: «لن يزيد على خمسة»،
فحذف الفحص كلّه.

**واقرأ الجملة في رسالة الذعر:** «هذا الفحص اختياريّ، ولا يجوز الاعتماد عليه في
الأمان». المترجم يقول لك بنفسه إن ما أمسكه هنا صدفةٌ من بناء التطوير.

## و`Miri` يرى ما لا يراه الملفّ التنفيذيّ

مخالفةٌ أدقّ: مرجعان قابلان للتعديل من مؤشّرٍ واحد.

<!-- part: 11-alias -->

```rust
fn main() {
    let mut x = 10i32;
    let p = &mut x as *mut i32;
    let a = unsafe { &mut *p };
    let b = unsafe { &mut *p };
    *a = 1;
    *b = 2;
    println!("{} {}", a, b);
}
```

<!-- out: `rustc` بالبناءين معاً — لا شكوى ولا فرق -->

```
2 2
```

ثم شغّله على `Miri` — مفسِّرٌ ينفّذ الكود الوسيط ويتتبّع كل استعارة:

```bash
rustup toolchain install nightly --component miri
cargo +nightly miri run
```

<!-- shell -->

<!-- out -->

```
error: Undefined Behavior: attempting a write access using <589> at alloc219[0x0],
       but that tag does not exist in the borrow stack for this location
 --> src/main.rs:6:5
  |
6 |     *a = 1;
  |     ^^^^^^ this error occurs as part of an access at alloc219[0x0..0x4]
  |
help: <589> was created by a Unique retag at offsets [0x0..0x4]
 --> src/main.rs:4:22
help: <589> was later invalidated at offsets [0x0..0x4] by a Unique retag
 --> src/main.rs:5:22
```

**سطرا الإنشاء والإبطال بالضبط.** المترجم سكت، والملفّ التنفيذيّ سكت، و`Miri`
سمّى القاعدة وأشار إلى السطرين.

**فالقاعدة العملية:** كل كتلة `unsafe` تكتبها يجب أن تمرّ باختبارٍ تحت `Miri`.
وثمنه بطءٌ عشرات الأضعاف، **ولهذا يُشغَّل على الاختبارات لا على الإنتاج**.

## `transmute` والاتّحاد: إعادة تفسير البتات

<!-- part: 11-transmute -->

```rust
#[repr(C)]
#[derive(Debug)]
struct Pair { a: u32, b: u32 }

union Bits { f: f32, i: u32 }

fn main() {
    let p = Pair { a: 1, b: 2 };
    let n: u64 = unsafe { transmute(p) };
    println!("transmute → {n} (0x{n:x})");

    let b = Bits { f: 1.0 };
    println!("1.0f32 بتاته = 0x{:08x}", unsafe { b.i });

    println!("size_of Pair = {} · u64 = {}", size_of::<Pair>(), size_of::<u64>());
}
```

<!-- out -->

```
transmute → 8589934593 (0x200000001)
1.0f32 بتاته = 0x3f800000
size_of Pair = 8 · u64 = 8
```

`0x200000001` = ٢ في الكلمة العليا و١ في الدنيا — **ترتيب البايتات الصغير**
مقروءاً مباشرةً. و`#[repr(C)]` ضروريّة هنا: بلا إعلانٍ للتخطيط لا معنى لإعادة
التفسير.

**و`transmute` أخطر ما في اللغة**: تقبل أي نوعين متساويي الحجم. فما تحوّله إلى
`bool` وقيمته ٢ يفسد المطابقة نفسها.

و`union` نظيرتها المصرَّح بها: **قراءةُ حقلٍ لم يُكتَب سلوكٌ غير معرَّف**، ولهذا كانت
القراءة `unsafe` والكتابة آمنة.

## و`static mut` صار خطأً

في الإصدارة ٢٠٢٤ لم تعد `unsafe` كافية:

```rust
static mut TOTAL: u64 = 0;

fn main() {
    unsafe {
        TOTAL += 1;
        println!("{}", TOTAL);
    }
}
```

<!-- err: static_mut_refs -->

```
error: creating a shared reference to mutable static
 --> j08.rs:6:24
  |
6 |         println!("{}", TOTAL);
  |                        ^^^^^ shared reference to mutable static
  |
  = note: shared references to mutable statics are dangerous; it's undefined behavior if the static is mutated or if a mutable reference is created for it while the shared reference lives
  = note: `#[deny(static_mut_refs)]` (part of `#[deny(rust_2024_compatibility)]`) on by default
```

**هذا مثالٌ حيّ لما تفعله الإصدارات:** نمطٌ كان يُترجَم بتحذير صار خطأً في ٢٠٢٤،
والكود القديم يبقى يعمل بإصدارته.

والبديل `AtomicU64` أو `Mutex` — **وكلاهما آمن**، وقد رأيتهما في الإقليم السابق.

## الحدّ إلى C

`extern "C"` تعبر إلى مكتبةٍ لا يعرف المترجم عنها شيئاً:

<!-- part: 11-ffi -->

```rust
unsafe extern "C" {
    fn abs(x: i32) -> i32;
    fn strlen(s: *const i8) -> usize;
}

fn main() {
    unsafe {
        println!("abs(-42) = {}", abs(-42));
    }

    let owned = std::ffi::CString::new("hello").unwrap();
    unsafe {
        println!("strlen = {}", strlen(owned.as_ptr()));
    }
    println!("len في Rust = {}", "hello".len());
}
```

<!-- out -->

```
abs(-42) = 42
strlen = 5
len في Rust = 5
```

**والتوقيع الذي تكتبه ادّعاءٌ لا يُفحَص.** لو كتبتَ `fn abs(x: i64) -> i64` لترجم
البرنامج ولأعطى جواباً فاسداً — لا أحد يقارن إعلانك بالمكتبة الحقيقية.

و`CString` هي الجسر الصحيح للنصّ: **تضيف الصفر الختاميّ** الذي تنتظره C ولا
تعرفه `&str`. وتمرير `"hello".as_ptr()` مباشرةً يجعل `strlen` تقرأ حتى تصادف
صفراً في ذاكرةٍ ليست لك.

## ما لا يعِد به المترجم أصلاً

و«آمن» في Rust كلمةٌ لها حدٌّ مرسوم:

| ما يمنعه الكود الآمن | ما لا يمنعه |
|---|---|
| قراءةٌ بعد تحرير | **تسريب الذاكرة** — رأيتَه في الإقليم ٠٩ |
| تحريرٌ مزدوج | **الجمود** بين قفلين |
| مؤشّرٌ متدلٍّ | **الذعر** وإسقاط البرنامج |
| تجاوز حدٍّ صامت | **فيضٌ يلتفّ** في بناء الإصدار |
| سباق بيانات | **سباق شروط** في منطق برنامجك |

**فالوعد دقيق: لا سلوك غير معرَّف.** وليس «لا أخطاء» ولا «لا تسريب». ومن يقول
غير ذلك يبيعك ما لم تشترِه.

## وكم `unsafe` تحتك؟

عُدّها في المكتبة القياسية نفسها:

```bash
rustup component add rust-src
SRC=~/.rustup/toolchains/$(rustc -vV | sed -n 's/host: //p')/lib/rustlib/src/rust/library
grep -rho '\bunsafe\b' $SRC/core --include='*.rs' | wc -l
```

<!-- shell -->

<!-- out: عدُّ الكلمة أينما وردت — كتلةً ودالّةً وتنفيذاً وتعليقاً -->

```
core   280 ملفّ ·  168802 سطر ·  3351 unsafe
alloc   78 ملفّ ·   60897 سطر ·  1697 unsafe
std    712 ملفّ ·  168580 سطر ·  3231 unsafe
```

**نحو اثنين في المئة من الأسطر.** وبرنامجك أنت — أحد عشر إقليماً من مفكِّكٍ ومُحلِّل
وحاسبٍ وخيوط — فيه **صفر**.

وهذا هو نموذج اللغة كلّه: **قلّةٌ مركَّزة تُدقَّق وتُختبَر بـ`Miri`، وكثرةٌ فوقها
تُترجَم أو تُرفَض.** فليست القاعدة «لا تكتب `unsafe`»، بل: اكتبها حيث لا بديل،
واحبسها خلف واجهةٍ آمنة، واكتب شرطها، واختبرها.

## بذرة

انتهى تفكيك اللغة. تعرف ما يثبته المترجم، وأين ينتهي إثباته، وماذا يبقى عليك.

ويبقى سؤالٌ لم يُطرح: كل ما بنيتَه كان **ملفّاً واحداً يُترجَم بـ`rustc`**. ولا
مشروعَ حقيقيّ كذلك.

فأين تسكن الوحدات؟ وكيف يُوثَّق ما تكتبه فيُقرأ في المتصفّح؟ وكيف يُختبَر؟ وما
الذي يردّه `clippy` وإن ترجم؟ **وما الذي يكسر مستعمليك حين ترفع رقم إصدارك؟**

**الإقليم الأخير عن كيف تُكتب Rust** — لا كيف تعمل.
