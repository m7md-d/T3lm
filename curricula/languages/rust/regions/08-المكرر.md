# الإقليم ٠٨ — المكرِّر

> `Counter` نفّذت `Iterator` في خمسة عشر سطراً، فجاءت `filter` و`collect` و`sum`
> بلا سطرٍ إضافيّ. وسلسلةٌ من ثلاث طبقات تبدو كثلاث حلقات.
>
> **فهل مرّت الأرقام ثلاث مرّات؟ وأين خُزِّنت بينها؟** هنا تقيس الجواب بنفسك — عدد
> المرور، وعدد التخصيصات، والزمن مقابل حلقةٍ تكتبها بيدك.

## البذرة: كم مرّةً تمرّ؟

ضع طباعةً داخل كل مهايئ، وتوقّع الترتيب:

```rust
fn main() {
    let v = vec![1, 2, 3, 4, 5, 6];

    let out: Vec<i32> = v
        .iter()
        .map(|x| {
            println!("  map({x})");
            x * 10
        })
        .filter(|x| {
            println!("  filter({x})");
            x % 20 == 0
        })
        .collect();

    println!("{out:?}");
}
```

المخرَج:

```
  map(1)
  filter(10)
  map(2)
  filter(20)
  map(3)
  filter(30)
  map(4)
  filter(40)
  map(5)
  filter(50)
  map(6)
  filter(60)
[20, 40, 60]
```

**متداخلان.** كل عنصرٍ يعبر السلسلة كاملةً قبل أن يبدأ الذي بعده.

فلا `Vec` وسيطة بين `map` و`filter`، **ولا مرورٌ ثانٍ على البيانات**. والسلسلة
مرورٌ واحد مهما طالت.

## و«الكسل» ليس مجازاً

احذف `collect`، وانظر ماذا يحدث:

```rust
fn main() {
    let v = vec![1, 2, 3];
    v.iter().map(|x| println!("مرّ {x}"));
    println!("انتهت main");
}
```

<!-- out: ومعه تحذيران من المترجم، نصّهما تحت -->

```
انتهت main
```

**ولا سطر «مرّ».** والمترجم يقولها بحرفها:

```
warning: unused `Map` that must be used
  = note: iterators are lazy and do nothing unless consumed
help: use `let _ = ...` to ignore the resulting value

warning: `Iterator::map` call that discard the iterator's values
  = note: `Iterator::map`, like many of the methods on `Iterator`, gets executed
    lazily, meaning that its effects won't be visible until it is iterated
help: you might have meant to use `Iterator::for_each`
```

فالمهايئ **يبني نوعاً ولا يفعل شيئاً**. والذي يشغّل السلسلة `collect` أو `sum` أو
`for` أو أي مستهلك.

## مدىً بأربعة مليارات، وألفان مرّوا

فإن كان الكسل حقيقياً فهذا يجب أن ينتهي فوراً:

```rust
use std::sync::atomic::{AtomicU64, Ordering::Relaxed};

static SEEN: AtomicU64 = AtomicU64::new(0);

fn main() {
    let out: Vec<u32> = (0..u32::MAX)
        .filter(|x| {
            SEEN.fetch_add(1, Relaxed);
            x % 1_000 == 7
        })
        .take(3)
        .collect();

    println!("{out:?}");
    println!("عدد ما مرّ على المرشّح: {}", SEEN.load(Relaxed));
    println!("طول المدى: {}", u32::MAX);
}
```

<!-- out -->

```
[7, 1007, 2007]
عدد ما مرّ على المرشّح: 2008
طول المدى: 4294967295
```

**٢٠٠٨ من أربعة مليارات.** و`take(3)` أوقفت السلسلة من فوق: حين امتلأت طلباتها
الثلاث توقّفت عن سؤال `filter`، فتوقّف `filter` عن سؤال المدى.

**والسحب من الأعلى** هو الفرق كلّه: المستهلك يسأل، والمهايئات تُمرِّر السؤال إلى
المصدر. ولهذا يعمل مدىً لا نهاية له.

## السلسلة نوعٌ، لا حلقة

اطبع نوع كل خطوة:

```rust
use std::any::type_name_of_val;

/// اسم النوع بلا ضجيج المسارات — والبادئة الأولى اسمُ ملفّك أنت.
fn shape<T>(x: &T) -> String {
    let krate = format!("{}::", module_path!().split("::").next().unwrap());
    type_name_of_val(x)
        .replace("core::iter::adapters::", "")
        .replace("core::slice::iter::", "")
        .replace(&krate, "")
        .replace("main::{{closure}}", "closure")
}

fn main() {
    let v = vec![1, 2, 3];

    println!("{}", shape(&v.iter()));
    println!("{}", shape(&v.iter().map(|x| x * 2)));
    println!("{}", shape(&v.iter().map(|x| x * 2).filter(|x| *x > 2)));
    println!("{}", shape(&v.iter().map(|x| x * 2).filter(|x| *x > 2).take(1)));
}
```

<!-- out -->

```
Iter<'_, i32>
map::Map<Iter<'_, i32>, closure>
filter::Filter<map::Map<Iter<'_, i32>, closure>, closure>
take::Take<filter::Filter<map::Map<Iter<'_, i32>, closure>, closure>>
```

**كل مهايئٍ يلفّ ما قبله في نوعٍ جديد.** والسلسلة الرباعية نوعٌ واحد، معروفٌ
بالكامل وقت الترجمة، وحجمه مجموع حجوم أجزائه.

ولأن النوع معلوم، فكل `next` نداءٌ مباشر يستطيع المترجم أن يدمجه. **لا `dyn` ولا
جدول ولا تخصيص** — وهذا أساس ما تقيسه في الشوطين التاليين.

## صفريّة الكلفة، مقيسة

نفس العمل مرّتين: حلقة `while` بفهرسٍ يدويّ، وسلسلةُ `filter().map().sum()`:

<!-- runs: 08-zero-cost -->

```rust
fn by_loop(v: &[u64]) -> u64 {
    let mut acc = 0;
    let mut i = 0;
    while i < v.len() {
        if v[i] % 3 == 0 {
            acc += v[i] * 2;
        }
        i += 1;
    }
    acc
}

fn by_chain(v: &[u64]) -> u64 {
    v.iter().filter(|x| *x % 3 == 0).map(|x| x * 2).sum()
}
```

<!-- out: بـ`-O`، وأقلّ زمنٍ من سبع جولات؛ الأزمنة تختلف عندك والنسبة لا -->

```
حلقة يدوية : 6.808583ms
سلسلة      : 6.802042ms
النسبة     : 1.00×
متساويان؟ true
```

**١٫٠٠×.** كرّرتُ التشغيل أربع مرّات فخرجت بين ٠٫٩٧ و١٫٠٠.

**وطريقة القياس جزءٌ من النتيجة:** `black_box` تمنع المترجم من حذف العمل، وأقلّ
زمنٍ من سبع جولات لأن الضجيج يزيد الزمن ولا ينقصه. **وبلا هذين تقيس المخبأ لا
الكود.**

> وانتبه: هذه المقارنة **مع `-O`**. بلا تحسينٍ تكون السلسلة أبطأ بكثير، لأن كل
> `next` تبقى استدعاءً حقيقياً.

## وصفرُ تخصيصٍ كذلك

الفرق الأوضح ليس في الزمن. عُدّ التخصيصات:

<!-- part: 08-alloc -->

```rust
fn main() {
    let v: Vec<u64> = (0..1000).collect();

    let c0 = COUNT.load(Relaxed);
    let chained: u64 = v.iter().filter(|x| *x % 3 == 0).map(|x| x * 2).sum();
    let c1 = COUNT.load(Relaxed);

    let kept: Vec<&u64> = v.iter().filter(|x| *x % 3 == 0).collect();
    let doubled: Vec<u64> = kept.iter().map(|x| *x * 2).collect();
    let stepwise: u64 = doubled.iter().sum();
    let c2 = COUNT.load(Relaxed);
    // … طباعة الفروق
}
```

<!-- out -->

```
سلسلة   : 0 تخصيصاً  ·  333666
بخطوات  : 9 تخصيصاً  ·  333666
```

**صفرٌ مقابل تسعة**، ونفس الجواب. والتسعة كلّها من نموّ المتّجهين الوسيطين.

وهذا هو الفرق العمليّ الذي تدفعه حين تكتب `.collect()` في منتصف سلسلة: **ماديّة
البيانات**. فاجعلها في الآخر، أو حيث تحتاج المرور مرّتين فعلاً.

## `collect` تجمع في ما تطلبه

المستهلك الأشهر يقرأ **النوع الذي تُعلنه**:

```rust
use std::collections::HashMap;

fn main() {
    let words = ["سعر", "12", "+", "30"];

    let v: Vec<usize> = words.iter().map(|w| w.chars().count()).collect();
    let s: String = words.iter().copied().collect();
    let m: HashMap<&str, usize> = words.iter().map(|w| (*w, w.len())).collect();

    println!("{v:?}");
    println!("{s}");
    println!("{}", m["سعر"]);

    let ok: Result<Vec<i64>, _> = ["12", "30"].iter().map(|w| w.parse::<i64>()).collect();
    let bad: Result<Vec<i64>, _> = ["12", "ثلاثون", "30"].iter().map(|w| w.parse::<i64>()).collect();
    println!("{ok:?}");
    println!("{bad:?}");
}
```

<!-- out -->

```
[3, 2, 1, 2]
سعر12+30
6
Ok([12, 30])
Err(ParseIntError { kind: InvalidDigit })
```

**والسطران الأخيران هما المكسب المخبّأ:** `Result<Vec<_>, E>` تقلب السلسلة —
`collect` تجمع حتى أوّل `Err` **ثم تتوقّف**، فتُرجع خطأً واحداً بدل متّجهٍ من
النتائج.

فحلقةٌ من عشرة أسطر فيها `match` و`break` صارت سطراً واحداً، **والفرق نوعٌ مكتوب
على اليسار.**

## المهايئات التي ستكتبها كل يوم

عشرةٌ تغنيك عن أكثر الحلقات:

```rust
fn main() {
    let v = vec![3, 1, 4, 1, 5, 9, 2, 6];

    println!("any  : {}", v.iter().any(|x| *x > 8));
    println!("all  : {}", v.iter().all(|x| *x > 0));
    println!("pos  : {:?}", v.iter().position(|x| *x == 4));
    println!("find : {:?}", v.iter().find(|x| **x > 4));
    println!("fold : {}", v.iter().fold(0, |a, x| a + x));
    println!("max  : {:?}", v.iter().max());
    println!("rev  : {:?}", v.iter().rev().take(3).collect::<Vec<_>>());
    println!("zip  : {:?}", v.iter().zip(v.iter().skip(1)).take(2).collect::<Vec<_>>());
    println!("chunks: {:?}", v.chunks(3).collect::<Vec<_>>());
    println!("windows: {:?}", v.windows(2).take(2).collect::<Vec<_>>());
}
```

<!-- out -->

```
any  : true
all  : true
pos  : Some(2)
find : Some(5)
fold : 31
max  : Some(9)
rev  : [6, 2, 9]
zip  : [(3, 1), (1, 4)]
chunks: [[3, 1, 4], [1, 5, 9], [2, 6]]
windows: [[3, 1], [1, 4]]
```

**و`any` و`all` و`find` و`position` تقصّر:** تتوقّف عند أوّل جوابٍ يحسم. فـ`any`
على مدىً لا نهاية له تنتهي متى وجدت.

و`rev` تحتاج `DoubleEndedIterator` — سمةٌ ثانية ينفّذها ما يعرف نهايته. **ولهذا
`rev` تعمل على `Vec` ولا تعمل على قارئ ملفّ.**

## المفكِّك يصير مكرِّراً، والمُحلِّل يقرأ منه

في الإقليم ٠٦ بنى المُحلِّل شجرته من `&[Token]` — أي من متّجهٍ مادّيّ. **والمفكِّك
مكرِّرٌ أصلاً**، فلمَ الوسيط؟

<!-- part: 08-peekable -->

```rust
fn expr<I: Iterator<Item = Token>>(it: &mut Peekable<I>) -> Expr {
    let mut left = term(it);
    while it.peek() == Some(&Token::Sym('+')) {
        it.next();
        let right = term(it);
        left = Expr::Add(Box::new(left), Box::new(right));
    }
    left
}

fn main() {
    let src = "12 + 30 * 2";
    let mut it = Lexer { rest: src }.peekable();
    let tree = expr(&mut it);

    println!("{tree:?}");
    println!("{src} = {}", eval(&tree));
}
```

<!-- out -->

```
Add(Num(12), Mul(Num(30), Num(2)))
12 + 30 * 2 = 72
```

**ولا `Vec<Token>` في البرنامج كلّه.** الرمز يُقرأ من النصّ ويُستهلَك في الشجرة
مباشرةً، فذهب تخصيصٌ كامل وذهب معه مرورٌ على البيانات.

و`peek` هي كل ما احتاجه المُحلِّل زيادةً: **نظرةٌ إلى الرمز القادم بلا استهلاكه**.
و`Peekable` مهايئٌ يخبّئ عنصراً واحداً ويعطي `peek`، بلا أن يفقد المكرِّر كسله.

**ولاحظ التوقيع `I: Iterator<Item = Token>`:** المُحلِّل لم يعد مرتبطاً بالمفكِّك.
يقرأ من أي شيءٍ يعطي رموزاً — ملفٍّ، أو شبكة، أو اختبارٍ يعطي رموزاً بيدك.

## بذرة

المفكِّك والمُحلِّل والحاسب صاروا سلسلةً واحدة، والمِلكية فيها **خطٌّ مستقيم**: كل
قيمةٍ تُنقَل إلى من بعدها، ولها مالكٌ واحد في كل لحظة.

فماذا لو احتاج شيئان أن يمسكا القيمة نفسها؟ جدولُ رموزٍ يشير إليه المُحلِّل
والحاسب معاً، أو عقدةٌ في رسمٍ يعرفها أبواها؟

**البديهية الأولى تقول: مالكٌ واحد.** وهذا شكلٌ لا يقبله المترجم أصلاً.

**والإقليم القادم عن المِلكية المشتركة** — عدّادٌ في وقت التشغيل، وقاعدةُ الاستعارة
منقولةً إلى وقت التشغيل معها، **وثمنٌ ثالث: حلقةٌ تسرّب ذاكرة في لغةٍ يقال إنها لا
تسرّب.**
