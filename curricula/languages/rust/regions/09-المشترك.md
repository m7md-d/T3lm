# الإقليم ٠٩ — المشترَك

> البديهية الأولى: **لكل قيمةٍ مالكٌ واحد**. وقد بنيتَ عليها ثمانية أقاليم.
>
> وهنا تقابل الشكل الذي لا تقبله: جدولُ رموزٍ يمسكه المُحلِّل والحاسب معاً. فتنقل
> القاعدة إلى **وقت التشغيل**، وتدفع ثمنها الثلاثيّ: عدّادٌ، واحتمالُ ذعر،
> **وتسريبُ ذاكرةٍ في لغةٍ يقال إنها لا تسرّب.**

## البذرة: مالكان لشيءٍ واحد

المُحلِّل يحتاج جدول الرموز، والحاسب يحتاجه. اكتبها كما تُكتب في أي لغة:

```rust
struct Table { names: Vec<String> }
struct Parser { table: Table }
struct Evaluator { table: Table }

fn main() {
    let t = Table { names: vec![String::from("سعر")] };

    let p = Parser { table: t };
    let e = Evaluator { table: t };

    println!("{} {}", p.table.names.len(), e.table.names.len());
}
```

<!-- err: E0382 -->

```
error[E0382]: use of moved value: `t`
  --> h01.rs:17:32
   |
14 |     let t = Table { names: vec![String::from("سعر")] };
   |         - move occurs because `t` has type `Table`, which does not implement the `Copy` trait
16 |     let p = Parser { table: t };
   |                             - value moved here
17 |     let e = Evaluator { table: t };
   |                                ^ value used here after move
   |
note: if `Table` implemented `Clone`, you could clone the value
```

والاقتراح في آخر الرسالة **جوابٌ خاطئ هنا**: نسختان تعنيان جدولين، فما يسجّله
المُحلِّل لا يراه الحاسب.

فالمطلوب **قيمةٌ واحدة ومالكان**. وهذا ما لا يستطيع المترجم إثباته وقت الترجمة:
مَن آخر من يموت؟ الجواب يعتمد على مسار التنفيذ.

## `Rc` — العدّاد يقرّر

`Rc<T>` تنقل السؤال إلى وقت التشغيل: **عدّادٌ يزيد بالنسخ، وينقص بالموت، والقيمة
تموت عند الصفر.**

```rust
use std::rc::Rc;

struct Table { names: Vec<String> }

fn main() {
    let t = Rc::new(Table { names: vec![String::from("سعر")] });
    println!("بعد الإنشاء : {}", Rc::strong_count(&t));

    let p = Rc::clone(&t);
    println!("بعد نسخةٍ   : {}", Rc::strong_count(&t));

    {
        let e = Rc::clone(&t);
        println!("بعد نسختين : {}", Rc::strong_count(&t));
        println!("الاسم من الثالثة: {}", e.names[0]);
    }

    println!("بعد نطاقٍ   : {}", Rc::strong_count(&t));
    println!("نفس العنوان؟ {}", Rc::ptr_eq(&t, &p));
}
```

<!-- out -->

```
بعد الإنشاء : 1
بعد نسخةٍ   : 2
بعد نسختين : 3
الاسم من الثالثة: سعر
بعد نطاقٍ   : 2
نفس العنوان؟ true
```

**والسطر الأخير هو المهمّ:** الثلاثة تشير إلى الجدول نفسه. `Rc::clone` تزيد عدداً
وتنسخ مؤشّراً — **ولا تنسخ الجدول**.

ولهذا تُكتب `Rc::clone(&t)` بهذا الشكل لا `t.clone()`: **الشكل يقول للقارئ إن هذه
مشاركةٌ رخيصة**، لا نسخةٌ عميقة.

## و`Rc` لا تُعطي `&mut`

المشاركة سهلة. والتعديل ممنوع:

```rust
use std::rc::Rc;

struct Table { names: Vec<String> }

fn main() {
    let t = Rc::new(Table { names: vec![] });
    let _p = Rc::clone(&t);

    t.names.push(String::from("سعر"));
}
```

<!-- err: E0596 -->

```
error[E0596]: cannot borrow data in an `Rc` as mutable
  --> h03.rs:11:5
   |
11 |     t.names.push(String::from("سعر"));
   |     ^^^^^^^ cannot borrow as mutable
   |
   = help: trait `DerefMut` is required to modify through a dereference, but it is not implemented for `Rc<Table>`
```

**وهذا هو المتوقَّع تماماً.** البديهية الثانية تقول: كاتبٌ واحد أو قرّاءٌ كثيرون.
و`Rc` صنعت قرّاءً كثيرين، فالكتابة خرجت.

فالمشاركة وحدها لا تكفي. **يلزم أن تنتقل قاعدة الاستعارة نفسها إلى وقت التشغيل.**

## `RefCell` — الاستعارة تُحصى

`RefCell<T>` تحمل القاعدة في عدّاد: قرّاءٌ كثيرون، أو كاتبٌ واحد، **وتُفحَص عند كل
استعارة**.

```rust
use std::cell::RefCell;

fn main() {
    let c = RefCell::new(vec![1, 2, 3]);

    {
        let a = c.borrow();
        let b = c.borrow();
        println!("قارئان معاً: {} {}", a.len(), b.len());
    }

    c.borrow_mut().push(4);
    println!("بعد التعديل: {:?}", c.borrow());

    println!("try_borrow_mut أثناء قراءة:");
    let guard = c.borrow();
    println!("  {:?}", c.try_borrow_mut().is_err());
    drop(guard);
    println!("  بعد إفلات القارئ: {:?}", c.try_borrow_mut().is_ok());
}
```

<!-- out -->

```
قارئان معاً: 3 3
بعد التعديل: [1, 2, 3, 4]
try_borrow_mut أثناء قراءة:
  true
  بعد إفلات القارئ: true
```

**`borrow` تُرجع حارساً** (`Ref`)، والعدّاد ينقص بموته. ولهذا احتاج السطر
`drop(guard)`.

و`try_borrow_mut` تُرجع `Result` بدل الذعر — **وهي الصورة التي تكتبها في كودٍ
يعالج مدخلات**، بعد ما تعلّمتَه في إقليم الفشل.

## والمخالفة تذعر

نفس البرنامج الذي رفضه المترجم في الإقليم ٠٣، بـ`RefCell`:

```rust
use std::cell::RefCell;

fn main() {
    let c = RefCell::new(vec![1, 2, 3]);
    let read = c.borrow();
    println!("قراءة {}", read.len());
    c.borrow_mut().push(4);
    println!("{:?}", read);
}
```

<!-- out: بعده سطر backtrace، والخروج بالرمز ١٠١ -->

```
قراءة 3

thread 'main' panicked at h06.rs:7:7:
RefCell already borrowed
```

**يُترجَم، ويُشحَن، ثم ينهار عند المستخدم.**

قارِنه بـ`E0502` في الإقليم ٠٣: نفس الخطأ بالضبط، ونفس القاعدة. **والفرق متى
يُكتشَف**، وهو الفرق الذي تشتريه حين تختار `RefCell`.

> والقاعدة العملية: `RefCell` لِما **لا** تستطيع إثباته وقت الترجمة. ومن يضعها
> هرباً من رفضٍ يستطيع إصلاحه يشتري ذعراً بلا ثمن.

## و`Cell` بلا عدّاد ولا ذعر

للأنواع التي تُنسخ، هناك صورةٌ أرخص:

```rust
use std::cell::{Cell, RefCell};
use std::mem::size_of;

struct Counter { hits: Cell<u32> }

impl Counter {
    /// تعديلٌ خلف `&self` — لا استعارة، ولا احتمال ذعر.
    fn hit(&self) -> u32 {
        self.hits.set(self.hits.get() + 1);
        self.hits.get()
    }
}

fn main() {
    let c = Counter { hits: Cell::new(0) };
    println!("{} {} {}", c.hit(), c.hit(), c.hit());

    println!("u32           : {}", size_of::<u32>());
    println!("Cell<u32>     : {}", size_of::<Cell<u32>>());
    println!("RefCell<u32>  : {}", size_of::<RefCell<u32>>());
}
```

<!-- out -->

```
1 2 3
u32           : 4
Cell<u32>     : 4
RefCell<u32>  : 16
```

**`Cell<u32>` بحجم `u32`.** لا عدّاد ولا حارس، لأنها لا تُعطي مرجعاً أصلاً:
`get` تنسخ، و`set` تكتب، **وبينهما لا شيء يمكن أن يتدلّى**.

و`RefCell<u32>` ستّ عشرة: أربعٌ للقيمة، وثمانٍ للعدّاد، وأربعٌ حشو. **فاختر `Cell`
كلّما كفتك النسخة.**

## `Rc<RefCell<T>>` — الشكل الذي تكتبه فعلاً

الاثنان معاً: مالكون كثيرون، وتعديلٌ محروسٌ عند التشغيل.

```rust
use std::cell::RefCell;
use std::rc::Rc;
use std::mem::size_of;

#[derive(Debug)]
struct Table { names: Vec<String> }

fn main() {
    let t = Rc::new(RefCell::new(Table { names: vec![] }));
    let p = Rc::clone(&t);

    t.borrow_mut().names.push(String::from("سعر"));
    p.borrow_mut().names.push(String::from("12"));

    println!("{:?}", t.borrow());
    println!("عدد المالكين: {}", Rc::strong_count(&t));

    println!("Vec<String>             : {}", size_of::<Vec<String>>());
    println!("RefCell<Vec<String>>    : {}", size_of::<RefCell<Vec<String>>>());
    println!("Rc<RefCell<Vec<String>>>: {}", size_of::<Rc<RefCell<Vec<String>>>>());
}
```

<!-- out -->

```
Table { names: ["سعر", "12"] }
عدد المالكين: 2
Vec<String>             : 24
RefCell<Vec<String>>    : 32
Rc<RefCell<Vec<String>>>: 8
```

**اقرأ الترتيب من الخارج:** `Rc` مؤشّرٌ بثماني بايتات. وخلفه في الكومة عدّادان
و`RefCell` بثنتين وثلاثين — أربعٌ وعشرون للجدول، وثمانٍ لعلم الاستعارة.

**والترتيب لا يُعكس:** `RefCell<Rc<T>>` تعني «خليّةٌ فيها مؤشّر مشترَك» — تستطيع
أن تبدّل إلى **أيّ** جدولٍ تشير، ولا تستطيع تعديل الجدول نفسه.

## الثمن مقاساً

«المشاركة أرخص من النسخ» ادّعاء. قِسه:

<!-- part: 09-share-cost -->

```rust
let c0 = COUNT.load(Relaxed);
let deep: Vec<Table> = (0..8).map(|_| big.clone()).collect();
let c1 = COUNT.load(Relaxed);

let rc = Rc::new(RefCell::new(big));
let c2 = COUNT.load(Relaxed);
let shared: Vec<Rc<RefCell<Table>>> = (0..8).map(|_| Rc::clone(&rc)).collect();
let c3 = COUNT.load(Relaxed);
```

<!-- out: جدولٌ فيه مئة اسم -->

```
ثمانُ نسخٍ عميقة : 809 تخصيصاً
ثمانُ مشاركات   : 1 تخصيصاً
(بناء Rc نفسه   : 1 تخصيصاً)
100 أسماء · 8 نسخة · 8 مشاركة
```

**٨٠٩ مقابل واحد.** كل نسخةٍ عميقة تخصّص للمتّجه ولمئة `String` فيه؛ والمشاركات
الثماني خصّصت للمتّجه الحاوي وحده.

**وبناء `Rc` نفسه تخصيصٌ واحد** — العدّادان والقيمة في كتلةٍ واحدة، لا كتلتين.

## الحلقة تسرّب

وهنا الثمن الذي لا يذكره أحد. عقدتان تشير كلٌّ منهما إلى الأخرى:

<!-- part: 09-cycle -->

```rust
struct Node {
    name: &'static str,
    links: RefCell<Vec<Rc<Node>>>,
}

impl Drop for Node {
    fn drop(&mut self) { println!("مات {}", self.name); }
}
```

<!-- out -->

```
— بلا حلقة —
  أ=1 ب=2
مات أ
مات ب
— بحلقة —
  س=2 ص=2
— انتهى النطاق —
```

**«مات س» و«مات ص» لم يُطبَعا.**

في الحالة الأولى مات `أ` فنقص عدّاد `ب` إلى صفرٍ فمات. وفي الثانية عدّاد كلٍّ منهما
اثنان: واحدٌ من المتغيّر المحلّيّ، وواحدٌ من الأخرى. فلمّا مات المتغيّران صار كلٌّ
منهما بعدّادٍ واحد **يمسكه الميّت الآخر**.

**فذاكرتهما لم تُحرَّر، و`Drop` لم تعمل، والبرنامج انتهى وهو لا يعرف.** وهذا تسريبٌ
حقيقيّ في الكود الآمن — والأمان في Rust يمنع الوصول الفاسد، **ولا يعِد بأن كل
شيءٍ سيُحرَّر**.

## `Weak` — إشارةٌ لا تملك

الحلّ أن يكون أحد الطرفين غير مالك:

<!-- part: 09-weak -->

```rust
struct Node {
    name: &'static str,
    child: RefCell<Option<Rc<Node>>>,
    parent: RefCell<Weak<Node>>,
}

// … ثم:
*parent.child.borrow_mut() = Some(Rc::clone(&child));
*child.parent.borrow_mut() = Rc::downgrade(&parent);
```

<!-- out -->

```
قويّ: أب=1 ابن=2
ضعيف على الأب: 1
الصعود إلى الأب: Some("الأب")
مات الأب
مات الابن
— انتهى النطاق —
```

**عدّادان لا واحد:** القويّ يقرّر متى تموت القيمة، والضعيف يشير إليها بلا أن
يبقيها.

و`upgrade` تُرجع `Option<Rc<T>>`: **`Some` إن كانت حيّة، و`None` إن ماتت.** فصار
المؤشّر المتدلّي حالةً تُطابَق، لا انهياراً.

**والقاعدة:** المِلكية تنزل، والإشارة تصعد. الأب يملك أبناءه، والابن يشير إلى أبيه
بـ`Weak`.

## و`Rc` لا تعبر إلى خيط

سطران يفرّقان بين `Rc` و`Arc`:

```rust
use std::rc::Rc;
use std::thread;

fn main() {
    let shared = Rc::new(vec![1, 2, 3]);
    let h = thread::spawn(move || shared.len());
    println!("{}", h.join().unwrap());
}
```

<!-- err: E0277 -->

```
error[E0277]: `Rc<Vec<i32>>` cannot be sent between threads safely
 --> h10.rs:7:27
  |
7 |     let h = thread::spawn(move || shared.len());
  |             ------------- -------^^^^^^^^^^^^^
  |             |             |
  |             |             `Rc<Vec<i32>>` cannot be sent between threads safely
  |             |             within this `{closure@h10.rs:7:27: 7:34}`
  |
  = help: within `{closure@h10.rs:7:27: 7:34}`, the trait `Send` is not implemented for `Rc<Vec<i32>>`
note: required by a bound in `spawn`
```

**عدّاد `Rc` عددٌ عاديّ**: زيادتان من خيطين قد تعطيان واحدة، فيموت المشترَك ومعه
مؤشّرات حيّة. ولهذا لا تحمل `Rc` سمة `Send`.

و`Arc` نظيرتها بعدّادٍ **ذرّيّ**، وتعبر. وثمنها في كل نسخةٍ وكل موت — **وهذا سببُ
وجود الاثنتين**: من يعمل في خيطٍ واحد لا يدفع.

**والحارس هنا سمةٌ فارغة.** لا كلمةَ محجوزة ولا فحصَ خاصّ: `Send` علامة، والمترجم
يمنع بها ما يمنع.

## المفكِّك: جدولٌ يمسكه اثنان

المُحلِّل يسجّل الأسماء، والحاسب يقرؤها. وكلاهما يمسك الجدول نفسه:

<!-- part: 09-symbols -->

```rust
type Shared = Rc<RefCell<Symbols>>;

struct Parser { syms: Shared }
struct Evaluator { syms: Shared, values: HashMap<usize, i64> }

impl Parser {
    fn read(&self, src: &str) -> Vec<usize> {
        src.split_whitespace()
            .map(|w| self.syms.borrow_mut().intern(w))
            .collect()
    }
}
```

<!-- out -->

```
معرّفات: [0, 1, 0]
عدد الرموز: 2
سعر=12
كمّية=30
مالكون: 3
```

**«سعر» مرّتان في النصّ، ومعرّفٌ واحد.** و`intern` تحوّل الاسم إلى رقم مرّةً
واحدة، فتصير الموازنة عدداً بدل نصّ.

ولاحظ `read(&self)` — **تعديلٌ خلف مرجع قراءة**. هذا ما اشترته `RefCell`: توقيعٌ
لا يعلن `&mut`، وتعديلٌ يقع فعلاً. **وهو ما يجعلها خطرةً في واجهةٍ عامّة**: من قرأ
التوقيع لن يتوقّع أن الاستدعاء يغيّر شيئاً.

**والعدّاد ثلاثة:** الأصل ونسختان. ولو أضفتَ ثالثاً لصار أربعة، بتخصيصٍ صفر.

## بذرة

نقلتَ في هذا الإقليم قاعدتين إلى وقت التشغيل: المِلكية بـ`Rc`، والاستعارة
بـ`RefCell`. ودفعتَ ثمنهما عدّاداً وذعراً وتسريباً محتملاً.

وفي آخر شوطٍ ظهرت كلمةٌ لم تُشرَح: **`Send`** — سمةٌ فارغة منعت `Rc` من العبور.

فما الذي يجعل نوعاً صالحاً للعبور؟ ومن يقرّر؟ **وهل يكفي `Arc` وحده لتشارك
البيانات بين خيطين؟**

**الإقليم القادم عن الخيط.** وستجد فيه أن كل ما بناه المترجم في تسعة أقاليم —
المِلكية والاستعارة والأعمار — **كان هو نفسه ما يمنع سباق البيانات**، وأن اللغة
لم تُضِف لأجل التزامن إلا سمتين فارغتين.
