# الإقليم ٠٧ — السمة

> `#[derive(Debug)]` سطرٌ كتبتَه ست مرّاتٍ ولم تسأل ماذا يفعل. و`Iterator` أعطت
> مفكِّكك `for` و`collect` و`map` مجّاناً. و`Display` جعلت خطأك يُطبَع بلغتك.
>
> **الثلاثة شيءٌ واحد: سمة.** وهي في Rust مكان الوراثة والواجهات معاً — بلا شجرة
> أنواع، وبقرارٍ في الإرسال تملكه أنت.

## البذرة: `Debug` ليست سحراً

`derive` تكتب لك تنفيذاً. واكتب أنت التنفيذ الثاني بيدك:

```rust
use std::fmt;

#[derive(Debug)]
enum Expr {
    Num(i64),
    Add(Box<Expr>, Box<Expr>),
    Mul(Box<Expr>, Box<Expr>),
}

impl fmt::Display for Expr {
    fn fmt(&self, f: &mut fmt::Formatter<'_>) -> fmt::Result {
        match self {
            Expr::Num(n) => write!(f, "{n}"),
            Expr::Add(a, b) => write!(f, "({a} + {b})"),
            Expr::Mul(a, b) => write!(f, "({a} * {b})"),
        }
    }
}

fn main() {
    let t = Expr::Add(
        Box::new(Expr::Num(12)),
        Box::new(Expr::Mul(Box::new(Expr::Num(30)), Box::new(Expr::Num(2)))),
    );
    println!("Debug  : {t:?}");
    println!("Display: {t}");
    println!("داخل نصّ: {}", format!("النتيجة لـ{t}"));
}
```

<!-- out -->

```
Debug  : Add(Num(12), Mul(Num(30), Num(2)))
Display: (12 + (30 * 2))
داخل نصّ: النتيجة لـ(12 + (30 * 2))
```

**عشرة أسطر أعطت الشجرة صورةً بشرية**، وأعطتها معها `to_string()` و`format!`
والدخول في أي نصّ — لأن كلّها مبنيّةٌ على `Display`.

ولاحظ `{a}` داخل `write!`: **الاستدعاء ذاتيّ** ويمرّ بنفس السمة. `derive` تفعل هذا
بالضبط، وتكتبه عنك حين يكفيك الشكل الحرفيّ.

## السمة عقدٌ، وفيه ما لا تكتبه

الطريقة الافتراضية تُكتب مرّةً في السمة، ويأخذها كل منفِّذ:

```rust
use std::any::type_name;

/// اسم النوع بلا بادئة الحزمة — البادئة اسمُ ملفّك أنت.
fn short<T: ?Sized>() -> &'static str {
    type_name::<T>().rsplit("::").next().unwrap()
}

trait Weigh {
    fn weight(&self) -> usize;

    /// طريقةٌ افتراضية — من ينفّذ السمة يأخذها بلا كتابة.
    fn label(&self) -> String {
        format!("{} بوزن {}", short::<Self>(), self.weight())
    }
}

struct Word(String);
struct Num(i64);

impl Weigh for Word {
    fn weight(&self) -> usize { self.0.len() }
}

impl Weigh for Num {
    fn weight(&self) -> usize { self.0.unsigned_abs().to_string().len() }
}

fn describe<T: Weigh>(x: &T) -> String {
    format!("[{}] {}", short::<T>(), x.label())
}

fn main() {
    println!("{}", describe(&Word(String::from("سعر"))));
    println!("{}", describe(&Num(1200)));
}
```

<!-- out -->

```
[Word] Word بوزن 6
[Num] Num بوزن 4
```

**والاسمان في المخرَج دليل التوحيد الشكليّ.** `describe` دالّةٌ واحدة في المصدر،
وفي الملفّ التنفيذيّ **نسختان**: واحدةٌ `T = Word` وأخرى `T = Num`.

فلا بحثَ عن الطريقة وقت التشغيل، ولا مؤشّر دالّة. **الاستدعاء مباشر، وقابلٌ
للتضمين كأي دالّةٍ عادية** — وهذه هي البديهية الخامسة في العمل.

## `dyn` — حين لا تُعرف الأنواع مسبقاً

توحيدٌ شكليّ لكل نوعٍ يعني أن المتّجه يحمل نوعاً واحداً. فماذا لو أردتَ خليطاً؟

<!-- part: 07-dyn -->

```rust
use std::mem::size_of;

fn main() {
    let items: Vec<Box<dyn Weigh>> = vec![
        Box::new(Word(String::from("سعر"))),
        Box::new(Num(1200)),
        Box::new(Word(String::from("مجموع"))),
    ];

    let total: usize = items.iter().map(|x| x.weight()).sum();
    println!("مجموع الأوزان: {total}");

    println!("&Word          : {}", size_of::<&Word>());
    println!("&dyn Weigh     : {}", size_of::<&dyn Weigh>());
    println!("Box<dyn Weigh> : {}", size_of::<Box<dyn Weigh>>());
}
```

توقّع الأرقام الثلاثة.

المخرَج:

```
مجموع الأوزان: 20
&Word          : 8
&dyn Weigh     : 16
Box<dyn Weigh> : 16
```

**ستّ عشرة، لا ثمانٍ.** `&dyn Weigh` مؤشّران: واحدٌ إلى القيمة، وآخر إلى **جدول
الطرق** (vtable) الخاصّ بنوعها.

فحلّ الطريقة انتقل إلى وقت التشغيل: قراءةٌ من الجدول ثم قفزٌ غير مباشر. وهذا هو
الثمن، **وهو ثمنُ اختيارك** — لا ضريبةٌ تدفعها اللغة عنك في كل استدعاء.

## والفرق مقيسٌ لا مقدَّر

جمعُ وزنٍ على مليونَي عنصر، خمسين مرّة، بالتمثيلين:

<!-- runs: 07-dispatch-bench -->

```rust
fn sum_static<T: Weigh>(v: &[T]) -> usize {
    v.iter().map(|x| x.weight()).sum()
}

fn sum_dyn(v: &[Box<dyn Weigh>]) -> usize {
    v.iter().map(|x| x.weight()).sum()
}
```

<!-- out: بـ`-O`؛ والأزمنة تختلف عندك، والثابت هو النسبة -->

```
ثابت : 14.484167ms
ديناميّ: 101.003375ms
النسبة: 7.0×
```

**واقرأ هذا الرقم بحذر.** كرّرتُ القياس ثلاث مرّات فخرجت النسبة بين ٥٫٨ و٧٫٦.
**وبلا `-O` صارت ١٫٠×** — أي أن الفارق كلّه من أشياءٍ يفعلها المُحسِّن للنسخة
الثابتة ولا يستطيعها مع الجدول: التضمين، ثم التوجيه الشعاعيّ للحلقة.

فهذه **أفضل حالةٍ للثابت**، لا متوسّط. وحلقةٌ تفعل عملاً حقيقياً في كل عنصر
تُخفي هذا الفارق تماماً.

**والقاعدة العملية:** ابدأ بالعامّ، وانتقل إلى `dyn` حين تحتاج خليطاً أو تريد
تقليل حجم الملفّ التنفيذيّ. **وقِس قبل أن تعود.**

## وليست كل سمةٍ تصلح لـ`dyn`

أضِف طريقةً عامّة إلى السمة، ثم حاول:

```rust
trait Weigh {
    fn weight(&self) -> usize;
    fn compare<T: Weigh>(&self, other: &T) -> bool {
        self.weight() > other.weight()
    }
}
```

**السبب هندسيّ محض:** الجدول مصفوفةُ مؤشّراتٍ مبنيّةٌ وقت الترجمة. والطريقة العامّة
تحتاج مدخلاً لكل `T` تُستدعى به، **وعددها غير محدود**.

ومعها قاعدتان أخريان: لا طريقةٌ تُرجع `Self` بالقيمة، ولا دالّةٌ بلا `self`. والحلّ
دائماً واحد: **انقل ما يمنع إلى سمةٍ ثانية**.

## التنفيذ الشامل

`impl` على **كل نوعٍ يحقّق شرطاً**:

```rust
use std::fmt::Display;

trait Shout {
    fn shout(&self) -> String;
}

impl<T: Display> Shout for T {
    fn shout(&self) -> String {
        format!("<<{self}>>")
    }
}

fn main() {
    println!("{}", 12.shout());
    println!("{}", "سعر".shout());
    println!("{}", 3.5.shout());
    println!("{}", String::from("مملوك").shout());
}
```

<!-- out -->

```
<<12>>
<<سعر>>
<<3.5>>
<<مملوك>>
```

**أربعة أنواعٍ لم أذكر واحداً منها بالاسم.** كل ما ينفّذ `Display` أخذ `shout`،
والعدد مفتوحٌ لأنواعٍ لم تُكتب بعد.

وهذا ما يجعل `ToString` تعمل على كل شيءٍ يُطبَع: **تنفيذها في المكتبة سطرٌ شامل
واحد**، ومن نفّذ `Display` أخذها.

## قاعدة اليتيم

جرّب أن تعطي `Vec<i64>` صورةً بشرية:

```rust
impl std::fmt::Display for Vec<i64> {
    fn fmt(&self, f: &mut std::fmt::Formatter<'_>) -> std::fmt::Result {
        write!(f, "{} عنصراً", self.len())
    }
}
```

**السمة غريبة والنوع غريب، فلا يجوز.** ولو جاز لاستطاعت حزمتان أن تعطيا `Vec<i64>`
تنفيذين مختلفين لـ`Display`، **ولانكسر برنامجٌ لمجرّد أنه ضمّ الاثنتين**.

والحلّ في آخر سطرٍ من الرسالة: **نوعٌ محلّيّ يلفّ الغريب** — `struct Rows(Vec<i64>)`
— فيصير النوع لك. وهو نمطٌ سترى `Money` منه في الشوط التالي.

## العوامل سماتٌ كذلك

`+` ليست كلمةً محجوزة: هي استدعاء `Add::add`.

<!-- part: 07-operators -->

```rust
use std::ops::{Add, Index};

#[derive(Debug, Clone, Copy, PartialEq)]
struct Money(i64);

impl Add for Money {
    type Output = Money;
    fn add(self, rhs: Money) -> Money {
        Money(self.0 + rhs.0)
    }
}

struct Row(Vec<Money>);

impl Index<usize> for Row {
    type Output = Money;
    fn index(&self, i: usize) -> &Money {
        &self.0[i]
    }
}
```

<!-- out -->

```
42 ريال
true
30 ريال
```

**و`Money` نوعٌ محلّيّ يلفّ `i64`** — فجاز عليه ما لم يجز على `Vec`. وهذا هو نمط
النوع الجديد الذي أشارت إليه الرسالة قبل قليل.

ولاحظ `type Output`: **نوعٌ مرافق**، يقرّره المنفِّذ. فجمع `Money + Money` يعطي
`Money`، ويستطيع نوعٌ آخر أن يُرجع شيئاً مختلفاً تماماً.

## النوع المرافق مقابل معامل النوع

`Iterator` مبنيّةٌ على مرافقٍ واحد، وهو سبب عمل كل شيءٍ عليها:

```rust
struct Counter { at: u32, end: u32 }

impl Iterator for Counter {
    type Item = u32;

    fn next(&mut self) -> Option<u32> {
        if self.at >= self.end { return None; }
        self.at += 1;
        Some(self.at)
    }
}

fn evens(end: u32) -> impl Iterator<Item = u32> {
    Counter { at: 0, end }.filter(|x| x % 2 == 0)
}

fn main() {
    let v: Vec<u32> = Counter { at: 0, end: 5 }.collect();
    println!("{v:?}");
    println!("{}", Counter { at: 0, end: 100 }.sum::<u32>());
    println!("{:?}", evens(10).collect::<Vec<_>>());
}
```

<!-- out -->

```
[1, 2, 3, 4, 5]
5050
[2, 4, 6, 8, 10]
```

**خمسةَ عشرَ سطراً أعطت `collect` و`sum` و`filter`** — والمكتبة كلّها.

والفرق عن معامل النوع: `Iterator<Item = u32>` **مرافق**، فللنوع الواحد تنفيذٌ واحد
بعنصرٍ واحد. ولو كان معاملاً (`Iterator<u32>`) لجاز أن ينفّذ `Counter` السمة مرّةً
بـ`u32` ومرّةً بـ`String`، **ولما عرف `collect` أيّهما يقصد**.

و`impl Iterator<Item = u32>` في المُرجَع تقول: «نوعٌ يحقّق هذا، ولن أسمّيه» —
والنوع الحقيقيّ الذي تبنيه `filter` اسمٌ طويل لا يعني القارئ شيئاً.

## المفكِّك: طيٌّ واحد، وثلاثة تفسيرات

`eval` تمشي في الشجرة، و`Display` تمشي فيها، وقياس العمق يمشي فيها. **مشيةٌ واحدة
وثلاثة أجوبة** — والمرافق هو ما يفصلها:

<!-- part: 07-fold -->

```rust
trait Fold {
    type Out;
    fn num(&self, n: i64) -> Self::Out;
    fn add(&self, a: Self::Out, b: Self::Out) -> Self::Out;
    fn mul(&self, a: Self::Out, b: Self::Out) -> Self::Out;
}

fn walk<F: Fold>(f: &F, e: &Expr) -> F::Out {
    match e {
        Expr::Num(n) => f.num(*n),
        Expr::Add(a, b) => { let (x, y) = (walk(f, a), walk(f, b)); f.add(x, y) }
        Expr::Mul(a, b) => { let (x, y) = (walk(f, a), walk(f, b)); f.mul(x, y) }
    }
}
```

<!-- out: بمنفِّذات `Calc` و`Show` و`Depth` -->

```
(12 + (30 * 2))
= 72
عمقها 3
```

`Calc::Out = i64`، و`Show::Out = String`، و`Depth::Out = usize`. **والمشية مكتوبةٌ
مرّة**، فإضافة شكلٍ جديد إلى `Expr` تكسر `walk` وحدها.

**والثلاثة موحَّدةٌ شكلياً**: `walk` صارت ثلاث دوالّ في الملفّ التنفيذيّ، كلٌّ
منها تعرف نوع مخرَجها ولا تلمس جدولاً.

## بذرة

`Counter` نفّذت `Iterator` في خمسة عشر سطراً، فجاءت `filter` و`collect` و`sum` بلا
سطرٍ إضافيّ.

لكن `evens(10)` بنت سلسلةً من ثلاث طبقات — عدّادٌ ثم مرشّح ثم جامع. **فهل مرّت
الأرقام ثلاث مرّات؟ وأين خُزِّنت بينها؟**

والسؤال أحدّ من ذلك: `(0..u32::MAX).filter(...).take(3)` تنتهي فوراً. **فمن أوقف
العدّ؟**

**الإقليم القادم عن الكسل** — وفيه تقيس بنفسك كم مرّةً مرّ العنصر، وكم تخصيصاً
كلّفت السلسلة.
