# الإقليم ٠٩ — «اشتغل عندي»

> مخزنك يقفل قبل كل كتابة. ولم نسأل يوماً: **ما الذي يضمن أن ما كتبتْه goroutine
> يراه غيرها أصلاً؟**
>
> السؤال يبدو تافهاً — كُتب في الذاكرة، فليُقرأ منها. وهو ليس كذلك: بينك وبين
> الذاكرة مسجّلاتٌ ومخابئ ومترجمٌ يُعيد ترتيب سطورك.
>
> هذا الإقليم عن **الضمان**: ما تعِد به اللغة نصّاً، وما لا تعِد به أبداً. وعن
> أخطر جملةٍ في هذا المجال.

---

## أربع زياداتٍ بلا قفل

```go
package main

import (
	"fmt"
	"sync"
)

var count int

func main() {
	var wg sync.WaitGroup

	for i := 0; i < 4; i++ {
		wg.Add(1)
		go func() {
			defer wg.Done()
			count++
		}()
	}

	wg.Wait()
	fmt.Println(count)
}
```

أربع `goroutines`، كلٌّ تزيد واحداً، و`wg.Wait()` تنتظرهنّ. ولا قفل.

**شغّله.** ثم شغّله عشراً. غالباً سترى `4` في كل مرّة.

<!-- notice: مخرَجٌ غير حتميّ. ما تحته إحصاءُ خمسة آلاف تشغيلة على جهاز المؤلّف، لا تشغيلةٌ واحدة. -->

<!-- out: من إحصاء خمسة آلاف تشغيلة لا من تشغيلةٍ واحدة — عمودُ التكرار ثم القيمة -->

```
  89   →  3
4911   →  4
```

## ثمانيةٌ وتسعون في المئة

**١٫٨٪ من التشغيلات أعطت `3`.**

واحدةٌ من كل ستٍّ وخمسين. أي أنك لو شغّلته في التطوير خمسين مرّة، **لرأيتَ الجواب
الصحيح خمسين مرّة**. ولو كتبتَ له اختباراً لمرّ. ولو راجعه زميلك لقال «يعمل».

ثم يقع في الإنتاج، حيث يُنفَّذ ملايين المرّات على عتادٍ آخر بأحمالٍ أخرى.

**وهذا معنى «اشتغل عندي»:** ليست الجملة كذباً — هي **قياسٌ لا يقيس شيئاً**. لأن
الاختبار يكشف وجود العطب ولا يكشف غيابه، وفي التزامن تكون فجوة الكشف بحجم
مليون تشغيلة.

`count++` ليست عملية واحدة: **اقرأ، زِد، اكتب**. وحين تتشابك ثلاث خطواتٍ من
أربع `goroutines`، تضيع زيادةٌ حين تكتب الثانية فوق ما قرأته قبل أن تكتب الأولى.

**والسؤال الصحيح ليس «هل يعمل؟» بل «هل هذا معرَّف؟»**

## ما تقوله المواصفة

لـGo **نموذج ذاكرةٍ مكتوب**، وهو وثيقةٌ قصيرة تُعرّف متى تكون كتابةٌ **مرئيّةً**
لقارئٍ آخر. ولا تعِد بشيءٍ خارجها.

وأصرح ما فيها:

> **سباق البيانات** أن تكتب `goroutine` في موضعٍ بينما تقرأ أو تكتب فيه أخرى، بلا
> علاقة **مزامنةٍ** بينهما.
>
> والبرنامج الذي فيه سباق بيانات **لا سلوك معرَّفاً له** عند ذلك الموضع.

**«لا سلوك معرَّف»** لا تعني «قيمةً قديمة» ولا «رقماً خاطئاً». تعني أن المترجم
والمعالج أُطلقت يدهما: يُعيدان ترتيب السطور، ويحتفظان بالقيمة في مسجّل، ويطويان
حلقةً كاملة.

فبرنامجك أعلاه **ليس برنامجاً يعطي `3` أحياناً**. هو برنامجٌ **بلا معنى**، وقد صادف
أن أعطى `4` في ٩٨٪.

## ما يقيمه ضماناً

الوثيقة تسمّي العلاقات التي **تصنع** المزامنة. وأهمّها ثلاث، منقولةً عن نصّها:

> **الإرسال في قناة مزامَنٌ قبل اكتمال الاستقبال المقابل منها.**
>
> **وإغلاق قناة مزامَنٌ قبل استقبالٍ يُرجع القيمة الصفرية بسبب الإغلاق.**

وثالثةٌ عن الأقفال: فتحُ قفلٍ مزامَنٌ قبل أيّ إقفالٍ لاحقٍ له.

```
goroutine A            goroutine B
  a = "hello"
  c <- 0        ──────►  <-c
                          print(a)     ← يرى "hello" مضموناً
```

**فالقفل والقناة لا يمنعان التشابك فقط.** هما ما **يجعل الكتابة مرئيّة** أصلاً.
ومن ظنّ أن القفل «تنظيم دور» فقد نصف وظيفته.

**وكل ما ليس في تلك القائمة ليس ضماناً:** لا `time.Sleep`، ولا ترتيب السطور في
مصدرك، ولا «هي `goroutine` واحدة تكتب فقط».

## أداةٌ ترى ما لا تراه

لا تعتمد على عينك. الـruntime يستطيع أن يراقب كل وصولٍ للذاكرة ويخبرك:

```bash
go run -race main.go
```

<!-- out: الكتلة الأولى فقط من عدّة كتل، ومسار الملفّ مختصَر -->

```
==================
WARNING: DATA RACE
Read at 0x000100b4b690 by goroutine 8:
  main.main.func1()
      .../main.go:17 +0x68

Previous write at 0x000100b4b690 by goroutine 9:
  main.main.func1()
      .../main.go:17 +0x80
==================
```

**عنوانٌ واحد، وقراءةٌ وكتابةٌ بلا مزامنةٍ بينهما، ورقم السطر.** هذا هو التقرير
كلّه، وهو كافٍ.

والكاشف مبنيٌّ على **نموذج الذاكرة نفسه**: يبني علاقات «مزامَنٌ قبل» أثناء التشغيل،
ثم يبلّغ عن كل زوجٍ لا علاقة بينهما. وهذا مثالٌ على ما قلناه في الفصل صفر —
أداةٌ كهذه تحتاج لغةً تملك تزامنها.

## وحدُّها الذي يجب أن تعرفه

**الكاشف ديناميكيّ لا ساكن.** لا يقرأ كودك — يراقب ما جرى فعلاً.

فهو لا يبلّغ إلا عن سباقٍ **وقع في تلك التشغيلة**. والسطر الذي لم يُنفَّذ لا يُفحَص،
والتشابك الذي لم يحدث لا يُرى.

| | |
|---|---|
| **لا إنذار كاذب** | ما بلّغ عنه سباقٌ **حقيقيّ**. لا تجادله |
| **وإنذارٌ ناقص** | صمتُه ليس شهادة براءة |
| **والثمن** | أبطأ ٢–٢٠ ضعفاً، وذاكرةٌ أضعاف. **لا يُشغَّل في الإنتاج** |

**فاستعمله حيث تكثر التشابكات:** في الاختبارات (`go test -race`)، وفي بيئة
التكامل، وتحت حملٍ اصطناعيّ. ولا تكتفِ بتشغيلةٍ واحدة على المسار السعيد.

## الذرّيّ

للحالة البسيطة — عدّادٌ أو علَم — لا تحتاج قفلاً. `sync/atomic` يعطيك عمليات
**غير قابلةٍ للتقسيم**:

```go
package main

import (
	"fmt"
	"sync"
	"sync/atomic"
)

var count atomic.Int64

func main() {
	var wg sync.WaitGroup

	for i := 0; i < 100; i++ {
		wg.Add(1)
		go func() {
			defer wg.Done()
			count.Add(1)
		}()
	}

	wg.Wait()
	fmt.Println(count.Load())
}
```

<!-- out -->

```
100
```

مئةٌ، ومئةٌ دائماً. `Add` تقرأ وتزيد وتكتب **في تعليمةٍ واحدة لا تُقسَم**، وتُقيم
علاقة المزامنة التي يطلبها النموذج.

**والأنواع الجديدة `atomic.Int64` و`atomic.Bool` أفضل من الدوال القديمة**
(`atomic.AddInt64`) لسببٍ واحد: النوع نفسه يمنع أن تلمس القيمة بلا ذرّيّة. فلا
يوجد `count` عاريةٌ يمكن أن تُقرأ بـ`=` بالغلط.

## الذرّيّ لا يجعل التسلسل ذرّياً

وهذه نفس مصيدة «افحص ثم افعل» التي رأيتَها مع القفل، بلباس `atomic`:

```go
if flag.Load() == 0 {   // ذرّيّة
    flag.Store(1)       // ذرّيّة
}                       // ← والمجموع ليس ذرّياً
```

بين السطرين فجوة. والعلاج عمليةٌ واحدة تفعل الاثنين:

```go
package main

import (
	"fmt"
	"sync"
	"sync/atomic"
)

var initialized atomic.Int32
var winners atomic.Int32

func main() {
	var wg sync.WaitGroup

	for i := 0; i < 1000; i++ {
		wg.Add(1)
		go func() {
			defer wg.Done()
			if initialized.CompareAndSwap(0, 1) {
				winners.Add(1)
			}
		}()
	}

	wg.Wait()
	fmt.Println("من فاز بالتهيئة:", winners.Load())
}
```

ألف `goroutine` تتسابق على تهيئةٍ واحدة. **توقّع الرقم.**

المخرَج:

```
من فاز بالتهيئة: 1
```

## فائزٌ واحد، دائماً

`CompareAndSwap(0, 1)` تقول: **إن كانت القيمة صفراً فاجعلها واحداً، وأخبرني هل
فعلتَ** — والاثنان في تعليمةٍ واحدة لا يدخل بينها أحد.

فمهما بلغ عدد المتسابقين، تنجح واحدةٌ ويفشل الباقي. **بلا قفل، وبلا حجب.**

وللحالة الشائعة — «هيّئ مرّةً» — لا تكتب هذا بيدك:

```go
var once sync.Once
once.Do(func() { … })
```

`sync.Once` تضمن **التنفيذ مرّةً واحدة**، وتضمن أيضاً أن كل من ينادي `Do` **يرى
أثر التهيئة** بعد رجوعها — وهذا الضمان الثاني هو ما ينساه من يكتبها بيده بعلَمٍ
`bool`.

## هيّئ مرّةً، ولتَرَ الألف

`CompareAndSwap` تضمن فائزاً واحداً. و`sync.Once` تضمن ذلك **وشيئاً ثانياً**:

```go
package main

import (
	"fmt"
	"sync"
)

var (
	once  sync.Once
	value int
	calls int
)

func main() {
	var wg sync.WaitGroup
	var seen sync.Map

	for i := 0; i < 1000; i++ {
		wg.Add(1)
		go func() {
			defer wg.Done()
			once.Do(func() {
				calls++
				value = 42
			})
			seen.Store(value, true)
		}()
	}

	wg.Wait()

	n := 0
	seen.Range(func(k, v any) bool { n++; return true })
	fmt.Println("نُفِّذت:", calls, "· القيمة:", value, "· قيمٌ مختلفة رآها الألف:", n)
}
```

`calls++` و`value = 42` **بلا قفل**، وألفُ `goroutine` تقرأ `value` بعد `Do`.
توقّع الأرقام الثلاثة — وانتبه للثالث.

المخرَج:

```
نُفِّذت: 1 · القيمة: 42 · قيمٌ مختلفة رآها الألف: 1
```

## الضمان الثاني هو المهمّ

الأول متوقَّع: نُفِّذت مرّة.

**والثالث هو الجائزة:** الألف كلّهم رأوا `42`. ولا واحد منهم رأى صفراً.

لأن `Once.Do` **لا ترجع حتى يكتمل التهيئة ويصير مرئيّاً**: هي تُقيم علاقة «مزامَنٌ
قبل» بين جسم الدالّة وكل رجوعٍ لاحق من `Do`. فالكتابة بلا قفل داخلها **آمنة**،
وهذا ليس صدفة.

ومن كتبها بيده بعلَمٍ `bool`:

```go
if !initialized {        // ← لا مزامنة
    value = 42
    initialized = true   // ← وقد يُرى قبل value
}
```

حصل على الضمان الأول وفقد الثاني — **فيرى بعضهم `initialized == true` و`value ==
0`**. و`go test -race` يمسكه، وهذا البرنامج أعلاه يمرّ عنده نظيفاً.

## الفحص الذي يمسك الأخطاء البنيوية

الكاشف ديناميكيّ، و`go vet` ساكن. وبينهما تُغطّى معظم الحالات:

```bash
go vet ./...
```

`vet` يمسك ما **يظهر في البنية** بلا تشغيل: قفلٌ يُنسَخ بالقيمة (رأيتَه في إقليم
القفل) · `sync.WaitGroup` تُمرَّر نسخةً · دالّةٌ مؤجَّلة داخل حلقة · وسائط `Printf`
لا تطابق صيغتها.

**والثلاثة معاً هي المنظومة:**

| الأداة | ماذا تمسك | متى |
|---|---|---|
| `go vet` | أخطاء بنيوية | كل بناء |
| `go test -race` | سباقاتٌ **وقعت فعلاً** | كل اختبار |
| مراجعة النموذج | ما لا تمسكه أداة | عند التصميم |

**ولا تُغني الثالثة عن الأوليين، ولا تُغنيان عنها.**

## بذرة

نموذج الذاكرة مفهوم الآن: ما يُعَدّ ضماناً، وما ليس كذلك، وكيف تُقاس.

وننتقل من داخل البرنامج إلى شكله. مخزنك ملفٌّ واحد في `package main`. وفي
الحقيقة يسكن حزمةً، وتستوردها حزم، ولها ترتيب تهيئةٍ ولحظة بناء.

الإقليم القادم: **الحزمة والبناء** — لماذا تُمنَع الدورات بين الحزم، ومن يُهيَّأ
أوّلاً، وما الذي يدخل ملفّك التنفيذيّ فعلاً.
