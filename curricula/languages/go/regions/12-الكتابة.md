# الإقليم ١٢ — كيف تُكتب Go

> فكّكتَ المخزن أحد عشر فصلاً: تعرف لماذا كل سطرٍ فيه كذلك، وما ثمنه، وأين ينتهي
> ضمانه.
>
> ويبقى سؤالٌ لم يُطرَح: **لو سلّمتَه لغيرك، هل يقبله؟** لأن الكود الذي يعمل شيء،
> والكود الذي يُقرأ ويُختبَر ويُصان شيءٌ آخر. وهذا الفصل عن الثاني: تخطيط الحزمة،
> والتسمية، والتوثيق، والاختبار، والمقياس، والأدوات التي تمسك ما يمرّ من المترجم.
>
> والمادّة هي مخزنك نفسه، يُعاد كتابته باصطلاح اللغة. **والفرق بين النسختين هو
> الدرس.**

## من ملفٍّ إلى حزمة

مخزنك كلّه في `main.go` تحت `package main`. وفي أي مشروعٍ يكبر سيسكن حزمةً
مستقلّة، فيتغيّر شيئان فوراً: **ما يراه المستعمِل، وكيف يناديه**.

```
store/
├── go.mod          module example.com/store
├── store.go        النوع وطرقه — package store
└── store_test.go   package store_test
```

والاسم المصدَّر يُقرأ **مسبوقاً باسم الحزمة دائماً**. فالدالّة التي سمّيتَها
`NewStore` تُنادى هكذا:

```go
s := store.NewStore(sink, 8)   // store store
s := store.New(sink, 8)        // store.New
```

**اسم الحزمة جزءٌ من اسم كل شيءٍ فيها.** ولذلك تُحذف الكلمة المكرّرة: `store.New`
لا `store.NewStore`، و`http.Get` لا `http.HTTPGet`. وهذه أوّل قاعدة يمسكها مراجعٌ
في Go، وسببها بصريّ محض — القارئ يرى الاسمين معاً وأنت تكتب واحداً.

**والمكسب:** واجهة الحزمة تقصر بلا أن تفقد معنى، لأن السياق يحمل نصف الاسم.

## الاسم يقصر كلّما ضاق مداه

القاعدة الثانية عكس ما تتوقّعه من C: **كلّما صغُر نطاق الاسم، قصُر**.

| المدى | الاسم | لماذا |
|---|---|---|
| مستقبِل الطريقة | `s` | يظهر في كل سطرٍ من الطريقة، والنوع معلومٌ من التوقيع |
| متغيّرٌ في حلقة | `i`، `r` | حياته ثلاثة أسطر |
| معامِلٌ مصدَّر | `key`، `hint` | يظهر في التوثيق، ويقرؤه من لا يرى الجسد |
| نوعٌ مصدَّر | `Record` | يُقرأ في كل ملفٍّ يستورد الحزمة |

فمستقبِلٌ اسمه `theStore` أو `self` يخالف الاصطلاح، ومعامِلٌ مصدَّر اسمه `h` بدل
`hint` يخالفه أيضاً — **والاتجاهان متعاكسان**.

**والمكسب:** الاسم الطويل في موضعٍ ضيّق ضوضاء، والقصير في موضعٍ واسع لغز. والقاعدة
تحسم أيّهما تكتب بلا نقاش.

## التوثيق جملةٌ تبدأ بالاسم

تعليق التوثيق في Go ليس زخرفة: **`go doc` يقرؤه، وموقع الحزم يعرضه**. وشكله
مُتّفَقٌ عليه — جملةٌ كاملة تبدأ باسم الشيء الموثَّق.

```go
// Put يحفظ value تحت key. ويملك المخزن نسخته الخاصة،
// فتعديل value بعد العودة لا يمسّ المحفوظ.
func (s *Store) Put(key string, value []byte) error {
```

```bash
go doc example.com/store Store.Put
```

<!-- out -->

```
package store // import "example.com/store"

func (s *Store) Put(key string, value []byte) error
    Put يحفظ value تحت key. ويملك المخزن نسخته الخاصة، فتعديل value بعد العودة
    لا يمسّ المحفوظ.
```

**والجملة الثانية هي المهمّة.** التوقيع يقول إن `Put` تأخذ `[]byte`، ولا يقول من
يملكها بعد العودة. **وهذا عقدٌ لا يظهر في النوع** — ملكيّة الذاكرة، وصلاحية القيمة
الصفرية، وأمان الاستعمال المتزامن. مواضعها كلّها التوثيق.

## القيمة الصفرية جزءٌ من العقد

البديهية الأولى تقول إن القيمة الصفرية صالحة. **ومخزنك يخالفها**: `var s Store`
يعطيك خريطةً `nil`، وأوّل `Put` يذعر.

وأمامك بابان، وكلاهما مقبول:

**إمّا أن تجعل الصفر صالحاً** — تُنشئ الخريطة كسولاً داخل `Put` تحت القفل. تكسب
`var s Store` وتدفع فحصاً في كل كتابة.

**وإمّا أن تعلن أنه غير صالح.** سطرٌ في توثيق الحزمة:

```go
// المخزن آمنٌ للاستعمال من goroutines متعدّدة. وقيمته الصفرية غير صالحة:
// استعمل [New].
package store
```

**والخطأ الوحيد هو الصمت.** مستعمِلٌ يرى `Store` ويعرف البديهية الأولى سيكتب
`var s Store` ويثق. والذعر عند التشغيل ثمن سطرٍ لم تكتبه.

**والمكسب:** `[New]` بين قوسين معقوفين رابطٌ في التوثيق المولَّد منذ Go 1.19 —
تكتبه نصّاً ويصير وصلة.

## اقبل واجهة، وأرجِع بنية

انظر إلى توقيع `New`:

```go
func New(sink Sink, hint int) *Store
```

**يقبل واجهةً ويُرجع بنية.** وهذا اصطلاحٌ له سببان مقيسان:

القبول بواجهة يجعل حزمتك تعمل مع ما لم يُكتب بعد — أي منفِّذٍ لـ`Write(Record)
error`. وهذا ما يجعل اختبارك يمرّر `nil` أو عدّاداً من عشرة أسطر بدل ملفٍّ حقيقيّ.

والإرجاع ببنية يبقي كل طريقةٍ مرئيةً للمستدعي وللأدوات. **واجهةٌ مُرجَعة تخفي**:
`Len` تختفي إن أرجعتَ `Sink`، ويصير على المستدعي أن يؤكّد نوعاً ليصل إليها.

**والمكسب:** القاعدة تُغني عن السؤال في كل توقيعٍ تكتبه — الدخول واسع، والخروج
محدّد.

## الاختبار جدولٌ في اللغة نفسها

لا إطار اختبارٍ في Go ولا مكتبة تأكيدات في المكتبة القياسية. الاختبار **دالّة**،
والفشل **نداء**. والشكل الغالب جدول حالاتٍ وحلقة:

```go
tests := []struct {
	name string
	key  string
	want string
	err  error
}{
	{name: "موجود", key: "a", want: "1"},
	{name: "غائب", key: "zz", err: store.ErrNotFound},
	{name: "مفتاح فارغ", key: "", err: store.ErrNotFound},
}

for _, tc := range tests {
	t.Run(tc.name, func(t *testing.T) {
		s := store.New(nil, 4)
		put(t, s, "a", "1")

		got, err := s.AppendValue(nil, tc.key)
		if !errors.Is(err, tc.err) {
			t.Fatalf("AppendValue(%q) err = %v، والمنتظَر %v", tc.key, err, tc.err)
		}
		if string(got) != tc.want {
			t.Errorf("AppendValue(%q) = %q، والمنتظَر %q", tc.key, got, tc.want)
		}
	})
}
```

**وحالةٌ جديدة سطرٌ في الجدول.** هذا هو المكسب كلّه: كلفة إضافة حالةٍ تقترب من
الصفر، فتُضاف الحالات الشاذّة بدل أن تُؤجَّل.

**و`errors.Is(err, nil)` تصحّ** حين `tc.err` صفرية — فحالة النجاح وحالة الفشل
تمرّان بنفس السطر.

## الاسم يصير مسار تنفيذ

`t.Run` تعطي كل حالةٍ اسماً، والأسماء تتشعّب:

```bash

```

اختباران يفشلان بنفس السبب، وبينهما فرق يوم عمل:

```go
if string(got) != "2" {
	t.Error("خطأ في AppendValue")

if want := "2"; string(got) != want {
	t.Errorf("AppendValue(nil, %q) = %q، والمنتظَر %q", "a", got, want)
}
```

--- FAIL: TestClear (0.00s)

## سطر الفشل يشير إلى النداء

الدوالّ المساعدة تُخفي موضع الخطأ. جرّبها: مساعدان متطابقان، والثاني وحده فيه
`t.Helper()`.

<!-- run: no -->

```go
func mustGetNoHelper(t *testing.T, s *store.Store, key, want string) {
	got, _ := s.AppendValue(nil, key)
	if string(got) != want {
		t.Errorf(/* السطر ١٢ */ "AppendValue(%q) = %q، والمنتظَر %q", key, got, want)
	}
}

func mustGet(t *testing.T, s *store.Store, key, want string) {
	t.Helper()
	got, _ := s.AppendValue(nil, key)
	if string(got) != want {
		t.Errorf("AppendValue(%q) = %q، والمنتظَر %q", key, got, want)
	}
}

func TestHelperLine(t *testing.T) {
	s := store.New(nil, 1)
	_ = s.Put("a", []byte("1"))
	mustGetNoHelper(t, s, "a", "2") /* السطر ٢٧ */
	mustGet(t, s, "a", "2")         /* السطر ٢٨ */
}
```

<!-- out -->

```
--- FAIL: TestHelperLine (0.00s)
    h_test.go:12: AppendValue("a") = "1"، والمنتظَر "2"
    h_test.go:28: AppendValue("a") = "1"، والمنتظَر "2"
```

**السطر ١٢ داخل المساعد، والسطر ٢٨ عند النداء.** وحين ينادي عشرون اختباراً نفس
المساعد، يشير الأول إلى موضعٍ واحدٍ عشرين مرّة.

**والمكسب:** سطرٌ واحد يحوّل رسالة الفشل من «فشل شيءٌ ما» إلى «فشل هذا النداء».

## نفس الدالّة، نداءان، وثمنان

`AppendValue(dst, key)` تُلحق بمخزنٍ يملكه المستدعي. وهذا يعني أن **كلفتها تتغيّر
بحسب من يناديها**.

<!-- run: no -->

```go
buf := make([]byte, 0, 64)
for b.Loop() {
	buf, _ = s.AppendValue(buf[:0], "k")   // مخزنٌ يُعاد استعماله
}

for b.Loop() {
	_, _ = s.AppendValue(nil, "k")         // مخزنٌ جديد كل مرّة
}
```

مقياسان، و`go test -bench . -benchmem ./...` يشغّلهما. **توقّع الفرق في عمود
التخصيصات قبل أن تفتح.**

المخرَج:

```
BenchmarkAppendValue-8      	63095232	        18.56 ns/op	       0 B/op	       0 allocs/op
BenchmarkAppendValueNil-8   	42506150	        28.60 ns/op	      16 B/op	       1 allocs/op
```

**صفر تخصيصٍ مقابل واحد، و١٨٫٥٦ نانوثانية مقابل ٢٨٫٦٠.** والفرق كلّه في **موقع
النداء**، والدالّة واحدة. والأزمنة وأعداد التكرار من `Apple M1`، وتختلف عندك —
**والثابت هو عمود التخصيصات**.

**والمكسب:** هذا ما يشتريه توقيعٌ يأخذ `dst`. ولولا `-benchmem` لبقي الادّعاء
رأياً.

## المترجم يقبل، وvet يرفض

ملفٌّ يمرّ من `go build` بلا كلمة:

<!-- run: no -->

```go
package bad

import (
	"fmt"
	"sync"
)

type Store struct {
	mu   sync.RWMutex
	data map[string]string
}

// مستقبِلٌ بالقيمة على نوعٍ فيه قفل.
func (s Store) Len() int {
	return len(s.data)
}

func (s *Store) Describe(key string) string {
	return fmt.Sprintf("%d = %q", key, s.data[key])
}
```

`go build ./...` يمرّ عليه صامتاً. **توقّع ما الذي يقوله `go vet`، وعن أي سطر.**

المخرَج:

```
bad.go:14:9: Len passes lock by value: example.com/bad.Store contains sync.RWMutex
bad.go:19:22: fmt.Sprintf format %d has arg key of wrong type string
```

**الأول درس الإقليم ٠٣ حرفياً:** مستقبِلٌ بالقيمة ينسخ البنية، والبنية فيها قفل،
فالنسخة تحمل قفلاً آخر. **والثاني** خطأ نوعٍ لا يراه المترجم لأن `Sprintf` تأخذ
`...any`.

**والمكسب:** `go vet` جزءٌ من `go test` منذ Go 1.10 — يجري وحده قبل كل اختبار.

## ما يمرّ في الترجمة ويسقط في المراجعة

ثلاثةٌ يقبلها المترجم ويردّها مراجع:

**١) قيمةٌ مصدَّرة تشير إلى داخلك.** `Sink` تستقبل `Record` وفيها `Value []byte`.
والمنفِّذ يستطيع تعديلها.

<!-- run: no -->

```go
func (Mutator) Write(r store.Record) error {
	r.Value[0] = 'X'
	return nil
}
```

توقّع ما الذي يحفظه المخزن بعد `Put("greeting", []byte("hello"))`.

المخرَج:

```
ما يحفظه المخزن الآن: "Xello"
```

**نسخةُ `Record` كاملة، والنسخة الكاملة لرأسٍ فيه مؤشّر تعطي المؤشّر نفسه**
(البديهية الثانية). فإمّا أن تنسخ قبل التسليم، وإمّا أن توثّق أن الوجهة تستلم
ملكيّةً مشتركة.

**٢) `interface{}` في توقيعٍ مصدَّر.** يدفع الفحص من الترجمة إلى التشغيل.

**٣) `context.Context` حقلاً في بنية.** موضعه أوّل معامِلٍ في الدالّة.

## حلقةٌ تُشغَّل قبل الدفع

أربعة أوامر، بهذا الترتيب:

```bash
gofmt -l .          # يطبع أسماء الملفّات غير المنسّقة. الصمت = نظيف
go vet ./...        # ما يقبله المترجم ويرفضه العقل
go test -race ./... # الاختبارات مع كاشف السباقات
go build ./...      # آخر فحص
```

`gofmt` بلا خيارات ولا ملفّ إعدادات — تنسيقٌ واحد للغة كلّها، وقد رأيتَ في الفصل
صفر لماذا اختير هكذا. و`-race` يُبطئ عشرة أضعاف، فموضعه هذه الحلقة لا كل تشغيل.

**والمكسب:** أربعة أسطرٍ تمسك: تنسيقاً مختلفاً، ونسخ قفل، وسباقاً، وكسر ترجمة —
قبل أن يراها أحد.

## المخزن باصطلاح Go

هذا مخزنك، وقد صار حزمة. **لا سطر منطقٍ تغيّر عمّا انتهيتَ إليه في الإقليم ١١** —
تغيّر ما حوله.

<!-- run: no -->

```go
// حزمة store تحفظ قيماً في الذاكرة، وتسجّل كل كتابةٍ في سجلٍّ مرتَّب.
//
// المخزن آمنٌ للاستعمال من goroutines متعدّدة. وقيمته الصفرية غير صالحة:
// استعمل [New].
package store

import (
	"errors"
	"fmt"
	"sync"
)

// ErrNotFound يُرجَع مغلَّفاً حين لا يوجد المفتاح. افحصه بـerrors.Is.
var ErrNotFound = errors.New("store: key not found")

// Record سجلُّ كتابةٍ واحدة.
type Record struct {
	Key     string
	Value   []byte
	Deleted bool
}

// Sink يستقبل كل كتابةٍ ناجحة. يُنادى خارج قفل المخزن،
// فعلى المنفِّذ أن يحمي حالته بنفسه.
type Sink interface {
	Write(Record) error
}

// Store مخزنُ مفتاحٍ وقيمة مع سجلٍّ للكتابات.
type Store struct {
	mu   sync.RWMutex
	data map[string]Record
	log  []Record
	sink Sink
}

// New ينشئ مخزناً يكتب كل تغييرٍ إلى sink. وsink قد يكون nil.
// وhint عددُ المفاتيح المتوقَّع، يُستعمل للحجز المسبق.
func New(sink Sink, hint int) *Store {
	return &Store{
		data: make(map[string]Record, hint),
		log:  make([]Record, 0, hint),
		sink: sink,
	}
}
```

**والباقي — `Put` و`AppendValue` و`Len` — كما كتبتَه في ١١**، بتوثيقٍ فوق كلٍّ
منها.

## ماذا اشترى هذا الفصل

قارن الواجهتين:

```
// الإقليم ٠١            // الإقليم ١٢
NewStore(sink)           store.New(sink, hint)
Get(key) (Record, bool)  AppendValue(dst, key) ([]byte, error)
s.log                    s.Len()
```

| ما تغيّر | ما اشتراه |
|---|---|
| `NewStore` ← `New` | اسمٌ لا يكرّر حزمته |
| `bool` ← `error` يلفّ `ErrNotFound` | سببٌ يُفحَص بـ`errors.Is` عبر حدّ الحزمة |
| `Record` مُرجَعة ← `dst []byte` | صفر تخصيصٍ عند المستدعي، مقيسٌ لا مدَّعى |
| حقلٌ خام ← `Len()` | الداخل يتغيّر بلا كسر مستعمِل |
| بلا توثيق ← جملةٌ فوق كل مصدَّر | ملكيّة الذاكرة والقيمة الصفرية معلومتان |
| بلا اختبار ← جدولٌ ومقياس | الادّعاءات تُفحَص آلياً |

**ولم يتغيّر سطرُ منطقٍ واحد.** ما تغيّر: من يستطيع استعماله بلا أن يسألك.

## بذرة أخيرة

انتهى الطريق. مخزنٌ من ٧٥ سطراً، فُكِّك أحد عشر فصلاً، ثم كُتب كما تُكتب Go.

وثلاثة أشياء تركتُها لك عمداً:

**واحد.** `Len()` تقفل. وقارئٌ يناديها في حلقةٍ ضيّقة يزاحم الكتّاب. **قِس ذلك**،
ثم قرّر: هل تكفي `atomic.Int64` تُحدَّث تحت القفل وتُقرأ خارجه؟

**اثنان.** `Record.Value` مصدَّر ويشير إلى داخل المخزن. أغلِقه — أيّهما تختار:
نسخةٌ عند التسليم، أم حقلٌ غير مصدَّر وطريقةٌ تقرأ؟ ولكلٍّ ثمنٌ صرتَ تعرف كيف
تقيسه.

**ثلاثة.** اكتب `store_test.go` كاملاً بنفسك: حالة الوجهة التي تُخطئ، وحالة
`Put` المتزامنة تحت `-race`، وحالة القيمة الصفرية.

**ثم شغّل الحلقة الأربعة.** فإن سكتت الأربعة، سلّمه.
