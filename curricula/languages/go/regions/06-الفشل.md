# الإقليم ٠٦ — الفشل

> في مخزنك توقيعان يقولان كل شيء:
>
> ```
> func (s *Store) Put(key string, value []byte) error
> func (s *Store) Get(key string) (Record, bool)
> ```
>
> الأولى تُرجع فشلاً **قيمةً**. والثانية تُرجع `bool` لأن الغياب ليس فشلاً.
>
> والسؤال المعلّق منذ الفصل صفر: لماذا تُرجَع الأخطاء ولا تُرمى؟ ومتى يُذعَر إذن؟
> ومن أين جاء أشهر فخٍّ في هذه اللغة؟

---

## الفشل قيمة

`error` واجهةٌ بطريقةٍ واحدة، ولا شيء فيها من اللغة. وأبسط استعمالٍ لها **خطأٌ
حارس**: قيمةٌ وحيدة تُنشَأ مرّةً ويُقارَن بها.

```go
package main

import (
	"errors"
	"fmt"
)

var ErrNotFound = errors.New("not found")

func get(key string) error {
	if key == "" {
		return ErrNotFound
	}
	return nil
}

func main() {
	err := get("")
	fmt.Println(err)
	fmt.Println(err == ErrNotFound)
	fmt.Println(errors.Is(err, ErrNotFound))
}
```

<!-- out -->

```
not found
true
true
```

**المساواة نجحت** لأن `errors.New` تُرجع مؤشّراً، والمقارنة مقارنة عناوين — فكل
`errors.New("not found")` جديدة قيمةٌ مختلفة، والحارس واحدٌ يُشار إليه.

`errors.Is` نجحت أيضاً، وتبدو زائدة. **حتى تُغلَّف الطبقات.**

## الطبقات

الكود الحقيقيّ لا يُرجع الخطأ كما وصله. يضيف سياقاً:

```go
package main

import (
	"errors"
	"fmt"
)

var ErrNotFound = errors.New("not found")

func store(key string) error {
	return fmt.Errorf("store %q: %w", key, ErrNotFound)
}

func handler() error {
	if err := store("greeting"); err != nil {
		return fmt.Errorf("handler: %w", err)
	}
	return nil
}

func main() {
	err := handler()
	fmt.Println(err)
	fmt.Println("بالمساواة:", err == ErrNotFound)
	fmt.Println("بـ errors.Is:", errors.Is(err, ErrNotFound))
	fmt.Println("طبقة تحت:", errors.Unwrap(err))
}
```

طبقتان فوق الحارس. **توقّع السطور الأربعة**، وخصوصاً الثاني والثالث.

المخرَج:

```
handler: store "greeting": not found
بالمساواة: false
بـ errors.Is: true
طبقة تحت: store "greeting": not found
```

## سلسلةٌ لا صندوق

`%w` لا تنسخ الرسالة. **تحفظ الخطأ الأصليّ داخل الجديد**، فتصير الأخطاء قائمةً
مترابطة:

```
err ──► fmt.wrapError{ "handler: …" }
          └─► fmt.wrapError{ "store \"greeting\": …" }
                └─► ErrNotFound          ← الهدف
```

`==` تقارن **العقدة الأولى** فقط، وهي ليست الحارس. و`errors.Is` تمشي في السلسلة
حتى تجده أو تنتهي.

| | متى تستعملها |
|---|---|
| `%w` | يصير الخطأ الداخليّ **جزءاً من عقدك** — يستطيع المستدعي فحصه |
| `%v` | يصير نصّاً فقط. **العقد مغلق**، والتغيير لاحقاً لا يكسر أحداً |
| `errors.Is` | «هل في السلسلة هذا الخطأ بعينه؟» |
| `errors.As` | «هل في السلسلة خطأٌ من هذا النوع؟» — وأعطني إيّاه |

**واختيار `%w` قرار تصميم API لا زينة.** فمن غلّف اليوم لا يستطيع أن يفكّ غداً بلا
كسر.

## استخراج البيانات لا الرسالة

الخطأ نوعٌ عاديّ، فيحمل حقولاً. و`errors.As` تنتزعها من أيّ عمقٍ في السلسلة:

<!-- notice: `errors.As` لا تعمل في مفسّر المتصفّح. المخرَج المسجَّل من الأداة الحقيقية. -->

<!-- run: no -->

```go
package main

import (
	"errors"
	"fmt"
)

type NotFound struct{ Key string }

func (e *NotFound) Error() string { return "not found: " + e.Key }

func find(key string) error {
	return fmt.Errorf("layer: %w", &NotFound{Key: key})
}

func main() {
	err := find("greeting")

	var nf *NotFound
	if errors.As(err, &nf) {
		fmt.Println("المفتاح المفقود:", nf.Key)
	}
	fmt.Println(err)
}
```

<!-- out -->

```
المفتاح المفقود: greeting
layer: not found: greeting
```

**فالمعالج لم يحلّل نصّاً.** أخذ المفتاح من حقل. وهذا الفرق بين نموذج فشلٍ يُبنى
عليه وبين رسائل تُقرأ بالعين.

**ولاحظ `&nf`:** `errors.As` تحتاج **مؤشّراً إلى المتغيّر** لتكتب فيه. ومن نسي `&`
أذعر برنامجه.

## خطأٌ يساوي الصفر ولا يساويه

وهذا أشهر فخٍّ في اللغة. اقرأه ببطء:

<!-- notice: مفسّر المتصفّح يعطي هنا **الجواب المعاكس**. المخرَج المسجَّل من الأداة الحقيقية. -->

<!-- run: no -->

```go
package main

import "fmt"

type NotFound struct{ Key string }

func (e *NotFound) Error() string { return "not found: " + e.Key }

func lookup(key string) *NotFound {
	if key == "ok" {
		return nil
	}
	return &NotFound{Key: key}
}

func get(key string) error {
	return lookup(key)
}

func main() {
	err := get("ok")
	fmt.Println("err == nil ؟", err == nil)
	fmt.Printf("%v %T\n", err, err)
}
```

`lookup("ok")` أرجعت `nil` صراحةً. و`get` لم تفعل شيئاً سوى إعادتها. **توقّع
السطرين.**

المخرَج:

```
err == nil ؟ false
<nil> *main.NotFound
```

## الكلمتان مرّةً أخرى

هذا ليس فخّاً جديداً — هو **نفس ما رأيتَه في الفصل صفر**، واقعاً في أخطر موضع.

`return lookup(key)` تحوّل `*NotFound` إلى `error`. والتحويل يملأ **خانة النوع**:

```
lookup ترجع          →  (*NotFound)(nil)          مؤشّرٌ صفريّ
get تحوّلها إلى error  →  [ type: *NotFound │ data: nil ]
                                   ▲
                          ليست صفراً، فالواجهة ليست nil
```

و`%v` طبعت `<nil>` لأنها تنظر في **البيانات**، والمقارنة تنظر في **الكلمتين**.
فالمخرَج يقول «فارغ» والشرط يقول «ليس فارغاً»، **وكلاهما صادق**.

**والقاعدة التي تُغلق الباب:**

> **لا تجعل نوع العائد نوع خطأٍ محدَّداً. اجعله `error` دائماً.**

فلو كانت `lookup` تُرجع `error` لكان `return nil` صفراً حقيقياً. والفحص آليّ:
`go vet` يمسك بعض الحالات، و`nilness` في `staticcheck` يمسك أكثر.

## أكثر من خطأٍ واحد

منذ الإصدار ١.٢٠ تستطيع أن تجمع أخطاءً في واحد:

```go
package main

import (
	"errors"
	"fmt"
)

var ErrA = errors.New("خطأ أ")
var ErrB = errors.New("خطأ ب")

func main() {
	err := errors.Join(ErrA, ErrB)

	fmt.Println(err)
	fmt.Println(errors.Is(err, ErrA), errors.Is(err, ErrB))
}
```

<!-- out -->

```
خطأ أ
خطأ ب
true true
```

الرسالة سطرٌ لكل خطأ، و`errors.Is` تجد **كليهما** — فالسلسلة صارت شجرة.

وموضعه: التحقّق من صحّة نموذجٍ فيه عشرة حقول، أو إغلاق موارد فيفشل بعضها.
**بدلاً من أن تُرجع أوّل فشلٍ وتُخفي البقيّة.**

## متى يُذعَر إذن

الخطأ لحالةٍ **متوقَّعة**: ملفٌّ غير موجود، شبكةٌ مقطوعة، مدخلٌ فاسد. والذُّعر
لحالةٍ **مستحيلة**: خللٌ في المبرمج لا في البيئة.

واللغة نفسها تعمل بهذه القاعدة:

<!-- run: no -->

```go
package main

import "fmt"

func mustPositive(n int) int {
	if n <= 0 {
		panic(fmt.Sprintf("mustPositive: %d", n))
	}
	return n
}

func main() {
	fmt.Println(mustPositive(3))

	s := []int{1, 2, 3}
	fmt.Println(s[1])
	fmt.Println(s[5])
}
```

<!-- out: بعده أثر مكدّسٍ فيه مسارات جهاز المؤلّف -->

```
3
2
panic: runtime error: index out of range [5] with length 3
```

**تجاوز حدّ الشريحة ذُعرٌ لا خطأ.** لأنه ليس حالةً تُعالَج — هو دليلٌ على أن حساباً
في كودك خاطئ، والاستمرار بعده يعني الاستمرار ببيانات فاسدة.

**والاصطلاح المعلَن:** دالّةٌ تبدأ بـ`Must` تذعر بدل أن تُرجع خطأ، وتُستعمل عند
التهيئة حيث الفشل يعني أن البرنامج لا يصلح أصلاً — `regexp.MustCompile` مثلاً.

## الاسترداد محلّيّ

`recover` توقف انتشار الذُّعر — **في المكدّس الذي تعمل فيه**:

```go
package main

import (
	"fmt"
	"sync"
)

func main() {
	defer fmt.Println("مؤجَّل main")

	var wg sync.WaitGroup
	wg.Add(1)

	go func() {
		defer wg.Done()
		defer func() {
			if r := recover(); r != nil {
				fmt.Println("استُرد داخل الـgoroutine:", r)
			}
		}()
		panic("انهيار في خيط آخر")
	}()

	wg.Wait()
	fmt.Println("main حيّة")
}
```

<!-- out -->

```
استُرد داخل الـgoroutine: انهيار في خيط آخر
main حيّة
مؤجَّل main
```

`goroutine` ذعرت واستردّت نفسها، والبرنامج مضى. **ولاحظ ترتيب `wg.Done` و`recover`
في المؤجَّلات:** الاسترداد مؤجَّلٌ ثانياً فيُنفَّذ أوّلاً، ثم `Done`. ولو انعكسا
لأُعلِن الانتهاء قبل الاسترداد.

## ولا يعبر الخيوط

فماذا لو لم تستردّ الـ`goroutine` نفسها، وكان في `main` مسترِدٌّ جاهز؟

<!-- run: no -->

```go
package main

import "fmt"

func main() {
	defer func() {
		if r := recover(); r != nil {
			fmt.Println("استرداد main:", r)
		}
	}()

	go func() {
		panic("ذُعرٌ في goroutine بلا استرداد")
	}()

	select {}
}
```

`main` فيها `recover` كامل. **توقّع: هل تلتقطه؟**

المخرَج (مقتطع: بعده أثر مكدّسٍ فيه مسارات جهاز المؤلّف):

```
panic: ذُعرٌ في goroutine بلا استرداد
```

## لأن لكلٍّ مكدّسه

**لا شيء من `main` طُبع.** لا الاسترداد، ولا أيّ مؤجَّل.

`recover` تعمل على **مكدّس الـ`goroutine` التي تناديها**. والـ`goroutine` الجديدة
مكدّسها الخاصّ — لا أبَ لها فيه ولا سلسلة استدعاء تصل إلى `main`. فذُعرها يصعد إلى
قاع مكدّسها، فلا يجد مسترِداً، **فيُنهي العملية كلّها**.

```
main                     goroutine
┌────────────┐           ┌──────────────┐
│ defer      │           │ panic        │
│  recover ✓ │           │   ▲ يصعد     │
└────────────┘           │   ╳ لا مسترِدّ│
   ▲ لا صلة              └──────────────┘
   └──────────────────────────┘  ← ليست موجودة
```

**والقاعدة الصارمة:** كل `goroutine` تشغّل كوداً قد يذعر **تحمل مسترِدّها بنفسها**،
في أوّل سطرٍ فيها. ولا يوجد في Go «مُعالِج ذُعرٍ عامّ» — ولا يمكن أن يوجد، لأن
المكدّسات مستقلّة.

## بذرة

نموذج الفشل كامل الآن: قيمةٌ تُرجَع، وسلسلةٌ تُفحَص، وذُعرٌ للمستحيل، واسترداد
محلّيّ.

وبقيت مسألةٌ أجّلناها منذ الفصل صفر، وقلنا يومها إن لها إقليماً كاملاً:

`len("مرحبا")` = ١٠. والفهرسة تعطي بايتاً، و`range` تعطي نقطة ترميز.

**فكم حرفاً في هذا النصّ؟** السؤال يبدو تافهاً، وله أربعة أجوبة صحيحة — وواحدٌ
منها فقط هو ما يقصده مستخدمك.

الإقليم القادم عن النصّ.
