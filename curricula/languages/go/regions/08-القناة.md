# الإقليم ٠٨ — القناة

> مخزنك يستعمل قفلاً، وذلك صحيح. لكن أشهر جملةٍ في ثقافة Go تقول غير ذلك:
> **«لا تتواصل بمشاركة الذاكرة؛ شارك الذاكرة بالتواصل.»**
>
> والقناة هي الأداة التي تعنيها تلك الجملة. رأيتَ نوعها واتجاهه في الفصل صفر ولم
> تشغّلها.
>
> هنا نشغّلها، ثم نجيب عن سؤالٍ لا يجيب عنه الشعار: **متى قناة، ومتى قفل؟**

---

## القناة موعدٌ لا صندوق

`make(chan T)` بلا سعة تُنشئ قناةً **بلا مكانٍ للتخزين**. والإرسال فيها لا يُودِع
شيئاً — **ينتظر مستقبِلاً**، ثم تنتقل القيمة في لحظةٍ واحدة.

```go
package main

import "fmt"

func main() {
	ch := make(chan string)
	done := make(chan struct{})

	go func() {
		v := <-ch
		fmt.Println("المستقبِل: وصلني", v)
		close(done)
	}()

	fmt.Println("المرسِل: أُرسل الآن")
	ch <- "سجلّ"
	<-done
	fmt.Println("المرسِل: انتهيت")
}
```

<!-- out -->

```
المرسِل: أُرسل الآن
المستقبِل: وصلني سجلّ
المرسِل: انتهيت
```

`ch <- "سجلّ"` **حجبت المرسِل** حتى وصل مستقبِل. ولهذا تسمّى القناة غير المخزَّنة
**موعداً**: لا أحد يمضي حتى يصل الآخر.

**وهذا مزامنةٌ لا نقل بيانات فقط.** ولهذا كثيراً ما تُرسَل فيها `struct{}` — قيمةٌ
بحجم صفر — حين يكون المطلوب الإشارة لا القيمة.

## سعةٌ وإغلاق

وبالسعة تصير صندوقاً: الإرسال يُودع ويمضي ما دام فيه فراغ.

```go
package main

import "fmt"

func main() {
	ch := make(chan int, 2)

	ch <- 1
	ch <- 2
	fmt.Println("أُرسل اثنان بلا مستقبِل:", len(ch), cap(ch))

	close(ch)

	v1, ok1 := <-ch
	v2, ok2 := <-ch
	v3, ok3 := <-ch
	v4, ok4 := <-ch

	fmt.Println(v1, ok1)
	fmt.Println(v2, ok2)
	fmt.Println(v3, ok3)
	fmt.Println(v4, ok4)
}
```

أُغلقت القناة وفيها قيمتان، ثم قُرئت **أربع مرّات**. توقّع الأزواج الأربعة.

المخرَج:

```
أُرسل اثنان بلا مستقبِل: 2 2
1 true
2 true
0 false
0 false
```

## الإغلاق لا يُفرِغ

القيمتان خرجتا **بعد** الإغلاق. فالإغلاق ليس حذفاً — هو إعلانٌ بأن **لا مزيد**.

والقراءة من قناةٍ مغلقة **لا تحجب أبداً**: تُخرج ما تبقّى، ثم تعطي القيمة الصفرية
بلا انتظار، إلى الأبد.

```
[ 1 │ 2 ] مغلقة  →  1,true   2,true   0,false   0,false   0,false …
```

**و`ok` هو الفرق بين «صفرٌ أُرسل» و«القناة انتهت».** فمن قرأ بلا `ok` من قناةٍ
مغلقة حصل على صفرٍ لا نهائيّ يظنّه بيانات — وهي حلقةٌ ساخنة تدور بلا عمل.

## قناةٌ مغلقة وقارئان ينتظران

والآن المسألة التي سُمّي بها هذا الإقليم:

```go
package main

import (
	"fmt"
	"sync"
)

func main() {
	ch := make(chan int)
	var wg sync.WaitGroup
	out := make([]string, 3)

	for i := 1; i <= 2; i++ {
		wg.Add(1)
		go func(id int) {
			defer wg.Done()
			v, ok := <-ch
			out[id] = fmt.Sprintf("قارئ %d: v=%d ok=%v", id, v, ok)
		}(i)
	}

	close(ch)
	wg.Wait()

	fmt.Println(out[1])
	fmt.Println(out[2])
}
```

قناةٌ **بلا سعة**، وقارئان محجوبان عليها، ثم `close` — **ولا قيمة تُرسَل إطلاقاً**.
توقّع السطرين.

المخرَج:

```
قارئ 1: v=0 ok=false
قارئ 2: v=0 ok=false
```

## الإغلاق بثٌّ لا تسليم

**الاثنان استيقظا معاً.** ولو كانوا ألفاً لاستيقظ الألف.

وهذه خاصّيةٌ لا تملكها القناة في أيّ حالٍ آخر: الإرسال **تسليمٌ لواحد**، والإغلاق
**بثٌّ للجميع**. وهو الآلية الوحيدة في اللغة لإيقاظ عددٍ مجهولٍ من المنتظرين مرّةً
واحدة.

وعليها يقوم اصطلاح الإلغاء كلّه:

```go
done := make(chan struct{})
// … عند الإلغاء:
close(done)
// وكل من ينتظر:
select {
case <-done:
    return
case v := <-work:
    …
}
```

**ولا شيء يُرسَل في `done` أبداً.** الإشارة هي الإغلاق نفسه. وهذا هو قلب
`context.Context` في المكتبة القياسية — حقلٌ اسمه `Done()` يُرجع قناةً لا تحمل
شيئاً.

## ما يُذعِر

للقناة ثلاث عمليات تذعر، وكلّها **أخطاء برمجة** لا حالاتٍ تُعالَج:

<!-- run: no -->

```go
package main

import "fmt"

func main() {
	ch := make(chan int, 1)
	close(ch)

	fmt.Println("القراءة بعد الإغلاق:", <-ch)
	ch <- 1
	fmt.Println("لن يصل هنا")
}
```

<!-- out: بعده أثر مكدّسٍ فيه مسارات جهاز المؤلّف -->

```
القراءة بعد الإغلاق: 0
panic: send on closed channel
```

| العملية | النتيجة |
|---|---|
| القراءة من مغلقة | **آمنة** — صفرٌ و`ok=false` |
| الإرسال إلى مغلقة | **ذُعر** |
| إغلاق المغلقة | **ذُعر** |
| إغلاق قناةٍ صفرية | **ذُعر** |

**ولاحظ عدم التماثل:** القراءة آمنة والإرسال ليس كذلك. وليس هذا مصادفة — منه تُشتقّ
القاعدة التالية.

## من يُغلق

> **يُغلق المرسِل، ولا يُغلق المستقبِل أبداً.**

لأن المستقبِل لا يعرف هل بقي مرسِلٌ آخر، فإغلاقه قد يُذعِر غيره. والمرسِل يعرف
متى انتهى.

**فإن كان المرسِلون كثُراً؟** لا يُغلق أحدهم. الحلّ أن يعدّهم `sync.WaitGroup`،
وأن تنتظرهم `goroutine` واحدة ثم تُغلق:

```go
go func() { wg.Wait(); close(ch) }()
```

**والإغلاق ليس واجباً أصلاً.** القناة التي لا يمرّ عليها `range` ولا ينتظر إغلاقَها
أحد يجمعها الكانس كأيّ قيمة. لا يوجد «تسريب قناة» بسبب ترك الإغلاق — **يوجد تسريب
`goroutine`** محجوبةٍ على قناةٍ لن يصلها شيء، وذاك شيءٌ آخر.

## `range` حتى الإغلاق

```go
package main

import "fmt"

func main() {
	ch := make(chan int, 3)
	ch <- 1
	ch <- 2
	ch <- 3
	close(ch)

	for v := range ch {
		fmt.Println("وصل:", v)
	}
	fmt.Println("انتهت الحلقة")
}
```

<!-- out -->

```
وصل: 1
وصل: 2
وصل: 3
انتهت الحلقة
```

`range` على قناة تقرأ حتى الإغلاق ثم تخرج. **وهي الصيغة الوحيدة التي تفحص `ok`
نيابةً عنك** — فلا تُخرج لك صفراً لا نهائياً.

**وبلا `close` تتجمّد هذه الحلقة** بعد آخر قيمة. جرّبها: احذف السطر.

## القناة الصفرية تُطفئ الفرع

`select` ينتظر عدّة قنوات ويأخذ أوّل جاهز. وله سلوكٌ يبدو غريباً ثم يصير أداة:

```go
package main

import "fmt"

func main() {
	var off chan int
	on := make(chan int, 1)
	on <- 5

	for i := 0; i < 2; i++ {
		select {
		case v := <-off:
			fmt.Println("من الصفرية:", v)
		case v, ok := <-on:
			if !ok {
				fmt.Println("العاملة أُغلقت — أُطفئها")
				on = nil
				continue
			}
			fmt.Println("من العاملة:", v)
			close(on)
		}
	}
}
```

`off` قناةٌ **صفرية** لم تُنشَأ أصلاً. والحلقة تدور مرّتين. توقّع السطرين.

المخرَج:

```
من العاملة: 5
العاملة أُغلقت — أُطفئها
```

## لماذا لم تتجمّد

القراءة من قناةٍ صفرية **تحجب إلى الأبد**. ولو كانت هذه العملية وحدها لتجمّد
البرنامج.

لكن داخل `select` القاعدة تنقلب إلى أداة: **الفرع الذي قناته صفرية لا يصير جاهزاً
أبداً، فيُهمَل.** فأصبح إسناد `nil` إلى متغيّر القناة **طريقةً لإطفاء فرعٍ ديناميكياً**.

```
select {
case <-off:   ← off == nil   ⇒  الفرع مُطفَأ، ولا يُنظَر فيه
case <-on:    ←              ⇒  الفرع الحيّ الوحيد
}
```

وهذا هو الاصطلاح الذي رأيتَه: عند إغلاق قناة، اجعلها `nil` **حتى لا يدور `select`
عليها بلا عمل** — لأن المغلقة **جاهزةٌ دائماً**، فتحوّل الحلقة إلى دوّامة.

**وثلاث حالاتٍ لـ`select` تكمل الصورة:** فرعان جاهزان معاً ⇒ يُختار **عشوائياً**
لا بالترتيب (منعاً للتجويع) · لا فرع جاهز ولا `default` ⇒ يحجب · `select{}` بلا
فروع ⇒ يحجب أبداً.

## بلا مستقبِل

آخر ما يجب أن تراه بعينك قبل أن تنتقل:

<!-- run: no -->

```go
package main

import "fmt"

func main() {
	ch := make(chan int)
	fmt.Println("قبل الإرسال")
	ch <- 1
	fmt.Println("لن يصل هنا")
}
```

<!-- out: بعده أثر مكدّسٍ فيه مسارات جهاز المؤلّف -->

```
قبل الإرسال
fatal error: all goroutines are asleep - deadlock!
```

قناةٌ بلا سعة، وإرسالٌ بلا مستقبِل. **الموعد الذي لا يأتي إليه أحد.**

ولاحظ الفرق عن الذُّعر: هذا `fatal error` لا `panic` — **لا يُسترَدّ**. لأنه ليس
خطأً في `goroutine` واحدة، بل حكمٌ من الـruntime بأن البرنامج كلّه لا يستطيع
التقدّم.

## متى قناة ومتى قفل

الشعار يقول «تواصل»، والمخزن يستعمل قفلاً. **وكلاهما صحيح** — والفرق ليس ذوقاً:

| | القفل | القناة |
|---|---|---|
| المسألة | **حماية حالةٍ مشتركة** | **نقل ملكيّةٍ أو إشارة** |
| المثال | خريطةٌ يكتب فيها كثيرون | خطُّ معالجة · إلغاء · نتيجة |
| الكلفة | نانوثوانٍ | أعلى — فيها جدولة |
| الخطر | جمود · نسيان الفتح | تسريب `goroutine` · إغلاق مزدوج |

**فمخزنك محقّ.** حالته خريطةٌ في مكان، والقفل يحرسها في نانوثوانٍ. ولو أدرناه
بقناةٍ لجعلنا كل قراءةٍ رحلةً عبر المجدول، بلا مكسب.

**والقاعدة العملية:** إن كان السؤال «من يملك هذه القيمة الآن؟» فالقناة. وإن كان
«كيف أمنع اثنين من الكتابة معاً؟» فالقفل.

## بذرة

القناة مفهومة الآن، والقفل من قبلها. وكلاهما يَعِدك بشيء.

**وسؤالٌ لم نطرحه:** ما الذي يضمن أن ما كتبتْه `goroutine` **يراه** غيرها أصلاً؟

سترى في الإقليم القادم برنامجاً بلا قفلٍ ولا قناة، يعمل صحيحاً **ألف مرّة**، ثم
يعطي جواباً مستحيلاً. وستعرف لماذا «اشتغل عندي» أخطر جملةٍ في هذا المجال.
