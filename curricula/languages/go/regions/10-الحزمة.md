# الإقليم ١٠ — الحزمة والبناء

> مخزنك ملفٌّ واحد في `package main`. وفي أيّ مشروعٍ حقيقيّ سيسكن حزمةً، وتستوردها
> حزم، ويكون له ترتيب تهيئةٍ ولحظة ربط.
>
> رأيتَ في الفصل صفر أن الحزمة **وحدة الترجمة** لا الملفّ، وأن الحرف الكبير هو
> نظام الرؤية. وهنا نفكّك الباقي: لماذا تُمنَع الدورات، ومن يُهيَّأ أوّلاً، وما
> الذي يدخل ملفّك التنفيذيّ فعلاً.
>
> **وهذا الإقليم يُشغَّل محلياً كلّه** — بضع حزمٍ في مجلّدات، لا برنامجاً في متصفّح.

---

## شجرةٌ لا رسم بيانيّ

الحزمة تُترجَم مرّةً وتُخلّف وصف واجهتها، والمستورِد يقرأ الوصف لا المصدر. ولهذا
يفتح المترجم **ملفاً واحداً لكل استيرادٍ مباشر** — وذاك أصل السرعة التي بدأت منها
القصّة.

وتستطيع أن ترى الشجرة كاملةً:

```bash
go list -deps .
```

<!-- out: من `go list -deps` — آخر خمسة أسطر فقط، والقائمة كاملةً بالعشرات -->

```
os
fmt
example/store
example/audit
example
```

**والترتيب ليس اعتباطياً:** الاعتماديات قبل من يعتمد عليها. وهذا الترتيب نفسه هو
ترتيب الترجمة، وترتيب التهيئة — كما سترى بعد قليل.

## لا دورات

حزمتان تستورد كلٌّ منهما الأخرى:

<!-- run: no -->

```go
// cycle/a/a.go
package a

import "example/cycle/b"

func A() int { return b.B() }
```

<!-- out: من `go build ./cycle/...` -->

```
package example/cycle/a
	imports example/cycle/b from a.go
	imports example/cycle/a from b.go: import cycle not allowed
```

**رفضٌ عند الترجمة، لا تحذير.** ولا حيلة تلتفّ عليه.

وهذا يشتري ثلاثة أشياء دفعةً واحدة: **مرورٌ واحد** في الترجمة بلا تصريحاتٍ مسبقة ·
**ترجمةٌ على التوازي** لأن الشجرة لها أوراقٌ تُترجَم أوّلاً · و**ترتيب تهيئةٍ
معلوم** — إذ لا معنى لأن نسأل «من يُهيَّأ أوّلاً» في دورة.

**والثمن معماريّ:** حين تصطدم بالرفض فالغالب أن التقسيم خاطئ لا أن اللغة متزمّتة.
والعلاج المعتاد: انتزع ما تشترك فيه الحزمتان إلى ثالثة، أو **اقلب الاعتماد
بواجهة** يعرّفها المستهلك — وقد رأيتَ في الفصل صفر أن الواجهة الضمنية تسمح بذلك بلا
استيرادٍ مضادّ.

## من يُهيَّأ أوّلاً

ثلاث حزم: `main` تستورد `audit`، و`audit` تستورد `store`. وفي كلٍّ منها **متغيّرٌ
على مستوى الحزمة** و**دالّة `init`**.

<!-- run: no -->

```go
// main.go — package main
var greeting = start()

func start() string {
	fmt.Println("1. main: تهيئة المتغيّر greeting")
	return "hi"
}

func init() { fmt.Println("6. main: init") }

func main() { fmt.Println("7. main: البداية —", greeting, audit.Limit) }
```

رقّمتُ الأسطر السبعة **بالترتيب الذي يظنّه أكثر الناس**: الأعلى أوّلاً. فهل هو
كذلك؟ توقّع الترتيب الحقيقيّ.

المخرَج:

```
3. store: تهيئة المتغيّر Capacity
4. store: init
5. audit: init — رأى Capacity = 16
1. main: تهيئة المتغيّر greeting
6. main: init
7. main: البداية — hi 32
```

## من الأوراق إلى الجذر

الترتيب **مقلوبٌ تماماً** عن ترتيب القراءة: يبدأ من أعمق اعتمادية ويصعد.

```
store  ─►  audit  ─►  main
  ①          ②         ③
```

وداخل كل حزمة، خطوتان بهذا الترتيب:

**أولاً متغيّرات المستوى الأعلى**، مرتّبةً **بالاعتماد لا بالنصّ**: لو كان `var a =
b + 1` فوق `var b = 2` هُيِّئت `b` أوّلاً. المترجم يبني رسماً بيانياً ويحلّه.

**ثم `init()`** بترتيب النصّ.

**ولذلك رأت `audit` قيمة `Capacity = 16` جاهزة** — لا لأنها انتظرت، بل لأن الترتيب
يضمن ذلك. **وهذه علاقة «مزامَنٌ قبل» أيضاً**: كل ما هُيِّئ قبلك مرئيٌّ لك، بلا قفل.

**وأخيراً `main()`.** وهي آخر شيءٍ يبدأ في البرنامج كلّه.

## قواعد `init`

| | |
|---|---|
| العدد | **بلا حدّ** — عدّة في الملفّ الواحد، وفي كل ملفّات الحزمة |
| الترتيب بين الملفّات | ترتيب أسماء الملفّات كما يعطيها البناء. **لا تعتمد عليه** |
| التوقيع | `func init()` — بلا وسائط وبلا عائد |
| المناداة | **ممنوعة**. لا يمكنك أن تناديها بنفسك |
| متى تُنفَّذ | ولو لم تستعمل الحزمة إلا لأثرها الجانبيّ |

والصفّ الأخير هو اصطلاحٌ ستراه كثيراً:

```go
import _ "github.com/lib/pq"
```

**الشرطة السفلية استيرادٌ للأثر لا للأسماء.** الحزمة تُهيَّأ فتسجّل نفسها في سجلٍّ
عامّ (سائق قاعدة بيانات، صيغة صورة)، ولا تُستعمَل باسمها. وبدون `_` يرفض المترجم
الاستيراد غير المستعمَل — وقد عرفتَ لماذا منذ الفصل صفر.

**ونصيحةٌ عمليّة:** `init` تعمل قبل أن تقرأ أنت أيّ إعداد، ولا يمكن اختبارها
منفردةً، ولا تُرجع خطأً — فالفشل فيها ذُعرٌ لا خيار غيره. **فأقلِل منها**، واجعل
التهيئة دالّةً تناديها من `main`.

## حدٌّ ثالث للرؤية

الحرف الكبير يفتح الاسم لكل من يستورد. و`internal` تضيّقه:

```
example/
  internal/
    codec/          ← يراها example/… فقط
  store/
  audit/
```

**أيّ حزمةٍ تحت مجلّدٍ اسمه `internal` لا يستوردها إلا من يشترك معها في الأب.**
قاعدةٌ يفرضها البناء لا الاصطلاح، ورفضُها خطأ ترجمة.

فصارت للرؤية ثلاث درجات: **خاصٌّ بالحزمة** (حرف صغير) · **خاصٌّ بالوحدة**
(`internal`) · **عامّ** (حرف كبير). وهذا كل ما في اللغة — لا `protected` ولا
`friend`.

## وسوم البناء

الملفّ كلّه قد يدخل البناء أو لا يدخله، بسطرٍ في أعلاه:

<!-- run: no -->

```go
// mode_default.go
//go:build !debug

package main

const mode = "release"
```

وملفٌّ آخر بجانبه يحمل `//go:build debug` ويعرّف نفس الثابت بقيمةٍ أخرى.

<!-- out: من `go run .` ثم `go run -tags debug .` -->

```
mode = release
mode = debug
```

**ثابتٌ واحد، ملفّان، ولا `#ifdef`.** الاختيار على مستوى **الملفّ** لا السطر — فلا
كودَ منسوجٌ بشروطٍ لا تُقرأ.

**وأشهر وسومٍ لا تكتبها بيدك** هي التي يضعها البناء نفسه: `linux` · `darwin` ·
`arm64` · `cgo`. ولذلك ترى `file_linux.go` و`file_windows.go` — **اللاحقة في اسم
الملفّ وسمٌ ضمنيّ**.

## قيمةٌ تُحقَن عند الربط

الرابط يستطيع أن يكتب في متغيّرٍ نصّيٍّ قبل التشغيل:

```bash
go run -ldflags="-X main.version=1.4.2" .
```

<!-- out -->

```
version = 1.4.2
```

والمصدر يقول `var version = "dev"`. **فالقيمة الافتراضية بقيت في المصدر، والحقيقية
دخلت عند البناء.**

هكذا تُحقَن أرقام الإصدارات وبصمات الـcommit بلا توليد ملفّات. **وحدّه:** يعمل
على `string` على مستوى الحزمة فقط، ولا يعمل على ثابت `const` لأن الثابت يُحسَم عند
الترجمة لا الربط.

## ما يدخل ملفّك التنفيذيّ

ثلاثة أرقامٍ من نفس الجهاز:

**توقّع الأول:** كم يزن ملفٌّ تنفيذيّ لبرنامج `func main() {}` فارغٍ تماماً؟

المخرَج (مقتطع: من `ls -l` على ثلاثة ملفّاتٍ بُنيت على darwin/arm64):

```
1749218   func main() {}   فارغ تماماً
2492962   المشروع كاملاً
1657922   المشروع كاملاً، مربوطاً بـ -ldflags="-s -w"
```

**البرنامج الفارغ ١٫٧ ميغابايت.** لأنك لا تشحن كودك وحده — تشحن **الـruntime**:
المجدول، وكانس القمامة، ومخصِّص الذاكرة، وجداول الأنواع للانعكاس.

**وهذه أرضيةٌ لا سقف.** ولذلك يقفز الملفّ من ١٫٧ إلى ٢٫٥ بمشروعٍ كامل، ولا يقفز
إلى عشرة.

**والسطر الثالث أصغر من الأول** لأن `-s -w` تسقط جدول الرموز ومعلومات التنقيح.
وثمنها أن أثر المكدّس يفقد أسماء الدوال — **فلا تفعلها في بناءٍ تنقّحه**.

**وكل هذا مربوطٌ ربطاً ساكناً** افتراضاً: لا `.so` ولا مكتبة C. الملفّ ينسخ إلى
حاوية فارغة فيعمل، وهذا سبب انتشار Go في هذا الموضع بالذات.

## بذرة

بقي شيءٌ واحد.

مررنا في هذا المنهج على ضماناتٍ كثيرة: القيمة الصفرية صالحة، والنسخة كاملة،
والعنوان لا يتحرّك، والسباق يُكشَف، والحزمة لا تدور.

**ولكل ضمانٍ حدٌّ ينتهي عنده.** وخلف ذلك الحدّ حزمةٌ اسمها `unsafe` لا تُشبه بقيّة
اللغة، وبابٌ إلى C، ومواضع تعمل فيها اللغة بلا وعدٍ منها.

الإقليم الأخير عن ذلك الحدّ — وعن مخزنك، مرّةً أخيرة.
