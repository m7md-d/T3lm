# الإقليم ٠٤ — أين تعيش قيمتك

> بقيت البذرة الثالثة من مخزنك: `Get` تُرجع نسخةً تشارك المخزن مصفوفتها.
>
> والحلّ معروف منذ إقليمين: **انسخ البايتات**. سنكتبه في اللقطة الأولى، ولن نجادل
> في صحّته.
>
> ثم نفعل ما لم نفعله بعد: **نقيسه**. لأن الثمن ليس حيث يظنّه أغلب الناس، ولا
> يُعرَف بالحدس — يُعرَف بأداة.

---

## الحلّ الواضح

```go
package main

import "fmt"

type Record struct {
	Key   string
	Value []byte
}

func get(store map[string]Record, key string) (Record, bool) {
	r, ok := store[key]
	if !ok {
		return Record{}, false
	}
	value := make([]byte, len(r.Value))
	copy(value, r.Value)
	r.Value = value
	return r, true
}

func main() {
	store := map[string]Record{
		"greeting": {Key: "greeting", Value: []byte("hello")},
	}

	r, _ := get(store, "greeting")
	r.Value[0] = 'X'

	fmt.Printf("المخزن: %q\n", store["greeting"].Value)
	fmt.Printf("النسخة: %q\n", r.Value)
}
```

<!-- out -->

```
المخزن: "hello"
النسخة: "Xello"
```

**انفصلت النسخة.** ثلاثة أسطر: خصّص بطول المصدر، انسخ، أعِد إسناد الرأس.

والسؤال الآن: **كم كلّفتنا هذه الأسطر الثلاثة؟** ومن أين جاءت الكلفة — من النسخ
أم من شيءٍ آخر؟

## لا تخمّن. قِس

`go test` فيه مقياسٌ مدمج. لا مكتبة، ولا إعداد.

```go
package bench

import "testing"

var sink []byte

func run(b *testing.B, n int, f func(*Store)) {
	s := New(n)
	b.ReportAllocs()
	for b.Loop() {
		f(s)
	}
}

func BenchmarkShared8(b *testing.B) { run(b, 8, func(s *Store) { r, _ := s.GetShared("k"); sink = r.Value }) }
func BenchmarkCopy8(b *testing.B)   { run(b, 8, func(s *Store) { r, _ := s.GetCopy("k"); sink = r.Value }) }
func BenchmarkCopy1K(b *testing.B)  { run(b, 1024, func(s *Store) { r, _ := s.GetCopy("k"); sink = r.Value }) }
func BenchmarkCopy64K(b *testing.B) { run(b, 65536, func(s *Store) { r, _ := s.GetCopy("k"); sink = r.Value }) }
```

ثلاثة أشياء تجعل الرقم صادقاً:

**`b.Loop()`** تدير التكرار بنفسها، وتمنع المترجم من حذف الحلقة لأنها بلا أثر.

**`sink` متغيّرٌ على مستوى الحزمة.** بدونه يرى المترجم أن النتيجة مهملة فيحذف
العمل كلّه، فتقيس الفراغ.

**`b.ReportAllocs()`** تضيف عمودَي البايتات وعدد التخصيصات. **وهما العمودان
المهمّان**، لا الزمن.

## الثمن ليس النسخ

خذ الطرفين واستخرج منهما سرعة النسخ نفسها:

```
64K:  4045.0 − 8.2  =  4036.8 ns  لـ 65536 بايتاً
                    →  0.0616 ns للبايت  ≈ 16 غيغابايت/ثانية

8 بايتات:  8 × 0.0616  =  0.49 ns   ← النسخ
           الزيادة المقيسة 9.46 ns
           الفرق 8.97 ns            ← ليس نسخاً
```

**نصف نانوثانية نسخٌ، وتسع نانوثوانٍ شيءٌ آخر.** أي أن **٩٥٪ من كلفة «انسخ ثمانية
بايتات» ليست نسخاً.**

الشيء الآخر هو `make`: طلبُ ذاكرةٍ من المخصِّص، وتصفيرها، وتسجيلها عند الكانس
ليجمعها لاحقاً. **العمود الذي يقول ذلك موجودٌ أمامك: `1 allocs/op`.**

**ولهذا نقرأ عمود `allocs/op` قبل عمود `ns/op`.** الزمن نتيجة، والتخصيص سبب.

## نفس النسخ، بلا تخصيص

إن كانت الكلفة في `make` لا في `copy`، فالعلاج **ألّا تخصّص** — لا ألّا تنسخ.

والنمط المعروف في Go: بدل أن تُرجع شريحةً جديدة، **أضِف إلى شريحةٍ يعطيكها
المستدعي**:

```go
func (s *Store) AppendTo(dst []byte, key string) ([]byte, bool) {
	r, ok := s.data[key]
	if !ok {
		return dst, false
	}
	return append(dst, r.Value...), true
}
```

والمستدعي يعيد استعمال مخزنه المؤقّت: `buf, ok = s.AppendTo(buf[:0], "k")`.

<!-- out: سطرٌ واحد من نفس التشغيلة، بجانبه سطر النسخ للمقارنة -->

```
BenchmarkCopy8-8       65917618   17.70 ns/op    8 B/op    1 allocs/op
BenchmarkAppend8-8    100000000   10.07 ns/op    0 B/op    0 allocs/op
```

**البايتات الثمانية ما زالت تُنسخ.** والفرق أن الوجهة موجودة سلفاً.

`buf[:0]` تصفّر الطول وتُبقي السعة — فتكتب `append` في المصفوفة نفسها بلا تخصيص.
وهذا هو الاستعمال الأنظف لما تعلّمتَه في إقليم الشريحة.

## عدّاد التخصيص في يدك

لا تحتاج مقياساً لترى العدد. الـruntime يعدّه، ويعطيكه:

<!-- notice: مفسّر المتصفّح يخصّص لحسابه هو، فأرقامه لا تقيس هذا البرنامج. شغّله محلياً. -->

<!-- run: no -->

```go
package main

import (
	"fmt"
	"runtime"
)

var sink []byte

func main() {
	src := []byte("12345678")

	var before, after runtime.MemStats
	runtime.GC()
	runtime.ReadMemStats(&before)

	for i := 0; i < 100_000; i++ {
		dst := make([]byte, len(src))
		copy(dst, src)
		sink = dst
	}

	runtime.ReadMemStats(&after)
	fmt.Println("تخصيصات:", after.Mallocs-before.Mallocs)
	fmt.Println("بايتات: ", after.TotalAlloc-before.TotalAlloc)
}
```

مئة ألف دورة، كلٌّ تخصّص ثمانية بايتات. **توقّع الرقمين.**

المخرَج:

```
تخصيصات: 100000
بايتات:  800000
```

## وبنمط الإضافة

نفس الحلقة، ونفس النسخ، ومخزنٌ مؤقّت واحد يُعاد استعماله:

<!-- notice: وهذا أيضاً لا يُقاس في المتصفّح — شغّله محلياً. -->

<!-- run: no -->

```go
package main

import (
	"fmt"
	"runtime"
)

var sink []byte

func main() {
	src := []byte("12345678")
	buf := make([]byte, 0, 64)

	var before, after runtime.MemStats
	runtime.GC()
	runtime.ReadMemStats(&before)

	for i := 0; i < 100_000; i++ {
		buf = append(buf[:0], src...)
		sink = buf
	}

	runtime.ReadMemStats(&after)
	fmt.Println("تخصيصات:", after.Mallocs-before.Mallocs)
	fmt.Println("بايتات: ", after.TotalAlloc-before.TotalAlloc)
}
```

نفس السؤال: **توقّع الرقمين.**

المخرَج:

```
تخصيصات: 0
بايتات:  0
```

**صفر.** مئة ألف نسخةٍ بلا تخصيصٍ واحد.

وهذا يغلق الحلقة: النسخ رخيص، والتخصيص ليس كذلك، والفرق بينهما **يُقاس ولا
يُخمَّن**.

## من يقرّر أين تعيش قيمتك

في C أنت تقرّر: `int x` على المكدّس، و`malloc` على الكومة. **وفي Go لا توجد
الكلمتان.**

`make` و`new` و`&x` **لا تعني الكومة**. المترجم يقرّر بنفسه بتحليلٍ اسمه **تحليل
الهروب**: إن أثبت أن القيمة لا تُرى بعد رجوع الدالة، وضعها على المكدّس.

والقاعدة الحاكمة سطرٌ واحد:

> **القيمة تهرب إلى الكومة إن كان عمرها قد يتجاوز الإطار الذي وُلدت فيه.**

وليس عليك أن تخمّن. المترجم يُريك قراره:

```bash
go build -gcflags='-m' main.go
```

## القرار مقروءاً

هذا الملفّ فيه ثلاث دوال: واحدةٌ تُرجع طولاً، وواحدةٌ تُرجع مؤشّراً، وواحدةٌ تنسخ.

<!-- run: no -->

```go
package main

import "fmt"

type Record struct {
	Key   string
	Value []byte
}

func onStack() int {
	r := Record{Key: "k"}
	return len(r.Key)
}

func escapes() *Record {
	r := Record{Key: "k"}
	return &r
}

func copyValue(src []byte) []byte {
	dst := make([]byte, len(src))
	copy(dst, src)
	return dst
}

func main() {
	fmt.Println(onStack(), escapes().Key, len(copyValue([]byte("hi"))))
}
```

<!-- out: من `go build -gcflags='-m'` لا من تشغيل البرنامج؛ وأسقطتُ سطور can inline وinlining call -->

```
./main.go:16:2: moved to heap: r
./main.go:20:16: src does not escape
./main.go:21:13: make([]byte, len(src)) escapes to heap
```

**`escapes` أعادت `&r`، فنُقلت `r` إلى الكومة** — عمرها يتجاوز إطارها.

**و`onStack` لا يُذكَر إطلاقاً.** لا خبر خبرٌ: ما لا يهرب لا يُسجَّل.

## سطرٌ واحد، جوابان

انظر إلى بقيّة المخرَج نفسه — نفس التشغيلة، نفس الملفّ:

<!-- out: سطران من نفس مخرَج `-gcflags='-m'`، أُدرجا وحدهما للمقارنة -->

```
./main.go:21:13: make([]byte, len(src)) escapes to heap
./main.go:27:53: make([]byte, len(src)) does not escape
```

**السطر ٢١ نفسه، والحكم متناقض.** فأيّهما الصحيح؟

**كلاهما.** لأن الهروب ليس خاصّيةً لسطر — هو خاصّيةٌ **لموضع نداء**.

`copyValue` وحدها تُرجع الشريحة، فهي تهرب. لكن المترجم **دمجها** في `main` (رأيتَ
`inlining call to copyValue` في السطور التي أسقطتُها)، وهناك رأى أن الناتج يُمرَّر
إلى `len` فقط ثم يُهمَل. **فلم يهرب.**

فالسؤال «هل يخصّص هذا السطر؟» **سؤالٌ ناقص**. السؤال الكامل: «هل يخصّص هذا السطر
حين يُنادى من هنا؟»

## ما يُهرِّب فعلاً

اقرأ هذه مرّةً وارجع إليها عند كل مقياس:

| الحال | يهرب؟ | لماذا |
|---|---|---|
| `return &x` | **نعم** | العمر يتجاوز الإطار |
| قيمةٌ تُخزَّن في واجهة | **نعم** | حجمها ونوعها مجهولان عند المستقبِل |
| `make` بحجمٍ **غير معلومٍ** وقت الترجمة | **نعم** | لا يُحجَز على المكدّس ما لا يُعرَف حجمه |
| قيمةٌ تُرسَل على قناة | **نعم** غالباً | قد تعيش في `goroutine` أخرى |
| مؤشّرٌ يُخزَّن في بنيةٍ هاربة | **نعم** | الهروب يعدي |
| مؤشّرٌ يُمرَّر إلى دالّةٍ لا تحفظه | **لا** | «does not escape» |
| بنيةٌ كبيرة تُمرَّر بالقيمة | **لا** | تُنسخ على المكدّس، ولو كانت ضخمة |

**والصفّ الثاني هو الفخّ اليوميّ:** `fmt.Println(x)` يضع `x` في `interface{}`،
فيهرب. ولهذا سطر تسجيلٍ واحد داخل حلقةٍ ساخنة يقلب ملفّك التعريفيّ رأساً على عقب.

## بذرة

عرفتَ الآن أن الثمن تخصيصٌ لا نسخ، وأن المترجم يقرّر الموضع ويُريك قراره.

وبقيت في مخزنك جملةٌ لم نفحصها منذ الإقليم الأول:

```go
s.mu.Lock()
defer s.mu.Unlock()
```

قلنا إن `defer` تُنفَّذ **عند رجوع الدالة، لا عند نهاية الكتلة**. وقلنا إن الفرق
سيؤذيك في حلقة.

الإقليم القادم يجعله يؤذيك.
