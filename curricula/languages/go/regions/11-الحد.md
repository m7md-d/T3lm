# الإقليم ١١ — الحدّ

> مرّ بك في هذا المنهج ضماناتٌ كثيرة. القيمة الصفرية صالحة، والنسخة كاملة،
> والعنوان لا يتحرّك، والسباق يُكشَف، والحزمة لا تدور.
>
> **ولكل ضمانٍ حدٌّ ينتهي عنده.** ومعرفة الحدّ ليست ترفاً: من لا يعرف أين ينتهي
> الوعد يبني على شيءٍ لم يوعَد به، فيعمل كوده اليوم ويكسره ترقيةٌ بعد سنة.
>
> هذا آخر إقليم. وفيه ما لا تعِد به اللغة، وحزمةٌ لا تشبهها، ثم مخزنك مرّةً
> أخيرة.

---

## حزمةٌ ليست حزمة

`unsafe` ليست مكتبةً بل **معرفةٌ في المترجم**. لا كود لها، ولا يشملها وعد التوافق
بنفس الصيغة، واستيرادها يمنع بعض أدوات التحليل من العمل.

وأدواتها التي رأيتَها — `Sizeof` و`Offsetof` و`Alignof` — تُحسَب **وقت الترجمة**
وتُرجع ثوابت. أمّا `unsafe.Pointer` فشيءٌ آخر: **مؤشّرٌ بلا نوع**، يتحوّل من أيّ
مؤشّرٍ وإليه.

<!-- notice: `unsafe.Add` غير مدعومة في مفسّر المتصفّح. المخرَج المسجَّل من الأداة الحقيقية. -->

<!-- run: no -->

```go
package main

import (
	"fmt"
	"unsafe"
)

type Record struct {
	Key     string
	Value   []byte
	Deleted bool
}

func main() {
	r := Record{Key: "greeting", Value: []byte("hello"), Deleted: false}

	base := unsafe.Pointer(&r)
	off := unsafe.Offsetof(r.Deleted)

	flag := (*bool)(unsafe.Add(base, off))
	fmt.Println("قبل:", r.Deleted)
	*flag = true
	fmt.Println("بعد:", r.Deleted)

	fmt.Println("الإزاحة:", off, "الحجم:", unsafe.Sizeof(r))
}
```

كتبنا في حقلٍ **بلا أن نسمّيه**: حسبنا عنوانه من عنوان البنية زائد إزاحته. توقّع
السطور الثلاثة.

المخرَج:

```
قبل: false
بعد: true
الإزاحة: 40 الحجم: 48
```

## لماذا تعمل هذه الحيلة أصلاً

`40` و`48` — نفس رقمَي الإقليم الأول. **والحيلة تعمل لأن اللغة تعِد بشيءٍ لم
نسمّه بعد.**

ارجع إلى ما قرأتَه في الفصل صفر، من شيفرة الكانس نفسها:

```go
// $GOROOT/src/runtime/mgc.go
// It is a concurrent mark and sweep that uses a write barrier. It is
// non-generational and non-compacting.
```

**`non-compacting`.** الكانس لا يحرّك الكائنات ليردم الفجوات. فالعنوان الذي حسبتَه
يبقى صالحاً ما دام الكائن حيّاً.

ولو كانت Go تضغط ذاكرتها — كما تفعل JVM — **لما أمكن `unsafe.Pointer` أن يوجد
بهذه البساطة**، ولاحتاج كل مؤشّرٍ خام إلى تثبيتٍ صريح.

**فالتنازل الذي دفعته اللغة في الأداء هو الذي اشترى لك هذا الباب.** ولا يوجد قرار
بلا ثمنٍ ومقابل.

## صفر نسخٍ بين النصّ والبايتات

عرفتَ أن `[]byte(s)` تنسخ، وأن النسخ يعني تخصيصاً. و`unsafe` تلغيه:

<!-- notice: `unsafe.Slice` غير مدعومة في مفسّر المتصفّح. المخرَج المسجَّل من الأداة الحقيقية. -->

<!-- run: no -->

```go
package main

import (
	"fmt"
	"unsafe"
)

func toBytes(s string) []byte {
	return unsafe.Slice(unsafe.StringData(s), len(s))
}

func main() {
	s := "hello"
	b := toBytes(s)

	fmt.Println(len(b), string(b))
	fmt.Println("نفس البايتات؟", unsafe.StringData(s) == &b[0])
}
```

<!-- out -->

```
5 hello
نفس البايتات؟ true
```

**نفس البايتات، بلا تخصيص.** و`unsafe.Slice` و`unsafe.String` أُضيفتا لتكونا
الصيغة **المعتمَدة** لهذا، بدل قلب الرؤوس يدوياً كما كان الناس يفعلون.

**والثمن أنك كسرت ضماناً:** النصّ في Go للقراءة فقط، وقد صار عندك الآن مقبضٌ
للكتابة عليه. والكتابة فيه **سلوكٌ غير معرَّف** — قد تُعدّل ثابتاً مشتركاً في
القطعة الساكنة، وقد تُعدّل مفتاحاً في خريطةٍ فتفسدها.

**فالاتجاه الآمن واحد:** من `[]byte` إلى `string` حين تعرف أن البايتات لن تتغيّر
بعدها. والعكس **لا**.

## القاعدة التي تُغني عن الحفظ

توثيق `unsafe` يعدّ ستّة أنماطٍ صالحة لتحويل `Pointer`. ولا تحتاج حفظها — تحتاج
القاعدة التي وراءها:

> **لا يجوز أن يوجد `uintptr` يحمل عنواناً حيّاً بين تعليمتين.**

لأن `uintptr` **عددٌ لا مؤشّر**. والكانس لا يرى الأعداد. فبين السطرين قد يُجمَع
الكائن، فيصير عندك عنوانٌ لذاكرةٍ صارت لغيرك.

```go
p := uintptr(unsafe.Pointer(&r))   // ✗ العنوان صار عدداً…
q := unsafe.Pointer(p + off)       //   وبينهما قد يُجمَع r
```

```go
q := unsafe.Add(unsafe.Pointer(&r), off)   // ✓ تعبيرٌ واحد لا فجوة فيه
```

**ولهذا وُجدت `unsafe.Add`**: لتكتب الحساب في تعبيرٍ واحد لا فجوة فيه.

## وفحصُه آليّ

لستَ وحدك مع هذه القاعدة:

```bash
go vet -unsafeptr ./...
```

يمسك أشهر صيغةٍ للخرق — تحويل `uintptr` إلى `Pointer` بلا حسابٍ في نفس التعبير.
**وصمتُه ليس براءة** كما هو حال كل تحليلٍ ساكن.

**و`runtime.KeepAlive(x)`** أداةٌ ثانية للغرض نفسه: تخبر الكانس أن `x` ما زال
مطلوباً حتى هذا السطر، ولو لم يظهر في الكود بعده. وتحتاجها حين تحمل مقبضاً خاماً
لموردٍ يملكه كائنٌ صار — من وجهة نظر المترجم — بلا مستعمِل.

## التخطيط ليس عقداً

في الإقليم الأول قِستَ `Record` فكان ٤٨، ثم أعدتَ ترتيب حقوله فبقي ٤٨ — **وقلنا إن
الترتيب من الأكبر للأصغر ليس قاعدة**.

الآن بنيةٌ أخرى:

```go
package main

import (
	"fmt"
	"unsafe"
)

type A struct {
	Flag bool
	N    int64
	Tag  byte
}

type B struct {
	N    int64
	Flag bool
	Tag  byte
}

func main() {
	fmt.Println(unsafe.Sizeof(A{}), unsafe.Sizeof(B{}))
	fmt.Println(unsafe.Offsetof(A{}.N), unsafe.Offsetof(B{}.N))
}
```

نفس الحقول الثلاثة، وترتيبان. **توقّع الحجمين والإزاحتين.**

المخرَج:

```
24 16
8 0
```

## فجوةٌ داخلية، لا ذيل

**هنا نفع الترتيب**، وهناك لم ينفع. والفرق كلّه في **موضع الضياع**:

```
A:  [ Flag │ ×××××××  حشو 7  ×××××××│ N (8) │ Tag │ حشو 7 ]  = 24
      1                              8       1              ← فجوةٌ داخلية + ذيل

B:  [ N (8) │ Flag │ Tag │ حشو 6 ]                          = 16
      8       1      1               ← ذيلٌ فقط، والصغيران تجاوَرا
```

في `A` جاء `bool` قبل `int64`، فاحتاج `N` إزاحةً تقبل القسمة على ثمانية — **فضاعت
سبعة في المنتصف**. وفي `B` تجاور الصغيران فسكنا نفس الكلمة.

**فالقاعدة الحقيقية ليست «رتّب من الأكبر للأصغر»** — هي: *قلّل الفجوات الداخلية
بأن تُجاور الحقول الصغيرة*. والترتيب التنازليّ يحقّقها **عرَضاً** في بعض البنى،
ولا يحقّقها في `Record` لأنه لا فجوة داخلية فيها أصلاً.

**والأهمّ:** لا شيء من هذا **موعودٌ به**. المواصفة تضمن ترتيب الحقول في الذاكرة،
ولا تضمن مقدار الحشو ولا الحجم النهائيّ — وهما يختلفان بالمعمارية، وقد يختلفان
بالإصدار. **فلا تُرسِل بنيةً على الشبكة بنسخ بايتاتها.**

## ترتيبٌ عشوائيّ عمداً

<!-- notice: الأعداد تتغيّر في كل تشغيلة — وهذا هو الدرس. -->

<!-- run: no -->

```go
package main

import "fmt"

func main() {
	m := map[string]int{"a": 1, "b": 2, "c": 3, "d": 4, "e": 5}

	first := map[string]int{}
	for i := 0; i < 10_000; i++ {
		for k := range m {
			first[k]++
			break
		}
	}

	fmt.Println("مفاتيح ظهرت أوّلاً:", len(first))
	for _, k := range []string{"a", "b", "c", "d", "e"} {
		fmt.Printf("%s كان أوّلاً %d مرّة\n", k, first[k])
	}
}
```

<!-- out: من تشغيلةٍ واحدة على جهاز المؤلّف — والأعداد لا تتكرّر -->

```
مفاتيح ظهرت أوّلاً: 5
a كان أوّلاً 4912 مرّة
b كان أوّلاً 1293 مرّة
c كان أوّلاً 1288 مرّة
d كان أوّلاً 1281 مرّة
e كان أوّلاً 1226 مرّة
```

**كل المفاتيح الخمسة ظهرت أوّلاً في مرّات.** فالترتيب ليس ثابتاً.

**لكن انظر إلى `a`: نصف المرّات تقريباً.** فالعشوائية **ليست انتظاماً**. الـruntime
يبدأ المرور من موضعٍ عشوائيّ داخل الجدول، لا يخلط المفاتيح — فالتوزيع يتبع بنية
الجدول.

**وهذا القرار متعمَّد**، وأُدخل ليكسر الكود الذي كان يعتمد على ترتيبٍ لم يُوعَد به.
اللغة **تعشوِر لتمنعك** من بناء افتراضٍ خاطئ. وهي فلسفةٌ نادرة تستحقّ التأمّل: بدل
أن تترك السلوك مستقرّاً بالصدفة ثم تُلام على تغييره، جعلته غير مستقرٍّ من اليوم
الأول.

## ما لا تعِد به اللغة

اقرأها مرّةً، وارجع إليها كلّما وجدتَ كوداً «يعمل ولا تعرف لماذا»:

| لا يُوعَد | ماذا تفعل بدلاً منه |
|---|---|
| ترتيب المرور على الخريطة | اجمع المفاتيح ورتّبها |
| ترتيب تنفيذ الـgoroutines | قناة أو `WaitGroup` |
| متى يعمل الكانس | لا تعتمد عليه. `runtime.GC()` للاختبار فقط |
| حجم البنية وحشوها | `encoding/*` لا نسخ بايتات |
| ترتيب `init` بين الملفّات | دالّة تهيئةٍ تناديها بنفسك |
| متى تُنفَّذ الـfinalizers | أغلق مواردك بـ`defer` |
| ثبات نصّ رسائل الأخطاء | `errors.Is` و`errors.As` لا مقارنة نصوص |
| ترتيب `select` بين فرعين جاهزين | صمِّم بلا اعتمادٍ على الأولوية |

**والصفّان الأخيران يُوقعان المحترفين**، لأن كليهما يعمل بثبات في التطوير.

## بابٌ يبقي الوعد قائماً

وعدُ ٢٠١٢ يقول إن البرنامج الصحيح يظلّ يعمل. **فكيف تُصلَح أخطاء السلوك إذن؟**

بآليةٍ اسمها `GODEBUG`: حين يتغيّر سلوكٌ قد يكسر كوداً قائماً، **يُبقي الفريق
السلوك القديم خلف مفتاح**، ويكون الاختيار الافتراضيّ بحسب سطر `go` في ملفّ
`go.mod` عندك.

```bash
GODEBUG=httplaxcontentlength=1 ./myserver
```

فترقية Go لا تغيّر سلوك وحدتك حتى **ترفع أنت** سطر `go` في `go.mod`. وقائمة
المفاتيح كلّها في `$GOROOT/doc/godebug.md` على جهازك.

**وهذا يشرح كيف تعيش لغةٌ ثلاث عشرة سنةً بلا كسر:** لا بتجميد السلوك، بل بجعل كل
تغييرٍ خطراً **قابلاً للإرجاع بمفتاح**، وربطِه بإعلانٍ صريح منك.

## المخزن، مرّةً أخيرة

اجمع الطريق كلّه في ملفٍّ واحد. **كل سطرٍ هنا جوابٌ عن إقليم:**

<!-- notice: مفسّر المتصفّح يعجز عن هذا البرنامج (واجهةٌ بمستقبِل مؤشّر داخل goroutines). شغّله محلياً. -->

<!-- run: no -->

```go
package main

import (
	"errors"
	"fmt"
	"sync"
	"sync/atomic"
)

var ErrNotFound = errors.New("store: key not found")

type Record struct {
	Key     string
	Value   []byte
	Deleted bool
}

type Sink interface {
	Write(Record) error
}

type Store struct {
	mu   sync.RWMutex
	data map[string]Record
	log  []Record
	sink Sink
}

func NewStore(sink Sink, hint int) *Store {
	return &Store{
		data: make(map[string]Record, hint),
		log:  make([]Record, 0, hint),
		sink: sink,
	}
}

func (s *Store) Put(key string, value []byte) error {
	owned := make([]byte, len(value))
	copy(owned, value)
	r := Record{Key: key, Value: owned}

	s.mu.Lock()
	s.data[key] = r
	s.log = append(s.log, r)
	sink := s.sink
	s.mu.Unlock()

	if sink == nil {
		return nil
	}
	if err := sink.Write(r); err != nil {
		return fmt.Errorf("store: sink %q: %w", key, err)
	}
	return nil
}

func (s *Store) AppendValue(dst []byte, key string) ([]byte, error) {
	s.mu.RLock()
	defer s.mu.RUnlock()

	r, ok := s.data[key]
	if !ok || r.Deleted {
		return dst, fmt.Errorf("store: get %q: %w", key, ErrNotFound)
	}
	return append(dst, r.Value...), nil
}

// الوجهة تُنادى **خارج القفل**، فهي مسؤولة عن تزامنها بنفسها.
type Counter struct{ n atomic.Int64 }

func (c *Counter) Write(Record) error { c.n.Add(1); return nil }

func main() {
	c := &Counter{}
	s := NewStore(c, 8)

	var wg sync.WaitGroup
	for i := 0; i < 3; i++ {
		wg.Add(1)
		go func(n int) {
			defer wg.Done()
			_ = s.Put(fmt.Sprintf("k%d", n), []byte("v"))
		}(i)
	}
	wg.Wait()

	src := []byte("hello")
	_ = s.Put("greeting", src)
	src[0] = 'X'

	buf := make([]byte, 0, 16)
	buf, err := s.AppendValue(buf, "greeting")
	fmt.Printf("%q %v\n", buf, err)

	_, err = s.AppendValue(buf[:0], "missing")
	fmt.Println(errors.Is(err, ErrNotFound), err)

	fmt.Println("سجلّات:", len(s.log), "· كتابات الوجهة:", c.n.Load())
}
```

<!-- out -->

```
"hello" <nil>
true store: get "missing": store: key not found
سجلّات: 4 · كتابات الوجهة: 4
```

## اقرأه سطراً سطراً

**`owned := make(...)` ثم `copy` قبل القفل.** النسخ خارج المنطقة الحرجة (٠٣)،
والملكية تنتقل إلى المخزن (٠٢) — ولذلك `src[0] = 'X'` بعدها **لم تصل**، والمخرَج
`"hello"`.

**`sink := s.sink` ثم `Unlock` ثم النداء.** لا نداء لغريبٍ تحت قفل (٠٣). **وثمن
هذا القرار مدفوعٌ في `Counter`:** لمّا خرج النداء من القفل صار على الوجهة أن تحمي
نفسها — و`atomic.Int64` هي الحماية (٠٩). **كتبتُ هذا السطر خطأً أوّل مرّة، وأمسكه
`go test -race`.**

**`AppendValue(dst, key)` بدل `Get`.** تُضيف إلى مخزنٍ يملكه المستدعي، فلا تخصيص
(٠٤). ومستقبِلها `RLock` لأنها قراءة (٠٣).

**`%w` و`ErrNotFound`.** الغياب خطأٌ مغلَّف يُفحَص بـ`errors.Is` لا بمقارنة نصّ
(٠٦).

**`Counter` مستقبِلاته مؤشّرات.** لأن فيه حالةً تتغيّر، ولأن نسخ نوعٍ فيه أداة
تزامن يُبطلها (٠٣، ٠٠).

## بذرة

انتهى التشريح. والمخزن الذي بدأتَ به في ٧٥ سطراً مفكَّكٌ بالكامل: كل سطرٍ فيه
تعرف **لماذا هو كذلك، وما ثمنه، وأين ينتهي ضمانه**.

وقبل الفصل الأخير، ثلاثة أسئلة جوابها ليس في هذا المنهج:

**واحد.** `AppendValue` تحمل `RLock` وهي تنسخ. فلو كانت القيمة ميغابايتاً وقارئوها
ألفاً، أيّهما أسوأ: القفل الطويل، أم النسخ خارج القفل من بياناتٍ قد تتغيّر تحتك؟
**قِس، ثم قرّر.**

**اثنان.** `log` تنمو أبداً. فمتى تُقصّ، ومن يقرّر؟ وهل تُقصّ بـ`s.log = s.log[n:]`
— وقد عرفتَ الآن ما تفعله هذه بالمصفوفة القديمة؟

**ثلاثة.** أضِف `Delete`. هل تحذف من الخريطة، أم ترفع `Deleted`؟ ولكلٍّ ثمنٌ في
الذاكرة وفي السجلّ وفي القراءة — **وقد صار عندك ما يقيسه**.

اكتب جوابك، ثم اكتب المقياس الذي يثبته.

**ويبقى واحد.** تعرف الآن كيف تعمل Go. والفصل الأخير عن كيف **تُكتب**: مخزنك
يصير حزمةً يستعملها غيرك — باسمٍ وتوثيقٍ واختبارٍ ومقياس.
