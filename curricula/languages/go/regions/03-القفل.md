# الإقليم ٠٣ — القفل والغريب

> في `Put` سطران متجاوران:
>
> ```
> s.mu.Lock()
> defer s.mu.Unlock()
> …
> return s.sink.Write(r)      ← نداءُ غريبٍ، والقفل في يدك
> ```
>
> `Sink` واجهة. أي أن الكود الذي يُنفَّذ هناك **لا تعرفه، ولم تُترجَمه معك، وقد
> يُكتَب بعد سنة**. وأنت تناديه وأنت تمسك قفل مخزنك.
>
> هذا الإقليم عن ثمن تلك السطور الثلاثة.

---

## نداءٌ لا تعرف ما وراءه

القفل عقدٌ ضمنيّ: **من يمسكه يَعِد بأن يتركه بسرعة**. والوعد سهل ما دام الكود
الذي تحته لك.

فإن ناديتَ واجهةً، خرج الوعد من يدك. والوجهة قد:

- تكتب على الشبكة، فتحمل قفلك ثانيةً كاملة
- تذعر، فيبقى القفل مأخوذاً — إلا أن يحرّره `defer`
- **تنادي مخزنك نفسه**

والثالثة هي التي تقتل. وهذه هي الحالة:

<!-- notice: هذا البرنامج **لا ينتهي** — يتجمّد ثم يُنهيه الـruntime. وهو المقصود. -->

<!-- run: no -->

```go
package main

import (
	"fmt"
	"sync"
)

type Store struct {
	mu   sync.Mutex
	data map[string]string
	sink func(key string)
}

func (s *Store) Put(key, value string) {
	s.mu.Lock()
	defer s.mu.Unlock()

	s.data[key] = value
	if s.sink != nil {
		s.sink(key)
	}
}

func (s *Store) Len() int {
	s.mu.Lock()
	defer s.mu.Unlock()
	return len(s.data)
}

func main() {
	s := &Store{data: map[string]string{}}

	s.sink = func(key string) {
		fmt.Println("الوجهة استُدعيت بـ:", key)
		fmt.Println("وتسأل عن الحجم…")
		fmt.Println("الحجم:", s.Len())
	}

	s.Put("a", "1")
	fmt.Println("انتهى")
}
```

`Len` طريقةٌ بريئة تقفل وتقرأ وتفتح. والوجهة تناديها. **توقّع المخرَج كاملاً.**

المخرَج (مقتطع: بعده أثر مكدّسٍ فيه مسارات جهاز المؤلّف):

```
الوجهة استُدعيت بـ: a
وتسأل عن الحجم…
fatal error: all goroutines are asleep - deadlock!
```

## قفلٌ لا يُعاد الدخول إليه

**`sync.Mutex` لا يقبل إعادة الدخول.** الخيط الذي يمسكه إن طلبه ثانيةً انتظر
نفسه إلى الأبد.

وهذا **قرار**، لا نقص. القفل التعاوديّ موجودٌ في لغاتٍ أخرى، ورفضته Go لسبب:

> القفل يحرس **ثابتاً** (`invariant`). وحين تدخل ثانيةً وأنت داخل، فأنت تدخل
> والثابت **مكسورٌ في منتصف تعديل**. القفل التعاوديّ يعطيك دخولاً ويخفي عنك أن ما
> تقرؤه غير متّسق.

فالجمود الذي رأيتَه **إفصاحٌ فوريّ عن خطأ تصميم**، لا عقوبة. والبديل — لو سمحت
اللغة — بياناتٌ فاسدة بصمت.

## العلاج: انسخ، أطلق، ثم نادِ

القاعدة سطرٌ واحد: **لا تحمل قفلاً وأنت تنادي كوداً لا تملكه.**

```go
package main

import (
	"fmt"
	"sync"
)

type Store struct {
	mu   sync.Mutex
	data map[string]string
	sink func(key string)
}

func (s *Store) Put(key, value string) {
	s.mu.Lock()
	s.data[key] = value
	sink := s.sink
	s.mu.Unlock()

	if sink != nil {
		sink(key)
	}
}

func (s *Store) Len() int {
	s.mu.Lock()
	defer s.mu.Unlock()
	return len(s.data)
}

func main() {
	s := &Store{data: map[string]string{}}

	s.sink = func(key string) {
		fmt.Println("الوجهة استُدعيت بـ:", key)
		fmt.Println("الحجم:", s.Len())
	}

	s.Put("a", "1")
	fmt.Println("انتهى")
}
```

<!-- out -->

```
الوجهة استُدعيت بـ: a
الحجم: 1
انتهى
```

**ولاحظ أن `defer` اختفت.** ذاك ثمن هذا النمط: صار عليك أن تفتح بيدك، وأن تتذكّر
كل مسار خروج. مقايضةٌ حقيقية — أمانُ الجمود مقابل أمان النسيان.

وثمنٌ ثانٍ **أخطر**: بين `Unlock` والنداء صارت هناك فجوة. فما يراه `sink` قد يكون
قديماً. والقاعدة: **مرّر لقطةً، لا وعداً بأنها ما زالت الحقيقة.**

## القفل يحرس متغيّراً، لا بايتات

أشهر سوء فهمٍ عن الأقفال. توقّع مخرَج هذا:

```go
package main

import (
	"fmt"
	"sync"
)

type Store struct {
	mu   sync.Mutex
	data map[string]string
}

func (s *Store) All() map[string]string {
	s.mu.Lock()
	defer s.mu.Unlock()
	return s.data
}

func (s *Store) Put(key, value string) {
	s.mu.Lock()
	defer s.mu.Unlock()
	s.data[key] = value
}

func main() {
	s := &Store{data: map[string]string{"a": "1"}}

	out := s.All()
	out["b"] = "دُسّت من خارج القفل"

	fmt.Println(len(s.data), s.data["b"])
}
```

`All` تقفل وتفتح كما ينبغي. والكتابة في `out` تقع **بعد** أن فُتح القفل.

المخرَج:

```
2 دُسّت من خارج القفل
```

## لأن الخريطة مؤشّر

`All` أعادت **المحروس نفسه**. والقفل حرس لحظة القراءة لا ما بعدها.

وهذا تطبيقٌ مباشر للبديهية الثانية: `return s.data` نسخت رأس الخريطة نسخاً كاملاً
— **والرأس كلمةٌ واحدة، مؤشّر**. فصار للمستدعي مقبضٌ على نفس الجدول، بلا قفل.

```
   s.data ──┐
             ├──► [ الجدول ]   ← اثنان يكتبان فيه، وواحدٌ فقط يقفل
   out    ──┘
```

**القاعدة:** ما يخرج من تحت القفل يجب أن يكون **مملوكاً للخارج**. فإمّا أن تُرجع
نسخةً (`maps.Clone`)، أو أن تُرجع ما استُخرج (`Len`، `Get`)، أو ألّا تُرجع شيئاً.

وينطبق الشيء نفسه على الشريحة وعلى أيّ بنيةٍ فيها مؤشّر. **وقد رأيتَ في الإقليم
السابق كيف يبدو ذلك بالبايتات.**

## قفلٌ يُنسَخ فلا يقفل

وهذه تجمع البديهية الثانية مع درس مجموعة الطُّرق:

```go
package main

import (
	"fmt"
	"sync"
)

type Counter struct {
	mu sync.Mutex
	n  int
}

func (c Counter) Inc() {
	c.mu.Lock()
	c.n++
	c.mu.Unlock()
}

func main() {
	var c Counter
	c.Inc()
	c.Inc()
	c.Inc()
	fmt.Println("العدّاد:", c.n)
}
```

الكود صحيحٌ نحوياً، ويُترجَم بلا شكوى، ويعمل بلا ذُعر. **توقّع الرقم.**

المخرَج:

```
العدّاد: 0
```

## المستقبِل قيمةٌ، فكل شيء نسخة

`func (c Counter) Inc()` — مستقبِلٌ **قيمة**. فكل نداءٍ ينسخ البنية كاملةً: القفل
والعدّاد معاً.

فقفلتَ نسخةً، وزدتَ عدّاد نسخةٍ، ثم رميتَ النسخة. ثلاث مرّات.

**وهذا ليس خطأً نادراً** — هو أشهر خطأ تزامنٍ في Go، ولذلك له فحصٌ خاصّ:

```bash
go vet ./...
```

<!-- out -->

```
main.go:13:9: Inc passes lock by value: main.Counter contains sync.Mutex
```

**احفظ هذه القاعدة:** أيّ نوعٍ يحوي `sync.Mutex` — أو أيّ شيءٍ لا يجوز نسخه —
**يُمرَّر بالمؤشّر دائماً**، ومستقبِلاته كلّها مؤشّرات. ولو طريقةٌ واحدة لا تعدّل.

## ترتيب القفلين

القفل الواحد سهل. والاثنان مسألةٌ أخرى:

<!-- notice: هذا البرنامج أيضاً لا ينتهي — ويُنهيه الـruntime. -->

<!-- run: no -->

```go
package main

import (
	"fmt"
	"sync"
)

func main() {
	var a, b sync.Mutex
	held := make(chan struct{})
	done := make(chan struct{})

	go func() {
		b.Lock()
		close(held)
		a.Lock()
		a.Unlock()
		b.Unlock()
		close(done)
	}()

	a.Lock()
	<-held
	fmt.Println("كلٌّ يحمل واحداً، وكلٌّ يطلب الآخر")
	b.Lock()
	b.Unlock()
	a.Unlock()
	<-done
}
```

<!-- out: بعده أثر مكدّسٍ فيه مسارات جهاز المؤلّف -->

```
كلٌّ يحمل واحداً، وكلٌّ يطلب الآخر
fatal error: all goroutines are asleep - deadlock!
```

**واحدٌ أخذ `a` ثم طلب `b`، والآخر أخذ `b` ثم طلب `a`.** ولا أحد يتنازل.

والقناة هنا ليست جزءاً من الخطأ — هي التي جعلته **حتمياً** بدل أن يقع مرّةً في
الألف. وذاك أخطر ما في هذا الصنف: يمرّ في الاختبارات ويقع في الإنتاج.

**والعلاج قاعدةٌ واحدة تُكتب في مشروعك:** رتّب أقفالك ترتيباً كلّياً، ولا يأخذ أحدٌ
قفلاً متأخّراً وهو يحمل متقدّماً. أو — وهو الأفضل — **صمّم بحيث لا يُؤخَذ قفلان
معاً أبداً**.

ولاحظ أن الـruntime كشفه: يعرف أن كل الـgoroutines نائمة، فيصرخ. **لكنه لا يكشف
جموداً يشمل بعضها فقط** ما دامت واحدةٌ تعمل.

## قارئان وكاتب

`sync.RWMutex` قفلان في واحد: قرّاءٌ كثيرون معاً، أو كاتبٌ واحد وحده.

```go
package main

import (
	"fmt"
	"sync"
)

func main() {
	var mu sync.RWMutex

	mu.RLock()
	mu.RLock()
	fmt.Println("قارئان معاً: نجح")
	mu.RUnlock()
	mu.RUnlock()

	var wg sync.WaitGroup
	wg.Add(1)
	go func() {
		defer wg.Done()
		mu.Lock()
		fmt.Println("الكاتب دخل بعد خروجهما")
		mu.Unlock()
	}()
	wg.Wait()
}
```

<!-- out -->

```
قارئان معاً: نجح
الكاتب دخل بعد خروجهما
```

**وهذا لا يعني أنه أسرع.** `RWMutex` أثقل من `Mutex` في الحالة غير المتنازَع
عليها، ولا يربح إلا حين تكون القراءات **كثيرةً وطويلة**. فقراءةٌ من خريطةٍ تستغرق
نانوثوانٍ لا تستحقّه.

**وفخٌّ يجب أن تعرفه:** `RLock` **ليس تعاودياً هو الآخر**. فإن أمسك قارئٌ القراءة
ثم طلبها ثانيةً، وكان كاتبٌ ينتظر بينهما، جمد الثلاثة — لأن الكاتب المنتظر يمنع
القرّاء الجدد.

## `WaitGroup`: أضِف قبل أن تطلق

```go
package main

import (
	"fmt"
	"sync"
)

func main() {
	var mu sync.Mutex
	var wg sync.WaitGroup
	count := 0

	for i := 0; i < 1000; i++ {
		wg.Add(1)
		go func() {
			defer wg.Done()
			mu.Lock()
			count++
			mu.Unlock()
		}()
	}

	wg.Wait()
	fmt.Println(count)
}
```

<!-- out -->

```
1000
```

ألف `goroutine`، ونتيجةٌ **حتميّة**. الترتيب غير مضمون، والمجموع مضمون — وهذا
الفرق هو التزامن كلّه.

**وموضع `wg.Add(1)` ليس ذوقاً.** لو كتبتَه داخل الـ`goroutine` لأمكن أن تصل
`wg.Wait()` قبل أن تبدأ أيٌّ منها، فترى عدّاداً صفراً وتمضي. **أضِف في الأب، لا في
الابن.**

و`wg` لا يُنسَخ أيضاً — للسبب نفسه الذي رأيتَه في `Counter`. مرّره مؤشّراً أو
احبسه في إغلاق.

## خطأٌ لا تراه في المخرَج

آخر لقطةٍ هنا، ولا مفاجأة فيها — **وهذا هو الدرس**:

```go
package main

import (
	"fmt"
	"sync"
)

type Store struct {
	mu   sync.Mutex
	data map[string]string
}

func (s *Store) Get(key string) string {
	s.mu.Lock()
	defer s.mu.Unlock()
	return s.data[key]
}

func main() {
	s := &Store{data: map[string]string{"n": "1"}}

	if s.Get("n") == "1" {
		s.mu.Lock()
		s.data["n"] = "2"
		s.mu.Unlock()
	}

	fmt.Println(s.Get("n"))
}
```

<!-- out -->

```
2
```

**صحيحٌ تماماً — بخيطٍ واحد.** والقفل مأخوذٌ في القراءة وفي الكتابة، فلا شيء
يشتكي، ولا `go vet` يمسكه، ولا `-race` يراه في هذا البرنامج.

لكن بين `Get` و`Lock` **فجوةٌ لا قفل فيها**. فخيطٌ آخر يستطيع أن يغيّر `n` هناك،
فتكتب `"2"` بناءً على حقيقةٍ ماتت.

**فالقفل يجعل كل عمليةٍ ذرّية، ولا يجعل تسلسلها ذرّياً.** و«افحص ثم افعل» يحتاج
قفلاً واحداً يغطّي الاثنتين — أو طريقةً واحدة تفعلهما تحت قفلٍ واحد.

## بذرة

القفل الآن مفهوم: ما يحرسه، ومتى يُترَك، ولمن يُنسَخ.

وبقيت من مخزنك بذرةٌ واحدة معلّقة منذ إقليمين:

**`Get` تُرجع نسخةً تشارك المخزن مصفوفتها. والحلّ الواضح أن تنسخ البايتات.**

الحلّ صحيح، ولن نجادل فيه. لكن **قِسه**: كم يكلّف؟ وأين يذهب الوقت؟ الجواب ليس
حيث تظنّ، ولا يُعرَف بالحدس — يُعرَف بأداة.

الإقليم القادم يقيس.
