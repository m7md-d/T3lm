# الإقليم ٠٥ — المؤجَّل

> `defer s.mu.Unlock()` في مخزنك **صحيحة**، ولن نغيّرها. لأن نطاقها دالّةٌ قصيرة،
> ولها مخرجان، و`defer` تغطّيهما.
>
> لكنّا قلنا يومها جملةً ولم نُثبتها: **`defer` لا تُنفَّذ عند نهاية الكتلة `{}`،
> بل عند رجوع الدالّة.** وقلنا إن الفرق سيؤذيك في حلقة.
>
> هذا الإقليم يجعله يؤذيك، ثم يُريك الكلفة الحقيقية للأداة.

---

## مؤجَّلٌ في حلقة

<!-- notice: مفسّر المتصفّح **يخطئ** في تقييم وسائط `defer` — يقرؤها عند التنفيذ لا عند التأجيل. ولذلك لا زرّ هنا: المخرَج المسجَّل من الأداة الحقيقية. -->

<!-- run: no -->

```go
package main

import "fmt"

func main() {
	for i := 0; i < 3; i++ {
		defer fmt.Println("مؤجَّل", i)
		fmt.Println("دورة", i)
	}
	fmt.Println("نهاية الحلقة")
}
```

سبعة أسطر. **توقّعها بترتيبها**، وانتبه لشيئين: متى تُطبع، وبأيّ قيمةٍ لـ`i`.

المخرَج:

```
دورة 0
دورة 1
دورة 2
نهاية الحلقة
مؤجَّل 2
مؤجَّل 1
مؤجَّل 0
```

## الكتلة ليست النطاق

المؤجَّلات لا تُنفَّذ عند `}` الحلقة. تتراكم في **مكدّسٍ خاصّ بالدالّة**، ويُفرَّغ
عند رجوعها — من الأعلى إلى الأسفل.

```
أثناء الحلقة              عند رجوع main
┌──────────────┐
│ Println(i=2) │ ◄─ آخر ما دُفع    ──► يُنفَّذ أوّلاً
│ Println(i=1) │
│ Println(i=0) │ ◄─ أوّل ما دُفع    ──► يُنفَّذ آخراً
└──────────────┘
```

وهذا الترتيب **مقصود لا اعتباطيّ**: المؤجَّلات غالباً تحرير موارد، والمورد الذي
فُتح أخيراً هو الذي يجب أن يُغلق أوّلاً — تماماً كإطارات المكدّس.

**فالقاعدة:** `defer` تربط عمر العمل بعمر **الدالّة**. فإن أردتَ أن تربطه بعمر
دورةٍ في حلقة، فالحلقة ليست دالّة.

## ثلاثة مفتوحة معاً

بمثالٍ أقرب إلى الحقيقة — دالّةٌ تحجز مورداً وتُرجع ما يحرّره:

```go
package main

import "fmt"

var open int

func acquire(name string) func() {
	open++
	fmt.Printf("فتح %s — المفتوح الآن %d\n", name, open)
	return func() {
		open--
		fmt.Printf("أغلق %s — المفتوح الآن %d\n", name, open)
	}
}

func main() {
	for _, name := range []string{"a", "b", "c"} {
		release := acquire(name)
		defer release()
	}
	fmt.Println("بعد الحلقة، المفتوح:", open)
}
```

**توقّع الرقم في السطر الرابع.** وتوقّع ترتيب الإغلاق.

المخرَج:

```
فتح a — المفتوح الآن 1
فتح b — المفتوح الآن 2
فتح c — المفتوح الآن 3
بعد الحلقة، المفتوح: 3
أغلق c — المفتوح الآن 2
أغلق b — المفتوح الآن 1
أغلق a — المفتوح الآن 0
```

## لماذا هذا خطرٌ حقيقيّ

الثلاثة أُغلقت في النهاية — فما المشكلة؟

المشكلة أن العدد كان `3` **في نفس اللحظة**. وثلاثة أشياء صغيرة في هذا المثال، وفي
الكود الحقيقيّ:

- مقبض ملفٍّ لكل ملفّ في مجلّد — والنظام يحدّ المقابض المفتوحة لكل عملية
- اتصال قاعدة بيانات لكل صفّ — والمسبح ينفد
- **قفل** لكل عنصر — وقد تعرف الآن إلى أين يقود ذلك

فالحلقة التي تعالج مئة ألف ملفّ لا تنهار عند الملفّ الأول. **تنهار عند الحدّ**،
وبعد أن تكون قد عملت في الإنتاج ثلاثة أشهر.

**والفحص:** أهناك `defer` داخل حلقةٍ لا تعرف عدد دوراتها سلفاً؟ ذاك خطأ حتى تثبت
العكس.

## العلاج: اجعل الجسم دالّة

`defer` مربوطةٌ بالدالّة — **فأعطها دالّة**:

```go
package main

import "fmt"

var open int

func acquire(name string) func() {
	open++
	fmt.Printf("فتح %s — المفتوح الآن %d\n", name, open)
	return func() {
		open--
		fmt.Printf("أغلق %s — المفتوح الآن %d\n", name, open)
	}
}

func each(name string) {
	release := acquire(name)
	defer release()
}

func main() {
	for _, name := range []string{"a", "b", "c"} {
		each(name)
	}
	fmt.Println("بعد الحلقة، المفتوح:", open)
}
```

<!-- out -->

```
فتح a — المفتوح الآن 1
أغلق a — المفتوح الآن 0
فتح b — المفتوح الآن 1
أغلق b — المفتوح الآن 0
فتح c — المفتوح الآن 1
أغلق c — المفتوح الآن 0
بعد الحلقة، المفتوح: 0
```

**واحدٌ مفتوحٌ في كل لحظة.** والدالّة المستخرَجة قد تكون مجهولةً تُنادى في مكانها
— `func() { … }()` — إن لم تستحقّ اسماً.

## متى تُقرأ القيمة

سطران متجاوران في نفس الدالّة، وجوابان مختلفان:

<!-- notice: هذا بالذات ما يخطئ فيه مفسّر المتصفّح. المخرَج المسجَّل من الأداة الحقيقية. -->

<!-- run: no -->

```go
package main

import "fmt"

func main() {
	x := 1

	defer fmt.Println("وسيطٌ قُيّم عند التأجيل:", x)
	defer func() { fmt.Println("إغلاقٌ يقرأ عند التنفيذ:", x) }()

	x = 2
	fmt.Println("x الآن:", x)
}
```

كلاهما يطبع `x`، وكلاهما يُنفَّذ بعد `x = 2`. **توقّع الرقمين.**

المخرَج:

```
x الآن: 2
إغلاقٌ يقرأ عند التنفيذ: 2
وسيطٌ قُيّم عند التأجيل: 1
```

## الوسيط قيمة، والإغلاق مرجع

`defer f(x)` **تُقيّم `x` الآن** وتحفظ القيمة مع التأجيل. أُجّل النداء، لا التقييم.

`defer func(){ … x … }()` تؤجّل دالّةً **بلا وسائط**، وتلك تلتقط `x` بالمرجع فتقرأ
قيمتها لحظة التنفيذ.

```
defer fmt.Println("…", x)      →  [ Println │ "…" │ 1 ]   ← القيمة محفوظة
defer func(){ … x … }()        →  [ closure ] ──► x       ← عنوانٌ يُقرأ لاحقاً
```

**وهذا ليس تفصيلاً.** أشهر استعمالٍ له:

`defer file.Close()` — يُقيَّم `file` الآن. فإن أعدتَ إسناد `file` بعده، أُغلق
**القديم** لا الجديد.

و`defer func(){ log(err) }()` — يقرأ `err` عند الخروج، فيرى آخر قيمة. وهو
المقصود عادةً.

**والقاعدة:** إن أردتَ حالة الخروج فاستعمل إغلاقاً؛ وإن أردتَ حالة الدخول فمرّرها
وسيطاً. والاثنان صحيحان، والخلط بينهما ليس كذلك.

## العائد المسمّى

آخر فروق `defer`، وأقلّها شهرةً وأكثرها استعمالاً في المكتبة القياسية:

```go
package main

import "fmt"

func plain() int {
	r := 1
	defer func() { r = 2 }()
	return r
}

func named() (r int) {
	r = 1
	defer func() { r = 2 }()
	return r
}

func main() {
	fmt.Println(plain(), named())
}
```

<!-- out -->

```
1 2
```

الدالّتان متطابقتان حرفاً بحرف **إلا في اسم العائد**. والفرق آليٌّ لا سحريّ:

`return r` ليست تعليمةً واحدة. هي **اثنتان**: أسنِد إلى متغيّر العائد، ثم نفّذ
المؤجَّلات، ثم ارجع.

```
plain()   →  [عائدٌ مجهول] = r(1)  ;  المؤجَّل يغيّر r  ;  يُرجَع 1
named()   →  r = r(1)              ;  المؤجَّل يغيّر r  ;  يُرجَع 2
```

في `plain` غيّر المؤجَّل متغيّراً محلّياً **بعد** أن نُسخت قيمته إلى مكان العائد.
وفي `named` المتغيّر **هو** مكان العائد.

**وهذا هو الباب الوحيد لتعديل ما تُرجعه دالّةٌ بعد `return`** — وعليه يقوم كل نمط
استرداد الذُّعر.

## الذُّعر لا يُلغي المؤجَّل

```go
package main

import "fmt"

func safe() (err error) {
	defer func() {
		if r := recover(); r != nil {
			err = fmt.Errorf("استُرد: %v", r)
		}
	}()

	panic("انهيار")
}

func main() {
	fmt.Println(safe())
	fmt.Println("البرنامج ما زال حيّاً")
}
```

<!-- out -->

```
استُرد: انهيار
البرنامج ما زال حيّاً
```

اجتمعت هنا ثلاث قطعٍ لا تعمل إلا معاً: **الذُّعر ينشر ويُنفّذ المؤجَّلات في طريقه**،
و**`recover` لا تعمل إلا داخل مؤجَّل**، و**العائد المسمّى** هو ما يسمح بتحويل
الذُّعر إلى خطأ مُرجَع.

انزع أيّاً منها فلا شيء يعمل. ولهذا ترى هذا الشكل بالحرف نفسه في كل مكان — ليس
اصطلاحاً بل **الشكل الوحيد الممكن**.

## ما يُلغيه فعلاً

المؤجَّل ليس ضماناً مطلقاً. يُتخطّى في حالتين:

<!-- notice: مفسّر المتصفّح لا ينهي العملية عند `os.Exit`، فيُظهر ذُعراً وينفّذ المؤجَّل. **عكس الحقيقة.** -->

<!-- run: no -->

```go
package main

import (
	"fmt"
	"os"
)

func main() {
	defer fmt.Println("مؤجَّلٌ لن يُنفَّذ")
	fmt.Println("قبل الخروج")
	os.Exit(0)
}
```

<!-- out -->

```
قبل الخروج
```

**`os.Exit` تُنهي العملية فوراً.** لا مؤجَّلات، ولا إغلاق ملفّات، ولا إفراغ
مخازن. وكذلك `log.Fatal` لأنها تناديها.

والثانية: **ذُعرٌ غير مُسترَدّ في `goroutine` أخرى** يُنهي البرنامج كلّه، فلا
تُنفَّذ مؤجَّلات الـ`goroutine` الرئيسية.

فإن كان لك عملٌ لا بدّ منه عند الخروج، **فلا تعتمد على `defer` وحده** في دالّةٍ
قد تُنهي العملية.

## هل `defer` مكلفة؟

كانت. وحتى الإصدار ١.١٣ كانت تُخصّص سجلّاً وتضيفه إلى قائمة. ثم أُعيدت كتابتها في
١.١٤ فصارت — في الحالة الشائعة — **تُدرَج في الكود مباشرةً**.

قِسها بنفسك:

```bash
go test -bench=. -run=XXX
```

<!-- out: أسقطتُ سطور goos/pkg وسطر PASS -->

```
cpu: Apple M1
BenchmarkWithDefer-8      82778637    13.98 ns/op
BenchmarkWithoutDefer-8   88806384    13.72 ns/op
```

**ربع نانوثانية.** على قفلٍ يكلّف أربع عشرة.

فالنصيحة القديمة «تجنّب `defer` في المسارات الساخنة» **صحيحةٌ لإصدارٍ مضى**، وهي
مثالٌ حيّ على ما قلناه في الفصل صفر: جملةٌ عن Go لا تذكر إصدارها ادّعاءٌ ناقص.

**والحدّ الباقي:** الإدراج المباشر لا يقع إن كانت `defer` في حلقة، أو كان عددها في
الدالّة يتغيّر بحسب المسار. وتلك الحالة نفسها التي بدأنا بها هذا الإقليم.

## بذرة

`defer` مفهومة الآن: نطاقها، وتقييمها، وترتيبها، وثمنها، وحدّها.

ورأيتَ في اللقطة قبل الأخيرة شيئاً مرّ سريعاً: **`panic` و`recover`**.

استعملناهما هناك أداةً، ولم نسأل عنهما. وفي مخزنك سؤالٌ معلّق منذ الفصل صفر: لماذا
تُرجَع الأخطاء ولا تُرمى؟ ومتى يُذعَر إذن؟ وما الفرق بين خطأٍ وذُعر؟

الإقليم القادم عن نموذج الفشل كلّه.
