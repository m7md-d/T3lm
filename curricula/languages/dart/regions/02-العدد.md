# الإقليم ٠٢ — العدد والقيمة

> أوّل ما تلمسه من لغةٍ جديدة هو العدد، وأوّل ما تظنّه مألوفاً هو العدد.
>
> وفي هذا الإقليم أربعة مواضع يعطيك فيها الرمزُ نفسه جواباً غير الذي يعطيه في
> C — واحدٌ منها يعطي جوابين مختلفين في Dart نفسها، حسب أين تشغّلها.

## القسمة لا تعني ما تعنيه في C

```dart
void main() {
  print(5 / 2);
  print(5 ~/ 2);
  print((5 / 2).runtimeType);
}
```

<!-- out -->

```
2.5
2
double
```

```c
#include <stdio.h>
int main(void) { printf("%d\n", 5 / 2); }
```

<!-- c -->

```
2
```

**`/` في Dart لا تُرجِع `int` أبداً** — ولو كان الطرفان صحيحين. نوع إرجاعها
`double` دائماً، مكتوبٌ هكذا في `lib/core/num.dart` سطر ١٥٥.

والسبب بديهيّتان تصطدمان: العدد الصحيح **صنفٌ في الشجرة** لا نمط بتات، وقسمة
اثنين على اثنين قيمةٌ حقيقية. فبدل أن يتغيّر معنى `/` بنوع طرفيه — كما في C —
ثُبِّت معناها وأُعطيت القسمةُ الصحيحة رمزاً خاصّاً: `~/`.

**والخطأ الذي يمنعه:** في C يقرأ الناظرُ `a / b` ولا يعرف أي عملية هي حتى يتتبّع
نوعي الطرفين. وهنا يعرف من الرمز.

## `%` ليست بقيّة C

**الاعتقاد الشائع:** «`%` تُرجِع باقي القسمة، وإشارتها كإشارة المقسوم — كما في
كل لغة.»

**ولماذا يبدو مقنعاً:** لأنه صحيحٌ في C وC++ وJava وGo وRust. خمس لغاتٍ تتّفق،
فيصير الافتراض قاعدة.

```dart
void main() {
  print(-7 % 3);
  print((-7).remainder(3));
  print(-7 ~/ 3);
}
```

<!-- out -->

```
2
-1
-2
```

```c
#include <stdio.h>
int main(void) {
    printf("%d\n", -7 % 3);
    printf("%d\n", -7 / 3);
}
```

<!-- c -->

```
-1
-2
```

**الآلية:** عمليتان مختلفتان تحملان الاسم نفسه في الأدبيات.

<!-- part -->

```
              -7 ÷ 3
   truncate toward zero :  q = -2 ,  r = -1      ← C's  %   ,  Dart's .remainder()
   floor / euclidean    :  q = -3 ,  r =  2      ← Dart's %
   in both:  q * 3 + r  ==  -7
```

**القاعدة الصحيحة:** `%` في Dart **مقياسٌ** (modulo) لا بقيّة — نتيجتها بين الصفر و«المقسوم عليه»
مطلقاً — يشمل الصفر ولا يبلغ الحدّ — فلا تكون سالبة أبداً. و`remainder()` هي بقيّة C.

**وحدُّها:** الاثنتان تتّفقان حين يكون المقسوم موجباً. ولهذا لا يُكتشَف الفرق في
الاختبارات — يُكتشَف في الإنتاج، عند أوّل مُدخَلٍ سالب.

**وأين يؤذي:** فهرسةٌ دائرية `list[i % list.length]`. في C تنفجر عند `i` سالبة،
وفي Dart تعمل. ومن نقل الكود من Dart إلى C نقل معها عيباً صامتاً.

## `int` ٦٤ بتاً، والالتفاف **معرَّف**

```dart
void main() {
  const max = 9223372036854775807;
  print(max + 1);
  print(1 << 63);
  print(-1 >>> 60);
}
```

<!-- out -->

```
-9223372036854775808
-9223372036854775808
15
```

الالتفاف نفسه الذي تعرفه من C — **لكن بفرقٍ واحدٍ حاسم**: في C فيض العدد الصحيح
**المُشار** سلوكٌ غير معرَّف (المواصفة §٦٫٥/٥). المترجم يملك أن يفترض أنه لا يقع،
وأن يحذف فحصاً كتبتَه بناءً على ذلك.

**وفي Dart سلوكٌ موصوف:** متمّم اثنين على ٦٤ بتاً، والنتيجة مكتوبة. والفرق ليس
راحة — هو أن ما تقرؤه هنا يبقى صحيحاً بعد ترقية المترجم.

والقسمة على صفر مثالٌ آخر:

```dart
void main() {
  print(1 ~/ 0);
}
```

<!-- err -->

```
Unhandled exception:
IntegerDivisionByZeroException
```

انفجارٌ **معلوم**، بنوعٍ تلتقطه إن أردت. أمّا في C فسلوكٌ غير معرَّف: جرّبتُه
بـ`cc -O2` فطبع عدداً عشوائياً وخرج بالرمز صفر — لا إشارة، ولا رسالة.

## وعلى الويب ليست كذلك

كل ما سبق كان `@vm`. وهذا هو الموضع الذي وعدتُك به في الإقليم ٠١.

```dart
void main() {
  final n = int.parse('9007199254740992');
  print(n + 1 == n);
  print(1.0 is int);
  print(int.parse('1000000000000000003') % 10);
}
```

<!-- out -->

```
false
false
3
```

<!-- web -->

```
true
true
0
```

**السطر الأول يقول إن عدداً يساوي نفسه زائداً واحداً.** والسبب في الشكل، لا في
اللغة:

<!-- part -->

```
  native int : 64-bit two's complement
  ┌─┬──────────────────────────────────────────────────────────┐
  │S│                      63 value bits                       │
  └─┴──────────────────────────────────────────────────────────┘
     exact for every integer in  [-2^63 , 2^63)

  web int    : IEEE-754 binary64  (there is no other number in JS)
  ┌─┬───────────────┬──────────────────────────────────────────┐
  │S│  exponent 11  │            mantissa 52                   │
  └─┴───────────────┴──────────────────────────────────────────┘
     exact for every integer in  [-2^53 , 2^53]
     beyond that: the gap between representable values is 2, then 4, then 8 …
```

عند `2^53` تصير المسافة بين قيمتين متجاورتين **اثنين**. فـ`n + 1` ليس له موضع،
فيُقرَّب إلى `n`. والسطر الثالث الأثر نفسه: آخرُ رقمٍ في عددٍ من تسعة عشر رقماً
ضاع في التقريب.

**والسطر الثاني أعمق:** `1.0 is int` صحيحٌ على الويب، لأن `int` و`double` هناك
**التمثيل نفسه**. البديهية الثانية لم تُكسَر — النوع لا يكذب — لكن ما يعنيه
«النوع» تغيّر بتغيّر ما تحته.

**وحدُّ هذا كلّه واحد:** إن كان برنامجك سيعمل على الويب، فأعدادك الصحيحة آمنةٌ
حتى `2^53` لا `2^63`. وما تجاوزها يحتاج `BigInt`.

## `double` هو IEEE 754 نفسه

هنا لا فرق عن C، ولا فرق بين المنصّتين. والفخّ نفسه:

```dart
void main() {
  print(0.1 + 0.2 == 0.3);
  print((0.1 + 0.2).toStringAsFixed(20));
  print(1.0 / 0.0);
  print(double.nan == double.nan);
}
```

<!-- out -->

```
false
0.30000000000000004441
Infinity
false
```

`0.1` ليست عُشراً — هي أقرب `double` إليه. والسطر الأخير من المواصفة نفسها:
`NaN` لا تساوي شيئاً، ولا نفسها. فمقارنةُ عائمين بـ`==` قرارٌ يُبرَّر، لا عادة.

**ولاحظ أن `1.0 / 0.0` لم تنفجر** بينما `1 ~/ 0` انفجرت. عمليتان مختلفتان على
نوعين مختلفين، ولكلٍّ قاعدتها.

## أين البايتات؟

لا `unsigned` في Dart، ولا `uint8`، ولا تحكّم في عرض العدد. فأين يذهب من يقرأ
بروتوكولاً أو ملفّاً ثنائياً؟

```dart
import 'dart:typed_data';

void main() {
  final b = Uint8List(4);
  b[0] = 300;
  b[1] = -1;
  print(b);

  final v = ByteData.view(b.buffer);
  v.setInt32(0, -2, Endian.big);
  print(b);
  print(v.getUint32(0, Endian.big));
}
```

<!-- out -->

```
[44, 255, 0, 0]
[255, 255, 255, 254]
4294967294
```

**`dart:typed_data` هو الجواب**، وفيه ما تعرفه من C: عرضٌ ثابت، واقتطاعٌ عند
الإسناد (`300` صارت `44`، و`-1` صارت `255`)، وترتيب بايتاتٍ تعلنه صراحةً.

**والفرق عن C:** الاقتطاع هنا **معرَّف** لا ضمنيّ، والنافذة (`ByteData.view`)
تشترك في المخزن نفسه بلا نسخ — وهذا أقرب ما تصل إليه من `char*` في هذه اللغة.
والإقليم ٢٠ يعبر بهذا المخزن إلى C فعلاً.

## والنصّ وحداتُ UTF-16

القيمة الأخيرة في هذا الإقليم ليست عدداً — لكن طولها عدد، والعدد يكذب.

```dart
void main() {
  const s = 'أهلاً👋';
  print(s.length);
  print(s.runes.length);
  print(s[5]);
}
```

<!-- out -->

```
7
6
�
```

**`String` في Dart سلسلةُ وحدات UTF-16**، و`length` تعدّها هي لا الحروف.
والإيموجي يشغل وحدتين، فالفهرس `5` يقع في **نصف** زوجٍ بديل — فيخرج محرف
الاستبدال.

`runes` تعطيك النقاط البرمجية (٦). وحتى هي ليست «الحروف»: عَلَمٌ أو إيموجي بلون
بشرةٍ عدّةُ نقاطٍ يراها الإنسان حرفاً واحداً، وذلك يحتاج حزمةً خارج اللغة.

**والقاعدة:** `s.length` عددُ وحدات التخزين، لا عدد ما يراه القارئ. ومن بنى عليها
اقتطاعاً أو محاذاةً في واجهة، كسر النصّ العربيّ أوّلاً.

## التمرين

**١ — اجعل الفرق يظهر.** اكتب دالّة `wrapIndex` تأخذ فهرساً وطولاً وتُرجِع
فهرساً صالحاً دائماً، بما في ذلك الفهرس السالب. اكتبها **مرّتين**: مرّةً بـ`%` ومرّةً
بـ`remainder`. ثم اختبر الاثنتين على `i` من `-10` إلى `10`.

أيّهما احتاجت سطراً إضافياً؟ ولماذا؟

**٢ — احسب الحدّ قبل أن تقيسه.** بلا تشغيل: ما أكبر عددٍ صحيح لا يزال يختلف
عن نفسه زائداً واحداً، على الويب؟ اكتب الجواب، ثم ابنِ برنامجاً يبحث عنه بمضاعفةٍ ثم
تنصيف، وترجمه بـ`dart compile js`.

**٣ — اقرأ ملفّاً ثنائياً.** خذ أوّل ثمانِ بايتاتٍ من أي ملفّ PNG واقرأ منها رقم
العرض والارتفاع (هما `int32` كبيرا الطرف عند الإزاحة ١٦). استعمل `ByteData` ولا
تستعمل `int.parse`.

ثم اسأل: كم نسخةً للبيانات صنعتَ من الملفّ إلى العدد؟

## الخلاصة

| ما رأيتَه | البديهية | أين يُستعمل بعدُ |
|---|---|---|
| `/` تُرجِع `double` دائماً | الأولى — النوع صنفٌ لا نمط بتات | ٠٩ |
| `%` مقياسٌ لا بقيّة | الوضوح على المألوف | كل فهرسةٍ دائرية |
| الالتفاف معرَّف، والقسمة على صفر استثناء | الثانية — لا مفاجأة صامتة | ١٧ |
| `int` تختلف بالمنصّة | أثر قرار ٢٠١٥ | ١٩ |
| `typed_data` مخزنٌ بعرضٍ ثابت | المهرب المنضبط | ٢٠ |
| `String` وحداتُ UTF-16 | التمثيل ملكُ الـruntime | ١١ · ٢١ |

## البذرة

في هذا الإقليم أعلنتُ أكبر عددٍ صحيح ثابتاً بـ`const` فعمل. واكتب الآن:

<!-- part -->

```dart
final n = DateTime.now().millisecondsSinceEpoch;
const m = n + 1;
```

المترجم سيرفض السطر الثاني بأربع كلماتٍ يقول فيها إن هذا ليس تعبيراً ثابتاً.
**ولا تصلحها** — بل اسأل لماذا كان الأوّل تعبيراً ثابتاً وهذا ليس، مع أن الاثنين
`int`.

والجواب أن `const` في Dart ليست درجةَ ثبات — هي **موضعٌ في الزمن**، وهذا غير ما
تعنيه الكلمة في C.

والإقليم ٠٤ يفكّك ما يفصل `const` عن `final` عن `var`، ولماذا الفرق **موضعٌ في
الزمن** لا درجةُ ثبات.
