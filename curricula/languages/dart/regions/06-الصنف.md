# الإقليم ٠٦ — الصنف

> في C تكتب `struct` ثم دالّة `point_init` وتأمل أن يناديها كلُّ من يبني. ولا
> شيء في اللغة يمنع أحداً من أخذ بنيةٍ من المكدّس واستعمالها بلا تهيئة.
>
> والصنف في Dart يغلق هذا الباب: **لا سبيل إلى كائنٍ إلا عبر بانٍ**. وثمن ذلك
> ترتيبٌ دقيق يجري بين لحظة `Counter()` وأوّل سطرٍ في الجسم — وهو ما وعدتُك به
> في الإقليمين ٠٣ و٠٥.

## البانٍ المولِّد، والاختصار

```dart
class Point {
  final int x;
  final int y;

  Point(this.x, this.y);

  int get distanceSquared => x * x + y * y;

  @override
  String toString() => 'Point($x, $y)';
}

void main() {
  final p = Point(3, 4);
  print(p);
  print(p.distanceSquared);
}
```

<!-- out -->

```
Point(3, 4)
25
```

**`Point(this.x, this.y);` بانٍ كامل بلا جسم.** الصيغة `this.x` في قائمة
الوسائط تعني: خذ الوسيط وأسنده إلى الحقل. ولذلك يستطيع الحقل أن يكون `final`
رغم أنه لم يُسنَد عند التصريح.

ولا كلمة `new`. كانت مطلوبة قبل الإصدار الثاني، ثم صارت اختيارية ثم زائدة —
لأنها لا تحمل معلومة: نداءُ صنفٍ باسمه لا يكون إلا بناءً.

و`get` تعرّف **قارئاً محسوباً**: `p.distanceSquared` تُقرأ حقلاً وتُنفَّذ دالّة.
وهذا ما جعل الحقل غير قابلٍ للترقية في الإقليم ٠٣ — لأن أحداً من خارج لا يفرّق
بينهما.

## الترتيب الذي لم تكتبه

**الاعتقاد الشائع:** «مُهيِّئات الحقول تعمل مع الباني، من الأعلى إلى الأسفل —
الأب أوّلاً ثم الابن، كما هو المنطق.»

**ولماذا يبدو مقنعاً:** لأن الأب يُبنى قبل الابن في كل لغةٍ تعرفها، ولأن هذا
الترتيب هو الوحيد الذي يجعل الأب صالحاً حين يعمل الابن.

اقرأ هذا وتوقّع ترتيب الأسطر الستّة قبل أن تشغّله:

```dart
int say(String s) {
  print(s);
  return 0;
}

class Base {
  final int b = say('مُهيِّئ حقلٍ في Base');
  Base() {
    say('جسم Base');
  }
}

class Child extends Base {
  final int a = say('مُهيِّئ حقلٍ في Child');
  final int c;
  Child() : c = say('قائمة تهيئة Child') {
    say('جسم Child');
  }
}

void main() {
  say('قبل البناء');
  Child();
}
```

**المخرَج**:

```
قبل البناء
مُهيِّئ حقلٍ في Child
قائمة تهيئة Child
مُهيِّئ حقلٍ في Base
جسم Base
جسم Child
```

### الآلية

<!-- part -->

```
        ┌─ derived first ─────────────────────────┐
   1.   │ Child : field initialisers              │   no `this` yet
   2.   │ Child : initialiser list                │   no `this` yet
        └─────────────────────────────────────────┘
   3.     Base  : field initialisers                  no `this` yet
   4.     Base  : initialiser list                    no `this` yet
        ┌─ base first ────────────────────────────┐
   5.   │ Base  : constructor BODY                │   `this` is live
   6.   │ Child : constructor BODY                │   `this` is live
        └─────────────────────────────────────────┘
```

**كل ما يُسنِد يعمل أوّلاً، من الابن صعوداً. ثم كل ما يُنفِّذ يعمل، من الأب
نزولاً.**

**والسبب سطرٌ واحد:** جسم باني الأب يستطيع أن ينادي طريقةً **أعاد الابن
تعريفها**. فلو عمل جسم الأب قبل أن تُسنَد حقول الابن، لقرأت تلك الطريقة حقولاً
غير مهيّأة — وهي `null` في لغةٍ لا تسمح بـ`null`.

**القاعدة الصحيحة:** لا تُنفَّذ سطراً من جسم أي بانٍ حتى تُسنَد **كل** الحقول
النهائية في السلسلة كلِّها.

**وحدُّها:** الطريقة التي يناديها الأب في جسمه ترى حقول الابن **مُسنَدة** لكنها
ترى جسم الابن **لم يعمل بعد**. وهذا هو الفخّ الباقي، ولا تغلقه اللغة.

## ولهذا `this` ممنوعةٌ قبل الجسم

الترتيب أعلاه يفسّر رفضاً ستراه:

```dart
class P {
  final int x;
  final int y;
  P(this.x) : y = m();
  int m() => 1;
}

void main() => print(P(1).y);
```

<!-- err -->

```
main.dart:4:19: Error: Can't access 'this' in a field initializer to read 'm'.
  P(this.x) : y = m();
                  ^
```

**الكائن ليس موجوداً بعد** حين تعمل قائمة التهيئة. ولذلك لا طريقة ولا حقلاً ولا
`this`.

وهذا يعمل، ويخدع:

```dart
class P {
  final int x;
  final int y;
  P(this.x) : y = x * 2;
}

void main() => print(P(3).y);
```

<!-- out -->

```
6
```

**`x` هنا ليست الحقل — هي الوسيط.** الاسم نفسه، والمصدر مختلف. والقاعدة تبقى
سليمة: قائمة التهيئة تقرأ الوسائط والثوابت والدوال العليا، ولا تقرأ الكائن.

## البانيات المسمّاة، والتوجيه

Dart رفضت التحميل الزائد (جدول الإقليم ٠٠). فكيف تبني نقطةً من قطبيّاتٍ ونقطةً
من سجلّ؟ **باسمٍ لكلٍّ:**

```dart
import 'dart:math';

class Point {
  final double x;
  final double y;

  const Point(this.x, this.y);

  const Point.origin() : this(0, 0);

  Point.polar(double r, double theta) : x = r * cos(theta), y = r * sin(theta);

  factory Point.parse(String s) {
    final f = s.split(',');
    return Point(double.parse(f[0]), double.parse(f[1]));
  }

  @override
  String toString() => 'Point(${x.toStringAsFixed(2)}, ${y.toStringAsFixed(2)})';
}

void main() {
  print(const Point.origin());
  print(Point.polar(2, pi / 2));
  print(Point.parse('3,4'));
}
```

<!-- out -->

```
Point(0.00, 0.00)
Point(0.00, 2.00)
Point(3.00, 4.00)
```

`Point.origin` **بانٍ موجِّه**: جسمُه `: this(0, 0)` يحيل إلى بانٍ آخر في الصنف
نفسه. ولا يملك قائمة تهيئةٍ معه — التوجيه يستوعبها كلَّها.

`Point.polar` بانٍ مولِّد بقائمة تهيئةٍ تحسب.

`Point.parse` **مصنع**، وسيأتي.

**والفائدة في موضع النداء:** نداءُ `Point.polar` يقول ماذا تعني وسيطتاه.
وتوقيعٌ ثانٍ باسم `Point` كان سيتركهما مبهمتين.

## المصنع لا يبني بالضرورة

البانٍ المولِّد يُنشئ كائناً جديداً حتماً. والمصنع **يُرجِع** كائناً — أيَّ
كائنٍ من نوع الصنف أو تحته.

```dart
class Colour {
  final String name;
  const Colour._(this.name);

  static const _cache = {'أحمر': Colour._('أحمر'), 'أزرق': Colour._('أزرق')};

  factory Colour(String name) => _cache[name] ?? Colour._(name);

  @override
  String toString() => 'Colour($name)';
}

void main() {
  print(identical(Colour('أحمر'), Colour('أحمر')));
  print(identical(Colour('أخضر'), Colour('أخضر')));
  print(Colour('أحمر'));
}
```

<!-- out -->

```
true
false
Colour(أحمر)
```

**النداءان الأولان أعطيا الكائن نفسه** لأن المصنع وجده في المخزن. والثالث بنى
جديداً لأنه ليس فيه.

و`Colour._` بانٍ **خاصّ** — الشرطة السفلية تمنع من خارج المكتبة أن يتجاوز
المصنع. وبها يصير المصنع الطريق الوحيد، وهذا هو نمطُ «لا كائن إلا من هنا».

**والمصنع لا يملك `this`** — لأنه لم يبنِ شيئاً بعد. وهو دالّةٌ ساكنة بثوب بانٍ.

## `==` وما لا يضمنه النظام

```dart
class P {
  final int x;
  const P(this.x);

  @override
  bool operator ==(Object other) => other is P && other.x == x;
}

void main() {
  final a = P(1), b = P(1);
  print(a == b);
  print({a, b}.length);
  print({a: 'أ'}[b]);
}
```

<!-- out -->

```
true
2
null
```

**`a == b` صحيح، والمجموعة فيها اثنان، والقاموس لم يجد.**

والسبب أن `Set` و`Map` لا تسألان `==` أوّلاً — تسألان `hashCode`. وما دام
الافتراضيّ هويّةً، فالكائنان في دلوين مختلفين ولا يلتقيان أبداً.

**وهنا حدُّ البديهية الثانية بالضبط.** النظام يضمن أن النوع لا يكذب، **ولا يضمن
أن العقود تُحترَم**. و`dart analyze` على هذا الملفّ يقول `No issues found`.

والأداة موجودة لكنها **تُطلَب**: أضف `hash_and_equals` إلى `analysis_options.yaml`
فيقول المدقّق إن تعريف `hashCode` المقابل ناقص.

**والقاعدة:** من كتب `==` كتب `hashCode` معه، و`Object.hash(...)` يبنيه من
الحقول. والأسلم أن تكون الحقول `final` — فكائنٌ يتغيّر بعد دخوله مجموعةً يضيع
فيها.

## التمرين

**١ — أوقع الفخّ الباقي.** في «حدُّها» أعلاه بقي فخٌّ لا تغلقه اللغة: طريقةٌ
يناديها جسم باني الأب وقد أعاد الابن تعريفها.

اكتبه، واجعل الابن يطبع حقلاً يُسنَد **في جسم بانيه**. ما الذي طُبع؟ ولماذا لم
يمنعه نظام الأنواع رغم أن الحقل ليس `String?`؟

**٢ — اجعل المصنع يُرجِع نوعاً آخر.** اكتب `Shape` بمصنعٍ يُرجِع `Circle` أو
`Square` حسب وسيطه، ثم اجعله يُرجِع صنفاً **خارج** الشجرة.

ما الذي رفضه المترجم بالضبط؟ اكتب الرسالة.

**٣ — قِس ثمن `hashCode`.** اكتب صنفاً بخمسة حقول، وثلاث نسخٍ من `hashCode`:
واحدةً بـ`Object.hash`، وواحدةً تُرجِع `x.hashCode` وحده، وواحدةً تُرجِع `0`.

ضع مئة ألف كائنٍ في `Set` بكلٍّ منها وقِس الزمن. الثلاث **صحيحة** بمعنى العقد.
فما الذي اختلف؟ وكم؟

## الخلاصة

| ما رأيتَه | البديهية | أين يعود |
|---|---|---|
| البانٍ الطريق الوحيد | الأولى — لا كائن بلا تهيئة | ٠٧ |
| الإسناد صعوداً والتنفيذ نزولاً | ترتيبٌ يحمي `final` | ٠٧ · ٠٨ |
| قائمة التهيئة بلا `this` | الكائن لم يوجد بعد | ٠٤ |
| المصنع يُرجِع ولا يُنشئ | الأولى — كل شيء كائن | ١٠ · ١١ |
| النظام يضمن الأنواع لا العقود | **حدّ** الثانية | ٠٩ · ٢١ |

## البذرة

`Colour._` منعت البناء من خارج المكتبة. لكن أحداً يستطيع أن يكتب:

<!-- part -->

```dart
class FakeColour implements Colour {
  @override
  String get name => 'مزيّف';
}
```

**بلا `extends`، وبلا نداء بانٍ، وبلا إذنٍ منك** — لأن كل صنفٍ واجهةٌ ضمناً
(الإقليم ٠٠). فما الذي بقي من ضمانك؟

جرّبه. ثم ابحث عن الكلمات الثلاث التي أضافها الإصدار الثالث لتغلق هذا الباب،
وما تكلّفه كلٌّ منها. والإقليم ٠٧ يفكّكها.
