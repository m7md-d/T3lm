# الإقليم ٠٤ — الاسم والثبات

> ثلاث كلماتٍ تسبق الأسماء في Dart: `var` و`final` و`const`. وترتيبها يوحي
> بسُلَّم: متغيّر ← ثابت ← أثبت.
>
> **وهذا الإيحاء خاطئ.** الفرق بين الثانية والثالثة ليس درجةَ ثبات — هو **موضعٌ
> في الزمن**. وبينهما وبين `const` في C خندق.

## `var` ليست `dynamic`

```dart
void main() {
  var n = 5;
  var s = 'اب';
  print(n.runtimeType);
  print(s.runtimeType);
  n = 7;
  n = 'نص';
}
```

<!-- err -->

```
main.dart:7:7: Error: A value of type 'String' can't be assigned to a variable of type 'int'.
  n = 'نص';
      ^
```

**`var` لا تعني «بلا نوع» — تعني «استنتِج النوع من أول إسناد».** والنوع الذي
استُنتج نهائيّ: `n` هي `int` إلى آخر البرنامج.

وهي أقرب إلى `auto` في C++ منها إلى أي شيء في C. **والاستدلال يقف عند حدّه**:
حقلٌ بلا مُهيِّئ أو معاملٌ بلا سياق يصير `dynamic`، وهناك يصمت المدقّق — كما رأيت
في الإقليم ٠٠.

## `final` تقيّد الاسم لا الشيء

**الاعتقاد الشائع:** «`final` هي `const` التي أعرفها من C: القيمة لا تتغيّر.»

**ولماذا يبدو مقنعاً:** لأنه صحيحٌ تماماً للأعداد والنصوص — وهي أوّل ما يجرّبه
القادم. أسنِد خمسةً إلى اسمٍ `final` ثم حاول إسناد ستّة، فيُرفَض، فتترسّخ القاعدة قبل أن تُختبَر على
كائن.

```dart
void main() {
  final a = [1, 2];
  final b = a;
  b.add(3);
  print(a);
  print(identical(a, b));
  final m = {'x': 1};
  m['y'] = 2;
  print(m);
}
```

<!-- out -->

```
[1, 2, 3]
true
{x: 1, y: 2}
```

### الآلية

<!-- part -->

```
   final a = [1, 2];        final b = a;

     a ──┐                    b ──┐
         │                        │
         ▼                        ▼
       ┌─────────────────────────────┐
       │  List   [ 1 , 2 , 3 ]       │   ← one object, two names
       └─────────────────────────────┘

   final  locks the arrow.      It does not touch the box.
```

في C يقول `const char *s` شيئاً عن **المُشار إليه**، و`char *const s` شيئاً عن
**المؤشّر**، واللغة تميّز الاثنين في النوع. **وDart لا تملك الأول إطلاقاً**:
`final` هي `char *const` وحدها، ولا وجود لـ`const char *`.

**القاعدة الصحيحة:** `final` تمنع إعادة **الربط**، ولا تقول شيئاً عن قابلية
الكائن للتغيّر.

**وحدُّها:** لا يوجد في Dart تجميدٌ عامّ للكائنات. من أراد قائمةً لا تتغيّر
يبنيها `const`، أو يغلّفها بـ`List.unmodifiable`، أو يختار نوعاً غير قابلٍ
للتغيّر أصلاً.

**وأين يؤذي:** حقلٌ `final Map` في صنفٍ تنشره — العميل لا يستطيع استبداله ويستطيع
إفراغه. ومن ظنّ `final` عقداً على المحتوى، نشر ثغرة.

## `const` موضعٌ في الزمن

```dart
void main() {
  const list = [1, 2];
  list.add(3);
}
```

<!-- err -->

```
Unhandled exception:
Unsupported operation: Cannot add to an unmodifiable list
```

هنا الصندوق نفسه صار غير قابلٍ للتغيّر. والسبب أن `const` لا تصف الاسم — تصف
**متى بُنيت القيمة**: وقت الترجمة، لا وقت التشغيل.

وما يُبنى وقت الترجمة يُكتَب في قسمٍ من الملفّ التنفيذيّ، ولا يملك أحدٌ تعديله.

```dart
void main() {
  final n = DateTime.now().year;
  const m = n + 1;
  print(m);
}
```

<!-- err -->

```
main.dart:3:13: Error: Not a constant expression.
```

**`n + 1` عمليةٌ على عددين، وترفضها اللغة** — لأن `n` لا تُعرَف إلا حين يعمل
البرنامج. فالسؤال الذي تسأله `const` ليس «هل تتغيّر؟» بل **«هل أستطيع حسابها
الآن، وأنا أترجم؟»**

وهذا هو الفرق كلُّه عن `final`: `final` تُحسَب وقت التشغيل ثم تُقفَل، و`const`
تُحسَب قبل أن يبدأ التشغيل أصلاً.

## التقييس: نسخةٌ واحدة في البرنامج كلّه

وما دام يُبنى وقت الترجمة، فلا سبب لبنائه مرّتين.

```dart
class P {
  final int x;
  const P(this.x);
}

List<P> makeConst() => [for (var i = 0; i < 3; i++) const P(1)];
List<P> makeNew() => [for (var i = 0; i < 3; i++) P(1)];

void main() {
  final a = makeConst();
  final b = makeNew();
  print(identical(a[0], a[1]) && identical(a[1], a[2]));
  print(identical(b[0], b[1]));
  print(identical(const [1, 2], const [1, 2]));
  print(a[0] == b[0]);
}
```

<!-- out -->

```
true
false
true
false
```

**الحلقة دارت ثلاثاً وبَنَت كائناً واحداً.** وحتى القائمتان المكتوبتان في موضعين
مختلفين من الملفّ هما الكائن نفسه: التقييس على مستوى البرنامج لا الموضع.

**وهذا هو ما يُشترى بـ`const`**: لا حجزَ في الكومة، ولا عملَ للجامع. وفي إطارٍ
يعيد بناء شجرةٍ ستّين مرّةً في الثانية، الفرق بين ألف كائنٍ جديدٍ في كل إطار
وصفرٍ منها ليس تحسيناً تجميلياً.

**والسطر الأخير فخّ:** `a[0] == b[0]` أعطى `false` رغم أن `x` واحدةٌ في
الاثنين — لأن `P` لم تعرّف `==`، والافتراضيّ في `Object` هو **الهويّة**. فمساواةُ
القيمة شيءٌ تكتبه أنت، والإقليم ٠٦ يريك أين.

## شروط `const`، ومَن يفرضها

الباني `const` عقدٌ بشروط، والمترجم يفحصها:

```dart
class P {
  final int x;
  int y = 0;
  const P(this.x);
}

void main() => print(P(1).x);
```

<!-- err -->

```
main.dart:4:9: Error: Constructor is marked 'const' so all fields must be final.
  const P(this.x);
        ^
main.dart:3:7: Context: Field isn't final, but constructor is 'const'.
```

**حقلٌ واحدٌ متغيّر يُسقِط العقد كلَّه** — لأن كائناً مشتركاً بين كل مواضع
البرنامج لا يجوز أن يتغيّر من أحدها.

وداخل سياقٍ ثابتٍ لا تحتاج تكرار الكلمة:

```dart
class P {
  final int x;
  const P(this.x);
}

const pair = [P(1), P(2)];

void main() => print(identical(pair[0], const P(1)));
```

<!-- out -->

```
true
```

`P(1)` هنا **ثابتةٌ ضمناً** لأنها داخل `const pair`. وهذا سكّرٌ لغويّ لا آلية
جديدة، والناتج هو الكائن المقيَّس نفسه.

## الجدول الذي يُحسَم به

| | `var` | `final` | `const` |
|---|---|---|---|
| متى تُحسَب القيمة | تشغيلاً | تشغيلاً | **ترجمةً** |
| هل يُعاد الربط؟ | نعم | لا | لا |
| هل يتغيّر الكائن؟ | نعم | **نعم** | لا |
| نسخةٌ لكل موضع؟ | نعم | نعم | **لا — واحدة** |
| يقبل نتيجة نداءٍ | نعم | نعم | لا |
| مقابله في C | `auto` (C++) | `T *const` | `constexpr` |

**والصفّ الأخير أدقّ مما يبدو:** `const` في C وصفٌ للنوع، و`constexpr` في C++
شرطُ حسابٍ وقت الترجمة. و`const` في Dart هي الثانية، لا الأولى.

## التمرين

**١ — اكسر التقييس.** اكتب صنفاً `const` ثم اجعل كائنين منه **غير** متطابقين رغم
أن حقولهما متساوية وكلاهما `const`. بلا تغيير الحقول.

(هذا ممكن. والجواب في تعريف التقييس لا في حيلة.)

**٢ — قِس ما اشتريتَه.** اكتب برنامجاً يبني مليون كائنٍ من صنفٍ `const`: مرّةً
بـ`const` ومرّةً بدونها. شغّل الاثنين بـ`dart run --observe` واقرأ
**Allocation Profile** لكلٍّ منهما.

كم كائناً حُجز في كلٍّ؟ وكم مرّةً عمل الجامع؟

**٣ — ابحث عن الحدّ.** ما الذي يقبله المترجم في تعبيرٍ ثابت؟ جرّب واحداً واحداً:
جمعٌ · شرطٌ ثلاثيّ · `.length` على سلسلة · `if` داخل قائمة · نداءُ دالّةٍ عليا ·
`identityHashCode` · `String.fromCharCode`.

اكتب قائمتين — ما قُبل وما رُفض — ثم استخرج القاعدة التي تفصل بينهما بجملة.

## الخلاصة

| ما رأيتَه | البديهية | أين يعود |
|---|---|---|
| `var` استدلالٌ لا تخلٍّ عن النوع | الثانية | ٠٩ |
| `final` تقفل السهم لا الصندوق | المرجع دائماً (٠٠) | ٠٥ |
| `const` موضعٌ في الزمن | الخامسة — وجهان للمترجم | ١٩ |
| التقييس نسخةٌ واحدة | الأولى — الجامع يملك الكومة | ١٢ |
| `==` الافتراضية هويّة | كل شيء كائن | ٠٦ |

## البذرة

في هذا الإقليم مرّت حلقةٌ **داخل** قائمة بلا تعليق:

<!-- part -->

```dart
[for (var i = 0; i < 3; i++) const P(1)]
```

وفي الإقليم ٠١ مرّ مقارِنٌ بلا اسمٍ وسيطاً لـ`sort` — دالّةٌ مُرِّرت كقيمة.

الاثنتان بناءٌ لغويّ لم يُشرَح بعد. والسؤال الذي يفتح الإقليم القادم: **ما الذي
تحمله دالّةٌ بلا اسمٍ حين تُمرَّر؟** اكتب دالّةً تُرجِع دالّة، واجعل الداخلية
تقرأ متغيّراً من الخارجية، ثم استدعِها بعد أن ينتهي نطاق الخارجية.

في C هذا مؤشّرٌ متدلٍّ. وهنا يعمل — والإقليم ٠٥ يقول بأيّ ثمن.
