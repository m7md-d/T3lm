# الإقليم ٠٧ — الوراثة والواجهة

> قلتُ في الإقليم ٠٠ إن **كل صنفٍ واجهةٌ ضمناً**، وتركتُ الجملة تمرّ. وفي بذرة
> الإقليم ٠٦ رأيتَ ثمنها: صنفٌ خارج مكتبتك يعلن `implements` على صنفك، فيصير
> من نوعه بلا أن يمرّ ببانيك.
>
> هذا الإقليم في تفكيك ذلك القرار: ماذا اشترى، وماذا كلّف، وما الذي أضافه
> الإصدار الثالث لتستعيد به السيطرة — وبأي ثمنٍ على مستعملي صنفك.

## `extends` يرث، و`implements` يَعِد

```dart
class Engine {
  int power = 100;
  void start() => print('دار بقوّة $power');
  void stop() => print('وقف');
}

class Turbo extends Engine {
  @override
  void start() {
    super.start();
    print('وتوربو');
  }
}

void main() {
  Turbo().start();
  Turbo().stop();
}
```

<!-- out -->

```
دار بقوّة 100
وتوربو
وقف
```

`extends` يأخذ **التطبيق**: `Turbo` ورثت `power` و`stop` بلا سطر، و`super.start()`
تنادي ما استبدلته.

و`implements` يأخذ **الشكل وحده**:

```dart
class Engine {
  int power = 100;
  void start() => print('دار بقوّة $power');
  void stop() => print('وقف');
}

class Electric implements Engine {
  @override
  int power = 50;
  @override
  void start() => print('صمت');
}

void main() => Electric().start();
```

<!-- err -->

```
main.dart:7:7: Error: The non-abstract class 'Electric' is missing implementations for these members:
 - Engine.stop
```

**`implements` لا يورّث سطراً واحداً** — يُلزِمك بكل عضوٍ في الواجهة، ومنها
الحقول (فالحقل عندهم قارئٌ وكاتب). ولذلك أعادت `Electric` تعريف `power` رغم أنه
حقلٌ لا طريقة.

**والفرق في يدك:** `extends` مرّةً واحدة (لا وراثة متعدّدة)، و`implements` بلا
حدّ. وصنفٌ يعلن `implements` على ثلاثة يفي بثلاثة عقود.

## ما اشتراه القرار

لأن كل صنفٍ واجهةٌ ضمناً، لا تحتاج أن تكتب `interface Engine` ثم `class RealEngine
implements Engine` ليكون عندك بديلٌ في اختبار. تكتب الصنف الحقيقيّ، ويكتب من
شاء بديلاً عنه.

```dart
class HttpClient {
  String get(String url) => 'استجابةٌ حقيقية من $url';
}

class FakeClient implements HttpClient {
  @override
  String get(String url) => 'استجابةٌ مزيّفة';
}

String fetchTitle(HttpClient c) => c.get('/title');

void main() {
  print(fetchTitle(HttpClient()));
  print(fetchTitle(FakeClient()));
}
```

<!-- out -->

```
استجابةٌ حقيقية من /title
استجابةٌ مزيّفة
```

**`FakeClient` ليست ابنةً ولم تنادِ بانياً** ومع ذلك تمرّ حيث تُطلَب
`HttpClient`. وهذا يوفّر في Dart طبقةَ واجهاتٍ كاملة تكتبها لغاتٌ أخرى بيدها.

**وثمنه:** كل صنفٍ تنشره صار عقداً، وكلُّ عضوٍ عامٍّ فيه بندٌ في ذلك العقد. أضف
طريقةً غداً، فكل من `implements` صنفك خارج مكتبتك **ينكسر بناؤه**.

## استعادة السيطرة — ثلاث كلمات

الإصدار الثالث أضاف مُعدِّلاتٍ تسدّ باباً وتترك آخر. وهي **لا تعمل إلا عبر حدّ
المكتبة**: داخل ملفّك تفعل ما شئت.

<!-- part: modifiers/implement_plain -->

```dart
// shapes.dart
base class Based { void go() => print('based'); }
interface class Faced { void go() => print('faced'); }
final class Locked { void go() => print('locked'); }
```

<!-- out -->

```
mine
```

*(اللوحة أعلاه من `implement_plain.dart`: صنفٌ بلا مُعدِّل، فيُطبَّق بلا اعتراض.)*

والآن كلٌّ منها على حدة، من **مكتبةٍ أخرى**:

<!-- part: modifiers/implement_base -->

```dart
import 'shapes.dart';

class Mine implements Based {
  @override
  void go() => print('mine');
}
```

<!-- err -->

```
implement_base.dart:3:7: Error: The type 'Mine' must be 'base', 'final' or 'sealed' because the supertype 'Based' is 'base'.
```

<!-- part: modifiers/extend_interface -->

```dart
import 'shapes.dart';

class Mine extends Faced {}
```

<!-- err -->

```

```

## الجدول الذي يُختار به

| المُعدِّل | يُمتَدّ من خارج؟ | يُطبَّق من خارج؟ | ماذا يضمن لك |
|---|---|---|---|
| بلا مُعدِّل | نعم | نعم | لا شيء |
| `base` | نعم | **لا** | أن كل نوعٍ فرعيّ مرّ ببانيك وورث تطبيقك |
| `interface` | **لا** | نعم | أن أحداً لا يرث تفاصيلك ولا ينادي `super` |
| `final` | **لا** | **لا** | أن الشجرة مغلقة، فتضيف أعضاءً بلا كسر أحد |
| `sealed` | **لا** | **لا** | ما تضمنه `final`، **ومعه شمولُ المطابقة** |

**و`base` تُعدي:** لاحظ رسالة الرفض الأولى — لم تقل «ممنوع»، قالت **يجب أن يكون
`Mine` واحداً من ثلاثة**. فمن امتدّ من `base` صار ملزَماً أن يغلق بابه هو.
والضمانة تنتشر في الشجرة كلِّها، وهذا هو ثمنها على مستعمليك.

**والقاعدة العملية:** ابدأ بالأضيق الذي يكفي. توسيعُ الإذن لاحقاً لا يكسر أحداً،
وتضييقه يكسر الجميع.

## `sealed` والشمول

رأيتَ `sealed` في الإقليم ٠١ تجعل المترجم يعدّ الحالات. والآن تعرف موضعها من
الجدول: هي `final` **زائد** أن المترجم يعرف كل الفروع، لأنها كلَّها في ملفٍّ
واحد.

```dart
sealed class Shape {
  const Shape();
}

final class Circle extends Shape {
  final double r;
  const Circle(this.r);
}

final class Square extends Shape {
  final double side;
  const Square(this.side);
}

double area(Shape s) => switch (s) {
      Circle(:final r) => 3.14159 * r * r,
      Square(:final side) => side * side,
    };

void main() {
  print(area(const Circle(1)));
  print(area(const Square(3)));
}
```

<!-- out -->

```
3.14159
9.0
```

**و`sealed` مجرّدةٌ ضمناً:** لا تستطيع أن تكتب `Shape()`. وهذا مقصود — الصنف
المختوم اسمٌ لمجموعة فروع، لا شيءٌ يُبنى.

## الباب الأخير: `noSuchMethod`

بقيت طريقةٌ لا يغلقها مُعدِّل: أن يعترض الصنف **كل** نداءٍ لا يعرفه.

```dart
class Ghost {
  @override
  dynamic noSuchMethod(Invocation i) {
    print('نُودي: ${i.memberName} بوسائط ${i.positionalArguments}');
    return null;
  }
}

void main() {
  final g = Ghost() as dynamic;
  g.anything(1, 2);
  g.other;
}
```

<!-- out -->

```
نُودي: Symbol("anything") بوسائط [1, 2]
نُودي: Symbol("other") بوسائط []
```

**هذا مهربٌ من نظام الأنواع كلِّه** — ولذلك احتاج `dynamic` ليمرّ. ولولاها لرفض
المدقّق النداء قبل أن يصل إلى `noSuchMethod`.

**وهو ثمنٌ آخر للبديهية الخامسة:** آليةٌ كهذه تحتاج أسماء الأعضاء حيّةً، وهي
عدوّة الحذف في الترجمة المسبقة. ولذلك تجدها في المولّدات والاختبارات، لا في
الكود المشحون.

## التمرين

**١ — أوقع الكسر الذي وصفتُه.** اكتب مكتبةً فيها صنفٌ بلا مُعدِّل، ومكتبةً أخرى
تطبّقه. ثم **أضف طريقةً** إلى الصنف الأصليّ بلا لمس الثانية.

كم ملفّاً انكسر؟ ثم أعِد التجربة والصنف `final` — ماذا تغيّر في **رسالة**
الكسر، ومتى ظهرت؟

**٢ — ابحث عن الرابع.** الجدول أعلاه فيه أربع حالاتٍ لمُعدِّلَين اثنين
(يُمتَدّ/يُطبَّق). و`sealed` احتلّت خانةً محجوزة.

فهل يوجد مُعدِّلٌ **يُجمَع** مع آخر؟ جرّب `base` مع `mixin`، و`abstract` مع
`interface`. اكتب أي التركيبات قبلها المترجم، وما الذي يضيفه كلٌّ منها.

**٣ — اكتب واجهةً تُطبَّق ولا تُورَّث، وقِس ثمنها.** خذ `HttpClient` أعلاه
واجعله `interface class`. الآن اكتب `CachingClient` تريد أن **تعيد استعمال**
تطبيق `get` وتضيف تخزيناً.

لا تستطيع `extends`. فما البديل؟ اكتبه، ثم عُدّ الأسطر: كم سطراً كلّفك المُعدِّل؟

## الخلاصة

| ما رأيتَه | البديهية | أين يعود |
|---|---|---|
| `extends` يرث و`implements` يَعِد | كلُّ صنفٍ واجهةٌ ضمناً (٠٠) | ٠٨ |
| المُعدِّلات تعمل عبر حدّ المكتبة | الخصوصية للمكتبة لا للصنف | ١٨ |
| `base` تُعدي في الشجرة | ضمانةٌ لها ثمنٌ على غيرك | ٠٨ |
| `sealed` = `final` + شمول | الثانية — المترجم يعدّ | ١١ |
| `noSuchMethod` مهربٌ يحتاج `dynamic` | حدّ الثانية | ١٩ |

## البذرة

`extends` مرّةً واحدة. فكيف تعطي عشرة أصنافٍ غير متقاربةٍ نفس القدرة على
التسجيل — بلا أن تنسخ الكود، وبلا أن تجعلها كلَّها ترث من صنفٍ واحد؟

في C++ تُحلّ بالوراثة المتعدّدة، ومعها مشكلة الماس. وDart رفضت الوراثة المتعدّدة
عمداً (جدول الإقليم ٠٠).

فما البديل؟ اكتب `with` بين اسم الصنف وأبيه وشاهد ما يقبله المترجم. ثم **بدّل
ترتيب اثنين** بعد `with` وأعِد التشغيل.

**المخرَج سيتغيّر.** والإقليم ٠٨ يقول كيف يُحسَب ذلك الترتيب، ولماذا هو حسابٌ لا
اصطلاح.
