# الإقليم ١٤ — `Future` و`async`/`await`

> عرفتَ في الإقليم ١٣ أين تُسجَّل بقيّة الدالّة. وهذا الإقليم في **ما هي بقيّة
> الدالّة أصلاً**: ما الذي يُترجَم إليه `await`، وأين تعود السيطرة، ولماذا يظهر
> خطأٌ بعد أن يكون البرنامج قد تجاوز موضعه بأسطر.
>
> والقاعدة التي تحكم الإقليم كلَّه: **`async` لا تؤجّل شيئاً حتى تصل إلى أوّل
> `await`.**

## الجسم يبدأ فوراً

**الاعتقاد الشائع:** «نداء دالّةٍ `async` يجدولها، ويعود فوراً بلا أن ينفّذ
شيئاً. جسمُها يعمل لاحقاً.»

**ولماذا يبدو مقنعاً:** لأن نوع الإرجاع `Future`، والنداء لا يحجب. فيبدو أن
الجسم كلَّه ذهب إلى مكانٍ آخر.

```dart
Future<int> f() async {
  print('ب · جسم الدالّة بدأ');
  await null;
  print('د · بعد أوّل await');
  return 7;
}

Future<void> main() async {
  print('أ · قبل النداء');
  final fut = f();
  print('ج · بعد النداء، قبل await');
  print('هـ · ${await fut}');
}
```

**المخرَج**:

```
أ · قبل النداء
ب · جسم الدالّة بدأ
ج · بعد النداء، قبل await
د · بعد أوّل await
هـ · 7
```

**السطر الثاني طُبع قبل أن يعود النداء.** أي أن جسم الدالّة عمل **متزامناً**
حتى بلغ `await`، وعندها فقط عاد `Future` إلى المنادي.

### الآلية

<!-- part -->

```
   Future<int> f() async {  A;  await X;  B;  return v;  }

   is (in effect) rewritten to:

   Future<int> f() {
     final completer = Completer<int>();
     A;                                   ← runs NOW, synchronously
     X.then((_) {
       B;                                 ← the "rest of the function"
       completer.complete(v);
     }, onError: completer.completeError);
     return completer.future;             ← returned at the first await
   }
```

**القاعدة الصحيحة:** `async` تقسم الجسم عند كل `await` إلى قطع. القطعة الأولى
تعمل عند النداء، وكل قطعةٍ بعدها تُسجَّل في طابور (الإقليم ١٣).

**وحدُّها:** دالّةٌ `async` بلا `await` أصلاً تعمل كلُّها متزامنةً، ثم تُرجِع
`Future` مكتملاً. النوع لا يعني تأجيلاً.

**وأين يفيد:** ضع الفحوص والتحقّق **قبل** أوّل `await`، فتقع فوراً عند النداء لا
بعد دورةٍ في الحلقة.

## وهذا هو السكّر مفكوكاً

```dart
Future<int> sugar() async {
  final a = await Future.value(1);
  final b = await Future.value(a + 1);
  return b * 10;
}

Future<int> manual() {
  return Future.value(1).then((a) {
    return Future.value(a + 1).then((b) {
      return b * 10;
    });
  });
}

Future<void> main() async {
  print(await sugar());
  print(await manual());
}
```

<!-- out -->

```
20
20
```

**الدالّتان متكافئتان.** و`await` ليست ميزةً في وقت التشغيل — هي **صياغة** تولّد
سلسلة `.then` بلا التداخل.

والمترجم لا يبني سلسلةً حرفياً بل **آلة حالات**: متغيّرٌ يحمل رقم القطعة، وقفزةٌ
إليها عند كل استئناف. وهذا ما يجعل حلقةً فيها `await` ممكنةً أصلاً — سلسلة
`.then` لا تعبّر عنها.

**والفائدة الحقيقية في الاستثناءات:** `try`/`catch` حول `await` يعمل، ومحاولةُ
كتابتها في سلسلة `.then` تحتاج `onError` في كل حلقة.

## أين يذهب الخطأ

```dart
Future<int> boom() async => throw StateError('انفجر');

Future<void> main() async {
  try {
    await boom();
  } on StateError catch (e) {
    print('التُقط: ${e.message}');
  }

  boom();
  print('نداءٌ بلا await — تابعنا');
  await Future.delayed(const Duration(milliseconds: 50));
  print('لن نصل هنا');
}
```

<!-- err -->

```
التُقط: انفجر
نداءٌ بلا await — تابعنا
Unhandled exception:
Bad state: انفجر
```

**النداء الأول التُقط، والثاني قتل البرنامج** — والسطر الأخير لم يُطبَع.

**والسبب أن `Future` يحمل نتيجةً أو خطأً.** فمن لم ينتظره لم يستلم خطأه، ويبقى
الخطأ معلّقاً حتى تنتهي دورة الحلقة فيُعلَن غيرَ ملتقَط.

**ولاحظ الترتيب:** «تابعنا» طُبعت قبل الانفجار. فالخطأ وقع في مكانٍ وظهر في مكانٍ
آخر — وهذا ما يجعل تتبّعه أصعب من خطأٍ متزامن.

**والقاعدة:** كل `Future` إمّا يُنتظَر، أو يُعلَّق عليه `catchError`، أو يُعلَن
تركُه صراحةً بـ`unawaited` من `dart:async`. والثالثة توثيقٌ للقارئ لا حمايةٌ من
شيء.

## الانتظار الجماعيّ

```dart
Future<int> after(int ms, int v) async {
  await Future.delayed(Duration(milliseconds: ms));
  return v;
}

Future<void> main() async {
  final t0 = DateTime.now();
  final all = await Future.wait([after(60, 1), after(30, 2), after(10, 3)]);
  final ms = DateTime.now().difference(t0).inMilliseconds;
  print('$all في نحو $ms م.ث');

  final first = await Future.any([after(60, 1), after(10, 9)]);
  print('أوّل واصل: $first');
}
```

<!-- runs -->

```
[1, 2, 3] في نحو 62 م.ث
أوّل واصل: 9
```

**`Future.wait` تحفظ ترتيب القائمة لا ترتيب الوصول** — النتيجة `[1, 2, 3]` رغم
أن الثالث وصل أوّلاً. وتنتهي بانتهاء **أطولها**، لا بمجموعها: ستّون لا مئة.

**ولم يتوازَ شيء.** ثلاث انتظاراتٍ سُجّلت في طابور الأحداث، والحلقة خدمتها
بالترتيب الذي نضجت به. والتوفير كلُّه من أن الانتظار **لا يشغل** المعالج.

**وحدُّها الخطر:** فشلُ واحدٍ يُفشِل `Future.wait` كلَّها، **وبقيّةُ الأخطاء
تضيع**. ومن أراد كلَّ النتائج يمرّر `eagerError: false` ويلتقط بنفسه، أو يغلّف
كلَّ واحدٍ بـ`catchError`.

## `FutureOr` وحين لا تحتاج انتظاراً

```dart
import 'dart:async';

FutureOr<int> maybe(bool now) => now ? 1 : Future.value(2);

Future<void> main() async {
  final a = maybe(true);
  print(a.runtimeType);
  print(maybe(false).runtimeType);
  print(await maybe(true));

  print('أ');
  await maybe(true);
  print('ب');
}
```

<!-- out -->

```
int
Future<int>
1
أ
ب
```

`FutureOr<T>` نوعٌ يقبل `T` أو `Future<T>`. وهو ما يسمح لواجهةٍ أن تُرجِع
النتيجة فوراً حين تعرفها، وتؤجّل حين لا تعرفها — بلا أن تُلزِم كلَّ منادٍ
بـ`await` على قيمةٍ حاضرة.

**و`await` على قيمةٍ غير مؤجَّلة ليست مجّانية:** لا تزال تقطع الدالّة وتسجّل
الباقي مهمّةً دقيقة. فحتى `await 1` تكلّف دورةً في الطابور.

## التمرين

**١ — اكتب آلة الحالات بيدك.** خذ دالّةً `async` فيها **حلقةٌ** بداخلها `await`،
وأعِد كتابتها بـ`.then` وحدها بلا `async` وبلا `await`.

(الحلقة هي الصعوبة. وستحتاج دالّةً تنادي نفسها.)

ثم قارن الطول والوضوح. **وما الذي فقدتَه في `try`/`catch`؟**

**٢ — امسك الخطأ الضائع.** اكتب `Future.wait` على خمسة، يفشل الثاني والرابع
بأخطاءٍ مختلفة. اجعل البرنامج يطبع **كلا الخطأين** والنتائج الثلاث الناجحة.

كم صيغةً وجدتَ؟ وأيّها لا يحتاج `eagerError`؟

**٣ — قِس ثمن `await`.** اكتب حلقةً بمليون دورة تجمع أعداداً، مرّةً متزامنةً
ومرّةً بـ`await Future.value(i)` في كل دورة.

قِس النسبة. ثم استبدل بها `FutureOr` بلا `await` حين تكون القيمة حاضرة — **كم
استرجعتَ؟**

## الخلاصة

| ما رأيتَه | البديهية | أين يعود |
|---|---|---|
| الجسم يعمل حتى أوّل `await` | الرابعة | ١٥ |
| `await` سكّرٌ على `.then` وآلةِ حالات | الخامسة — المترجم يولّد | ١٩ |
| خطأُ future غير منتظَرٍ يقتل لاحقاً | — | ١٧ |
| `wait` بترتيب القائمة، وبأطولها | الرابعة — لا توازي | ١٦ |
| `FutureOr` يتجنّب دورةً لا لزوم لها | الرابعة | ١٥ |

## البذرة

`Future` قيمةٌ واحدة تصل مرّة. فماذا لو وصلت **ألف** قيمة؟

في الإقليم ٠١ كتبتَ `await for` على أسطر ملفّ، ومرّت بلا شرح. وقلتُ يومها إن
الملفّ **مجرًى لا مصفوفة**.

والآن جرّب هذا: اقرأ ملفّاً بمجرًى، **ولا تستهلكه**. ثم اقرأه بمجرًى واستهلكه
مرّتين.

**الأولى لن تقرأ شيئاً، والثانية سترمي.** والإقليم ١٥ يقول لماذا، وما الفرق بين
مجرًى ينتظر مشتركاً ومجرًى يبثّ بلا أن يسأل.
