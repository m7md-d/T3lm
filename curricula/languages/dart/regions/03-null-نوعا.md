# الإقليم ٠٣ — `null` نوعاً

> في C المؤشّر الفارغ قيمةٌ في نوعٍ يقبلها. تُسنِد `NULL` إلى `char *` فيسلم
> السطر تماماً، ثم تمرّره إلى `strlen` فيُترجَم بلا شكوى وينهار وقت التشغيل.
>
> وفي Dart الفارغُ **نوعٌ آخر**. وهذا الإقليم كلُّه في فهم ما يترتّب على تلك
> الكلمة الواحدة — ولماذا يرفض المدقّق كوداً تراه صحيحاً بعينك.

## `?` عاملٌ على الأنواع

رأيتَ في الإقليم ٠٠ أن `Null` صنفٌ حقيقيّ لقيمةٍ واحدة. و`String?` ليست
«`String` قد تكون فارغة» — هي **اتّحاد نوعين**: `String` أو `Null`.

```dart
void main() {
  String? a = 'اب';
  String? b = null;
  print(a.runtimeType);
  print(b.runtimeType);
  print(b is Null);
  print(b is String);
}
```

<!-- out -->

```
String
Null
true
false
```

**لا يوجد نوعٌ اسمه `String?` وقت التشغيل.** القيمة إمّا `String` وإمّا `Null`،
والعلامة أداةٌ للمدقّق وحده.

وهذا هو الاتّحاد الوحيد في اللغة: لا تستطيع أن تكتب `String | int`، لكنك تكتب
`String?` — لأن اللغة احتاجت هذا الاتّحاد بالذات فبنته خاصّاً.

## الترقية: المدقّق يتتبّع تدفّقك

```dart
int len(String? s) {
  if (s == null) return 0;
  return s.length;
}

void main() {
  print(len('أهلاً'));
  print(len(null));
}
```

<!-- out -->

```
5
0
```

**السطر الثالث يصل إلى `.length` على `String?` بلا علامة.** والسبب أن المدقّق
يعرف: إن وصل التنفيذ إلى هنا فالشرط الأول لم يتحقّق، فنوع `s` في هذا الفرع
`String` لا `String?`.

هذه **الترقية** (promotion)، وهي ما يجعل السلامة من `null` محتملةً بدل أن تكون
عبئاً في كل سطر. وهي تحليل تدفّقٍ حقيقيّ: `return` و`throw` و`&&` و`||` وحتى
`switch` تشارك فيه.

## حيث تتوقّف الترقية — وهذا هو الاعتقاد

**الاعتقاد الشائع:** «فحصتُ أنه ليس `null`، فهو ليس `null`. والمدقّق يرى ما
أرى.»

**ولماذا يبدو مقنعاً:** لأنه صحيحٌ تماماً في المتغيّر المحلّي، ويشتغل في تسعين
بالمئة من الكود. فحين يفشل، يبدو عيباً في الأداة.

```dart
class Box {
  String? name;
  Box(this.name);

  int len() {
    if (name != null) {
      return name.length;
    }
    return 0;
  }
}

void main() => print(Box('اب').len());
```

<!-- err -->

```
main.dart:7:19: Error: Property 'length' cannot be accessed on 'String?' because it is potentially null.
Try accessing using ?. instead.
      return name.length;
                  ^^^^^^
main.dart:2:11: Context: 'name' refers to a public property so it couldn't be promoted.
```

**اقرأ سطر الـContext**، فهو الجواب كلُّه: «حقلٌ **عامّ**، فلا يُرقّى».

### الآلية

`name` ليس متغيّراً — هو **نداءُ getter**. والمدقّق لا يملك أن يفترض أن نداءين
متتاليين يعطيان القيمة نفسها. وسببان يمنعانه:

<!-- part -->

```
   if (name != null)      →  call #1 of the getter
       name.length        →  call #2 of the getter

   Between them, either could happen:
     (a) the field was reassigned          → if it is not final
     (b) the getter was overridden         → if another library can see it
                                             and return something else
```

فإن أُغلق البابان، رُقِّي الحقل:

```dart
class Box {
  final String? _name;
  Box(this._name);

  int len() {
    if (_name != null) {
      return _name.length;
    }
    return 0;
  }
}

void main() {
  print(Box('اب').len());
  print(Box(null).len());
}
```

<!-- out -->

```
2
0
```

**`final` أغلق الباب الأول، والشرطة السفلية أغلقت الثاني** — فالخصوصية في Dart
على مستوى **المكتبة**، ولا يستطيع صنفٌ خارجها أن يعلن getter بهذا الاسم.

**القاعدة الصحيحة:** يُرقّى المتغيّر المحلّي دائماً. ويُرقّى العضو إن اجتمعت
فيه ثلاث: أن يكون **حقلاً**، و**نهائياً**، و**خاصّاً**. وما عداه يُنسَخ إلى
متغيّرٍ محلّي أوّلاً.

**والمدقّق يسمّي أيّها اختلّت، ولكلٍّ رسالتُه:**

<!-- part -->

```
  public field   →  '_name' refers to a public property so it couldn't be promoted
  non-final      →  '_name' refers to a non-final field so it couldn't be promoted
  a getter       →  '_name' refers to a getter so it couldn't be promoted
```

**والثالث هو الذي يفاجئ:** الشرط «حقلاً» ليس شكلياً. ضع getter خاصّاً فوق حقلٍ
خاصٍّ نهائيّ، فتسقط الترقية — الغلاف الذي أضفتَه للتنظيم أسقطها.

**و`late` ليس منها.** حقلٌ `late final` خاصّ يُرقّى كغيره.

## `!` ادّعاءٌ تدفع ثمنه

حين تعرف ما لا يعرفه المدقّق، تقول له ذلك بعلامة تعجّب. **وهي ليست تحويلاً — هي
فحصٌ وقت التشغيل:**

```dart
void main() {
  String? s = DateTime.now().year > 2000 ? null : 'اب';
  print(s?.length);
  print(s ?? 'بديل');
  print(s!.length);
}
```

<!-- err -->

```
null
بديل
Unhandled exception:
Null check operator used on a null value
```

ثلاثة أدواتٍ في ثلاثة أسطر:

`?.` تُوقف السلسلة وتُرجِع `null` بدل أن تنفجر — ونوع الناتج `int?`.

`??` تُعطي بديلاً حين يكون اليسار `null`. ومعها `??=` للإسناد الشرطي.

`!` **تنفجر**. وهي إعلانٌ منك بأن الادّعاء عليك لا على المدقّق، ولذلك تُبرَّر ولا
تُرَشّ.

## `late` تنقل الفحص إلى وقت التشغيل

بقيت حالة: قيمةٌ ستوجد قطعاً، لكن ليس عند البناء. وفي C كنتَ ستضع `NULL`
وتتذكّر. وهنا:

```dart
class Conf {
  late final String path = _compute();

  String _compute() {
    print('حُسب الآن');
    return '/etc/x';
  }
}

void main() {
  final c = Conf();
  print('بُني الكائن');
  print(c.path);
  print(c.path);
}
```

<!-- out -->

```
بُني الكائن
حُسب الآن
/etc/x
/etc/x
```

**التهيئة لم تعمل عند البناء** — عملت عند أوّل قراءة، ثم حُفظت. وهذا `late`
بمعناه الأنفع: **تأجيلٌ كسول** بلا أن تكتب حقلاً فارغاً وفحصاً في كل getter.

والوجه الآخر أنك أخذتَ الضمانة على عاتقك:

```dart
class Node {
  late final Node parent;
  final String name;
  Node(this.name);
}

void main() {
  final a = Node('أ');
  print(a.name);
  print(a.parent.name);
}
```

<!-- err -->

```
أ
Unhandled exception:
LateInitializationError: Field 'parent' has not been initialized.
```

**البرنامج تُرجم بلا شكوى.** `late` **حذف الفحص الساكن ووضع مكانه فحصاً حيّاً** —
ولذلك يُقرأ كل `late` سؤالاً: من الذي يضمن أن هذا يُسنَد قبل أن يُقرأ؟

وحين يستطيع المدقّق أن يبرهن على الخطأ، لا يؤجّله:

```dart
void main() {
  late String s;
  print(s.length);
}
```

<!-- err -->

```
main.dart:3:9: Error: Late variable 's' without initializer is definitely unassigned.
```

## ماذا اشترى هذا كلُّه

السلامة من `null` ليست راحةً للكاتب. هي **معلومةٌ للمترجم**.

في نظامٍ يقبل `null` في كل نوع، على المترجم أن يفترض أن أي مرجعٍ قد يكون فارغاً،
فيبقي فحصاً قبل كل نداء. وحين يصير الفارغُ نوعاً منفصلاً، يعرف المترجم أن `String`
**ليست** `Null` أبداً — فيحذف الفحص كلَّه.

**وهذا هو الضغط الذي شُرح في الإقليم ٠٠**: Flutter يبني شجرة الواجهة ستّين مرّة
في الثانية، وفحصٌ محذوفٌ في نداءٍ متكرّرٍ ملايين المرّات ليس تفصيلاً.

**والثمن مكتوبٌ في هذا الإقليم كلِّه:** رسائل رفضٍ تبدو متزمّتة، وقاعدةُ ترقيةٍ
عليك أن تعرفها، وكلمتان (`!` و`late`) تنقلان الضمانة إليك.

## التمرين

**١ — اجمع أسباب الرفض.** رأيتَ ثلاثة. **ابحث عن رابع**: عضوٌ لا يُرقّى لسببٍ
لم يُذكَر هنا.

وابدأ من السؤال الذي ولّد الثلاثة كلَّها: *ما الذي يمنع المدقّق من الجزم بأن
القراءتين تعطيان القيمة نفسها؟* وكلُّ جواب لهذا السؤال سببُ رفض.

**٢ — اقرأ الفرق في المُخرَج.** اكتب صنفاً فيه حقل `String?` عامّ، ودالّةً تصل
إليه مرّتين. ترجمه إلى JavaScript بلا تصغيرٍ ولا تحسين، مرّةً بـ`?.` ومرّةً
بمتغيّرٍ محلّي مُرقًّى.

ابحث في الملفّين عن اسم الحقل. **أيّهما فيه فحصٌ أقلّ؟** وكم؟

**٣ — احسب الخطر.** خذ `programs/tally.dart` من الإقليم ٠١ واستبدل بكل
`int.tryParse` نداءً `int.parse` مع `!`. ثم شغّله على السجلّ نفسه.

أين انفجر؟ وكم سطراً من التقرير خسرتَ مقابل سطرين وفّرتَهما؟

## الخلاصة

| ما رأيتَه | البديهية | أين يعود |
|---|---|---|
| `?` اتّحادُ نوعٍ مع `Null` | الثانية — النوع لا يكذب | ٠٩ · ١١ |
| الترقية تحليلُ تدفّق | الثانية | كل إقليمٍ بعده |
| الحقل لا يُرقّى إلّا خاصّاً نهائياً | كلُّ صنفٍ واجهةٌ ضمناً (٠٠) | ٠٧ |
| `!` فحصٌ حيّ لا تحويل | لا مفاجأة صامتة | ١٧ |
| `late` ينقل الضمانة إليك | — | ٠٤ · ٠٦ |

## البذرة

الحقل الذي أعلنّاه `late final` بمُهيِّئٍ **لم يُحسَب عند البناء**. والحقل
`final` بالمُهيِّئ نفسه يُحسَب عنده حتماً.

فمتى بالضبط يُحسَب؟ قبل جسم الباني، أم بعده؟ وهل يستطيع أن يقرأ `this`؟

اكتب الاثنين في صنفٍ واحد وضع `print` في كل موضع، ورتّب المخرَج. **الترتيب الذي
ستراه ليس الترتيب الذي كتبتَه** — والإقليم ٠٦ يقول لماذا، ولماذا لقائمة التهيئة
موضعٌ قبل الجسم أصلاً.
