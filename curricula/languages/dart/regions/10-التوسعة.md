# الإقليم ١٠ — التوسعة

> عندك نوعٌ لا تملكه — `int` أو `String` أو صنفٌ من حزمةٍ لا تعدّلها — وتريد أن
> تضيف إليه. وفي C تكتب `int_twice(x)` وتعيش مع ذلك.
>
> وفي Dart طريقان: أن تضيف **طريقةً** إلى نوعٍ قائم، أو أن تصنع **نوعاً** فوق
> تمثيلٍ قائم. وكلاهما يختفي وقت التشغيل، ولكلٍّ ثمنٌ مختلف تماماً.

## `extension` تضيف طريقة

```dart
extension Doubling on int {
  int get twice => this * 2;
  int times(int n) => this * n;
}

void main() {
  print(5.twice);
  print(5.times(3));
  print((-2).twice);
}
```

<!-- out -->

```
10
15
-4
```

**`5.twice` تُقرأ كأنها عضوٌ في `int`**، و`int` صنفٌ مختوم في SDK لا تستطيع أن
تمتدّ منه ولا أن تعدّله. ومع ذلك مرّ السطر.

و`this` داخل التوسعة هي القيمة المُوسَّعة. ولا حالةَ لك فيها: **لا تستطيع
التوسعة أن تضيف حقلاً** — لأنها لا تملك الكائن.

## والاعتقاد الذي تزرعه

**الاعتقاد الشائع:** «التوسعة تضيف الطريقة إلى النوع. فمن يحمل قيمةً من ذلك
النوع يجدها، أيّاً كان المتغيّر الذي يحملها.»

**ولماذا يبدو مقنعاً:** لأن صيغة النداء مطابقةٌ لنداء الطريقة تماماً. ولا شيء في
موضع الاستعمال يقول إن هذه ليست عضواً.

```dart
class Animal {}

class Cat extends Animal {}

extension AnimalSound on Animal {
  String speak() => 'صوتٌ ما';
}

extension CatSound on Cat {
  String speak() => 'مواء';
}

void main() {
  Cat c = Cat();
  Animal a = c;
  print(c.speak());
  print(a.speak());
  print(identical(c, a));
}
```

**المخرَج**:

```
مواء
صوتٌ ما
true
```

### الآلية

<!-- part -->

```
   Cat c = Cat();          static type of `c` is Cat
   Animal a = c;           static type of `a` is Animal   (same object!)

   The compiler REWRITES each call site using the STATIC type:

       c.speak()   →   CatSound.speak(c)
       a.speak()   →   AnimalSound.speak(a)

   There is no method table lookup, no dispatch, nothing at run time.
   `speak` is not a member of Animal or Cat — it never was.
```

**القاعدة الصحيحة:** التوسعة **إعادةُ كتابةٍ وقت الترجمة**، تُحسَم بالنوع الساكن
للتعبير. وهي عكس كل ما تعرفه عن الإرسال الديناميّ.

**وحدُّها:** لا يظهر الفرق ما دام النوع الساكن يطابق الحقيقيّ — وهو الحال في
تسعين بالمئة من الكود.

**وأين يؤذي:** توسيعُ صنفٍ أساسٍ ثم توسيعُ ابنه بالاسم نفسه. والدالّة التي تأخذ
الأب ستنادي توسعة الأب أبداً، ولو مرّرتَ ابناً. **والاختبارات تمرّ** لأنك
تختبرها بالنوع الدقيق.

وأصدق دليلٍ على أنها ليست عضواً:

```dart
extension Doubling on int {
  int get twice => this * 2;
}

void main() {
  print(5.twice);
  dynamic d = 5;
  print(d.twice);
}
```

<!-- err -->

```
10
Unhandled exception:
NoSuchMethodError: Class 'int' has no instance getter 'twice'.
Receiver: 5
```

**`dynamic` نقلت الحسم إلى وقت التشغيل** — ووقت التشغيل لا يعرف `twice`. فالتوسعة
والقيمة لا يلتقيان إلا في المترجم.

## `extension type` يصنع نوعاً

المشكلة الأخرى: `typedef` لا يصنع نوعاً (الإقليم ٠٠)، وصنفُ غلافٍ يصنع كائناً
وحجماً وحجزاً. والحلّ الثالث:

```dart
extension type Id(int value) {
  String get label => 'رقم $value';
}

extension type Age(int value) implements int {}

void main() {
  final id = Id(7);
  print(id.label);
  print(id.value + 1);
  print(Age(30) + 5);
}
```

<!-- out -->

```
رقم 7
8
35
```

`Id` **معتِم**: لا يرث شيئاً من `int`، فلا تجمعه ولا تقارنه — تصل إلى تمثيله
بالاسم `value` وحده. وهذا ما يمنع خلط الوحدات.

`Age` **شفّاف** بـ`implements int`: يأخذ كل أعضاء `int`، فتجمعه كأنه عدد. وتكسب
الاسم وتفقد المنع.

**والاختيار بينهما هو السؤال كلُّه:** هل تريد نوعاً يمنع الخلط، أم اسماً يوثّق
ولا يمنع؟

## وما بقي منه وقت التشغيل: لا شيء

```dart
extension type Id(int value) {}

void main() {
  final ids = <Id>[Id(1), Id(2)];
  print(ids.runtimeType);
  print(ids is List<int>);
  print(Id(1) is int);
}
```

<!-- out -->

```
List<int>
true
true
```

**قائمةٌ من `Id` هي `List<int>` حرفياً.** لا غلاف، ولا حجز، ولا كلمةٌ إضافية في
الكائن، ولا فحصٌ في أي نداء.

**وهذا هو الكسب كلُّه، وهو الخسارة كلُّها.** قارن بالإقليم ٠٩: هناك دفعتَ قراءةَ
نوعٍ وفحصاً عند كل كتابة، واشتريتَ بذلك حمايةً حيّة. وهنا لا تدفع شيئاً، ولا
تُحمى إلا من المترجم.

**فمتى يؤذي؟** حين يعبر النوعُ حدّاً لا يراه المترجم: `jsonDecode` يعطيك
`dynamic`، وقاعدةُ بياناتٍ تعطيك `List<Object?>`، ورسالةٌ من isolate تصل
منسوخةً. في تلك المواضع `Id` و`int` شيءٌ واحد، ولن يعترض أحد.

## الثلاثة في جدول

| | `extension` | `extension type` | صنفُ غلاف |
|---|---|---|---|
| يضيف طرقاً | نعم | نعم | نعم |
| يصنع نوعاً | **لا** | نعم (ساكناً) | نعم (حيّاً) |
| يمنع الخلط | لا | نعم — إن كان معتِماً | نعم |
| كلفةٌ في الذاكرة | صفر | **صفر** | كائنٌ لكل قيمة |
| يراه `is` و`runtimeType` | لا | **لا** | نعم |
| يحسمه | النوع الساكن | النوع الساكن | النوع الحيّ |
| يعبر حدّ `dynamic` | لا | لا | **نعم** |

**والصفّ الأخير هو الفاصل عملياً.** بياناتٌ تدخل من خارج برنامجك تفقد كل ما
يحسمه المترجم وحده.

## التمرين

**١ — أوقع الفخّ الأول.** اكتب دالّةً تأخذ `Animal` وتنادي `speak` عليها، ثم
مرّر `Cat`. **بلا تغيير التوسعتين**، اجعل النداء يعطي «مواء».

كم طريقةً وجدت؟ وأيّها لا يزال يعتمد على النوع الساكن؟

**٢ — اكشف التسرّب.** اكتب نوعَ توسعةٍ معتِماً اسمه `Metre` فوق `double`، ثم مرّر
قائمةً منه عبر `jsonEncode` و`jsonDecode` وأعِدها إلى `List<Metre>`.

هل اعترض أحد؟ الآن أدخِل في الطريق قيمةً هي ثوانٍ لا أمتار. **أين كان يجب أن
يُكتشَف ذلك، ولماذا لم يُكتشَف؟**

**٣ — قِس الغلاف.** اكتب النسختين — `extension type` وصنف غلافٍ عاديّ — واحجز
مليوناً من كلٍّ في قائمة. شغّل بـ`dart run --observe` واقرأ حجم الكومة.

كم فرقاً؟ وهل الفرق ثابتٌ أم يكبر مع العدد؟

## الخلاصة

| ما رأيتَه | البديهية | أين يعود |
|---|---|---|
| التوسعة إعادةُ كتابةٍ بالنوع الساكن | الخامسة — المترجم يحسم | ١١ |
| ولا وجود لها عبر `dynamic` | حدّ الثانية | ١٧ |
| `extension type` نوعٌ بلا كلفة | الأولى — التمثيل ملكُ الـruntime | ١٢ · ٢٠ |
| المعتِم يمنع، والشفّاف يوثّق | اختيارٌ لا افتراضيّ | ١١ |
| كلاهما يسقط عند حدّ البيانات الخارجية | — | ١٦ · ١٨ |

## البذرة

`Id` معتِمٌ ولا يقبل الجمع. و`Age` شفّافٌ يقبله. فماذا لو أردتَ **ثالثاً**:
قيمةً إمّا `Id` وإمّا رسالةَ خطأ، ولا شيء غيرهما؟

كتبتَ هذا في الإقليم ٠١ بـ`sealed`، وكتبتَ `switch` بفرعين، وأخبرَك المترجم حين
نسيتَ أحدهما.

والآن اجعل أحد الفرعين يحمل **ثلاث قيم**، واستخرجها في الـ`switch` بلا أن تكتب
`.` ولا اسم حقلٍ واحد. ثم أضف شرطاً على إحدى القيم داخل النمط نفسه.

**كل هذا سطرٌ واحد.** والإقليم ١١ يفكّك ما الذي يجري فيه.
