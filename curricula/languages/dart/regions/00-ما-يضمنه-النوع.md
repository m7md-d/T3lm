# الإقليم ٠٠ — ما يضمنه النوع

> هذا الفصل كلّه **نظريّ**، وهو الفصل الوحيد الذي سيكون كذلك.
>
> لن تبني فيه شيئاً. ستخرج منه بأربعة أشياء: **تحت أي ضغطٍ صارت Dart لغة**،
> و**البديهيات الخمس** التي تتساقط منها بقيّتها، و**نظام الأنواع** كاملاً — ما
> «النوع»، وأين يُحسم، وما الذي يضمنه وقت التشغيل — ثم **الطريق**.
>
> ولن يُطلَب منك تصديق شيء. كل ادّعاءٍ هنا يقابله مقطعٌ يعمل، أو **رفضٌ صريح من
> المترجم** منقولٌ بنصّه. والرفض هنا أداة تدريسٍ من الدرجة الأولى: نصف ما تعرفه
> عن نظام أنواع Dart لا تراه إلا في رسالة خطأ.

**الإصدار المثبَّت:** Dart 3.13.2. وحيث يعتمد السلوك على المنصّة، تجد وسماً:
`@spec` تضمنه المواصفة في كل مكان · `@vm` تقرّره الآلة الافتراضية · `@web` يختلف
حين تُترجَم إلى JavaScript · `@aot` يظهر في الترجمة المسبقة وحدها.

---

## الجزء الأول — تحت أي ضغط

القصّة هنا **سببية**: لكل واقعةٍ ضغطٌ دفع، وقرارٌ اتُّخذ، وثمنٌ دُفع، وأثرٌ تراه
في كودك اليوم. وما لا ينتهي إلى بناءٍ لغويّ ستكتبه لاحقاً تركتُه خارج الفصل.

### لغةٌ وُلدت لتحلّ محلّ لغةٍ أخرى

في أكتوبر ٢٠١١، وفي مؤتمر GOTO بمدينة آرهوس، أعلن **Lars Bak** و**Kasper Lund**
لغةً جديدة. وBak هو من بنى **V8**، محرّك JavaScript في Chrome. فرجلٌ يعرف حدود
JavaScript من داخلها بنى لغةً لتحلّ محلّها في المتصفّح.

**والخطّة كانت آلةً افتراضية داخل Chrome** تشغّل Dart أصلاً، بلا مرورٍ بـ
JavaScript. وحينها تصير Dart لغةً حرّةً في تصميمها: أعدادها أعدادُها، وأنواعها
أنواعُها.

**وهذا لم يحدث.**

في ٢٥ مارس ٢٠١٥ كتب الرجلان نفساهما جملةً واحدة أغلقت الطريق:

> «We have decided not to integrate the Dart VM into Chrome.»
>
> «…we will focus our web efforts on compiling Dart to JavaScript.»

**والثمن الذي تدفعه أنت اليوم:** حين تستهدف المتصفّح، تُترجَم Dart إلى
JavaScript. ولا يملك JavaScript إلا نوعاً عددياً واحداً — عائماً بدقّة مضاعفة.
فـ`int` عندك ليست هي `int` هناك.

### حيث تفترق اللغة عن نفسها

اقرأ هذا البرنامج، ثم انظر إلى مخرَجه على الآلة الأصلية، ثم إليه بعد ترجمته إلى
JavaScript.

```dart
void main() {
  print(1 == 1.0);
  print(identical(1, 1.0));
  print((1).runtimeType == (1.0).runtimeType);
}
```

<!-- out -->

```
true
false
false
```

<!-- web -->

```
true
true
true
```

**على الويب `1` و`1.0` ليسا متساويين فحسب — هما الكائن نفسه.** لأن JavaScript
لا يملك ما يفرّق بينهما، وDart لا تستطيع أن تخترع تمييزاً لا تحمله الآلة
المستضيفة.

**وأثره في يدك:** كل موضعٍ تعتمد فيه على أن العدد صحيح — قسمةً، أو فيضاً، أو
مقارنةَ نوع — يحتاج أن تعرف على أيّ من الاثنين تعمل. وسنسمّي هذه المواضع بالاسم
في الإقليم ٠٢.

### الحدّ الذي يرفضه المترجم قبل أن يعمل

الفرق ليس سلوكاً وقت التشغيل فقط. مترجم الويب **يرفض** أن يترجم ما لا يستطيع
تمثيله:

```dart
void main() {
  int big = 9223372036854775807;
  print(big + 1);
}
```

<!-- out -->

```
-9223372036854775808
```

على الآلة الأصلية `int` **٦٤ بتاً بمتمّم اثنين**، تلتفّ عند الحدّ كما تلتفّ في
C — بلا سلوكٍ غير معرَّف، وبقاعدةٍ مكتوبة. أمّا مترجم الويب فيقف عند السطر
نفسه:

<!-- web-err -->

```
main.dart:2:13:
Error: The integer literal 9223372036854775807 can't be represented exactly in JavaScript.
  int big = 9223372036854775807;
            ^^^^^^^^^^^^^^^^^^^
Error: Compilation failed.
```

**والمكسب:** «الويب مختلف» ليست تحذيراً في هامش. هي **خطأ ترجمة** يوقفك قبل أن
تشحن. وهذا نمطٌ سيتكرّر: Dart تفضّل أن ترفض على أن تفاجئك.

### نظامُ أنواعٍ كان زينة

في نسختها الأولى كانت أنواع Dart **اختيارية وغير سليمة**: تكتبها فتوثّق نيّتك،
ولا يضمن لك أحدٌ أن القيمة وقت التشغيل تطابق ما كتبت. أي: `TypeScript` تقريباً.

ثم جاء الإصدار ٢٫٠ في أغسطس ٢٠١٨، ووصفه فريق اللغة في مستودعه بجملةٍ واحدة:

> «Dart 2.0 focused on one large, single change: Reworking the Dart 1.x type
> system to a complete & sound type system.»

**ضغطٌ واحد دفع إلى ذلك:** Flutter. إطارٌ يعيد بناء شجرة الواجهة ستّين مرّة في
الثانية لا يحتمل فحصَ نوعٍ في كل وصول، ولا يحتمل مفاجأةً وقت التشغيل. والمترجم
لا يستطيع أن يحذف الفحوص إلا إذا كان النوع **يضمن** شيئاً.

**وأثره في يدك:** كل سطرٍ سيرفضه المدقّق في الأقاليم القادمة هو هذا القرار
مطبَّقاً. وسنقيس في الإقليم ١٩ ما اشتراه هذا القرار فعلاً.

### وجهان لمترجمٍ واحد

Flutter احتاج شيئين متناقضين: **إعادة تحميلٍ ساخنة** أثناء التطوير — أي أن يبقى
البرنامج حيّاً وتتغيّر شيفرته تحته — و**بدءَ تشغيلٍ فوريّ** عند المستخدم بلا
مترجمٍ يعمل في الخلفية.

فصارت Dart تُترجَم بطريقتين. والفرق ليس في السرعة وحدها: **مكتباتٌ كاملة موجودة
في وجهٍ وغائبةٌ في الآخر.**

```dart
import 'dart:mirrors';

void main() {
  print(reflectClass(int).simpleName);
}
```

<!-- out -->

```
Symbol("int")
```

هذا البرنامج نفسه، حين يُطلَب منه أن يصير ملفّاً تنفيذياً مستقلّاً:

<!-- aot-err -->

```
main.dart:1:8: Error: Dart library 'dart:mirrors' is not available on this platform.
import 'dart:mirrors';
       ^
Error: AOT compilation failed
```

**السبب ميكانيكيّ لا سياسيّ:** الترجمة المسبقة تحذف ما لا يُستدعى (tree shaking).
ومكتبةٌ تستطيع أن تنادي أي شيءٍ بالاسم وقت التشغيل تُبطِل الحذف كلَّه.

**وأثره في يدك:** «اشتغل عندي في التطوير» ليس دليلاً في Dart. والإقليم ١٩ يقيس
الفرق بين الوجهين بالحجم وبزمن البدء.

### `null` صار نوعاً

الإصدار ٣٫٠ في مايو ٢٠٢٣ أغلق آخر أبواب النسخة القديمة: **السلامة من `null`
صارت إلزامية**، لا خياراً في ملفّ إعدادات.

```dart
void main() {
  String s = null;
  print(s);
}
```

<!-- err -->

```
main.dart:2:14: Error: A value of type 'Null' can't be assigned to a variable of type 'String'.
  String s = null;
             ^
```

**اقرأ الرسالة مرّةً أخرى.** لم يقل المترجم «لا يجوز إسناد null». قال: **قيمةٌ من
النوع `Null`** لا تُسنَد إلى متغيّرٍ من النوع `String`. أي أن `null` ليست حالةً
خاصّة في اللغة — هي **قيمةٌ لها نوع**، والنوع لا يقبلها.

وافتح مصدر SDK لترى ذلك بعينك: `lib/core/null.dart` فيه `final class Null`،
وبانيها يرمي استثناءً. صنفٌ لا يُنشَأ منه إلا كائنٌ واحد.

**وأثره في يدك:** `?` و`!` و`late` في الإقليم ٠٣ ليست علامات ترقيم. هي عمليات
على **الأنواع**.

### خمسة قرارات، لا خمسون

هذه الوقائع الخمس ليست تاريخاً. كلٌّ منها **قرارٌ ما زال يعمل**، وستقع على أثره
في كل إقليمٍ بعد هذا. وما يبدو غريباً في Dart لاحقاً — لماذا يوجد `num` أصلاً،
ولماذا تُنسَخ الرسائل بين الـisolates، ولماذا `await` ليست انتظاراً — يتساقط من
خمس جُملٍ تأتي الآن.

## الجزء الثاني — البديهيات الخمس

### لماذا خمسٌ بالذات

البديهية هنا ليست شعاراً. هي **جملةٌ يُشتقّ منها سلوكٌ لم تره بعد**: تعرفها،
فتتنبّأ بما تفعله اللغة في موضعٍ لم يمرّ بك. وهذا معيار قبولها الوحيد.

وخمسٌ لأنها الحدّ الذي وجدتُ أنه يفسّر ما ستراه. وكل واحدةٍ منها تُعرَض الآن
**ببرنامجٍ يُظهرها**، لا بتعريف.

### الأولى — كلُّ شيء كائن، وللعدم نوع

في C يوجد صنفان: أنواعٌ بدائية هي أنماط بتات، وبنًى تُصنَع منها. و`3` نمطُ
بتات لا يملك شيئاً ولا يُسأل عن شيء.

```dart
void main() {
  print(3.toString());
  print(3.bitLength);
  print(3.14.floor());
  print(main.runtimeType);
  print(null.toString());
}
```

<!-- out -->

```
3
2
3
() => void
null
```

**لا استثناء في هذه القائمة.** العدد الحرفيّ يستقبل نداءً، والدالّة `main` نفسها
قيمةٌ لها نوع، و`null` — وهي غياب القيمة — تستقبل `toString` وتردّ.

والسبب في مصدر SDK لا في الشرح: `lib/core/int.dart` يعلن `int` صنفاً مجرّداً
يمتدّ من `num`. فهو **صنفٌ** في شجرةٍ جذرُها `Object`، لا كلمةٌ محجوزة تعني
«أربع بايتات».

**وما يتساقط منها:** لا فرق بين «نوعٍ بدائيّ» و«كائن» في الاستعمال، فأي قيمةٍ
تصلح وسيطاً عامّاً بلا تغليف تكتبه أنت. **والثمن** أن السؤال «كم حجم هذه
القيمة؟» — وهو أول ما تسأله في C — **لا جواب له في اللغة**. لا يوجد `sizeof`،
ولن يوجد. والإقليم ١٢ يشرح لماذا.

### الثانية — النوع لا يكذب

المواصفة تعرّف السلامة بجملةٍ واحدة: *لا يمكن أن تصل إلى حالةٍ تُنتج فيها عبارةٌ
قيمةً لا تطابق نوعها الساكن*.

اقرأ هذا وتوقّع: كل سطرٍ فيه يقبله المدقّق بلا شكوى.

```dart
void main() {
  List<int> ints = [1, 2, 3];
  List<Object> objs = ints;
  objs.add('نص');
  print(objs);
}
```

<!-- err -->

```
Unhandled exception:
type 'String' is not a subtype of type 'int' of 'value'
```

*(أثر المكدّس بعد هذين السطرين مقتطع — فيه مسار ملفّك أنت.)*

**السطر الثاني صحيح**: كل `List<int>` هي `List<Object>`. **والثالث صحيح**:
`List<Object>` تقبل `String`. ومع ذلك انفجر البرنامج — لأن الاثنين معاً يكذّبان
النوع الأول.

**وهنا موضع الافتراق عن TypeScript** بالضبط: النظامان يقبلان هذين السطرين، لكن
Dart تزرع **فحصاً وقت التشغيل** حيث عجز الفحص الساكن. النتيجة أن `ints` بقيت
`List<int>` صادقةً حتى النهاية، والثمن انفجارٌ عند الحدّ.

**وما يتساقط منها:** كل موضعٍ لا يستطيع المترجم أن يبرهن فيه على النوع يحمل
فحصاً تدفع ثمنه. والإقليم ٠٩ يسمّي هذه المواضع بالاسم.

### الثالثة — لا ذاكرة مشتركة

هذا برنامج C. المتغيّر عامّ، والخيط يزيد عليه ألفاً.

```c
#include <pthread.h>
#include <stdio.h>

int counter = 0;
int seen = 0;

void *bump(void *a) {
    counter += 1000;
    seen = counter;
    return NULL;
}

int main(void) {
    counter = 7;
    pthread_t t;
    pthread_create(&t, NULL, bump, NULL);
    pthread_join(t, NULL);
    printf("هناك: %d\n", seen);
    printf("هنا:  %d\n", counter);
}
```

<!-- c -->

```
هناك: 1007
هنا:  1007
```

**١٠٠٧ في الموضعين**، لأن الخيط والأصل يريان الذاكرة نفسها. الآن الترجمة الحرفية
إلى Dart:

```dart
import 'dart:isolate';

int counter = 0;

void bump(SendPort p) {
  counter += 1000;
  p.send(counter);
}

void main() async {
  counter = 7;
  final rp = ReceivePort();
  await Isolate.spawn(bump, rp.sendPort);
  print('هناك: ${await rp.first}');
  print('هنا:  $counter');
}
```

**المخرَج**:

```
هناك: 1000
هنا:  7
```

**١٠٠٠ لا ١٠٠٧.** الـisolate الجديد لم يرَ الـ`7` — بل بدأ من متغيّرٍ عامٍّ
**أُعيدت تهيئته من الصفر في كومته هو**. لا شيء مشترك: لا الكومة، ولا حتى
المتغيّرات العامّة.

**وما يتساقط منها:** لا سباق بيانات في Dart، ولا قفل، ولا `mutex` — لأن الشرط
المادّي للسباق غير موجود. **والثمن** أن كل رسالةٍ تعبر الحدّ **تُنسَخ**، وأن
النسخ يُقاس. والإقليم ١٦ يقيسه.

### الرابعة — `async` ليست خيطاً

البديهية الثالثة نفت الخيوط المتشاركة. فما الذي يفعله `await` إذاً؟

```dart
import 'dart:async';

void main() {
  print('١');
  Future(() => print('٤'));
  scheduleMicrotask(() => print('٣'));
  Future.value(0).then((_) => print('٣ب'));
  print('٢');
}
```

<!-- out -->

```
١
٢
٣
٣ب
٤
```

شغّله عشر مرّات: **الترتيب نفسه في كل مرّة.** ليس هنا جدولةٌ تقرّر، ولا خيطٌ
يسبق خيطاً. هناك حلقةٌ واحدة وطابوران، وقاعدةٌ تستطيع أن تحسبها على ورقة.

**وهذا هو الفرق الذي يهمّك من C:** برنامج الخيوط تتنبّأ بمخرَجه احتمالياً،
وبرنامج Dart غير المتزامن تتنبّأ بمخرَجه **يقيناً**.

**وما يتساقط منها:** `await` لا تُوقف شيئاً — تُسجّل بقيّة الدالّة في طابور
وتعود. والإقليم ١٣ يفكّك الطابورين، والإقليم ١٤ يفكّ سكر `await` إلى ما يكافئه.

### الخامسة — الضمانات لها وزن

البديهيات الأربع السابقة كلُّها **تحتاج شيئاً يعمل تحت كودك**: جامعاً يقرّر متى
تموت القيمة، وفحوصاً تزرعها السلامة، وحلقةَ أحداثٍ وطابورين، ومجدولاً للـisolates.

وهذا الشيء يُشحَن معك. هذا برنامجٌ من سطرٍ واحد، بلغتين:

<!-- shell -->

```
cc -O2 -o hello hello.c && ls -l hello        →     33 424 بايت
dart compile exe -o hello hello.dart && ls -l →  5 749 600 بايت
```

*(الأرقام من جهازٍ واحد وSDK مثبَّت. والثابت هو **الرتبة**: مئةٌ وسبعون ضعفاً،
لا خمسة بالمئة.)*

**وما تشتريه بهذه الميغابايتات الخمس** هو البديهيات الأربع نفسها. ولذلك تُترجَم
Dart بوجهين: وجهٌ يبقي المترجم حيّاً ليعيد التحميل الساخن، ووجهٌ يطبع كل هذا في
ملفٍّ واحد ليبدأ فوراً.

**وما يتساقط منها:** أن ما يعمل في التطوير قد يُرفَض في النشر — ورأيتَ ذلك في
الجزء الأول مع `dart:mirrors`. والإقليم ١٩ يقيس الوجهين.

### ما رفضته اللغة عمداً

| ما لا تجده | البديهية التي حمَته | الثمن الذي تدفعه أنت |
|---|---|---|
| `free` و`delete` | الأولى — كل شيء كائنٌ يملكه الجامع | لا تعرف **متى** تموت القيمة، والإقليم ١٢ يقول ما يبقى بيدك |
| `sizeof` وتخطيطُ البنية | الأولى — التمثيل ملكُ الـruntime لا ملكُك | لا تحسب حجماً ولا محاذاة، وتفقد ضبط الذاكرة الدقيق |
| الأنواع البدائية المنفصلة | الأولى | تغليفُ العدد ثمنٌ خفيّ، يخفّفه المترجم ولا يمحوه |
| ذاكرةٌ مشتركة بين الخيوط | الثالثة | كل رسالةٍ **تُنسَخ**، والعمل الثقيل المشترك يحتاج تصميماً آخر |
| القفل والـmutex | الثالثة — لا سباق فلا حاجة | لا تستطيع تشارُك بنيةٍ ضخمة بلا نسخها أو نقلها |
| الوراثة المتعدّدة | نظام الأنواع — الخطّية تُحسَب لا تُخمَّن | تحتاج `mixin` وترتيبها يغيّر النتيجة (الإقليم ٠٨) |
| التحميل الزائد للدوال | الوضوح على الإيجاز | اسمٌ واحدٌ لكل سلوك، وبانياتٌ مسمّاة بدلاً منه (الإقليم ٠٦) |
| `int` بعرضٍ تختاره | البديهية الأولى + قيدُ الويب | لا `uint8` ولا `int32`؛ وللبايتات مكتبةٌ منفصلة |

## الجزء الثالث — نظام الأنواع

هذا أطول أجزاء الفصل، ويُستوفى هنا **نظرياً** بالكامل: ما «النوع»، وأين يُحسم،
وما الذي يبقى منه وقت التشغيل، وكيف تُصنَع أنواعٌ جديدة، وأين ينكسر النظام. ولا
يبقى للأقاليم بعده إلا **تطبيقه**.

### النوع صنفٌ في شجرة، والشجرة جذرُها واحد

في C «النوع» وصفةٌ للتخطيط: كم بايتاً، وكيف تُفسَّر. وليس بينها قرابة — `int`
و`struct point` لا يجمعهما شيء.

في Dart النوع **صنفٌ في شجرة وراثة**، وللشجرة جذرٌ واحد. وليست هذه استعارة: افتح
`lib/core/int.dart` في مصدر SDK، فأوّل سطرٍ ذي معنى فيه إعلانُ `int` صنفاً
يمتدّ من `num`:

<!-- part -->

```dart
abstract final class int extends num { /* … */ }
```

و`num` نفسها مختومة (`sealed`) في `lib/core/num.dart`. فالسلسلة كاملةً:
`int` → `num` → `Object`.

**والفائدة ليست ترتيباً:** لأن `int` صنفٌ في الشجرة، تصلح قيمتُه حيث يصلح
`Object`، فتدخل قائمةً عامّة ووسيطاً عامّاً بلا تغليفٍ تكتبه أنت. **والثمن** أن
«ما تخطيط هذه القيمة في الذاكرة؟» سؤالٌ خارج اللغة: الشجرة تصف **ما تستطيع
القيمة أن تفعله**، لا كم تشغل.

### قمّةٌ فوق كل شيء، وقاعٌ بلا قيمة

في الشجرة موضعان لا يشغلهما صنفٌ تكتبه:

| النوع | ما يقبل | لماذا يوجد |
|---|---|---|
| `Object?` | **كل قيمة**، و`null` منها | قمّة الشجرة — ما لا تعرف عنه شيئاً |
| `Object` | كل قيمة **إلّا** `null` | القمّة بعد استبعاد العدم |
| `Null` | `null` وحدها | صنفٌ حقيقيّ لقيمةٍ واحدة |
| `Never` | **لا شيء** | قاع الشجرة — نوعُ ما لا يعود |

`Never` هو الغريب: نوعٌ **لا قيمة له**. ودالّةٌ نوعُ إرجاعها `Never` تعني أنها لا
تُرجِع أبداً — ترمي أو تدور إلى الأبد. والمترجم يستعمل ذلك: يعرف أن ما بعد
ندائها ميّت.

```dart
void main() {
  print(null is Object);
  print(null is Object?);
  print(<Never>[] is List<int>);
  print(null is Never);
}
```

<!-- out -->

```
false
true
true
false
```

**السطر الثالث هو الفائدة:** `List<Never>` قائمةٌ من كل شيء، لأن `Never` تحت
الجميع. ولهذا تصلح القائمة الفارغة لأي نوع.

### `dynamic` ليست نوعاً — هي إذنٌ بالصمت

`Object?` و`dynamic` يقبلان القيم نفسها. والفرق كلُّه في **ما يفعله المدقّق**.

```dart
void main() {
  Object? o = 5;
  print(o.noSuchThing);
}
```

<!-- err -->

```
main.dart:3:11: Error: The getter 'noSuchThing' isn't defined for the type 'Object'.
```

والقيمة نفسها، والنداء نفسه، بكلمةٍ واحدة مختلفة:

```dart
void main() {
  dynamic d = 5;
  print(d.noSuchThing);
}
```

<!-- err -->

```
Unhandled exception:
NoSuchMethodError: Class 'int' has no instance getter 'noSuchThing'.
Receiver: 5
```

**`dynamic` لم تغيّر القيمة.** غيّرت **من يفحص**: نقلت الفحص من المترجم إلى وقت
التشغيل. وهي المهرب الرسميّ الوحيد من البديهية الثانية — لا تكسر السلامة، لكنها
تؤجّل ثمنها إلى أسوأ لحظة.

**والقاعدة العملية:** `Object?` حين لا تعرف النوع، و`dynamic` حين تريد إسكات
المدقّق. والثانية قرارٌ يُبرَّر، لا افتراضٌ يُترَك.

### الأنواع تبقى وقت التشغيل

في Java تُمحى وسائط النوع (erasure): `List<int>` و`List<String>` شيءٌ واحد بعد
الترجمة. Dart لا تفعل ذلك.

```dart
void main() {
  var a = <int>[];
  var b = <String>[];
  print(a.runtimeType);
  print(a.runtimeType == b.runtimeType);
  print(a is List<int>);
  print(a is List<String>);
}
```

<!-- out -->

```
List<int>
false
true
false
```

**القائمة الفارغة تعرف نوعها.** لا قيمة فيها تدلّ عليه — الوسيط محفوظٌ في الكائن
نفسه.

**وهذا ما يجعل البديهية الثانية ممكنة أصلاً:** الفحص الحيّ الذي أنقذ `List<int>`
في الجزء الثاني يحتاج أن يعرف الكائنُ أنه `List<int>`. **والثمن** كلمةٌ إضافية
في كل كائنٍ عامّ، ووقتٌ في كل فحص.

### كل صنفٍ واجهةٌ ضمناً

في Dart لا تُعلن الواجهة. **كل صنفٍ تكتبه يُنتج واجهةً بنفس اسمه**، ويستطيع أي
صنفٍ آخر أن يعلن `implements` عليها بلا إذنٍ منك.

```dart
class Engine {
  void start() => print('دار');
}

class Mock implements Engine {
  void start() => print('تمثيل');
}

void main() {
  Engine e = Mock();
  e.start();
  print(Mock() is Engine);
}
```

<!-- out -->

```
تمثيل
true
```

**`Mock` ليست ابنةً لـ`Engine`** — لم ترث منها سطراً واحداً، و`start` كُتبت من
الصفر. ومع ذلك `Mock() is Engine` صحيح.

**وما يتساقط منه:** لا تحتاج أن تكتب `interface` لتصنع بديلاً في اختبار. **والثمن**
أن كل صنفٍ تنشره يصير عقداً على مؤلّفه ولو لم يقصد — ولهذا دخلت في الإصدار الثالث
كلماتٌ تقيّد ذلك (`final` و`base` و`interface`)، والإقليم ٠٧ يفكّكها.

### الاسم المستعار لا يصنع نوعاً

`typedef` في C لا يصنع نوعاً جديداً — يصنع اسماً آخر للنوع نفسه. وDart لم تخالف
ذلك.

```dart
typedef Metre = int;
typedef Second = int;

void main() {
  Metre m = 5;
  Second s = m;
  print(s);
  print(Metre == int);
}
```

<!-- out -->

```
5
true
```

**أسندتَ متراً إلى ثانية ولم يعترض أحد**، و`Metre == int` صحيح: الاسمان يشيران
إلى الصنف نفسه. فمن أراد أن يمنع خلط الوحدات لا يجده هنا.

### نوعٌ يوجد للمترجم وحده

الإصدار الثالث أضاف الجواب: `extension type` يصنع نوعاً **ساكناً** جديداً فوق
تمثيلٍ قائم، **ويختفي وقت التشغيل**.

```dart
extension type Metre(int v) {}
extension type Second(int v) {}

void main() {
  Metre m = Metre(5);
  Second s = m;
  print(s.v);
}
```

<!-- err -->

```
main.dart:6:14: Error: A value of type 'Metre' can't be assigned to a variable of type 'Second'.
```

هنا اعترض. والآن انظر ما بقي منه بعد الترجمة:

```dart
extension type Metre(int v) {}

void main() {
  Metre m = Metre(5);
  print(m is int);
  print(m.runtimeType);
}
```

<!-- out -->

```
true
int
```

**النوع مات عند حدّ المترجم.** لا كائن غلاف، ولا حقلٌ إضافيّ، ولا كلفةٌ في
الذاكرة — و`m` عددٌ صحيح كأي عدد. **وثمنه** أن الفحص الحيّ لا يراه: `is`
و`runtimeType` يقولان `int`، والإقليم ١٠ يُري أين يؤذي هذا.

### السجلّ نوعٌ بنيويّ — والاستثناء الوحيد

كل ما سبق **اسميّ** (nominal): صنفان بنفس الحقول نوعان مختلفان. والسجلّات
(`records`) تخالف ذلك وحدها.

```dart
void main() {
  (int, String) a = (1, 'اب');
  var b = (1, 'اب');
  print(a.runtimeType);
  print(a == b);
  print(identical(a, b));
}
```

<!-- out -->

```
(int, String)
true
false
```

**بُنيا منفصلين ومتساويان** — لأن نوع السجلّ **شكلُه**: عدد حقوله وأنواعها
وأسماؤها. ومساواته تُشتقّ من حقوله بلا أن تكتب `==`.

**وما يتساقط منه:** إرجاع قيمتين من دالّةٍ بلا صنفٍ تخترعه. **والحدّ**: `identical`
تبقى `false`، فالسجلّ قيمةٌ متساوية لا كائنٌ واحد.

### التباين: يُقبَل ساكناً، ويُفحَص حيّاً

رأيتَ في الجزء الثاني `List<int>` تُسنَد إلى `List<Object>`. القاعدة اسمها
**التغاير** (covariance): إن كان `int` تحت `Object`، فـ`List<int>` تحت
`List<Object>`.

وهذا **غير سليمٍ نظرياً** في كل لغة — لأن القائمة تُقرأ وتُكتَب، والكتابة تعكس
الاتجاه. ولكل لغةٍ جوابها:

| اللغة | جوابها | الثمن |
|---|---|---|
| Java | تغايرٌ في المصفوفات وفحصٌ حيّ · وwildcards للعموم | `ArrayStoreException` |
| C# | `in` و`out` يعلنهما المؤلّف | الرفض ساكناً، وثقلٌ في التصريح |
| TypeScript | يقبل ولا يفحص | يمرّ بصمتٍ إلى مخرَجٍ خاطئ |
| **Dart** | يقبل **ويفحص عند الكتابة** | انفجارٌ عند الحدّ، وكلفةٌ في كل إسناد |

**وهذا معنى «سليم» في Dart بالضبط:** ليس أن المترجم يبرهن على كل شيء، بل أن
**النوع الساكن لا يكذب أبداً** — فحيث عجز البرهان، زُرع فحص. والإقليم ٠٩ يريك
أين تُزرَع هذه الفحوص وكم تكلّف.

### المساواة والهوية والتقييس

`==` تسأل عن التكافؤ، و`identical` تسأل عن **الكائن نفسه**. والفرق يظهر حيث
تقيّس اللغة القيم.

```dart
class P {
  final int x;
  const P(this.x);
}

void main() {
  print(identical(const P(1), const P(1)));
  print(identical(P(1), P(1)));
  print(identical('اب', 'ا' 'ب'));
}
```

<!-- out -->

```
true
false
true
```

**`const P(1)` كائنٌ واحد في البرنامج كلّه** مهما كتبتَه مرّات — يُبنى وقت
الترجمة ويُقيَّس. والسطر الثاني يبني اثنين لأنه بلا `const`. والسلاسل الحرفية
مقيَّسةٌ كذلك ولو رُكّبت من قطع.

**وأثره في يدك:** `const` ليست «ثابتاً» بمعنى C. هي **أمرٌ للمترجم أن يبني
القيمة الآن ويشاركها**. والإقليم ٠٤ يفصّل ما يقبله المترجم هنا وما يرفضه.

### الجسر من C — من يملك ماذا

هذا الجدول هو ما يمنعك من قراءة Dart بعادات C:

| السؤال | C | Dart |
|---|---|---|
| من يحجز؟ | أنت (`malloc`) أو المكدّس | الـruntime، وفي الكومة دائماً للكائنات |
| من يحرّر؟ | أنت (`free`) | الجامع، في لحظةٍ لا تعرفها |
| متى تموت القيمة؟ | حين تقرّر أنت | حين لا يبقى إليها طريق |
| من يقرّر النوع؟ | أنت، والمترجم يصدّقك | المترجم، ولا يصدّقك |
| ماذا يبقى من النوع حيّاً؟ | لا شيء | الصنف كاملاً، ووسائط العموم معه |
| ماذا يحمل المتغيّر؟ | القيمة نفسها أو عنوانها | **مرجعاً** دائماً، للكائنات |
| هل تقيس الحجم؟ | `sizeof` | لا |
| ما وحدة التزامن؟ | خيطٌ يشارك الذاكرة | isolate لا يشارك شيئاً |

**والصفّ السادس أخطرها**، وهو منبع أكبر سوء فهمٍ ينتقل من C: في Dart لا يوجد
«تمرير بالقيمة» لكائن. والإقليم ٠٥ يفكّك ما يعنيه ذلك للإسناد والالتقاط.

### ما لا تجده في هذا النظام

- **لا أنواعٌ اتّحادية** (`String | int`). أقرب المتاح الأصنافُ المختومة والمطابقة
  (الإقليم ١١).
- **لا تحقّقٌ من الوحدات أو الأبعاد.** `extension type` أقربها، وهو ساكنٌ فقط.
- **لا تعميمٌ على القيم** (const generics). العموم على الأنواع وحدها.
- **لا تحكّمٌ في التخطيط.** لا ترتيب حقول ولا محاذاة ولا حشو — إلّا خلف حدّ FFI
  (الإقليم ٢٠).
- **لا `unsigned`.** والبتّ الأعلى إشارةٌ دائماً، وللبايتات `dart:typed_data`.

## الجزء الرابع — الطريق

### ما الذي تغيّر بعد هذا الفصل

دخلتَ وأنت تعرف C: تعرف أين تسكن كل قيمة، ومن يملكها، ومتى تموت، وكم تشغل.
وتخرج وأنت تعرف أن **ثلاثة من هذه الأسئلة الأربعة لا جواب لها في Dart** — وأن
مكانها سؤالاً واحداً هو محور المنهج كلّه: **ما الذي يضمنه النوع؟**

ولديك الآن ما تقيس به كل ما سيأتي:

| حين ترى | اسأل |
|---|---|
| رفضاً من المدقّق | أي بديهيةٍ حمَتها هذه الرسالة؟ |
| انفجاراً وقت التشغيل | أين عجز البرهان الساكن فزُرع فحص؟ |
| فرقاً بين منصّتين | هل هو أثر ٢٠١٥، أم قرارُ الـVM؟ |
| صياغةً مريحة | ما الذي تُترجَم إليه حرفياً؟ |

### أدواتك

لا تصدّق نصّاً في هذا المنهج. كل ادّعاءٍ فيه يقابله أمرٌ تشغّله:

| الأمر | ماذا يكشف |
|---|---|
| `dart analyze` | ما يرفضه النظام قبل التشغيل، بلا تنفيذ |
| `dart run --enable-asserts` | ادّعاءاتٌ مغلقةٌ افتراضياً |
| `dart compile js` بلا تصغير | **ما يولّده المترجم حرفياً** للمتصفّح |
| `dart compile exe` | الوجه الآخر: ما يُشحَن، وكم يزن |
| `dart compile kernel` | التمثيل الوسيط قبل أي منصّة |
| `dart run --observe` | الكومة حيّةً: ما حُجز، وما نجا من الجامع |

**والأمر الثالث أثمنها في هذا المنهج**: هو الوحيد الذي يريك السحر مفكوكاً.

### لا زرّ تشغيلٍ في هذا الموقع

أثبت الجزء الأول أن Dart المُترجَمة إلى JavaScript **تعطي جواباً مختلفاً** عن
Dart الأصلية: `1.0 is int` تصير `true`، والعدد الكبير يُرفض قبل أن يعمل.

وأي مشغّلٍ في متصفّحك مبنيٌّ على ذلك المسار بالضبط. فزرُّ تشغيلٍ هنا كان
سيعطيك **عكس ما يقوله النصّ** في أوّل فصلٍ بعد هذا.

**فلا زرّ.** كل لوحةٍ في هذا المنهج مخرَجٌ مسجَّل من `dart run` على آلةٍ أصلية،
وكلُّها مفحوصةٌ آلياً بـ`tools/verify.py`. وحين يكون الفرق نفسُه هو الدرس، تجد
اللوحتين معاً موسومتين.

### الطريق — خمس حِزَم

| | | |
|---|---|---|
| `00–01` | **البداية** | هذا الفصل، ثم برنامجٌ يعمل قبل أن تفهم نصفه |
| `02–05` | **القيمة والاسم** | ما تحمله، ومن يملكها، ومتى تموت — بلا `free` |
| `06–12` | **النوع** | الصنف والوراثة والـmixin والعموم والأنماط، ثم الكومة والجامع |
| `13–17` | **الزمن** | حلقة الأحداث والـFuture والـStream والـisolate والأخطاء |
| `18–22` | **من النصّ إلى برنامجٍ يُسلَّم** | الحزمة والترجمة وFFI والاختبار، ثم ختام |

**والإقليم التالي ليس شرحاً.** فيه أداةُ سطر أوامرٍ تعمل، تكتبها بيدك، وفيها
**ثلاثة أشياء لن تفهمها اليوم** — وهي بذور الأقاليم التي تليها.

### بذرة

في C تشغل هذه البنية اثنتي عشرة بايتاً لا تسعاً، وتعرف لماذا: المحاذاة والحشو.

<!-- part -->

```c
struct { int a; char b; int c; };
```

اكتب المكافئ في Dart. ثم اسأل: **كم يزن؟**

لن تجد `sizeof` تسأله. ولن تجد ترتيباً تتحكّم فيه. ومع ذلك للجواب أثرٌ يُقاس —
وسنقيسه، بأداةٍ من الجدول أعلاه، في الإقليم ١٢.
