# الإقليم ١٧ — الأخطاء

> في C ليس عندك آلية فشل — عندك اصطلاحات: رمزُ إرجاعٍ سالب، و`errno`، و`NULL`.
> ولا شيء يُلزِمك بفحصها، ولا يميّز بينها أحد.
>
> وفي Dart آليةٌ واحدة — الرمي والالتقاط — **وتقسيمٌ صريح** لما يُرمى إلى
> صنفين، ولكلٍّ منهما عقدٌ مختلف تماماً. ومن خلط بينهما كتب كوداً يخفي عيوبه عن
> نفسه.

## صنفان لا يجمعهما جدّ

```dart
void main() {
  print(FormatException('س') is Exception);
  print(FormatException('س') is Error);
  print(StateError('س') is Error);
  print(StateError('س') is Exception);
  print(ArgumentError('س') is Error);
  try {
    throw 'نصٌّ عارٍ';
  } catch (e) {
    print('${e.runtimeType}: $e');
  }
}
```

<!-- out -->

```
true
false
true
false
true
String: نصٌّ عارٍ
```

**`Exception` و`Error` شجرتان منفصلتان**، ولا نوع فرعيّ مشترك. والسطر الأخير
يقول إن اللغة تسمح برمي أي شيء — حتى نصّ.

**والفرق عقدٌ لا تصنيف:**

| | `Exception` | `Error` |
|---|---|---|
| ماذا يعني | حالةٌ متوقّعة لم تُستبعَد | **عيبٌ في البرنامج** |
| مثاله | ملفٌّ غير موجود · نصٌّ لا يُحلَّل · شبكةٌ انقطعت | فهرسٌ خارج المدى · وسيطٌ باطل · حالةٌ مستحيلة |
| من يسبّبه | العالم | **أنت** |
| هل يُلتقَط | نعم — وهو سبب وجوده | **لا** — الالتقاط يخفي العيب |
| العلاج | تعالجه في الكود | **تصلح الكود** |

**والقاعدة العملية:** إن كنتَ تستطيع أن تكتب `if` يمنع وقوعه، فهو `Error` — وموضع
إصلاحه ذلك الـ`if`، لا `catch`. وإن كان يقع مهما فعلتَ، فهو `Exception`.

**وأين يؤذي الخلط:** `catch (e)` عامّةٌ تبتلع `RangeError` مع `SocketException`.
فيصير عيبُ فهرسةٍ في كودك تحذيراً في السجلّ، ويعيش سنة.

## `on` تفرز، و`catch` تعمّ

```dart
import 'dart:io';

String read(String path) {
  try {
    return File(path).readAsStringSync();
  } on PathNotFoundException {
    return '(لا ملفّ)';
  } on FileSystemException catch (e) {
    return '(خطأ نظام ملفّات: ${e.osError?.errorCode})';
  }
}

void main() {
  print(read('/لا/يوجد'));
  print(read('/'));
}
```

<!-- runs -->

```
(لا ملفّ)
(خطأ نظام ملفّات: 21)
```

**`on` بلا `catch`** حين لا تحتاج الكائن. و**الترتيب يهمّ**: `PathNotFoundException`
نوعٌ فرعيّ من `FileSystemException`، فلو انعكس الصفّان لابتلع الأعمُّ الأخصّ ولما
وصل إليه شيء.

**ولا يفحص المترجم هذا الترتيب.** لا يوجد في Dart استثناءٌ مُتحقَّقٌ منه (checked)
كما في Java — التوقيع لا يذكر ما تَرمي، ولا أحد يُلزِمك بالتقاطه.

**وهذا قرارٌ له ثمن:** الوثائق هي مصدرك الوحيد لمعرفة ما يرميه نداء. والمقابل أنك
لا تكتب `throws` في كل توقيعٍ في السلسلة.

## `rethrow` ليست `throw e`

**الاعتقاد الشائع:** «التقطتُه ثم رميتُه من جديد — النتيجة واحدة.»

**ولماذا يبدو مقنعاً:** لأن الكائن المرميّ **هو نفسه**، ونوعه واحد، والرسالة
واحدة. ولا شيء في المخرَج يبدو مختلفاً.

```dart
void inner() => throw StateError('من الداخل');

void middle() {
  try {
    inner();
  } catch (e) {
    rethrow;
  }
}

void swallow() {
  try {
    inner();
  } catch (e) {
    throw e;
  }
}

void main() {
  for (final f in [middle, swallow]) {
    try {
      f();
    } catch (e, st) {
      final frames = st.toString().trim().split('\n');
      print('${frames.length} إطاراً');
    }
  }
}
```

**المخرَج**:

```
5 إطاراً
4 إطاراً
```

### الآلية

<!-- part -->

```
   rethrow          keeps the ORIGINAL stack trace
                    the frame of inner() is still there

   throw e          creates a NEW throw at THIS line
                    everything below the catch is gone

   #0  inner            ← present with rethrow, LOST with throw e
   #1  middle
   #2  main
```

**القاعدة الصحيحة:** `rethrow` تُكمل الرمية الأصلية، و`throw e` تبدأ رميةً جديدة
من موضع الـ`catch`. **والإطار المفقود هو بالضبط الإطار الذي وقع فيه الخطأ.**

**وحدُّها:** إن كنتَ تريد فعلاً أن تُخفي الداخل — لأنك تغلّف مكتبةً وتَعِد بواجهةٍ
خاصّة بك — فـ`throw` نوعاً جديداً ومرّر الأصل والأثر معه.

**وأين يؤذي:** طبقةُ تسجيلٍ تلتقط وتسجّل ثم ترمي بـ`throw e`. تعمل سنة، وأثرُ
كل خطأٍ في المنتَج يبدأ من سطر التسجيل.

## `finally` تعمل قبل الخروج

```dart
void main() {
  try {
    try {
      throw StateError('أ');
    } finally {
      print('finally الداخليّ');
    }
  } catch (e) {
    print('التُقط: $e');
  }

  print(f());
}

int f() {
  try {
    return 1;
  } finally {
    print('finally مع return');
  }
}
```

<!-- out -->

```
finally الداخليّ
التُقط: Bad state: أ
finally مع return
1
```

**`finally` تعمل حتى مع `return`** — وقيمة الإرجاع قد حُسبت قبلها. وهي الموضع
الصحيح لإغلاق ملفٍّ أو إلغاء اشتراك (الإقليم ١٥)، لأنها تعمل في المسارين.

## الأخطاء غير المتزامنة والحارس

رأيتَ في الإقليم ١٤ أن `Future` غير منتظَرٍ يقتل البرنامج. و`try` لا تلتقطه، لأن
الكتلة انتهت قبل أن يقع.

```dart
import 'dart:async';

void main() {
  runZonedGuarded(() {
    Future(() => throw StateError('من مستقبلٍ يتيم'));
    Timer.run(() => throw StateError('من مؤقّت'));
    print('سجّلتُ اثنين');
  }, (e, st) {
    print('الحارس التقط: $e');
  });

  print('تابعنا');
}
```

<!-- out -->

```
سجّلتُ اثنين
تابعنا
الحارس التقط: Bad state: من مستقبلٍ يتيم
الحارس التقط: Bad state: من مؤقّت
```

**الـzone سياقٌ يُورَّث** إلى كل ما يُسجَّل في الطابورين من داخلها. ولذلك التقط
الحارس خطأَين لم يقعا في جسمه — وقعا بعد أن عاد.

**ولاحظ ترتيب المخرَج:** «تابعنا» قبل الالتقاطين. الحارس لا يُبطئ شيئاً — يستلم
حين تصل الحلقة إلى تلك المهامّ.

**وحدُّها:** الـzone **لا تعبر حدّ الـisolate**. وخطأٌ في isolate آخر يحتاج
`onError` عند التوليد، أو `Isolate.run` التي تُعيد رميَه (الإقليم ١٦).

**وموضعها:** جذر التطبيق، لتسجّل ما أفلت. **ولا تُستعمَل بديلاً عن `try`** —
حارسٌ يبتلع كل شيء هو `catch (e)` العامّة بثوبٍ أوسع.

## `assert` تعمل في وجهٍ ولا تعمل في آخر

```dart
void main() {
  assert(1 == 2, 'الادّعاء فشل');
  print('عبرتُ الادّعاء');
}
```

<!-- out -->

```
عبرتُ الادّعاء
```

**لم ينفجر شيء.** الادّعاءات **مطفأةٌ افتراضياً** حتى في `dart run`، وتحتاج
`--enable-asserts`. وفي الترجمة المسبقة تُحذَف من الشيفرة تماماً.

**وهذا يحدّد ما يُكتَب فيها:** فحوصٌ داخلية تكشف عيوبك أثناء التطوير. **ولا يُوضَع
فيها أثرٌ جانبيّ**، ولا تحقّقٌ من مُدخَلٍ خارجيّ — فذاك يحتاج `ArgumentError`
يعمل دائماً.

## التمرين

**١ — أثبت فقدان الإطار.** خذ برنامج `rethrow` واطبع الأثر كاملاً في الحالتين بدل
عدد الإطارات.

أيّ سطرٍ اختفى بالضبط؟ ثم اكتب صيغةً ثالثة تُخفي الداخل **ولا** تفقد الأثر
الأصليّ.

**٢ — افرز الشجرتين.** خذ `programs/tally.dart` واجعله يفرّق: خطأُ مسارٍ غير
موجود يُطبَع للمستخدم برسالةٍ ودّية، وأيُّ `Error` يقتل البرنامج فوراً بأثره
كاملاً.

**بلا `catch (e)` عامّةٍ واحدة.** كم صنفاً احتجتَ أن تسمّيه؟

**٣ — اكشف ما يبتلعه الحارس.** ابنِ برنامجاً فيه `runZonedGuarded` وداخله
`RangeError` حقيقيّ من عيبٍ في فهرسة.

هل التقطه الحارس؟ ثم اسأل: **هل هذا ما تريده؟** واكتب حارساً يمرّر `Error` ويلتقط
`Exception` وحدها.

## الخلاصة

| ما رأيتَه | البديهية | أين يعود |
|---|---|---|
| `Error` عيبٌ و`Exception` حالة | عقدٌ لا تصنيف | ٢١ |
| لا استثناءات متحقَّقٌ منها | الوضوح على الإلزام | ١٨ |
| `rethrow` تحفظ الأثر | — | ٢١ |
| الـzone ترث ولا تعبر الـisolate | الثالثة (١٦) | ٢٢ |
| `assert` أداةُ تطويرٍ تُحذَف | الخامسة — وجهان | ١٩ |

## البذرة

كلُّ ما كتبتَه حتى الآن ملفٌّ واحد أو ملفّان في مجلّد. ونداءُ `File` جاء من
`dart:io`، و`StateError` من `dart:core` بلا أن تستوردها.

فمن قرّر أن `dart:core` تُستورَد وحدها؟ وأين تسكن `dart:io`؟ ومن أين تأتي
مكتبةٌ ليست في SDK أصلاً؟

اكتب `import 'package:http/http.dart';` في ملفٍّ وشغّله. **الرسالة التي ستراها
تسمّي ملفّاً لم تكتبه** — والإقليم ١٨ يقول ما هو، ومن يولّده، ولماذا لقيود
الإصدار في مشروعٍ يكبر ثمنٌ يُقاس.
