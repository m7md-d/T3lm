# الإقليم ٠٩ — العموم

> قلتُ في الإقليم ٠٠ إن Dart **تقبل التغاير ساكناً وتفحصه حيّاً**، ووضعتُ الجملة
> في جدولٍ ومضيتُ. وهذا الإقليم في تحصيلها: **أين** يُزرَع ذلك الفحص بالضبط،
> ومن يدفعه، وكيف تراه بعينك في المخرَج المُولَّد.
>
> وفي C ليس عندك عموم — عندك `void *` وماكرو. فالمقارنة هنا ليست في الساينتاكس،
> بل في: **من يفحص، ومتى.**

## الوسيط نوعٌ حيّ

```dart
class Box<T> {
  T value;
  Box(this.value);
  T get() => value;
  void set(T v) => value = v;
}

void main() {
  final b = Box<int>(1);
  print(b.runtimeType);
  print(b is Box<int>);
  print(b is Box<Object>);
  print(Box<String>('اب').runtimeType);
}
```

<!-- out -->

```
Box<int>
true
true
Box<String>
```

**الكائن يحمل وسيطَه.** في Java يُمحى بعد الترجمة فلا يبقى منه شيء، وفي C++
يُولَّد صنفٌ كامل لكل وسيط (monomorphization) فيكبر الملفّ. وDart بينهما: **كودٌ
واحد، ومعلومةُ نوعٍ في الكائن**.

والسطر الثالث هو التغاير: `Box<int>` **هي** `Box<Object>`. وهذا مريحٌ ومُهلِك،
والباقي في تفصيل الاثنين.

## أين يُزرَع الفحص

```dart
class Box<T> {
  T value;
  Box(this.value);
  T get() => value;
  void set(T v) => value = v;
}

void main() {
  final ints = Box<int>(1);
  final objs = ints as Box<Object>;
  print(objs.get());
  objs.set('نص');
}
```

<!-- err -->

```
1
Unhandled exception:
type 'String' is not a subtype of type 'int' of 'v'
```

**اقرأ آخر الرسالة: `of 'v'`.** ليس الفحص عند الإسناد `objs = ints`، ولا عند
`objs.set(...)` في موضع النداء. الفحص **داخل `set`، على الوسيط `v`**.

والسبب أن الموضع الوحيد الذي يُعرَف فيه `T` الحقيقيّ هو داخل الكائن. وموضع
النداء يرى `Box<Object>` فيصدّق.

**والقراءة سليمةٌ بلا فحص:** `objs.get()` أعطت `1` بلا اعتراض، لأن كل `int` هو
`Object`. **الخطر في الكتابة وحدها** — وهذا هو تعريف التغاير غير السليم.

## وهذا شكله في المخرَج

لا تصدّقني. الصنفان التاليان يفعلان الشيء نفسه، وأحدهما عامّ:

```dart
class Box<T> {
  T value;
  Box(this.value);
  void set(T v) => value = v;
}

class IntBox {
  int value;
  IntBox(this.value);
  void set(int v) => value = v;
}

void main() {
  Box<int>(0).set(1);
  IntBox(0).set(1);
}
```

<!-- shell -->

```
$ dart compile js --no-minify -O0 -o out.js main.dart >/dev/null
$ grep -A3 'A.Box.prototype' out.js
  A.Box.prototype = {
    $set$1(v) {
      return this.$ti._precomputed1._as(v);
    }
$ grep -A3 'A.IntBox.prototype' out.js
  A.IntBox.prototype = {
    $set$1(v) {
      return A._asInt(v);
    }
```

*(اللوحة مقتطعةٌ من مخرَجٍ طويل — والأمران يُشغَّلان في الفحص الآليّ.)*

`$ti` هي معلومة النوع المخزَّنة في الكائن. **والنسخة العامّة تقرؤها في كل
نداء** ثم تفحص، والنسخة المخصوصة تفحص مباشرةً.

**ولاحظ ما بقي وما ذهب:** الإسناد `value = v` حُذف — لأن الحقل لا يُقرأ في أي
مكان، فالمُحسِّن أسقطه. **والفحص لم يُحذَف.** لأنه ليس تحسيناً؛ هو ما يجعل
البديهية الثانية صادقة.

## `covariant`: تضييقٌ تعلنه أنت

المعامل في الطريقة **متغاير عكسياً** — رأيتَ ذلك في الإقليم ٠٥. فإعادةُ تعريفٍ
تضيّق المعامل مرفوضةٌ نظرياً. ومع ذلك:

```dart
class Animal {
  void feed(Animal a) => print('حيوان');
}

class Cat extends Animal {
  @override
  void feed(covariant Cat c) => print('قطّ');
}

void main() {
  Animal a = Cat();
  a.feed(Cat());
  a.feed(Animal());
}
```

<!-- err -->

```
قطّ
Unhandled exception:
type 'Animal' is not a subtype of type 'Cat' of 'c'
```

**`covariant` كلمةٌ تقول للمدقّق: أعرف أن هذا غير سليم، وأتحمّله.** فيقبل، ويزرع
الفحص نفسه.

وهي ليست حيلةً هامشية — هي ما يجعل شجرة الواجهات في Flutter ممكنة: طريقةٌ في
الأب توقيعُها عامّ، ويضيّقها كل ابنٍ إلى نوعه.

**والقاعدة:** كل `covariant` تكتبها **دَينٌ** يُسدَّد وقت التشغيل. اكتبها حين
يكون الضيق مضموناً ببناء برنامجك، لا حين تريد إسكات رسالة.

## الحدود، والاستدلال الذي يفاجئ

```dart
T largest<T extends Comparable<T>>(List<T> xs) {
  print('T = $T');
  var best = xs.first;
  for (final x in xs) {
    if (x.compareTo(best) > 0) best = x;
  }
  return best;
}

void main() {
  print(largest([3, 9, 2]));
  print(largest(['ب', 'أ', 'ت']));
  print(1 is Comparable<int>);
  print(1 is Comparable<num>);
}
```

<!-- out -->

```
T = num
9
T = String
ت
false
true
```

**`T` صار `num` لا `int`.** والسطران الأخيران يفسّران: `int` **ليست**
`Comparable<int>` — هي `Comparable<num>`، لأن مقارنة عددٍ صحيح بعددٍ عائم
مشروعة.

فلو كتب المستدلّ `T = int` لسقط الحدّ. فبحث عن أضيق نوعٍ يُرضيه فوجد `num`.
والقائمة `List<int>` مرّت لأنها `List<num>` بالتغاير — **القاعدة نفسها التي
انفجرت في الأعلى، تنقذك هنا.**

وحين تكتب الوسيط بيدك، يُفحَص الحدّ ساكناً:

```dart
class Box<T extends num> {
  final T v;
  Box(this.v);
}

void main() => print(Box<String>('اب').v);
```

<!-- err -->

```
main.dart:6:22: Error: Type argument 'String' doesn't conform to the bound 'num' of the type variable 'T' on 'Box'.
```

## ما تدفعه، وما تشتريه

| | العموم في Dart | `void *` في C |
|---|---|---|
| من يفحص | المترجم، **وما عجز عنه** زُرع فحصاً حيّاً | لا أحد |
| متى يظهر الخطأ | عند الكتابة الخاطئة، بنوعٍ وموضع | متى شاء، وربّما لا يظهر |
| كلفة الحجم | كودٌ واحد للجميع | صفر |
| كلفة الزمن | قراءةُ نوعٍ وفحصٌ عند كل كتابة | صفر |
| ما يبقى حيّاً | الوسيط كاملاً | لا شيء |

**والمقايضة معلنة:** Dart اختارت أن تدفع في وقت التشغيل ما لا تستطيع أن تبرهنه
وقت الترجمة، بدل أن تمنعك (C#) أو أن تصمت (TypeScript).

## التمرين

**١ — اجعل الفحص يظهر ويختفي.** خذ `Box<T>` أعلاه وترجمه إلى JavaScript ثلاث
مرّات: كما هو · و`T` محدوداً بـ`extends Object` · و`Box` غير عامّ بـ`int`.

قارن جسم `set` في الثلاثة. **أيّها فقد الفحص؟** ولماذا لم يفقده الثاني؟

**٢ — ابنِ وعاءً آمناً.** اكتب `SafeBox<T>` **لا يمكن** أن ينفجر عند الكتابة مهما
فعل مستعمله — بلا `dynamic` وبلا فحصٍ تكتبه بيدك.

(القاعدة التي تحلّها موجودة في هذا الإقليم: الخطر في الكتابة وحدها.)

**٣ — قِس ثمن التغاير.** اكتب حلقةً تكتب عشرة ملايين مرّة في `List<int>` مباشرةً،
وأخرى تكتب في المتغيّر نفسه بعد إسناده إلى `List<Object>` ثم إرجاعه.

هل اختلف الزمن؟ ثم أعِد التجربة على `dart compile exe`. **وقارن النسبة لا
الرقم.**

## الخلاصة

| ما رأيتَه | البديهية | أين يعود |
|---|---|---|
| الوسيط محفوظٌ في الكائن | الأولى — كل شيء كائن | ١١ · ١٦ |
| الفحص داخل الطريقة على المعامل | الثانية — النوع لا يكذب | ١٧ |
| `covariant` دَينٌ تعلنه | حدّ الثانية | — |
| الاستدلال يبحث عن أضيق ما يُرضي الحدّ | الثانية | ١١ |
| كودٌ واحد لا نسخةٌ لكل نوع | الخامسة — حجم المشحون | ١٩ |

## البذرة

`Box<int>` و`Box<Object>` نوعان مختلفان حيّاً — رأيتَه في أوّل لوحةٍ هنا. ومع
ذلك، وصل نداءُ `set` بنصٍّ **إلى داخل الطريقة** قبل أن يُرفَض.

والآن اقلب السؤال: هل تستطيع أن تصنع نوعاً جديداً **بلا** أن يحمل الكائن شيئاً
إضافياً، وبلا فحصٍ حيّ أصلاً؟

مرّ بك جوابٌ في الإقليم ٠٠ في سطرين. اكتبه من جديد، ثم اسأل: ماذا يقول `is`
عنه؟ وماذا يقول `runtimeType`؟

**النوع الذي لا يراه وقت التشغيل لا يكلّفه شيئاً — ولا يحميك منه.** والإقليم ١٠
يقيس هذه المقايضة.
