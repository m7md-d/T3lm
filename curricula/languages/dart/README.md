## لمن كُتب

**لمن أنهى [منهج C](../c/README.md)**، فيعرف أين تسكن كل قيمة ومن يملكها ومتى
تموت. وهذا بالضبط ما يجعل Dart مفهومةً بدل أن تكون سحراً: كل ما تخفيه Dart،
رأيتَه مكشوفاً هناك.

**والمنهج يشرح ما تفعله Dart بما تركته C**: من يحرّر؟ ومن يملك؟ وماذا يعني
«كائن» حين لا يوجد `malloc`؟

> **تشخيصُ المستوى شرطٌ قبل التصميم** (القانون ٧): يُسأل المتعلّم عن مستواه في
> Dart وعن لغة المرساة التي يتقنها. وهذه الخطّة مكتوبةٌ على أن **C مرساة و
> Dart صفر** — فإن اختلف، تغيّر الفصل صفر وحده.

## الأدوات المستهدفة

```
dart --version        # يُثبَّت الإصدار ويُعلَن — Dart 3 فما فوق
dart analyze · dart test · dart compile exe · dart run --observe
```

**Dart 3 فما فوق** لأن ما قبلها لغةٌ أخرى عملياً: السلامة من `null` صارت
إلزامية، ودخلت `records` و`patterns` والأصناف المختومة. والفروق التي تهمّ
تُذكَر في موضعها.

## الطريق — خمس حِزَم

| | | |
|---|---|---|
| `00–01` | **البداية** | القصّة، والبديهيات، وبرنامجٌ يعمل قبل أن تفهم نصفه |
| `02–05` | **القيمة والاسم** | ما تحمله، ومن يملكها، ومتى تموت — بلا `free` |
| `06–12` | **النوع** | الصنف والوراثة والـmixin والعموم والأنماط — وسلامةُ النظام |
| `13–17` | **الزمن** | حلقة الأحداث والـFuture والـStream والـisolate والأخطاء |
| `18–22` | **من النصّ إلى برنامجٍ يُسلَّم** | الحزمة والترجمة وFFI والاختبار، ثم ختام |

### وتفصيلُها

| | | |
|---|---|---|
| `00` | **الفصل صفر: لغةٌ وُلدت لتحلّ محلّ JavaScript** | النظريّ الوحيد: القصّة تحت ضغطها — لماذا فشلت في المتصفّح، وكيف أنقذها Flutter، ولماذا صار ذلك يفسّر نصف تصميمها · البديهيات الخمس بأدلّةٍ تعمل · وسؤالُ السلطة: من قرّر — المواصفة، أم الـVM، أم المترجم AOT، أم المنصّة (ويب أم أصليّ)؟ |
| `01` | **أوّل برنامج يعمل** | أداةُ سطر أوامرٍ في نحو مئة سطر: تقرأ ملفّاً وتحلّله وتطبع تقريراً. **فيها ثلاثة أشياء لن تفهمها اليوم** — وهي بذورُ الأقاليم القادمة |
| `02` | **العدد والقيمة** | `int` و`double` و`num` · وأن `int` على الويب **٥٣ بتاً لا ٦٤** — أوّل موضعٍ تختلف فيه المنصّة · والمقارنة بـC صريحة |
| `03` | **`null` نوعاً** | `?` و`!` و`late` · ولماذا هي مسألةُ **نوعٍ** لا فحصٍ بـ`if` · وما الذي كسره الانتقال، وكيف نجت المكتبات |
| `04` | **الاسم والثبات** | `var` و`final` و`const` · الثابتُ وقت الترجمة · والـcanonicalization: `const` واحدةٌ في الذاكرة مهما تكرّرت |
| `05` | **الدالّة قيمة** | الوسائط المسمّاة والاختيارية · الـclosure وما تلتقطه · والـtear-off |
| `06` | **الصنف** | البانيات: مولِّدة ومسمّاة وموجِّهة و`factory` · قائمةُ التهيئة ولماذا تسبق الجسم · و`this` |
| `07` | **الوراثة والواجهة** | `extends` و`implements` · و**أن كل صنفٍ واجهةٌ ضمناً** — قرارٌ يفسّر كثيراً مما يلي |
| `08` | **الـmixin** | `with` · وخطّية الحلّ (linearization): **الترتيب يغيّر النتيجة**، ويُرى ببرنامج |
| `09` | **العموم (generics)** | التباين · `covariant` · و**أن الأنواع باقيةٌ وقت التشغيل** (reified) — بخلاف Java، ويُرى بـ`is` |
| `10` | **التوسعة** | `extension` على نوعٍ لا تملكه · و`extension type` وأين يختفي وقت التشغيل |
| `11` | **الأنماط** | `sealed` والمطابقة الشاملة · `records` · والتفكيك · وما الذي صار المدقّق يضمنه بها |
| `12` | **الكومة والجامع** | جامعُ الأجيال · ولماذا الكائنُ الصغير قصيرُ العمر رخيص · و**لماذا لا يوجد `sizeof`** · وما يعنيه التسريب في لغةٍ بجامع |
| `13` | **حلقة الأحداث** | طابورُ المهامّ الدقيقة وطابورُ الأحداث · و**تتنبّأ بترتيب الطباعة قبل أن تشغّل** — بوّابةُ تنبّؤ |
| `14` | **`Future` و`async`/`await`** | ما الذي يُترجَم إليه `await` · وأين تعود السيطرة · و`Future` المكتملة سلفاً وأثرها في الترتيب |
| `15` | **`Stream`** | المفردة والمذاعة · الاشتراك والإلغاء · الضغطُ الخلفيّ · و`async*` و`yield` |
| `16` | **الـisolate** | كومةٌ لكلٍّ · `SendPort` · **نسخُ الرسائل وثمنه مقيساً** · `Isolate.run` · وما الذي لا يُنسَخ |
| `17` | **الأخطاء** | `Exception` مقابل `Error` · والالتقاطُ عبر `await` كيف يختلف · والـzone وما تلتقطه |
| `18` | **الحزمة** | `pub` و`pubspec` · قيودُ الإصدار وحلُّها · وما يعنيه أن تعتمد على حزمةٍ لا تقرؤها |
| `19` | **الترجمة** | JIT مقابل AOT · `dart compile exe` · حجمُ الناتج وtree shaking · و**قياسُ الفرق** بين وضعي التشغيل |
| `20` | **FFI** | `dart:ffi` · استدعاءُ دالّة C · و**ملكيةُ الذاكرة عبر الحدّ**: من يحرّر؟ وهنا يلتقي المنهجان |
| `21` | **الاختبار والأدوات** | `test` · المدقّق واللِّنت · و`--observe` والملاحظة الحيّة |
| `22` | **الختام** | مشروعٌ بمعايير قبول، بلا كودٍ جاهز: أداةٌ حقيقية تُترجَم AOT، تستعمل isolates لعملٍ ثقيل وFFI لقدرةٍ من C |

## الفصل صفر — ما يجب أن يحمله

1. **القصّة تحت ضغطها**: Dart صُمّمت لتحلّ محلّ JavaScript في المتصفّح، ففشلت
   في ذلك ونجحت في غيره. وأكثرُ ما يبدو غريباً فيها أثرٌ من ذلك الهدف الأوّل —
   ومن التوافق مع JavaScript الذي لم تستطع تركه.
2. **البديهيات الخمس بأدلّةٍ تعمل** — لا شرحَ لها بل برنامجٌ يُظهر كلاً منها.
3. **الجسر من C**: جدولٌ صريح — من يحجز، ومن يحرّر، ومن يقرّر النوع، وأين
   تسكن القيمة. عمودان: C وDart. وهو ما يمنع القارئ من قراءة Dart بعادات C.

## التحقّق

`tools/verify.py` على نمط منهج C: يشغّل كل بلوكٍ ويقارن مخرَجه بلوحته.

**وسلطاتٌ يفرضها الموضوع:**

| السلطة | معناها |
|---|---|
| `@spec` | تضمنه مواصفة اللغة على أي منصّة |
| `@vm` | تقرّره الـVM — كترتيب الطابورين وسلوك الجامع |
| `@web` | يختلف على الويب: `int` و`double` والأعداد |
| `@aot` | يظهر في الترجمة AOT ولا يظهر في JIT (أو العكس) |

**ولوحاتُ الزمن تُشغَّل مراراً**: ترتيبٌ ظهر مرّةً ادّعاءٌ لا لوحة.

## ما يتركه لغيره

- **الواجهة** — [`web/flutter`](../../web/flutter/README.md)، وهو يبني على هذا
  المنهج ولا يعيده.
- **الترميز والنصّ** — [`systems/text-encoding`](../../systems/text-encoding/README.md).
  يقف هذا عند حدّ: `String` في Dart وحداتُ UTF-16، وهذا أثرُه.
- **نظام الأنواع نظريةً** — [`languages/typescript`](../typescript/README.md)
  يحمل «النوع مجموعة». وهنا يُستعمل الفرق: Dart سليمة وTypeScript ليست، والمقارنة
  سطرٌ لا فصل.

## قرارات معلّقة

1. **إصدار Dart** يُثبَّت ويُعلَن.
2. **هل يُبنى قبل Flutter أم معه؟** الخطّة تفترض قبله. والبديل أن يُدمَجا،
   وهو ما يجعل منهجاً واحداً بأربعين إقليماً — ويُرفَض لذلك.
3. **الويب هدفاً**: تُعرَض فروقُه في عمودٍ ثانٍ، أم يُثبَّت المنهج على الأصليّ
   ويُذكَر الويب في موضعين أو ثلاثة؟
