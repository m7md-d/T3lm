## الفشل يصعد بالنداءات

الاستثناء يخرج من الموضع الذي وقع فيه، ويصعد في سلسلة النداءات حتى يجد `except`
يمسكه. وإن لم يجد، يطبعه المفسّر وينتهي البرنامج.

**والأثر (traceback) يحمل السلسلة كاملةً** من أعلى النداء إلى موضع الفشل.

**مثال**

<!-- part: 11-propagate -->

```python
def report(table):
    return summarise(table)


def summarise(table):
    return total_of(table, "profit")


def total_of(table, name):
    return sum(table[name])


report(Table({"sales": [1, 2]}))
```

**المخرَج**

<!-- err: KeyError -->

```
Traceback (most recent call last):
  File "programs/11-propagate.py", line 16, in <module>
    report(Table({"sales": [1, 2]}))
  File "programs/11-propagate.py", line 5, in report
    return summarise(table)
  File "programs/11-propagate.py", line 9, in summarise
    return total_of(table, "profit")
  File "programs/11-propagate.py", line 13, in total_of
    return sum(table[name])
  File "programs/table.py", line 16, in __getitem__
    return self.columns[name]
KeyError: 'profit'
```

خمسةُ مواضع: من `<module>` إلى `__getitem__` في ملفٍّ آخر. **والسطر الأخير وحده
هو الخطأ**، وما قبله الطريق إليه.

**والرسالة `KeyError: 'profit'` تقول المفتاح ولا تقول أنه اسمُ عمود.** من يقرأها
لا يعرف أن الجدول هو المصدر إلا بقراءة الأثر.

**المكسب:** الأثر يُقرأ من أسفل: الخطأ، ثم من نادى، ثم من نادى قبله. وهذا
ترتيبٌ معاكس لما تفعله العين أوّل مرّة.

## استثناءٌ يحمل سببه

`raise X from Y` يربط الاستثناء الجديد بالأصليّ، فيبقى الاثنان في الأثر.

**مثال**

<!-- part: 11-from -->

```python
class MissingColumn(Exception):
    pass


def column(table, name):
    try:
        return table[name]
    except KeyError as e:
        raise MissingColumn(f"لا عمود بالاسم {name}") from e
```

**المخرَج**

<!-- err: MissingColumn -->

```
MissingColumn → لا عمود بالاسم profit
السبب: KeyError 'profit'
__context__ هو __cause__: True
The above exception was the direct cause of the following exception:
MissingColumn: لا عمود بالاسم profit
```

الاستثناء الجديد يحمل رسالةً تقول المشكلة بلغة الجدول، ويحمل `__cause__` فيه
الأصليّ.

**والفرق بين `from e` وحذفها فرقٌ في الأثر لا في السلوك:**

| ما تكتب | ما يظهر في الأثر |
|---|---|
| `raise X from e` | `The above exception was the direct cause of…` |
| `raise X` داخل `except` | `During handling of the above exception, another…` |
| `raise X from None` | الأصليّ يُحجَب كلَّه |

**المكسب:** `from e` تقول «هذا ترجمةٌ لذاك». وحذفُها تقول «وقع خطأٌ آخر أثناء
المعالجة» — وهي جملةٌ أضعف، ويقرؤها من يشخّص شكّاً في أن معالجتك نفسها كسرت شيئاً.

## الحالات

### `finally` تلتقط الخروج، وقد تسرقه

**توقّع** قبل أن تقرأ: ما الذي تعيده كلٌّ من الثلاث؟

<!-- part: 11-finally -->

```python
def careful():
    try:
        return "من try"
    finally:
        print("  finally عملت")


def greedy():
    try:
        return "من try"
    finally:
        return "من finally"


def swallow():
    try:
        raise ValueError("انظر إليّ")
    finally:
        return "لا شيء حدث"
```

المخرَج:

<!-- out -->

```
  finally عملت
من try
من finally
لا شيء حدث
programs/11-finally.py:12: SyntaxWarning: 'return' in a 'finally' block
  return "من finally"
programs/11-finally.py:19: SyntaxWarning: 'return' in a 'finally' block
  return "لا شيء حدث"
```

`careful` طبعت من `finally` ثم أعادت قيمة `try` — فـ`finally` تعمل ولا تغيّر
النتيجة.

`greedy` أعادت قيمة `finally`، لأن `return` فيها تحلّ محلّ ما قبلها.

**و`swallow` هي الخطيرة:** رفعت `ValueError` وأعادت نصّاً. الاستثناء اختفى بلا
أثرٍ ولا رسالة.

**والسطران الأخيران تحذيرٌ من المفسّر نفسه** على مجرى الخطأ: `return` في
`finally` نمطٌ ترفضه اللغة بلسانها، وعند السطرين ١٢ و١٩ بالضبط.

والقاعدة: `finally` للتنظيف — إغلاق ملفّ، تحرير قفل. و`return` أو `break`
فيها تكتم ما كان يصعد.

### `except Exception` لا تمسك كلَّ شيء

<!-- part: 11-base -->

```python
print([c.__name__ for c in KeyboardInterrupt.__mro__])
print([c.__name__ for c in ValueError.__mro__])

for exc in (ValueError("قيمة"), KeyboardInterrupt()):
    try:
        raise exc
    except Exception:
        print("مُسِك بـexcept Exception:", type(exc).__name__)
    except BaseException:
        print("أفلت منها، ومُسِك بـBaseException:", type(exc).__name__)
```

<!-- out -->

```
['KeyboardInterrupt', 'BaseException', 'object']
['ValueError', 'Exception', 'BaseException', 'object']
مُسِك بـexcept Exception: ValueError
أفلت منها، ومُسِك بـBaseException: KeyboardInterrupt
```

`KeyboardInterrupt` و`SystemExit` يرثان `BaseException` مباشرةً، ويتخطّيان
`Exception`. وقراءةُ `__mro__` هي التي تقول ذلك، كما في الفصل `08`.

وهذا مقصود: `except Exception` في حلقةٍ طويلة لا تمنع المستخدم من إيقاف
البرنامج بـCtrl-C، ولا تمنع `sys.exit` من الخروج.
