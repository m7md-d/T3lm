# ٠٧ — الصنف والنسخة

الفصل السابق قال إن المفسّر يبحث عن الأسماء المحجوزة على النوع. هنا تعرف ما
النوع فعلاً: كائنٌ يحمل قاموساً، وبحثُ السمة يمرّ عليه.

---

## سمةٌ في النسخة وسمةٌ في الصنف

كل نسخةٍ تحمل قاموساً في `__dict__`، وكل صنفٍ يحمل قاموساً آخر. وبحثُ `obj.name`
ينظر في قاموس النسخة أولاً، ثم في قاموس الصنف، ثم في أصوله.

**مثال**

<!-- part: 07-dict -->

```python
class Row:
    kind = "row"

    def __init__(self, city):
        self.city = city


a = Row("Riyadh")
b = Row("Jeddah")

print(a.__dict__)
print(a.kind, b.kind)

a.kind = "header"
print(a.__dict__)
print(a.kind, b.kind, Row.kind)

Row.kind = "record"
print(a.kind, b.kind)
```

**المخرَج**

<!-- out -->

```
{'city': 'Riyadh'}
row row
{'city': 'Riyadh', 'kind': 'header'}
header row row
header record
```

**السطر الأول:** قاموس النسخة يحمل `city` وحده. و`kind` ليس فيه، ومع ذلك
`a.kind` تعمل — لأن البحث صعد إلى الصنف.

بعد `a.kind = "header"`: الإسناد كتب في قاموس النسخة. صار لـ`a` سمةٌ
تحجب سمة الصنف، و`b` ما زال يرى سمة الصنف.

بعد `Row.kind = "record"`: تغيّر `b` ولم يتغيّر `a`، لأن `a` صار له نسختُه.

**المكسب:** سمةُ صنفٍ قابلةٌ للتغيير مشتركةٌ بين كل النسخ. هذا هو سبب `into=[]`
في الفصل `05` بصيغةٍ أخرى — وقائمةٌ في جسم صنفٍ تُشارَك كما تُشارَك القيمة
الافتراضية.

---

## `self` وسيطٌ يُملأ عنك

الطريقة في جسم الصنف دالّةٌ عادية. والذي يصنع `self` هو **الوصول عبر النسخة**.

**مثال**

<!-- part: 07-bound -->

```python
from table import Table

t = Table({"sales": [1, 2, 3]})

print(Table.__len__)
print(t.__len__)
print(t.__len__.__self__ is t)

print(Table.__len__(t), t.__len__(), len(t))
```

**المخرَج**

<!-- runs: 07-bound -->

```
<function Table.__len__ at 0x10291b270>
<bound method Table.__len__ of <table.Table object at 0x102910590>>
True
3 3 3
```

`Table.__len__` دالّة. و`t.__len__` طريقةٌ مربوطة (bound method): كائنٌ
يحمل الدالّةَ والنسخةَ معاً، ويظهر ذلك في `__self__`.

والسطر الأخير يقول إن الثلاثة طريقٌ واحد: `len(t)` تصل إلى `Table.__len__(t)`.

**المكسب:** `self` ليس كلمةً محجوزة. هو اسمُ أوّل معامِلٍ يملؤه الربط، ولو سمّيتَه
`this` عمل — والاصطلاح وحده يمنعك.

## كلفة القاموس

القاموس لكل نسخةٍ يعطي المرونة ويكلّف ذاكرة. و`__slots__` يستبدله بخاناتٍ ثابتة.

**مثال**

<!-- part: 07-slots -->

```python
class Wide:
    def __init__(self, city, sales):
        self.city = city
        self.sales = sales


class Narrow:
    __slots__ = ("city", "sales")

    def __init__(self, city, sales):
        self.city = city
        self.sales = sales
```

**المخرَج**

<!-- err: AttributeError -->

```
Wide   48 + 296 = 344
Narrow 48
AttributeError: 'Narrow' object has no attribute 'profit' and no __dict__ for setting new attributes
```

٣٤٤ بايتاً مقابل ٤٨. والفرق قاموسُ النسخة، وهو ٢٩٦ بايتاً لسمتين.

**والثمن في السطر الأخير:** `__slots__` يمنع إضافة سمةٍ لم تُعلَن. وهذا يمنع
الخطأ المطبعيّ الصامت أيضاً: `row.slaes = 5` يفشل بدل أن ينشئ سمةً جديدة.

**والرقم ٢٩٦ ثمنُ طلب القاموس:** المفسّر يخزّن السمات مضغوطةً ولا يبني قاموساً
إلا حين يُطلَب `__dict__` صريحاً. و`a.kind = "x"` تكتب فيه بالضبط كما تكتب
`a.__dict__["kind"] = "x"`.

**المكسب:** مليونُ نسخةٍ بسمتين تكلّف ٣٤٤ ميغابايت بقاموس و٤٨ بلا قاموس. وهذا
القرار يعود في الفصل `17` حين تسأل لماذا لا يكفي صنفٌ لكل صفّ.

## الحالات

### الصنف كائنٌ يُبنى وقت التشغيل

<!-- part: 07-classobj -->

```python
class Row:
    kind = "row"

    def label(self):
        return self.kind


print(type(Row), type(type(Row)))
print([k for k in Row.__dict__ if not k.startswith("__")])

Made = type("Made", (), {"kind": "made", "label": Row.label})
print(Made().label(), type(Made))
```

<!-- out -->

```
<class 'type'> <class 'type'>
['kind', 'label']
made <class 'type'>
```

`type(Row)` هو `type`، و`Row.__dict__` قاموسٌ فيه ما كتبتَه في جسم الصنف. والسطر
الأخير بنى صنفاً بلا جملة `class`: `type(name, bases, namespace)`.

فجملةُ `class` سكرٌ فوق نداءٍ لـ`type`، والصنف كائنٌ يُنشَأ ويُعدَّل وقت التشغيل.
وهذا ما يجعل مزخرِفات الفصل `09` قادرةً على تغيير الأصناف كما تغيّر الدوالّ.

## تمرين

اكتب `Table` بـ`__slots__` وقِس الفرق على عشرة آلاف جدول، ثم أضف صنفاً يرثه.

<!-- task -->

```python
class Slim:
    __slots__ = ("columns",)


class Child(Slim):
    pass
```

هل ورث `Child` المنعَ أم عاد إليه القاموس؟ وما الذي يغيّر الجواب؟

وسؤالٌ ثانٍ: صنفٌ بـ`__slots__` لا يقبل `functools.cached_property`. لماذا؟
