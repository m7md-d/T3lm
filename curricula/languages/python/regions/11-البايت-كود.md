# الإقليم ١١ — البايت-كود

> «لا شيء يُحسَم قبل التشغيل إلا شكل الكود» — البديهية الرابعة. وهذه الحزمة تسأل:
> **وما هو ذلك الشكل بالضبط؟**
>
> والجواب ليس نظرياً. أداةٌ في المكتبة القياسية تطبعه، ورقمٌ تقيسه يثبت أنه يفسّر
> الأداء.

## آلةُ مكدَّس

الكود يُترجَم إلى تعليماتٍ لآلةٍ افتراضية تعمل بمكدَّس: كلُّ تعليمةٍ تدفع قيماً أو
تسحبها.

<!-- part: 11-dis -->

```python
def h(x):
    return x.y + 1


dis.dis(h)
```

<!-- out -->

```
  4           RESUME                   0

  5           LOAD_FAST_BORROW         0 (x)
              LOAD_ATTR                0 (y)
              LOAD_SMALL_INT           1
              BINARY_OP                0 (+)
              RETURN_VALUE
```

اقرأها سطراً سطراً: ادفع `x`، استبدله بصفته `y`، ادفع `1`، اسحب اثنين وادفع
حاصل `+`، ثم أعد ما في القمّة.

**ولا شيء هنا يذكر نوعاً.** `BINARY_OP` واحدةٌ لكل الأنواع؛ ما تفعله يُقرَّر وقت
التشغيل من نوعَي المعامِلَين (البديهية الأولى). ولهذا لا يستطيع المفسّر أن يستبدل
جمع عددين بتعليمة جمعٍ في المعالج: **لا يعرف قبل أن يصل.**

## اسمان، تعليمتان مختلفتان

<!-- part: 11-local-vs-global -->

```python
g = 1


def uses_global():
    return g


def uses_local():
    x = 1
    return x
```

<!-- out -->

```
uses_global
    RESUME 
    LOAD_GLOBAL g
    RETURN_VALUE 
uses_local
    RESUME 
    LOAD_SMALL_INT 
    STORE_FAST x
    LOAD_FAST_BORROW x
    RETURN_VALUE 
```

`LOAD_FAST` مقابل `LOAD_GLOBAL` — وهذا هو ما وعدتُك به في الإقليم `02`.

المحلّيّ يسكن **مصفوفةً** في الإطار، ويُقرَأ بفهرسٍ محسوبٍ وقت الترجمة. والعالميّ
يسكن **قاموساً**، ويُقرَأ ببحثٍ عن مفتاح.

**وهنا يظهر لماذا حُسمت محلّيّةُ الاسم من النصّ:** لأن الفهرس في المصفوفة يجب أن
يكون معروفاً قبل التشغيل. و`UnboundLocalError` رسالةُ خانةٍ في المصفوفة لم
تُملَأ بعد.

## الفرق يُقاس

**تنبّأ:** أربع قراءات — متغيّرٌ محلّيّ، واسمٌ عالميّ، وصفةُ كائن، وعنصرُ قائمة.
رتّبها بالكلفة، وخمّن الفرق بين الأولى والأخيرة.

<!-- part: 11-attr-cost -->

```python
def read_local():
    x = 1
    for _ in R:
        x
    return x


def read_attr():
    for _ in R:
        h.value
```

المخرَج:

<!-- runs: 11-attr-cost -->

```
محلّيّ      1.1 ns لكل قراءة
عالميّ      2.2 ns لكل قراءة
صفة         4.6 ns لكل قراءة
فهرس        5.5 ns لكل قراءة
```

(طُرحت كلفة الحلقة الفارغة من الأربعة.)

**خمسةُ أضعافٍ بين الطرفين**، وكلُّها «قراءةُ قيمة» في الظاهر. والترتيب يطابق
التعليمات: فهرسٌ في مصفوفة، فبحثٌ في قاموس، فبحثٌ يصعد سلّم الإقليم `05`، فنداءُ
فتحة `__getitem__`.

**وهذه هي القاعدة التي تفسّر تحسينات Python الحقيقية:** ما يُكرَّر في حلقةٍ ساخنة
يُنقَل إلى متغيّرٍ محلّيّ قبلها. لا لأنه «أنيق»، بل لأن التعليمة تتغيّر.

## التمرين

`Table.total` تقرأ `self.columns[name]` مرّةً ثم تدور. **فكّكها بـ`dis` واعدد
التعليمات داخل الحلقة**، ثم اكتب نسخةً ثانيةً تنقل كلّ ما تستطيع خارجها.

**والقيد:** قِس الاثنتين على مليون صفّ، **ولا تقبل تحسيناً لا تراه في `dis`.** إن
تحسّن الزمن ولم تتغيّر تعليمات الحلقة فأنت تقيس ضوضاء.

**ثم:** ما أقلُّ عددٍ من التعليمات يمكن أن تصل إليه داخل الحلقة؟ وكم يبقى بينك
وبين الـ×١٢٢ التي رأيتَها في الإقليم `01`؟

## الخلاصة

الكود يصير تعليماتٍ لآلة مكدَّس، والتعليمة لا تحمل نوعاً فيُقرَّر كلُّ شيءٍ وقت
التشغيل.

والاسم المحلّيّ فهرسٌ في مصفوفة، والعالميّ مفتاحٌ في قاموس، والصفة سلّمٌ يُصعَد —
وثلاثتها تُقاس فتظهر بالترتيب نفسه.

وبقي أن نسأل: أين تسكن تلك المصفوفة؟
