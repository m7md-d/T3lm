# الإقليم ٠٥ — الكائن من الداخل

> عرفتَ أن الاسم مفتاحٌ في قاموس. الآن: **الصفة كذلك.**
>
> وهذا الإقليم يفتح الحزمة الثانية بسؤالٍ واحد: أين تسكن `p.x` فعلاً، ومن يبحث
> عنها، وكم تكلّف.

## الصفة مفتاحٌ أيضاً

في C البنية تخطيطٌ يُحسَم وقت الترجمة: `p.x` تُترجَم إلى «العنوان + إزاحةٌ معلومة».
هنا `p.x` **بحثٌ في قاموسٍ وقت التشغيل**.

<!-- part: 05-dict -->

```python
class P:
    def __init__(self, x, y):
        self.x = x
        self.y = y


p = P(1, 2)
print(p.__dict__)
p.z = 3
print(p.__dict__, p.z)
print("الصنف يحمل قاموسه:", "x" in P.__dict__, "__init__" in P.__dict__)
```

<!-- out -->

```
{'x': 1, 'y': 2}
{'x': 1, 'y': 2, 'z': 3} 3
الصنف يحمل قاموسه: False True
```

`self.x = x` كتبت مفتاحاً في قاموس الكائن. ولذلك استطعتَ إضافة `z` بعد الإنشاء
بلا أن يعترض أحد: **لا يوجد تخطيطٌ ثابتٌ لتخالفه.** وهذه البديهية الأولى مطبَّقةً
على الصفات — النوع صفةُ الكائن، فلا يملي على الكائن ما يحمله.

والسطر الأخير يفصل قاموسين: قاموسُ الكائن فيه بياناته، وقاموسُ الصنف فيه طرقُه.
و`x` ليست في الصنف لأنها لا تُنشَأ إلا حين يعمل `__init__`.

## البحث يصعد

**تنبّأ:** صنفٌ فيه `kind = "أساس"`، وكائنٌ منه. تكتب `k.kind = "خاصّ"` ثم
`del k.kind`. ماذا تطبع `k.kind` بعدها؟

<!-- part: 05-lookup -->

```python
class Base:
    kind = "أساس"


class Kid(Base):
    pass


k = Kid()
print(k.kind, "|", "kind" in k.__dict__)
k.kind = "خاصّ"
print(k.kind, Kid.kind, Base.kind, "|", k.__dict__)
del k.kind
print(k.kind)
```

المخرَج:

<!-- out -->

```
أساس | False
خاصّ أساس أساس | {'kind': 'خاصّ'}
أساس
```

القراءة الأولى وجدت `kind` في **الصنف** بعد أن لم تجدها في الكائن. والكتابة لم
تمسّ الصنف — أنشأت مفتاحاً في قاموس الكائن **يحجب** ما فوقه. والحذف أزال الحاجب،
فعاد الأصل يظهر.

**والقاعدة:** القراءة تصعد (الكائن، فالصنف، فقواعده)، والكتابة تقع في الكائن
دائماً. وهي القاعدة نفسها التي رأيتَها في الإقليم `02` مع الفضاءات الاسمية —
سلَّمٌ للقراءة، ودرجةٌ واحدةٌ للكتابة.

## ثمنُ القاموس

المرونة التي رأيتَها لها فاتورةٌ تُقاس: **قاموسٌ كاملٌ لكل كائن.**

<!-- part: 05-slots -->

```python
class Loose:
    def __init__(self, x, y):
        self.x, self.y = x, y


class Tight:
    __slots__ = ("x", "y")

    def __init__(self, x, y):
        self.x, self.y = x, y


a, b = Loose(1, 2), Tight(1, 2)
print("الكائن  :", sys.getsizeof(a), sys.getsizeof(b))
print("مع قاموسه:", sys.getsizeof(a) + sys.getsizeof(a.__dict__), sys.getsizeof(b))
```

<!-- err: AttributeError -->

```
الكائن  : 48 48
مع قاموسه: 344 48
Traceback (most recent call last):
  File "programs/05-slots.py", line 22, in <module>
    b.z = 3
    ^^^
AttributeError: 'Tight' object has no attribute 'z' and no __dict__ for setting new attributes
```

الكائنان متساويان في السطر الأول — لأن `getsizeof` تقيس الكائن وحده، والقاموس
كائنٌ آخر يشير إليه. وفي السطر الثاني تظهر الفاتورة: **٣٤٤ مقابل ٤٨**.

`__slots__` تستبدل القاموس بمصفوفةِ مؤشّراتٍ ثابتةِ الطول، فتوفّر الذاكرة وتسرّع
الوصول — **وتدفع الثمن الذي تراه في الرفض**: لا صفةً جديدة بعد التعريف.

وهذا قرارٌ تتّخذه حين يكون عندك ملايينُ الكائنات من نوعٍ واحد. وسنعود إليه في
الحزمة الرابعة، حين نكتشف أن الجواب الحقيقيّ لذلك الحجم **ليس كائناتٍ أصغر، بل
لا كائناتٍ أصلاً**.

## ماذا يعني هذا للجدول

عمودك يخزّن `list` من الكائنات. مليون صفٍّ يعني: كائنُ قائمةٍ واحد، ومليون
مؤشّرٍ فيه، ومليون كائن عدد — كلٌّ منها ٢٨ بايتاً وترويسةٌ وعدّاد.

**قِس هذا الآن بنفسك** قبل أن تقرأ الحزمة الرابعة، فالفارق الذي ستراه هناك يبدأ
من هنا.

## التمرين

**أضف `__slots__` إلى `Column`، وقِس الفرق في جدولٍ بعشرة أعمدة ومليون صفّ.**

**والقيد:** قِس شيئين لا شيئاً واحداً — حجمَ الكائنات، **وزمنَ** `total`. وفسّر
لماذا تغيّر أحدهما ولم يتغيّر الآخر تغيّراً يُذكَر.

## الخلاصة

الصفة مفتاحٌ في قاموس، والبحث عنها يصعد من الكائن إلى صنفه إلى قواعده، والكتابة
تقع في الكائن فتحجب ما فوقه.

والقاموس ثمنُ المرونة، و`__slots__` مقايضةٌ صريحةٌ تدفع المرونة وتأخذ الذاكرة.

وبقي أن نسأل: لماذا وجدت `len(p)` طريقةً اسمها `__len__` ولم تجد `p.length`؟ من
كتب هذه القائمة، وما الذي فيها؟
