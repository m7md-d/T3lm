# الإقليم ٠٢ — الرِّباط

> تركتَ الإقليم السابق على ثقب: `select` بنت جدولاً جديداً، فتغيّر الأصل معه.
>
> هنا تُغلَق المسألة من جذرها: **ما الذي يحدث فعلاً حين تكتب `=`؟** والجواب يفسّر
> بعد ذلك الوسائط، والنطاق، والـclosure، ورسالةَ خطأٍ ستراها ولن تفهمها بلا هذا
> الإقليم.

## الاسم ليس خانة

في C يعني `long x;` أن هناك خانةً بثمانية بايتات اسمُها `x`، و`y = x` تنسخ
البايتات من خانةٍ إلى خانة. **الاسم في C وصفٌ لموضعٍ في الذاكرة.**

هنا الاسم **مفتاحٌ في قاموس**، وقيمتُه مؤشّرٌ إلى كائن. و`=` تكتب في القاموس، ولا
تمسّ الكائن.

فلا يوجد «نسخٌ بالقيمة» ولا «تمريرٌ بالمرجع». يوجد شيءٌ واحد: **ربطُ اسمٍ بكائن.**

<!-- part: 02-binding -->

```python
a = [1, 2]
b = a
print(f"بعد b = a      : a→{id(a):#x}  b→{id(b):#x}  {a} {b}")

b.append(3)
print(f"بعد b.append   : a→{id(a):#x}  b→{id(b):#x}  {a} {b}")

b = [9]
print(f"بعد b = [9]    : a→{id(a):#x}  b→{id(b):#x}  {a} {b}")
```

<!-- runs: 02-binding -->

```
بعد b = a      : a→0x10032d980  b→0x10032d980  [1, 2] [1, 2]
بعد b.append   : a→0x10032d980  b→0x10032d980  [1, 2, 3] [1, 2, 3]
بعد b = [9]    : a→0x10032d980  b→0x10035bc00  [1, 2, 3] [9]
```

(العناوين من تشغيلٍ واحد وتختلف عندك؛ **المهمّ تساويها واختلافها**، لا قيمتها.)

**والعنوان هو الدليل:** `a` و`b` يشيران إلى **العنوان نفسه** في السطرين
الأوّلين، ويفترقان في الثالث.

**والسطران الأخيران هما الفرق كلُّه:**

`b.append(3)` **تعديل**: تمسّ الكائن الذي يشير إليه الاسمان، فيراه الاثنان.

`b = [9]` **ربطٌ جديد**: تكتب في القاموس مؤشّراً إلى كائنٍ آخر. الكائن الأول لم
يُمسّ، و`a` ما زال عليه.

هذا هو المحور الذي تدور حوله بقيّة الإقليم: **`=` تربط، والطريقة تعدّل.**

## الوسيط

السؤال «هل Python تمرّر بالقيمة أم بالمرجع؟» سؤالٌ لا جواب له، لأنه مبنيٌّ على
تقسيمٍ لا وجود له هنا. الجواب الصحيح: **النداء يربط أسماء المعامِلات بالكائنات
الممرَّرة**، وهي القاعدة نفسها.

<!-- part: 02-argument -->

```python
def rebind(xs):
    xs = [9]
    return xs


def mutate(xs):
    xs.append(9)
    return xs
```

<!-- out -->

```
قبل           : [1]
rebind يعيد   : [9] والأصل: [1]
mutate يعيد   : [1, 9] والأصل: [1, 9]
```

`rebind` أعادت الربط داخل فضائها الاسميّ، فلم يخرج أثرُها منه. و`mutate` مسّت
الكائن نفسه، فخرج الأثر إلى كل اسمٍ مربوطٍ به.

**ولهذا `select` شاركت.** ما بنته كان قاموساً جديداً يربط الأسماء بالأعمدة القديمة
— ربطٌ جديد لكائناتٍ قديمة.

## أين يعيش الاسم

لكل دالّةٍ فضاءٌ اسميّ خاصّ يُنشَأ عند النداء ويموت بانتهائه. ولكل وحدةٍ فضاءٌ
عالميّ. والبحث عن اسمٍ يمرّ بها بترتيبٍ ثابت: المحلّي، فالمُحيط، فالعالميّ،
فالمدمَج.

<!-- part: 02-namespace -->

```python
def outer():
    x = "خارجيّ"

    def inner_reads():
        return x

    def inner_rebinds():
        x = "داخليّ"
        return x

    def inner_nonlocal():
        nonlocal x
        x = "غيّرتُ الخارجيّ"
```

<!-- out -->

```
خارجيّ | داخليّ | خارجيّ
بعد nonlocal: غيّرتُ الخارجيّ
العالميّ سليم: عالميّ
```

`inner_reads` **قرأت** من المحيط بلا إعلان. و`inner_rebinds` **ربطت** اسماً
محلّياً جديداً لم يمسّ الخارجيّ. و`nonlocal` وحدها هي التي جعلت الربط يقع في فضاء
`outer`.

**والقاعدة التي تخرج بها:** القراءة تصعد إلى الفضاءات المحيطة تلقائياً، والكتابة
لا تصعد أبداً إلا بإعلان — `nonlocal` إلى الفضاء المحيط، و`global` إلى فضاء
الوحدة. وكلمتان لا ثالثة لهما، لأن الفضاءات ثلاثةٌ لا أكثر.

## المحلّي يُحسَم بالنصّ، لا بالتشغيل

هنا حالةٌ تُنتج رسالةً يظنّها كثيرون خطأً في اللغة. **تنبّأ:** متغيّرٌ عالميّ
اسمه `count`، ودالّةٌ تفعل `count = count + 1`. ماذا يقع؟

<!-- part: 02-scope-error -->

```python
count = 0


def bump():
    count = count + 1


bump()
```

المخرَج:

<!-- err: UnboundLocalError -->

```
Traceback (most recent call last):
  File "programs/02-scope-error.py", line 8, in <module>
    bump()
    ~~~~^^
  File "programs/02-scope-error.py", line 5, in bump
    count = count + 1
            ^^^^^
UnboundLocalError: cannot access local variable 'count' where it is not associated with a value
```

لم يقل «العالميّ غير معرَّف»، وقال **«المحلّي لم يُربَط بعد»**. لأن وجود `count =`
في جسد الدالّة يجعل `count` **محلّياً في الدالّة كلِّها**، من أوّل سطرٍ فيها إلى
آخره. وهذا القرار يُتَّخذ عند تحويل الجسد إلى bytecode، لا عند التشغيل.

**وهذا هو الاستثناء الوحيد للبديهية الرابعة الذي تحتاج أن تعرفه**: النحو لا يحسم
الأنواع، لكنه يحسم **أيُّ الأسماء محلّيّ**. وسترى الفتحة التي كُتب فيها ذلك بعينك
في الإقليم `11`.

## الـclosure تلتقط الرباط لا القيمة

**تنبّأ:** ثلاثُ دوالٍّ تُبنى في حلقةٍ على `range(3)`، كلٌّ منها تعيد `i`. ماذا
تطبع حين تُنادى بعد الحلقة؟

<!-- part: 02-closure -->

```python
fs = [lambda: i for i in range(3)]
print([f() for f in fs])

gs = [lambda i=i: i for i in range(3)]
print([g() for g in gs])

print(fs[0].__closure__)
print(gs[0].__defaults__)
```

المخرَج:

<!-- out -->

```
[2, 2, 2]
[0, 1, 2]
(<cell at 0x…: int object at 0x…>,)
(0,)
```

الدوالُّ الثلاث الأولى تعيد `2` كلُّها. لأن ما التُقط ليس **قيمة** `i` وقت البناء،
بل **الخليّة** التي يسكنها الرباط. والحلقة تكتب في الخليّة نفسها ثلاث مرّات،
فالجميع يقرأ آخر ما كُتب.

والسطر الثالث يُظهر الآلية بلا تفسير: `__closure__` مجموعةٌ من `cell`، وفي كلٍّ
مؤشّرٌ إلى الكائن الحاليّ.

والحيلة في `gs` ليست إصلاحاً للـclosure — هي **تجنّبٌ لها**: الوسيط الافتراضيّ
يُقيَّم عند تعريف الدالّة (رأيتَها في الإقليم `00`)، فيُحفَظ العدد نفسه في
`__defaults__`.

## التمرين

`select` تشارك الأعمدة. **أضف إلى `Table` طريقةً `detach()` تعيد جدولاً لا يشارك
شيئاً مع الأصل** — بحيث يفشل الاختبار التالي إن بقيت المشاركة:

<!-- task -->

```python
t2 = t.select("v").detach()
t2["v"].values[0] = 999
assert t["v"][0] == 10
assert t2["v"] is not t["v"]
```

**والقيد:** لا تستعمل أي وحدةٍ من المكتبة القياسية. اكتبها بما تعرفه الآن.

**ومعيار القبول الحقيقيّ ليس نجاح الـ`assert`.** بعد أن تنجح، اسأل: ماذا لو كانت
القيم في العمود قوائم لا أعداداً؟ هل بقي جدولك منفصلاً؟ اكتب حالةً تُثبت جوابك.
وسترى في الإقليم التالي أن لهذا السؤال اسماً، وأن للغة جوابين لا واحداً.

## الخلاصة

`=` تربط اسماً بكائنٍ في قاموس، ولا تنسخ شيئاً. والتعديل يمسّ الكائن فيراه كلُّ
اسمٍ مربوطٍ به، والربطُ الجديد لا يمسّ أحداً. والنداءُ حالةٌ من الربط، لا نوعٌ
ثالث من التمرير.

وأُضيف إلى هذا: الكتابة لا تصعد إلى فضاءٍ محيطٍ إلا بإعلان، و**محلّيّةُ الاسم
تُحسَم من نصّ الدالّة** قبل أن يعمل شيء، والـclosure تحمل الخليّة لا القيمة.

وبقي سؤالٌ فتحه التمرين: ما الذي يجعل كائناً قابلاً للتعديل أصلاً، ولماذا لا
تحتاج الأعداد والنصوص إلى هذا الحذر كلِّه؟
