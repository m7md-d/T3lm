# ٢١ — الكلفة تُقاس

الحزمة كلُّها بُنيت على ادّعاء: إخراج الحلقة من المفسّر يربح. هذا الفصل يقيسه،
ويقيس أين يخسر.

---

## ثلاث طرقٍ لجمعِ عمود

**توقّع** قبل أن تقرأ: خمسةُ ملايين عدد. رتّب الثلاثة، وخمّن النسبة بين الأولى
والأخيرة.

<!-- part: 21-bench -->

```python
N = 5_000_000
py = list(range(N))
nd = np.arange(N, dtype=np.int64)


def loop():
    t = 0
    for v in py:
        t += v
    return t


base = timed("حلقةٌ في Python", loop)
b = timed("sum() المدمَجة", lambda: sum(py))
c = timed("nd.sum()", lambda: int(nd.sum()))
```

المخرَج:

<!-- runs: 21-bench -->

```
حلقةٌ في Python              101.75 ms   = 12499997500000
sum() المدمَجة                23.27 ms   = 12499997500000
nd.sum()                       0.66 ms   = 12499997500000

النسبة إلى الحلقة:  sum ×4.4   ·   numpy ×154.5
```

النتيجة واحدةٌ في الثلاث. والأرقام من جهازٍ واحد، والثابت هو النسبة.

**الحلقة ١٠١ ms:** ثلاثةُ عشرة تعليمةً في البايت-كود كما قاس الفصل `12`، خمسة
ملايين مرّة.

و`sum()` ×٤٫٤: حلقتُها بـC، لكنها ما زالت تفكّ كل كائنِ `int` وتنادي
`__add__` عليه. فربحت حلقةَ المفسّر وبقيت تدفع ثمن الكائنات.

و`nd.sum()` ×١٥٤٫٥: لا كائنات أصلاً. حلقةٌ بـC على ثمانية بايتاتٍ متجاورة،
ولا شيء يُبنى ولا يُحرَّر.

**المكسب:** الفرق بين ×٤٫٤ و×١٥٤٫٥ هو ثمن الكائنات، والفصل `02` قاسه بالبايت
والفصل `17` قاسه بالمرور. **والقفزة الكبرى تحتاج التخزين المتجاور ولغةَ الحلقة
معاً**، وكلٌّ منهما وحده يعطي ×٤ لا ×١٥٤.

**وكلُّ زمنٍ هنا من جهازٍ واحد.** والنسب ثابتةٌ في العادة، ونسبةُ `sum()` تتغيّر
بحجم الذاكرة المخبَّأة عندك — فأعِد القياس.

## أين تخسر

**مثال**

<!-- part: 21-loses -->

```python
small_py = [1, 2, 3, 4, 5]
small_nd = np.array(small_py)
timed("خمسُ قيم — sum() على list", lambda: sum(small_py))
timed("خمسُ قيم — nd.sum()", lambda: small_nd.sum())

big_nd = np.arange(100_000, dtype=np.int64)

def odd(v):
    return v * 2 if v % 2 else v

timed("مئةُ ألف — np.vectorize", lambda: np.vectorize(odd)(big_nd))
timed("مئةُ ألف — np.where", lambda: np.where(big_nd % 2, big_nd * 2, big_nd))
```

**المخرَج**

<!-- runs: 21-loses -->

```
خمسُ قيم — sum() على list           0.08 µs
خمسُ قيم — nd.sum()                 0.38 µs

مئةُ ألف — np.vectorize          7959.13 µs
مئةُ ألف — np.where               270.33 µs
```

**الحالة الأولى:** على خمس قيمٍ تخسر NumPy ×٤٫٨. كل نداءٍ يعبر حدَّ Python إلى C
ويعود، والعبور كلفةٌ ثابتةٌ لا تعتمد على الحجم. فتحت الأحجام الصغيرة يغلب العبورُ
العمل.

**والحالة الثانية أهمُّ:** `np.vectorize` أبطأ ×٢٩ من `np.where` على نفس البيانات
ونفس النتيجة. لأنها **حلقةٌ في Python بثوبِ NumPy**: تنادي `odd` مئةَ ألف مرّة،
فتبني كائناً لكل قيمةٍ وتفكّه.

**المكسب:** الربح ليس في استعمال NumPy. هو في **ألّا يُنادى كودُ Python لكل
عنصر**. و`np.vectorize` تكتب كأنها تُوجِّه العملية وهي تفعل العكس، فاسمُها هو
الفخّ.

## الحالات

### المرور الوسيط يُقاس قبل أن يُحسَّن

`(a + b) * c` تبني مصفوفةً وسيطةً وتمرّ على البيانات مرّتين. والاصطلاح المتداول
أن يُستعمَل `out=` لإعادة استعمال مخزنٍ واحد.

<!-- part: 21-passes -->

```python
N = 20_000_000
a = np.arange(N, dtype=np.float64)
b = np.arange(N, dtype=np.float64)
c = np.arange(N, dtype=np.float64)
out = np.empty(N)

timed("(a + b) * c — وسيطان", lambda: (a + b) * c)
timed("out= — بلا تخصيصٍ وسيط", lambda: np.multiply(np.add(a, b, out=out), c, out=out))
```

<!-- runs: 21-passes -->

```
(a + b) * c — وسيطان                  28.1 ms
out= — بلا تخصيصٍ وسيط                34.7 ms
```

**والنسخة «المحسَّنة» أبطأ** على هذا الجهاز بهذا الحجم. التخصيص الوسيط ليس
الكلفة الغالبة هنا، والكتابة في `out` نفسه في خطوتين تكسر ما يحسّنه المخزن
المؤقّت.

**والدرس في المنهج كلِّه:** الرقم قبل التحسين. و`total` في الجدول مثالُ العكس —
الفصل `18` قال إن الربح لم يأتِ بعد، والسبب أن `total` حلقةُ `for` في Python.
واستبدالها بـ`column.sum()` ينقل الجدول من ١٠١ ms إلى ٠٫٦٦، وهو سطرٌ واحد.
