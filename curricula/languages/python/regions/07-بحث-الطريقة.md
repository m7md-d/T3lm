# الإقليم ٠٧ — بحث الطريقة

> رأيتَ أن القراءة تصعد: الكائن، فالصنف، فقواعده. والسؤال الذي بقي: **وإن كانت
> القواعد أكثر من واحدة؟**
>
> وهنا تكتشف أن اللغة لا تخمّن. عندها خوارزميةٌ تُحسَب مرّةً، وترتيبٌ يُطبَع، ورفضٌ
> صريح إن كان الترتيب مستحيلاً.

## الترتيب يُحسَب ويُطبَع

**تنبّأ:** `A` فيها `who` تعيد `"A"`. و`B` ترث `A` بلا `who`. و`C` ترث `A` وفيها
`who` تعيد `"C"`. و`D` ترث `B` و`C`. ماذا تعيد `D().who()`؟

<!-- part: 07-mro -->

```python
class A:
    def who(self):
        return "A"


class B(A):
    pass


class C(A):
    def who(self):
        return "C"


class D(B, C):
    pass


print([c.__name__ for c in D.__mro__])
print(D().who())
```

المخرَج:

<!-- out -->

```
['D', 'B', 'C', 'A', 'object']
C
```

الحدس يقول `"A"`: أنت ورثتَ `B` أولاً، و`B` ترث `A`، فالصعود المباشر يمرّ بـ`A`.
**والجواب `"C"`.**

لأن البحث لا يصعد شجرةً؛ يمشي على **قائمةٍ خطّيّة** محسوبةٍ مسبقاً هي `__mro__`.
والقاعدة التي تبنيها: كلُّ صنفٍ يسبق قواعده، وترتيبُ القواعد المحلّيّ محفوظ. فجاء
`B` قبل `C`، و`C` قبل `A` — **لأن `A` قاعدةٌ لكلٍّ منهما فوجب أن تأتي بعدهما.**

وهذا يعطيك قاعدةً عملية: `A` **لا يمكن** أن تسبق `C` في أي ترتيبٍ صحيح، فلو
اعتمدتَ على «الأقرب أولاً» بمعناه الشجريّ لأخطأتَ كلَّ مرّة.

## والمستحيل يُرفَض

<!-- part: 07-mro-reject -->

```python
class A:
    pass


class B(A):
    pass


class Bad(A, B):
    pass
```

<!-- err: TypeError -->

```
Traceback (most recent call last):
  File "programs/07-mro-reject.py", line 9, in <module>
    class Bad(A, B):
        pass
TypeError: Cannot create a consistent method resolution order (MRO) for bases A, B
```

طلبتَ أن يسبق `A` الصنفَ `B`، و`B` يرث `A` فيجب أن يسبقه. مطلبان متناقضان، فلا
ترتيب.

**ولاحظ متى وقع الرفض:** عند **تعريف** الصنف، لا عند إنشاء كائنٍ منه ولا عند نداء
طريقة. وهذا هو نفس ما رأيتَه في الإقليم `00`: جسد الصنف يُنفَّذ، ونداءُ `type` يقع،
فيُفحَص هناك.

## الطريقة ليست دالّةً في الكائن

<!-- part: 07-bound -->

```python
class K:
    def m(self):
        return self


k = K()
print(K.m)
print(k.m)
print(k.m.__self__ is k)
print(K.m(k) is k.m())
```

<!-- out -->

```
<function K.m at 0x…>
<bound method K.m of <__main__.K object at 0x…>>
True
True
```

`K.m` **دالّةٌ عادية**. و`k.m` شيءٌ آخر: كائنٌ يحمل الدالّة والكائن معاً، ويسمّى
`bound method`. والسطر الأخير يُثبت أنهما طريقان لنفس النداء.

**ومن أين جاء هذا التحويل؟** لا شيء في `class` فعله. الدالّة نفسها تملك فتحة
`__get__`، فحين يُقرَأ اسمُها من كائنٍ تُنادى تلك الفتحة فتعيد الطريقةَ المربوطة.

وهذا يفسّر شيئاً كنتَ تحفظه: **لماذا `self` مكتوبٌ صراحةً.** لأنه وسيطٌ عاديّ،
والذي يمرّره هو `__get__` لا اللغة.

## الـdescriptor

كلُّ كائنٍ فيه `__get__` أو `__set__` يتحكّم بما يحدث حين تُقرَأ صفةٌ أو تُكتَب.
والدالّة واحدةٌ منها، و`property` غلافٌ عليها، ويمكنك أن تكتب واحداً:

<!-- part: 07-descriptor -->

```python
class Celsius:
    def __set_name__(self, owner, name):
        self.slot = "_" + name

    def __get__(self, obj, owner=None):
        if obj is None:
            return self
        return getattr(obj, self.slot)

    def __set__(self, obj, value):
        if value < -273.15:
            raise ValueError(f"تحت الصفر المطلق: {value}")
        setattr(obj, self.slot, value)


class Reading:
    t = Celsius()
```

<!-- err: ValueError -->

```
21.5 {'_t': 21.5}
Traceback (most recent call last):
  File "programs/07-descriptor.py", line 23, in <module>
    r.t = -300
    ^^^
  File "programs/07-descriptor.py", line 12, in __set__
    raise ValueError(f"تحت الصفر المطلق: {value}")
ValueError: تحت الصفر المطلق: -300
```

`r.t = 21.5` **لم تكتب `t` في قاموس الكائن** — كتبت `_t`. لأن الـdescriptor في
الصنف اعترض الكتابة قبل أن تقع.

**وهذا يكسر القاعدة التي بنيتَها في الإقليم `05`.** قلنا: الكتابة تقع في الكائن
دائماً. والدقيق: الكتابة تسأل الصنف أولاً هل فيه descriptor له `__set__` —
فإن كان، فهو الذي يقرّر. والقاعدة السابقة كانت **نموذجاً مبسّطاً**، وهذا وقت
ترقيته.

## التمرين

`Column` يحمل `values` قائمةً مكشوفة، فيستطيع أي كودٍ أن يستبدلها بشيءٍ أطول
فيكسر الجدول كلَّه.

**اكتب descriptor يمنع استبدال `values` بما يخالف طولها الحاليّ**، ويسمح بالتعديل
في مكانه.

**والقيد:** لا تستعمل `property`. اكتب الفتحات بيدك — فالغرض أن ترى أن `property`
ليست ميزةً في اللغة بل صنفٌ يفعل ما فعلتَه.

**ثم:** كم موضعاً في `Table` بقي يستطيع كسرَ الشرط رغم descriptor؟ عدّها.

## الخلاصة

البحث عن الطريقة يمشي على قائمةٍ خطّيّةٍ محسوبةٍ عند تعريف الصنف، لا على شجرةٍ
وقت النداء. والقائمة تُطبَع فتُقرَأ، والمستحيل منها يُرفَض في موضع التعريف.

والطريقة ليست شيئاً خاصّاً: دالّةٌ فيها `__get__` تعيد نفسها مربوطةً بالكائن.
ومنها يُشتقّ `self`، و`property`، وكلُّ ما يبدو سحراً في الوصول إلى الصفات.

وبقي أن نأخذ الدالّة نفسها على محمل الجدّ: **إن كانت كائناً، فما الذي يمكن فعله بها
مما لا يمكن في C؟**
