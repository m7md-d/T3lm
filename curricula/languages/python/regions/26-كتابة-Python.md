> فيها، ولماذا صارت الاصطلاحات كما هي.
>
> ولن تجد هنا «أفضل ممارسة» بلا سبب ميكانيكيّ. كلُّ اصطلاحٍ هنا يُردّ إلى بديهيةٍ
> أو إلى شيءٍ قِسته.

## لا خصوصية — وما يوجد بدلها

<!-- part: 26-privacy -->

```python
class Column:
    def __init__(self):
        self._internal = 1
        self.__mangled = 2


c = Column()
print("لا خصوصية:", c._internal)
print("الصفات:", [k for k in vars(c)])
print("المشوّه يُقرَأ باسمه الحقيقيّ:", c._Column__mangled)
```

<!-- out -->

```
لا خصوصية: 1
الصفات: ['_internal', '_Column__mangled']
المشوّه يُقرَأ باسمه الحقيقيّ: 2
الوراثة لا تصطدم: ['_Column__mangled', '_Sub__mangled', '_internal']
```

الصفة مفتاحٌ في قاموس (الإقليم `05`)، ولا يوجد ما يمنع قراءته. **فالخصوصية هنا
اتّفاقٌ لا آلية.**

و`_name` بشرطةٍ واحدة **اصطلاحٌ خالص**: يقول «هذا ليس من الواجهة»، ولا يفعل شيئاً.

و`__name` بشرطتين **آليةٌ حقيقية لكن غرضها ليس الخصوصية**: المترجم يعيد تسميتها
إلى `_ClassName__name`. والسطر الأخير يريك الغرض — الصنف المشتقّ عرّف الاسم نفسه
فلم يصطدما. **فهي حمايةٌ من التصادم في الوراثة، لا من القارئ.**

**والاصطلاح المشتقّ:** استعمل `_` لتقول «داخليّ»، ولا تستعمل `__` إلا حين تكتب
صنفاً يُورَث فعلاً وتخشى التصادم. واستعمالها للخصوصية يكسر الوراثة ولا يمنع أحداً.

## `finally` — والفخّ الذي تحذّر منه اللغة نفسها

<!-- part: 26-finally -->

```python
def swallows():
    try:
        return "من try"
    finally:
        return "من finally"


def hides_exception():
    try:
        raise ValueError("ضاع")
    finally:
        return "لا أحد يعلم"
```

<!-- out -->

```
من finally
لا أحد يعلم
  نُظِّف
من try
programs/26-finally.py:5: SyntaxWarning: 'return' in a 'finally' block
  return "من finally"
programs/26-finally.py:12: SyntaxWarning: 'return' in a 'finally' block
  return "لا أحد يعلم"
```

(الفاحص يضع المخرَج القياسيّ ثم تحذيرات الترجمة؛ عندك تظهر التحذيرات أوّلاً.)

`finally` تعمل دائماً — بعد `return`، وأثناء صعود استثناء. **فإن كان فيها `return`
فهي تكتب فوق كليهما**: الدالّة الثانية رفعت `ValueError` **وأعادت نصّاً**، فضاع
الخطأ بلا أثر.

**واللغة نفسها تحذّر:** `SyntaxWarning` في الترجمة. وهذا نادر — أن يحذّر المترجم
من نمطٍ صحيحٍ نحوياً — ويقيس لك خطورته.

**فالقاعدة:** `finally` للتنظيف وحده. وما فيها لا يعيد ولا يرفع.

## `match` — مطابقةٌ على البنية

<!-- part: 26-match -->

```python
def describe(spec):
    match spec:
        case {"name": str(name), "dtype": "int64"}:
            return f"عمودٌ صحيح اسمه {name}"
        case {"name": str(name), "dtype": dt}:
            return f"عمودٌ {dt} اسمه {name}"
        case [first, *rest]:
            return f"قائمةٌ أوّلها {first} وبقيّتها {len(rest)}"
        case str() as s:
            return f"نصّ: {s}"
        case _:
            return "لا أعرف"
```

<!-- out -->

```
عمودٌ صحيح اسمه v
عمودٌ float64 اسمه t
قائمةٌ أوّلها 1 وبقيّتها 2
نصّ: خام
لا أعرف
```

**ليست `switch`.** `switch` تقارن قيمةً بقيم. و`match` تفكّك **بنية**: شكلُ
القاموس، وطولُ القائمة، ونوعُ العنصر — وتربط الأسماء أثناء المطابقة.

ولاحظ `str(name)`: ليست نداءً. في سياق `case` هي **نمط**: «إن كان نصّاً، فسمِّه
`name`». والقراءة الخاطئة لهذا السطر أشيع أخطاء من يبدأ بها.

**ومتى تستحقّ؟** حين تكون البيانات **شكلاً متفرّعاً** — استجابةٌ من واجهة، أو
وصفٌ مقروءٌ من ملفّ. وحين يكون التفريع على قيمةٍ واحدة، فـ`if`/`elif` أوضح
و`dict` أسرع.

## `:=` — الربط داخل التعبير

<!-- part: 26-walrus -->

```python
for v in values:
    if (half := v // 2) > 0:
        total += half
print("المجموع:", total, "| آخر half:", half)
```

<!-- out -->

```
المجموع: 6 | آخر half: 2
```

`:=` تربط اسماً **داخل تعبير**، فتحسب مرّةً وتستعمل مرّتين. والاسم يبقى في الفضاء
المحيط بعد الجملة — كما يقول السطر الأخير.

**وهي إعادةُ ربطٍ عاديّة** (البديهية الثانية) بموضعٍ نحويٍّ جديد لا أكثر. وقيمتها
الحقيقية في الحلقة التي تقرأ حتى ينتهي شيء، وفي الشرط الذي يستعمل ما فحصه.

**وحدُّها:** إن احتجتَ قوسين لتوضيحها فقد تجاوزتَ موضعها.

## الاختبار كما تقدّمه اللغة

`assert` جملةٌ في اللغة، **وتُحذَف كلُّها** حين يُشغَّل المفسّر بـ`-O`. فهي أداةُ
تطويرٍ وفحص، **ولا يُبنى عليها تحقّقٌ يحمي مستعملاً** — ذاك يكون `if` و`raise`.

وفي الحزم الخمس كتبتَ ثمانية تمارينَ لها معايير قبول. **وأصدق اختبارٍ في هذا
المنهج نمطٌ رأيتَه في الإقليم `23`:** مرجعٌ بطيءٌ مكتوبٌ بأبسط ما يمكن، ونسخةٌ
سريعة، ومقارنةٌ بينهما على بياناتٍ صغيرة. البطيء لا يُنشَر، لكنه الشيء الوحيد الذي
يكشف خطأً في حلقةٍ مُشعَّبة.

## والـepitome باصطلاح اللغة

عندك الآن نسختان من الجدول: الأولى في الإقليم `01` والثانية في `21`. **وأعد كتابته
مرّةً ثالثة** بما تعرفه: `__slots__` حيث تكثر الكائنات، وبروتوكولاتٌ بدل طرقٍ
مسمّاة، ومولّدٌ حيث تكون العناصر مؤقّتة، وغلافٌ يفحص كلَّ ما لا تفحصه C.

**والفرق بين النسخ الثلاث هو الدرس** — لا الثالثة وحدها.

## التمرين

**اقرأ `array` في المكتبة القياسية** — الوحدة نفسها التي جرّبتها في الإقليم `16`.

**والقيد:** أجب عن ثلاثة أسئلةٍ بموضعٍ من الكود لا برأي: أين يُبنى كائن العدد عند
كل قراءة؟ وكيف تصف الوحدة نفسها للبروتوكول العازل؟ ولماذا لا توجد فيها عملياتٌ
حسابية؟

**والسؤال الثالث هو المهمّ**، وجوابه يفسّر لماذا وُجدت NumPy خارج المكتبة القياسية.

## الخلاصة

لا خصوصية في اللغة؛ `_` اصطلاح، و`__` حمايةٌ من التصادم في الوراثة.

و`finally` للتنظيف وحده. و`match` تفكّك بنيةً لا تقارن قيمة. و`:=` ربطٌ في موضعٍ
نحويٍّ جديد. و`assert` تُحذَف تحت `-O` فلا يُبنى عليها أمان.

وبقي أن يُجمَع كلُّ هذا في شيءٍ واحد يعمل.
