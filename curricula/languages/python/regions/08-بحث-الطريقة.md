# ٠٨ — بحث الطريقة

الفصل السابق قال إن بحث السمة يصعد من النسخة إلى الصنف ثم إلى أصوله. وحين يكون
للصنف أكثر من أصلٍ واحد، «ثم إلى أصوله» تحتاج ترتيباً.

---

## الترتيب قائمةٌ محسوبةٌ مرّةً واحدة

لكل صنفٍ **قائمةُ ترتيب البحث** (method resolution order) محفوظةٌ في `__mro__`.
يحسبها المفسّر عند إنشاء الصنف، ويمرّ عليها بالترتيب حتى يجد الاسم.

**مثال**

<!-- part: 08-mro -->

```python
class Source:
    def describe(self):
        return "source"


class Timed(Source):
    def describe(self):
        return "timed → " + super().describe()


class Cached(Source):
    def describe(self):
        return "cached → " + super().describe()


class Feed(Timed, Cached):
    pass


print(Feed().describe())
print([c.__name__ for c in Feed.__mro__])
```

**المخرَج**

<!-- out -->

```
timed → cached → source
['Feed', 'Timed', 'Cached', 'Source', 'object']
```

`Timed.describe` تنادي `super().describe()`، وأعطت `cached` لا `source`.

**و`super()` لا تعني «الأصل»**، بل «التالي في قائمة الصنف الذي نُودِي». و`Timed`
هنا نُودِيت من نسخة `Feed`، والتالي بعدها في قائمة `Feed` هو `Cached`.

**المكسب:** هذا هو سبب اصطلاحين تراهما في كل كود Python يستعمل الوراثة المتعدّدة:
أن تنادي كلُّ طريقةٍ `super()` ولو ظنّت نفسها الأخيرة، وأن تتّفق التوقيعات — لأن
من يأتي بعدها ليس معروفاً عند كتابتها.

---

## كيف تُحسَب القائمة

القاعدة ثلاثة شروط، والمفسّر يحلّها معاً:

1. الصنف قبل أصوله.
2. الأصول بترتيب كتابتها في `class C(A, B)`.
3. ما يُذكَر لاحقاً يأتي لاحقاً في كل القوائم — فلا يتقدّم أصلٌ على فرعه.

ولو لم تُحلّ الشروط معاً، يرفض المفسّر إنشاء الصنف.

**مثال**

<!-- part: 08-conflict -->

```python
class A:
    pass


class B(A):
    pass


class Bad(A, B):
    pass
```

**المخرَج**

<!-- err: TypeError -->

```
TypeError: Cannot create a consistent method resolution order (MRO) for bases A, B
```

`class Bad(A, B)` يطلب `A` قبل `B`، و`B` يرث `A` فيطلب `B` قبل `A`. لا ترتيب
يحقّق الاثنين.

**والرفض عند تعريف الصنف لا عند النداء** — وهذه واحدة من المرّات القليلة التي
يمسك فيها Python خطأً بنيوياً قبل أن يُستعمَل الشيء.

## الحالات

### `object` في آخر القائمة، و`None` فيه يحجب

`object` أصلُ كل شيء، وفيه `__str__` و`__eq__` و`__hash__` الافتراضية. ولهذا
`print(obj)` تعمل على أي كائنٍ ولو لم تعرّف شيئاً.

وهذا يفسّر ما رأيتَه في الفصل `04`: تعريف `__eq__` وحده يمنع التجزئة.

<!-- part: 08-hash -->

```python
class Plain:
    pass


class Eq:
    def __init__(self, name):
        self.name = name

    def __eq__(self, other):
        return self.name == other.name


print("Plain :", Plain.__hash__ is object.__hash__)
print("Eq    :", Eq.__hash__)
```

<!-- err: TypeError -->

```
Plain : True
Eq    : None
TypeError: cannot use 'Eq' as a dict key (unhashable type: 'Eq')
```

`Plain.__hash__` هو `object.__hash__` نفسه — وجده البحث في آخر القائمة. و`Eq`
حصل على `__hash__ = None` في قاموسه، فأوقف البحث قبل أن يصل إلى `object`.

والقاعدة: الحجب في MRO لا يحتاج طريقةً بديلة. `None` في الموضع يكفي.

**وحين تشكّ في أي طريقةٍ تُنادى:** اطبع `type(x).__mro__` واقرأها من اليسار. أوّل
صنفٍ فيها يعرّف الاسم هو الذي يُنادى.

## تمرين

اكتب صنفين `Logged` و`Cached` يورَثان معاً بأي ترتيب، وكلٌّ منهما يلفّ
`describe`. الشرط أن يعمل الترتيبان `(Logged, Cached)` و`(Cached, Logged)` بلا
تعديل، وأن يظهر أثرُ الاثنين في المخرَج.

ثم اطبع `__mro__` للترتيبين وقل أيَّ سطرٍ في كودك جعل هذا ممكناً.
