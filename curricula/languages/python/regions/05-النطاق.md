# ٠٥ — النطاق والرباط

الفصل `01` قال إن `=` تضع مدخلاً في جدول أسماء. هنا تعرف أي جدول، وكيف يختار
المفسّر بينها.

---

## أربعة جداول

حين يقابل المفسّر اسماً، يبحث عنه بهذا الترتيب:

| المرتبة | الجدول | مثاله |
|---|---|---|
| ١ | المحلّيّ (local) | أسماء الدالّة الجارية |
| ٢ | المحيط (enclosing) | أسماء دالّةٍ تحيط بها |
| ٣ | العالميّ (global) | أسماء الوحدة |
| ٤ | المدمج (builtins) | `print` · `len` · `int` |

والاختصار المتداول لهذا الترتيب: LEGB.

**مثال**

<!-- part: 05-scope -->

```python
rate = 10


def show():
    print("داخل الدالّة:", rate)


def shadow():
    rate = 99
    print("محلّيّ:", rate)


show()
shadow()
print("عالميّ بعدهما:", rate)
```

**المخرَج**

<!-- out -->

```
داخل الدالّة: 10
محلّيّ: 99
عالميّ بعدهما: 10
```

`show` وجدت `rate` في الجدول العالميّ. و`shadow` أنشأت اسماً محلّياً بالاسم نفسه،
فحجب العالميّ داخلها ولم يمسّه.

---

## القراءة والكتابة ليستا متماثلتين

القراءة تصعد السلّم. **والكتابة تنشئ محلّياً** ما لم تُعلن غير ذلك بـ`global` أو
`nonlocal`.

وهذا يُحسم عند الترجمة لا عند التشغيل: المفسّر يفحص جسم الدالّة، فإن وجد إسناداً
لاسمٍ عدّه محلّياً في الدالّة كلِّها.

**توقّع** قبل أن تقرأ.

<!-- part: 05-unbound -->

```python
rate = 10


def bump():
    print(rate)
    rate = rate + 1


bump()
```

المخرَج:

<!-- err: UnboundLocalError -->

```
UnboundLocalError: cannot access local variable 'rate' where it is not associated with a value
```

`print(rate)` يسبق الإسناد، ومع ذلك فشل. السبب أن السطر الثاني جعل `rate` محلّياً
في الدالّة كلِّها، فالقراءة في السطر الأول تسأل عن اسمٍ محلّيٍّ لم يُربط بعد.

**المكسب:** الرسالة تقول «محلّيّ» وأنت تظنّه عالمياً. هذا أشيع سبباً لهذا الخطأ،
وعلاجه `global rate` إن أردتَ الكتابة في العالميّ، أو اسمٌ آخر إن لم ترد.

## الإغلاق

الدالّة الداخلية تحتفظ بإشارةٍ إلى أسماء الدالّة المحيطة بعد أن تنتهي تلك.

**مثال**

<!-- part: 05-closure -->

```python
def counter():
    n = 0

    def step():
        nonlocal n
        n += 1
        return n

    return step


c1 = counter()
c2 = counter()
print(c1(), c1(), c1())
print(c2())
print(c1.__closure__[0].cell_contents)
```

**المخرَج**

<!-- out -->

```
1 2 3
1
3
```

كل نداءٍ لـ`counter` ينشئ خليّةً (cell) مستقلّة، فـ`c1` و`c2` لا يتشاركان `n`.
والسطر الأخير يفتح الخليّة ويقرأ ما فيها.

`nonlocal` تقول: الكتابة على `n` تخصّ الجدول المحيط لا المحلّيّ.

## الحالات

### القيمة الافتراضية تُقيَّم مرّةً واحدة

**توقّع** قبل أن تقرأ.

<!-- part: 05-default -->

```python
def add(value, into=[]):
    into.append(value)
    return into


print(add(1))
print(add(2))
print(add(3, []))
print(add.__defaults__)
```

المخرَج:

<!-- out -->

```
[1]
[1, 2]
[3]
([1, 2],)
```

القائمة الافتراضية تُنشَأ حين تُنفَّذ جملة `def`، وتُخزَّن في `add.__defaults__`.
كل نداءٍ بلا وسيطٍ يربط `into` بالكائن نفسه.

**وهذا يتّبع القاعدة التي بنيتَها:** جسم الدالّة يُنفَّذ عند النداء، وسطر `def`
يُنفَّذ مرّةً عند التعريف. والقيمة الافتراضية على سطر `def`.

والاصطلاح: `into=None` ثم `if into is None: into = []` داخل الجسم.

### جسم الصنف نطاقٌ لا تراه طرقُه

جسم الصنف يُنفَّذ في نطاقٍ خاصّ، والسطور التي فيه ترى أسماءه. أمّا الدوالّ
المعرَّفة داخله فلا: بحثها يقفز من المحلّيّ إلى العالميّ مباشرةً.

**مثال**

<!-- part: 05-classbody -->

```python
LIMIT = 5


class Report:
    LIMIT = 99
    doubled = LIMIT * 2

    def show(self):
        return LIMIT


print(Report.doubled)
print(Report().show())
```

**المخرَج**

<!-- out -->

```
198
5
```

`doubled` سطرٌ في جسم الصنف، فرأى `LIMIT = 99` وأعطى ١٩٨. و`show` دالّة، فقفز
بحثُها فوق جسم الصنف إلى الوحدة وأعطى ٥.

**المكسب:** الوصول إلى سمة الصنف من داخل طريقةٍ يكون بـ`self.LIMIT` أو
`Report.LIMIT`. والفصل `07` يقول ما الذي يفعله `self` بالضبط.

## تمرين

`add(value, into=[])` تتراكم عبر النداءات. أصلحها بثلاث طرق مختلفة:

1. بـ`None` حارساً.
2. بلا تغيير التوقيعة ولا استعمال `None`.
3. بمصنعٍ يُنادى عند كل نداء.

ثم اطبع `add.__defaults__` في الثلاث، وقل أيُّها يبقي التوقيعة مقروءةً لمن يفتح
`help(add)`.
