# ١٧ — حدود `list`

الفصل `02` قاس قائمةَ ألفِ عددٍ فوجدها مصفوفةَ إشاراتٍ لا مصفوفةَ أعداد. هذا
الفصل يقيس ثمن ذلك، ويحدّد أين يقع الثمن بالضبط.

---

## الحاوية والقيم

**مثال**

<!-- part: 17-scatter -->

```python
N = 1_000_000

lst = list(range(N))
arr = array.array("q", range(N))

print("list        :", sys.getsizeof(lst), "بايتاً للحاوية")
print("array('q')  :", sys.getsizeof(arr), "بايتاً، والقيم داخلها")
print("العدد الواحد:", sys.getsizeof(lst[500]), "بايتاً، ×", N, "خارج الحاوية")


def walk(seq):
    t = 0
    for v in seq:
        t += v
    return t
```

**المخرَج**

<!-- runs: 17-scatter -->

```
list        : 8000056 بايتاً للحاوية
array('q')  : 8183816 بايتاً، والقيم داخلها
العدد الواحد: 28 بايتاً، × 1000000 خارج الحاوية
مرورٌ على list  :   21.4 ms
مرورٌ على array :   26.4 ms
```

**السطور الثلاثة الأولى:** الحاويتان بحجمٍ متقارب. والفرق أن `array` تحمل القيم،
و`list` تحمل مليونَ إشارةٍ إلى مليون كائنٍ بـ٢٨ بايتاً لكلٍّ — نحو ٢٨ ميغابايت
زائدة.

**والسطران الأخيران يخالفان الحدس:** المرور على `array` أبطأ.

---

## أين يقع الثمن

`array` تحمل ثمانية بايتاتٍ خامّة لكل قيمة. وحين تكتب `for v in arr` يجب أن يصير
`v` كائنَ `int` كي يعمل معه `+=`. فكل دورةٍ تبني كائناً وتحرّره.

و`list` لا تبني: الكائنات موجودةٌ سلفاً، والحلقة تنسخ إشارة.

**فالتخزين المتجاور وحده لا يربح شيئاً** إن بقيت الحلقة في Python. الربح يحتاج
أن يخرج المرور نفسه من المفسّر إلى كودٍ مترجَم يعمل على البايتات الخامّة.

**المكسب:** هذا هو تعريف NumPy: تخزينٌ متجاور مع عملياتٍ مكتوبةٍ بـC تمرّ
عليه بلا أن تبني كائناً واحداً.

**و`sum(lst)` المدمَجة تربح بلا NumPy** لأن حلقتَها بـC، وتبقى تفكّ كل كائنٍ
لتجمعه. والفصل `21` يقيس الثلاثة معاً.

**و`array.array` تبقى مفيدةً في موضعين:** حين تكتب البايتات إلى ملفٍّ أو مقبس،
وحين تمرّرها إلى دالّة C — وذلك موضوع الفصلين `22` و`23`.

## الحالات

### القائمة تكبر بالنسبة

`list.append` تحجز أكثر ممّا تحتاج، فتصير الإضافة رخيصةً في المتوسط.

<!-- part: 17-growth -->

```python
lst = []
last = sys.getsizeof(lst)

for i in range(1, 130):
    lst.append(i)
    now = sys.getsizeof(lst)
    if now != last:
        print(f"{len(lst):>7}  {now:>8}  +{now - last}")
        last = now
```

<!-- out -->

```

     65       664  +96

```

الزيادة تكبر مع الطول: ٣٢ في البداية، ثم ٦٤، ثم ٩٦، ثم ١٦٠. فعددُ إعادات
التخصيص لمليون إضافةٍ نحو أربعين، والإضافةُ الواحدة رخيصةٌ في المتوسط.

**وهذا يفسّر الرقم `8000056` أعلاه:** لا فضل فيه، لأن `list(range(N))` يعرف الطول
سلفاً فيحجز مضبوطاً — ثمانيةُ ملايين للإشارات، وستٌّ وخمسون للترويسة.
