# ٠٦ — البروتوكولات

الفصل `01` كتب في الجدول طريقتين باسمين محجوزين: `__len__` و`__getitem__`. هنا
تعرف من ينادي هذين الاسمين ومتى.

---

## المعامل يسأل الكائن

المعامل في Python ليس له معنًى واحدٌ ثابت. `*` بين عددين ضرب، وبين نصٍّ وعددٍ
تكرار. والمفسّر لا يسأل «ما معنى `*`» بل «كيف يستجيب هذا الكائن لـ`*`».

والبروتوكول مجموعةُ طرقٍ باسمٍ محجوز يبحث عنها المفسّر حين ينفّذ عملية. الكائن
يتبع البروتوكول إن عرّفها، ولو لم يورَث من أي صنفٍ بعينه.

**مثال**

<!-- part: 06-protocol -->

```python
print(5 * 3)
print("hi" * 3)
print([1, 2] * 2)

print(len("Python"))
print(len(10))
```

**المخرَج**

<!-- err: TypeError -->

```
15
hihihi
[1, 2, 1, 2]
6
TypeError: object of type 'int' has no len()
```

`int` لا يعرّف `__len__`، فرسالة الخطأ تقول ذلك بلفظه: `has no len()`.

---

## الأسماء وما ينادي كلاً منها

| ما تكتبه | ما يُنادى |
|---|---|
| `a + b` | `type(a).__add__` |
| `a * b` | `type(a).__mul__` |
| `len(a)` | `type(a).__len__` |
| `a[k]` | `type(a).__getitem__` |
| `k in a` | `type(a).__contains__`، أو `__iter__` بحثاً |
| `for x in a` | `type(a).__iter__` |
| `a()` | `type(a).__call__` |
| `bool(a)` | `type(a).__bool__`، أو `__len__` |
| `print(a)` | `type(a).__str__` |

**والعمود الثاني يقول شيئاً يُغفَل:** البحث على النوع لا على الكائن.

---

## البحث على النوع، لا على الكائن

**توقّع** قبل أن تقرأ: ماذا يطبع السطر الأخير؟

<!-- part: 06-lookup -->

```python
class Quiet:
    def __len__(self):
        return 0


q = Quiet()
print(bool(q), len(q))

q.__len__ = lambda: 99
print(len(q))
print(q.__len__())
```

المخرَج:

<!-- out -->

```
False 0
0
99
```

`bool(q)` أعطى `False` لأن `Quiet` لا يعرّف `__bool__`، فسقط المفسّر إلى `__len__`
ووجدها صفراً.

**والسطران الأخيران هما الدرس:** `q.__len__` صار موجوداً على الكائن ويعطي ٩٩ عند
النداء المباشر، و`len(q)` ما زال صفراً. لأن `len` تسأل `type(q)` ولا تسأل `q`.

**المكسب:** الأسماء المحجوزة تُعرَّف في الصنف. تركيبُها على النسخة لا يغيّر سلوك
المعاملات، وهذا يفسّر لماذا لا يُرقَّع كائنٌ واحدٌ بسلوكٍ خاصّ بهذه الطريقة.

---

## الجدول يصير قابلاً للمرور

الجدول اليوم يستجيب لـ`len` و`[]`. وطريقتان تجعلانه يستجيب لـ`for` و`in`.

**مثال**

<!-- part: 06-iter -->

```python
class Rows(Table):
    def __iter__(self):
        names = list(self.columns)
        for i in range(len(self)):
            yield {name: self.columns[name][i] for name in names}

    def __contains__(self, name):
        return name in self.columns
```

**المخرَج**

<!-- out -->

```
{'city': 'Riyadh', 'sales': 120}
{'city': 'Jeddah', 'sales': 340}
True False
```

`__iter__` تعطي صفّاً صفّاً بدل أن تبني قائمةً بالصفوف كلِّها. الفصل `10` يشرح
`yield`.

**و`__contains__` قرارٌ في المعنى لا في الميكانيزم:** `"sales" in t` تسأل عن
اسم عمود، وكان يمكن أن تسأل عن قيمةٍ في عمود. الاثنان صحيحان، والذي يختار
كاتبُ الصنف.

**المكسب:** أربع طرقٍ محجوزة جعلت الجدول يعمل مع `len` و`[]` و`for` و`in` — وهي
الأدوات التي تعمل مع كل حاويةٍ مدمَجة. هذا ما يشتريه اتّباع البروتوكول.

## الحالات

### الجدول الفارغ ينهار

**توقّع** قبل أن تقرأ.

<!-- part: 06-empty -->

```python
from table import Table

t = Table({})
print(len(t))
```

المخرَج:

<!-- err: StopIteration -->

```
StopIteration
```

`__len__` تكتب `next(iter(self.columns.values()))` لتأخذ أوّل عمود. وبلا أعمدة
يرفع `next` استثناء `StopIteration`، وهو استثناءُ نهاية التكرار لا استثناءُ
خطأ.

والرسالة بلا نصّ، فلا تدلّ على شيء. وهذا العيب الثاني من عيوب الجدول الثلاثة التي
تركها الفصل `01`، وإصلاحه سطرٌ في `__len__`: `if not self.columns: return 0`.

**والقائمة الفارغة والقاموس الفارغ لا يفعلان هذا:** يعرّفان `__len__` فيصيران
`False` ولا يرفعان شيئاً، كما رأيتَ في المثال السابق. أمّا الجدول فيرفع قبل أن يُسأل.

**و`StopIteration` داخل مولّدٍ يُبلَّغ عن نفسه بشكلٍ آخر**، وذلك في الفصل `10`.

### `match` بروتوكولٌ آخر

`match` تسأل الكائن كما يسأله المعامل. والصنف يقول ما يُطابَق منه في
`__match_args__`.

<!-- part: 06-match -->

```python
class Row:
    __match_args__ = ("city", "sales")

    def __init__(self, city, sales):
        self.city = city
        self.sales = sales


def describe(value):
    match value:
        case Row("Riyadh", sales) if sales > 100:
            return f"الرياض، وبيعٌ كبير: {sales}"
        case Row(city, _):
            return f"مدينةٌ أخرى: {city}"
        case {"sales": sales}:
            return f"قاموسٌ فيه sales={sales}"
        case [first, *rest]:
            return f"تسلسلٌ أوّلُه {first} وبعده {len(rest)}"
        case _:
            return "لا شيء يطابق"
```

<!-- out -->

```
الرياض، وبيعٌ كبير: 340
مدينةٌ أخرى: Jeddah
قاموسٌ فيه sales=5
تسلسلٌ أوّلُه 1 وبعده 2
لا شيء يطابق
('city', 'sales')
```

`Row("Riyadh", sales)` تطابق **بالموضع**: أوّلُ عنصرٍ في `__match_args__` هو
`city`، والثاني `sales`. وبلا `__match_args__` يرفض المفسّر المطابقة بالموضع.

**والحالتان الثالثة والرابعة تطابقان القاموس والتسلسل** بلا تصريحٍ منك، لأن
`dict` و`list` يعلنان بروتوكوليهما.

**و`match` و`case` كلمتان طريّتان** (soft keywords): تصلحان أسماء متغيّراتٍ في
كل موضعٍ آخر، لأن المحلّل يعرفهما من موضعهما لا من نصّهما.
