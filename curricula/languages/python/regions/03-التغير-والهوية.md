# ٠٣ — التغيّر والهوية

الفصل `01` ترك عيباً في `select`: الجدول المشتقّ يشارك أعمدة الأصل. هنا تعرف
سببه وتصلحه.

---

## نوعان من الكائنات

الكائن إمّا يقبل التعديل بعد إنشائه أو لا يقبله.

| يقبل التعديل | يمنعه |
|---|---|
| `list` · `dict` · `set` · معظم الأصناف التي تكتبها | `int` · `float` · `str` · `tuple` · `frozenset` |

والفرق يُرى في العنوان.

**مثال**

<!-- part: 03-mutable -->

```python
values = [1, 2]
print(f"list  قبل: {id(values):#x}")
values.append(3)
print(f"list  بعد: {id(values):#x}  {values}")

text = "ab"
print(f"str   قبل: {id(text):#x}")
text += "c"
print(f"str   بعد: {id(text):#x}  {text}")
```

**المخرَج**

<!-- runs: 03-mutable -->

```
list  قبل: 0x1005c1980
list  بعد: 0x1005c1980  [1, 2, 3]
str   قبل: 0x100680e10
str   بعد: 0x100681230  abc
```

العناوين تختلف عندك. المهمّ أن عنوان القائمة لم يتغيّر بعد `append`، وأن
عنوان النصّ تغيّر بعد `+=`.

`text += "c"` تبني نصّاً جديداً وتربط الاسم به. الكائن الأول باقٍ حتى يبلغ
عدّاده صفراً.

**المكسب:** بناء نصٍّ داخل حلقةٍ بـ`+=` ينشئ كائناً في كل دورة. البديل هو
`"".join(parts)`، وتقيس الفرق في الفصل `21`.

## متى `is` ومتى `==`

`is` يقارن العنوان. `==` ينادي `__eq__` على الكائن، فيقارن القيمة كما يعرّفها
نوعُه.

**مثال**

<!-- part: 03-eq-is -->

```python
a = [1, 2]
b = list(a)

print("a == b:", a == b, "  a is b:", a is b)

none = None
print("none is None:", none is None)
```

**المخرَج**

<!-- out -->

```
a == b: True   a is b: False
none is None: True
```

`list(a)` بنت قائمةً جديدةً بنفس العناصر: متساويةٌ في القيمة ومختلفةٌ في العنوان.

القاعدة العملية: `==` لكل مقارنة، و`is` لـ`None` وحدها — لأن `None` كائنٌ
واحدٌ في المفسّر كلِّه، فمقارنة العنوان تكفي وتصحّ.

## إصلاح `select`

`select` تبني قاموساً جديداً وتضع فيه الكائنات نفسها. القاموس نُسخ، والقوائم
لا. هذا هو النسخ السطحيّ.

**مثال**

<!-- part: 03-copy -->

```python
import copy

grid = [[0, 0], [0, 0]]

shallow = copy.copy(grid)
deep = copy.deepcopy(grid)

grid[0].append(9)

print("الأصل   :", grid)
print("السطحيّ :", shallow)
print("العميق  :", deep)
```

**المخرَج**

<!-- out -->

```
الأصل   : [[0, 0, 9], [0, 0]]
السطحيّ : [[0, 0, 9], [0, 0]]
العميق  : [[0, 0], [0, 0]]
```

`copy.copy` تنسخ الحاوية الخارجية وتشارك ما بداخلها. `copy.deepcopy` تنزل إلى
القاع وتنسخ كل شيء.

والإصلاح في `select` سطرٌ واحد: `list(...)` حول كل عمود.

**مثال**

<!-- part: 03-select-fixed -->

```python
def select(self, names):
    return Table({name: list(self.columns[name]) for name in names})
```

**المخرَج**

<!-- out -->

```
[120, 340]
[120, 340, 999]
```

الأصل بقي كما هو.

**المكسب:** ليست كل نسخةٍ صحيحة. النسخ العميق يكلّف، والسطحيّ يشارك. القرار
يتبع ما تريده من الجدول المشتقّ، وقد اخترنا هنا عزلَ الأعمدة.

## الحالات

### `tuple` يمنع الاستبدال ولا يمنع التعديل

**توقّع** قبل أن تقرأ.

<!-- part: 03-tuple -->

```python
row = (1, [2, 3])
row[1].append(4)
print(row)

row[0] = 9
```

المخرَج:

<!-- err: TypeError -->

```
(1, [2, 3, 4])
TypeError: 'tuple' object does not support item assignment
```

الـ`tuple` يثبّت الإشارات التي يحملها. الإشارة الثانية ما زالت إلى القائمة
نفسها، والقائمة تقبل التعديل. والسطر الأخير يحاول تبديل إشارةٍ فيُرفَض.

والأثر العمليّ: `tuple` فيه قائمة لا يصلح مفتاحاً في قاموس، وتراه في الفصل
`04`.

## تمرين

اجعل `Table` يمنع تعديل أعمدته من الخارج: `t["sales"].append(9)` يجب أن يفشل،
و`len(t)` و`total(t["sales"])` يجب أن يبقيا يعملان.

الشرط أن تفعله بتغييرٍ في `__getitem__` وحدها، وأن تقول ما الذي يكلّفه حلُّك في
الذاكرة أو في الزمن.

**الفصل التالي:** القاموس — كيف يجد المفتاح، ولماذا لا يقبل بعض الكائنات مفاتيح.
