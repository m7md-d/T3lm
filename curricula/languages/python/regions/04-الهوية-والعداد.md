# الإقليم ٠٤ — الهوية والعدّاد

> عرفتَ أن الاسم يربط، وأن الكائن يُعدَّل أو لا يُعدَّل. بقي السؤال الثالث في هذه
> الحزمة: **متى يكون الكائنان كائناً واحداً، ومتى يموت الكائن؟**
>
> والسؤالان واحدٌ في الحقيقة، لأن الجواب في الموضعين رقمٌ واحدٌ في ترويسة كلّ كائن.

## سؤالان لا سؤال

`==` تسأل عن **القيمة**، و`is` تسأل عن **الكائن**. وفي C لا يوجد لهذا نظير: `==`
على المؤشّرات تقارن العناوين، وعلى القيم تقارن البتّات، والفرق يقرّره النوع.
**هنا الفرق يقرّره العامل نفسه، وأنت الذي تختار.**

<!-- part: 04-eq-vs-is -->

```python
a, b = [1, 2], [1, 2]
print(a == b, a is b)


class Point:
    def __init__(self, x):
        self.x = x

    def __eq__(self, other):
        return isinstance(other, Point) and self.x == other.x


print(Point(1) == Point(1), Point(1) is Point(1))
print(Point(1) == 1)
```

<!-- out -->

```
True False
True False
False
```

`a == b` صحيحة لأن `list.__eq__` تقارن العناصر واحداً واحداً. و`a is b` كاذبة
لأنهما كائنان.

وحين كتبتَ `__eq__` لنوعك صار `==` يعني ما تقوله أنت (البديهية الثالثة). ولاحظ
السطر الأخير: `Point(1) == 1` أعادت `False` ولم ترفع خطأ — لأن `__eq__` أعادت
`False` بعد أن فشل `isinstance`. ولو أعدتَ `NotImplemented` بدلها لجرّب Python
الطرف الآخر قبل أن يحكم.

## أين ينتهي عقد اللغة

هنا موضعٌ يبني عليه كثيرون قواعد خاطئة، لأنهم يجرّبونه في سطرٍ واحد.

<!-- part: 04-interning -->

```python
print('int("256") مرّتين :', int("256") is int("256"))
print('int("257") مرّتين :', int("257") is int("257"))

s1 = "".join(["a", "b"])
s2 = "".join(["a", "b"])
print('"ab" مبنيّان      :', s1 is s2, "| متساويان:", s1 == s2)
print("بعد intern       :", sys.intern(s1) is sys.intern(s2))
```

<!-- out -->

```
int("256") مرّتين : True
int("257") مرّتين : False
"ab" مبنيّان      : False | متساويان: True
بعد intern       : True
```

CPython يحتفظ بكائناتٍ جاهزةٍ للأعداد الصغيرة، فيعيد الكائن نفسه لـ`256` ولا
يفعل لـ`257`. والنصّان المبنيّان في وقت التشغيل كائنان، حتى لو تطابقا حرفاً بحرف،
حتى تطلب `intern` صراحةً.

**وهذا كلُّه `@cpython`:** تفصيلُ تطبيقٍ لا تعدك به اللغة، ويجوز أن يتغيّر بين
إصدارٍ وآخر. ولو كتبتَ `x is 257` لعمل عندك اليوم وسقط غداً.

**القاعدة:** `is` للـ`None` وللأعلام المفردة (sentinels) التي تنشئها أنت. وما عدا
ذلك `==`.

## العدّاد في الترويسة

كلُّ كائنٍ يحمل عدداً: **كم اسماً أو حاوية تشير إليه الآن.** الربط يزيده، وخروج
الاسم من نطاقه ينقصه، وحين يبلغ صفراً يُحرَّر الكائن فوراً.

<!-- part: 04-refcount -->

```python
obj = object()
print("بعد الربط الأول :", sys.getrefcount(obj) - 1)

box = [obj]
print("وبعد وضعه بقائمة:", sys.getrefcount(obj) - 1)

box.clear()
print("وبعد إفراغها    :", sys.getrefcount(obj) - 1)
```

<!-- out -->

```
بعد الربط الأول : 1
وبعد وضعه بقائمة: 2
وبعد إفراغها    : 1
```

(نطرح واحداً لأن تمرير الكائن إلى `getrefcount` يزيده مؤقّتاً.)

**والفرق عن C جوهريّ:** هناك أنت تقرّر متى تُحرَّر الذاكرة بـ`free`. وهنا يقرّرها
العدّاد، **وفي لحظةٍ محدّدةٍ تعرفها**: السطر الذي يُسقط آخر مرجع.

وهذا العدّاد هو الذي رأيتَ ثمنه في الإقليم `00`: لأنه جزءٌ من واجهة C المعلنة،
احتاج قفلاً يحميه.

## ما لا يستطيع العدّاد

**تنبّأ:** كائنان، كلٌّ منهما يشير إلى الآخر، ثم تحذف الاسمين. هل يموتان؟

<!-- part: 04-cycle -->

```python
class Node:
    def __init__(self, name):
        self.name = name
        self.peer = None

    def __del__(self):
        print(f"  مات {self.name}")


x, y = Node("ب"), Node("ج")
x.peer, y.peer = y, x
del x, y
print("  (لم يمت أحد بعد)")

print("بعد نداء الجامع:", gc.collect(), "كائناً")
```

المخرَج:

<!-- out -->

```
بلا دور:
  مات أ
بدور:
  (لم يمت أحد بعد)
  مات ب
  مات ج
بعد نداء الجامع: 2 كائناً
```

الكائن الأول مات فور `del` — عدّاده بلغ صفراً. والاثنان الآخران **لم يموتا**: كلٌّ
منهما ما زال عليه مرجعٌ واحد، من الآخر. عدّادٌ يعدّ المراجع لا يستطيع أن يكتشف
جزيرةً مغلقةً على نفسها.

**ولهذا في CPython جامعان لا واحد:** العدّاد يقتل الأغلبية فوراً، وجامعٌ دوريّ
يمشي على البنى ويبحث عن الجزر المغلقة. والجامع الثاني هو الذي حرّر الاثنين، وأخبرك
كم حرّر.

## و`__del__` ليست destructor

في C++ يعمل الـdestructor في لحظةٍ يضمنها المعيار. وهنا `__del__` تعمل حين يُحرَّر
الكائن — **ولا تعرف متى ذلك بالضبط** إن كان في دورة، ولا تعمل أصلاً إن انتهى
المفسّر وفيه كائناتٌ حيّة.

فلا تضع فيها إغلاق ملفٍّ ولا تحرير قفل. موضعُ ذلك `with` وبروتوكولها — الإقليم
`10`.

## التمرين

جدولُك يحمل قاموساً من الأعمدة، وكلُّ عمودٍ يحمل قائمةً من القيم. **اكتب دالّةً
تقيس كم كائناً حيّاً يمثّل جدولاً بمليون صفٍّ وعمودين** — لا كم بايتاً، بل كم
كائناً.

**والقيد:** لا تخمّن من الشكل. أثبت الرقم بأداةٍ تُشغّلها.

**ثم اسأل:** لو كانت القيم كلُّها أعداداً بين `0` و`255`، كم كائناً **مختلفاً**
هناك فعلاً؟ الفرق بين جوابَي السؤالين هو نصف ما ستراه في الحزمة الرابعة.

## الخلاصة

`==` سؤالٌ عن القيمة تجيب عنه `__eq__`، و`is` سؤالٌ عن الكائن لا يُستعمل إلا مع
`None` وأعلامك. وما تراه من تطابق هويّةٍ في الأعداد والنصوص تفصيلُ تطبيقٍ لا وعدَ
لغة.

والكائن يموت حين يبلغ عدّاده صفراً، في لحظةٍ تعرفها — إلا أن يكون في دورةٍ مغلقة،
فينتظر جامعاً دوريّاً لا تعرف موعده.

وبهذا اكتملت الحزمة الأولى: **الاسم يربط، والكائن يُعدَّل أو لا، والعدّاد يقرّر
الموت.** والحزمة التالية تسأل سؤالاً واحداً: ما الذي يجعل كائنك يستجيب لـ`len`
و`for` و`+` و`with` — بلا أن يرث شيئاً؟
