# ٠١ — الاسم والكائن

هنا تبني البرنامج الذي يرافق المنهج كلَّه، ثم تعرف ما الذي يحدث حين تكتب `=`.

---

## البرنامج الذي يفتح المنهج

جدولٌ بأعمدة. تبنيه من أربع قطع، وكل حزمةٍ بعد هذه تعدّله أو تمدّه.

**القطعة الأولى — التخزين.** الجدول قاموسٌ من اسم العمود إلى قائمة قيمه.

<!-- head: table.py -->

```python
class Table:
    def __init__(self, columns):
        self.columns = columns
```

**القطعة الثانية — القياس والفهرسة.** طريقتان باسمين محجوزين تجعلان `len(t)`
و`t["sales"]` تعملان على الجدول.

<!-- head: table.py -->

```python
    def __len__(self):
        return len(next(iter(self.columns.values())))

    def __getitem__(self, name):
        return self.columns[name]
```

الاسمان `__len__` و`__getitem__` ليسا اصطلاح تسمية. المفسّر يبحث عنهما بالاسم
حين ينفّذ `len(...)` و`[...]`. الفصل `06`.

**القطعة الثالثة — الاشتقاق.** جدولٌ جديد ببعض الأعمدة.

<!-- head: table.py -->

```python
    def select(self, names):
        return Table({name: self.columns[name] for name in names})
```

**القطعة الرابعة — الحساب.** جمعُ عمود.

<!-- head: table.py -->
```python
def total(values):
    result = 0
    for value in values:
        result += value
    return result
```


الملفّ كاملاً في [`programs/table.py`](../programs/table.py) — ستةٌ وعشرون سطراً.

**مثال**

<!-- part: 01-table -->
```python
from table import Table, total

t = Table({"city": ["Riyadh", "Jeddah", "Dammam"], "sales": [120, 340, 90]})

print(len(t))
print(t["sales"])
print(total(t["sales"]))
```

<!-- out -->

**المخرَج**

```
3
[120, 340, 90]
550
```

**المكسب:** برنامجٌ يعمل الآن، وفيه أربعة أشياء يفصّلها المنهج: الاسم والكائن،
والقاموس، والبروتوكول، وكلفة الحلقة.

## ما الذي تفعله `=`

في C يعني `y = x` نسخَ البايتات من خانةٍ إلى خانة. في Python تضع `=` مدخلاً في
جدول أسماء، وقيمة المدخل إشارةٌ إلى كائن. الكائن نفسه لا يُمسّ.

**مثال**

<!-- part: 01-bind -->
```python
a = [1, 2]
b = a
print(f"b = a        a→{id(a):#x}  b→{id(b):#x}  {a} {b}")

b.append(3)
print(f"b.append(3)  a→{id(a):#x}  b→{id(b):#x}  {a} {b}")

b = [9]
print(f"b = [9]      a→{id(a):#x}  b→{id(b):#x}  {a} {b}")
```

<!-- runs: 01-bind -->

**المخرَج**

```
b = a        a→0x100439980  b→0x100439980  [1, 2] [1, 2]
b.append(3)  a→0x100439980  b→0x100439980  [1, 2, 3] [1, 2, 3]
b = [9]      a→0x100439980  b→0x100537bc0  [1, 2, 3] [9]
```

العناوين تختلف عندك في كل تشغيل. المهمّ تساويها في السطرين الأولين واختلافها في
الثالث.

**السطر الثاني `b.append(3)`** يعدّل الكائن الذي يشير إليه الاسمان، فيراه
الاثنان.

**السطر الثالث `b = [9]`** يكتب في جدول الأسماء إشارةً إلى كائنٍ آخر. الكائن
الأول باقٍ، و`a` ما زال يشير إليه.

**القاعدة:** `=` تربط اسماً بكائن، والطريقة (`append`) تعدّل الكائن.

---

## الوسيط يتبع القاعدة نفسها

نداء الدالّة يربط أسماء المعامِلات بالكائنات الممرَّرة. لا فرق بين هذا وبين `=`.

**مثال**

<!-- part: 01-arg -->
```python
def rebind(values):
    values = [9]


def mutate(values):
    values.append(9)


xs = [1, 2]
rebind(xs)
print(xs)

mutate(xs)
print(xs)
```

<!-- out -->

**المخرَج**

```
[1, 2]
[1, 2, 9]
```

`rebind` أعادت ربط الاسم المحلّي `values` بكائنٍ جديد، فلم يتأثّر `xs`.
و`mutate` عدّلت الكائن نفسه.

**المكسب:** السؤال «هل Python تمرّر بالقيمة أم بالمرجع؟» يسأل عن تقسيمٍ غير
موجودٍ هنا. القاعدة واحدة: ربطُ اسمٍ بكائن، في `=` وفي النداء.

## الحالات

### الجدول المشتقّ يشارك الأصل

`select` تبني قاموساً جديداً، وقيمُه هي القوائم نفسها. القاموس نُسخ، والقوائم لا.

**توقّع** قبل أن تقرأ.

<!-- part: 01-share -->
```python
from table import Table

t = Table({"city": ["Riyadh", "Jeddah"], "sales": [120, 340]})
small = t.select(["sales"])

small["sales"].append(999)

print(t["sales"])
print(small["sales"])
print(t["sales"] is small["sales"])
```

<!-- out -->

المخرَج:

```
[120, 340, 999]
[120, 340, 999]
True
```

الإضافة إلى الجدول المشتقّ ظهرت في الأصل، لأن العمود كائنٌ واحدٌ يشير إليه
الاثنان.

وهذا عيبٌ في `select`، ويبقى مفتوحاً حتى الفصل `03` حيث تعرف أي الأنواع
يقبل التعديل وأيّها يمنعه، وكيف تنسخ نسخاً صريحاً.
