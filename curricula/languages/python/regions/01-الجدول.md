# الإقليم ٠١ — الجدول

> هنا تبني الـepitome: **جدولٌ عموديٌّ في خمسين سطراً**، فيه كلُّ علاقةٍ سيفصّلها
> هذا المنهج. لن يكون سريعاً ولا كاملاً — سيكون **صحيحاً وقابلاً للقياس**، وكلُّ
> إقليمٍ بعده يعدّله أو يمدّه حتى يصير في الحزمة الخامسة مكتبةً بنواةٍ من C.
>
> وستنتهي منه بثقبٍ واحدٍ مقصود، هو مدخل الإقليم التالي.

## لماذا جدولٌ عموديّ

الصفّ هو الشكل الذي يخطر أولاً: قائمةٌ من القواميس، كلُّ قاموسٍ سجلّ. وهو الشكل
الذي **يخفي كلَّ ما نريد أن نراه**.

الجدول العموديّ يخزّن كلَّ حقلٍ في مصفوفةٍ مستقلّة. وهذا الاختيار يضع أمامك
مباشرةً: **ما الذي يُخزَّن فعلاً، ومن يملكه، وكم يكلّف المرور عليه.** وهي الأسئلة
الثلاثة التي يدور حولها المنهج.

## العمود

ابدأ بأصغر شيء: عمودٌ له اسمٌ وقيم.

<!-- part: 01-column -->

```python
class Column:
    def __init__(self, name, values):
        self.name = name
        self.values = list(values)

    def __len__(self):
        return len(self.values)

    def __getitem__(self, i):
        return self.values[i]

    def __iter__(self):
        return iter(self.values)

    def __repr__(self):
        return f"Column({self.name!r}, n={len(self)})"
```

أربع فتحاتٍ فقط — ولا وراثة، ولا واجهة مُعلَنة. وهذا يكفي ليصير العمود **مواطناً
من الدرجة الأولى**: تعمل عليه `len` و`[]` و`for` و`sum` و`max`، وكلُّها تطلب
الفتحات التي ملأتَها (البديهية الثالثة).

<!-- out -->

```
Column('v', n=3)
3 3 [3, 1, 4]
8 4
```

`sum(c)` و`max(c)` لم تُكتَبا في الصنف. تعملان لأن `__iter__` موجودة، لا لأن
`Column` ورث من شيء.

**و`list(values)` في السطر الثالث ليست زينة.** لو كتبتَ `self.values = values`
لصار العمود مربوطاً بقائمة المستدعي نفسها، فيتغيّر من تحتك. وهذا بالضبط ما سنراه
يقع بعد قليل — في مكانٍ نسيتُ أن أفعلها فيه عمداً.

## الجدول

<!-- part: 01-table -->

```python
class Table:
    def __init__(self, columns):
        sizes = {len(c) for c in columns}
        if len(sizes) > 1:
            raise ValueError(f"أعمدةٌ بأطوالٍ مختلفة: {sorted(sizes)}")
        self.columns = {c.name: c for c in columns}

    def __len__(self):
        if not self.columns:
            return 0
        return len(next(iter(self.columns.values())))

    def __getitem__(self, name):
        return self.columns[name]

    def rows(self):
        names = list(self.columns)
        for i in range(len(self)):
            yield {n: self.columns[n][i] for n in names}

    def select(self, *names):
        return Table([self.columns[n] for n in names])

    def total(self, name):
        s = 0
        for v in self.columns[name]:
            s += v
        return s
```

<!-- out -->

```
Table(['id', 'v'], n=3)
3 30
{'id': 1, 'v': 10}
{'id': 2, 'v': 20}
{'id': 3, 'v': 30}
المجموع: 60
```

لاحظ ثلاثة أشياء ستُفكَّك كلُّها لاحقاً:

`__getitem__` هنا تأخذ **اسماً** لا رقماً. لا شيء في اللغة يمنع ذلك — الفتحة
تستقبل ما تُعطى، والمعنى لك.

و`rows` ليست دالّةً تعيد قائمة. فيها `yield`، فهي **مولّد**: لا تبني الصفوف كلَّها
في الذاكرة، بل توقف نفسها وتستأنف. وهذا هو الإقليم `09` كاملاً.

و`total` حلقةٌ صريحة. اكتبها هكذا الآن، فهي المرجع الذي ستُقاس عليه أربع مرّات.

## أربعة أرقام

**تنبّأ قبل أن تقرأ اللوحة**: أمامك أربع طرقٍ لجمع مليون عددٍ من العمود نفسه —
حلقتك الصريحة، و`sum` المدمَجة (وهي مكتوبةٌ بـC)، وNumPy، ودالّة C تُنادى مباشرةً
على البايتات. **رتّبها، وخمّن النسب.**

<!-- part: 01-four-numbers -->

```python
cases = {
    "حلقة Python صريحة": lambda: t.total("v"),
    "sum المدمَجة": lambda: sum(t["v"].values),
    "NumPy": lambda: int(arr.sum()),
    "دالّة C": lambda: lib.col_sum(p, N),
}
```

المخرَج:

<!-- runs: 01-four-numbers -->

```
حلقة Python صريحة      12225.9 µs   ×   1.0
sum المدمَجة            4176.9 µs   ×   2.9
NumPy                    100.2 µs   × 122.0
دالّة C                   99.8 µs   × 122.5
```

(الأرقام من جهازٍ واحد؛ **النسبة هي الثابت**، وستقيسها عندك.)

**اثنان هنا يخالفان الحدس.**

`sum` المدمَجة **مكتوبةٌ بـC** ولا تكسب إلا ثلاثة أضعاف. لأنها تخرج من حلقة
الـbytecode وتبقى داخل نموذج الكائنات: تفكّ مليون `PyObject` وتنادي `__add__` في
كلٍّ منها. **الكسبُ في ترك المفسّر، لا في لغة المكتبة.**

ودالّة C **لا تتفوّق على NumPy**. لأن الاثنتين تفعلان الشيء نفسه بالضبط: حلقةٌ
مُشعَّبة على بايتاتٍ متجاورة. الفرق الوحيد الذي بقي بينهما كلفةُ عبور الحدّ، وهي
دون الميكرو ثانية.

**النسبة ×١٢٢ ليست ثمن Python كلغة.** هي ثمن أن يكون العدد كائناً في صندوق
(البديهية الخامسة) — وهذا ما تحلّه الحزمة الرابعة.

## الثقب

**تنبّأ:** جدولٌ فيه عمودان، تأخذ منه `select("v")`، ثم تعدّل قيمةً في الناتج.
ماذا يقول الأصل؟

<!-- part: 01-select-shares -->

```python
t = Table([Column("id", [1, 2, 3]), Column("v", [10, 20, 30])])
part = t.select("v")

part["v"].values[0] = 999

print("من الجدول الأصليّ:", t["v"][0])
print("نفس الكائن؟", t["v"] is part["v"])
```

المخرَج:

<!-- out -->

```
من الجدول الأصليّ: 999
نفس الكائن؟ True
```

`select` بنت جدولاً جديداً، فظننتَ أنك تملك نسخة. وليس هناك نسخة: **الجدول الجديد
يحمل الكائن نفسه.** الذي نُسخ هو القاموس الذي يربط الأسماء بالأعمدة، لا الأعمدة.

وهذا ليس عيباً في `select` — هو البديهية الثانية تعمل كما وُعدت: `[self.columns[n]
for n in names]` قائمةٌ من **الرباطات**، لا من القيم.

**وهنا ينتهي هذا الإقليم عمداً.** لأن السؤال الذي يفتحه — متى يربط الإسناد ومتى
ينسخ، وأين تعيش الأسماء أصلاً — أكبر من أن يُجاب في سطر.

## التمرين

**أضف `Table.describe()` تعيد لكلّ عمود: اسمه، وطوله، وأصغر قيمةٍ فيه، وأكبرها،
ومجموعها.**

**والقيد:** اكتبها نسختين — واحدةً تمرّ على العمود **مرّةً** وتحسب الأربعة معاً،
وأخرى تمرّ عليه **أربع مرّات**. ثم قِس الاثنتين على مليون صفّ.

**والسؤال هو الجواب:** أسرعُ نسخةٍ من الأخرى بأربعة أضعاف؟ **قِس ثم فسّر النسبة
التي حصلت عليها.** والتفسير سيقول لك أين تُدفَع الكلفة فعلاً — وهو ما تفكّكه
الحزمة الثالثة.

## الخلاصة

بنيتَ نظاماً يعمل: عمودٌ يملأ أربع فتحاتٍ فيصير مواطناً، وجدولٌ يرفض ما لا يصحّ
وقت التشغيل، ومولّدٌ يعطي الصفوف بلا أن يبنيها، وحلقةُ تجميعٍ صارت مرجعاً بأربعة
أرقام.

وتركتَ ثقبين معلومين: **الأول** أن `total` أبطأ من نظيرتها بـ١٢٢ ضعفاً، والجواب
في الحزمتين الرابعة والخامسة. **والثاني** أن `select` تشارك ولا تنسخ — والجواب
في الإقليم التالي مباشرةً.
