# الإقليم ١٠ — الاستثناءات

> في C تُبلّغ عن الفشل بقيمةٍ مُعادة، ومن ينساها يمضي ببياناتٍ فاسدة. وهنا الفشل
> **يقاطع** — لا يمكن تجاهله بالسهو.
>
> والسؤال الذي يقرّر أسلوب كودك كلَّه: متى تفحص قبل، ومتى تحاول وتمسك؟ وله جوابٌ
> يُقاس بالنانو ثانية.

## الفشل الذي يُقاطع

الاستثناء ليس قيمةً تُعاد. هو **تحويلٌ للتحكّم** يصعد في مكدّس النداءات حتى يجد
من يمسكه، فإن لم يجد أنهى البرنامج وطبع المسار الذي سلكه.

وهذا يحلّ المشكلة التي تعرفها من C: `malloc` تعيد `NULL` ومن لم يفحص مضى. **هنا
لا يمضي أحد.**

<!-- part: 10-chaining -->

```python
def parse(s):
    try:
        return int(s)
    except ValueError as e:
        raise TypeError(f"ليس عدداً: {s!r}") from e


parse("سبعة")
```

<!-- err: TypeError -->

```
Traceback (most recent call last):
  File "programs/10-chaining.py", line 3, in parse
    return int(s)
ValueError: invalid literal for int() with base 10: 'سبعة'

The above exception was the direct cause of the following exception:

Traceback (most recent call last):
  File "programs/10-chaining.py", line 8, in <module>
    parse("سبعة")
    ~~~~~^^^^^^^^
  File "programs/10-chaining.py", line 5, in parse
    raise TypeError(f"ليس عدداً: {s!r}") from e
TypeError: ليس عدداً: 'سبعة'
```

**أثران لا أثر.** `raise ... from e` تربط الاستثناء الجديد بالقديم، فيبقى السببان
معاً: ما فشل أصلاً، وما رفعتَه أنت بلغة مجالك.

ولو حذفتَ `from e` لبقيت السلسلة ظاهرةً أيضاً — بصيغة «وقع استثناءٌ آخر أثناء
معالجة هذا» — لأن Python تربط تلقائياً ما يُرفَع داخل `except`. **والفرق بين
الصيغتين إعلانُ نيّة**: هل هذا سببٌ مباشر، أم عطبٌ وقع أثناء المعالجة؟

## الثمن يُقاس

القاعدة الشائعة «اطلب الغفران لا الإذن» ليست ذوقاً. هي قرارٌ له رقم.

<!-- part: 10-cost -->

```python
def hit_try():
    try:
        return d["a"]
    except KeyError:
        return None


def hit_check():
    if "a" in d:
        return d["a"]
    return None
```

<!-- runs: 10-cost -->

```
try — والمفتاح موجود        25.4 ns
if  — والمفتاح موجود        33.1 ns
try — والمفتاح غائب        103.7 ns
if  — والمفتاح غائب         24.9 ns
```

**`try` أرخص من `if` حين لا يقع شيء.** لأن دخول الكتلة لا يكلّف عملاً وقت التشغيل
— جدولٌ يُستشار عند الرفع فقط — بينما `if "a" in d` بحثٌ كاملٌ إضافيّ يُدفَع في
كل مرور.

**وأغلى منه أربع مرّاتٍ حين يقع.** لأن رفع الاستثناء يبني كائناً، ويجمع الأثر،
ويصعد في المكدّس.

**فالقاعدة مشتقّةٌ لا محفوظة:** إن كان الفشل نادراً فـ`try` أرخص. وإن كان الفشل
هو الحالة الغالبة — كتحقّقٍ من مدخلاتٍ نصفُها خطأ — فالفحص المسبق أرخص. **وتذكّر
أن هذه أرقام جهازٍ واحد؛ النسبة هي الثابت.**

## `with` — الخروج المضمون

`__del__` لا تصلح لإغلاق مورد (الإقليم `04`). البديل بروتوكولٌ صريح:

<!-- part: 10-context -->

```python
class Guard:
    def __enter__(self):
        print("  دخلت")
        return self

    def __exit__(self, exc_type, exc, tb):
        print("  خرجت، والاستثناء:", exc_type.__name__ if exc_type else None)
        return False
```

<!-- out -->

```
  دخلت
  في الجسد
  خرجت، والاستثناء: None
  دخلت
  خرجت، والاستثناء: ValueError
أُمسِك خارج with: انفجر
```

`__exit__` نوديت في الحالتين: حين انتهى الجسد بسلام، وحين خرج باستثناء — **ومعها
الاستثناء نفسه**. فتستطيع أن تسجّله، أو تنظّف على أساسه.

**وقيمتها المُعادة هي القرار:** `False` تعني «لم أبتلعه، فليواصل صعوده»، و`True`
تعني «أنا أمسكته، توقّف هنا». وهذه هي الآلية التي تجعل `contextlib.suppress`
ممكنة، وهي أيضاً أخطر سطرٍ يمكن أن تكتبه بلا قصد.

## التمرين

**اجعل الجدول قابلاً للاستعمال في `with`**، بحيث يُبنى نسخةً عاملةً عند الدخول
ويستبدل الأصل بها عند الخروج **إن لم يقع استثناء**، ويتركه كما كان إن وقع:

<!-- task -->

```python
with t.transaction() as staged:
    staged["v"].values[0] = 999
    raise ValueError("تراجع")
# t["v"][0] لم يتغيّر
```

**والقيد:** لا تنسخ عميقاً بلا حاجة. الإقليم `03` قال لك أيَّ طبقةٍ تحتاج أن
تنفصل، والإقليم `02` قال لك لماذا.

**ثم:** ماذا يحدث لو رفع `__exit__` نفسه استثناءً أثناء التراجع؟ اكتب الحالة
وشغّلها واقرأ الأثر — ستجد فيه ما تعلّمتَه في أوّل هذا الإقليم.

## الخلاصة

الفشل يقاطع ولا يُنسى، ويحمل معه سلسلة أسبابه. وكلفتُه صفرٌ تقريباً حين لا يقع
وأربعةُ أضعافٍ حين يقع — ومن هنا تُشتقّ القاعدة لا تُحفَظ.

و`with` بروتوكولٌ من فتحتين يضمن الخروج، ويرى الاستثناء، ويقرّر مصيره.

**وبهذا اكتملت الحزمة الثانية.** تعرف الآن كيف يُبنى الكائن، وكيف تُطلَب فتحاته،
ومن يفوز عند البحث، وأن الدالّة كائن، وأن الإطار يقف ويستأنف، وأن الفشل يصعد.

والحزمة التالية تنزل طبقةً: **ما الذي يفعله المفسّر بكلّ هذا فعلاً؟**
