# الإقليم ٢١ — الملفّ

> `printf` تكتب إلى `stdout`. وما هو `stdout`؟
>
> جوابه هنا: **ملفّ**. وهذا ليس مجازاً — النوع واحد، والدوالّ واحدة، والفرق أنك
> لم تفتحه بنفسك.
>
> وفي هذا الإقليم يُستوفى `FILE`: ما هو، وكيف يُفتَح ويُقرأ ويُكتَب، ولماذا
> `while (!feof(f))` خطأٌ يكتبه الجميع.

---

## `FILE *` مقبضٌ لا تفتحه

```c
FILE *f = fopen("notes.txt", "r");
```

`fopen` تُرجع `FILE *`. **ولا تعرف أنت ما داخل `FILE`، ولا يجب أن تعرف.**

وهذا هو **النوع المُعتِم** من الإقليم ١٨ في أشهر تطبيقاته: النوع معلَنٌ في
`<stdio.h>`، ومحتواه شأن المكتبة. تحمل الـpointer وتمرّره، ولا تقرأ حقلاً منه
ولا تنسخه.

**وما بداخله فعلاً** — وستعرفه في الإقليمين ٢٣ و٢٤ — رقمٌ يعرفه النظام، وbuffer،
وموضعٌ فيه، وعَلَما نهايةٍ وخطأ.

**ولذلك `fclose` ليست تجميلاً:** هي التي تُفرغ الـbuffer وتعيد المورد للنظام.
وبرنامجٌ يفتح آلاف الملفّات بلا إغلاقٍ ينفد منه شيءٌ لا تراه.

---

## اكتب ثم اقرأ

```c
#include <stdio.h>

int main(void)
{
	FILE *f = fopen("notes.txt", "w");

	if (f == NULL) {
		printf("تعذّر الفتح\n");
		return 1;
	}
	fprintf(f, "name ali\n");
	fputs("lang c\n", f);
	fclose(f);

	f = fopen("notes.txt", "r");
	if (f == NULL)
		return 1;

	char line[128];
	while (fgets(line, sizeof line, f) != NULL)
		printf("[%s]", line);
	fclose(f);

	f = fopen("nope.txt", "r");
	printf("nope: %p\n", (void *)f);
	return 0;
}
```

<!-- out -->

```
[name ali
][lang c
]nope: 0x0
```

**الأقواس تكشف شيئاً:** `fgets` **تُبقي** السطر الجديد داخل ما قرأت. ولهذا كتبتَ
`strcspn` في الإقليم ٠١ — لتمسحه.

**وتُبقيه لسببٍ وجيه:** بغيابه لا تستطيع أن تفرّق بين سطرٍ انتهى وسطرٍ **قُطع**
لأن الـbuffer امتلأ. وهذا هو خطؤك الثالث من الإقليم ٠١، ويُغلَق في اللقطة بعد
القادمة.

**والسطر الأخير:** ملفٌّ غير موجود ⇒ `NULL`. والفحص عليك، دائماً. **ولماذا فشل
بالضبط** — لا يقوله `fopen`؛ ذلك هو الإقليم ٢٢.

## الأنماط

الحرف الأول في الوسيط الثاني يقرّر ثلاثة أشياء معاً:

| | يقرأ | يكتب | إن كان موجوداً | إن لم يكن |
|---|---|---|---|---|
| `"r"` | ✓ | | يُفتَح من أوّله | **يفشل** |
| `"w"` | | ✓ | **يُفرَّغ** | يُنشَأ |
| `"a"` | | ✓ | يُكتَب في آخره | يُنشَأ |
| `"r+"` | ✓ | ✓ | يُفتَح من أوّله | يفشل |
| `"w+"` | ✓ | ✓ | **يُفرَّغ** | يُنشَأ |
| `"a+"` | ✓ | ✓ | القراءة حرّة، والكتابة في آخره | يُنشَأ |

**و`"w"` تمسح بلا سؤال.** لا تُرجع خطأً، ولا تحذّر — هذا تعريفها.

**ويُضاف `b`** — `"rb"`، `"wb"` — للملفّات الثنائية. **ولا أثر له على أنظمة
POSIX**؛ وعلى ويندوز يمنع تحويل `\n` إلى حرفين عند الكتابة وعكسَه عند القراءة.

**وهذه منطقةٌ رمادية بحكم المواصفة:** التمييز بين نمطٍ نصّيّ وثنائيّ موجودٌ فيها،
وأثرُه متروكٌ للتنفيذ. فاكتب `b` حين تكون البيانات ثنائية — يكلّفك حرفاً، ويوفّر
عليك عطباً لا يظهر إلا على منصّةٍ أخرى.

## `while (!feof(f))` خطأ

هذه أشهر مصيدةٍ في هذا الباب، وسببها سوء فهمٍ لكلمة «نهاية».

```c
#include <stdio.h>

int main(void)
{
	FILE *f = fopen("t.txt", "w");

	fputs("ab", f);
	fclose(f);

	f = fopen("t.txt", "r");
	int n = 0;
	while (!feof(f)) {
		int c = fgetc(f);
		printf("%d ", c);
		n++;
	}
	printf("\nدورات = %d\n", n);
	fclose(f);

	f = fopen("t.txt", "r");
	n = 0;
	int c;
	while ((c = fgetc(f)) != EOF) {
		printf("%d ", c);
		n++;
	}
	printf("\nدورات = %d\n", n);
	fclose(f);
	return 0;
}
```

<!-- out -->

```
97 98 -1 
دورات = 3
97 98 
دورات = 2
```

**الملفّ حرفان، والحلقة الأولى دارت ثلاثاً** وطبعت `-1` — وهي `EOF`.

**السبب أن `feof` لا تتنبّأ.** لا تقول «الملفّ سينتهي»، بل **«محاولةُ قراءةٍ فشلت
لأنه انتهى»**. فبعد قراءة `b` لم يكن العَلَم مرفوعاً بعد — لم تفشل قراءةٌ بعد —
فدارت الحلقة مرّةً أخرى وفشلت **حينئذٍ** رُفع العَلَم.

**والصواب: افحص نتيجة القراءة نفسها.** فهي التي تعرف. و`feof` موضعها **بعد**
انتهاء الحلقة، حين تسأل: انتهى الملفّ أم وقع خطأ؟

```c
if (ferror(f))
	/* عطبٌ في القراءة */;
else if (feof(f))
	/* انتهى سليماً */;
```

**ولاحظ `int c` لا `char c`** — وهذا هو درس الإقليم ٠٥ بعينه: `EOF` هي `-1`، ولا
تسع في `char` مع ٢٥٦ قيمةَ بايت.

## البايتات كما هي

`fread` و`fwrite` تنقلان بايتاتٍ بلا تفسير:

```c
#include <stdio.h>

int main(void)
{
	unsigned int n = 0x11223344;
	FILE *f = fopen("bin", "wb");

	fwrite(&n, sizeof n, 1, f);
	fclose(f);

	f = fopen("bin", "rb");
	unsigned char b[4];
	size_t got = fread(b, 1, 4, f);
	fclose(f);

	printf("%zu: ", got);
	for (int i = 0; i < 4; i++)
		printf("%02X ", b[i]);
	printf("\n");
	return 0;
}
```

<!-- out @impl -->

```
4: 44 33 22 11 
```

**وهنا يُدفَع الوعد المعلّق منذ الإقليم ٠٢.** الملفّ يحمل `44 33 22 11` — ترتيب
هذه الآلة. وبرنامجٌ يقرؤه على آلةٍ big-endian سيقرأ `0x44332211`، **ولن يشتكي
أحد**.

**فالترتيب لا يعنيك ما دامت البايتات لا تغادر برنامجك.** ويعنيك لحظةَ تعبر إلى
ملفٍّ أو شبكة. وصيغةُ الملفّ التي تُكتب لغيرك **تُعلن ترتيبها**، أو تُكتب نصّاً.

**والوسيطان الأوسطان `(size, count)`** والقيمة المرجَعة **عدد العناصر** لا
البايتات. فـ`fread(b, 1, 4, f)` تُرجع ٤، و`fread(b, 4, 1, f)` تُرجع ١ — والقصّ
الجزئيّ يظهر في الأولى ولا يظهر في الثانية.

## الموضع

```c
#include <stdio.h>

int main(void)
{
	FILE *f = fopen("t.txt", "w+");

	fputs("abcdef", f);
	printf("%ld\n", ftell(f));
	fseek(f, 0, SEEK_END);
	printf("%ld\n", ftell(f));
	fseek(f, 2, SEEK_SET);
	printf("%c\n", fgetc(f));
	rewind(f);
	printf("%c\n", fgetc(f));
	fclose(f);
	return 0;
}
```

<!-- out -->

```
6
6
c
a
```

الملفّ ليس تيّاراً في اتّجاهٍ واحد: فيه **موضع** يتقدّم مع كل قراءةٍ وكتابة،
ويمكن نقله.

| | |
|---|---|
| `ftell(f)` | أين نحن الآن، بالبايت من الأوّل |
| `fseek(f, off, SEEK_SET / SEEK_CUR / SEEK_END)` | انقل الموضع |
| `rewind(f)` | إلى الأوّل، **وامسح عَلَمَي النهاية والخطأ** |

**وحدٌّ عمليّ:** `fseek` بإزاحةٍ غير صفرية على ملفٍّ فُتح نصّياً **غير مضمون**
بالمواصفة — القيم الوحيدة المضمونة ما جاء من `ftell` نفسها.

## و`stdout` واحدٌ منها

```c
//! pty
#include <stdio.h>

int main(void)
{
	fprintf(stdout, "إلى stdout\n");
	fprintf(stderr, "إلى stderr\n");
	return 0;
}
```

<!-- out -->

```
إلى stdout
إلى stderr
```

**ثلاثة مجارٍ مفتوحةٌ قبل `main`:**

| | | |
|---|---|---|
| `stdin` | الدخل | من أين تقرأ `fgets(…, stdin)` |
| `stdout` | الخرج | حيث تكتب `printf` |
| `stderr` | الأخطاء | مجرىً منفصل، **لا يُخزَّن مؤقّتاً** |

و`printf(fmt, ...)` **تعريفها** `fprintf(stdout, fmt, ...)`. و`getchar()` هي
`fgetc(stdin)`. لا شيء منها بنيةٌ لغوية.

**ولماذا مجرىً منفصل للأخطاء؟** لأن المستعمل يوجّه المخرَج إلى ملفّ ويريد أن يرى
الأخطاء على شاشته. و`./main > out.txt` توجّه `stdout` وحده.

**وهذا هو نصف جواب سؤالك المعلّق منذ الإقليم ٠١** عن `fflush(stdout)`. النصف
الآخر في الإقليم ٢٤ — وهو أنّ **متى** تُكتَب البايتات فعلاً ليس متى ناديتَ
`printf`.

## قبل أن تكمل

> **١.** أضِف إلى الإقليم ٠١ أمرَي `save f` و`load f` يكتبان الجدول ويقرآنه.
> نصّاً أم ثنائياً؟ اكتب سببك قبل أن تكتب الكود.
>
> **٢.** الخطأ الثالث من الإقليم ٠١: سطرٌ أطول من ١٢٧. اكتب دالّةً تقرأ سطراً
> كاملاً مهما طال — بـ`fgets` في حلقة و`realloc`. متى تعرف أن السطر انتهى؟
>
> **٣.** `fopen("/etc/passwd", "w")` — ماذا تُرجع، ولماذا؟ ثم `fopen(".", "r")`
> — وهل تنجح؟ جرّبهما، وسجّل الفرق للإقليم القادم.
