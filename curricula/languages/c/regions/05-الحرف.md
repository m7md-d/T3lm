# الإقليم ٠٥ — الحرف

> في الإقليم ٠٢ رأيتَ `'A'` بايتاً واحداً قيمته `41`. وفي أسئلة ذلك الإقليم
> طلبتُ منك أن تبحث عن `FFFFFFAA` ولم أقل لماذا.
>
> هنا الجواب. و`char` هو النوع الذي تجتمع فيه أكثر مناطق C رماديةً: إشارته
> **معرَّفةٌ بالتنفيذ**، وحجمه في التعبير ليس حجمه في الذاكرة، ونصف الأخطاء التي
> يقع فيها الناس مع الدخل تعود إلى سطرٍ واحد فيه.

---

## `'A'` عددٌ باتّفاق

لا يوجد في الآلة شيء اسمه حرف. يوجد جدولٌ متّفق عليه يربط عدداً بشكل، اسمه
**ASCII**.

```c
#include <stdio.h>

int main(void)
{
	printf("%d %d %d %d\n", 'A', 'a', '0', ' ');
	printf("%d\n", 'a' - 'A');
	printf("%c %c\n", 'A' | 0x20, 'a' & ~0x20);
	return 0;
}
```

<!-- out @impl -->

```
65 97 48 32
32
a A
```

**والجدول ليس عشوائياً.** الفرق بين الكبير والصغير ٣٢ بالضبط، و٣٢ هي `0x20` —
**bit واحدة**. فتحويل الحالة قلبُ bit: `| 0x20` يصغّر، و`& ~0x20` يكبّر.

وترتيب الأرقام متتابع، ولذلك `'7' - '0'` تعطيك سبعة. وهذه هي كل «خوارزمية»
تحويل نصٍّ إلى عدد.

**واستعملها بأسمائها لا بأرقامها:** اكتب `c - '0'` لا `c - 48`. الرقم يعمل ويخفي
المعنى.

---

## و`sizeof('A')` أربعة

```c
#include <stdio.h>

int main(void)
{
	printf("%zu %zu\n", sizeof('A'), sizeof(char));
	return 0;
}
```

<!-- out @impl -->

```
4 1
```

**الحرف بايتٌ في الذاكرة، و`int` في التعبير.** لأن `'A'` في C ليست ثابتاً من نوع
`char` — هي ثابتٌ من نوع `int` بنصّ المواصفة (§6.4.4.4).

وليست تفصيلاً بلا أثر: هذه هي الفروق التي تجعل مقطعاً واحداً يعطي جوابين في C
وC++، حيث `'A'` هناك من نوع `char`.

**وما ستلمسه منها مباشرةً:** `printf("%c", …)` تأخذ `int` لا `char`، و`getchar`
تُرجع `int` — واللقطتان التاليتان تقولان لماذا.

---

## إشارة `char`: منطقةٌ رمادية بحكم المواصفة

`char` في C **ثلاثة أنواعٍ لا واحد**: `char`، و`signed char`، و`unsigned char`.
والثالث ليس مرادفاً للأول.

وأمّا `char` المجرّد فإشارته **معرَّفةٌ بالتنفيذ**: المترجم يختار، ويُلزَم بأن
يوثّق اختياره، ولا يُلزَم باختيارٍ بعينه.

```c
#include <stdio.h>

int main(void)
{
	char          a = 0xAA;
	unsigned char b = 0xAA;

	printf("%d %d\n", a, b);
	printf("%X %X\n", a, b);
	return 0;
}
```

<!-- out @impl: على هذا الهدف، حيث `char` ذو إشارة -->

```
-86 170
FFFFFFAA AA
```

**نفس البايت، ورقمان.** الـbit العليا في `0xAA` مرفوعة؛ فإن كان النوع ذا إشارة
صارت وزناً سالباً، وإلا فوزناً موجباً.

وهذا مصدر `FFFFFFAA` الذي بحثتَ عنه في الإقليم ٠٢: `%X` ينتظر `int`، فيُرقَّى
`char` السالب إلى `int` سالب — **وتمتدّ الواحدات إلى الأعلى**. الإقليم ٠٦ يفصّل
الـpromotion.

**والقاعدة العملية ثلاث كلمات:**

| | |
|---|---|
| `char` | نصٌّ يُقرأ ويُطبَع |
| `unsigned char` | **بايتٌ خام** — ذاكرةٌ تُفحَص، بياناتٌ ثنائية |
| `signed char` | عددٌ صغير بإشارة، حين تقصدها |

## السطر الذي يكسر قراءة الدخل

هذه أشهر مصيدةٍ في C، وسببها اللقطتان السابقتان مجتمعتين.

`getchar` تُرجع `int`: قيمة البايت من ٠ إلى ٢٥٥، **أو** `EOF` وهي `-1`. مئتان
وستّةٌ وخمسون احتمالاً في نوعٍ لا يسع إلا ٢٥٦ — فلا يكفي `char`.

```c
#include <stdio.h>

unsigned char data[] = { 'a', 'b', 0xFF, 'c', 'd' };
size_t pos = 0;

int next(void)                     /* هذا بالضبط ما تفعله getchar */
{
	if (pos == sizeof data)
		return EOF;
	return data[pos++];
}

int main(void)
{
	int  n;
	char c;
	int  i;

	pos = 0;
	n = 0;
	while ((c = next()) != EOF)
		n++;
	printf("char: %d\n", n);

	pos = 0;
	n = 0;
	while ((i = next()) != EOF)
		n++;
	printf("int:  %d\n", n);
	return 0;
}
```

<!-- out @impl -->

```
char: 2
int:  5
```

**نفس البيانات، ونفس الحلقة، وجوابان.** البايت `0xFF` بيانٌ صحيح؛ لكنه حين
يُخزَّن في `char` ذي إشارة يصير `-1`، وهي بعينها قيمة `EOF`. فالحلقة تظنّ أن
الملفّ انتهى وتتوقّف عند الثالث.

**والخطأ صامت.** لا تحذير، ولا تعطّل، ولا بايتاتٌ مشوّهة — بياناتٌ ناقصة فقط.
وبرنامجٌ يقرأ نصّاً إنجليزياً لن يلمسه أبداً، لأن `0xFF` لا يظهر في ASCII. ثم يصل
ملفٌّ عربيّ أو صورة، فيقصّ البرنامج نفسه من نصفه.

**القاعدة: ما يُقرأ من الدخل يُخزَّن في `int`، ويُقارَن بـ`EOF`، ثم يُنقل إلى
`char`.**

## النصّ العربيّ بايتاتٌ لا حروف

ASCII سبع bits: ١٢٨ رمزاً، ولا حرف عربيّ فيها. والاتّفاق الذي يحلّها **UTF-8**،
وفيه الحرف الواحد **أكثر من بايت**.

```c
#include <stdio.h>
#include <string.h>

int main(void)
{
	char s[] = "مدى";

	printf("%zu\n", strlen(s));
	printf("%zu\n", sizeof s);
	for (size_t i = 0; i < strlen(s); i++)
		printf("%02X ", (unsigned char)s[i]);
	printf("\n");
	return 0;
}
```

<!-- out @impl -->

```
6
7
D9 85 D8 AF D9 89 
```

**ثلاثة حروفٍ في ستّة بايتات**، وسابعٌ للصفر الختاميّ. كل حرفٍ عربيّ بايتان في
UTF-8، والإنجليزيّ بايتٌ واحد.

فـ`strlen` **لا تعدّ الحروف**؛ تعدّ البايتات إلى أوّل صفر. وهي محقّة: اللغة لا
تعرف ما هو الحرف أصلاً (البديهية ٥).

**وما يتساقط من هذا:**

- `s[0]` ليس حرفاً، بل **نصف** حرف. وطباعته وحده تعطي رمزاً مكسوراً.
- عكس النصّ بايتاً بايتاً **يفسده**.
- قصّ النصّ عند بايتٍ محسوب قد يقطع حرفاً في نصفه.

ولاحظ أن `printf("%s")` تطبعه سليماً: هي ترمي البايتات إلى الـterminal، **والـterminal**
هي التي تفهم UTF-8. لا البرنامج ولا اللغة.

## الهروب

بعض الرموز لا تُكتب داخل النصّ مباشرةً، فلها صيغةٌ تبدأ بـ`\`:

```c
#include <stdio.h>

int main(void)
{
	printf("%d %d %d %d\n", '\n', '\t', '\0', '\\');
	printf("%d %d\n", '\x41', '\101');
	return 0;
}
```

<!-- out @impl -->

```
10 9 0 92
65 65
```

| | |
|---|---|
| `\n` `\t` `\r` | سطرٌ جديد · مسافة جدولة · عودة إلى أوّل السطر |
| `\0` | البايت الصفريّ — نهاية النصّ |
| `\\` `\"` `\'` | الرمز نفسه حين يلتبس بالصيغة |
| `\x41` | بايتٌ بقيمته السِّتّ عشريّة |
| `\101` | بايتٌ بقيمته **الثمانيّة** — ولا تحتاج بادئة `x` |

والصيغتان الأخيرتان تعطيان `A` نفسه. `\0` ليست حالةً خاصّة: هي `\` وصفرٌ
ثمانيّ — أي البايت صفر.

## دوالّ `<ctype.h>` وشرطها

المكتبة تعطيك أسئلةً جاهزة عن البايت: `isalpha` و`isdigit` و`isspace`،
و`toupper` و`tolower`.

```c
#include <stdio.h>
#include <ctype.h>

int main(void)
{
	char c = 'a';

	printf("%d %d %d\n", isalpha('A'), isdigit('7'), isspace(' '));
	printf("%c %c\n", toupper((unsigned char)c), tolower('Z'));
	return 0;
}
```

<!-- out -->

```
1 1 1
A z
```

**وكلّها تأخذ `int`، وشرطها مكتوب** (§7.4): يجب أن تكون القيمة ممثَّلةً كـ
`unsigned char`، أو `EOF`. وما عدا ذلك **سلوكٌ غير معرَّف**.

فحين تمرّر `char` قد يكون سالباً — بايتٌ عربيّ مثلاً — فأنت خارج الشرط، لأن هذه
الدوالّ تُنفَّذ عادةً بجدولٍ يُفهرَس بالقيمة، والفهرس السالب يقرأ ما قبل الجدول.

**ولذلك تراها في الكود الجيّد دائماً هكذا:**

```c
toupper((unsigned char)c)
```

الـ`cast` هنا ليس تجميلاً ولا عادة. هو ما يجعل الاستدعاء داخل الشرط.

## قبل أن تكمل

> **١.** في الإقليم ٠١، دالّة `split` تقارن `*p == ' '`. ماذا يحدث لو كان في
> السطر مسافة جدولة بدل مسافة؟ وأي دالّةٍ من `<ctype.h>` تحلّها، وبأي `cast`؟
>
> **٢.** اكتب دالّةً تحوّل نصّاً إلى حالةٍ كبيرة **بلا** `<ctype.h>`، بقلب bit
> واحدة. ثم أعطِها `"مدى"` — ماذا تخرج، ولماذا؟
>
> **٣.** `strlen("مدى")` ستّة. اكتب دالّةً تعدّ **الحروف** لا البايتات في UTF-8.
> (التلميح الوحيد: انظر إلى البتّتين العلييَن من كل بايت — `10` بادئة، وما عداها
> بداية حرف.)
