# الإقليم ٠١ — حلقة الأوامر

> ستبني في هذا الإقليم برنامجاً يعمل: **حلقةٌ تقرأ أمراً وتنفّذه**. تكتب فيها
> `set name ali` فتحفظ، و`get name` فتُرجِع، و`list` فتعرض.
>
> مئةٌ وعشرون سطراً. وحين تنتهي، سيكون فيها **ثلاثة أخطاء** لا يكشفها استعمالٌ
> عاديّ، وكلٌّ منها بابٌ لإقليم.
>
> **وهذا البرنامج هو مرجع المنهج كلّه.** كل ما يأتي بعده يفكّكه أو يمدّه — حتى
> الإقليم الأخير، حيث تصير الحلقة نفسها قادرةً على تشغيل أوامر النظام.
>
> اكتبه بيدك. لا تنسخه.

---

## أوّل ملفّ

افتح ملفاً اسمه `main.c` واكتب فيه هذا بالضبط:

```c
#include <stdio.h>

int main(void)
{
	printf("hello\n");
	return 0;
}
```

ثم في الـterminal، في نفس المجلّد:

```bash
cc -std=c17 -Wall -Wextra -o main main.c
./main
```

<!-- out -->

```
hello
```

الأمر الأول حوّل نصّك إلى ملفٍّ تنفيذيّ اسمه `main`، والثاني شغّله.

وفي الملفّ أربعة أشياء ستراها في كل برنامج C بعده:

| | |
|---|---|
| `#include <stdio.h>` | يجلب **إعلانات** دوالّ الدخل والخرج، ومنها `printf` |
| `int main(void)` | نقطة البدء. النظام ينادي هذه بالاسم |
| `{ … }` | القوسان يحدّدان جسم الدالّة |
| `return 0;` | ما تخبر به النظام: صفرٌ يعني «تمّ بلا خطأ» |

و`\n` داخل النصّ ليس حرفين، بل **حرفٌ واحد**: سطرٌ جديد. احذفه وأعِد التشغيل
لترى الفرق.

**وفي الجدول كذبةٌ مؤقّتة**: `#include` ليس «استيراداً». الإقليم ١٨ يكشف ما يفعله
حقاً، وهو أبسط وأخشن ممّا تظنّ.

---

## سطرٌ من الدخل

البرنامج الآن يتكلّم ولا يسمع. اجعله يقرأ:

<!-- part: 01-echo -->

```c
#include <stdio.h>
#include <string.h>

int main(void)
{
	char line[128];

	while (1) {
		printf("> ");
		fflush(stdout);
		if (fgets(line, sizeof line, stdin) == NULL)
			break;
		line[strcspn(line, "\n")] = '\0';
		printf("[%s]\n", line);
	}
	return 0;
}
```

ترجم وشغّل، واكتب سطرين ثم اضغط **Ctrl-D**:

<!-- out -->

```
> set name ali
[set name ali]
> hello
[hello]
>
```

`while (1)` حلقةٌ لا تنتهي بنفسها. تنتهي بـ`break`، و`break` يقع حين تُرجع
`fgets` قيمة `NULL` — أي حين ينتهي الدخل. وCtrl-D هو ما يُنهيه: لا يُطبع شيئاً،
فيبقى الـprompt الأخير وحده على الشاشة ويعود البرنامج.

**و`char line[128]` صندوقٌ ثابت الحجم**: مئةٌ وثمانية وعشرون بايتاً، لا تكبر ولا
تصغر. احفظ هذا الرقم؛ سنعود إليه في آخر الإقليم.

أمّا سطر `strcspn` فيمسح السطر الجديد الذي تتركه `fgets` في آخر ما قرأت. جرّب
حذفه لترى لماذا هو موجود.

## من سطرٍ إلى كلمات

الأمر `set name ali` ثلاث كلمات. البرنامج يحتاج أن يفصلها.

```c
#define MAX_WORDS 8

int split(char *line, char **words)
{
	int n = 0;
	char *p = line;

	while (*p != '\0' && n < MAX_WORDS) {
		while (*p == ' ')
			p++;
		if (*p == '\0')
			break;
		words[n] = p;
		n++;
		while (*p != '\0' && *p != ' ')
			p++;
		if (*p == ' ') {
			*p = '\0';
			p++;
		}
	}
	return n;
}
```

ضعها فوق `main`، واستبدل سطر الطباعة بهذا:

<!-- part: 01-split -->

```c
		int n = split(line, words);
		for (int i = 0; i < n; i++)
			printf("%d: [%s]\n", i, words[i]);
```

وأضِف `char *words[MAX_WORDS];` بجانب `line`.

<!-- out -->

```
> set name ali
0: [set]
1: [name]
2: [ali]
>    get   x  
0: [get]
1: [x]
>
```

المسافات الزائدة اختفت وحدها، والكلمتان خرجتا نظيفتين.

---

## ما الذي فعلته `split` فعلاً

**لم تنسخ حرفاً واحداً.**

`p` يمشي داخل `line` نفسه. وعند كل كلمة يسجّل `words[n]` **موضع بدايتها**، ثم
يستبدل المسافة التي تليها بالبايت `'\0'`.

```
line:  s  e  t  \0 n  a  m  e  \0 a  l  i  \0
       ↑           ↑              ↑
    words[0]    words[1]       words[2]
```

فالكلمات الثلاث تسكن **نفس الصندوق**، والذي فصلها هو ثلاثة أصفارٍ زُرعت مكان
المسافات. وهذا هو الاتّفاق الذي رأيتَه في الفصل صفر: النصّ ينتهي عند أوّل صفر.

**والمكسب أن `split` مجّانية**: لا حجز ولا نسخ، مهما طال السطر. **وثمنها** أنك
لو غيّرت `line` بعدها، تغيّرت الكلمات كلّها معاً — لأنها ليست نسخاً، بل **مواضع**
فيه.

النجمة في `char *p` وفي `char **words` هي موضوع الإقليمين ١١ و١٤. لا تحتاج فهمها
الآن؛ تحتاج أن تراها تعمل.

## السجلّ والجدول

الآن الذاكرة. كل ما يحفظه البرنامج **سجلّ**: مفتاحٌ وقيمة.

```c
#include <stdlib.h>

#define MAX_ITEMS 64

struct Item {
	char  key[16];
	char *value;
};

struct Item table[MAX_ITEMS];
int items = 0;

struct Item *find(char *key)
{
	for (int i = 0; i < items; i++)
		if (strcmp(table[i].key, key) == 0)
			return &table[i];
	return NULL;
}
```

`struct Item` نوعٌ جديد صنعتَه أنت: بايتاتٌ متتابعة، ستّة عشر منها للمفتاح، ثم
موضعٌ لعنوان القيمة.

و`table` array من أربعةٍ وستّين منها، و`items` عدد المشغول فعلاً.

**ولاحظ `strcmp(a, b) == 0`.** لم أكتب `a == b`. الأولى تقارن **الحروف**،
والثانية تقارن شيئاً آخر تماماً — ستعرف ماذا في الإقليم ١٣.

---

## الأوامر الأربعة

القيمة لا تسكن السجلّ، بل يسكنه **عنوانها**. فمن يحجز لها مكاناً؟

```c
char *copy(char *s)
{
	char *p = malloc(strlen(s) + 1);
	strcpy(p, s);
	return p;
}
```

`malloc` تطلب من النظام عدداً من البايتات وتُرجع عنوان أوّلها. و`strlen(s) + 1`
هو الطول **زائد موضعٍ للصفر الختاميّ**. احذف الواحد وسترى.

<!-- part: 01-cmd -->

```c
void cmd_set(char *key, char *value)
{
	struct Item *it = find(key);

	if (it == NULL) {
		it = &table[items];
		items++;
		strcpy(it->key, key);
	}
	it->value = copy(value);
}

void cmd_get(char *key)
{
	struct Item *it = find(key);

	if (it == NULL)
		printf("(none)\n");
	else
		printf("%s\n", it->value);
}

void cmd_del(char *key)
{
	struct Item *it = find(key);

	if (it == NULL)
		return;
	free(it->value);
	*it = table[items - 1];
	items--;
}

void cmd_list(void)
{
	for (int i = 0; i < items; i++)
		printf("%-8s %s\n", table[i].key, table[i].value);
}
```

`cmd_del` لا تزحزح شيئاً: تنقل **آخر** سجلٍّ إلى مكان المحذوف وتنقص العدّاد. وهذا
يعني أن `list` بعد الحذف تعرض بترتيبٍ مختلف — تصميمٌ لا خطأ.

## الحلقة تربط الكلّ

<!-- part: 01-cmd -->

```c
int main(void)
{
	char  line[128];
	char *words[MAX_WORDS];

	while (1) {
		printf("> ");
		fflush(stdout);
		if (fgets(line, sizeof line, stdin) == NULL)
			break;
		line[strcspn(line, "\n")] = '\0';

		int n = split(line, words);
		if (n == 0)
			continue;

		if (strcmp(words[0], "set") == 0 && n == 3)
			cmd_set(words[1], words[2]);
		else if (strcmp(words[0], "get") == 0 && n == 2)
			cmd_get(words[1]);
		else if (strcmp(words[0], "del") == 0 && n == 2)
			cmd_del(words[1]);
		else if (strcmp(words[0], "list") == 0)
			cmd_list();
		else if (strcmp(words[0], "quit") == 0)
			break;
		else
			printf("?\n");
	}
	return 0;
}
```

الشرط `&& n == 3` ليس تجميلاً: بدونه يقرأ `cmd_set` كلمةً ثانيةً وثالثةً لم
تُكتبا. واللغة لن تمنعك.

## الجلسة

ترجم بالأمر نفسه، وشغّل، وجرّب:

<!-- out -->

```
> set name ali
> set lang c
> get name
ali
> list
name     ali
lang     c
> del name
> list
lang     c
> get name
(none)
> quit
```

**يعمل.** مئةٌ وعشرون سطراً كتبتَها بيدك، فيها نوعٌ صنعتَه، ودالّةٌ تمشي في
الذاكرة، وحجزٌ من النظام، وحلقةٌ تقرأ من الدخل.

وكل إقليمٍ بعد هذا يأخذ جزءاً منها ويسأل: **لماذا هكذا، وأين يكسر؟**

## ثلاثة أخطاء

البرنامج يعمل، وفيه ثلاثة أخطاء. لا يكشفها استعمالٌ عاديّ، وكلٌّ منها لا يزال
موجوداً في برامجَ تعمل اليوم في العالم.

**الأول — المفتاح الطويل.** `key` ستّة عشر بايتاً، و`strcpy` تكتب ما أعطيتَها
مهما طال. جرّب مفتاحاً من ثلاثين حرفاً ثم `list`. **ولن يشتكي المترجم.**
← الإقليمان ١٣ و٢٦.

**الثاني — الإسناد المتكرّر.** `set x 1` ثم `set x 2`: من يحجز الجديد رأيتَه، فمن
يعيد القديم؟ لا أحد. البايتات الأولى صارت غير قابلةٍ للوصول وغير محرَّرة.
← الإقليم ١٦.

**الثالث — السطر الطويل.** الصندوق مئةٌ وثمانية وعشرون بايتاً، وأنت لم تفحص ما
يحدث لسطرٍ أطول. لن يُرفض ولن يُقصّ بصخب: **سيصير أمرين.** ← الإقليم ٢١.

---

## قبل أن تكمل

ثلاثة أسئلة. اكتب جوابك المتوقّع أوّلاً، ثم افحصه على البرنامج نفسه:

> **١.** ماذا يحدث عند `set` رقم ٦٥؟ الجدول أربعةٌ وستّون، والعدّاد لا يُفحَص.
>
> **٢.** `del` تنقل آخر سجلٍّ إلى مكان المحذوف. فماذا يحدث حين يكون المحذوف هو
> آخر سجلٍّ بنفسه؟
>
> **٣.** ولماذا يعمل `fflush(stdout)`؟ احذفه وشغّل — ثم شغّل مرّةً أخرى وقد
> وجّهتَ المخرَج إلى ملفّ: `./main > out.txt`. الجوابان مختلفان.

ولا تبحث عن الأجوبة الآن. سجّلها، وسترى متى تُغلق.
