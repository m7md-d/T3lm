# الإقليم ٠٨ — المسار

> كتبتَ في الإقليم ٠١ `while (1)` و`if` و`else if` وقبلتَها بلا سؤال.
>
> هنا تعرف ما الذي يجعلها تعمل: أن C **لا تعرف الصواب والخطأ**، وأن `for` سكّرٌ
> على `while`، وأن `switch` قفزةٌ لا سلسلةُ شروط — ولذلك يسقط من حالةٍ إلى التي
> بعدها ما لم تمنعه.

---

## لا يوجد «صحيح» و«خطأ»

C تفحص **عدداً**: الصفر كذب، وكل ما عداه صدق.

```c
#include <stdio.h>
#include <stdbool.h>

int main(void)
{
	printf("%d %d %d %d\n", !0, !1, !5, !!5);
	printf("%d %d\n", 3 > 2, 2 > 3);

	bool t = 5;
	printf("%d %zu\n", t, sizeof(bool));

	if (-1)
		printf("سالبُ واحدٍ صحيح\n");
	return 0;
}
```

<!-- out -->

```
1 0 0 1
1 0
1 1
سالبُ واحدٍ صحيح
```

**`-1` صحيح.** الشرط لا يسأل «هل هذا صواب» بل «هل هذا غير صفر».

والمقارنات تُرجع `int`: واحداً أو صفراً بالضبط. ولذلك `(a > b) + (c > d)` تعبيرٌ
سليم يعدّ كم شرطاً تحقّق.

**و`!!x`** ليست حشواً: نفيان يحوّلان أي قيمةٍ إلى صفرٍ أو واحد. وهي الطريقة
القديمة لتسوية قيمةٍ قبل مقارنتها.

**و`bool` وصلت متأخّرة.** لم تكن في اللغة أصلاً؛ أُضيفت `_Bool` في C99 ومعها
`<stdbool.h>`، ثم صارت `bool` كلمةً أصيلة في C23. وهي **ليست bit واحدة** —
بايتٌ كامل — لكنها تحفظ صفراً أو واحداً فقط: أسندتَ إليها خمسةً فصارت واحداً.

## الفاصلة المنقوطة الضالّة

```c
#include <stdio.h>

int main(void)
{
	int x = 0;

	if (x);
		printf("طُبعت\n");
	return 0;
}
```

<!-- out -->

```
طُبعت
```

**الشرط كاذب، والسطر طُبع.** لأن جسم `if` هو الفاصلة المنقوطة وحدها — جملةٌ فارغة
سليمة — و`printf` خارج الشرط، والإزاحة لا تعني شيئاً للمترجم.

<!-- warn @impl -->

```
warning: if statement has empty body
```

**والإزاحة في C تجميلٌ محض.** لا تحمل معنى، ولا يقرؤها المترجم. وهذا يجعل الأقواس
المعقوفة قراراً في السلامة لا في الذوق — واللقطة التالية تُظهر لماذا.

## `else` تلتصق بالأقرب

```c
#include <stdio.h>

void f(int a, int b)
{
	if (a)
		if (b)
			printf("كلاهما\n");
		else
			printf("إلى مَن تعود هذه؟\n");
}

int main(void)
{
	f(1, 0);
	f(0, 0);
	return 0;
}
```

<!-- out -->

```
إلى مَن تعود هذه؟
```

الإزاحة تقول إن `else` تتبع `if (a)`. **والمترجم يربطها بـ`if (b)`.**

والدليل في المخرَج: `f(0, 0)` لم تطبع شيئاً. لو كانت `else` تتبع الشرط الخارجيّ
لطبعت.

**والقاعدة: `else` تتبع أقرب `if` بلا `else`.** والحلّ ليس حفظ القاعدة، بل
الأقواس المعقوفة دائماً — حتى لجملةٍ واحدة.

## `for` سكّرٌ على `while`

`for` ليست بنيةً مستقلّة. هي ترتيبٌ لثلاثة أجزاء تكتبها في `while` بيدك:

```c
#include <stdio.h>

int main(void)
{
	for (int i = 0; i < 3; i++)
		printf("%d", i);
	printf("\n");

	{
		int i = 0;
		while (i < 3) {
			printf("%d", i);
			i++;
		}
	}
	printf("\n");
	return 0;
}
```

<!-- out -->

```
012
012
```

```
for (تهيئة; شرط; تقدّم)          تهيئة;
	جسم                 ⇔      while (شرط) { جسم; تقدّم; }
```

**والمكسب الحقيقيّ ليس الاختصار، بل أن الأجزاء الثلاثة في سطرٍ واحد.** حلقةٌ
تقدُّمها في آخر جسمها الطويل تُنسى بسهولة، والنسيان حلقةٌ لا تنتهي.

**وفرقٌ واحد يبقى:** `continue` في `for` تقفز إلى **التقدّم**، وفي `while` تقفز
إلى الشرط مباشرةً — فتتخطّى الزيادة وتدور بلا نهاية. هذا أشهر خطأٍ في تحويل
حلقةٍ من صيغةٍ إلى أخرى.

**والأجزاء الثلاثة كلّها اختيارية:** `for (;;)` حلقةٌ أبدية مثل `while (1)`.

## `do` والحالة التي تستحقّها

```c
#include <stdio.h>

int main(void)
{
	int i = 10;

	while (i < 3)
		printf("while %d\n", i++);

	i = 10;
	do
		printf("do %d\n", i++);
	while (i < 3);
	return 0;
}
```

<!-- out -->

```
do 10
```

**الأولى لم تدر، والثانية دارت مرّة.** لأن `do` تفحص الشرط **بعد** الجسم.

وموضعها واحد: حين يكون الجسم هو الذي **ينتج** ما يُفحَص — قراءة سطرٍ ثم فحصه،
أو محاولةٌ ثم فحص نتيجتها. وفي غيره `while` أوضح.

**ولا تنسَ الفاصلة المنقوطة بعد `while` الأخيرة.** إسقاطها يعطي رسالةً غامضة،
لأن ما بعدها يصير جسم حلقةٍ جديدة.

## `switch` قفزةٌ لا سلسلة شروط

هذا هو أهمّ ما في الإقليم، ومصدر أخطاءٍ حقيقية:

```c
#include <stdio.h>

void f(int n)
{
	switch (n) {
	case 1:
		printf("واحد ");
	case 2:
		printf("اثنان ");
		break;
	case 3:
		printf("ثلاثة ");
		break;
	default:
		printf("غيره ");
	}
	printf("\n");
}

int main(void)
{
	f(1);
	f(2);
	f(3);
	f(9);
	return 0;
}
```

<!-- out -->

```
واحد اثنان 
اثنان 
ثلاثة 
غيره 
```

**`f(1)` طبعت سطرين.** لأن `case` **علامةُ دخول** لا فرعٌ مغلق: التنفيذ يقفز
إليها ثم **يواصل** حتى يصادف `break` أو نهاية القوس.

وهذا ليس عيباً؛ هو ما يجعل `switch` تُترجَم أحياناً إلى **جدول قفز** — array من
العناوين يُفهرَس بالقيمة — فتصير كلفتها واحدة مهما كثرت الحالات، بخلاف سلسلة
`else if` التي تُفحَص واحدةً واحدة.

**وثمن ذلك ثلاثة قيود:**

| | |
|---|---|
| قيم `case` **ثوابت** تُعرَف وقت الترجمة | لا `case x:` ولا مدى |
| النوع **صحيح** | لا نصوص ولا عشريّ |
| السقوط هو الأصل | و`break` هو ما تكتبه أنت |

**والسقوط المقصود يُكتَب عليه تعليق** — `/* fallthrough */` — لأن قارئك لا يعرف
هل قصدتَ أم نسيت. وهذا اصطلاحٌ يفحصه بعض المترجمين.

## `goto`، ولماذا بقي

سمعتُه سيّئة، وله في C موضعٌ واحدٌ يفوز فيه على كل بديل: **التنظيف عند الفشل.**

C لا تملك شيئاً يُنفَّذ تلقائياً عند الخروج من دالّة. فدالّةٌ تحجز ثلاثة موارد
وتفشل عند الثالث يجب أن تحرّر الأوّلين بيدها — **في كل مسار خروج**.

```c
#include <stdio.h>
#include <stdlib.h>

int build(int fail_at)
{
	char *a = NULL, *b = NULL, *c = NULL;
	int   rc = -1;

	a = malloc(8);
	if (a == NULL || fail_at == 1)
		goto out;
	b = malloc(8);
	if (b == NULL || fail_at == 2)
		goto out_a;
	c = malloc(8);
	if (c == NULL || fail_at == 3)
		goto out_b;

	rc = 0;
	free(c);
out_b:
	free(b);
out_a:
	free(a);
out:
	printf("fail_at=%d rc=%d\n", fail_at, rc);
	return rc;
}

int main(void)
{
	build(1);
	build(2);
	build(3);
	build(0);
	return 0;
}
```

<!-- out -->

```
fail_at=1 rc=-1
fail_at=2 rc=-1
fail_at=3 rc=-1
fail_at=0 rc=0
```

**العلامات مرتّبةٌ عكس الحجز**، فكل مسارٍ يحرّر ما حُجز قبله بالضبط ولا يحرّر ما
لم يُحجَز. والبديل — تكرار `free` في كل فرع — يكبر تربيعياً ويُنسى منه سطر.

**وشرطان يجعلانه مقبولاً:** أن تكون القفزة **إلى الأمام** دائماً، وأن تكون داخل
الدالّة الواحدة (واللغة تمنع غير ذلك أصلاً).

هذه الصيغة تملأ نواة لينكس، وليست استثناءً يُعتذر عنه. **وستعود إليها في الإقليم
١٦** حين يصير الحجز حقيقياً.

---

## قبل أن تكمل

> **١.** أعِد كتابة `f` في لقطة `switch` بحيث تعطي نفس المخرَج بالضبط، **بلا**
> `switch`. كم سطراً كلّفك السقوط المقصود؟
>
> **٢.** في الإقليم ٠١، حلقة `main` فيها `continue` بعد `if (n == 0)`. حوّلها إلى
> `for` ثم شغّل — هل تغيّر شيء؟ ولماذا كان الجواب سيختلف لو كان التقدّم في آخر
> الجسم؟
>
> **٣.** `while (i < 3);` بفاصلةٍ منقوطة — ماذا تفعل؟ وهل يحذّر منها المترجم كما
> حذّر من `if (x);`؟ جرّب.
