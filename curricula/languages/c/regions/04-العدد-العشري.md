# الإقليم ٠٤ — العدد العشريّ

> رأيتَ في الإقليم ٠٢ أن `1.0f` بايتاتها `00 00 80 3F`، ولا يشبه أيٌّ منها الواحد.
>
> هنا تعرف لماذا: العشريّ ليس رقماً مخزَّناً، بل **ثلاثة حقولٍ يُحسَب منها رقم**.
> وحين تفهم الحقول الثلاثة تصير كل «غرابات» العشريّ نتيجةً واحدة متوقّعة.

---

## المقايضة التي وُلد منها

عندك ٣٢ bit. تستطيع أن تنفقها على **مدىً** أو على **دقّة**، ولا تجمعهما.

`int` ينفقها كلّها على الدقّة: كل قيمةٍ في مداه ممثَّلةٌ بالضبط، ولا شيء خارجه.
والعشريّ يقترض بعض الـbits ليقول **أين تقع الفاصلة**، فيشتري بها مدىً هائلاً:

| | المدى | الدقّة |
|---|---|---|
| `int` (٤ بايت) | ±2×10⁹ | **كاملة** داخل المدى |
| `float` (٤ بايت) | ±3×10³⁸ | **٦ خاناتٍ عشرية** تقريباً |

نفس البايتات الأربعة، وفرقٌ في المدى بمقدار عشرين رتبة. **والثمن أن أكثر
الأعداد لا تُمثَّل بالضبط** — وبقيّة هذا الإقليم شرحُ هذا الثمن.

---

## الحقول الثلاثة

`float` ثلاثة حقولٍ محشوّة في ٣٢ bit بمعيار IEEE-754: **إشارةٌ** (١) ثم **أُسٌّ**
(٨) ثم **كسرٌ** (٢٣).

```c
#include <stdio.h>
#include <string.h>

void show(const char *label, float f)
{
	unsigned int b;

	memcpy(&b, &f, 4);
	printf("%-6s ", label);
	for (int i = 31; i >= 0; i--) {
		printf("%d", (b >> i) & 1);
		if (i == 31 || i == 23)
			printf(" ");
	}
	printf("  أُسّ=%d\n", (int)((b >> 23) & 0xFF) - 127);
}

int main(void)
{
	show("1.0", 1.0f);
	show("2.0", 2.0f);
	show("0.5", 0.5f);
	show("-1.0", -1.0f);
	show("0.1", 0.1f);
	return 0;
}
```

<!-- out @impl -->

```
1.0    0 01111111 00000000000000000000000  أُسّ=0
2.0    0 10000000 00000000000000000000000  أُسّ=1
0.5    0 01111110 00000000000000000000000  أُسّ=-1
-1.0   1 01111111 00000000000000000000000  أُسّ=0
0.1    0 01111011 10011001100110011001101  أُسّ=-4
```

القاعدة التي تولّد الجدول كلّه:

```
القيمة = (-1)^إشارة × 1.كسر × 2^أُسّ
```

فـ`1.0` هي `1.0 × 2⁰`، و`2.0` هي `1.0 × 2¹` — نفس الكسر، وأُسٌّ زاد واحداً.
و`-1.0` هي `1.0` وقد قُلبت bit واحدة.

**والأُسّ مخزَّنٌ مزاحاً بـ١٢٧** ليصير سالبه موجباً: `01111111` هي ١٢٧، فالأُسّ
صفر. والسبب أن المقارنة بين عشريَّين تصير حينئذٍ مقارنة أعدادٍ صحيحة بنفس ترتيب
الـbits.

---

## الكسر ثنائيّ، ولذلك `0.1` لا تُكتب

انظر السطر الأخير: كسر `0.1` نمطٌ يتكرّر `1001 1001 1001…` ثم يُقطَع عند ٢٣ bit.

السبب أن الكسر مجموع **قوى اثنين سالبة**: نصفٌ وربعٌ وثُمن وهكذا. وعُشرٌ لا يُكتب
مجموعَ أنصافٍ وأرباعٍ مهما طال — تماماً كما لا يُكتب ثُلثٌ عشرياً مهما أطلتَ
الخانات.

```c
#include <stdio.h>

int main(void)
{
	printf("%.20f\n", 0.1);
	printf("%.20f\n", 0.1 + 0.2);
	printf("%.20f\n", 0.3);
	printf("%d\n", 0.1 + 0.2 == 0.3);
	return 0;
}
```

<!-- out @impl -->

```
0.10000000000000000555
0.30000000000000004441
0.29999999999999998890
0
```

**ثلاثة أرقامٍ لا يساوي أيٌّ منها ما كتبتَه.** و`0.1 + 0.2` ليست `0.3` لأنهما
عددان مختلفان فعلاً — الفرق في الخانة السابعة عشرة، وهو حقيقيّ لا وهم.

**والخطأ ليس في العشريّ ولا في المترجم.** أنت طلبتَ كتابة عددٍ لا يُكتب في هذا
النظام، فكُتب أقربُ ما يمكن، ثم تراكم الفرق.

---

## الدقّة تنفد فجأة

هذه اللقطة تكسر أكثر ممّا يتوقّع الناس:

```c
#include <stdio.h>

int main(void)
{
	float f = 16777216.0f;

	printf("%.1f\n", f);
	printf("%.1f\n", f + 1.0f);
	printf("%d\n", f == f + 1.0f);
	return 0;
}
```

<!-- out @impl -->

```
16777216.0
16777216.0
1
```

**`f + 1` تساوي `f`.** والرقم ليس عشوائياً: `16777216` هو `2²⁴`، وكسر `float`
٢٣ bit. فوق هذا الحدّ تصير المسافة بين عددين متجاورين **اثنين**، ثم أربعة، ثم
ثمانية.

فالحدّ العمليّ: **`float` يعدّ الصحيح بدقّةٍ حتى ١٦.٧ مليون فقط.** وعدّادٌ من نوع
`float` يتوقّف عن الزيادة عند هذا الرقم بلا خطأ وبلا تحذير.

و`double` يؤجّل الحدّ إلى `2⁵³` — نحو تسعة كوادريليون — ولا يلغيه.

---

## والخطأ يتراكم

```c
#include <stdio.h>

int main(void)
{
	double total = 0.0;

	for (int i = 0; i < 100; i++)
		total += 0.01;
	printf("%.20f\n", total);
	printf("%d\n", total == 1.0);
	return 0;
}
```

<!-- out @impl -->

```
1.00000000000000066613
0
```

مئة قرشٍ ليست ريالاً. وكل جمعةٍ أضافت خطأً صغيراً، وتراكمت المئة.

**ولهذا لا يُحسَب المال بالعشريّ.** الحلّ ليس `double` أدقّ، بل **عدداً صحيحاً
بوحدةٍ أصغر**: احسب بالقروش لا بالريالات، فيعود الحساب دقيقاً تماماً.

والقاعدة العامّة: **العشريّ للقياس، والصحيح للعدّ.** المسافة والوزن ودرجة الحرارة
قياسٌ فيه خطأ أصلاً؛ والمال والفهارس وعدد المستخدمين عدٌّ لا يحتمل خطأً.

---

## قيمٌ ليست أعداداً

الأُسّ حين تكون bitsه كلّها واحدات لا يعني أُسّاً، بل يعني حالةً:

```c
#include <stdio.h>
#include <math.h>

int main(void)
{
	double z = 0.0;
	double inf = 1.0 / z;
	double nan = z / z;

	printf("%f %f\n", inf, -inf);
	printf("%f\n", nan);
	printf("%d %d\n", nan == nan, nan != nan);
	printf("%d %d\n", isnan(nan), isinf(inf));
	return 0;
}
```

<!-- out @impl -->

```
inf -inf
nan
0 1
1 1
```

**القسمة على صفرٍ هنا لا تُعطِّل البرنامج.** وهي تخالف نظيرتها في الأعداد الصحيحة:
`1 / 0` في `int` سلوكٌ غير معرَّف، وفي العشريّ قيمةٌ معرَّفةٌ اسمها `inf`.

**و`nan != nan`.** هذا هو الشيء الوحيد في اللغة الذي لا يساوي نفسه، وهو مقصود:
`nan` تعني «ليس عدداً»، وسؤال «هل هذا العدد يساوي ذاك» بلا معنى إن لم يكن أحدهما
عدداً. فافحصه بـ`isnan` لا بـ`==`.

`0.0 / 0.0` تعطي `nan`، و`1.0 / 0.0` تعطي `inf` — والفرق أن الثانية لها حدٌّ
رياضيّ والأولى لا.

---

## كيف يُقارَن إذن

`==` لا يصلح. والبديل الشائع مقارنةٌ بهامش، **وله حدٌّ يجب أن تعرفه**:

```c
#include <stdio.h>
#include <float.h>
#include <math.h>

int close_enough(double a, double b, double eps)
{
	return fabs(a - b) <= eps * fmax(fabs(a), fabs(b));
}

int main(void)
{
	printf("FLT_DIG = %d، DBL_DIG = %d\n", FLT_DIG, DBL_DIG);
	printf("FLT_EPSILON = %g\n", FLT_EPSILON);
	printf("%d\n", close_enough(0.1 + 0.2, 0.3, 1e-12));
	printf("%d\n", close_enough(1e-20, 0.0, 1e-12));
	return 0;
}
```

<!-- out @impl -->

```
FLT_DIG = 6، DBL_DIG = 15
FLT_EPSILON = 1.19209e-07
1
0
```

الهامش **نسبيّ** لا مطلق: خطأُ `float` عند الألف أكبر منه عند الواحد، فالهامش
الثابت خاطئ في أحد الطرفين.

**والسطر الأخير هو الحدّ:** `1e-20` قريبةٌ من الصفر بأي معيارٍ إنسانيّ، والمقارنة
النسبية تقول لا — لأن النسبة إلى صفرٍ بلا معنى. **فالمقارنة قرب الصفر تحتاج هامشاً
مطلقاً**، ولا توجد دالّةُ مقارنةٍ واحدة تصلح لكل الحالات.

و`DBL_DIG = 15` هو الوعد: خمس عشرة خانةً عشرية تمرّ من `double` وتعود كما دخلت.

---

## رماديةٌ أخيرة: أين يُحسَب

المواصفة تسمح بأن يُحسَب تعبيرُ `float` **بدقّةٍ أعلى** من نوعه، ثم يُقصَّ عند
الإسناد. وأثر ذلك أن نتيجةً وسيطةً قد تختلف باختلاف المترجم أو flagsه.

والماكرو `FLT_EVAL_METHOD` في `<float.h>` يعلن الاختيار: `0` يعني أن كل نوعٍ
يُحسَب بدقّته، و`1` أن `float` يُحسَب بدقّة `double`، و`2` أن الجميع يُحسَب
بـ`long double`.

**والـflag الذي يكسر الباب كلّه `-ffast-math`**: يأذن للمترجم بأن يعامل الحساب
العشريّ كأنه رياضياتٌ حقيقية — فيعيد ترتيب الجمع، ويفترض ألّا `nan` ولا `inf`.
مقطعٌ صحيحٌ يصير خاطئاً به بلا أن يتغيّر حرفٌ فيه.

---

## قبل أن تكمل

> **١.** ما أصغر عددٍ موجب يمكن أن يمثّله `float`؟ الأُسّ ثماني bits، وقيمتان
> منها محجوزتان (كلّها أصفار، وكلّها واحدات). فما بقي؟
>
> **٢.** `float f = 0.1f;` ثم `double d = f;` — هل `d == 0.1`؟ توقّع، ثم شغّل،
> ثم اطبع الاثنين بـ`%.20f`.
>
> **٣.** اكتب `close_enough` تعمل قرب الصفر وبعيداً عنه معاً. وحين تعجز عن كتابة
> واحدةٍ تصلح للحالتين، اكتب لماذا عجزت — ذلك هو الجواب.
