# الإقليم ٠٩ — الدالّة

> كتبتَ في الإقليم ٠١ ستّ دوالّ ونادَيتَها. هنا تعرف ما الذي يحدث فعلاً عند
> النداء: أين تسكن المتغيّرات المحلّية، ومتى تموت، ولماذا لا تستطيع دالّةٌ أن
> تغيّر ما أعطيتَها.
>
> وفي آخره أوّل حائطٍ حقيقيّ في هذا المنهج: مشكلةٌ لا تُحلّ بما تعرفه، وحلّها هو
> الإقليم ١١.

---

## النداء قفزةٌ وعودة

الدالّة اسمٌ لقطعةٍ من التعليمات. والنداء ثلاثة أشياء تحدث معاً:

```
١) تُحفَظ الوسائط في موضعٍ متّفقٍ عليه
٢) يُحفَظ عنوان العودة — أين نكمل بعد الانتهاء
٣) يُقفَز إلى أوّل الدالّة
```

والخطوة الثانية هي المهمّة: **البرنامج يترك لنفسه ملاحظةً** بأين كان. ولذلك تستطيع
نداء الدالّة نفسها من عشرة مواضع وتعود إلى الصحيح في كل مرّة.

وهذه الملاحظات تُكدَّس فوق بعضها، والمكان الذي تُكدَّس فيه اسمه **الـstack**،
وستراه بعينك بعد ثلاث لقطات.

---

## المترجم يريد أن يعرف قبل أن ينادي

اكتب النداء قبل الدالّة، بلا إعلانٍ سابق:

```c
#include <stdio.h>

int main(void)
{
	int n = square(5);

	printf("%d\n", n);
	return 0;
}

int square(int x)
{
	return x * x;
}
```

<!-- err -->

```
error: call to undeclared function 'square'; ISO C99 and later do not support implicit function declarations
```

**والرسالة تحمل تاريخها:** «ISO C99 وما بعدها لا تدعم». أي أن هذا كان **مسموحاً**
قبل ١٩٩٩: يفترض المترجم أن الدالّة تُرجع `int` ويمرّر ما أعطيتَه بلا فحص.

فإن كانت تُرجع `double`، أو تأخذ `long` وأعطيتَها `int`، **لا يعترض أحد** —
وتقرأ الدالّة بايتاتٍ ليست لها.

والحلّ **الـprototype**: سطرٌ يقول الاسم والنوع بلا جسم.

```c
#include <stdio.h>

int square(int x);          /* إعلان: يقول النوع */

int main(void)
{
	printf("%d\n", square(5));
	return 0;
}

int square(int x)           /* تعريف: يقول الجسم */
{
	return x * x;
}
```

<!-- out -->

```
25
```

**والفرق بين الإعلان والتعريف هو مفتاح الإقليم ١٨** حيث تتفرّق الدوالّ على ملفّات.

---

## `f()` ليست `f(void)`

فخٌّ باقٍ من زمن ما قبل الـprototype:

```c
#include <stdio.h>

void f();

int main(void)
{
	f(1, 2, 3);
	return 0;
}

void f(void)
{
	printf("نُودِيت\n");
}
```

<!-- out -->

```
نُودِيت
```

**ثلاثة وسائط لدالّةٍ لا تأخذ شيئاً، والبرنامج يعمل.** لأن `void f();` في C17 لا
تعني «بلا وسائط»؛ تعني **«الوسائط غير محدَّدة، فلا تفحص»**.

<!-- warn @impl -->

```
warning: passing arguments to 'f' without a prototype is deprecated
```

**فاكتب `void` صراحةً** في كل دالّةٍ بلا وسائط. و C23 أنهت الفرق أخيراً وجعلت
`()` تعني `(void)` — بعد خمسين سنة.

---

## الـstack بعينك

كل نداءٍ يأخذ شريحةً جديدة من الـstack اسمها **الـframe**، وفيها متغيّراته
المحلّية.

<!-- runs -->

```c
#include <stdio.h>

void level3(void) { int x; printf("3: %p\n", (void *)&x); }
void level2(void) { int x; printf("2: %p\n", (void *)&x); level3(); }
void level1(void) { int x; printf("1: %p\n", (void *)&x); level2(); }

int main(void)
{
	int x;

	printf("m: %p\n", (void *)&x);
	level1();
	return 0;
}
```

<!-- out @machine: العناوين تختلف بين تشغيلين، والذي يُقرأ هو الاتّجاه والمسافة -->

```
m: 0x16b242578
1: 0x16b24254c
2: 0x16b24252c
3: 0x16b24250c
```

**أربعة متغيّراتٍ اسمها `x`، وأربعة عناوين.** كلٌّ في frame ندائه، ولا يرى أحدها الآخر.

والعناوين **تنقص** كلّما تعمّق النداء: الـstack على هذا الهدف ينمو نحو العناوين
الأدنى. وهذا قرار منصّة لا لغة — والمواصفة لا تذكر stack أصلاً.

**وما يهمّك منه:** أن عمق النداء له ثمنٌ في الذاكرة، وأن الثمن يُدفَع تلقائياً
ويُستردّ تلقائياً. الإقليم ١٥ يصل بهذا إلى حدّه.

---

## والـframe يُترَك، لا يُنظَّف

حين تعود الدالّة، **لا يُمسَح الـframe**. يُترَك، ويأخذه النداء التالي.

```c
#include <stdio.h>

void a(void)
{
	int x = 111;
	printf("a: %d\n", x);
}

void b(void)
{
	int y;
	printf("b: %d\n", y);
}

int main(void)
{
	a();
	b();
	return 0;
}
```

<!-- out @ub: ما وقع في هذا التشغيل — والرقم غير موعودٍ به -->

```
a: 111
b: 111
```

**`b` لم تُسنِد شيئاً إلى `y`، وطبعت ١١١.** لأن frame الخاصّ بـ`b` وقع في موضع frame `a`،
و`y` سكنت البايتات التي كانت فيها `x`.

<!-- warn @impl -->

```
warning: variable 'y' is uninitialized when used here
```

**والرقم ١١١ ليس درساً.** الدرس أن قراءة متغيّرٍ محلّيّ قبل إسناد قيمةٍ إليه
**سلوكٌ غير معرَّف**، وأن ما يظهر هو ما تركه غيرك — فيتغيّر بتغيّر ما نُودي قبله،
وقد يعمل شهراً ثم ينهار.

**فأسنِد عند الإعلان.** `int y = 0;` يكلّف تعليمةً واحدة، وقد يحذفها المترجم إن
رأى أنها لا تُقرأ.

## الوسيط نسخة (البديهية ٣)

```c
#include <stdio.h>

void add_one(int n)
{
	n = n + 1;
	printf("داخلها: %d\n", n);
}

int main(void)
{
	int x = 5;

	add_one(x);
	printf("بعدها:  %d\n", x);
	return 0;
}
```

<!-- out -->

```
داخلها: 6
بعدها:  5
```

`n` متغيّرٌ مستقلّ في frame `add_one`، نُسخت إليه قيمة `x` عند النداء. غيّرتَ
النسخة، ثم مات الـframe.

**ولا توجد في C كلمةٌ تعطّل هذا.** لا «تمرير بالمرجع» ولا شيءٌ يشبهه — البديهية
الثالثة بلا استثناء.

---

## قيمةُ إرجاعٍ واحدة، والحيلة المعتادة

`return` يعطي **قيمةً واحدة**. فماذا تفعل دالّةُ قسمةٍ تريد أن تعطيك الناتج
والباقي؟

```c
#include <stdio.h>

int divmod(int a, int b, int *rem)
{
	*rem = a % b;
	return a / b;
}

int main(void)
{
	int r;
	int q = divmod(17, 5, &r);

	printf("%d %d\n", q, r);
	return 0;
}
```

<!-- out -->

```
3 2
```

**الدالّة كتبت في متغيّرٍ يسكن frame `main`.** لم تأخذ نسخةً من `r` — أخذت
**عنوانه**، فوصلت إلى الأصل.

هذه هي الصيغة التي ستراها في نصف الـstandard library، واسمها **الـout parameter**. والنجمتان في `int *rem` و`*rem =` هما موضوع الإقليم ١١ كاملاً.

**ولاحظ ما لم تكسره هذه الحيلة:** الوسيط ما زال نسخةً — نسخةً من **العنوان**.
البديهية الثالثة سليمة.

## الحائط

والآن المشكلة التي لا تُحلّ بما تعرفه:

```c
#include <stdio.h>

int *bad(void)
{
	int x = 42;

	return &x;
}

int main(void)
{
	int *p = bad();

	printf("%d\n", *p);
	return 0;
}
```

<!-- warn @impl -->

```
warning: address of stack memory associated with local variable 'x' returned
```

الدالّة أعطتك عنوان شيءٍ **مات مع الـframe الذي أنشأته**. والمترجم رأى ذلك وقاله.

فإن أردتَ من دالّةٍ أن تُرجع شيئاً أكبر من قيمةٍ واحدة — نصّاً بنته، أو جدولاً
ملأته — فأين يسكن ذلك الشيء؟ ليس في الـframe، لأنه يموت. وليس عند نادِيها، لأنه لا
يعرف حجمه بعد.

**هذا هو السؤال الذي فتح `malloc` في الإقليم ٠١** حين كتبتَ `copy`. وجوابه
الكامل في الإقليم ١٦.

---

## قبل أن تكمل

> **١.** أعِد كتابة `divmod` بحيث تُرجع الناتج والباقي **بلا** pointer. كم طريقةً
> تجد، وما ثمن كلٍّ منها؟
>
> **٢.** في لقطة الـframes، أضِف `char buf[1000];` إلى `level2`. كيف يتغيّر الفرق
> بين عنوانَي `2` و`3`؟ توقّع الاتّجاه قبل أن تشغّل.
>
> **٣.** دالّةٌ `int f(void)` بلا `return` — هل يُترجَم؟ وما قيمة `f()` حينئذٍ؟
> جرّب، واقرأ التحذير، ثم اسأل: هل هذا خطأٌ أم سلوكٌ غير معرَّف؟
