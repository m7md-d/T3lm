# الإقليم ١٦ — الـheap

> انتهى الإقليم ٠٩ عند سؤال: أين يسكن شيءٌ يعيش بعد الدالّة التي صنعته، ولا
> يُعرَف حجمه وقت الترجمة؟ والإقليم ١١ سمّى ما يحدث حين تخطئ الجواب: `dangling
> pointer`.
>
> هنا الجواب، ومعه ثمنه: **منطقةٌ ثالثة لا يديرها أحد نيابةً عنك**. وفيه يُغلق
> خطؤك الثاني من الإقليم ٠١ — وستراه برقم.

---

## طلبٌ وتسليم

```c
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

char *make(const char *s)
{
	char *p = malloc(strlen(s) + 1);

	if (p == NULL)
		return NULL;
	strcpy(p, s);
	return p;
}

int main(void)
{
	char *a = make("hello");

	printf("[%s]\n", a);
	free(a);
	free(NULL);
	return 0;
}
```

<!-- out -->

```
[hello]
```

`malloc(n)` تطلب `n` بايتاً وتُرجع عنوان أوّلها، أو `NULL` إن عجزت. و`free(p)`
تعيدها.

**والفرق عن كل ما سبق أن العمر بيدك.** لا يموت هذا الحجز بخروج `make`، ولا
بخروج `main` — يموت حين تنادي `free`، ولا شيء غير ذلك.

**و`free(NULL)` لا تفعل شيئاً**، وهي مضمونة بالمواصفة. فلا تحتاج فحصاً قبلها،
والصيغة `if (p) free(p);` حشوٌ لا حماية.

---

## ما لا يخبرك به الـheap

ثلاثة أشياء يفترضها الناس وليست صحيحة:

```c
#include <stdio.h>
#include <stdlib.h>

int main(void)
{
	unsigned char *m = malloc(8);
	unsigned char *c = calloc(8, 1);

	for (int i = 0; i < 8; i++)
		printf("%02X ", c[i]);
	printf("  <- calloc\n");
	printf("%zu\n", sizeof m);
	free(m);
	free(c);
	return 0;
}
```

<!-- out @impl: و`sizeof m` حجمُ pointer، يقرّره الهدف -->

```
00 00 00 00 00 00 00 00   <- calloc
8
```

**أولاً: `malloc` لا تصفّر.** محتوى ما تعطيه **غير محدَّد** — بايتاتٌ تركها من
حرّر قبلك. و`calloc(n, size)` تصفّر، وتفحص الضرب من الفيض، وثمنها الكتابة.

**وثانياً: `sizeof p` ثمانية، لا ثمانية آلاف.** الـpointer لا يحمل الطول — وهو
نفس درس الإقليم ١٢، وهنا أخطر لأن لا `sizeof` تنقذك أصلاً.

**وثالثاً: لا سبيل إلى سؤال الـheap عن الحجم.** ومع ذلك `free(p)` تعرفه — لأن
المخصِّص يحفظه في بايتاتٍ **قبل** ما أعطاك، لا في نوعك. وهو دفتره هو، لا واجهةٌ
لك.

**فالطول معلومةٌ تحملها أنت.** بجانب كل `pointer` إلى حجزٍ يجب أن يعيش عددٌ يقول
كم — في متغيّرٍ، أو في `struct`، أو بعلامة نهايةٍ متّفقٍ عليها.

## الخطأ الثاني من الإقليم ٠١

قلتُ لك: `set x 1` ثم `set x 2` — من يعيد البايتات الأولى؟ لا أحد. والآن **عُدّها**.

<!-- part: 16-count -->

```c
static long live = 0;

void *xmalloc(size_t n)
{
	live++;
	return malloc(n);
}

void xfree(void *p)
{
	if (p != NULL)
		live--;
	free(p);
}
```

ثم `copy` تنادي `xmalloc` بدل `malloc`، وثلاثة أوامر `set` لنفس المفتاح:

<!-- out -->

```
قيمة x = 3
حجزٌ حيّ = 3
بعد free = 2
```

**ثلاثة حجوزٍ حيّة، والقيمة واحدة.** كل `set` على مفتاحٍ موجود حجز نصّاً جديداً
ودَهَس الـpointer القديم — فالبايتات باقية، **ولا يعرف أحدٌ عنوانها**.

وهذا هو **التسريب** (leak): ذاكرةٌ محجوزة لا سبيل إلى الوصول إليها ولا إلى
تحريرها. لا انهيار، ولا رسالة، ولا تحذير — **رقمٌ يكبر فقط**.

**والإصلاح سطرٌ واحد** قبل الحجز الجديد:

```c
xfree(table[i].value);
table[i].value = copy(value);
```

**والقاعدة التي تولّده:** كل `pointer` يُسنَد إليه شيءٌ جديد **يجب أن يُسأل عمّا
كان يحمله**. الإسناد لا يحرّر.

---

## ولماذا عددتَها بيدك

لأن هذا الجهاز لا يستطيع أن يعدّها عنك:

<!-- shell -->

```
==…==AddressSanitizer: detect_leaks is not supported on this platform.
```

كشفُ التسريب ليس في `-fsanitize=address` على كل هدف. وهو موجودٌ بأسماءٍ مختلفة:
`-fsanitize=leak` أو `ASAN_OPTIONS=detect_leaks=1` حيث يُدعَم، و`valgrind
--leak-check=full` على لينكس، و`leaks` على macOS.

**والعدّاد الذي كتبتَه يعمل في كل مكان**، ويعطيك ما لا تعطيه الأداة: أنت تختار ما
يُعدّ. وهذا نموذجٌ ستعيده كثيراً في هذه اللغة — **حين تعجز الأداة، اكتب أصغر أداةٍ
تكفي**.

## الاستعمال بعد التحرير

التسريب يضيّع ذاكرة. وهذا أسوأ:

```c
//! cc: -fsanitize=address
//! scrub
//! head: 3
#include <stdio.h>
#include <stdlib.h>

int main(void)
{
	int *p = malloc(sizeof(int));

	*p = 7;
	free(p);
	printf("%d\n", *p);
	return 0;
}
```

<!-- out @ub: العناوين مستبدَلةٌ بنقاط، والتقرير مقتطع -->

```
=================================================================
==…==ERROR: AddressSanitizer: heap-use-after-free on address 0x… at pc 0x… bp 0x… sp 0x…
READ of size 4 at 0x… thread T0
```

**`free` لا تمسح `p`.** الثمانية بايتاتٍ فيه باقيةٌ تحمل نفس العنوان، والذي تغيّر
أن العنوان صار مِلك المخصِّص مرّةً أخرى.

**وبلا الـsanitizer لا يقول أحد شيئاً.** البايتات غالباً كما هي، فيطبع `7`
ويمضي — إلى أن يعطيها المخصِّص لحجزٍ آخر، فتقرأ بيانات غيرك أو تكتب فوقها.

**والقاعدة:** بعد `free`، أسنِد `NULL`. لن يمنعك ذلك من الخطأ، **لكنه يحوّله من
صامتٍ إلى انهيارٍ فوريّ** — ورأيتَ في الإقليم ١١ لماذا الانهيار أرحم.

---

## والتحرير مرّتين

```c
//! cc: -fsanitize=address
//! scrub
//! head: 2
#include <stdlib.h>

int main(void)
{
	int *p = malloc(4);

	free(p);
	free(p);
	return 0;
}
```

<!-- out @ub -->

```
=================================================================
==…==ERROR: AddressSanitizer: attempting double-free on 0x… in thread T0:
```

يفسد دفتر المخصِّص نفسه — لا بياناتك وحدها. وهو أساس فئةٍ كاملة من ثغرات
الاستغلال.

**و`p = NULL;` بعد `free` تمنعه تماماً**، لأن `free(NULL)` لا تفعل شيئاً. سطرٌ
واحد يغلق بابين.

## `realloc` تنقل ما حجزتَ

```c
#include <stdio.h>
#include <stdlib.h>
#include <stdint.h>

int main(void)
{
	int      *a = malloc(4 * sizeof(int));
	uintptr_t before = (uintptr_t)a;

	for (int i = 0; i < 4; i++)
		a[i] = i;

	int *b = realloc(a, 4096 * sizeof(int));

	printf("%d %d\n", b[0], b[3]);
	printf("انتقل؟ %d\n", before != (uintptr_t)b);
	free(b);
	return 0;
}
```

<!-- out @machine -->

```
0 3
انتقل؟ 1
```

**المحتوى نُقل، والعنوان تغيّر.** `realloc` قد توسّع في مكانها، وقد تحجز مكاناً
جديداً وتنسخ وتحرّر القديم.

**وما يتساقط من هذا فخّان:**

**الأول:** كل `pointer` آخر كان يشير إلى داخل الحجز القديم صار `dangling` —
ولا يحذّرك أحد. وهذا يقتل `char **words` من الإقليم ١٤ إذا كان يشير داخل صندوقٍ
أُعيد تخصيصه.

**والثاني في الصيغة التي يكتبها الجميع:**

```c
p = realloc(p, n);      /* خطأ */
```

إن عجزت `realloc` أرجعت `NULL` **وتركت القديم سليماً** — وأنت للتوّ دهستَ عنوانه.
فسرّبتَ الحجز وفقدتَ بياناتك في آن. والصواب:

```c
void *tmp = realloc(p, n);
if (tmp == NULL)
	/* p ما زال سليماً */;
else
	p = tmp;
```

## من يملك، ومن يحرّر

كل ما سبق يُختصر في سؤالٍ واحد لكل `pointer` في برنامجك:

| | من حجز | من يحرّر | ما يقوله التوقيع |
|---|---|---|---|
| `copy(s)` | الدالّة | **النادي** | تُرجع `char *` — إذن هي هبة |
| `split(line, words)` | لا أحد | لا أحد | `words` تستعير من `line` |
| `find(key)` | لا أحد | لا أحد | تُرجع عنواناً داخل `table` |

**واللغة لا تحمل هذه المعلومة.** لا في النوع، ولا في الاسم، ولا وقت التشغيل
(البديهية الأولى). فهي تُكتب في **مكانٍ واحد**: سطر تعليقٍ فوق كل دالّةٍ تُرجع
`pointer`، يقول من يحرّره.

**والاصطلاح الذي يوفّر أكثر التعليقات:** أن تحرّر الدالّة **التي حجزت**، فلا
تُرجع حجزاً إلا حين تكون هبةً معلومة — ويحمل اسمها ذلك: `make_`، `new_`، `dup_`.
الإقليم ٢٧ يبني هذا اصطلاحاً كاملاً.

> صفراً عند `quit`؟ وإن لم يصر، من الباقي؟
>

> القيم. ثم شغّل `set` ألف مرّةٍ ثم `clear` — وافحص العدّاد.
