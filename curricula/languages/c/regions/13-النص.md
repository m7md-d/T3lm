# الإقليم ١٣ — النصّ

> **لا يوجد في C نوعٌ اسمه «نصّ».** رأيتَ هذا في الفصل صفر جملةً، وستراه هنا
> يعمل.
>
> ما يوجد **اتّفاق**: array `char` ينتهي محتواها ببايتٍ صفريّ. وعلى هذا
> الاتّفاق وحده بُنيت نصف الـstandard library، وأكثر ثغرات الأمان في تاريخ البرمجة.
>
> وهنا يُغلق سؤالان تركتُهما في الإقليم ٠١: لماذا `strcmp` لا `==`، ولماذا `+ 1`.

---

## البايت الصفريّ هو النهاية

```c
#include <stdio.h>
#include <string.h>

int main(void)
{
	char s[] = "abc";

	printf("%zu %zu\n", sizeof s, strlen(s));
	for (size_t i = 0; i < sizeof s; i++)
		printf("%02X ", (unsigned char)s[i]);
	printf("\n");
	s[1] = '\0';
	printf("[%s] %zu %zu\n", s, sizeof s, strlen(s));
	return 0;
}
```

<!-- out -->

```
4 3
61 62 63 00 
[a] 4 1
```

**`sizeof` أربعة و`strlen` ثلاثة.** الفرق بايتٌ واحد: الصفر الختاميّ. والمترجم
أضافه عنك حين كتبتَ `"abc"`.

**والسطر الأخير هو الاتّفاق كلّه في مثال:** كتبتُ صفراً في الموضع الأول فصار النصّ
`"a"`. الحجم لم يتغيّر — أربعةٌ كما هو — والطول صار واحداً.

فـ`strlen` **ليست قراءةَ حقل**. هي حلقةٌ تمشي حتى تصادف صفراً، وكلفتها بعدد
الحروف. ونداؤها داخل شرط حلقةٍ يجعل الحلقة تربيعية.

---

## `strlen(s) + 1`

والآن السؤال الثاني من الإقليم ٠١:

```c
char *p = malloc(strlen(s) + 1);
```

`strlen` تعطيك عدد الحروف **قبل** الصفر. والصفر جزءٌ من النصّ في نظر كل دالّةٍ
ستقرؤه بعدك.

**فبلا الواحد:** تحجز ثلاثة، وتنسخ أربعة، فتكتب بايتاً خارج ما تملك. والبرنامج
يعمل غالباً — لأن البايت الذي بعده قد يكون فارغاً — ثم ينهار يوماً بلا سبب ظاهر.

**وهذا هو الـoff-by-one**، وهو أكثر أخطاء C شيوعاً على الإطلاق. ولا
يوجد له حلٌّ إلا أن تسأل نفسك في كل حجزٍ لنصّ: **هل حسبتُ الصفر؟**

---

## `char s[]` و`char *s`: فرقٌ في المِلكية

الصيغتان تبدوان متشابهتين، **وهما شيئان مختلفان تماماً**:

```c
#include <stdio.h>

int main(void)
{
	char  a[] = "abc";
	char *p   = "abc";

	printf("%zu %zu\n", sizeof a, sizeof p);
	a[0] = 'X';
	printf("%s\n", a);
	return 0;
}
```

<!-- out @impl -->

```
4 8
Xbc
```

**`char a[] = "abc"` تحجز أربعة بايتاتٍ وتنسخ إليها.** الـarray مِلكك، وتعديلها
مسموح. وهذا هو الاستثناء الثالث من استثناءات التحوّل في الإقليم ١٢.

**و`char *p = "abc"` لا تنسخ شيئاً.** الـliteral `"abc"` كائنٌ يسكن منطقةً ساكنة من
البرنامج، و`p` يحمل عنوانه فقط — ثمانية بايتات.

والفرق ليس نظرياً:

```c
#include <stdio.h>

int main(void)
{
	char *p = "abc";

	printf("قبل الكتابة\n");
	fflush(stdout);
	p[0] = 'X';
	printf("بعدها\n");
	return 0;
}
```

<!-- out @ub -->

```
قبل الكتابة
```

**«بعدها» لم تُطبَع.** البرنامج مات عند الكتابة: الـliterals تُوضَع في صفحاتٍ
للقراءة فقط، والنظام منع الكتابة فأنهى الـprocess.

**والمواصفة أخفّ من هذا وأخطر:** تقول إن تعديل literal نصّيّ **سلوكٌ غير معرَّف** —
لا «ممنوع». فمنصّةٌ أخرى قد تقبله وتصمت، ويعمل برنامجك حتى تنقله.

**والوقاية سطرٌ واحد:** اكتب `const char *p = "abc";`. عندها يرفضه المترجم وقت
الترجمة بدل أن يقتله النظام وقت التشغيل.

## `==` تقارن العناوين

والسؤال الأول من الإقليم ٠١:

```c
#include <stdio.h>
#include <string.h>

int main(void)
{
	char  a[] = "hi";
	char  b[] = "hi";
	char *p = a;
	char *q = b;

	printf("%d\n", p == q);
	printf("%d\n", strcmp(p, q) == 0);
	printf("%d %d %d\n", strcmp("a", "b"), strcmp("b", "a"), strcmp("a", "a"));
	return 0;
}
```

<!-- out -->

```
0
1
-1 1 0
```

**`p == q` صفر، والنصّان متطابقان.** لأنهما arrayان مختلفتان في عنوانين مختلفين،
و`==` بين pointerين تسأل «هل يشيران إلى نفس الموضع» — وهو سؤالٌ مشروع، **وليس
السؤال الذي تريده**.

و`strcmp` تمشي على البايتات وتقارنها، وتُرجع:

| | |
|---|---|
| **صفر** | متطابقان |
| **سالب** | الأول قبل الثاني |
| **موجب** | الأول بعده |

**ولذلك تُكتَب `strcmp(a, b) == 0` دائماً.** الاسم يوحي بـ«هل متساويان» والقيمة
تقول «الترتيب» — ومن يكتب `if (strcmp(a, b))` يحصل على العكس تماماً.

**وهذا فخٌّ يستحقّ الحذر:**

```c
#include <stdio.h>

int main(void)
{
	const char *a = "abc";
	const char *b = "abc";

	printf("%d\n", a == b);
	return 0;
}
```

<!-- out @unspec: على هذا المترجم — وليس وعداً -->

```
1
```

**هنا `==` أعطت الجواب الصحيح صدفة.** المترجم دمج الـliteralين المتطابقين في كائنٍ
واحد، فتساوى العنوانان. وهذا **غير محدَّد** في المواصفة: مترجمٌ آخر يفصلهما فتصير
صفراً.

فالكود الذي يقارن نصوصاً بـ`==` قد يمرّ باختباراتك كلّها، ثم يفشل عند تغيير
مترجمٍ أو flag.

## `strcpy` لا تسأل عن الحجم

وهذا خطؤك الأول في الإقليم ٠١:

```c
//! cc: -fsanitize=address
//! scrub
//! head: 3
#include <stdio.h>
#include <string.h>

void set(const char *src)
{
	char key[16];

	strcpy(key, src);
	printf("%s\n", key);
}

int main(void)
{
	set("aaaaaaaaaaaaaaaaaaaaaaaaaaaa");
	return 0;
}
```

<!-- out @ub: العناوين مستبدَلةٌ بنقاط، والتقرير مقتطع -->

```
=================================================================
==…==ERROR: AddressSanitizer: stack-buffer-overflow on address 0x… at pc 0x… bp 0x… sp 0x…
WRITE of size 29 at 0x… thread T0
```

**تسعٌ وعشرون بايتاً في صندوقٍ سعته ستّة عشر.** و`strcpy` نفّذت ما طُلب منها
بالضبط: تنسخ حتى تصادف صفراً، ولا تعرف حجم الوجهة أصلاً — **لم يخبرها أحد**.

**والوسيط الذي لا تأخذه هو العيب البنيويّ**: `strcpy(char *dst, const char *src)`.
لا مكان في التوقيع لحجم `dst`.

---

## وحين يقع الفائض داخل كائنٍ واحد، لا يراه الـsanitizer

الآن نفس الخطأ في شكله الأصليّ من الإقليم ٠١:

```c
//! cc: -fsanitize=address
#include <stdio.h>
#include <string.h>

struct Item { char key[16]; char *value; };
struct Item table[2];

int main(void)
{
	strcpy(table[0].key, "aaaaaaaaaaaaaaaaaaaaaaaaaaaa");
	printf("%s\n", table[0].key);
	return 0;
}
```

<!-- out @ub -->

```
aaaaaaaaaaaaaaaaaaaaaaaaaaaa
```

**لا تقرير، ولا انهيار، ولا شيء.** الـsanitizer يحرس حدود **الكائنات**، و`table` كائنٌ
واحد كبير — فالفائض بقي داخله: داس `table[0].value` ثم `table[1].key`.

والبرنامج طبع النصّ كاملاً لأن البايتات التالية صارت له فعلاً.

**والدرس أكبر من هذا الخطأ:** الـsanitizer يكشف ما يعرف حدوده. والتلف الذي يقع **داخل**
بنيةٍ أو array من بنى يمرّ صامتاً — وهو أكثر أشكال التلف حدوثاً في الكود
الحقيقيّ.

فـ`table[0].value` صار pointer يحمل حروف `a`. ونداءُ `free` عليه لاحقاً يسلّم
للنظام عنواناً مخترَعاً.

## البدائل، وثمن كلٍّ منها

```c
#include <stdio.h>
#include <string.h>

int main(void)
{
	char dst[8];

	memset(dst, 'Z', sizeof dst);
	strncpy(dst, "abcdefghij", sizeof dst);
	for (size_t i = 0; i < sizeof dst; i++)
		printf("%02X ", (unsigned char)dst[i]);
	printf("\n");

	char d2[8];
	int  n = snprintf(d2, sizeof d2, "%s", "abcdefghij");
	printf("[%s] %d\n", d2, n);
	return 0;
}
```

<!-- out -->

```
61 62 63 64 65 66 67 68 
[abcdefg] 10
```

**`strncpy` لم تكتب صفراً.** ثمانية بايتاتٍ كلّها حروف — لأنها تكتب `n` بايتاً
بالضبط، فإن امتلأت الوجهة **لم يبقَ موضعٌ للصفر**. والنتيجة نصٌّ بلا نهاية،
و`strlen` عليه تمشي إلى ما بعده.

**و`strncpy` لم تُصمَّم للنصوص أصلاً**؛ صُمّمت لحقولٍ ثابتة العرض في سجلّات
قديمة. واسمها يوحي بأنها «`strcpy` الآمنة»، وهي ليست كذلك.

**و`snprintf` تكتب الصفر دائماً**، وتقصّ ما زاد. ولاحظ ما أرجعته: **عشرة** — طول
ما **كان سيُكتب** لو اتّسع المكان، لا ما كُتب.

```c
if (snprintf(dst, sizeof dst, "%s", src) >= (int)sizeof dst)
	/* قُصّ النصّ */
```

**فهذه هي الصيغة التي تعرف أن القصّ وقع.** وهي الاختيار الافتراضيّ في كود اليوم.

## قبل أن تكمل

> **١.** أصلِح `cmd_set` في الإقليم ٠١ بحيث ترفض مفتاحاً لا يسع في `key`. أين
> تضع الفحص، وماذا تُرجع، ومن يقرأ الجواب؟
>
> **٢.** اكتب `strlen` بنفسك في ثلاثة أسطر. ثم اكتب حلقةً تنسخ نصّاً بها، وقارن
> عدد المرّات التي مشيتَ فيها على النصّ بعدد مرّات `strcpy`.
>
> **٣.** `char buf[16] = "";` ثم `strcat` مرّتين. كم مرّةً مشى البرنامج على `buf`
> من أوّله؟ ثم تخيّل ألف `strcat` — كم عمليةً صارت؟
