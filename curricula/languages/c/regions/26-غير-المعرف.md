# الإقليم ٢٦ — غير المعرَّف

> رأيتَ هذه العبارة في أربعة عشر إقليماً. وهذا هو الحساب الكامل.
>
> والادّعاء الذي يقوم عليه الإقليم كلّه: **السلوك غير المعرَّف ليس خطأً وقت
> التشغيل.** هو **رخصةٌ وقت الترجمة** — إذنٌ للمترجم بأن يفترض أن ما كتبتَه لا
> يقع، ثم يبني على الافتراض.
>
> ومن يفهم هذا يفهم لماذا يعمل كودُه سنةً ثم ينهار عند تغيير flag واحد.

---

## الأصناف الثلاثة، بدقّة

المواصفة §3.4 تفرّق بين ثلاثة، والخلط بينها هو الخطأ:

| | من يقرّر | هل يُوثَّق | مثال |
|---|---|---|---|
| **معرَّف بالتنفيذ** | المترجم | **نعم، ملزَم** | حجم `int` · إشارة `char` · القصّ إلى نوعٍ بإشارة |
| **غير محدَّد** | المترجم | لا | ترتيب تقييم الوسائط · تخطيط الـpadding |
| **غير معرَّف** | **لا أحد** | — | تجاوز `int` · قراءةٌ خارج array · use-after-free |

**والأولان محدودان.** تعرف أن الجواب أحد احتمالاتٍ معلومة، وتستطيع أن تكتب كوداً
يصحّ في كلٍّ منها.

**والثالث بلا حدود.** المواصفة تنصّ صراحةً على أن النتيجة قد تكون تجاهلاً كاملاً،
أو سلوكاً موثّقاً، أو إنهاءً للترجمة أو للتنفيذ — **بلا أي التزام**.

---

## ليس «ما تفعله الآلة»

هذا هو الاعتقاد الذي يجب أن يُدفَن.

**الاعتقاد:** «تجاوز `int` يلتفّ، لأن العتاد يلتفّ. المواصفة تركته للتنفيذ فقط.»

**ولماذا يبدو مقنعاً:** لأنك جرّبتَه فالتفّ. ولأن التعليمة في المعالج تلتفّ فعلاً.

**والكود المضادّ رأيتَه في الفصل صفر:** `x + 1 > x` أعطت `0` بلا تحسين و`1` مع
`-O2`. ولم يلتفّ شيء — **حُذفت المقارنة كلّها**.

**والآلية:** المترجم لا يترجم سطراً سطراً. يبني نموذجاً عن قيمك، ويستنتج منه.
و«تجاوز `int` غير معرَّف» يدخل النموذج بوصفه **حقيقة**: إذن `x + 1` أكبر من `x`
دائماً، إذن الشرط ثابت، إذن احذف الفرع.

**والقاعدة الصحيحة:** السلوك غير المعرَّف ليس شيئاً يقع وقت التشغيل. هو **افتراضٌ
يُبنى عليه وقت الترجمة**، وأثرُه قد يظهر في **سطرٍ آخر تماماً** — أو ألّا يظهر.

**وحدّها:** بلا تحسين، كثيرٌ منه «يعمل». ولهذا لا يكفي أن تختبر بـ`-O0`.

---

## المثال الذي يقنع: الـaliasing الصارم

```c
//! cc: -O2
#include <stdio.h>

int change(int *i, float *f)
{
	*i = 1;
	*f = 2.0f;
	return *i;
}

int main(void)
{
	int x = 0;

	printf("%d\n", change(&x, (float *)&x));
	return 0;
}
```

<!-- out @ub: مع ‎-O2 -->

```
1
```

**والبرنامج نفسه بلا تحسين:**

```c
#include <stdio.h>

int change(int *i, float *f)
{
	*i = 1;
	*f = 2.0f;
	return *i;
}

int main(void)
{
	int x = 0;

	printf("%d\n", change(&x, (float *)&x));
	return 0;
}
```

<!-- out @ub: بلا تحسين -->

```
1073741824
```

**نفس البايتات، وجوابان.** والثاني هو بتّات `2.0f` مقروءةً عدداً صحيحاً.

**والقاعدة التي بُني عليها التحسين** اسمها الـstrict aliasing: كائنٌ لا يُقرأ ولا
يُكتَب إلا عبر نوعه — أو نوعٍ حرفيّ (§6.5). فـ`int *` و`float *` **لا يمكن أن
يشيرا إلى نفس الشيء** في نظر المترجم.

فرأى `*i = 1` ثم `*f = 2.0f` ثم `return *i`، **وعرف** أن الثانية لا تمسّ الأولى،
فأرجع `1` بلا قراءة.

**وهذا ليس تحسيناً هامشياً:** بدونه يجب على المترجم أن يعيد قراءة كل شيءٍ بعد كل
كتابةٍ عبر أي pointer.

**والطريق المشروع للنظر في البايتات هو الذي استعملتَه منذ الإقليم ٠٢:**
`memcpy`، أو `unsigned char *`. وكلاهما مستثنىً بنصّ المواصفة.

## الفهرس

كلٌّ منها مرّ بك، وهذا موضع جمعها:

| | الإقليم | ماذا يكشفه |
|---|---|---|
| تجاوز `signed` | ٠٣ | UBSan |
| الإزاحة بعرض النوع أو أكثر | ٠٧ | UBSan |
| تعديلٌ مرّتين بلا ترتيب | ٠٧ | تحذير المترجم |
| قراءة متغيّرٍ غير مهيّأ | ٠٩ | **لا شيء هنا** |
| pointer معلَّق | ١١ · ١٦ | ASan (غالباً) |
| قراءةٌ عبر `NULL` | ١١ | UBSan |
| خارج حدود array | ١٢ | ASan |
| تعديل literal نصّيّ | ١٣ | إشارةٌ عند التشغيل |
| use-after-free · double free | ١٦ | ASan |
| قسمةٌ على صفر | هنا | UBSan |
| عنوانٌ غير محاذىً | هنا | UBSan |
| خرقُ الـstrict aliasing | هنا | **لا شيء** |

```c
//! cc: -fsanitize=undefined
//! pty
#include <stdio.h>

int main(int argc, char **argv)
{
	int z = argc - 1;

	(void)argv;
	printf("%d\n", 10 / z);
	return 0;
}
```

<!-- out @ub -->

```
main.c:8:20: runtime error: division by zero
SUMMARY: UndefinedBehaviorSanitizer: undefined-behavior main.c:8:20 in 
0
```

**ولاحظ `argc - 1`.** لو كتبتُ `10 / 0` لرفضه المترجم وقت الترجمة. والقيمة التي
تُحسَب وقت التشغيل تمرّ — وهذا نمطٌ يتكرّر في كل هذا الفهرس.

```c
//! cc: -fsanitize=undefined
//! pty
//! scrub
//! head: 1
#include <stdio.h>
#include <string.h>

int main(void)
{
	unsigned char buf[16];

	memset(buf, 0, sizeof buf);

	int *p = (int *)(buf + 1);

	printf("%d\n", *p);
	return 0;
}
```

<!-- out @ub: العناوين مستبدَلةٌ بنقاط، والتقرير مقتطع -->

```
main.c:12:17: runtime error: load of misaligned address 0x… for type 'int', which requires 4 byte alignment
```

**والمحاذاة ليست ترفاً** — رأيتَ في الإقليم ١٧ لماذا يهتمّ بها العتاد. وعلى
معماريّاتٍ أخرى هذا السطر **تعليمةٌ ترفض التنفيذ** لا تحذيراً.

## ما تكشفه الأدوات، وما لا تكشفه

| الأداة | تكشف | الثمن |
|---|---|---|
| `-Wall -Wextra` | ما يراه المترجم في النصّ | صفر |
| `-fsanitize=address` | حدود array · use-after-free · double free | ×٢ زمناً، ×٣ ذاكرةً |
| `-fsanitize=undefined` | التجاوز · الإزاحة · المحاذاة · `NULL` · القسمة | زمنٌ يسير |
| `-fsanitize=thread` | سباقات البيانات | ×١٠ تقريباً |
| `-fsanitize=memory` | القراءة غير المهيّأة | **غير مدعومة على كل هدف** |

**وسطران يجب أن يُقالا بلا تجميل:**

**الأول:** `-fsanitize=memory` **لا تعمل على هذا الهدف** — جرّبها وسترى رفضاً
صريحاً من المترجم. وقراءةُ المتغيّر غير المهيّأ التي رأيتَها في الإقليم ٠٩
**ليس لها كاشفٌ هنا**، وليس لها إلا التحذير و`= 0` عند الإعلان.

**والثاني:** لا شيء يكشف خرق الـstrict aliasing — لأن المترجم **قد استعمل
الافتراض** قبل أن يصل الكود إلى أي كاشف.

**والقاعدة العامّة:** الكاشف يكشف ما وقع في هذا التشغيل، بهذا الدخل. **وغيابُ
تقريرٍ ليس شهادةَ سلامة.**

## الانضباط الذي يخرج من هذا

ثلاثة أبنيةٍ لا واحد، ولكلٍّ غرضه:

```bash
# للتطوير: أوقفني عند أوّل خطأ
cc -std=c17 -Wall -Wextra -g -O0 \
   -fsanitize=address,undefined -o main main.c

# للفحص: تحسينٌ كامل — لأن التحسين هو ما يكشف الافتراضات
cc -std=c17 -Wall -Wextra -O2 -fsanitize=undefined -o main main.c

# للإصدار
cc -std=c17 -Wall -Wextra -O2 -DNDEBUG -o main main.c
```

**والثاني هو الذي يُهمَل**، وهو الأهمّ: كودٌ يمرّ بالكاشفات على `-O0` وينهار على
`-O2` كودٌ **فيه سلوكٌ غير معرَّف بُني عليه**. فشغّل اختباراتك على الاثنين.

**و`-g` ليست للتنقيح وحده:** بدونها تعطيك تقارير الكاشفات عناوين بلا أسماء ملفّات
ولا أرقام أسطر.

## ولماذا قبِلت C هذا كلّه

السؤال العادل في آخر الإقليم: **لماذا لم تُلزِم المواصفة بسلوكٍ واحد؟**

الجواب في الفصل صفر: لجنة ١٩٨٩ أمام آلاتٍ تختلف في تمثيل السالب وفي عرض الكلمة
وفيما يحدث عند التجاوز. **وإلزام سلوكٍ واحد يعني فحصاً في كل عملية** على نصف
الآلات.

**والصفقة معلَنة:** لا تفعل C ما لم تطلبه — لا فحص حدود، ولا فحص تجاوز، ولا تصفير
(الإقليم ٠٠، «الثمن الذي دُفع عن قصد»).

**والصفقة تُعقَد مرّةً وتُدفَع كل يوم.** ولذلك يستعمل هذا المنهج الكاشفات من أوّل
إقليم: هي التي تعيد إليك — **وقت التطوير وحده** — ما تنازلتَ عنه وقت التشغيل.

>
> **٢.** شغّل برنامج الإقليم ٠١ كاملاً بـ`-O2 -fsanitize=address,undefined`
> بمفتاحٍ من ثلاثين حرفاً وسطرٍ من مئتين. كم تقريراً؟ وهل تطابق أخطاءك الثلاثة؟
>
> **٣.** اكتب دالّةً تجمع عددين وتكشف التجاوز **قبل** وقوعه، بلا سلوكٍ غير
> معرَّف. ثم قارنها بـ`__builtin_add_overflow` — وأعلن أيّهما من اللغة وأيّهما من
> مترجمك.
