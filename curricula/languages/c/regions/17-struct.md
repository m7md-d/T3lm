# الإقليم ١٧ — الـstruct

> رأيتَ في الإقليم ٠٢ بايتين في `struct Item` لا يملكهما حقل، وقلتُ: سببهما هنا.
>
> وفي هذا الإقليم أيضاً **الاستثناء الوحيد** لقاعدةٍ عشتَ معها منذ الإقليم ١٢:
> الـarray لا تُنسَخ عند الإسناد — إلا حين تكون داخل `struct`.
>
> وفي آخره جدولُ أوامرٍ يُنادى من `struct` — وهو الشكل الذي ستأخذه حلقة الأوامر
> في مشروع التخرّج.

---

## الإسناد ينسخ كل شيء

```c
#include <stdio.h>
#include <string.h>

struct Item {
	char key[16];
	int  n;
};

int main(void)
{
	struct Item a;

	strcpy(a.key, "hi");
	a.n = 1;

	struct Item b = a;

	strcpy(b.key, "bye");
	b.n = 2;

	printf("%s %d\n", a.key, a.n);
	printf("%s %d\n", b.key, b.n);
	return 0;
}
```

<!-- out -->

```
hi 1
bye 2
```

**الستّة عشر بايتاً نُسخت.** غيّرتُ `b.key` فبقيت `a.key` كما هي.

وهذا يخالف ما تعرفه: `char x[16] = y;` **لا يُترجَم** أصلاً، والـarray لا تُنسَخ
بالإسناد ولا تُمرَّر بالنسخ.

**والـstruct هي الاستثناء الوحيد.** حين تسكن الـarray داخل `struct`، تنتقل معها
كاملةً في الإسناد وفي التمرير وفي الإرجاع — لأن المنقول حينئذٍ **الـstruct** لا
الـarray، والاسم لا يتحوّل إلى pointer.

**وهذه هي الحيلة القديمة** لتمرير array بالنسخة: لُفّها في `struct`. وثمنها أن
النسخ حقيقيّ: تمرير `struct Item` ينسخ ٢٤ بايتاً في كل نداء.

---

## أين ذهب البايتان

```c
#include <stdio.h>
#include <stddef.h>

struct Bad  { char a; int b; char c; };
struct Good { int b; char a; char c; };

int main(void)
{
	printf("Bad  حجم=%zu  a=%zu b=%zu c=%zu\n", sizeof(struct Bad),
	       offsetof(struct Bad, a), offsetof(struct Bad, b),
	       offsetof(struct Bad, c));
	printf("Good حجم=%zu  b=%zu a=%zu c=%zu\n", sizeof(struct Good),
	       offsetof(struct Good, b), offsetof(struct Good, a),
	       offsetof(struct Good, c));
	printf("_Alignof(int) = %zu\n", _Alignof(int));
	return 0;
}
```

<!-- out @unspec -->

```
Bad  حجم=12  a=0 b=4 c=8
Good حجم=8  b=0 a=4 c=5
_Alignof(int) = 4
```

**نفس الحقول الثلاثة، وحجمان.**

القاعدة قاعدتان:

| | |
|---|---|
| كل حقلٍ يبدأ عند `offset` يقبل القسمة على **الـalignment** الخاصّ بنوعه | `int` عند ٤ لا عند ١ |
| وحجم الـstruct يُقرَّب لأكبر alignment فيها | ليصحّ `a[i]` في array منها |

في `Bad`: `a` عند ٠، ثم يجب أن يبدأ `b` عند مضاعف أربعة — فضاعت ثلاثة. ثم `c`
عند ٨، ثم يُقرَّب الحجم إلى ١٢ — فضاع ثلاثةٌ أخرى. **ستّة بايتاتٍ من اثني عشر.**

وفي `Good` لم يتغيّر إلا الترتيب، فصار الحجم ثمانية.

**والقاعدة الثانية هي التي يغفل عنها الناس:** التقريب في الذيل ليس إهداراً، بل
شرطٌ لأن يعمل `array` من هذه الـstruct — لأن `a[1]` يجب أن يبدأ محاذىً مثل `a[0]`.

**ولماذا يهتمّ العتاد أصلاً؟** لأن قراءة أربعة بايتاتٍ من عنوانٍ يقبل القسمة على
أربعة عمليةٌ واحدة، ومن عنوانٍ لا يقبلها عمليتان ودمج — وعلى بعض المعماريات
**تعليمةٌ ترفض التنفيذ**.

## `->` سكّرٌ على نجمةٍ ونقطة

```c
#include <stdio.h>

struct P { int x, y; };

int main(void)
{
	struct P  p = { 1, 2 };
	struct P *q = &p;

	printf("%d %d %d\n", p.x, q->x, (*q).x);
	q->y = 9;
	printf("%d\n", p.y);
	return 0;
}
```

<!-- out -->

```
1 1 1
9
```

`q->x` **تعريفها** `(*q).x`. لا أكثر.

**والقوسان في `(*q).x` هما سبب وجود `->`:** أولوية `.` أعلى من `*`، فـ`*q.x`
تعني `*(q.x)` — أي «اقرأ الحقل `x` ثم اتبعه pointerاً»، وهو خطأ نوعٍ يرفضه
المترجم. فالسهم اختصارٌ لقوسين يُنسيان.

## `union`: البديهية الثانية في نوع

```c
#include <stdio.h>

union U {
	unsigned int  i;
	float         f;
	unsigned char b[4];
};

int main(void)
{
	union U u;

	printf("%zu\n", sizeof u);
	u.f = 100.0f;
	printf("%u\n", u.i);
	for (int k = 0; k < 4; k++)
		printf("%02X ", u.b[k]);
	printf("\n");
	return 0;
}
```

<!-- out @impl -->

```
4
1120403456
00 00 C8 42 
```

**الحقول الثلاثة تسكن نفس البايتات**، وحجم الـunion حجمُ أكبرها لا مجموعها.

والأرقام مألوفة: `00 00 C8 42` و`1120403456` هما بعينهما ما رأيتَه في الفصل صفر
حين قرأتَ أربعة بايتاتٍ بعدستين. **الـunion هو تلك العدسة بوصفها نوعاً.**

**وكتابةُ حقلٍ ثم قراءةُ آخر** لها في C حكمٌ ألطف ممّا يظنّ القادمون من C++:
مسموحة، والقيمة تُعاد تفسيرها بحسب النوع المقروء (المواصفة §6.5.2.3، الحاشية).
**وحدُّها** أن النمط الناتج قد لا يكون قيمةً صالحة للنوع الثاني أصلاً.

**واستعماله الشائع ليس هذا**، بل **الاتّحاد الموسوم**: `struct` فيها `enum` يقول
أيّ الحقول هو الحيّ، و`union` فيها الحقول. وهي طريقة C في «نوعٍ من عدّة أشكال».

## `enum` عددٌ بأسماء

```c
#include <stdio.h>

enum Kind  { SET, GET, DEL, LIST };
enum Flags { A = 1, B = 2, C = 4 };

int main(void)
{
	enum Kind k = DEL;

	printf("%d %d %d\n", SET, DEL, LIST);
	printf("%zu %zu\n", sizeof k, sizeof(enum Kind));
	printf("%d\n", A | C);
	k = 99;
	printf("%d\n", k);
	return 0;
}
```

<!-- out @impl -->

```
0 2 3
4 4
5
99
```

يبدأ من صفرٍ ويزيد واحداً، وتستطيع أن تُسنِد صراحةً كما في `Flags`.

**والسطر الأخير هو حدّه:** `k = 99` وليست من القائمة، **ولم يعترض أحد**. `enum`
في C ليست نوعاً مغلقاً — هي أسماءٌ لثوابت `int`، لا أكثر (البديهية الأولى: لا شيء
يبقى وقت التشغيل ليفحص).

**ومكسبه رغم ذلك حقيقيّ:** أسماءٌ في مكان أرقامٍ سحرية، و`switch` يحذّر منه
المترجم إن أهملتَ حالة، وقيمٌ متتابعة بلا عدٍّ يدويّ.

## الحقل المرن

مشكلةٌ يوميّة: نصٌّ وطولُه في كائنٍ واحد. الحلّ الساذج pointer — فيصير الحجز
حجزين، والتحرير تحريرين.

```c
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

struct Str {
	size_t len;
	char   data[];
};

int main(void)
{
	const char *s = "hello";
	size_t      n = strlen(s);
	struct Str *p = malloc(sizeof *p + n + 1);

	p->len = n;
	strcpy(p->data, s);
	printf("%zu %zu [%s]\n", sizeof *p, p->len, p->data);
	free(p);
	return 0;
}
```

<!-- out @impl -->

```
8 5 [hello]
```

`char data[]` بلا طول **حقلٌ مرن** (C99)، ولا يدخل في `sizeof` — والدليل أن الحجم
ثمانية لا أكثر. وأنت تحجز `sizeof *p` **زائد** ما تريده له.

**والمكسب حجزٌ واحد وتحريرٌ واحد**، والبيانات ملاصقةٌ لترويستها في الذاكرة.
**وثمنه** أن الـstruct لم تعد تُنسَخ بالإسناد نسخاً مفيداً: `*a = *b` تنقل `len`
وحدها.

ولاحظ `sizeof *p` لا `sizeof(struct Str)` — الصيغتان سواء، والأولى لا تكذب إن
غيّرتَ نوع `p` يوماً.

## جدول الأوامر

اجمع الإقليم كلّه: `struct` فيها اسمٌ وعددُ وسائطَ **وpointer إلى دالّة**.

<!-- part: 17-table -->

```c
struct Cmd {
	const char *name;
	int         argc;
	void      (*run)(char **argv);
};

static const struct Cmd table[] = {
	{ "set",  3, do_set  },
	{ "get",  2, do_get  },
	{ "list", 1, do_list },
};
```

<!-- out -->

```
set name = ali
list
24 72
```

**اقرأ `void (*run)(char **argv)` من الاسم خارجاً** كما تعلّمت في الفصل صفر:
`run` — القوس يجمعه بـ`*` ⇒ pointer — إلى دالّةٍ تأخذ `char **` وتُرجع `void`.

**وبلا القوسين** تصير `void *run(char **)` — دالّةً تُرجع `void *`. نفس الرموز،
ونوعان لا يجتمعان.

**وما اشتراه هذا الجدول:** سلسلة `else if` في الإقليم ٠١ صارت **بياناتٍ**. إضافة
أمرٍ سطرٌ في الجدول ودالّةٌ جديدة، ولا تُلمَس الحلقة. وعدد الأوامر يُحسَب
بـ`sizeof table / sizeof table[0]`، وفحص الوسائط يقع في مكانٍ واحد.

وهذه هي الصيغة التي تأخذها حلقة الأوامر في الإقليم ٢٨.

## قبل أن تكمل

> **١.** أعِد ترتيب حقول `struct Item` من الإقليم ٠١ — `char key[16]` و
> `char *value` — هل يوجد ترتيبٌ أصغر؟ ولماذا؟
>
> **٢.** حوّل حلقة `main` في الإقليم ٠١ إلى جدول أوامر. كم سطراً حذفتَ، وأين صار
> فحص `argc`؟
>
> **٣.** `struct Empty { };` — هل يُترجَم؟ وما `sizeof` عليه؟ جرّب مع `-pedantic`
> وبدونه، ثم اسأل: من قرّر الجواب، المواصفة أم مترجمك؟
