# الإقليم ٠٧ — التعبير

> ستّة أقاليم عن **ما تحمله القيمة**. من هنا يبدأ سؤالٌ آخر: **ماذا تفعل بها.**
>
> والتعبير في C ليس حساباً فقط. هو شيءٌ له **قيمة** وقد يكون له **أثر**، والخلط
> بينهما مصدر أشهر أخطاء اللغة — بما فيها خطأٌ يقبله المترجم ويعمل عكس ما كتبتَ.

---

## الإسناد تعبير

في لغاتٍ كثيرة الإسناد **جملة**. في C هو **تعبير** له قيمة: القيمة المُسنَدة.

```c
#include <stdio.h>

int main(void)
{
	int a, b, c;

	a = b = c = 5;
	printf("%d %d %d\n", a, b, c);
	printf("%d\n", (a = 0));
	return 0;
}
```

<!-- out -->

```
5 5 5
0
```

`a = b = c = 5` تعمل لأن `c = 5` **قيمتها خمسة**، فتُسنَد إلى `b`، وهكذا.
والإسناد يتجمّع من اليمين لهذا السبب.

**والأثر منفصلٌ عن القيمة:** السطر الثاني طبع صفراً **وغيّر `a`** في نفس الوقت.
شيئان في تعبيرٍ واحد، وهذا هو مفتاح الإقليم كلّه.

---

## `=` داخل `if`

ونتيجة اللقطة السابقة مباشرةً: هذه جملةٌ سليمة نحوياً في C.

```c
#include <stdio.h>

int main(void)
{
	int a = 0;

	if (a = 3)
		printf("دخلت، وقيمة a = %d\n", a);
	return 0;
}
```

<!-- out -->

```
دخلت، وقيمة a = 3
```

**الشرط لم يقارن شيئاً.** أسنَد ثلاثةً إلى `a`، وقيمةُ الإسناد ثلاثة، وثلاثةٌ ليست
صفراً — فالشرط صحيح. **وهو صحيحٌ دائماً**، مهما كانت `a` قبله.

والمترجم يرى المصيدة:

<!-- warn @impl -->

```
warning: using the result of an assignment as a condition without parentheses
```

**ولاحظ صياغة التحذير:** «بلا أقواس». فالمترجم لا يمنعك؛ يطلب منك أن تُعلن أنك
تقصد. و`if ((a = read()))` بقوسين مقبولةٌ بلا تحذير، وهي صيغةٌ شائعة ومقصودة.

---

## قبل وبعد

`++` و`--` لكلٍّ منهما موضعان، والفرق في **قيمة التعبير** لا في الأثر:

```c
#include <stdio.h>

int main(void)
{
	int i = 5;
	int a = i++;
	int j = 5;
	int b = ++j;

	printf("%d %d\n", a, i);
	printf("%d %d\n", b, j);
	return 0;
}
```

<!-- out -->

```
5 6
6 6
```

`i++` قيمتها **القديمة**، ثم تزيد. و`++j` تزيد أوّلاً، وقيمتها الجديدة.
والمتغيّران انتهيا إلى ستّة في الحالتين.

**فحين ترمي القيمة — `i++;` وحدها — لا فرق بينهما.** والفرق يظهر لحظةَ تستعملها،
وهذه بالضبط اللحظة التي يكثر فيها الخطأ.

---

## الـshort-circuit ليس تحسيناً

`&&` و`||` لا يقيّمان الطرف الأيمن إن كان الأيسر يحسم الجواب:

```c
#include <stdio.h>

int noisy(int v)
{
	printf("نُودِيت(%d) ", v);
	return v;
}

int main(void)
{
	printf("=%d\n", noisy(0) && noisy(1));
	printf("=%d\n", noisy(1) || noisy(0));
	return 0;
}
```

<!-- out -->

```
نُودِيت(0) =0
نُودِيت(1) =1
```

**نُوديت مرّةً في كل سطر.** الثانية لم تُنفَّذ أصلاً.

وهذا **مضمونٌ بالمواصفة**، لا تحسيناً يفعله المترجم إن شاء. ويترتّب عليه أن هذه
الصيغة سليمة:

```c
if (p != NULL && p->key[0] == 'a')
```

لو قُيّم الطرفان لانهار البرنامج عند `p` صفريّ. الترتيب هنا **جزءٌ من المعنى**.

**و`&&` و`||` تضمنان شيئاً ثانياً:** أن كل أثرٍ في الطرف الأيسر يتمّ **قبل** أن
يبدأ الأيمن. وأكثر المعاملات لا تضمن هذا — وهو موضوع اللقطة بعد القادمة.

## الأولوية حيث تلدغ

الجدول طويل، وحفظه بلا فائدة. **وموضعان منه يلدغان في كل مشروع:**

```c
#include <stdio.h>

int main(void)
{
	int a = 4, b = 4, c = 4;

	printf("%d\n", a & b == c);
	printf("%d\n", (a & b) == c);
	printf("%d\n", 1 << 2 + 3);
	printf("%d\n", (1 << 2) + 3);
	return 0;
}
```

<!-- out -->

```
0
1
32
7
```

**`==` أعلى من `&`.** فالسطر الأول حسب `b == c` أوّلاً — فصارت واحداً — ثم
`4 & 1` وهي صفر.

**و`+` أعلى من `<<`.** فالسطر الثالث حسب `2 + 3` أوّلاً، فصار `1 << 5`.

السبب تاريخيّ: معاملات الـbits أُضيفت وأولويتها أدنى من المقارنة، ولم يُغيَّر ذلك
لأن التغيير **يكسر بصمت** — وهي القاعدة التي رأيتَها في الفصل صفر.

والمترجم يحذّر من الاثنين:

<!-- warn @impl -->

```
warning: & has lower precedence than ==; == will be evaluated first
```

**والقاعدة العملية:** إن اجتمع في تعبيرٍ معاملان من عائلتين، ضع قوسين. القوس
مجّانيّ، والتحذير لا يظهر في كل الحالات.

---

## الإزاحة، وحدّها

`<<` و`>>` أرخص أدوات الـbits، ولها حدودٌ منصوصة:

```c
//! cc: -fsanitize=undefined
//! pty
#include <stdio.h>

int main(void)
{
	int n = 1;
	int k = 32;

	printf("%d\n", n << k);
	return 0;
}
```

<!-- out @ub -->

```
main.c:8:19: runtime error: shift exponent 32 is too large for 32-bit type 'int'
SUMMARY: UndefinedBehaviorSanitizer: undefined-behavior main.c:8:19 in 
1
```

**الإزاحة بمقدار عرض النوع أو أكثر سلوكٌ غير معرَّف.** ولاحظ الجواب: `1` — أي أن
المعالج تجاهل الإزاحة كأنها صفر. جوابٌ لا يخطر لأحد، ولا يَعِد به أحد.

وللإزاحة يميناً حكمٌ ثانٍ:

```c
#include <stdio.h>

int main(void)
{
	int n = -8;

	printf("%d\n", n >> 1);
	printf("%u\n", (unsigned int)-8 >> 1);
	return 0;
}
```

<!-- out @impl -->

```
-4
2147483644
```

**نفس الـbits، وإزاحةٌ واحدة، وجوابان.** في `unsigned` يدخل صفرٌ من الأعلى
دائماً. وفي `signed` السالب **يُترك للتنفيذ**: أن تدخل نسخةٌ من bit الإشارة
(وهو ما فعله هذا المترجم فبقيت القيمة سالبةً وصحيحة)، أو أن يدخل صفر.

**فأزِح على `unsigned`.** وإن أردتَ قسمةً على اثنين فاكتب `/ 2` — المترجم يولّد
الإزاحة عنك، ويعرف الحالات التي تختلف فيها.

## ما لا تعد به المواصفة من الترتيب

هذه أخطر لقطةٍ في الإقليم، لأن الخطأ فيها **يعمل عندك سنوات**.

```c
#include <stdio.h>

int say(int v)
{
	printf("(%d)", v);
	return v;
}

int main(void)
{
	printf(" = %d\n", say(1) + say(2));
	return 0;
}
```

<!-- out @unspec: هذا ما اختاره هذا المترجم، ولا وعد به -->

```
(1)(2) = 3
```

**الجمع مضمون، والترتيب ليس كذلك.** أي المُعامَلين يُقيَّم أوّلاً **غير محدَّد**
(unspecified) — للمترجم أن يختار، وأن يغيّر اختياره بين إصدارين أو بين flags
الترجمة، بلا أن يوثّق شيئاً.

وحين يكون للطرفين **أثر** على نفس المتغيّر، يصعد الحكم درجةً إلى **غير معرَّف**:

```c
#include <stdio.h>

int main(void)
{
	int i = 1;

	i = i++ + 1;
	printf("%d\n", i);
	return 0;
}
```

<!-- warn @impl -->

```
warning: multiple unsequenced modifications to 'i'
```

**ولن أكتب لك ما تطبعه.** ليس لأني لم أشغّلها — بل لأن الرقم الذي خرج عندي ليس
ادّعاءً عن اللغة، وكتابته هنا تعلّمك شيئاً كاذباً. المواصفة لا تعد بشيء، فليس
هناك جوابٌ يُنقل.

**والقاعدة التي تخرج بها:** متغيّرٌ يتغيّر مرّتين في تعبيرٍ واحد، أو يتغيّر ويُقرأ
في تعبيرٍ واحد — **افصلهما إلى جملتين**. لا يوجد سببٌ يستحقّ المخاطرة، والمكسب
صفر.

## الفاصلة والثلاثيّ

بقي معاملان يظهران كثيراً:

```c
#include <stdio.h>

int main(void)
{
	int a = 1, b = 2;
	int n = 0;

	printf("%d\n", a > b ? a : b);
	printf("%d\n", 1 + (a ? 10 : 20));

	for (int i = 0, j = 10; i < j; i++, j--)
		n++;
	printf("%d\n", n);
	return 0;
}
```

<!-- out -->

```
2
11
5
```

**الثلاثيّ `? :` تعبيرٌ لا جملة**، فله قيمةٌ تُسنَد وتُمرَّر. وأولويته منخفضةٌ جداً
— أدنى من `+` — ولذلك القوسان في السطر الثاني ليسا زينة.

**والفاصلة `,` معاملٌ يقيّم يساره ثم يمينه وقيمتُه اليمين.** وموضعها الوحيد الذي
يستحقّها رأسُ الحلقة، حيث لا يُقبل إلا تعبيرٌ واحد وأنت تريد اثنين.

وانتبه: الفاصلة في `f(a, b)` وفي `int a, b;` **ليست هذا المعامل** — بل فاصلٌ
نحويّ. نفس الرمز، ومعنيان.

## قبل أن تكمل

> **١.** `x != 0 && 10 / x > 1` — لماذا لا تنهار عند `x` صفريّ؟ وماذا يحدث لو
> بدّلتَ الطرفين؟
>
> **٢.** اكتب تعبيراً واحداً يقول هل عددٌ زوجيّ، **بلا** `%`. ثم اكتب لماذا يعمل
> على `unsigned` ولا تضمنه على `signed`.
>
> **٣.** في الإقليم ٠١ كتبتَ `line[strcspn(line, "\n")] = '\0';`. كم تعبيراً في
> هذا السطر، وما قيمة كلٍّ منها، وما أثره؟
