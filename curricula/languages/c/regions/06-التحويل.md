# الإقليم ٠٦ — التحويل

> بقيت من الإقليم الماضي جملةٌ بلا شرح: «`%X` ينتظر `int`، فيُرقَّى `char` السالب
> وتمتدّ الواحدات».
>
> هذا الإقليم عن تلك الجملة. وهو آخر أقاليم **التمثيل**: بعده تعرف ما يحدث
> للbits في كل مرّةٍ تلتقي فيها قيمتان من نوعين — وهو ما يقع في كل سطرٍ تكتبه
> تقريباً.

---

## لماذا يوجد التحويل أصلاً

المعالج لا يجمع `char` و`long`. تعليمةُ الجمع عنده تأخذ مُعامَلين **بنفس العرض
ونفس الطبيعة**.

فحين تكتب `a + b` ونوعاهما مختلفان، لا خيار أمام المترجم إلا أن يحوّل أحدهما.
والسؤال الذي تجيب عنه المواصفة: **أيّهما، وإلى ماذا؟**

والقواعد مكتوبة، وليست حدسيّة، وستراها تُنتج نتائجَ يرفضها الحدس.

---

## الـpromotion: كل ما دون `int` يصير `int`

القاعدة الأولى تُطبَّق قبل أي شيء (§6.3.1.1): **أي قيمةٍ نوعُها أضيق من `int`
تُرقَّى إلى `int` قبل أن تدخل أي عملية.**

```c
#include <stdio.h>

int main(void)
{
	char  a = 100;
	char  b = 100;
	short s = 1;

	printf("%zu %zu %zu\n", sizeof a, sizeof(a + b), sizeof(+s));
	printf("%d\n", a + b);
	return 0;
}
```

<!-- out @impl -->

```
1 4 4
200
```

`a` بايتٌ واحد، **و`a + b` أربعة**. ولذلك خرجت ٢٠٠ سليمةً رغم أنها لا تسع في
`char`: الجمع لم يقع في `char` أصلاً.

**ولاحظ `+s`.** علامة زائدٍ واحدة لا تفعل شيئاً بالقيمة، **وتفعل بالنوع**: ترقّيه
إلى `int`. وهذه هي الطريقة المختصرة لرؤية نوعِ ما بعد الـpromotion.

**والمكسب:** أن الحساب الوسيط لا يفيض في الأنواع الضيّقة. **والثمن** في اللقطة
التالية.

---

## وحين يُرقَّى السالب، تمتدّ الواحدات

الـpromotion تحفظ **القيمة**، لا الـbits. وحفظُ قيمةٍ سالبة في نوعٍ أعرض يوجب ملء
الأعلى بواحدات:

```c
#include <stdio.h>

int main(void)
{
	char          a = 0xAA;
	unsigned char b = 0xAA;
	int           x = a;
	int           y = b;

	printf("%08X %08X\n", x, y);
	return 0;
}
```

<!-- out @impl: حيث `char` ذو إشارة -->

```
FFFFFFAA 000000AA
```

**نفس البايت، ونتيجتان.** `a` قيمته `-86`، وحفظُ `-86` في ٣٢ bit يوجب
`FFFFFFAA`. و`b` قيمته `170`، فيُملأ الأعلى أصفاراً.

اسم الأول **sign extension**. وهو ليس خطأً؛ هو الـpromotion تعمل
بالضبط كما وُعدت — والقيمة محفوظة في الحالتين.

**وهذا هو `FFFFFFAA` الذي بحثتَ عنه في الإقليم ٠٢.** حين مرّرتَ `char` إلى
`printf` بصيغة `%X`، رُقِّي إلى `int` سالبٍ أوّلاً، ثم طُبع بلا إشارة.

**والقاعدة:** لفحص بايتٍ خام، `unsigned char` — دائماً، وبلا استثناء.

---

## الـusual arithmetic conversions، وحيث تُكسَر المقارنة

بعد الـpromotion تأتي القاعدة الثانية (§6.3.1.8): إن بقي النوعان مختلفين، يُحوَّلان
إلى **الأعلى رتبة**. وعند تساوي الرتبة، **`unsigned` يفوز**.

```c
#include <stdio.h>

int main(void)
{
	int          a = -1;
	unsigned int b = 1;
	long         c = -1;
	unsigned int d = 1;

	printf("%d\n", a < b);
	printf("%d\n", c < d);
	printf("%zu %zu\n", sizeof(a + b), sizeof(c + d));
	return 0;
}
```

<!-- out @impl -->

```
0
1
4 8
```

**سطران متطابقان في المعنى، وجوابان.**

في الأول تتساوى الرتبة، فيفوز `unsigned`: يصير `-1` هو `4294967295`، فلا يكون
أصغر من واحد.

وفي الثاني `long` أعلى رتبة **ويسع كل قيم `unsigned int`** — فيُحوَّل `d` إلى
`long`، وتبقى `-1` سالبةً، ويصحّ الجواب.

**وهنا رماديةٌ تلمسك:** الجواب الثاني صحيحٌ لأن `long` ثمانية بايتات على LP64.
وعلى LLP64 — ويندوز — `long` أربعة، فتتساوى الرتبة، **ويصير الجواب `0`**. نفس
الكود، ونفس المترجم تقريباً، وجوابان بحسب الهدف.

والمترجم يحذّر من الأول:

<!-- warn @impl -->

```
warning: comparison of integers of different signs: 'int' and 'unsigned int'
```

## القصّ: ما ينجو هو الأدنى

التحويل إلى نوعٍ **أضيق** لا يمكنه حفظ القيمة، فيحفظ الـbits الدنيا ويرمي ما
فوقها:

```c
#include <stdio.h>

int main(void)
{
	int   n = 300;
	char  c = (char)n;
	int   m = 0x12345678;
	short s = (short)m;

	printf("%d\n", c);
	printf("%X\n", (unsigned short)s);
	return 0;
}
```

<!-- out @impl -->

```
44
5678
```

`300` هي `0x12C`. البايت الأدنى `0x2C` = ٤٤، وذهب الباقي.
و`0x12345678` بقي منه `5678` في `short`.

**وحكمُ هذا في المواصفة يستحقّ الدقّة:**

| الاتّجاه | الحكم |
|---|---|
| إلى نوعٍ **بلا إشارة** | **معرَّف**: الباقي على `2ⁿ` — التفافٌ مضمون |
| إلى نوعٍ **بإشارة** لا يسع القيمة | **معرَّف بالتنفيذ** — لا «غير معرَّف» |

فهو ليس من صنف `x + 1 > x` الذي رأيتَه في الفصل صفر. المترجم يوثّق ما يفعل،
والعمليّ أنه يأخذ الـbits الدنيا. **لكنه ليس مضموناً بالمواصفة**، فلا تبنِ عليه
حساباً تريده منقولاً.

## بين العشريّ والصحيح

```c
#include <stdio.h>

int main(void)
{
	printf("%d %d %d\n", (int)3.9, (int)-3.9, (int)3.0000001);
	printf("%f\n", (float)7 / 2);
	printf("%f\n", (float)(7 / 2));
	int big = 16777217;
	printf("%d\n", (int)(float)big);
	return 0;
}
```

<!-- out -->

```
3 -3 3
3.500000
3.000000
16777216
```

**من العشريّ إلى الصحيح: قصٌّ نحو الصفر**، لا تقريب. و`3.9` تصير `3`، و`-3.9`
تصير `-3`.

**والسطران الأوسطان هما الفخّ اليوميّ.** موضع الـ`cast` يغيّر الجواب: في الأول
حُوِّل `7` قبل القسمة فوقعت قسمةٌ عشرية؛ وفي الثاني وقعت القسمة الصحيحة أوّلاً
ورُمي الباقي، ثم حُوِّل ثلاثةٌ إلى `3.000000`.

**والسطر الأخير:** `16777217` عددٌ صحيحٌ سليم، ومرورُه بـ`float` أنقصه واحداً —
لأنه فوق `2²⁴` الذي رأيتَه في الإقليم ٠٤. التحويل إلى العشريّ **ليس بلا خسارة**.

**وحدٌّ يجب أن تعرفه:** تحويل عشريٍّ لا يسع في النوع الصحيح — `(int)1e20` مثلاً —
**سلوكٌ غير معرَّف**، لا معرَّفٌ بالتنفيذ. افحص المدى قبل التحويل.

## الـ`cast` لا يعيد تفسير الـbits

هذا اعتقادٌ يحمله كثيرون، ويُدفَن بسطرين:

```c
#include <stdio.h>
#include <string.h>

int main(void)
{
	float f = 1.0f;
	int   a = (int)f;
	int   b;

	memcpy(&b, &f, 4);
	printf("%d %08X\n", a, b);
	return 0;
}
```

<!-- out @impl -->

```
1 3F800000
```

**`(int)f` أعطت `1`، و`memcpy` أعطت `3F800000`.**

الـ`cast` يطلب **القيمة** في النوع الجديد: واحدٌ عشريّ يصير واحداً صحيحاً، ويولّد
المترجم تعليمة تحويلٍ فعلية. أمّا إعادة تفسير الـbits نفسها فشيءٌ آخر، وأداتها
`memcpy`.

**والفرق بين الاثنين هو الفرق بين البديهيتين ٢ و٣ في العمل:** الـbits مسطّحة
ويمكن قراءتها بعدسةٍ أخرى، لكن النوع لا ينتقل معها — أنت الذي تختار العدسة، وأنت
الذي تتحمّل ما تراه.

---

## متى تكتب `cast`

الـ`cast` يُسكِت المترجم. وأكثر الأخطاء التي رأيتَها في هذا الإقليم **كان
المترجم يحذّر منها**، فمن يكتب `cast` ليُسكت التحذير يشتري صمتاً بثمن الخطأ.

**اكتبه في ثلاثة مواضع، ولا تكتبه في غيرها:**

| | |
|---|---|
| **لتصحيح الحساب** | `(double)a / b` — تغيّر ما يحدث فعلاً |
| **لتلبية شرطٍ منصوص** | `toupper((unsigned char)c)` — رأيتَه في الإقليم ٠٥ |
| **لأن المعنى يتطلّبه** | قصٌّ مقصود، وأنت تعرف ما يذهب |

وفي غيرها: **غيّر النوع، لا التعبير.** إن كان `int` يقابل `size_t` في مقارنة، فإن
أحدهما نوعٌ خاطئ للمهمّة — والـ`cast` يخفي ذلك ولا يصلحه.

---

## قبل أن تكمل

> **١.** `unsigned char x = 200; unsigned char y = 200;` فما قيمة `x + y`؟ ولماذا
> لا تلتفّ رغم أن النوعين بلا إشارة؟
>
> **٢.** في الإقليم ٠١، `strlen` تُرجع `size_t` وأنت تقارنها في حلقة. اكتب حلقةً
> تعدّ من آخر النصّ إلى أوّله بـ`size_t`، ثم افحص متى تدور بلا نهاية.
>
> **٣.** ما جواب `-1 < sizeof(int)`؟ توقّعه، ثم شغّله، ثم اشرحه بقاعدتين من هذا
> الإقليم.
