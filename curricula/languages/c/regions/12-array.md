# الإقليم ١٢ — الـarray

> رأيتَ في الفصل صفر أن `sizeof` يعطي رقمين مختلفين للـarray نفسها، وقلتُ إنها
> **ندبةٌ من B** لا تصميم. وفي الإقليم ١١ عرفتَ أن `a[i]` تعريفها `*(a + i)`.
>
> هنا يجتمع الاثنان. والـarray في C ليست نوعاً كاملاً كما تظنّ: هي بايتاتٌ
> متلاصقة **تفقد طولها عند أوّل عبور**.

---

## الفهرسة جمعٌ لا أكثر

```c
#include <stdio.h>

int main(void)
{
	int a[4] = { 10, 20, 30, 40 };

	printf("%d %d %d\n", a[2], *(a + 2), 2[a]);
	printf("%zu %zu\n", sizeof a, sizeof a / sizeof a[0]);
	return 0;
}
```

<!-- out @impl -->

```
30 30 30
16 4
```

**`2[a]` تعمل.** ليست حيلة: المواصفة تعرّف `E1[E2]` بأنها `*(E1 + E2)`، والجمع
تبديليّ. فالفهرسة ليست عملية «array»، بل **جمعُ pointer ثم قراءة**.

ومن هنا يتساقط كل ما بعده:

- لا يوجد فحص حدود، لأن الجمع لا يفحص شيئاً.
- الفهرس السالب سليمٌ نحوياً: `p[-1]` هي `*(p - 1)`.
- والـarray لا تحمل طولها، لأن الجمع لا يحتاجه.

**و`sizeof a / sizeof a[0]`** هي كل ما تملكه لعدّ العناصر — وستفقده بعد لقطتين.

---

## `a` و`&a`: عنوانٌ واحد ونوعان

```c
#include <stdio.h>

int main(void)
{
	int a[4] = { 10, 20, 30, 40 };

	printf("%d\n", (void *)a == (void *)&a);
	printf("%td\n", (char *)(a + 1) - (char *)a);
	printf("%td\n", (char *)(&a + 1) - (char *)&a);
	printf("%zu %zu\n", sizeof a, sizeof &a);
	return 0;
}
```

<!-- out @impl -->

```
1
4
16
16 8
```

**العنوان نفسه، والقفزة مختلفة.**

`a` تتحوّل إلى `int *`، فـ`a + 1` تقفز أربعة — عنصراً واحداً.
و`&a` نوعه `int (*)[4]` — pointer إلى **الـarray كلّها** — فـ`&a + 1` تقفز ستّة
عشر.

وهذا هو الإعلان الذي فكّكتَه في الفصل صفر: `int (*q)[3]`. لم يكن تمريناً نظرياً —
هو نوع `&a`.

---

## التحوّل، واستثناءاته الثلاثة

**القاعدة:** اسم الـarray في أي تعبير يتحوّل إلى pointer لأوّل عنصرٍ فيها. ولها
ثلاثة استثناءات فقط:

| الاستثناء | المثال | ماذا يبقى |
|---|---|---|
| `sizeof` | `sizeof a` | الحجم الحقيقيّ |
| `&` | `&a` | pointer إلى الـarray كلّها |
| تهيئة array `char` بنصّ | `char s[] = "ab";` | نسخٌ للمحتوى — الإقليم ١٣ |

وما عدا ذلك: **pointer**. بما في ذلك تمريرها إلى دالّة.

---

## ولذلك لا تُمرَّر array إلى دالّة

```c
#include <stdio.h>

void f(int a[4])
{
	printf("داخلها %zu\n", sizeof a);
	a[0] = 99;
}

int main(void)
{
	int a[4] = { 10, 20, 30, 40 };

	printf("خارجها %zu\n", sizeof a);
	f(a);
	printf("a[0] = %d\n", a[0]);
	return 0;
}
```

<!-- out @impl -->

```
خارجها 16
داخلها 8
a[0] = 99
```

**الرقم `4` في `int a[4]` لا يعني شيئاً.** المترجم يقرأ الوسيط `int *a` مهما
كتبتَ فيه — والدليل أن `sizeof` أعطى ثمانية.

<!-- warn @impl -->

```
warning: sizeof on array function parameter will return size of 'int *' instead of 'int[4]'
```

**والسطر الثالث هو المفاجأة الحقيقية:** الدالّة غيّرت `a[0]` في `main`. وهذا لا
يخالف البديهية الثالثة — الوسيط نسخة، لكنها نسخةٌ من **العنوان**.

**فالـarray الشيء الوحيد في C الذي لا يُنسَخ عند التمرير.** لا لأن لها حكماً
خاصاً، بل لأنها تتحوّل إلى pointer قبل أن يصل التمرير.

**والنتيجة العملية التي تحكم اللغة كلّها:**

```c
void f(int *a, size_t n)
```

**الطول يُمرَّر معه دائماً.** كل دالّةٍ في الـstandard library تأخذ array تأخذ معها
طولاً أو علامةَ نهاية — لا استثناء. وحين تنسى، لا يذكّرك أحد.

---

## لا أحد يفحص الحدّ

حين يكون الفهرس ثابتاً يراه المترجم:

```c
#include <stdio.h>

int main(void)
{
	int a[4] = { 0 };

	a[4] = 1;
	return 0;
}
```

<!-- warn @impl -->

```
warning: array index 4 is past the end of the array (that has type 'int[4]')
```

**وحين يُحسَب وقت التشغيل لا يراه:**

```c
//! cc: -fsanitize=address
//! scrub
//! head: 3
#include <stdio.h>

int main(int argc, char **argv)
{
	int a[4] = { 0 };
	int i = argc + 3;

	a[i] = 1;
	printf("%d\n", a[i]);
	return 0;
}
```

<!-- out @ub: العناوين ورقم الـprocess مستبدَلةٌ بنقاط، والتقرير مقتطع -->

```
=================================================================
==…==ERROR: AddressSanitizer: stack-buffer-overflow on address 0x… at pc 0x… bp 0x… sp 0x…
WRITE of size 4 at 0x… thread T0
```

نفس الكتابة، ونفس الموضع. الأولى كشفها المترجم لأنه يعرف الفهرس، والثانية لم
يعرفها أحد **حتى شغّلتَها بـsanitizer**.

**وبلا الـsanitizer لا يقول أحد شيئاً.** الكتابة تمضي إلى بايتاتٍ تلي الـarray في
الـframe — وقد تكون متغيّراً آخر، أو عنوان العودة.

**وهذا هو خطؤك الأول في الإقليم ٠١** حين نسخنا مفتاحاً طويلاً في `char key[16]`.

---

## الطول في نوعٍ لا يعبر

`a[4]` في الوسيط لا يعني شيئاً — لكن هناك صيغةً تعني:

```c
#include <stdio.h>

void f(int (*a)[4])
{
	printf("%zu %d\n", sizeof *a, (*a)[0]);
}

int main(void)
{
	int a[4] = { 10, 20, 30, 40 };

	f(&a);
	return 0;
}
```

<!-- out @impl -->

```
16 10
```

**الطول عبر هذه المرّة.** لأن النوع الممرَّر `int (*)[4]` — pointer إلى array من
أربعة — والطول جزءٌ من النوع نفسه، فيُفحَص وقت الترجمة.

**وثمنه صيغةٌ يقرؤها قليلون**: `(*a)[0]` بدل `a[0]`، وقوسان في الإعلان. ولذلك لا
تراها كثيراً، والاصطلاح السائد بقي «pointer وطول».

---

## البعدان: صفٌّ يتلو صفّاً

```c
#include <stdio.h>

int main(void)
{
	int a[2][3] = { { 1, 2, 3 }, { 4, 5, 6 } };
	int *flat = &a[0][0];

	printf("%zu %zu %zu\n", sizeof a, sizeof a[0], sizeof a[0][0]);
	for (int i = 0; i < 6; i++)
		printf("%d ", flat[i]);
	printf("\n");
	printf("%d %d\n", a[1][2], *(*(a + 1) + 2));
	return 0;
}
```

<!-- out @impl -->

```
24 12 4
1 2 3 4 5 6 
6 6
```

**لا وجود لـ«array ثنائية» في الذاكرة.** ستّة أعداد متلاصقة، والنوع وحده هو
الذي يقسمها صفّين.

و`a[2][3]` نوعها «array من اثنتين، كلٌّ منهما array من ثلاثة». فـ`a[1]` هي
الصفّ الثاني — array حجمها ١٢ — ثم `[2]` تفهرس داخله.

**والنتيجة التي تلدغ:** حين تمرّرها إلى دالّة يتحوّل الاسم إلى pointer إلى **صفّ**،
فيجب أن تكتب الطول الداخليّ:

```c
void f(int a[][3])      /* الثلاثة إلزامية */
```

لأن `a[i][j]` تحتاج أن تعرف طول الصفّ لتقفز `i` صفوفاً. والطول الخارجيّ وحده هو
الذي يضيع.

## التهيئة

```c
#include <stdio.h>

int main(void)
{
	int a[5] = { 1, 2 };
	int b[5] = { 0 };
	int c[5] = { [4] = 9, [0] = 1 };

	for (int i = 0; i < 5; i++) printf("%d", a[i]);
	printf("\n");
	for (int i = 0; i < 5; i++) printf("%d", b[i]);
	printf("\n");
	for (int i = 0; i < 5; i++) printf("%d", c[i]);
	printf("\n");
	return 0;
}
```

<!-- out -->

```
12000
00000
10009
```

**ما لم تذكره يُصفَّر.** ولذلك `{ 0 }` تصفّر الـarray كلّها — لا لأنها صيغةٌ
سحرية، بل لأن العنصر الأول صفرٌ والباقي يتبع القاعدة.

**والصيغة الثالثة `[4] = 9` تسمية صريحة** (designated initializer)، أُضيفت في
C99. وستراها كثيراً في جداول تُفهرَس بثوابت.

**والفرق بين `int a[5] = { 0 };` و`int a[5];`** هو الفرق بين array مصفَّرة
وarray فيها ما تركه غيرك — وقد رأيتَ ذلك في الإقليم ٠٩.

---

## قبل أن تكمل

> **١.** `char key[16]` في `struct Item`. اكتب `set` بمفتاحٍ من ثلاثين حرفاً
> وشغّل مع `-fsanitize=address`. ثم اقرأ: أي كائنٍ تجاوزتَه، وأين وقع الفائض؟
>
> **٢.** دالّةٌ تأخذ `int *a, size_t n` وتجمع العناصر. مرّر إليها `a + 1` و`n`
> نفسها. من يمنعك؟ ومتى يظهر الأثر؟
>
> **٣.** `sizeof a / sizeof a[0]` داخل دالّةٍ تأخذ `int a[]`. ما الجواب، ولماذا
> يبدو معقولاً وهو خطأ؟ احسبه بيدك قبل أن تشغّل.
