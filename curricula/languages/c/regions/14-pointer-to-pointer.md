# الإقليم ١٤ — pointer إلى pointer

> `char **words` كتبتَها في الإقليم ٠١ وقلتُ لك: لا تحتاج فهمها الآن.
>
> الآن تحتاجه. والنجمتان لا تعنيان «مستوى تعقيدٍ ثانٍ» — تعنيان أن الـpointer
> **متغيّرٌ كغيره**، فله عنوانٌ يُؤخَذ ويُمرَّر ويُخزَّن في array.
>
> ومن هذا تخرج بنيتان تحكمان C كلّها: **array الـpointers**، و**تعديل pointer
> النادي**.

---

## pointer إلى pointer

`int **pp` تُقرأ من الاسم خارجاً: `**pp` نوعه `int`، إذن `*pp` pointer إلى `int`،
إذن `pp` pointer إلى pointer إلى `int`.

```c
#include <stdio.h>

int main(void)
{
	int   x  = 42;
	int  *p  = &x;
	int **pp = &p;

	printf("%d %d %d\n", x, *p, **pp);
	**pp = 7;
	printf("%d\n", x);
	*pp = NULL;
	printf("%d\n", p == NULL);
	return 0;
}
```

<!-- out -->

```
42 42 42
7
1
```

سطران يفرّقان كل شيء:

| | ماذا تغيّر |
|---|---|
| `**pp = 7` | **القيمة** التي في آخر السلسلة — أي `x` |
| `*pp = NULL` | **الـpointer الأوسط** نفسه — أي `p` |

والثاني هو السبب الحقيقيّ لوجود النجمتين في أكثر الكود: **أن تغيّر pointer يملكه
غيرك.**

---

## أن تغيّر pointer النادي

البديهية الثالثة سارية على الـpointers كغيرها: دالّةٌ تأخذ `char *` تأخذ **نسخةً**
منه، فتغييرها لا يصل. فإن أرادت أن تعطيك pointer جديداً، تحتاج عنوان الـpointer عندك.

```c
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

int dup_it(const char *src, char **out)
{
	char *p = malloc(strlen(src) + 1);

	if (p == NULL)
		return -1;
	strcpy(p, src);
	*out = p;
	return 0;
}

int main(void)
{
	char *s = NULL;

	printf("قبل: %p\n", (void *)s);
	if (dup_it("hi", &s) == 0)
		printf("بعد: [%s]\n", s);
	free(s);
	return 0;
}
```

<!-- out -->

```
قبل: 0x0
بعد: [hi]
```

**وهذه الصيغة اصطلاحٌ كامل في C:** القيمة المُرجَعة **حالةُ النجاح**، والنتيجة
تخرج عبر وسيط. والسبب أن `return` واحد، والفشل يحتاج قناةً منفصلة عن النتيجة —
الإقليم ٢٢ يبني نموذج الفشل كلّه على هذا.

## array الـpointers مقابل الـarray الثنائية

الاستعمال الثاني للنجمتين. وهما شكلان مختلفان تماماً في الذاكرة:

```c
#include <stdio.h>

int main(void)
{
	char *pa[3]   = { "a", "bb", "ccc" };
	char  m[3][4] = { "a", "bb", "ccc" };

	printf("%zu %zu\n", sizeof pa, sizeof m);
	printf("%zu %zu\n", sizeof pa[0], sizeof m[0]);
	printf("%s %s\n", pa[2], m[2]);
	return 0;
}
```

<!-- out @impl -->

```
24 12
8 4
ccc ccc
```

```
char *pa[3]                       char m[3][4]
┌────┬────┬────┐                  ┌───┬───┬───┬───┐
│ ●  │ ●  │ ●  │  ٢٤ بايتاً        │ a │ \0│ ? │ ? │
└─┬──┴─┬──┴─┬──┘                  ├───┼───┼───┼───┤
  ▼    ▼    ▼                     │ b │ b │ \0│ ? │
 "a"  "bb" "ccc"   في مكانٍ آخر    ├───┼───┼───┼───┤
                                  │ c │ c │ c │ \0│
                                  └───┴───┴───┴───┘  ١٢ بايتاً
```

**الأولى ثلاثة عناوين**، والنصوص في مكانٍ آخر ولكلٍّ طوله. **والثانية بايتاتٌ
متلاصقة**، وكل صفٍّ بعرضٍ ثابت — فما قصر حُشي، وما طال لم يسع.

| | array pointers | array ثنائية |
|---|---|---|
| طول العنصر | حرّ | ثابت |
| الترتيب | تبديل عنوانين | نسخ صفٍّ كامل |
| كلفة الوصول | قراءتان | حسابٌ واحد |
| النصوص | قد تكون للقراءة فقط | مِلكك |

**و`argv` من النوع الأول**، ولذلك تصلح لوسائط أطوالها مجهولة.

## `argv`: أوّل `char **` رأيتَه

`main` لها صيغةٌ ثانية تعطيك ما كُتب في سطر الأمر:

```c
//! argv: set name ali
#include <stdio.h>

int main(int argc, char **argv)
{
	printf("argc = %d\n", argc);
	for (int i = 0; i < argc; i++)
		printf("argv[%d] = [%s]\n", i, argv[i]);
	printf("argv[argc] == NULL : %d\n", argv[argc] == NULL);
	return 0;
}
```

شغّله هكذا: `./main set name ali`

<!-- out -->

```
argc = 4
argv[0] = [./main]
argv[1] = [set]
argv[2] = [name]
argv[3] = [ali]
argv[argc] == NULL : 1
```

**`argv[0]` اسم البرنامج**، فالوسائط تبدأ من واحد.

**والسطر الأخير اصطلاحٌ ستحتاجه:** الـarray تنتهي بـpointer صفريّ. فتستطيع المرور
عليها بلا `argc` أصلاً — وهذا بالضبط ما تشترطه `execvp` في الإقليم ٢٥ حين تسلّمها
`argv` لتشغّل برنامجاً.

**وقسمةُ العمل واضحة:** الصدفة قسّمت السطر ومرّرت القِطع، وبرنامجك تسلّمها مقسومة.
وفي الإقليم ٠١ كنتَ **أنت** الصدفة: `split` تفعل ما تفعله هي.

## من يملك ماذا

وهذا هو السؤال الذي يفصل بين `char **` سليمة و`char **` قاتلة.

<!-- part: 14-own -->

```c
int main(void)
{
	char  line[] = "set name ali";
	char *words[MAX_WORDS];
	int   n = split(line, words);

	for (int i = 0; i < n; i++)
		printf("%td ", words[i] - line);
	printf("\n");
	line[4] = 'X';
	printf("[%s]\n", words[1]);
	return 0;
}
```

<!-- out -->

```
0 4 9 
[Xame]
```

**الأرقام إزاحاتٌ داخل `line`.** الكلمات الثلاث لا تملك بايتاً واحداً: كلٌّ منها
**يستعير** موضعاً في array يملكها `main`.

**والسطر الأخير هو البرهان:** غيّرتُ `line[4]` فتغيّرت `words[1]`. لأنهما نفس
البايت.

| | من يملك النصّ | متى يموت | من يحرّر |
|---|---|---|---|
| `split` في الإقليم ٠١ | `line` | بخروج `main` | لا أحد |
| `argv` | النظام | بنهاية الـprocess | لا أحد |
| `malloc` في `copy` | أنت | حين تحرّر | **أنت** |

**والخطأ الذي يقتل: أن تُرجع `words` من دالّةٍ يموت فيها `line`.** الـarray تعبر
سليمة، والبايتات التي تشير إليها تصير لغيرك — وهو الـdangling pointer من الإقليم ١١،
لكن ثمانية منه دفعةً واحدة.

**فحين تكتب `char **`، اكتب بجانبها من يملك ما تشير إليه.** هذا ليس نصيحة تنظيم:
هو المعلومة الوحيدة التي لا تحملها اللغة عنك، ولا يذكّرك بها أحد.

---

## قبل أن تكمل

> **١.** في الإقليم ٠١، ماذا يحدث لو نقلتَ `char line[128]` من `main` إلى داخل
> حلقةِ `while`؟ ولو جعلتَها `static`؟ ولو حجزتَها بـ`malloc` بلا `free`؟
>
> **٢.** اكتب دالّةً تنسخ `words` نسخاً حقيقياً — بحيث تعيش بعد موت `line`. كم
> `malloc` تحتاج، وكم `free` يقابلها، ومن ينادي أيّها؟
>
> **٣.** `char **p` و`char *p[]` في **وسيط دالّة** — هل بينهما فرق؟ وفي إعلانٍ
> داخل دالّة؟ جرّب الأربع حالات، واشرحها بقاعدة التحوّل من الإقليم ١٢.
