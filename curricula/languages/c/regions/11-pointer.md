# الإقليم ١١ — الـpointer

> انتهى الإقليم ٠٩ عند حائط: الدالّة تأخذ نسخة، فلا تصل إلى الأصل. ثم رأيتَ
> `divmod` تصل إليه بشيءٍ لم أشرحه.
>
> الـpointer ليس مفهوماً غامضاً. هو **متغيّرٌ قيمتُه عنوان**. وكل ما يبدو تعقيداً فيه
> نتيجةُ سطرٍ واحد: البديهية الثالثة — كل تمريرٍ نسخ — التي لا تُكسَر، فيُنسَخ
> العنوان بدل الشيء.

---

## عنوانٌ يُخزَّن

```c
#include <stdio.h>

int main(void)
{
	int  x = 42;
	int *p = &x;

	printf("%d %d\n", x, *p);
	*p = 7;
	printf("%d %d\n", x, *p);
	printf("%d\n", &x == p);
	printf("%zu %zu\n", sizeof x, sizeof p);
	return 0;
}
```

<!-- out -->

```
42 42
7 7
1
4 8
```

معاملان، وكلٌّ عكس الآخر:

| | |
|---|---|
| `&x` | **عنوان** `x` |
| `*p` | **الشيء الذي عنوانه** `p` |

والسطر الثاني هو المهمّ: `*p = 7` غيّرت `x` بلا أن تذكر اسمها. **وهذا كل ما يفعله
الـpointer.**

**والحجمان مختلفان:** `x` أربعة، و`p` ثمانية. حجم الـpointer حجمُ العنوان على هذا
الهدف، ولا علاقة له بحجم ما يشير إليه.

---

## اقرأ الإعلان من الاسم

`int *p;` تربك لأن الناس يقرؤونها «`int*` اسمه `p`». والقراءة الصحيحة من الاسم
خارجاً، كما في الفصل صفر:

```
int *p;      ⇐  «*p» نوعُه int   ⇐  p pointer إلى int
```

**ولهذا تُلصَق النجمة بالاسم** في اصطلاح C: `int *p` لا `int* p`. والسبب عمليّ لا
جماليّ:

```c
int* a, b;      /* a pointer، و b عددٌ عاديّ */
int *a, *b;     /* الاثنان pointerان */
```

النجمة تتبع **المُعلَن**، لا النوع. فمن يكتبها ملتصقةً بالنوع يُعلن نيّةً لا
تنفّذها اللغة.

---

## `NULL`: عنوانٌ لا يشير إلى شيء

الـpointer يحتاج قيمةً تعني «لا شيء». وهي `NULL`.

```c
//! cc: -fsanitize=undefined
//! head: 2
#include <stdio.h>

int main(void)
{
	int *p = NULL;

	printf("%d\n", *p);
	return 0;
}
```

<!-- out @ub: أوّل سطرين من التقرير — وذيلُه سجلّاتُ معالجٍ لا تعنيك -->

```
main.c:7:17: runtime error: load of null pointer of type 'int'
SUMMARY: UndefinedBehaviorSanitizer: undefined-behavior main.c:7:17 in
```

**والبرنامج يموت بعدها.** قراءة `*p` وهو `NULL` **سلوكٌ غير معرَّف**، وما وقع هنا
أن النظام منع الوصول إلى العنوان صفر فأنهى الـprocess.

**وهذا أرحم ما قد يحدث.** لأن الخطأ ظهر فوراً وبالسطر. والـpointer الذي يحمل عنواناً
**خاطئاً لا صفرياً** لا يُوقفه أحد — يقرأ بايتاتٍ ليست له ويمضي.

ولذلك اصطلاح C: **كل دالّةٍ تُرجع pointer قد تُرجع `NULL`، والفحص على النادي.**
رأيتَه في الإقليم ٠١ في `find`، وستراه في كل `malloc` بعد اليوم.

---

## الحساب على الـpointer يُقاس بالنوع

`p + 1` لا تزيد العنوان واحداً. تزيده **حجم ما يشير إليه**:

```c
#include <stdio.h>

int main(void)
{
	int   a[4] = { 10, 20, 30, 40 };
	int  *p = a;
	char *c = (char *)a;

	printf("%d %d %d\n", *p, *(p + 1), *(p + 3));
	printf("%td\n", (p + 3) - p);
	printf("%td\n", (char *)(p + 1) - (char *)p);
	printf("%d\n", *c);
	return 0;
}
```

<!-- out @impl -->

```
10 20 40
3
4
10
```

**السطر الثالث هو الدليل:** بين `p` و`p + 1` أربعة بايتات. المترجم ضرب الواحد في
`sizeof(int)` عنك.

**والطرح يعطي عدد العناصر لا البايتات:** `(p + 3) - p` هي `3`. ونوع الناتج
`ptrdiff_t`، وصيغته `%td`.

وهذا هو السبب في أن `a[i]` تعمل أصلاً. فـ`a[i]` **تعريفها في المواصفة**
`*(a + i)`، لا شيء آخر. الإقليم ١٢ يبني على هذا السطر كلّه.

**وحدٌّ منصوص:** الحساب مسموحٌ داخل الكائن الواحد **وعنصرٍ واحد بعد نهايته** فقط.
وما عدا ذلك غير معرَّف — حتى لو لم تقرأ من العنوان.

## `const` والـpointer: موضعان ومعنيان

هنا يخطئ الناس كثيراً، والقاعدة تُقرأ من الاسم كما تعلّمت:

```c
#include <stdio.h>

int main(void)
{
	int a = 1, b = 2;

	const int *p = &a;      /* ما يشير إليه ثابت */
	int *const q = &a;      /* الـpointer نفسه ثابت */

	p = &b;                 /* مسموح */
	*q = 3;                 /* مسموح */
	printf("%d %d\n", *p, *q);
	return 0;
}
```

<!-- out -->

```
2 3
```

والمنعان مقلوبان:

```c
int main(void)
{
	int a = 1;
	const int *p = &a;

	*p = 5;
	return 0;
}
```

<!-- err -->

```
error: read-only variable is not assignable
```

```c
int main(void)
{
	int a = 1, b = 2;
	int *const q = &a;

	q = &b;
	return 0;
}
```

<!-- err -->

```
error: cannot assign to variable 'q' with const-qualified type 'int *const'
```

**والقاعدة: `const` تؤهّل ما على يسارها**، فإن لم يكن على يسارها شيء فما على
يمينها.

**وأيّهما تستعمل؟** الأولى، وكثيراً. `const char *s` في وسيط دالّة **عقدٌ مع
القارئ**: هذه الدالّة تقرأ ولا تكتب. وستراها في كل نموذجٍ أوّليّ في المكتبة
القياسية — `strlen(const char *)` — والإقليم ١٣ يقول لماذا هي شرطٌ لا زينة.

## `void *`: pointer بلا عدسة

```c
#include <stdio.h>
#include <stdlib.h>

int main(void)
{
	void *v = malloc(4);
	int  *p = v;

	*p = 5;
	printf("%d\n", *p);
	printf("%zu\n", sizeof(void *));
	free(v);
	return 0;
}
```

<!-- out @impl -->

```
5
8
```

`void *` يحمل عنواناً **بلا نوعٍ مُشارٍ إليه**. ويتحوّل من أي pointer كائنٍ وإليه
بلا `cast`، ولذلك كان النوع الذي تُرجعه `malloc`: هي تعطيك بايتاتٍ ولا تعرف ماذا
ستضع فيها.

**وثمنه أنه لا يُقرأ:** لا `*v`، ولا `v + 1` — لأن الحساب يحتاج حجماً، ولا حجم
لـ`void`. وهذا هو الشرط الذي كسره مترجمك في الفصل صفر حين قبل `sizeof(void)`،
ورفضه `-pedantic`.

**فهو النوع الذي تعبر منه، لا الذي تعمل به.** خذه، وأسنِده إلى pointer له نوع،
ثم اعمل.

## الـdangling pointer

عُد إلى `bad()` من الإقليم ٠٩ بعينٍ جديدة:

```c
int *bad(void)
{
	int x = 42;

	return &x;
}
```

الـpointer الذي تُرجعه **سليمٌ في شكله**: ثمانية بايتاتٍ فيها عنوان. والعنوان نفسه
كان صحيحاً لحظةَ أُخذ.

**والذي مات ليس الـpointer، بل ما يشير إليه.** لا يوجد في الـpointer ما يقول ذلك، ولا
في الذاكرة ما يسجّله (البديهية الأولى). فقراءة `*p` بعدها تقرأ الـframe وقد صار لغيرك —
تماماً كما قرأت `b()` بقايا `a()`.

**واسم هذه الحالة: dangling pointer.** وهي أخطر ما في هذه اللغة، لأنها لا
تُكتشَف بالنظر ولا بالتشغيل غالباً.

**والسؤال الذي يفتح الإقليم ١٦:** إن كان ما تحجزه الدالّة يموت معها، فأين تضع
شيئاً تريده أن يعيش بعدها — ولا تعرف حجمه وقت الترجمة؟

---

## قبل أن تكمل

> **١.** في الإقليم ٠١، `find` تُرجع `struct Item *`، و`cmd_get` تفحص `NULL`.
> احذف الفحص وشغّل `get x` لمفتاحٍ غير موجود. ما الذي يحدث بالضبط، ولماذا؟
>
> **٢.** اكتب `swap(int *a, int *b)` تبدّل قيمتين. ثم اكتب لماذا يستحيل كتابتها
> بلا pointers — بجملةٍ واحدة تذكر البديهية الثالثة.
>
> **٣.** `int *p; *p = 5;` — لم تسنِد إلى `p` شيئاً. هل هذا مثل `NULL`؟ شغّله
> مع `-fsanitize=address`، ثم اشرح لماذا هذه الحالة **أسوأ** من الصفرية.
