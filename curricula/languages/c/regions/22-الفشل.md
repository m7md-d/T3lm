# الإقليم ٢٢ — الفشل

> `fopen` أرجعت `NULL` في الإقليم السابق، ولم تقل لماذا. وسؤالك الثالث هناك كان:
> ما الفرق بين ملفٍّ غير موجودٍ وملفٍّ لا تملك إذنه؟
>
> **في C لا يوجد استثناء.** لا `try` ولا `catch` ولا شيءٌ يقفز فوق `return`.
> والفشل **قيمةٌ تُرجَع**، ومعرفةُ سببه قناةٌ ثانية منفصلة تماماً.
>
> وهذا الإقليم عن القناتين، وعن الانضباط الذي تفرضانه.

---

## الفشل قيمة (البديهية الخامسة)

لا شيء في اللغة يعرف معنى «خطأ». فاصطلح الناس على أربع صيغ، وستراها كلّها في أي
كودٍ حقيقيّ:

| الصيغة | من يستعملها | الفحص |
|---|---|---|
| **`NULL`** لمن يُرجع pointer | `fopen` · `malloc` · `strchr` | `if (p == NULL)` |
| **عددٌ سالب** أو `-1` | `open` · `read` · معظم النظام | `if (n < 0)` |
| **قيمةٌ حارسة** | `getchar` ⟵ `EOF` · `strtol` ⟵ `0` | حسب الدالّة |
| **حالةٌ ترجع، والنتيجة في وسيط** | كودك أنت غالباً | `if (f(&out) != 0)` |

**والصيغة الثالثة أخطرها**، لأن القيمة الحارسة **قد تكون نتيجةً صحيحة**:
`strtol("0")` تُرجع صفراً، و`strtol("abc")` تُرجع صفراً. فلا يميّزهما إلا القناة
الثانية.

**والرابعة أنظفها**، وهي التي كتبتَها في الإقليم ١٤ في `dup_it`: القيمة المرجَعة
للحالة، والنتيجة عبر `char **out`.

## `errno`: القناة الثانية

```c
//! pty
#include <stdio.h>
#include <errno.h>
#include <string.h>

int main(void)
{
	FILE *f = fopen("nope.txt", "r");

	printf("f = %p\n", (void *)f);
	printf("errno = %d\n", errno);
	printf("strerror = %s\n", strerror(errno));
	perror("fopen");
	return 0;
}
```

<!-- out @impl -->

```
f = 0x0
errno = 2
strerror = No such file or directory
fopen: No such file or directory
```

`errno` رقمٌ عالميّ تضع فيه المكتبة والنظام سببَ آخر فشل. و`<errno.h>` يعطي
أسماءه: `ENOENT` لا موجود، و`EACCES` لا إذن، و`ENOMEM` لا ذاكرة.

| | |
|---|---|
| `strerror(errno)` | نصٌّ يصف الرقم |
| `perror("fopen")` | يطبع `"fopen: "` ثم النصّ **إلى `stderr`** |

**و`errno` ليس متغيّراً عادياً** — المواصفة تصفه بأنه lvalue قابل للتعديل، وهو
في التنفيذات الحديثة **ماكرو** يوصلك إلى نسخةٍ خاصّة بخيطك. ولذلك لا تكتب
`extern int errno;` كما كان يُفعَل قديماً.

## ومتى يصحّ أن تقرأه

هذه هي القاعدة التي يخالفها كثيرون:

```c
#include <stdio.h>
#include <errno.h>
#include <string.h>

int main(void)
{
	FILE *a = fopen("nope.txt", "r");

	(void)a;
	printf("بعد الفشل: %d\n", errno);

	FILE *b = fopen("ok.txt", "w");

	printf("b = %d\n", b != NULL);
	printf("بعد النجاح: %d — %s\n", errno, strerror(errno));
	if (b)
		fclose(b);
	return 0;
}
```

<!-- out @impl -->

```
بعد الفشل: 2
b = 1
بعد النجاح: 2 — No such file or directory
```

**النداء الثاني نجح، و`errno` ما زال يقول «لا يوجد».**

لأن المواصفة تلزم الدوالّ بأن **تضع** فيه عند الفشل، **ولا تلزمها بتصفيره عند
النجاح**. فقيمته بعد نداءٍ ناجح **بقايا** لا معلومة.

**فالقاعدتان:**

1. **لا تقرأ `errno` إلا بعد أن تكتشف الفشل بالقيمة المرجَعة.** هو يفسّر الفشل،
   ولا يعلن عنه.
2. **اقرأه فوراً.** أي نداءٍ بينهما — حتى `printf` — قد يغيّره.

**والاستثناء الوحيد:** دوالٌّ لا تُميّز الفشل بقيمتها، مثل `strtol`. فيها
**تصفّره أنت قبل النداء** ثم تفحصه بعده:

```c
#include <stdio.h>
#include <errno.h>
#include <stdlib.h>
#include <string.h>

int main(void)
{
	errno = 0;
	long v = strtol("999999999999999999999999", NULL, 10);

	printf("%ld\n", v);
	printf("errno = %d — %s\n", errno, strerror(errno));

	errno = 0;
	v = strtol("abc", NULL, 10);
	printf("%ld errno=%d\n", v, errno);
	return 0;
}
```

<!-- out @impl -->

```
9223372036854775807
errno = 34 — Result too large
0 errno=22
```

**السطر الأول قيمةٌ حقيقية** — `LONG_MAX` — ومع ذلك النداء فشل. ولولا `errno` لما
عرفتَ.

**والسطر الأخير رماديّ:** فشل التحويل أصلاً، و`errno` صار ٢٢. **والمواصفة لا تلزم
بشيءٍ هنا** — تلزم بـ`ERANGE` عند الفيض وحده. فالفحص المنقول هو `endptr`:

```c
char *end;
errno = 0;
long v = strtol(s, &end, 10);
if (end == s)          /* لم يُحوَّل شيء */;
if (*end != '\0')      /* بقيت حروف */;
if (errno == ERANGE)   /* فاض */;
```

## رمز الخروج

القناة التي يقرؤها من شغّل برنامجك:

<!-- part: 22-exit -->

```c
static void bye(void)  { printf("atexit 1\n"); }
static void bye2(void) { printf("atexit 2\n"); }

int main(void)
{
	atexit(bye);
	atexit(bye2);
	printf("EXIT_SUCCESS=%d EXIT_FAILURE=%d\n", EXIT_SUCCESS, EXIT_FAILURE);
	exit(3);
}
```

<!-- out -->

```
EXIT_SUCCESS=0 EXIT_FAILURE=1
atexit 2
atexit 1
رمز الخروج = 3
```

**صفرٌ نجاح، وغيره فشل.** وهذا اصطلاح النظام لا اللغة، وهو ما يجعل `cmd1 && cmd2`
تعمل في أي shell.

**و`atexit` تُنفَّذ بالترتيب المعكوس** — الأخير المسجَّل أوّلاً. وهي المكان الذي
تُغلَق فيه الموارد العامّة.

| | |
|---|---|
| `return n;` من `main` | كـ`exit(n)` تماماً |
| `exit(n)` | ينفّذ `atexit`، **ويُفرِغ الـbuffers**، ثم ينهي |
| `_exit(n)` | ينهي فوراً — **بلا** `atexit` وبلا إفراغ |
| `abort()` | إنهاءٌ غير طبيعيّ، والنظام يرى إشارةً لا رمزاً |

**والفرق بين `exit` و`_exit` سيصير حرجاً في الإقليم ٢٥** حين تصير في برنامجك
عمليتان لكلٍّ منهما نسخةٌ من نفس الـbuffer.

**ولا تُرجع رمزاً عشوائياً:** المدى المنقول ٠–١٢٥؛ وما فوقه تستعمله الـshells
لمعانٍ أخرى.

## الانضباط الذي يفرضه هذا

لا شيء في C يُجبرك على فحص قيمةٍ مرجَعة. **ولا شيء يخبرك أنك لم تفحص.**

```c
FILE *f = fopen(path, "r");
fgets(line, sizeof line, f);      /* و`f` صفريّ */
```

يُترجَم بلا كلمة. والانهيار يقع في `fgets`، بعيداً عن السبب.

**والقاعدة الوحيدة العملية: افحص عند النداء، لا بعده بأسطر.** وكل دالّةٍ في هذا
المنهج تُرجع pointer أو `int` **يجب** أن يُفحَص سطرَ ندائها.

**وحين تتراكم الفحوص** تعود إلى صيغة `goto` من الإقليم ٠٨ — وهذه هي صورتها
الحقيقية أخيراً:

```c
int load(const char *path, char **out)
{
	FILE *f    = NULL;
	char *buf  = NULL;
	int   rc   = -1;

	f = fopen(path, "rb");
	if (f == NULL)
		goto out;                       /* errno من fopen */

	buf = malloc(4096);
	if (buf == NULL)
		goto out_close;

	if (fread(buf, 1, 4096, f) == 0 && ferror(f))
		goto out_free;

	*out = buf;
	buf  = NULL;                            /* سلّمنا المِلكية */
	rc   = 0;

out_free:
	free(buf);
out_close:
	fclose(f);
out:
	return rc;
}
```

**وسطر `buf = NULL;` هو المهمّ.** بعده يصير `free(buf)` في مسار النجاح لا يفعل
شيئاً — لأن `free(NULL)` مضمونةٌ من الإقليم ١٦ — فيصير مسار النجاح ومسار الفشل
**نفس الكود**.

## ما اشترته C بهذا كلّه

الصيغة أطول من `try/catch` بلا شكّ. وثمنها معلوم: نسيان فحصٍ واحد خطأٌ صامت.

**وما اشترته:**

| | |
|---|---|
| **لا مسار تنفيذٍ خفيّ** | كل خروجٍ من دالّة مكتوبٌ في نصّها |
| **لا كلفة وقت تشغيل** | لا جداول فكّ مكدّس، ولا شيء يُحمَّل لأجل الفشل |
| **الفشل في التوقيع** | نوع الإرجاع يقول إن كان يفشل، فتراه قبل أن تقرأ الجسم |

وهذه هي البديهية الأولى تُطبَّق على الأخطاء: **لا شيء يبقى وقت التشغيل** — ولا
حتى آليةٌ لنقل خطأ.

## قبل أن تكمل

> **١.** أجب عن سؤالك المعلّق: `fopen("/etc/passwd", "w")` و`fopen(".", "r")` —
> اطبع `errno` واسمه في الحالتين. أي رقمين، وماذا يعنيان؟
>
> **٢.** في الإقليم ٠١، `malloc` في `copy` بلا فحص. أضِف الفحص — ماذا تُرجع
> `copy`؟ ومن يفحص جوابها؟ وماذا يفعل `cmd_set` حينئذٍ؟
>
> **٣.** اكتب `main` يُرجع `EXIT_FAILURE` إن فشل أمر. ثم شغّله في الـshell
> واقرأ `$?`. ثم جرّب `./prog && echo نجح`.
