# الإقليم ١٠ — الاسم والمكان

> في الإقليم ٠١ كتبتَ `struct Item table[64];` و`int items = 0;` **خارج** كل
> دالّة، وكتبتَ `char line[128]` **داخل** `main`. الفرق ليس في موضع السطر.
>
> هنا محوران منفصلان يخلط بينهما الناس: **أين يُرى الاسم**، و**متى يموت
> الشيء**. وبينهما تسكن الكلمتان اللتان تغيّران معنى كليهما: `static` و`extern`.

---

## الـscope: من يرى الاسم

الاسم يُرى داخل القوسين المعقوفين اللذين أُعلن فيهما، وفي كل ما بداخلهما.

```c
#include <stdio.h>

int x = 1;

int main(void)
{
	printf("%d\n", x);
	{
		int x = 2;
		printf("%d\n", x);
		{
			int x = 3;
			printf("%d\n", x);
		}
		printf("%d\n", x);
	}
	printf("%d\n", x);
	return 0;
}
```

<!-- out -->

```
1
2
3
2
1
```

**ثلاثة متغيّراتٍ بنفس الاسم، وثلاثة كائناتٍ مستقلّة.** والداخليّ **يحجب**
الخارجيّ ولا يمسّه — والدليل أن القيمة تعود عند الخروج من كل قوس.

هذا اسمه **الـshadowing**. وهو مسموحٌ ومفيد أحياناً — ومصدر ساعاتٍ ضائعة حين
لا تنتبه إلى أن الاسم الذي تعدّله ليس الذي تظنّ.

**والقوسان يصنعان scope حتى بلا `if` ولا حلقة**، كما في اللقطة. وهذه طريقةٌ
شرعية لحصر متغيّرٍ مؤقّت.

---

## أربعة scopes، لا واحد

| الـscope | أين يبدأ | مثاله عندك |
|---|---|---|
| **الكتلة** | من الإعلان إلى القوس المغلق | `int n` داخل `main` |
| **الملفّ** | من الإعلان إلى آخر الملفّ | `table` و`items` في الإقليم ٠١ |
| **الـprototype** | داخل قوسَي الإعلان وحدهما | الاسم في `int f(int len);` |
| **الدالّة** | الدالّة كلّها، للعلامات وحدها | `out:` في لقطة `goto` |

**والثالث يفسّر شيئاً قد يكون حيّرك:** الأسماء في الـprototype تُنسى فوراً،
ولذلك `int f(int len);` و`int f(int);` سواء، ولذلك يجوز أن يختلف الاسم بين
الإعلان والتعريف.

**والرابع سبب أن العلامات تُرى في كل الدالّة**: `goto out;` تعمل ولو كانت `out:`
بعدها بعشرين سطراً وخارج قوسها.

---

## العمر محورٌ آخر

الـscope يقول **من يرى**. والعمر يقول **متى يوجد**. وهما مستقلّان:

| العمر | متى يُنشأ ويُهدَم | أين يسكن |
|---|---|---|
| **تلقائيّ** (automatic) | عند دخول الكتلة، ويموت عند الخروج | الـstack |
| **ساكن** (static) | قبل `main`، ويعيش إلى نهاية البرنامج | منطقةٌ ثابتة |
| **مخصَّص** (allocated) | حين تطلب، ويموت حين تحرّر | الـheap — الإقليم ١٦ |

**وكل ما رأيتَه حتى الآن داخل الدوالّ تلقائيّ.** ولذلك مات `x` في `bad()` بنهاية
الإقليم السابق.

---

## `static` داخل دالّة: اسمٌ محلّيّ وعمرٌ طويل

```c
#include <stdio.h>

int counter(void)
{
	static int n = 0;

	n++;
	return n;
}

int plain(void)
{
	int n = 0;

	n++;
	return n;
}

int main(void)
{
	int a = counter(), b = counter(), c = counter();
	int x = plain(),   y = plain(),   z = plain();

	printf("%d %d %d\n", a, b, c);
	printf("%d %d %d\n", x, y, z);
	return 0;
}
```

<!-- out -->

```
1 2 3
1 1 1
```

`n` في `counter` **لا يُرى إلا داخلها**، ومع ذلك **لا يموت بخروجها**. الـscope
محلّيّ والعمر ساكن.

**و`= 0` تُنفَّذ مرّةً واحدة**، قبل `main` — لا في كل نداء. ولو كانت تُنفَّذ كل
مرّة لصارت `counter` مثل `plain`.

**ولاحظتَ أني أسنَدتُ النداءات إلى متغيّراتٍ أوّلاً**، ولم أكتبها داخل `printf`.
السبب من الإقليم ٠٧: ترتيب تقييم الوسائط **غير محدَّد**، ودالّةٌ لها أثرٌ باقٍ
تعطي جواباً يعتمد على ترتيبٍ لا يَعِد به أحد.

## والساكن يبدأ من الصفر

```c
#include <stdio.h>

int   g;
char  gs[4];
int  *gp;

int main(void)
{
	printf("%d %d %d %d\n", g, gs[0], gs[3], gp == NULL);
	return 0;
}
```

<!-- out -->

```
0 0 0 1
```

**كلّها أصفار، بلا أن تطلب.** والفرق عن المتغيّر المحلّيّ الذي طبع `111` في
الإقليم السابق هو الفرق بين عمرين: الساكن يُصفَّر مرّةً عند تحميل البرنامج،
والتلقائيّ يأخذ ما تركه غيره.

**والـpointer يصير `NULL`** لا بايتاتٍ صفرية اتّفاقاً — المواصفة تنصّ على أن التصفير
يعطي الـpointer قيمةً صفرية.

**وثمن هذا الضمان: تهيئة الساكن يجب أن تُعرَف وقت الترجمة.**

```c
#include <stdio.h>

int f(void) { return 5; }

int main(void)
{
	static int s = f();

	printf("%d\n", s);
	return 0;
}
```

<!-- err -->

```
error: initializer element is not a compile-time constant
```

القيمة تُكتب في الملفّ التنفيذيّ نفسه قبل أن يعمل شيء، فلا يمكن أن تأتي من نداء.
هذا هو ثمن **البديهية الأولى**: لا وقت تشغيلٍ يسبق `main` ليُنفِّذ التهيئة.

## ثلاث مناطق، وعنوانٌ يفضحها

<!-- runs -->

```c
#include <stdio.h>
#include <stdlib.h>

int g = 1;

int main(void)
{
	static int s = 2;
	int        a = 3;
	int       *h = malloc(sizeof(int));

	printf("global %p\n", (void *)&g);
	printf("static %p\n", (void *)&s);
	printf("heap   %p\n", (void *)h);
	printf("stack  %p\n", (void *)&a);
	free(h);
	return 0;
}
```

<!-- out @machine: العناوين تختلف بين تشغيلين، والذي يُقرأ هو التباعد -->

```
global 0x100e68000
static 0x100e68004
heap   0x13be05d80
stack  0x16ef9e578
```

**العامّ والساكن متجاوران** — أربعة بايتاتٍ بينهما — لأنهما في نفس المنطقة رغم
اختلاف scope كلٍّ منهما.

**والـheap والـstack بعيدان جداً** عنهما وعن بعضهما. وهذا ليس صدفة: المنطقتان تنموان
في اتّجاهين، فتُوضَعان على طرفين ليطول ما بينهما.

**والمواصفة لا تعرف شيئاً من هذا.** لا تذكر stack ولا heap ولا مناطق — تذكر
**أعماراً** فقط، والنظام هو الذي يترجمها إلى مواضع. الإقليم ٢٥ يقول من يرسم هذه
الخريطة.

---

## `static` على الملفّ: معناها الآخر

نفس الكلمة، ومعنىً مختلف تماماً بحسب موضعها:

| الموضع | المعنى |
|---|---|
| داخل دالّة | **عمرٌ** ساكن، والـscope كما هو |
| خارج كل دالّة | **الاسم لا يُرى خارج هذا الملفّ**، والعمر ساكن أصلاً |

فـ`static int items = 0;` خارج الدوالّ تقول: هذا المتغيّر **مِلك هذا الملفّ**،
ولا يستطيع ملفٌّ آخر أن يصل إليه ولو عرف اسمه.

**وهذا هو ما تملكه C بدل `private`.** لا كلمة `namespace` ولا `module`؛ وحدة
الإخفاء هي **الملفّ**، وأداتها `static`.

ومقابلها `extern`: إعلانٌ بأن هذا الاسم **معرَّفٌ في مكانٍ آخر**، فلا تحجز له
مكاناً هنا. والاثنتان لا يظهر أثرهما إلا حين تصير الملفّات أكثر من واحد —
**الإقليم ١٨**.

---

## ولذلك تحمل دوالُّ C بادئات

اجمع ما سبق: لا `namespace`، ووحدة الإخفاء ملفّ، والاسم الذي ليس `static` يُرى في
البرنامج كلّه.

فماذا يحدث حين تعرّف مكتبتان دالّةً اسمها `init`؟ **لا شيء وقت الترجمة** — يقع
الاصطدام عند الربط، وهو مكانٌ رسائله أغمض ما في السلسلة.

**والحلّ الوحيد المتاح: بادئةٌ في الاسم.** ولذلك ترى `pthread_create` و`SDL_Init`
و`json_parse` — لا لأن أحداً أحبّ الطول، بل لأن البديهية الخامسة لم تترك بديلاً.

وستكتب مثلها في الإقليم ٢٤، وتعرف عندها لماذا.

---

## قبل أن تكمل

> **١.** في الإقليم ٠١، `table` و`items` خارج الدوالّ. اجعلهما `static` — هل
> يتغيّر شيء في السلوك؟ ولماذا كتبتُهما بلا `static` أصلاً؟
>
> **٢.** اكتب دالّةً تُرجع نصّاً ثابتاً بـ`static char buf[64]` داخلها. ثم
> نادِها مرّتين واحفظ العنوانين وقارنهما. ما المشكلة التي اكتشفتَها؟
>
> **٣.** `static int n = 0;` داخل دالّة — أين يسكن `n` بالضبط؟ اطبع عنوانه، ثم
> قارنه بجدول المناطق أعلاه.
