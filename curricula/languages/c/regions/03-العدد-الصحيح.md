# الإقليم ٠٣ — العدد الصحيح

> في الإقليم السابق رأيتَ `int` أربعةَ بايتات. هنا تعرف ما الذي في تلك الـbits
> بالضبط: أين الإشارة، ولماذا يلتفّ العدد، ولماذا `-INT_MIN` سلوكٌ غير معرَّف.
>
> وفيه المنطقة الرمادية الكبرى في هذه اللغة: **الحجم**. ستخرج منها بقاعدةٍ
> تحميك، لا بجدولٍ تحفظه.

---

## لا إشارة في الـbits

اطبع bits ستّ قيمٍ من نوعٍ واحد:

<!-- part: 03-bits -->

```c
void bits(const char *label, int v)
{
	unsigned int u = (unsigned int)v;

	printf("%-8s", label);
	for (int i = 31; i >= 0; i--) {
		printf("%d", (u >> i) & 1);
		if (i % 8 == 0)
			printf(" ");
	}
	printf("= %d\n", v);
}
```

<!-- out @impl -->

```
0       00000000 00000000 00000000 00000000 = 0
1       00000000 00000000 00000000 00000001 = 1
-1      11111111 11111111 11111111 11111111 = -1
-2      11111111 11111111 11111111 11111110 = -2
INT_MAX 01111111 11111111 11111111 11111111 = 2147483647
INT_MIN 10000000 00000000 00000000 00000000 = -2147483648
```

**سالب واحدٍ كلّه واحدات.** ليس فيه bit اسمها «الإشارة» تُرفَع كالراية؛ الشكل
كلّه مختلف.

والقاعدة التي تفسّر الجدول: **الـbit العليا وزنها سالب.** في `int` وزنها
`−2³¹`، وبقيّة الـbits موجبةٌ كالمعتاد. فـ`-1` هي `−2³¹ + (2³¹ − 1)`، و`INT_MIN`
هي الـbit العليا وحدها.

اسم هذا الاتّفاق **two’s complement**. واللقطة التالية تقول لماذا فاز.

---

## سببه: جامعٌ واحد

المعالج لا يعرف إن كنتَ تقصد `signed` أو `unsigned`. يجمع الـbits ويرمي ما فاض.
**والـtwo’s complement يجعل هذا كافياً للاثنين.**

```c
#include <stdio.h>

int main(void)
{
	unsigned int a = 0xFFFFFFFFu;
	unsigned int b = 1;

	printf("%u + %u = %u\n", a, b, a + b);
	printf("%d + %d = %d\n", (int)a, (int)b, (int)(a + b));
	return 0;
}
```

<!-- out -->

```
4294967295 + 1 = 0
-1 + 1 = 0
```

**نفس الـbits، ونفس عملية الجمع، وسطران صحيحان.** القراءة الأولى تقول إن العدد
التفّ، والثانية تقول إن `-1 + 1 = 0`. لا يحتاج العتاد دائرتين.

هذا هو المكسب الذي اشترى الاتّفاق مكانه. **وC23 ألزمته أخيراً** — وقبلها كانت
المواصفة تسمح بتمثيلين آخرين، ولذلك ترى في كودٍ قديم احتياطاتٍ لا معنى لها اليوم.

---

## المدى ليس متماثلاً

عُدّ الاحتمالات: ٣٢ bit تعطي `2³²` شكلاً. واحدٌ منها للصفر، فيبقى عددٌ فرديّ
يُقسَم بين الموجب والسالب — **والقسمة لا تستوي**.

```c
#include <stdio.h>
#include <limits.h>

int main(void)
{
	printf("%-10s %d\n", "INT_MAX", INT_MAX);
	printf("%-10s %d\n", "INT_MIN", INT_MIN);
	printf("%-10s %u\n", "UINT_MAX", UINT_MAX);
	printf("%-10s %d\n", "SHRT_MAX", SHRT_MAX);
	printf("%-10s %lld\n", "LLONG_MAX", LLONG_MAX);
	return 0;
}
```

<!-- out @impl -->

```
INT_MAX    2147483647
INT_MIN    -2147483648
UINT_MAX   4294967295
SHRT_MAX   32767
LLONG_MAX  9223372036854775807
```

**لأصغر عددٍ سالب لا يوجد نظيرٌ موجب.** ونتيجتها المباشرة أن نفي `INT_MIN` ليس له
جواب:

```c
//! cc: -fsanitize=undefined
//! pty
#include <stdio.h>
#include <limits.h>

int main(void)
{
	int x = INT_MIN;

	printf("%d\n", -x);
	return 0;
}
```

<!-- out @ub -->

```
main.c:8:17: runtime error: negation of -2147483648 cannot be represented in type 'int'; cast to an unsigned type to negate this value to itself
SUMMARY: UndefinedBehaviorSanitizer: undefined-behavior main.c:8:17 in 
-2147483648
```

`-x` أعطت `x`. وهي ليست حيلةً طريفة: **سلوكٌ غير معرَّف** بنصّ المواصفة، والمترجم
حرٌّ في أن يفعل شيئاً آخر تماماً غداً (البديهية ٤). ودالّةُ قيمةٍ مطلقة تُكتب بلا
فحصٍ لهذه الحالة **خاطئةٌ لقيمةٍ واحدة** — وهذا نصف بلاغات الأمان في العالم.

---

## الالتفاف: معرَّفٌ هنا، غير معرَّف هناك

نفس العتاد، ونفس الـbits، وحُكمان مختلفان:

| | عند تجاوز الحدّ | لماذا |
|---|---|---|
| `unsigned` | **يلتفّ**، والمواصفة تضمنه: الحساب بالباقي على `2ⁿ` | لا معنى لـ«تجاوز» في دائرةٍ مغلقة |
| `signed` | **سلوكٌ غير معرَّف** | آلاتٌ قديمة كانت تُقاطِع، فلم تُلزَم المواصفة أحداً |

**والفرق ليس تاريخياً فقط.** لأن تجاوز `signed` غير معرَّف، يجوز للمترجم أن يفترض
أنه لا يقع — وقد رأيتَ في الفصل صفر كيف قلب ذلك جواب `x + 1 > x` عند `-O2`.

**فالقاعدة:** إن أردتَ التفافاً فاطلبه صراحةً بنوعٍ `unsigned`. وإن كنتَ تحسب
بأعدادٍ ذات إشارة فافحص الحدّ **قبل** العملية، لا بعدها — لأن ما بعدها لم يقع في
نظر المترجم.

---

## الرمادية الكبرى: الحجم

المواصفة **لا تقول إن `int` أربعة بايتات**. تقول شيئين:

**أولاً، حدوداً دنيا للمدى** (§5.2.4.2.1): `char` ≥ ٨ bits، و`short` و`int`
يسعان ±32767 على الأقلّ، و`long` ±2147483647، و`long long` ±9223372036854775807.

**وثانياً، ترتيباً لا ينكسر:**

```
sizeof(char) == 1 ≤ sizeof(short) ≤ sizeof(int) ≤ sizeof(long) ≤ sizeof(long long)
```

وما تراه عملياً اتّفاقان:

| | `int` | `long` | pointer |
|---|---|---|---|
| **LP64** — يونكس ٦٤-بت | ٤ | **٨** | ٨ |
| **LLP64** — ويندوز ٦٤-بت | ٤ | **٤** | ٨ |

فـ`long` هو النوع الذي لا تستطيع الاعتماد على حجمه، وكودٌ يفترض أنه ثمانية
بايتات **يُترجَم على الاثنين ويعمل على واحد**.

---

## القاعدة التي تحميك

لا تحفظ الجدول. اسأل سؤالاً واحداً: **هل الحجم جزءٌ من معنى هذه القيمة؟**

```c
#include <stdio.h>
#include <stdint.h>
#include <stddef.h>

int main(void)
{
	int32_t  id    = 7;          /* الحجم جزءٌ من المعنى */
	int      count = 3;          /* عددٌ صغير، لا يعنيني حجمه */
	size_t   len   = sizeof id;  /* حجمٌ أو طول */

	printf("%zu %zu %zu\n", sizeof id, sizeof count, sizeof len);
	printf("%d %d %zu\n", id, count, len);
	return 0;
}
```

<!-- out @impl -->

```
4 4 8
7 3 4
```

- **يعنيني الحجم** — بايتاتٌ تُكتب في ملفّ أو تُرسَل، أو أقنعةُ bits:
  `int32_t` و`uint8_t` وأخواتهما من `<stdint.h>`.
- **لا يعنيني** — عدّادٌ أو فهرس: `int`.
- **حجمٌ أو طول** — `size_t`، وهو النوع الذي تُرجعه `sizeof` وتأخذه `malloc`.

---

## `size_t` لا ينزل تحت الصفر

وهذه مصيدةُ `size_t` التي تدفع ثمنها الحلقات:

```c
#include <stdio.h>
#include <stddef.h>

int main(void)
{
	size_t n = 3;

	printf("%d\n", n - 5 > 0);
	return 0;
}
```

<!-- out -->

```
1
```

**ثلاثةٌ ناقص خمسةٍ أكبر من الصفر.** لأن `size_t` بلا إشارة: النتيجة التفّت إلى
عددٍ هائل، والمقارنة صحيحة تماماً في نظر اللغة.

والصيغة التي تقتل فعلاً:

```c
for (size_t i = n - 1; i >= 0; i--)
```

`i >= 0` صحيحةٌ **دائماً** لنوعٍ بلا إشارة، فالحلقة لا تنتهي — وعند `i == 0`
تلتفّ إلى `SIZE_MAX` وتقرأ ما ليس لك. الإقليمان ١٢ و٢٦ يعودان إليها.

---

## نوع الرقم الذي تكتبه

الرقم في نصّك ليس بلا نوع. له نوعٌ يختاره المترجم بقاعدة، وهي مصدر مفاجأة:

```c
#include <stdio.h>

int main(void)
{
	printf("%zu %zu %zu %zu\n",
	       sizeof(1), sizeof(1u), sizeof(1L), sizeof(1LL));
	printf("%d\n", 0x7FFFFFFF < 0);
	printf("%d\n", 0x80000000 < 0);
	return 0;
}
```

<!-- out @impl -->

```
4 4 8 8
0
0
```

السطر الأول متوقّع: اللاحقة تختار النوع — `u` و`L` و`LL`.

**والسطران بعده هما المفاجأة.** الرقمان متجاوران، وكلاهما ليس سالباً. لأن
`0x80000000` **لا يسع في `int`**، فتنقل القاعدة الـliteral إلى `unsigned int` —
والقيم بلا إشارة لا تكون سالبة أبداً.

فالـliteral العشريّ يبقى ذا إشارة ويكبر إلى `long`، **والـliteral السِّتّ عشريّ يقفز إلى
`unsigned`**. اكتب اللاحقة حين يهمّك الفرق.

## القسمة على السالب

آخر منطقةٍ في هذا الإقليم كانت رماديةً ثم حُسمت:

```c
#include <stdio.h>

int main(void)
{
	printf("%d %d\n",  7 / 2,   7 % 2);
	printf("%d %d\n", -7 / 2,  -7 % 2);
	printf("%d %d\n",  7 / -2,  7 % -2);
	return 0;
}
```

<!-- out -->

```
3 1
-3 -1
-3 1
```

**القسمة تقترب من الصفر**، لا من السالب. و`-7 / 2` تعطي `-3` لا `-4`.

ويتبع ذلك أن **إشارة الباقي هي إشارة المقسوم**: `-7 % 2` تعطي `-1`.

وقبل C99 كان الاتّجاه **معرَّفاً بالتنفيذ**: مترجمٌ يقرّب نحو الصفر وآخر نحو
السالب، والبرنامج يعطي جوابين. C99 حسمها نحو الصفر.

**وأثرها اليوم:** `i % n` لا تصلح فهرساً دائرياً إن كان `i` سالباً — تعطيك فهرساً
سالباً وتقرأ خارج الـarray.

---

## قبل أن تكمل

> **١.** ما bits `-2147483648` بالضبط؟ رأيتَها في اللوحة الأولى. والآن: لماذا
> يرفض المترجم `int x = -2147483648;` بتحذير، ويقبل `int x = INT_MIN;`؟
>
> **٢.** اكتب دالّةً تقول هل الجمع `a + b` سيتجاوز `INT_MAX`، **بلا أن تجمعهما**.
> ولماذا لا يصلح أن تجمع ثم تفحص؟
>
> **٣.** في الإقليم ٠١ كتبتَ `int items = 0;` وعدّاداً يزيد بلا فحص. ما أكبر عددٍ
> يبلغه قبل أن يصير سلوكه غير معرَّف؟ وهل هذا هو الخطر الحقيقيّ في ذلك السطر؟
