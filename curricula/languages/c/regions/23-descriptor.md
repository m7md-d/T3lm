# الإقليم ٢٣ — الـdescriptor

> قلتُ في الإقليم ٢١ إن داخل `FILE` رقماً يعرفه النظام. هذا الإقليم عن ذلك
> الرقم.
>
> وهو الموضع الذي تغادر فيه اللغة: **`open` و`read` و`write` ليست من C**. لا
> تجدها في المواصفة، ولا في `<stdio.h>` — هي واجهة النظام، ومعيارها POSIX.
>
> والحدّ يُعلَن، لا يُخفى. ومن هنا إلى الإقليم ٢٥ نحن خارج اللغة.

---

## الرقم تحت `FILE`

```c
#include <stdio.h>
#include <unistd.h>

int main(void)
{
	printf("stdin  = %d\n", fileno(stdin));
	printf("stdout = %d\n", fileno(stdout));
	printf("stderr = %d\n", fileno(stderr));

	FILE *f = fopen("t.txt", "w");

	printf("t.txt  = %d\n", fileno(f));
	fclose(f);
	return 0;
}
```

<!-- out @posix -->

```
stdin  = 0
stdout = 1
stderr = 2
t.txt  = 3
```

**ثلاثة أرقامٍ مفتوحةٌ قبل أن يعمل برنامجك:** صفرٌ للدخل، وواحدٌ للخرج، واثنان
للأخطاء. وأوّل ملفٍّ تفتحه يأخذ ثلاثة — **أصغر رقمٍ متاح**، وهذه قاعدة مضمونة في
POSIX ستستعملها في الإقليم ٢٨.

**والرقم فهرس.** لكل عمليةٍ جدولٌ يملكه النظام، والرقم موضعٌ فيه. فما تحمله أنت
عددٌ صغير، وما يحمله النظام كلُّ شيءٍ آخر: أي ملفّ، وأين الموضع، وبأي إذنٍ فُتح.

**ولذلك لا معنى للـdescriptor خارج عمليته.** ورقم ٣ عندك ليس رقم ٣ عند غيرك.

---

## الطبقة التي تحت

```c
//! pty
#include <fcntl.h>
#include <unistd.h>
#include <stdio.h>
#include <string.h>

int main(void)
{
	int fd = open("t.txt", O_WRONLY | O_CREAT | O_TRUNC, 0644);

	if (fd < 0)
		return 1;

	const char *s = "hello\n";
	ssize_t     w = write(fd, s, strlen(s));

	close(fd);

	fd = open("t.txt", O_RDONLY);
	char    buf[16];
	ssize_t r = read(fd, buf, sizeof buf);

	close(fd);

	printf("كتب=%zd قرأ=%zd\n", w, r);
	printf("[%.*s]\n", (int)r, buf);
	return 0;
}
```

<!-- out @posix -->

```
كتب=6 قرأ=6
[hello
]
```

قارِن بالطبقة التي فوقها:

| `<stdio.h>` — من C | `<unistd.h>` — من POSIX |
|---|---|
| `FILE *` مُعتِم | `int` مكشوف |
| `fopen("r")` | `open(O_RDONLY)` |
| `fgetc` · `fgets` · `fread` | `read(fd, buf, n)` |
| `fprintf` · `fputs` · `fwrite` | `write(fd, buf, n)` |
| **يُخزِّن مؤقّتاً** | **لا يُخزِّن شيئاً** |
| منقولٌ إلى كل منصّة | يونكس وما يشبهه |

**و`0644` أذونات الملفّ عند إنشائه** — ثمانيّة: القراءة والكتابة لمالكه، والقراءة
لغيره. ولا معنى لها إلا مع `O_CREAT`.

**و`%.*s` صيغةٌ تأخذ الطول وسيطاً** — لأن `buf` ليس نصّاً: `read` لا تضع صفراً
ختامياً. **هي تنقل بايتات، لا نصوصاً.**

---

## `read` قد تعطيك أقلّ ممّا طلبت

وهذا أهمّ ما في الإقليم، وأكثر ما يُغفَل.

`read(fd, buf, 4096)` **لا تعني «اقرأ ٤٠٩٦»**. تعني «اقرأ حتى ٤٠٩٦»، وقيمتها
المرجَعة كم قرأت فعلاً:

| القيمة | ماذا تعني |
|---|---|
| `n > 0` | قرأ `n` بايتاً — **وقد تكون أقلّ ممّا طلبت** |
| `0` | نهاية الملفّ |
| `-1` | خطأ، والسبب في `errno` |

**ومتى تعطي أقلّ؟** حين تقرأ من terminal ينتهي عند السطر، أو من pipe لم يصل إليه
كل شيءٍ بعد، أو من شبكةٍ وصلت حزمةٌ منها. **ومع الملفّات العادية يندر** — ولهذا
يمرّ الخطأ في الاختبار ويقع في الإنتاج.

**والصواب حلقة:**

```c
size_t got = 0;
while (got < want) {
	ssize_t n = read(fd, buf + got, want - got);
	if (n < 0) { if (errno == EINTR) continue; break; }
	if (n == 0) break;                  /* انتهى */
	got += (size_t)n;
}
```

**و`write` مثلها تماماً** — قد تكتب أقلّ، فتُلَفّ في حلقةٍ كهذه.

**و`EINTR` حالةٌ خاصّة:** إشارةٌ قاطعت النداء قبل أن يفعل شيئاً. ليست خطأً، بل
«أعِد المحاولة».

---

## كل شيءٍ descriptor

الرقم لا يقول ما وراءه. ملفّ، أو pipe، أو terminal، أو اتّصال شبكة — **نفس
`read` ونفس `write`**.

وهذه هي فكرة يونكس التي بُنيت عليها C أصلاً: **واجهةٌ واحدة للنقل**، والاختلاف
في من فتحه.

وتستطيع أن تسأل عن نوعه:

```c
//! pty
#include <unistd.h>
#include <stdio.h>

int main(void)
{
	printf("stdin  tty؟ %d\n", isatty(0));
	printf("stdout tty؟ %d\n", isatty(1));
	return 0;
}
```

<!-- out @machine: مشغَّلاً في terminal -->

```
stdin  tty؟ 1
stdout tty؟ 1
```

**والآن البرنامج نفسه، ومخرَجه موجَّه إلى ملفّ:**

```c
#include <unistd.h>
#include <stdio.h>

int main(void)
{
	printf("stdin  tty؟ %d\n", isatty(0));
	printf("stdout tty؟ %d\n", isatty(1));
	return 0;
}
```

<!-- out @machine: و`./main > out.txt` -->

```
stdin  tty؟ 0
stdout tty؟ 0
```

**نفس الكود، وجوابان — والذي تغيّر خارج البرنامج.**

وهذا ما تفعله الأدوات الجيّدة: `ls` تعرض أعمدةً على الشاشة وسطراً واحداً في
الأنبوب، و`grep` يلوّن على الشاشة ولا يلوّن في ملفّ. **الأداة تسأل عن وجهتها**.

**وهو أيضاً نصف جواب سؤال `fflush`** — لأن المكتبة تسأل السؤال نفسه، وتقرّر متى
تكتب بحسبه. والإقليم القادم يغلقه.

---

## `dup2`: أن تبدّل الوجهة

الرقم فهرس، ونسخُ فهرسٍ فوق آخر ممكن. وهذا هو **التوجيه** كلّه:

```c
#include <fcntl.h>
#include <unistd.h>
#include <stdio.h>

int main(void)
{
	int saved = dup(1);
	int fd    = open("out.txt", O_WRONLY | O_CREAT | O_TRUNC, 0644);

	dup2(fd, 1);
	close(fd);
	printf("هذا يذهب إلى الملفّ\n");
	fflush(stdout);

	dup2(saved, 1);
	close(saved);
	printf("وهذا إلى الشاشة\n");

	FILE *f = fopen("out.txt", "r");
	char  line[128];

	fgets(line, sizeof line, f);
	fclose(f);
	printf("في الملفّ: %s", line);
	return 0;
}
```

<!-- out @posix -->

```
وهذا إلى الشاشة
في الملفّ: هذا يذهب إلى الملفّ
```

**`printf` لم تتغيّر.** ما زالت تكتب إلى `stdout`، و`stdout` ما زال يحمل الرقم ١.
**والذي تغيّر ما وراء الرقم ١.**

| | |
|---|---|
| `dup(fd)` | نسخةٌ في **أصغر رقمٍ متاح** |
| `dup2(fd, n)` | نسخةٌ في الرقم `n` بالضبط — **ويُغلَق ما كان فيه** |

**و`fflush(stdout)` قبل استرجاع الوجهة ليست زينة:** بدونها تبقى البايتات في
الـbuffer، فتُكتَب بعد أن تكون قد أعدتَ الرقم ١ إلى الشاشة — فتظهر في المكان
الخطأ.

**وهذه هي `>` في الـshell حرفياً.** حين تكتب `ls > out.txt`، تفتح الـshell الملفّ
وتنادي `dup2(fd, 1)` **ثم** تشغّل `ls` — و`ls` لا تعرف شيئاً. الإقليم ٢٥ يركّب
النصف الثاني.

---

## ولماذا لا تكتب بـ`write` دائماً

`write` مباشرة، بلا طبقة، بلا `buffer`. فلماذا `printf` أصلاً؟

**لأن كل نداء `write` عبورُ حدّ.** ينتقل التنفيذ من برنامجك إلى النظام ويعود —
وثمنُه أضعافُ نداء دالّةٍ عادية.

فبرنامجٌ يكتب حرفاً حرفاً بـ`write` يعبر الحدّ مرّةً لكل حرف. وبرنامجٌ يكتب
بـ`printf` يجمعها في الذاكرة ويعبر مرّةً لكل بضعة آلاف.

**وهذه هي وظيفة `<stdio.h>` كلّها في جملة:** أن تجعل عبور الحدّ نادراً. وثمن ذلك
أن ما كتبتَه **ليس مكتوباً بعد** — وهذا هو الإقليم القادم.

---

## قبل أن تكمل

> **١.** اكتب `cat` بـ`read` و`write` وحدهما، بلا `<stdio.h>`. ثم جرّبه على ملفٍّ
> كبير بأحجام buffer مختلفة: ١ و١٦ و٤٠٩٦. قِس الزمن بـ`time`.
>
> **٢.** أضِف إلى الإقليم ٠١ أن يطبع المحثّ **فقط** إن كان `isatty(0)`. ثم
> `./cmd < commands.txt` — ما الفرق في المخرَج؟
>
> **٣.** `close(1)` ثم `printf("x\n")` — ماذا يحدث؟ وهل تُرجع `printf` خطأً؟ ثم
> افحص `ferror(stdout)`.
