# الإقليم ١٥ — الـrecursion

> رأيتَ في الإقليم ٠٩ أن كل نداءٍ يأخذ frame جديداً، وأن الـframes تُكدَّس.
>
> ولم يقل أحد إن النداء يجب أن يكون لدالّةٍ **أخرى**. ودالّةٌ تنادي نفسها تأخذ
> frame جديداً كأي نداء — فتصير عندك نسخٌ كثيرة من نفس الدالّة، لكلٍّ متغيّراتها.
>
> وفي آخره تكتب مطابقة الأنماط: `*.c` — وهي القطعة التي سيحتاجها مشروع التخرّج.

---

## نسخٌ من الدالّة نفسها

```c
#include <stdio.h>
#include <stdint.h>

void down(int n, uintptr_t prev)
{
	int       here;
	uintptr_t now = (uintptr_t)&here;

	if (prev != 0)
		printf("عمق %d: الـframe %lu بايتاً\n", n, (unsigned long)(prev - now));
	if (n == 3)
		return;
	down(n + 1, now);
}

int main(void)
{
	down(1, 0);
	return 0;
}
```

<!-- out @machine -->

```
عمق 2: الـframe 64 بايتاً
عمق 3: الـframe 64 بايتاً
```

**كل نداءٍ كلّف ٦٤ بايتاً.** فيها `here` و`now` و`n` و`prev` وعنوان العودة، وpadding
للـalignment.

والرقم هنا **قياس**: طرحتُ عنوانين حوّلتهما إلى `uintptr_t`. وهذا حسابٌ **معرَّفٌ
بالتنفيذ** لا سلوكاً موعوداً — يصلح أداةَ قياسٍ ولا يصلح أساس برنامج.

**والمكسب أن للعمق ثمناً معلوماً.** وstack هذه المنصّة نحو ٨ ميجابايت، فـ٦٤ بايتاً
لكل frame تعطي مئةً وثلاثين ألف نداءٍ تقريباً قبل أن ينفد.

---

## ولا بدّ من قاعٍ يوقفها

```c
#include <stdio.h>

long n = 0;

void down(void)
{
	n++;
	down();
}

int main(void)
{
	down();
	printf("%ld\n", n);
	return 0;
}
```

<!-- warn @impl -->

```
warning: all paths through this function will call itself
```

**البرنامج لا يطبع شيئاً؛ يموت.** حين ينفد الـstack يصطدم النداء بحدٍّ يفرضه
النظام، فيُنهي الـprocess.

**والـrecursion جزآن، وسقوط أحدهما يسقطه:**

| | |
|---|---|
| **حالة القاع** | مدخلٌ تُجيب عنه بلا نداء |
| **التقدّم نحوه** | كل نداءٍ يقرّب المدخل من القاع |

والثاني هو الذي يُنسى: دالّةٌ لها قاعٌ سليم ولا تتقدّم نحوه **لا تصل إليه**.
`down(n)` تنادي `down(n)` بدل `down(n - 1)` تحقّق الشرط الأول وتموت.

---

## والمترجم قد يحذف الـframe

هذه اللقطة تكسر ما بنيتُه للتوّ. برنامجٌ واحد، وأمرا ترجمةٍ يختلفان في flag واحد:

```c
#include <stdio.h>

long sum(long n, long acc)
{
	if (n == 0)
		return acc;
	return sum(n - 1, acc + n);
}

int main(void)
{
	printf("سأجمع مليون عدد\n");
	fflush(stdout);
	printf("%ld\n", sum(1000000, 0));
	return 0;
}
```

<!-- out @machine: بلا تحسين -->

```
سأجمع مليون عدد
```

**مات عند الجمع.** مليون frame لا يسعها الـstack.

والآن نفس النصّ حرفاً بحرف، مع `-O2`:

```c
//! cc: -O2
#include <stdio.h>

long sum(long n, long acc)
{
	if (n == 0)
		return acc;
	return sum(n - 1, acc + n);
}

int main(void)
{
	printf("سأجمع مليون عدد\n");
	fflush(stdout);
	printf("%ld\n", sum(1000000, 0));
	return 0;
}
```

<!-- out @impl: مع ‎-O2 -->

```
سأجمع مليون عدد
500000500000
```

**السبب أن النداء الأخير هو آخر ما تفعله الدالّة.** لا حساب بعده، ولا شيء يحتاج
frame الدالّة بعد أن ينطلق النداء — فبدل أن يُكدَّس frame جديد، **يُعاد استعمال frame الدالّة**.
ويصير الـrecursion حلقةً في لغة الآلة.

**وهذا تحسينٌ لا وعد.** المواصفة لا تذكره، والمترجم يفعله حين يستطيع ويتركه حين
لا يستطيع. فمن يبني برنامجه على أنه سيقع يبني على `-O2` — ويكسره أوّل بناءٍ
للتنقيح.

**والقاعدة:** إن كان العمق مرهوناً بحجم الدخل — عدد أسطر ملفّ، طول قائمة — فحوّلها
إلى حلقة بيدك. وإن كان مرهوناً ببنيةٍ عمقها لوغاريتميّ — شجرة، تقسيمٌ نصفيّ —
فالـrecursion آمنٌ ومقروء.

## أين يفوز فعلاً

الأمثلة المعتادة — المضروب، فيبوناتشي — تُحلّ بحلقةٍ أوضح وأرخص. **والاستدعاء
الذاتيّ يفوز حين تكون المشكلة نفسها معرَّفةً بنفسها.**

ومطابقة الأنماط منها. القاعدة كلّها أربعة أسطر:

<!-- part: 15-match -->

```c
int match(const char *p, const char *s)
{
	if (*p == '\0')
		return *s == '\0';
	if (*p == '*')
		return match(p + 1, s) || (*s != '\0' && match(p, s + 1));
	if (*s != '\0' && (*p == '?' || *p == *s))
		return match(p + 1, s + 1);
	return 0;
}
```

<!-- out -->

```
*.c      main.c   1
*.c      main.h   0
m?in.c   main.c   1
*                 1
a*b*c    axxbyyc  1
```

اقرأ الأسطر الأربعة بوصفها **تعريفاً** لا خوارزمية:

| السطر | ماذا يقول |
|---|---|
| `*p == '\0'` | نمطٌ فرغ يطابق نصّاً فرغ. **هذا القاع** |
| `*p == '*'` | إمّا أن النجمة أخذت صفر حروف، **أو** أخذت حرفاً وبقيت |
| `'?'` أو تطابق | استهلك حرفاً من كلٍّ وتابع |
| وإلا | لا تطابق |

**والسطر الثاني هو المفتاح.** «أو» فيه ليست شرطاً؛ هي **فرعان يُجرَّبان**. والـshort-circuit
الذي رأيتَه في الإقليم ٠٧ هو ما يوقف البحث عند أوّل نجاح.

**وكتابة هذا بحلقةٍ ممكنة، وتحتاج أن تحفظ بيدك أين كانت كل نجمة لتعود إليها** —
أي أن تبني stack. والـrecursion يعطيك ذلك الـstack مجّاناً، وهذا هو مكسبه
الحقيقيّ.

## والنداء المتبادل يحتاج إعلاناً

دالّتان تنادي كلٌّ منهما الأخرى: أيّهما تُكتب أوّلاً؟

```c
#include <stdio.h>

int is_odd(int n);

int is_even(int n)
{
	return n == 0 ? 1 : is_odd(n - 1);
}

int is_odd(int n)
{
	return n == 0 ? 0 : is_even(n - 1);
}

int main(void)
{
	printf("%d %d\n", is_even(10), is_odd(10));
	return 0;
}
```

<!-- out -->

```
1 0
```

**لا ترتيب يحلّها**، فالإعلان هو الحلّ: سطرٌ يقول النوع قبل الاستعمال، والتعريف
حيث شئت. وهذا بالضبط ما تفعله ملفّ الـheader حين تتفرّق الدوالّ على ملفّات — الإقليم
١٨.

---

## قبل أن تكمل

> **١.** `match("**", "abc")` — كم نداءً تقع؟ عُدّها بيدك أوّلاً، ثم أضِف عدّاداً
> ساكناً واطبعه. ثم جرّب `match("****************", "aaaaaaaaaaaaaaaaaaaa")`
> وانظر ماذا يحدث للزمن.
>
> **٢.** أضِف `match` إلى الإقليم ٠١: أمرٌ اسمه `find` يعرض كل مفتاحٍ يطابق نمطاً.
> `find n*` تعرض `name`.
>
> **٣.** اكتب `sum` من لقطة `-O2` بحلقة. ثم ترجم الاثنتين بـ`-O2 -S` وقارن لغة
> الآلة. هل تختلفان؟
