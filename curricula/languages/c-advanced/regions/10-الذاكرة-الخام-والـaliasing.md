# الفصل ١٠ — الذاكرة الخام والـaliasing

العقد في الفصل السابق يقول كم بايتاً تأخذ وبأي محاذاة. ولا يقول شيئاً عمّا **تصير**
تلك البايتات حين تكتب فيها.

وهذا سؤالٌ في اللغة لا في الـallocator: **ما الذي يستطيع المترجم أن يفترضه عن
وصولاتك؟** والجواب يقرّر كوداً يُولَّد، وقد يقلب نتيجة برنامجك.

---

## الذاكرة الخام بلا نوعٍ معلَن

متغيّرٌ تعلنه له **نوعٌ معلَن**: `int x;` كائنٌ نوعه `int` من ولادته إلى موته.

أمّا ما تعيده `malloc` فلا نوع معلَن له. وISO C تعطيه **نوعاً فعّالاً**
(`effective type`) يتحدّد بما يُخزَّن فيه: تكتب `int` فيصير نوعه الفعّال `int`
لذلك الوصول، ويبقى كذلك حتى يُكتَب فيه بنوعٍ آخر عبر نسخ بايتات.

**ولهذا نتيجة:** ذاكرةٌ من `malloc` كتبتَ فيها `int` ثم قرأتَها بـ`float *`
مخالفةٌ للعقد — لا لأن البايتات لا تكفي، بل لأن **القراءة بنوعٍ لا يوافق النوع
الفعّال ممنوعة**. وهذه هي قاعدة الـaliasing (ISO C §6.5p6–7).

---

## للقاعدة أسنان

**توقّع قبل أن تقرأ المخرَج:** ما الذي تطبعه هذه الدالّة؟

<!-- runs: 10-alias -->

```c
static int f(int *a, float *b) {
    *a = 1;
    *b = 2.0f;
    return *a;              /* هل يقرأ من الذاكرة، أم يفترض أنّها ١؟ */
}

printf("%d\n", f(&x, (float *)&x));
```

**المخرَج**

<!-- out @ub: البرنامج يخالف قاعدة الـaliasing؛ والمخرَج مسجَّلٌ لا موعود -->

```
-O0 alias.c  →  1073741824
-O2 alias.c  →  1
-O0 copy.c   →  1 1073741824
-O2 copy.c   →  1 1073741824
```

**نفس المصدر، وجوابان.**

عند `-O0` قرأ المترجم `*a` من الذاكرة، فرأى بايتات `2.0f` مقروءةً كعددٍ صحيح:
`1073741824`. وعند `-O2` **افترض أن كتابةً عبر `float *` لا تمسّ كائن `int`**،
فأعاد `1` بلا قراءة.

**ولا تقرأ الرقمين جواباً صحيحاً وجواباً مكسوراً.** البرنامج خالف القاعدة فخرج من
ضمانات ISO C، **والقيمتان أثرٌ لهذا المترجم بإصداره وهدفه ومستوى تحسينه** — لا
إحداهما «الحقيقية». والمقروء من التجربة شيءٌ واحد: مخالفةُ القاعدة تعطي المترجم
حرّيةً تظهر آثارُها.

**والمترجم لم يخطئ.** القاعدة تعطيه هذا الافتراض، والبرنامج هو الذي خالف.

وهذا الصنف من الأخطاء لا يظهر في التنقيح. تبني بـ`-O0` فيعمل، وتبني للإصدار
بـ`-O2` فينكسر.

---

## الطريق المشروع

السطران الأخيران في المخرَج من برنامجٍ آخر يفعل الشيء المقصود نفسه — قراءةَ بايتات
`float` كعددٍ صحيح — بـ`memcpy`:

```c
float b = 2.0f;
int   bits;
memcpy(&bits, &b, sizeof bits);
```

الجواب واحدٌ عند `-O0` و`-O2`. لأن `memcpy` **نسخُ بايتات**، وهو الوسيلة التي
تعرّفها المواصفة لإعادة تفسير التمثيل — والنوع الفعّال ينتقل مع البايتات.

**ولا تخف من الكلفة:** المترجم يعرف `memcpy` ويحوّل النسخة الصغيرة ثابتة الحجم إلى
تعليمة نقلٍ واحدة. **فالسليم هنا ليس أبطأ**، وهذا مقيسٌ في التمرين.

واتّحادٌ (`union`) طريقٌ ثانٍ، والقراءة من عضوٍ غير الذي كُتب فيه معرَّفةٌ في
C بخلاف C++ — وهو تمييزٌ يستحقّ أن تعرفه إن نقلتَ كوداً بينهما.

---

## `restrict`: عقدٌ تعطيه أنت

القاعدة السابقة تحمي المترجم من **أنواعٍ مختلفة. وماذا عن مؤشّرين من النوع
نفسه**؟

```c
void add2(int *a, int *b)                    { *a += *b; *a += *b; }
void add2r(int *restrict a, int *restrict b) { *a += *b; *a += *b; }
```

في الأولى، `a` قد يساوي `b`. فبعد `*a += *b` تكون `*b` قد تغيّرت، **والمترجم
مُلزَمٌ بإعادة قراءتها**.

<!-- runs: 10-restrict -->

```c
void add2(int *a, int *b)                    { *a += *b; *a += *b; }
void add2r(int *restrict a, int *restrict b) { *a += *b; *a += *b; }
/* ثم: objdump -d --disassemble=add2 r.o | grep -c ldr */
```

**المخرَج**

<!-- out @machine: aarch64، gcc 14.2 بـ‎-O2 -->

```
add2    →  3 تعليمةَ تحميل
add2r   →  2 تعليمةَ تحميل
0000000000000000 <add2>:
0:	b9400023 	ldr	w3, [x1]
4:	b9400002 	ldr	w2, [x0]
8:	0b030042 	add	w2, w2, w3
c:	b9000002 	str	w2, [x0]
10:	b9400021 	ldr	w1, [x1]
14:	0b020021 	add	w1, w1, w2
18:	b9000001 	str	w1, [x0]
```

السطر عند `10:` هو القراءة الثانية لـ`*b`. و`restrict` أزالها **في هذه الترجمة**.

**والمقروء أنّ العقد سمح للـoptimizer بافتراضٍ أقوى**، فاستعمله هنا. وليس وعداً
بأن `restrict` يزيل تحميلاً في كل موضع، ولا بأنه يجعل البرنامج أسرع: قد لا يغيّر
شيئاً، وقد يكون التحميلُ المحذوف خارج المسار الحارّ أصلاً. **والفرق يُقاس** بالطريقة
التي بناها الفصل `12`.

و`restrict` وعدٌ منك، لا فحصٌ من المترجم. تقول: ما دام هذا المؤشّر في هذا
النطاق، لن يُوصَل إلى الكائن إلا عبره. فإن كذبتَ فالسلوك غير معرَّف، ولا تحذير
ولا كاشفٌ يمسكك في الحالة العامّة.

ولهذا موضعُه واجهاتٌ عقدُها واضح — `memcpy` نفسها معلَنة بـ`restrict` على
معاملَيها — لا رشُّه على كل دالّة.

---

## التمرين

اكتب دالّتين تحوّلان `float` إلى بتّاته: واحدةً بـ`memcpy` وأخرى بـ`union`.

ترجمهما بـ`-O2` واقرأ الـassembly. كم تعليمةً في كلٍّ؟ ثم أضف ثالثةً بـ
`*(int *)&f` وقارن الثلاث — في المخرَج وفي ما يقوله `-fsanitize=undefined`.

**الفصل التالي:** تعرف الآن العقد الذي يجب أن تفي به، وحدود ما يجوز للمترجم أن
يفترضه. فاكتب الـallocator.
