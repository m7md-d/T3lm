# الفصل ٢٠ — الخيوط والتخزين الخاصّ

العملية في الفصل `00` كانت خريطةً من mappings. والخيط الثاني يدخل تلك الخريطة
نفسها: **لا يُنشِئ فضاء عناوين جديداً**، ويأخذ منها ما يخصّه.

وسؤال هذا الفصل: أيُّ شيءٍ يُرى من الخيطين، وأيُّه يبقى لكلٍّ وحده؟

---

## الفضاء واحد، والمكدّسان اثنان

<!-- part: 20-share -->

```c
pthread_mutex_lock(&mu);
*shared += (int) id + 1;            /* كائنٌ واحد في الكومة، يكتب فيه الاثنان */
pthread_mutex_unlock(&mu);

int local = 0;                      /* وفي مكدّس هذا الخيط وحده */
stack_of[id] = &local;
```

**المخرَج**

<!-- out @impl: glibc 2.41 على لينكس/aarch64 -->

```
one heap object, written by both: 3
distance between the two thread stacks: 8256 KB
errno in thread 0 after both failed: Bad file descriptor
errno in thread 1 after both failed: No such file or directory
default stack size in a fresh pthread_attr_t: 8192 KB
pthread_mutex_trylock returned Device or resource busy, errno is 0
```

السطر الأوّل يحسم الاشتراك: مؤشّرٌ واحد من الكومة، وخيطان كتبا فيه واحداً
واثنين فصار ثلاثة. العنوان نفسه يعني الكائن نفسه في الخيطين — وهذا هو الفرق
البنيويّ بين خيطٍ وعمليةٍ ثانية.

والسطر الثاني يحسم الانفصال: بين مكدّسَي الخيطين ثمانية ميغابايت وزيادة، وهي
الحجم الافتراضيّ في سمات POSIX معروضاً في السطر الخامس. فلكلّ خيطٍ mapping خاصّ
لمكدّسه، وعنوانُ متغيّرٍ محلّيٍّ في أحدهما لا يقع في مدى الآخر.

| ما يشتركان فيه | ما يبقى لكلٍّ |
|---|---|
| الكومة، والكائنات الساكنة، والكود | المكدّس، ومحتوى السجلّات |
| الواصفات المفتوحة، وجدول الإشارات | التخزين الخاصّ بالخيط، و`errno` |
| كل mapping في الخريطة | موضعُ التنفيذ في البرنامج |

---

## `errno` اسمٌ عامّ وقيمةٌ خاصّة

السطران الثالث والرابع أغرب ما في اللوحة. الخيطان فشلا بنداءين مختلفين، ثم
انتظر كلٌّ منهما الآخر عند حاجزٍ، ثم قرأ `errno`. وكلٌّ قرأ **خطأه هو**.

ويبدو في كودك متغيّراً عالمياً يُسنَد إليه ويُقرَأ: `if (errno == EBADF)`. وهو
في التنفيذ ماكرو يتوسّع إلى استدعاءٍ يعطي **موضعاً في التخزين الخاصّ بالخيط**.
والاسم الواحد يصل إلى كائنٍ مختلف في كل خيط.

| الطبقة | ماذا تقول عن `errno` |
|---|---|
| **ISO C §7.5** | قيمةٌ يُسنَد إليها، ولا يشترط أن تكون كائناً |
| **POSIX** | وفي برنامجٍ بخيوط، لكل خيطٍ قيمتُه المستقلّة |
| **glibc** | ماكرو يمرّ بموضعٍ في TLS |

**ولهذا يضرّ حفظُ `errno` في متغيّرٍ عامّ** ليقرأه خيطٌ آخر: تكون قد نقلتَ قيمةً
خاصّةً إلى موضعٍ مشترك.

---

## واصطلاح `pthread` غيرُ اصطلاح النداء

السطر الأخير يحمل فخّاً يقع فيه من جاء من واجهات النظام. `pthread_mutex_trylock`
على قفلٍ مأخوذ **أرجعت** `EBUSY`، و`errno` بقي صفراً.

| العائلة | كيف تُبلّغ عن الخطأ | كيف يُفحَص |
|---|---|---|
| نداءات النظام و`libc` القديمة | ترجع `-1` وتضبط `errno` | `if (rc == -1) perror(...)` |
| أكثر واجهات `pthread` | **ترجع رقم الخطأ نفسه**، ولا تمسّ `errno` | `if ((rc = pthread_...) != 0) ...` |

وكتابةُ فحصٍ من النمط الأوّل على دالّةٍ من الثاني تعطيك برنامجاً يبدو سليماً: قيمة
الإرجاع موجبةٌ فلا تساوي `-1`، فيمرّ الخطأ صامتاً. و`pthread_create` أشهرُ ضحاياه.

## آليّتان للتخزين الخاصّ

للغة آليةٌ، ولPOSIX أخرى. وهما مختلفتان في المصدر والقدرة:

<!-- part: 20-tls -->

```c
static _Thread_local int counter;          /* ISO C منذ C11 */
static pthread_key_t key;                  /* POSIX، ومعها هادمٌ يُنادى */

static void bye(void *p) { atomic_fetch_add(&destroyed, 1); free(p); }
```

**المخرَج**

<!-- out @posix: pthread من glibc 2.41 -->

```
_Thread_local counter — main 1, thread 0 10, thread 1 11
same name, three addresses: yes
pthread key — thread 0 100, thread 1 101
destructor calls after both threads ended: 2
```

الاسم `counter` واحد في المصدر، وله ثلاثة عناوين: واحدٌ لكل خيطٍ حيّ. وهو
الميكانيزم نفسه الذي يقف خلف `errno`.

| | `_Thread_local` | `pthread_key_create` |
|---|---|---|
| السلطة | ISO C (C11) | POSIX |
| متى يُنشأ | عند الترجمة، مع الخيط | في وقت التشغيل، بمفتاحٍ يُطلَب |
| القيمة الابتدائية | ثابتةٌ تُكتَب في الإعلان | `NULL` حتى تُضبَط |
| عند انتهاء الخيط | لا هادمَ في C | **هادمٌ يُنادى** بالقيمة إن لم تكن `NULL` |
| الكلفة عند الوصول | موضعٌ يُحسَب من مؤشّر الخيط | نداءُ دالّةٍ وبحثٌ بالمفتاح |

والسطر الأخير في الجدول هو سبب بقاء الآلية الثانية. مفتاحُ POSIX ينظّف
نفسه: أربعةُ أسطرٍ في اللوحة تقول إنّ الهادم نُودي مرّتين، مرّةً لكل خيطٍ ضبط
قيمة. و`_Thread_local` في C يعطيك الموضع ويترك التنظيف لك.

## التمرين

في `programs/20-tls.c` اجعل الخيطين يخرجان **قبل** أن يضبط أحدهما قيمةً
بـ`pthread_setspecific`، وأعد العدّ.

كم مرّةً نُودي الهادم؟ ثم اضبط القيمة بـ`NULL` صراحةً في خيطٍ واحد وأعد
السؤال. وما الذي يقوله ذلك عن الشرط الذي يُنادى عنده الهادم؟
