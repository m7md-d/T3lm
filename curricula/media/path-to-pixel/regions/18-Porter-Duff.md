# الإقليم ١٨ — Porter-Duff

> اثنا عشر مُركِّباً، **ومعادلةٌ واحدة**. وما يفرّق بينها مُعامِلان لا أكثر:
> كم من المصدر، وكم من الوجهة.

---

## المعادلة

<!-- math -->

```
c = cs·Fs + cb·Fb
```

على القيم المضروبة سلفاً، وعلى القنوات الأربع سواءً — **بما فيها الشفّافية**.
وهذا التوحيد هو ما يجعل الكود سطرين:

<!-- head: comp.h -->

```c
static rgba pd_blend(pdop op, rgba s, rgba b) {
  float fs, fb;
  pd_factors(op, s.a / 255.0f, b.a / 255.0f, &fs, &fb);
```

والمُعامِلان يخرجان من سؤالٍ واحد: **أين يُسمَح لكلٍّ منهما بالبقاء؟** المصدرُ
داخل الوجهة، أو خارجها، أو في الحالين. وثلاثةُ اختياراتٍ لكلٍّ منهما، فأربعةٌ في
ثلاثةٍ تعطي اثنَي عشر.

## الجدول كاملاً

<!-- part: 18-porter-duff -->

```c
for (int i = 0; i < 12; i++) {
  pd_factors((pdop)i, s.a / 255.0f, b.a / 255.0f, &fs, &fb);
  rgba o = pd_blend((pdop)i, s, b);
}
```

قبل أن تنظر: **أيُّ مُركِّبَين يعطيان الشفّافية نفسها؟**

المخرَج:

<!-- out -->

```
المصدر  أحمرُ  a=179  (مضروباً: 179,  0,  0)
الوجهة  أزرقُ a=128  (مضروباً:   0,  0,128)

  المُركِّب      Fs      Fb      الناتج
  clear        0.00    0.00   (  0,   0,   0,   0)
  src          1.00    0.00   (179,   0,   0, 179)
  dst          0.00    1.00   (  0,   0, 128, 128)
  src-over     1.00    0.30   (179,   0,  38, 217)
  dst-over     0.50    1.00   ( 89,   0, 128, 217)
  src-in       0.50    0.00   ( 90,   0,   0,  90)
  dst-in       0.00    0.70   (  0,   0,  90,  90)
  src-out      0.50    0.00   ( 89,   0,   0,  89)
  dst-out      0.00    0.30   (  0,   0,  38,  38)
  src-atop     0.50    0.30   ( 90,   0,  38, 128)
  dst-atop     0.50    0.70   ( 89,   0,  90, 179)
  xor          0.50    0.30   ( 89,   0,  38, 127)

  src-over(s,b) = (179,   0,  38, 217)
  src-over(b,s) = ( 89,   0, 128, 217)
```

اقرأ عمودَي المُعامِلين وحدهما: **الاثنا عشر ليست اثنتي عشرة خوارزمية**، بل
اثنتا عشرة قيمةً لزوجٍ من الأعداد. وهذا هو الاختزال الذي جعل الورقة تُذكَر بعد
أربعين سنة.

ولاحظ `src-atop` و`dst-atop`: شفّافيةُ الناتج تساوي شفّافية إحدى الطبقتين
بالضبط (`128` و`179`) — لأن `atop` تعني «داخلَ حدود الأخرى ولا شيء خارجها».

## أيُّها يُستعمَل فعلاً

**`src-over` وحدها تكفي تسعةً وتسعين بالمئة من الرسم.** وهي الافتراض في كلّ
واجهةٍ رسمتَ بها، وهي التي بُني عليها الإقليمان `16` و`17`.

والباقي يلزم في مواضعَ محدَّدة:

| المُركِّب | يلزم في |
|---|---|
| `src-in` | القصُّ بقناع: أبقِ من المصدر ما يقع داخل الوجهة |
| `dst-out` | حفرُ ثقبٍ في ما رُسم |
| `src-atop` | تلوينُ شكلٍ موجودٍ بلا تجاوز حدوده |
| `clear` | مسحُ منطقة |
| `xor` | نادر، وأكثرُ استعمالاته اليوم تعليمية |

والبقيّة — `dst-over` و`dst-in` و`src-out` و`dst-atop` — **تظهر حين يُعكَس
ترتيبُ الرسم لسببٍ آخر**، فتُوفّر إعادةَ ترتيب.

## والترتيبُ ليس تفصيلاً

السطران الأخيران يعيدان بديهية الفصل صفر: `src-over(s,b)` و`src-over(b,s)`
تعطيان **الشفّافية نفسها `217`** ولونين مختلفين.

فالشفّافيةُ الناتجة **دالّةٌ تبديلية** — `as + ab − as·ab` — واللونُ ليس كذلك.
ولهذا لا يمكن أن تُستنتَج الصورةُ من قناتها الرابعة، ولهذا يبقى ترتيبُ الطبقات
معلومةً يجب حفظُها.

---

## التمرين

املأ الجدول بيدك لمصدرٍ **صلب** (`as = 1`) قبل أن تشغّل. ستجد أربعةَ مُركِّباتٍ
تتطابق نتائجها، وأربعةً تعطي `clear`.

ثم اسأل: كم مُركِّباً **مميَّزاً** يبقى حين تكون كلتا الطبقتين صلبتين؟ الجواب
يفسّر لماذا لا يُذكَر Porter-Duff في الرسم غير الشفّاف أصلاً.

## الخلاصة

- معادلةٌ واحدة `c = cs·Fs + cb·Fb`، على القنوات الأربع سواء.
- الاثنا عشر **زوجُ مُعامِلاتٍ لا اثنتا عشرة خوارزمية**.
- `src-over` تكفي عامّة الرسم، والبقيّةُ لمواضعَ محدَّدة.
- **الشفّافيةُ الناتجة تبديلية واللونُ ليس كذلك**، فالترتيبُ معلومةٌ تُحفَظ.

**البابُ الذي فتحتَه:** صار التركيبُ كلُّه سطراً واحداً وجدولَ مُعامِلات.

**البابُ المغلق:** وماذا لو أردتَ شفّافيةً على **مجموعةٍ** من الأشكال لا على
كلٍّ منها؟ ذلك الإقليم `19`.
