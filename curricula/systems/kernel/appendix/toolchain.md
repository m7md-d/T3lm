# الأدوات

## ما يلزم

| الأداة | لماذا | الإصدار الذي بُني عليه |
|---|---|---|
| `clang` | مترجمٌ عابرٌ للأهداف: `--target=x86_64-elf` يكفي | 23.1 |
| `ld.lld` | رابطٌ يفهم ELF وسكربتات الربط | 23.1 |
| `llvm-readelf` · `llvm-objdump` · `llvm-nm` · `llvm-addr2line` | قراءةُ الصورة، وحلُّ العناوين في الفصل `26` | 23.1 |
| `limine` | الـbootloader، وملفّاته تُنسَخ في صورة الإقلاع | 12.8 |
| `xorriso` | بناءُ صورة ISO هجينة تُقلِع بـBIOS وUEFI | 1.5.8 |
| `qemu-system-x86_64` | التشغيل | 11.1.1 |

**ولا cross-GCC يُبنى بيد.** بناءُ `x86_64-elf-gcc` من المصدر يستغرق ساعةً ويحلّ
مشكلةً لا توجد: `clang` يحمل كلَّ الأهداف أصلاً. ومن أراد GCC فالبناء لا يتغيّر إلا
في قيمة `CC`.

```bash
# Debian/Ubuntu
sudo apt install clang lld llvm xorriso qemu-system-x86
# ثم limine من مستودعه — أو من حزمةٍ إن وُجدت

# macOS
brew install llvm lld limine xorriso qemu
```

على macOS، `llvm` و`lld` مُعلَّقان (keg-only)، و`programs/build.sh` يجدهما في
`/opt/homebrew/opt/` تلقائياً.

## البناء والتشغيل

```bash
cd programs
./build.sh 05          # يبني نواة المرحلة ٥ وصورة إقلاعها، ويطبع مسار الـISO
./build.sh 05 run      # ويشغّلها ويطبع طرفيتها
TIMEOUT=60 ./build.sh 21 run    # مهلةٌ أطول لمرحلةٍ تحسب طويلاً
```

والبناء يستعمل `-fno-omit-frame-pointer` دائماً: بدونه لا تُبنى سلسلةُ `rbp`،
فلا أثرَ مكدَّسٍ عند الانهيار (الفصل `26`). وثمنُه سجلٌّ واحدٌ محجوز.

وما يدخل بناء كل مرحلة في [`stages.conf`](../programs/stages.conf): سطرٌ فيه رقمُ
المرحلة، وملفّات النواة، ووسائطُ QEMU الزائدة. وملفُّ المرحلة نفسه
`demos/sNN.c` ويعرّف `stage_main()`.

**والمراحل ذواتُ الحرف تجاربُ فشلٍ مقصودة:** `01x` و`02x` و`05x` و`13x` و`16x`.
وكلٌّ منها مذكورةٌ في فصلها، ومخرَجُها جزءٌ من الدرس.

### وبرامج المستخدم

```bash
./user/build.sh prog     # يبني ويولّد prog_blob.h وprog_elf.h
```

ويستدعيها `build.sh` تلقائياً عند غياب الترويسة. **والترويسات مولَّدةٌ ولا تدخل
Git** — تُبنى بأمرٍ واحد.

## GDB على QEMU

```bash
./build.sh 11                       # ابنِ بلا تشغيل
qemu-system-x86_64 -cdrom out/11/kernel.iso -m 256M \
  -serial stdio -display none -no-reboot -S -s &
gdb out/11/kernel.elf
```

و`-S` يوقف المعالج قبل أوّل تعليمة، و`-s` يفتح منفذ التنقيح `1234`. ثم في GDB:

```
target remote :1234
break kmain
break context_switch
continue
info registers
x/8gx $rsp            # ثماني كلماتٍ من قمّة المكدَّس
p/x $cr3              # جذرُ جداول الصفحات
disassemble
```

**وأنفعُ موضعٍ لنقطة توقّف في هذا المنهج** `context_switch`: قف عندها، واقرأ
`$rsp`، ثم `stepi` ثلاث مرّات، واقرأه ثانيةً. السطران اللذان يبدّلان المكدَّس
يُرَيان هناك.

ولفحص جداول الصفحات بلا كود، من مراقب QEMU (`Ctrl-a c`):

```
info mem          # المطابقات الحالية
info registers    # حالةُ المعالج كاملةً
info tlb          # الترجمات المخزَّنة
```

## حين لا يُقلِع شيء

| العرَض | أوّلُ ما يُفحَص |
|---|---|
| إقلاعٌ متكرّر | triple fault. أضِف `-no-reboot -d cpu_reset` وانظر حالة التعيين |
| لا مخرَج البتّة | هل وصل التنفيذ أصلاً؟ ضع `qemu_exit(0x2a)` أوّلَ `stage_main` واقرأ الشفرة |
| توقّفٌ بلا رسالة | استثناءٌ بلا معالج قبل بناء IDT — أو مقاطعةٌ مطفأةٌ تنتظر |
| يعمل مرّةً ثم يصمت | `EOI` منسيّة (الفصل `08`)، أو قفلٌ لم يُفتَح |
| يعمل على QEMU ولا شيء يضمن غيره | راجع الفصل `02`: المحاكي يخفي عيوباً تفرضها المواصفة |
