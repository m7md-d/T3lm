# الفصل 17 — العملية

## المشكلة

عندك صورةٌ محمَّلة، وفضاءُ عنوان، وخيطٌ ينزل إلى الحلقة ٣. وليس عندك **عملية**.

والفرق ليس في التسمية: `sys_exit` في الفصل السابق لم تجد ما تُنهيه، فأنهت المرحلة
كلَّها. ولا يوجد من يملك جدول الملفّات، ولا من يُستردّ منه المكدَّس، ولا رقمٌ
يُشار به.

وأربعةُ مفاهيمٍ تُخلَط هنا عادةً، والخلطُ بينها هو المشكلة:

| | ما هو | ما يملكه |
|---|---|---|
| `execution context` | حالةُ معالجٍ محفوظة | `rsp` وما عليه — الفصل `10` |
| `thread` | سياقٌ + جدولةٌ + مكدَّسُ نواة | يُجدوَل، ولا يملك ذاكرةً |
| `address space` | جذرُ جداولٍ وما تحته | ترجمةً، ولا يُجدوَل |
| `process` | **حاويةٌ** تجمعها وتضيف هُويّة | فضاءً، وخيطاً أو أكثر، وجدولَ أوصاف |

والعمليةُ وحدها من هذه الأربعة **لا آليةَ لها في العتاد**. فهي تجريدٌ خالص، وكلُّ
ما فيها كودٌ نكتبه.

## البنية الداخلية

<!-- part: kernel/proc.h -->

```c
struct process {
    int       pid;
    const char *name;
    uint64_t  root;             /* فضاء العنوان — تملكه العملية لا الخيط */
    uint64_t  entry;
    struct thread *main;        /* خيطٌ واحدٌ اليوم؛ والبنية تحتمل أكثر */
    int       fds[MAX_FDS];     /* جدولٌ لكل عملية — يملؤه الفصل 19 */
    bool      alive;
    int       exit_code;
};
```

والتعليق على `root` هو الفرق كلُّه: **فضاء العنوان يخصّ العملية**. فخيطان في
عمليةٍ واحدة يتشاركان الذاكرة ولكلٍّ مكدَّسُه — وهذا هو تعريف الخيط المشترك الذي
رأيتَه من الطرف الآخر في `c-advanced` فصل `20`.

و`fds` مصفوفةٌ **لكل عملية**: الرقم ٣ في عمليةٍ لا علاقة له بالرقم ٣ في أخرى.
وهذا معنى «الوصف محلّيّ»، والفصل `19` يملؤها بشيء.

## ما يجب أن يتغيّر في الجدولة

الخيط صار قد يسكن فضاءً غير فضاء النواة. فحقلان يُضافان إليه، وثلاثةُ أسطرٍ إلى
`schedule`:

<!-- part: kernel/sched.c -->

```c
    /* ما يلزم قبل أن يعمل خيطٌ في فضاءٍ آخر:
       جذرُ جداوله، ومكدَّسُ الحلقة صفر الذي سيجده المعالج إن دخل من ٣. */
    if (next->kstack_top) { tss_set_rsp0(next->kstack_top); syscall_kstack = next->kstack_top; }
    if (next->cr3 && next->cr3 != cur->cr3) vmm_switch(next->cr3);
```

**الشرط `!=` ليس تحسيناً.** كتابةُ `cr3` تُبطِل الـTLB كلَّه (الفصل `05`)، فتبديلٌ
بلا حاجةٍ يدفع ثمناً بلا مقابل. وخيطان في عمليةٍ واحدة لهما نفس `cr3`.

والسطرُ الذي قبله يُحدِّث **موضعين**: `tss.rsp0` للمقاطعات والاستثناءات،
و`syscall_kstack` للاستدعاءات. ولو نسينا أحدهما، لدخل استدعاءٌ من العملية الثانية
على مكدَّس الأولى — وهو فسادٌ صامت.

## التجربة: عمليتان، وعنوانٌ واحد

<!-- runs: 17 -->

```c
struct process *a = proc_spawn("prog",    prog_elf_blob,    sizeof prog_elf_blob);
struct process *b = proc_spawn("counter", counter_elf_blob, sizeof counter_elf_blob);
```

**المخرَج**

<!-- out @ours: العناوين الفيزيائية تتغيّر بين تشغيلين؛ والافتراضيّ ثابتٌ بحكم الصورة -->

```
[INFO] pid 1 (prog) root=0x000000000007d000 entry=0x0000000000400000
[INFO] pid 2 (counter) root=0x000000000008d000 entry=0x0000000000400000
[INFO] same entry address, different address spaces: yes
[INFO] entry 0x0000000000400000 resolves to 0x0000000000082000 in pid 1, and 0x0000000000092000 in pid 2
```

هذا هو العزل في سطرٍ واحد. **نفس العنوان الافتراضيّ `0x400000` في العمليتين**،
ويترجَم إلى إطارين مختلفين.

فالعنوان الافتراضيّ ليس اسماً عالمياً: هو اسمٌ **داخل فضاء**. ومؤشّرٌ تمرّره عمليةٌ
إلى أخرى لا معنى له — وهذا سببٌ بنيويّ لوجود `copy_from_user` من الفصل `15`، لا
احتياطٌ أمنيّ فقط.

والعمليتان تكتبان من `0x402000` — نفس العنوان، وبياناتٌ مختلفة.

**المكسب** أنّ كلَّ ما بُني في الحِزَم الأربع السابقة صار نظاماً: خريطةٌ فيزيائية،
وجداولُ صفحات، ومقاطعات، وجدولة، وحدٌّ مع userspace — تجتمع في كيانٍ واحدٍ له
رقمٌ ونهاية.

⚠ و`slices = 1` لكلٍّ: البرنامجان قصيران وانتهى أحدُهما قبل أوّل استباق. فاللوحة
تشهد على العزل، **ولا تشهد على التداخل**. وتمرينُ الفصل يجعلهما يتداخلان.

## نهايةٌ مرتّبة

```c
void proc_exit(int code) {
    struct process *p = proc_current();
    p->alive = false;
    p->exit_code = code;
    p->main->state = T_DEAD;
    schedule();                 /* لا نعود: الخيط ميّت ولن يُختار */
    panic("proc_exit: a dead thread was scheduled");
}
```

و`panic` بعد `schedule` ليست حشواً: هي **ثابتٌ يُفحَص**. الخيط صار `T_DEAD` فلا
يجوز أن تختاره الجدولة؛ فإن عاد التنفيذ إلى هذا السطر، فالخلل في `schedule` لا
هنا. والانهيار عند الثابت المكسور أرخصُ من متابعةٍ بحالةٍ فاسدة.

⚠ وما **لا** تفعله هذه الدالّة مُعلَن: لا تحرّر الإطارات، ولا جداول الصفحات، ولا
مكدَّس النواة. والعملية تبقى `T_DEAD` بكل مواردها. وذلك حدٌّ يُرفَع في الفصل `23`
— فالتحرير يحتاج يقيناً بأن لا أحد يستعمل ما تحرّره، وذلك يقينٌ لا نملكه اليوم.

## الفخاخ التصوّرية

| الفخّ | الصواب |
|---|---|
| «العملية = البرنامج» | البرنامج ملفٌّ على قرص. والعملية تشغيلٌ له، وقد تكون عشراً من صورةٍ واحدة |
| «العملية = الخيط» | الخيط يُجدوَل والعملية لا. وعمليةٌ بخيطين شيءٌ واحدٌ يُجدوَل مرّتين |
| «العملية = فضاء العنوان» | الفضاء ترجمة. والعملية تضيف هُويّةً وجدولَ أوصافٍ ونهاية |
| «المؤشّر رقمٌ فيمكن تمريرُه» | اسمٌ داخل فضاء. واللوحة: نفس `0x400000` يعني إطارين |
| «`exit` تحرّر الموارد» | تُعلِّم الحالة. والتحرير يحتاج يقيناً بأن لا مستعمِل — الفصل `23` |
| «`pid` معرّفٌ يكفي» | رقمٌ يُعاد استعماله. وسباقُ «العملية ماتت وأُعطي رقمُها لغيرها» مشكلةٌ قائمة في أنظمةٍ حقيقية |

## Checkpoint

١. خيطان في عمليةٍ واحدة: أي حقولٍ في `struct thread` تختلف بينهما، وأيُّها
يتطابق؟
٢. `schedule` تبدّل `cr3` بشرط `!=`. صِف ما يُدفَع ثمناً لو حذفنا الشرط.
٣. `tss.rsp0` و`syscall_kstack` يُحدَّثان معاً. اذكر سيناريو فسادٍ لو حُدِّث أحدُهما.
٤. اكتب ما يجب أن يصحّ قبل أن تحرّر `p->root` وكلَّ ما تحته.

## Artifact

| | |
|---|---|
| مخطّط | عمليتان، ولكلٍّ جذرٌ وخيطٌ وجدولُ أوصاف، ونفسُ `0x400000` يشير إلى إطارين |
| تنفيذ | `proc_spawn` و`proc_exit`، وثلاثةُ أسطرٍ في `schedule` |
| تجربةُ فشل | `panic` بعد `schedule` — ثابتٌ يُفحَص لا سطرٌ ميّت |
| أثرُ تنفيذ | `spawn` ← فضاء ← تحميل ← مكدَّس ← خيط ← طابور ← `iretq` |
| مقارنة | `task_struct`: الخيط والعملية بنيةٌ واحدة تتشارك حقولَها بعلَم |

## التمرين

اجعل `prog` يدور مئة ألف دورةٍ بين كل كتابتين، وأعد التشغيل. هل تداخلت مخرجاتُ
العمليتين؟ واقرأ `slices` — بكم صارت؟

ثم أنشئ عمليةً ثالثة من **نفس** صورة `counter`. كم إطاراً استُهلك إضافياً، وأيُّها
كان يمكن أن يُشارَك لو بنينا copy-on-write؟

ثم اجعل `proc_exit` تحرّر مكدَّس النواة بـ`kfree` وأعد التشغيل. ماذا يقع، ولماذا؟
وأي سطرٍ في `proc_exit` يجعل هذا مستحيلاً بترتيبه الحاليّ؟

**الفصل التالي:** نظامُك يشغّل عملياتٍ ويخدمها. وكلُّ ما يعرفه عن العالم منفذٌ
تسلسليٌّ كتبناه في الفصل `02`. فكيف يتحدّث المعالج مع جهازٍ أصلاً؟
