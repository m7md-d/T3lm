# الفصل 21 — من أين يأتي التنافس

## المشكلة

كلُّ ما بُني حتى الآن قُرئ وكأنّ شيئاً واحداً يعمل في كل لحظة. وذلك لم يكن صحيحاً
منذ الفصل `09`: المقاطعة تقع **في وسط** كودك، بين تعليمةٍ وأختها، بلا إذنٍ منك.

ونواةٌ بمعالجٍ واحدٍ فيها أربعةُ مصادر للتنافس، ولكلٍّ علاجٌ مختلف:

| المصدر | متى ظهر | ما يوقفه |
|---|---|---|
| مقاطعةٌ تقطع كوداً | الفصل `09` | `cli` أو قناعُ الخطّ |
| استباقٌ يبدّل الخيط | الفصل `13` | منعُ الاستباق |
| معالجٌ ثانٍ | الفصل `22` | **قفلٌ، ولا شيء غيره** |
| جهازٌ يكتب بـDMA | لم نبنِه | حواجزُ ذاكرةٍ وملكيّةٌ مُعلَنة |

والصفُّ الثالث هو ما يجعل الصفَّين الأوّلين غير كافيين — وهو الفصل التالي.

## الآلية الخام: ما هو ذرّيٌّ أصلاً

قبل أي قفل، يجب أن يُعرَف ما الذي لا يحتاج قفلاً. وأوّلُ اختبارٍ أجريناه أعطى
جواباً غيرَ متوقّع:

<!-- out @arch: مخرَجُ `llvm-objdump` على كائن المرحلة -->

```
$ llvm-objdump -d out/21/s21_c.o
      c0:      	incq	(%rip)
```

`counter++` على متغيّرٍ من ٦٤ بت صار **تعليمةً واحدة**. والمقاطعة لا تقع داخل
تعليمة: المعالج يُنهيها ثم يخدم. فعلى معالجٍ واحد، هذه الزيادة آمنةٌ من المقاطعات
بلا أي حماية.

⚠ وهذا **ليس** ضماناً عامّاً: ليس ذرّياً تجاه معالجٍ ثانٍ (لا `lock` عليه)، ولا
مضموناً أن يختار المترجم تعليمةً واحدة، ولا صحيحاً لبنيةٍ من حقلين. والاعتماد
عليه اعتمادٌ على قرار مترجمٍ لا على قاعدة.

**القاعدة** أنّ التنافس يحتاج نافذة، والنافذةُ تحتاج أكثر من خطوة.

## التجربة: ثابتٌ من حقلين

فنبني حالةً لها **ثابت**: `a == b` دائماً بين التحديثين. والتحديثُ خطوتان.

<!-- part: demos/s21.c -->

```c
static volatile uint64_t a, b;

/* المقاطعة قارئٌ لا كاتب: تفحص الثابت وتعدّ خرقَه */
static void tick(void) {
    if (mode == 2) {
        uint64_t f = spin_lock_irqsave(&lk);
        checks++; if (a != b) broken++;
        spin_unlock_irqrestore(&lk, f);
    } else {
        checks++; if (a != b) broken++;
    }
}
```

**المخرَج**

<!-- runs: 21 -->
<!-- out @ours: النافذة موسَّعةٌ عمداً؛ والأعداد تتغيّر بين تشغيلين -->

```
[INFO] one CPU, no preemption. the only other actor is the timer interrupt.
[INFO] unprotected            checks=41  invariant broken=39
[INFO] cli/sti                checks=46  invariant broken=0
[INFO] spinlock + irqsave     checks=53  invariant broken=0
```

تسعةٌ وثلاثون خرقاً من إحدى وأربعين قراءة. ولا خيطَ ثانٍ ولا معالجَ ثانٍ: الطرفُ
الآخر **مقاطعةُ مؤقّتٍ** تقع بين `a++` و`b++`.

⚠ والنافذة موسَّعةٌ عمداً بحلقةٍ قصيرة لتصير مرئيةً في تشغيلٍ من ثوانٍ. وهي في
كودٍ حقيقيّ تتّسع بطبيعتها: إدراجٌ في قائمة، أو تحديثُ حقلين بينهما حساب. **والرقم
مقيسٌ في هذه البيئة، ولا يُقرأ احتمالاً عامّاً.**

## `cli` قفلٌ، وحدُّه معلوم

السطر الثاني: صفرُ خروقات بـ`cli/sti`. فالمقاطعة لم تعد تقع داخل النافذة.

```c
static inline uint64_t irq_save(void) {
    uint64_t f;
    __asm__ volatile("pushfq; popq %0; cli" : "=r"(f) :: "memory");
    return f;
}
static inline void irq_restore(uint64_t f) {
    __asm__ volatile("pushq %0; popfq" :: "r"(f) : "memory", "cc");
}
```

و**الحفظُ والاستعادة** لا `cli`/`sti` المجرّدتان. والسبب التداخل: دالّةٌ تطفئ ثم
تنادي دالّةً تطفئ وتُشعِل، فتعود الأولى وقد فُتحت المقاطعات وهي تظنّها مغلقة.
فالاستعادة تُرجِع **ما كان**، والكودُ يصير قابلاً للتركيب.

**وحدُّ `cli` ثلاثة، وكلُّها مُعلَنة:**

| الحدّ | ما يعنيه |
|---|---|
| **محلّيّ للمعالج** | لا يقول شيئاً لمعالجٍ ثانٍ — الفصل التالي |
| **يزيد زمن الاستجابة** | كلُّ مقاطعةٍ تنتظر. فالقسم المحميّ يجب أن يكون قصيراً |
| **لا يصلح للنوم** | كودٌ يطفئ المقاطعات ثم ينام يوقف النظام: لا مؤقّتَ يوقظه |

والثالث هو سبب وجود نوعين من الأقفال أصلاً.

## القفل: ذرّيةٌ لا نيّة

```c
void spin_lock(struct spinlock *l) {
    while (__atomic_exchange_n(&l->locked, 1, __ATOMIC_ACQUIRE))
        __asm__ volatile("pause");          /* تلميحٌ للمعالج: هذه حلقةُ انتظار */
}
```

و`__atomic_exchange_n` تُترجَم إلى `xchg` — وهي مقفلةٌ ضمناً على x86. والذرّية
شرطٌ لا تحسين: `if (!locked) locked = 1;` بخطوتين، ويمرّ منها اثنان معاً.

و`__ATOMIC_ACQUIRE` عند الأخذ و`__ATOMIC_RELEASE` عند الترك هما نفسُ الدلالتين من
`c-advanced` فصل `24`. وما يشتريانه أنّ ما بعد الأخذ لا يسبقه، وما قبل الترك لا
يتأخّر عنه — فما كتبتَه داخل القسم يراه من يأخذ القفل بعدك.

### ولماذا `irqsave` مع القفل

<!-- part: kernel/spinlock.h -->

```c
uint64_t spin_lock_irqsave(struct spinlock *l);
void     spin_unlock_irqrestore(struct spinlock *l, uint64_t flags);
```

حالةٌ يمسّها معالجُ مقاطعة تحتاج **الاثنين**. ولو أخذنا القفل بلا إطفاء
المقاطعات، ووقعت مقاطعةٌ على نفس المعالج وهي تريد نفس القفل: تدور تنتظر قفلاً
يملكه كودٌ **قُوطع ولن يُكمِل حتى تنتهي هي**. وذلك جمودٌ لا يُفَكّ.

**القاعدة** التي تخرج من هذا: قفلٌ يُؤخَذ من داخل مقاطعة يجب أن يُؤخَذ خارجها
بإطفاءٍ دائماً. وترتيبُ الأخذ مهمّ: نطفئ ثم نقفل، ونفتح القفل ثم نستعيد — والعكس
يترك نافذةً.

## الفخاخ التصوّرية

| الفخّ | الصواب |
|---|---|
| «نواةٌ بمعالجٍ واحدٍ بلا تنافس» | المقاطعة طرفٌ ثانٍ منذ الفصل `09`. واللوحة: ٣٩ خرقاً بلا خيطٍ ثانٍ |
| «`x++` ذرّيّ» | صار تعليمةً واحدة **هنا**، وذلك قرارُ مترجم. ولا يضمن شيئاً تجاه معالجٍ ثانٍ |
| «`cli` ثم `sti`» | استعِد ما كان. والتداخلُ يجعل `sti` تفتح ما أغلقه غيرُك |
| «القفل يحمي البيانات» | يحمي من **يأخذه**. ومن قرأ بلا قفلٍ قرأ حالةً نصفَ محدَّثة |
| «`volatile` تكفي» | تمنع تحسين المترجم. ولا ذرّيةَ ولا ترتيبَ بين معالجين |
| «القفل الأقصر أفضل دائماً» | القسم القصير يقلّل الانتظار، وتقسيمُ قسمٍ إلى قسمين قد يكسر الثابت بينهما |

## Checkpoint

١. لماذا لم يُكسَر الثابت حين كانت الزيادةُ تعليمةً واحدة؟ وما الذي تغيّر بإضافة
الحقل الثاني؟
٢. اكتب تسلسلاً يقع فيه جمودٌ لو أخذنا القفل بلا `irq_save`، وكان المؤقّت يأخذ
نفس القفل.
٣. `irq_restore` تعيد ما كان. اذكر مسار نداءاتٍ من ثلاث دوالّ ينكسر لو استعملنا
`sti` مباشرة.
٤. الحلقة في `spin_lock` تنادي `pause`. ما الذي تشتريه، ولماذا لا تكفي حلقةٌ
فارغة؟

## Artifact

| | |
|---|---|
| مخطّط | خطُّ زمنٍ لكودٍ يُحدِّث حقلين، وسهمُ المقاطعة يهبط بينهما |
| تنفيذ | `spin_lock` و`irq_save` و`spin_lock_irqsave` |
| تجربةُ فشل | النمط صفر: ٣٩ خرقاً من ٤١ قراءة |
| أثرُ تنفيذ | `a++` ← نافذة ← مقاطعة ← قراءةٌ ترى `a != b` ← `b++` |
| مقارنة | أقفال Linux: `spin_lock_irqsave` ومتى تُطلَب بدل `spin_lock` |

## التمرين

اجعل `WINDOW` صفراً وأعد التشغيل. كم صار عددُ الخروق؟ وهل يعني الصفرُ أنّ الكود
صار صحيحاً؟

ثم اعكس الترتيب في `spin_unlock_irqrestore`: استعِد المقاطعات **ثم** افتح القفل.
صِف النافذة التي فتحتَها، وهل تظهر في تشغيلٍ من ثوانٍ؟

ثم اجعل معالج المؤقّت يأخذ القفل بـ`spin_lock` المجرّدة بينما يأخذه الكود الرئيسيّ
كذلك بلا إطفاء. ماذا يحدث، وبعد كم نبضة؟

**الفصل التالي:** كلُّ علاجٍ في هذا الفصل يقوم على أنّ تنفيذاً واحداً يجري في كل
لحظة على هذه الآلة. وعلى الآلة معالجٌ ثانٍ لم نوقظه بعد.
