# النصّ من البايت — الترميز وفكّه ويونيكود

**مقترَح: هذه خطّةٌ كاملة، والمنهج لم يُبنَ بعد.** لا `curriculum.json` هنا حتى
يُبنى (انظر [`repo-layout.md`](../../../.claude/conventions/repo-layout.md)
§«المقترَح»).

---

## لمن كُتب

لمن يعرف **البايت** ولا يعرف كيف صار حرفاً. ولمن كتب `strlen("مرحبا")` فرأى
عشرة، أو رصف جدولاً بالعربية فانهارت أعمدته، أو قارن اسمين متطابقين على الشاشة
فلم يتساويا.

**المتطلّب:** منهج [`languages/c`](../../languages/c/README.md) أقاليم ٠٢–٠٦ —
البت والبايت، والعدد الصحيح، والحرف، والتحويل. والإقليم ٠٥ ينتهي عند الجملة
التي يبدأ منها هذا المنهج: **UTF-8 بايتاتٌ لا حروف.**

ولا يُفترَض شيءٌ غير ذلك: لا لغةٌ عالية، ولا خبرةٌ بالواجهات.

## الأدوات المستهدفة

```
cc -std=c17 -Wall -Wextra        # الكود كلّه C: البايت يُرى بلا وسيط
python3 -c 'import unicodedata'  # الجداول تُستشهَد لا تُحفَظ
hexdump -C · iconv · uconv       # القراءة والتحويل
```

**والكود بلغة C عمداً:** كل لغةٍ عاليةٍ تخفي طبقةً من هذا الموضوع، ومن يتعلّمه
خلف تجريدٍ يتعلّم تجريداً. وحيث يلزم جدولُ يونيكود يُستدعى `unicodedata` أداةً
مرجعية، ويُقال إنه مرجعٌ لا جزءٌ من الجواب.

**وإصدار يونيكود يُثبَّت ويُعلَن** — الجداول تتغيّر بين إصدارٍ وآخر، ولوحةٌ بلا
إصدارٍ ادّعاءٌ بلا سند.

## البديهيات الخمس

| # | البديهية | أوّل ما يتساقط منها |
|---|---|---|
| ١ | لا يوجد نصٌّ بلا ترميز | «ملفّ نصّ عاديّ» جملةٌ ناقصة · والبايتات لا تحمل معناها معها |
| ٢ | يونيكود **فهرس** لا ترميز | الفصل بين «ما رقمُ هذا الحرف» و«كيف يُكتَب الرقم بايتات» |
| ٣ | الحرف الذي تراه ليس code point | العَلَم رمزان، والعائلة ستّة، و`é` قد تكون اثنين |
| ٤ | «الطول» سؤالٌ ناقص | بايتات؟ code points؟ عناقيد؟ أعمدة على الطرفية؟ أربعةُ أجوبةٍ صحيحة |
| ٥ | المقارنة والترتيب **لغةٌ** لا رياضيات | `<` بين نصّين يسأل: بأي لغة؟ · وتركيا تكسر `toLowerCase` |

## الطريق — خمس حِزَم

| | | |
|---|---|---|
| `00–03` | **قبل يونيكود** | لماذا وُجد أصلاً — والفوضى التي جاء ليُنهيها |
| `04–07` | **الفهرس** | يونيكود ترقيمٌ وتسميةٌ وخصائص، ولا بايت فيه |
| `08–13` | **الترميزات** | من الرقم إلى البايتات، وبالعكس — وأخطاؤها |
| `14–19` | **الحرف الذي تراه** | العنقود والتطبيع والحالة والعرض والاتّجاه والتشكيل |
| `20–25` | **النصّ في الأنظمة** | الترتيب والبحث وأسماء الملفّات والسلك والأمن، ثم مكتبةٌ تُكتَب |

### وتفصيلُها

| | | |
|---|---|---|
| `00` | **الفصل صفر: البايت لا يقول ماذا يعني** | النظريّ الوحيد: من التلغراف إلى Baudot إلى ASCII إلى صفحات الترميز إلى يونيكود · البديهيات الخمس بأدلّةٍ تعمل · و**السؤال الرابع**: من قرّر أن هذا البايت هذا الحرف؟ |
| `01` | **ASCII** | سبعة بتات ولماذا سبعة · وترتيبه ليس اعتباطاً: `0x30` للأرقام، وبتٌّ واحد بين `A` و`a`، والحيل التي بُنيت على شكله |
| `02` | **البت الثامن** | Latin-1 وصفحات الترميز · CP1256 للعربية · و**mojibake**: تصنعه بيدك وتقرأ سببه |
| `03` | **قبل الفوضى بقليل** | Shift-JIS وGB2312 وBig5 · التراميز متعدّدة البايت · مصيدةُ الـlead byte، ولماذا كان `strchr` خطراً |
| `04` | **الـcode point** | `U+0000`..`U+10FFFF` · المستويات · ولماذا توقّف الحدّ عند `10FFFF` بالضبط (والجواب في UTF-16) |
| `05` | **الخصائص** | لكل code point صفٌّ في جدول · general category · وأن «هل هذا حرف؟» سؤالٌ يُجاب من الجدول لا من الحدس |
| `06` | **المحجوز** | الـsurrogates ولماذا لا تُرمَّز وحدها · noncharacters · private use · و**WTF-8** حين تُخالَف القاعدة |
| `07` | **الأسماء والكتل** | لماذا الاسم ثابتٌ إلى الأبد، ولماذا لا يُبنى قرارٌ على الكتلة (block) |
| `08` | **UTF-32** | أبسط ما يمكن · وثمنه أربعةُ أضعاف · ولماذا لا يحلّ مشكلة «الحرف» أصلاً |
| `09` | **UTF-16** | من أين جاءت · الـsurrogate pair · ولماذا حملتها Java وJavaScript وWindows · وما تكسره: `length` يكذب على الرموز التعبيرية |
| `10` | **UTF-8** | التصميم في صفحةٍ واحدة · **self-synchronizing** · وأن ترتيب بايتاتها يحفظ ترتيب الـcode points · ولماذا فازت |
| `11` | **تفكّها بيدك** | آلة حالاتٍ في ستّين سطر C · الترميز الزائد (overlong) وهجومُه · البايتات التي لا تصلح مطلقاً |
| `12` | **BOM** | ما هو · متى يُميّز · ومتى يفسد ملفّاً في أوّل بايتاته |
| `13` | **الفشل** | `U+FFFD` وكيف يُستبدَل · وسياسات الفشل الثلاث — تشدّد، إبدال، تجاهل — وأيُّها يخفي العطب |
| `14` | **العنقود (grapheme cluster)** | العَلَم رمزان، ولون البشرة معدِّل، والعائلة ستّة بـZWJ · وكيف يُقسَم النصّ فعلاً حين تضغط ⌫ |
| `15` | **التطبيع** | NFC وNFD وNFKC وNFKD · لماذا `é` شكلان · ومتى يُطبَّع ومتى يكون التطبيع خسارة |
| `16` | **الحالة** | `ß` و`İ` · ولماذا تركيا تكسر `toLowerCase` · و**casefold** ليست lowercase |
| `17` | **العرض** | عمودُ الطرفية · East Asian Width · وما يكسر محاذاة الجداول — وهو ما ترصده أنت في كل واجهة |
| `18` | **الاتّجاه** | خوارزمية bidi · المستويات · محارف العزل `LRI`/`RLI`/`FSI` · ولماذا **العربية تحتاج العزل** في كل واجهةٍ فيها كود |
| `19` | **التشكيل** | الوصل العربي · الأشكال الأربعة · ولماذا **الخطّ** يقرّر الشكل لا الترميز — وهنا يُفهَم لماذا يفكّ الخطّ الأحاديّ وصلَ الحروف |
| `20` | **الترتيب** | collation · الخوارزمية الموحّدة (UCA) · والمقارنة الثنائية متى تكفي ومتى تكذب |
| `21` | **البحث** | regex على أي وحدة؟ · حدود الكلمة · والمطابقة بعد التطبيع |
| `22` | **اسم الملفّ ليس نصّاً** | NFD في macOS · UTF-16 في Windows · بايتاتٌ عمياء في Linux · وما يحدث حين ينتقل الاسم بينها |
| `23` | **النصّ على السلك** | MIME وcharset · وماذا لو كذبت الترويسة · وسياسة «UTF-8 وحدها» في الويب |
| `24` | **الأمن** | المتشابهات بصرياً (confusables) · هجوم IDN · وحقن الاتّجاه في اسم ملفّ يقلب امتداده |
| `25` | **الختام: مكتبةٌ تُكتَب** | ترميزٌ وفكٌّ لـUTF-8 وUTF-16، وتقسيمُ عناقيد، وحسابُ عرض · **بلا كود جاهز**: مواصفةٌ ومعايير قبول، وحزمةُ اختباراتٍ من ملفّات يونيكود المرجعية |

## الفصل صفر — ما يجب أن يحمله

إلزاميٌّ لكل منهج، وهنا يحمل:

1. **القصّة تحت ضغطها**: كل قرارٍ في يونيكود جوابٌ على قيدٍ عمليّ — التوافق مع
   ما سبق، وحدُّ الذاكرة، وسياسةُ الدول. ومن لا يرى الضغط يرى تعقيداً بلا سبب.
2. **البديهيات الخمس، ولكلٍّ دليلٌ يعمل** — لا شرحَ لها بل برنامجٌ يُظهرها.
3. **السؤال الرابع** الذي يلازم كل لوحة: من يضمن هذا المخرَج — المواصفة، أم
   إصدارُ يونيكود، أم الخطّ، أم الطرفية؟ وهي **أربع سلطات** لا اثنتان.

## التحقّق

`tools/verify.py` على نمط منهج C: يترجم كل بلوكٍ ويقارن مخرَجه بلوحته، ويعدّ ما
لم يُفحَص فيظهر الثقب في التقرير.

**وثلاث سلطاتٍ خاصّةٌ بهذا الموضوع تُعلَن مع اللوحة:**

| السلطة | معناها |
|---|---|
| `@unicode:NN` | مضمونٌ بجداول إصدارٍ بعينه من يونيكود — وقد يتغيّر في التالي |
| `@font` | يقرّره الخطّ لا الترميز (الشكل، الوصل، الرموز المركّبة) |
| `@term` | يقرّره برنامج الطرفية (العرض، الاتّجاه، ما يُرسَم فعلاً) |

**وما لا يُفحَص آلياً يُعلَن**: شكلُ الحرف على الشاشة ادّعاءٌ بصريّ، وموضعه
لقطةُ صورةٍ في المنهج لا لوحةُ نصّ.

## قرارات معلّقة

1. **إصدار يونيكود** يُثبَّت عليه المنهج ويُعلَن في `curriculum.json`.
2. **العنقود أم التطبيع أوّلاً؟** الترتيب المقترَح يضع العنقود (١٤) قبل التطبيع
   (١٥) لأن «الحرف الذي تراه» أقرب إلى حدس القارئ. ويحتمل العكس.
3. **حزمة الاختبارات المرجعية**: ملفّات يونيكود (`NormalizationTest.txt` و
   `GraphemeBreakTest.txt`) تُحمَّل مرّةً وتُلتزَم، أم تُجلَب وقت الفحص؟
