# الإقليم ٣٠ — السجلّ

> رأيتَ الحزمة كملفّاتٍ على قرصك (الإقليم ٠٩)، وفي مخزن `containerd` (الإقليم
> ٢٦). وفي الحالتين كان مصدرها **سجلّاً** لم تفتحه بعد.
>
> والسجلّ ليس أداةً معقّدة — هو واجهة HTTP بسيطة، تتكلّم معها بـ`curl` وحده،
> بلا `docker login` ولا `docker pull`. هذا الإقليم يسحب صورةً حقيقية بيدك حتى
> القاع، ثم يرفع صورةً بيدك أيضاً.

---

## الرمز: من يثق بك بلا كلمة سرّ

السحب من سجلٍّ عامٍّ لا يحتاج حساباً، لكنّه يحتاج **رمزاً** لكل مستودعٍ تطلبه:

<!-- host -->

```sh
curl -s "https://auth.docker.io/token?service=registry.docker.io&scope=repository:library/alpine:pull" \
	| python3 -c 'import json,sys; d=json.load(sys.stdin); print(sorted(d.keys())); print(len(d["token"]) > 100)'
```

<!-- gate @impl -->

```
['access_token', 'expires_in', 'issued_at', 'token']
True
```

طلبٌ واحدٌ بلا اسم مستخدمٍ ولا كلمة سرّ، وعاد برمز JWT طويل. و`scope` في
الرابط هو المفتاح: `repository:library/alpine:pull` — **رمزٌ لمستودعٍ بعينه
ولفعلٍ بعينه**، لا رمزٌ عامّ لكل شيء.

**والمكسب:** هذا هو بالضبط ما يفعله `docker pull` قبل أوّل بايت. ولذلك تنجح
`docker pull alpine` بلا `docker login` من الأساس: السجلّ العامّ يمنح رموز
قراءةٍ لأي طالب، ويشترط اسم مستخدمٍ حين يكون الفعل `push` أو حين يكون
المستودع خاصّاً.

## المانفست: نفس الفهرس الذي مشيتَ عليه من قبل

<!-- host -->

```sh
TOKEN=$(curl -s "https://auth.docker.io/token?service=registry.docker.io&scope=repository:library/alpine:pull" \
	| python3 -c 'import json,sys; print(json.load(sys.stdin)["token"])')
curl -s -H "Authorization: Bearer $TOKEN" \
	-H "Accept: application/vnd.oci.image.index.v1+json" \
	"https://registry-1.docker.io/v2/library/alpine/manifests/3.20" \
	| python3 -c 'import json,sys
d = json.load(sys.stdin)
print("mediaType :", d["mediaType"])
print("manifests :", len(d["manifests"]))
arm = [m for m in d["manifests"] if m.get("platform",{}).get("architecture") == "arm64"][0]
print("arm64     :", arm["digest"])'
```

<!-- gate @machine -->

```
mediaType : application/vnd.oci.image.index.v1+json
manifests : 16
arm64     : sha256:…
```

ترويسةٌ واحدة (`Authorization: Bearer`)، ورابطٌ واحد، وعاد **نفس الشكل بعينه**
الذي فككتَه من `docker save` في الإقليم ٠٩، وقرأته من مخزن `containerd` في
الإقليم ٢٦: فهرسٌ بستّة عشر مدخلاً، وثمانيةٌ منها معماريّاتٌ حقيقية.

**السجلّ لا يترجم شيئاً.** الملفّ الذي يصلك بايتاً بايتاً هو نفسه الذي يخزَّن
على قرصك، بلا أي معالجةٍ بينهما.

## البلوب: بصمةٌ تتحقّق من نفسها عبر السلك

<!-- host -->

```sh
TOKEN=$(curl -s "https://auth.docker.io/token?service=registry.docker.io&scope=repository:library/alpine:pull" \
	| python3 -c 'import json,sys; print(json.load(sys.stdin)["token"])')
D=sha256:3f26bc2dec0b515f1c2818f6e13a8f1da1f88179a008445d4e587233386bff78
curl -sL -H "Authorization: Bearer $TOKEN" -o /tmp/blob30 \
	"https://registry-1.docker.io/v2/library/alpine/blobs/$D"
echo "downloaded : $(stat -f%z /tmp/blob30 2>/dev/null || stat -c%s /tmp/blob30) bytes"
echo "sha256     : sha256:$(shasum -a 256 /tmp/blob30 | cut -d' ' -f1)"
echo "requested  : $D"
rm -f /tmp/blob30
```

<!-- out -->

```
downloaded : 4092319 bytes
sha256     : sha256:3f26bc2dec0b515f1c2818f6e13a8f1da1f88179a008445d4e587233386bff78
requested  : sha256:3f26bc2dec0b515f1c2818f6e13a8f1da1f88179a008445d4e587233386bff78
```

اقرأ البصمة التي طلبتَها — **هي نفسها طبقة `alpine:3.20` الأولى** التي بنيتَ
عليها صورتك في الإقليم ٠٩ (`3f26bc2d…`). أعدتَ سحبها الآن بـ`curl` وحده، وسطر
واحدٍ يتحقّق: البصمة التي حسبتَها من البايتات الواصلة **مطابقةٌ حرفياً** لِما
طلبتَه في الرابط.

**والمكسب:** هذا ليس تصادفاً؛ هو معنى «الاسم بصمةُ المحتوى» (الإقليم ٠٩)
مطبَّقاً على الشبكة لا على القرص. فلا حاجة لشهادة SSL وحدها لتثق بما وصلك — لو
تلاعب أي وسيطٍ ببايتٍ واحد لفشلت هذه المطابقة، بصرف النظر عن القناة.

## والرفع: `PUT` ثلاث مرّات

قبل الرفع، سجلٌّ محليّ بلا مصادقة — حتى لا تحتاج حساباً على أي خدمة:

<!-- host-setup -->

```sh
docker rm -f reg30 > /dev/null 2>&1
docker run -d --name reg30 -p 5555:5000 registry:2 > /dev/null
sleep 2
mkdir -p .lab/push30 && cd .lab/push30
printf 'hello from region 30\n' > layer.txt
tar --numeric-owner --owner=0 --group=0 -czf layer.tar.gz layer.txt
```

هذه الخطوة تحتاج منفذاً على جهازك (`5555`)، فبقيّة الإقليم تعمل خارج
المختبر مباشرة. إن كان المنفذ مشغولاً غيّر الرقم في كل الأسطر التالية.

**الاعتقاد، صريحاً:** الطبقة بصمتان — واحدةٌ في `manifest.json` (الأرشيف كما
هو) وأخرى `diff_id` في `config.json` (نفس الأرشيف بعد فكّه) — **ويجب أن
تتطابقا**، لأنهما «نفس الطبقة».

<!-- host -->

```sh
cd .lab/push30
LAYER_DIGEST="sha256:$(shasum -a 256 layer.tar.gz | cut -d' ' -f1)"
LAYER_SIZE=$(stat -f%z layer.tar.gz 2>/dev/null || stat -c%s layer.tar.gz)

cat > config.json <<EOF
{"architecture":"arm64","os":"linux","config":{"Cmd":["/bin/sh"]},"rootfs":{"type":"layers","diff_ids":["$LAYER_DIGEST"]}}
EOF
CONFIG_DIGEST="sha256:$(shasum -a 256 config.json | cut -d' ' -f1)"
CONFIG_SIZE=$(stat -f%z config.json 2>/dev/null || stat -c%s config.json)

LOC=$(curl -s -D - -o /dev/null -X POST "http://localhost:5555/v2/manual/blobs/uploads/" \
	| grep -i '^location' | tr -d '\r' | cut -d' ' -f2)
SEP="&"; [[ "$LOC" == *"?"* ]] || SEP="?"
curl -s -o /dev/null -w "layer  : http %{http_code}\n" -X PUT \
	-H "Content-Type: application/octet-stream" --data-binary @layer.tar.gz "${LOC}${SEP}digest=${LAYER_DIGEST}"

LOC=$(curl -s -D - -o /dev/null -X POST "http://localhost:5555/v2/manual/blobs/uploads/" \
	| grep -i '^location' | tr -d '\r' | cut -d' ' -f2)
SEP="&"; [[ "$LOC" == *"?"* ]] || SEP="?"
curl -s -o /dev/null -w "config : http %{http_code}\n" -X PUT \
	-H "Content-Type: application/octet-stream" --data-binary @config.json "${LOC}${SEP}digest=${CONFIG_DIGEST}"

cat > manifest.json <<EOF
{"schemaVersion":2,"mediaType":"application/vnd.oci.image.manifest.v1+json","config":{"mediaType":"application/vnd.oci.image.config.v1+json","digest":"$CONFIG_DIGEST","size":$CONFIG_SIZE},"layers":[{"mediaType":"application/vnd.oci.image.layer.v1.tar+gzip","digest":"$LAYER_DIGEST","size":$LAYER_SIZE}]}
EOF
curl -s -o /dev/null -w "manifest: http %{http_code}\n" -X PUT \
	-H "Content-Type: application/vnd.oci.image.manifest.v1+json" \
	--data-binary @manifest.json "http://localhost:5555/v2/manual/manifests/broken"

docker rmi -f localhost:5555/manual:broken > /dev/null 2>&1
docker pull localhost:5555/manual:broken 2>&1 | tail -1
```

<!-- gate -->

```
layer  : http 201
config : http 201
manifest: http 201
wrong diff id "sha256:…" calculated on extraction "sha256:…", desc "sha256:…"
```

ثلاث عملياتٍ نجحت، والسحب فشل. **البصمتان لا تتطابقان أبداً بالتصميم**:
`digest` بصمةُ الأرشيف **المضغوط** كما ينتقل على السلك، و`diff_id` بصمةُ
الأرشيف **بعد فكّ الضغط** — وهذا ما قسته بالضبط في الإقليم ٠٩ حين استخرجتَ
`gunzip -c | sha256sum` وقارنتَه بحقل `diff_ids`.

```
layer.tar.gz على السلك                فكّ الضغط
────────────────────────    gunzip    ─────────────────
sha256 = digest في manifest  ───────►  sha256 = diff_id في config
   (ما وضعتَه أعلاه خطأً)              (ما كان يجب أن تضعه)
```

<!-- host -->

```sh
cd .lab/push30
DIFF_ID="sha256:$(gunzip -c layer.tar.gz | shasum -a 256 | cut -d' ' -f1)"
cat > config.json <<EOF
{"architecture":"arm64","os":"linux","config":{"Cmd":["/bin/sh"]},"rootfs":{"type":"layers","diff_ids":["$DIFF_ID"]}}
EOF
CONFIG_DIGEST="sha256:$(shasum -a 256 config.json | cut -d' ' -f1)"
CONFIG_SIZE=$(stat -f%z config.json 2>/dev/null || stat -c%s config.json)
LAYER_DIGEST="sha256:$(shasum -a 256 layer.tar.gz | cut -d' ' -f1)"
LAYER_SIZE=$(stat -f%z layer.tar.gz 2>/dev/null || stat -c%s layer.tar.gz)

LOC=$(curl -s -D - -o /dev/null -X POST "http://localhost:5555/v2/manual/blobs/uploads/" \
	| grep -i '^location' | tr -d '\r' | cut -d' ' -f2)
SEP="&"; [[ "$LOC" == *"?"* ]] || SEP="?"
curl -s -o /dev/null -w "config   : http %{http_code}\n" -X PUT \
	-H "Content-Type: application/octet-stream" --data-binary @config.json "${LOC}${SEP}digest=${CONFIG_DIGEST}"

cat > manifest.json <<EOF
{"schemaVersion":2,"mediaType":"application/vnd.oci.image.manifest.v1+json","config":{"mediaType":"application/vnd.oci.image.config.v1+json","digest":"$CONFIG_DIGEST","size":$CONFIG_SIZE},"layers":[{"mediaType":"application/vnd.oci.image.layer.v1.tar+gzip","digest":"$LAYER_DIGEST","size":$LAYER_SIZE}]}
EOF
curl -s -o /dev/null -w "manifest : http %{http_code}\n" -X PUT \
	-H "Content-Type: application/vnd.oci.image.manifest.v1+json" \
	--data-binary @manifest.json "http://localhost:5555/v2/manual/manifests/fixed"

docker rmi -f localhost:5555/manual:fixed > /dev/null 2>&1
docker pull localhost:5555/manual:fixed 2>&1 | tail -2 | head -1
docker create --name m30 localhost:5555/manual:fixed true > /dev/null
docker export m30 | tar xO layer.txt
docker rm m30 > /dev/null
```

<!-- gate -->

```
config   : http 201
manifest : http 201
Status: Downloaded newer image for localhost:5555/manual:fixed
hello from region 30
```

**سطرُ نصٍّ كتبتَه أنت، عاد من Docker حقيقيّ، بعد ثلاثة طلبات `PUT` بـ`curl`
لا أكثر.** لم تلمس `docker push`، ولم يتدخّل أي شيء بينك وبين السجلّ سوى
بروتوكول HTTP.

**والمكسب:** `docker push` نفسها تفعل هذا التسلسل بعينه — ترفع كل بلوبٍ لم
يكن موجوداً (وتتحقّق بـ`HEAD` قبل أن ترفع، توفيراً)، ثم ترفع المانفست أخيراً
لأنه المدخل الوحيد الذي يجعل الصورة **قابلةً للسحب باسمها**؛ قبل ذلك هي
بلوباتٌ يتيمة لا تشير إليها وسمٌ ولا فهرس.

<!-- host-setup -->

```sh
docker rmi -f localhost:5555/manual:broken localhost:5555/manual:fixed > /dev/null 2>&1
docker rm -f reg30 > /dev/null
cd ../.. && rm -rf .lab/push30
```

## التمرين — اثنان، ولا حلول

**١.** اطلب رمزاً بنطاقٍ (`scope`) خاطئ الاسم — مستودعٍ لا وجود له — واقرأ رمز
الاستجابة ونصّها. **معيار القبول:** جوابٌ عن الفرق بين ما يحدث هنا وما يحدث حين
تطلب `push` بلا اسم مستخدم، وسطرٌ يفسّره بحقل واحد في جسم الرمز نفسه.

**٢ (الأصعب).** ارفع صورةً بطبقتين متتاليتين (أنشئ الثانية فوق الأولى كما في
الإقليم ٠٩)، بلا أن تستعمل أي أداة غير `curl`. **معيار القبول:** الصورة تُسحَب
وتعمل، وسطرٌ يقول أي حقلٍ في `config.json` كان عليك أن تُصلحه بين الطبقتين —
مسنداً إلى ما تعلّمتَه عن `diff_ids` كقائمةٍ **مرتَّبة**.

## الخلاصة — أين نحن في الشجرة

| ما عرفتَه | العقدة التي يتعلّق بها |
|---|---|
| الرمز نطاقٌ لمستودعٍ ولفعلٍ بعينهما | لا حساب للسحب العامّ · حساب واجبٌ للرفع أو الخاصّ |
| المانفست نفس الفهرس حرفياً عبر السلك | لا ترجمة بين ما ينتقل وما يُخزَّن |
| البلوب يتحقّق من نفسه بالبصمة | الشبكة موثوقةٌ بالمحتوى لا بالقناة وحدها |
| `digest` للمضغوط، `diff_id` للمفكوك | نفس درس الإقليم ٠٩، مطبَّقاً على الرفع لا القراءة |
| المانفست هو ما يجعل البلوبات صورة | قبله بياناتٌ يتيمة لا يُسحَب باسمها شيء |

> **البذرة:** رفعتَ صورةً بيدك، بطبقةٍ واحدةٍ ونصّ بلا معنى. أمّا الصورة التي
> يبنيها `docker build` فمن أين تأتي طبقاتها بالضبط؟ وما الذي يقرّر أن تعديلاً
> واحداً في Dockerfile يعيد بناء نصفَ الصورة بينما يترك النصف الآخر كما هو؟
>
> الإقليم القادم يفتح البنّاء نفسه.
