# الإقليم ٠٦ — `user`: الجذر الذي ليس جذراً

> منذ الإقليم الأوّل و`box` يحمل ثغرةً معلَنة: خمسة أعلامٍ في `clone`، وليس
> فيها `CLONE_NEWUSER`. فجذر `box` هو جذرك — بالرقم صفر نفسه، على الملفّات
> المشتركة نفسها. هذا الإقليم يسدّها، ويكشف أن السدّ **أثقل ممّا يبدو**: إضافة
> نطاقٍ واحد تكسر ترتيباً كان يعمل صدفةً، وتمنع شيئاً لا يعوَّض عنه إلا بحيلة.

---

## الخريطة بين الفضاءين

<!-- lab -->

```sh
unshare --user id
unshare --user --map-root-user id
```

<!-- out -->

```
uid=65534(nobody) gid=65534(nogroup) groups=65534(nogroup)
uid=0(root) gid=0(root) groups=0(root)
```

بلا خريطة، الفضاء الجديد لا يعرف من أنت: **`65534` عدد الفيضان** — القيمة التي
تعرضها النواة حين لا يوجد سطرٌ يترجم رقمك. وبخريطةٍ صريحة تصير `0`.

<!-- lab -->

```sh
unshare --user --map-root-user cat /proc/self/uid_map
```

<!-- out @machine -->

```
         0          0          1
```

سطرٌ واحد، وثلاثة أعداد: **الرقم داخل النطاق، ومقابله خارجه، وطول المدى.** هنا
`0 → 0` لأنك بالفعل جذر. الفصل التالي يريها أثقل معنًى.

## غير جذر، ويصير جذراً بلا إذن أحد

<!-- setup -->

```sh
useradd -u 1000 -m -s /bin/sh alice
```

<!-- lab -->

```sh
runuser -u alice -- sh -c 'id; unshare --user --map-root-user sh -c "id"'
```

<!-- gate -->

```
uid=1000(alice) gid=1000(alice) groups=1000(alice)
uid=0(root) gid=0(root) groups=0(root)
```

> **توقّع قبل أن تشغّل:** `alice` مستخدمةٌ عاديّة، بلا `sudo` وبلا أي قدرة. هل
> تستطيع أن تصير جذراً في نطاقها الخاصّ **بلا أن يمنحها أحد صلاحية**؟

**نعم.** `CLONE_NEWUSER` **الاستثناء الوحيد بين النطاقات السبعة**: كل البقيّة
تحتاج `CAP_SYS_ADMIN` لتُنشأ، وهذا وحده لا يحتاجها — لأن من ينشئه **يمنح نفسه**
الصلاحية بداخله فقط، ولا يأخذ من أحد شيئاً. وهذا بالضبط ما يجعل الحاويات
اللاجذرية (rootless) ممكنة: `podman` العاديّ يفعل هذا حرفياً قبل أي شيءٍ آخر.

**و`/etc/subuid` هو أين تأتي مدايات أوسع من واحد:**

<!-- lab -->

```sh
grep alice /etc/subuid /etc/subgid
```

<!-- out -->

```
/etc/subuid:alice:100000:65536
/etc/subgid:alice:100000:65536
```

نطاقٌ من ٦٥٥٣٦ رقماً حجزه النظام لـ`alice` وحدها، لا يتقاطع مع مستخدمٍ آخر.
ومنه تُبنى خريطةٌ أوسع من سطر: `0` داخلاً يُخرَّط لـ`1000` (هي نفسها)، والأرقام
`1..999` تُخرَّط للمدى `100000..100998` — فيصير لديها **عدّة "مستخدمين" وهميين
تتحكّم بهم كلّهم، دون أن يملك أيٌّ منهم شيئاً حقيقياً خارج نطاقها.** هذا هو أساس
أن حاويةً لاجذرية تشغّل عمليةً بـ`UID=33` (`www-data`) داخلها بأمان — الإقليم
٢٩ يبني عليه كاملاً.

## القدرة داخل النطاق، لا خارجه

جذرٌ زائف — فماذا يملك بالضبط؟

<!-- setup -->

```sh
mkdir -p /root/secret && echo سرّ > /root/secret/f && chmod 700 /root/secret
```

<!-- lab -->

```sh
cat > /tmp/t.sh <<'SH'
unshare --user --map-root-user --mount sh -c '
	echo "أنا: $(id -u)"
	cat /root/secret/f 2>&1
	mkdir -p /tmp/mnt && mount -t tmpfs t /tmp/mnt 2>&1 && echo "mount نجح"
'
SH
runuser -u alice -- sh /tmp/t.sh
```

<!-- gate -->

```
أنا: 0
cat: /root/secret/f: Permission denied
mount نجح
```

> **توقّع قبل أن تشغّل:** `id` تقول ٠. أمامها محاولتان — قراءة ملفٍّ يملكه
> الجذر الحقيقيّ، وتشغيل `mount` (عمليةٌ تحتاج عادةً `CAP_SYS_ADMIN`). **كم
> منهما ستنجح؟**

**واحدةٌ فقط، والمفاجأة أيّتهما.** قراءة ملفّ الجذر **فشلت** — لأن الملفّ يملكه
الجذر **الحقيقيّ** خارج أي نطاق، والفحص يقارن هويّتك الحقيقية (`alice`، لا
تفويض لها) لا هويّتك المعروضة. ومحاولة `mount` **نجحت** — لأن `--mount` معها
أنشأ نطاق جبلٍ **جديداً تملكه هي**، ونطاقُ مستخدمين يمنح `CAP_SYS_ADMIN` الكامل
على **كل مصدرٍ ينشئه هو نفسه**، لا على ما سبقه.

```
  ما تملكه بعد unshare --user --map-root-user
  ─────────────────────────────────────────────

  ملفّاتٌ خُلقت قبل النطاق  ───► تُفحَص بهويّتك الحقيقية   (مرفوضة غالباً)
  نطاقاتٌ أنشأتها معه       ───► أنت جذرها الكامل          (كل شيء مباح)
```

**القاعدة الحاكمة إذاً ليست «هل أنا جذر؟» بل «من يملك هذا المورد؟»** — وهي
نفسها التي ستحكم كل نطاقٍ سترى امتيازه لاحقاً (الحزمة الخامسة كاملة).

## ولهذا `box` بلا `CLONE_NEWUSER` تعطَّل من أوّل سطرٍ فيها

أضِف العلَم إلى `box`، وشغّله دون أن تلمس شيئاً آخر:

<!-- part: 06-userbox.c -->

```c
	int p = clone(child, sp + STACK,
	              CLONE_NEWNS | CLONE_NEWPID | CLONE_NEWUTS |
	              CLONE_NEWIPC | CLONE_NEWNET | CLONE_NEWUSER | SIGCHLD, &j);
```

<!-- lab -->

```sh
#! rc: 1
sed 's/CLONE_NEWNET |/CLONE_NEWNET | CLONE_NEWUSER |/' programs/01-box.c > /tmp/broken.c
cc -std=c17 -o /tmp/broken /tmp/broken.c
/tmp/broken work/rootfs /bin/true
```

<!-- gate -->

```
mount proc: Operation not permitted
```

> **توقّع:** أضفتَ علَماً واحداً فقط، بلا تغيير ترتيب أي سطر. `box` عمل بلا
> شكوى في الإقليم الأوّل. **هل يعمل الآن؟**

**لا.** والسطر الذي يفشل ليس `mount /` ولا `pivot_root` ولا `mknod` —
**`mount("proc", "/proc", …)` بعد `pivot_root` بالذات.** ترتيبٌ كان بلا أهمّية
حين كنتَ جذراً حقيقياً صار حرجاً الآن: مساحة العناوين التي بُدِّل إليها الجذر
لحظة `pivot_root` تتبع مِلكيّتها **للنطاق القديم**، وحتى تُثبَّت خريطة
المستخدمين وتُقفَل شجرة الجذر الجديدة، مونتُ `proc` **بعد** التبديل يقع خارج
ما تملكه.

**والحلّ نقل سطرٍ واحد**: مونت `proc` **قبل** `pivot_root`، على مسار الجذر
الجديد مباشرةً بدل `/proc`:

<!-- part: 06-userbox.c -->

```c
	must(mount(j->root, j->root, NULL, MS_BIND | MS_REC, NULL), "bind");
	must(mount("proc", path, "proc", 0, NULL), "mount proc");
	…
	must(syscall(SYS_pivot_root, ".", "."), "pivot_root");
```

## والعلّة الثانية: `mknod` لا تعمل مطلقاً هنا

حتى بعد إصلاح `proc`، السطر التالي في `box` — صنع `/dev/null` — **يفشل
دائماً**، بلا علاقة بالترتيب:

<!-- lab -->

```sh
unshare --user --map-root-user --mount sh -c '
	mkdir -p /tmp/d && mount -t tmpfs t /tmp/d
	mknod /tmp/d/null c 1 3 2>/dev/null; echo رمز: $?
'
```

<!-- out -->

```
رمز: 1
```

**قيدٌ صريح في النواة، لا عيبٌ في الأذونات.** إنشاء ملفّ جهازٍ خاصّ
(char/block) **ممنوعٌ في أي نطاق مستخدمين غير الأصليّ**، مهما كانت الأذونات
ومهما كانت الملكية — لأن جهازاً برقمي `1,3` قد يشير عند نظامٍ آخر إلى قرصٍ
حقيقيّ، ولو سُمح بصنعه هنا لصار طريقاً للوصول إلى عتادٍ لا يملكه صاحب النطاق.

**والبديل الذي يستعمله كل عازلٍ لاجذريّ**: لا تصنع الجهاز، **اربطه** من جهاز
المضيف الحقيقيّ:

<!-- part: 06-userbox.c -->

```c
static void dev(const char *root, const char *name)
{
	char host[64], guest[256];

	snprintf(host, sizeof host, "/dev/%s", name);
	snprintf(guest, sizeof guest, "%s/dev/%s", root, name);
	must(open(guest, O_CREAT | O_WRONLY, 0666), guest);
	must(mount(host, guest, NULL, MS_BIND, NULL), guest);
}
```

ملفٌّ عاديّ فارغ يُصنَع أوّلاً كـ«مقبض»، ثم يُربَط عليه الجهاز الحقيقيّ —
`MS_BIND` لا تصنع شيئاً جديداً، تُظهر موجوداً في مكانٍ آخر.

## `userbox`: `box` وقد أُصلح، يعمل بلا صلاحيةٍ من الأساس

<!-- lab -->

```sh
cc -std=c17 -Wall -Wextra -o /tmp/userbox programs/06-userbox.c
cp -a work/rootfs /tmp/urootfs && chown -R alice /tmp/urootfs
chown alice /tmp/userbox
runuser -u alice -- /tmp/userbox /tmp/urootfs /bin/sh -c 'id; hostname; ls /dev'
```

<!-- out -->

```
uid=0(root) gid=0(root) groups=0(root)
box
null
urandom
zero
```

**`alice` — بلا `sudo`، بلا قدرةٍ واحدة زائدة عمّا يملكه أي مستخدمٍ عاديّ —
شغّلت عازلاً كاملاً**: جذرٌ خاصّ، اسم مضيفٍ خاصّ، `/dev` يعمل. هذا بالضبط ما
يفعله `podman` حين تشغّله بلا `sudo` أوّل مرّة، مصغّراً إلى تسعين سطراً تراها
كلَّها.

## التمرين — اثنان، ولا حلول

**١.** أضِف `CLONE_NEWCGROUP` إلى `userbox` وحاول كتابة `pids.max` كما فعل
`box` الأصليّ. **معيار القبول:** سطرٌ يقول أين فشل بالضبط ولماذا — لن ينجح
بلا تعديلٍ إضافيّ، والفشل نفسه هو التمرين.

**٢ (الأصعب).** ابنِ خريطةً بمدايين — `0→1000` (نفسك) و`1..999→100000..100998`
(من `subuid`) — وشغّل داخلها عمليتين بمعرّفين مختلفين (`su` أو `setuid` يدويّ)
تكتب كلٌّ منهما ملفّاً. **معيار القبول:** إثباتٌ أن الملفّين مملوكان لرقمين
مختلفين داخل النطاق، ولنفس المستخدم الحقيقيّ (`alice`) خارجه.

## الخلاصة — أين نحن في الشجرة

| ما عرفتَه | العقدة التي يتعلّق بها |
|---|---|
| `CLONE_NEWUSER` وحده لا يحتاج قدرة | فسّر كيف تنشئ `alice` نطاقاً بلا `sudo` |
| والقدرة تتبع **من أنشأ المورد** لا هويّتك المعروضة | حسم لغز قراءة/mount المتناقض |
| وترتيب `mount(proc)` صار حَرِجاً | أُصلح `box` بنقل سطرٍ واحد |
| و`mknod` ممنوعةٌ جذرياً هنا | استُبدلت بـ`MS_BIND` من جهاز المضيف |

> **البذرة:** ستّة نطاقاتٍ عزلَت **ما تراه العملية**، وواحدٌ عزل **من تكون**.
> بعدها في هذا المنهج يقف نطاقان آخران يعزلان شيئاً مختلفاً تماماً: ليس ما
> تراه العملية ولا من تكون، بل **ما يستطيع اثنتان منها أن تتقاسماه معاً بقرارٍ
> صريح** — لا بالخطأ.
>
> الإقليم القادم يفتح التقاسم، ويدفن فيه نموذج «الصندوق» نهائياً.
