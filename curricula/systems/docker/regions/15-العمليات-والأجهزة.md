# الإقليم ١٥ — العمليات والأجهزة

> بقي في حزمة الحدّ موردان لا يشبهان ما سبق.
>
> الأوّل **العمليات**: لا يُبطِئ تجاوزُه ولا يقتل — يجعل `fork` يفشل، فتعجز
> النواة عن تشغيل ما ينقذها. والثاني **الأجهزة**: الملفّ الذي كنت تكتب فيه
> قواعدها لم يعد موجوداً في `cgroup v2` أصلاً، والمنع قائم. فأين ذهب؟

---

## `pids.max`: حدٌّ لا يقتل ولا يُبطئ

البرنامج `programs/15-fork.c` يتفرّع حتى يُمنَع، ثم يقول عند أي رقمٍ مُنِع:

<!-- part: 15-fork.c -->

```c
		if (p < 0) {
			printf("fork #%d failed: %s\n", n + 1, strerror(errno));
```

ضع السقف عند عشرين، وشغّله. **ثم — وهذا هو السؤال — حاول أن تشغّل `ls`.**

<!-- setup -->

```sh
gcc -O0 -o /tmp/fork programs/15-fork.c
mkdir -p /sys/fs/cgroup/p1
```

<!-- lab -->

```sh
echo 20 > /sys/fs/cgroup/p1/pids.max
sh -c 'echo $$ > /sys/fs/cgroup/p1/cgroup.procs; exec /tmp/fork'
echo "pids.current : $(cat /sys/fs/cgroup/p1/pids.current)"
echo "pids.events  : $(cat /sys/fs/cgroup/p1/pids.events | tr '\n' ' ')"
sh -c 'echo $$ > /sys/fs/cgroup/p1/cgroup.procs; ls / > /dev/null' 2>&1 | head -1
echo 1 > /sys/fs/cgroup/p1/cgroup.kill
```

<!-- gate -->

```
fork #20 failed: Resource temporarily unavailable
pids.current : 19
pids.events  : max 1 
sh: 1: Cannot fork
```

لم يمت أحد ولم يبطؤ شيء. `fork` أعاد `EAGAIN` — وهو الخطأ نفسه الذي يعيده حين
تمتلئ جداول النواة، فلا يفرّق برنامجك بين الحالتين.

**والسطر الأخير هو الدرس:** الصدفة التي دخلت المجموعة بعد ذلك **بريئة تماماً**،
ولم تستطع تشغيل `ls`. فحدُّ العمليات يصيب من يأتي بعده، لا من استهلكه. ولو كان
الذي يأتي بعده مراقبك أو صدفتك التي تريد أن تُصلح بها، لعجز أيضاً.

**والمكسب:** هذا هو الحدُّ الوحيد في الحزمة الذي **يمنع الإنقاذ**. ولذلك تُضبَط
حدود العمليات دائماً بهامشٍ فوق الحاجة لا عندها.

> والافتراض عند الأداة `max` — أي **بلا حدّ**. فقنبلةُ `fork` في حاويةٍ عاديّة
> تُسقِط جهازك كلَّه لا حاويتك، ما لم تكتب `--pids-limit`.

## الأجهزة: المتحكّم الذي ليس هناك

انتقل إلى المورد الثاني. الحاوية العاديّة تملك `CAP_MKNOD` — تستطيع أن تصنع عقدة
جهاز. **فاصنع عقدةً لقرص جهازك، ثم اقرأ منه.**

<!-- host-setup -->

```sh
DEV=$(docker run --rm --privileged t3lm-docker-lab \
	sh -c "lsblk -dn -o MAJ:MIN,SIZE,TYPE | awk '\$3 == \"disk\" && \$2 != \"0B\" {print \$1; exit}'")
echo "$DEV" > .lab/disk-dev
```

<!-- host -->

```sh
DEV=$(cat .lab/disk-dev); MAJ=${DEV%:*}; MIN=${DEV#*:}
docker run --rm alpine:3.20 sh -c "
	mknod /tmp/d b $MAJ $MIN && echo 'mknod on the disk : ok'
	dd if=/tmp/d of=/dev/null bs=512 count=1 2>/dev/null \
		&& echo 'open the disk     : ok' || echo 'open the disk     : denied'
	mknod /tmp/z c 1 5
	dd if=/tmp/z of=/dev/null bs=512 count=1 2>/dev/null \
		&& echo 'open /dev/zero    : ok' || echo 'open /dev/zero    : denied'"
```

<!-- gate -->

```
mknod on the disk : ok
open the disk     : denied
open /dev/zero    : ok
```

ثلاثة أسطر، وفيها الجواب كلُّه: **صنعُ العقدة نجح، وفتحُها مُنِع.** وعقدةٌ
أخرى — `/dev/zero`، وهي `c 1 5` — صُنِعت وفُتِحت بلا اعتراض.

فالمنع ليس على `mknod`، ولا على الأذونات (العقدتان صُنِعتا بنفس المستخدم ونفس
الوضع)، ولا على المسار. المنع **على زوج الأرقام نفسه**، وموضعُه نداء `open`.

## وسطرٌ واحد يرفعه

القاعدة إذن تُكتَب في مكانٍ ما، وتُقرأ عند الفتح. والأداة تفتح لك بابها بعَلَم:

<!-- host -->

```sh
DEV=$(cat .lab/disk-dev); MAJ=${DEV%:*}; MIN=${DEV#*:}
r() {
	docker run --rm "$@" alpine:3.20 sh -c \
		"mknod /tmp/d b $MAJ $MIN && dd if=/tmp/d of=/dev/null bs=512 count=1 2>/dev/null \
		 && echo 'read 512 bytes off your disk' || echo 'open denied'"
}
echo "no rule : $(r)"
echo "+ rule  : $(r --device-cgroup-rule "b $DEV r")"
```

<!-- gate -->

```
no rule : open denied
+ rule  : read 512 bytes off your disk
```

نفسُ الأمر، ونفسُ العقدة، ونفسُ المستخدم — وعَلَمٌ واحد قلب الجواب. **فعقدة
الجهاز اسمٌ لا إذن**: زوجُ أرقامٍ في inode (الإقليم ٠١)، وصنعُها لا يمنح شيئاً.

و`--device-cgroup-rule` أعطى حاويةً عاديّة قراءةَ قرصك الخام — بجدول أقسامه،
وبكل ما عليه، ومن تحت أي نظام ملفّاتٍ وأي أذونات.

**والمكسب:** حين تقرأ `--device` أو `--device-cgroup-rule` في ملفّ تركيبٍ لا
تكتبه أنت، فأنت تقرأ منحَ وصولٍ إلى عتادٍ لا يمرّ على أي أذوناتٍ تعرفها.

## فأين القاعدة مكتوبة؟

في `cgroup v1` كان الجواب ملفّاً: `devices.allow` و`devices.deny`. **ابحث عنه
في v2.**

<!-- host-setup -->

```sh
docker rm -f d15 > /dev/null 2>&1
docker run -d --name d15 alpine:3.20 sleep 300 > /dev/null
```

<!-- host -->

```sh
ID=$(docker inspect -f '{{.Id}}' d15)
docker run --rm --privileged -v /sys/fs/cgroup:/hostcg -e ID="$ID" t3lm-docker-lab sh -c '
	echo "controllers    : $(cat /hostcg/cgroup.controllers)"
	echo "devices* files : $(find /hostcg -name "devices*" | wc -l)"
	P=$(find /hostcg -type d -name "*$ID*" | head -1)
	bpftool cgroup show "$P" | tail -n +2 | awk "{print \"attached       : \" \$2}"'
```

<!-- out -->

```
controllers    : cpuset cpu io memory hugetlb pids rdma
devices* files : 0
attached       : cgroup_device
```

لا `devices` في قائمة المتحكّمات، ولا ملفٌّ واحد باسمه في الشجرة كلِّها. ومع
ذلك مُنِعتَ.

**لأن الأجهزة في v2 ليست متحكّماً؛ هي برنامج eBPF مُعلَّقٌ على المجموعة.** والنواة
تستدعيه عند كل فتحِ عقدةِ جهاز، فيعيد `1` أو `0`. والقاعدة التي كنت تكتبها سطراً
صارت **فروعاً في كود**:

<!-- host -->

```sh
ID=$(docker inspect -f '{{.Id}}' d15)
docker run --rm --privileged -v /sys/fs/cgroup:/hostcg -e ID="$ID" t3lm-docker-lab sh -c '
	P=$(find /hostcg -type d -name "*$ID*" | head -1)
	N=$(bpftool cgroup show "$P" | tail -n +2 | awk "{print \$1}")
	bpftool prog dump xlated id $N | head -12'
docker rm -f d15 > /dev/null
```

<!-- runs -->

```
   0: (61) r2 = *(u32 *)(r1 +0)
   1: (54) w2 &= 65535
   2: (61) r3 = *(u32 *)(r1 +0)
   3: (74) w3 >>= 16
   4: (61) r4 = *(u32 *)(r1 +4)
   5: (61) r5 = *(u32 *)(r1 +8)
   6: (55) if r2 != 0x1 goto pc+5
   7: (bc) w1 = w3
   8: (54) w1 &= 1
   9: (5d) if r1 != r3 goto pc+2
  10: (b4) w0 = 1
  11: (95) exit
```

اقرأ السطور الستّة الأولى: نوعُ الجهاز، والرقم الأكبر، والرقم الأصغر، والوصول
المطلوب — مستخرجةً من بنيةٍ مرّرتها النواة. ثم تبدأ الفروع: `if` لكل قاعدةٍ
كتبتْها الأداة، و`w0 = 1` إذناً، والخروجُ بلا إذنٍ منعاً.

**والمكسب أبعد من الأجهزة:** هذا أوّل موضعٍ ترى فيه النواة تُستدعى ببرنامجٍ
حُمِّل فيها وقتَ التشغيل بدل جدولٍ ثابت. والإقليم ١٧ يبني مثله بيدك — مرشّحاً
يقرّر أي نداءِ نظامٍ يُسمَح به.

## التمرين — اثنان، ولا حلول

**١.** اضبط `pids.max` على مجموعةٍ **أب** ثم أنشئ تحتها ابنين بلا حدود، وشغّل
`fork` في أحدهما. **معيار القبول:** جوابٌ عمّا يحدث للابن الثاني، وسطرٌ يقول أين
تُحاسَب العملية — عند مجموعتها وحدها أم عند كل أجدادها — مسنداً إلى
`pids.current` مقروءاً في المستويين.

**٢ (الأصعب).** شغّل حاويةً بـ`--privileged` واقرأ برنامج `cgroup_device`
المعلَّق عليها كما فوق. **معيار القبول:** فرقٌ في `xlated` بالبايت بينها وبين
الحاوية العاديّة، وسطرٌ يفسّر لماذا كان الفرق في ذلك الاتّجاه بالذات.

## الخلاصة — أين نحن في الشجرة

| ما عرفتَه | العقدة التي يتعلّق بها |
|---|---|
| `pids.max` يمنع `fork` بـ`EAGAIN` | حدٌّ لا يُبطئ ولا يقتل · **ويمنع الإنقاذ** |
| الضحية من يأتي بعد الاستهلاك | اضبط بهامشٍ فوق الحاجة · والافتراض `max` أي بلا حدّ |
| عقدة الجهاز اسمٌ لا إذن | `mknod` ينجح و`open` يُمنَع · والقرار عند الفتح |
| لا متحكّم `devices` في v2 | القاعدة برنامج eBPF مُعلَّق، لا ملفّ يُقرأ |

> **البذرة:** انتهت حزمة الحدّ. تعرف الآن **ما ترى** (النطاقات) و**كم تأخذ**
> (الـcgroups). وبقي السؤال الثالث من الفصل صفر: **ما الذي يُسمَح لك أن تطلب.**
>
> وقد لمستَه مرّتين بلا أن تفتحه: في الإقليم ٠٦ حين صرتَ جذراً لا يستطيع
> `mknod`، وقبل قليل حين نجح `mknod` وفشل `open`. فالجذر ليس واحداً — والحزمة
> القادمة تفكّكه إلى أربعين.
