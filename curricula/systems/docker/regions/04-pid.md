# الإقليم ٠٤ — `pid`: الرقم موضعٌ لا صفة

> في الإقليم ٠٢ رأيتَ صدفةً تظنّ نفسها العملية الأولى في النظام، ولها الحقّ.
> هذا الإقليم يفتح ما يترتّب على ذلك الحقّ بالذات: **النواة تعامل صاحب الرقم ١
> معاملةً لا تعامل بها أحداً غيره**، ولا علاقة لهذا بالصلاحيات ولا بالقدرات —
> هذا نطاقُ إشاراتٍ خاصّ، مفروضٌ بمجرّد الرقم.
>
> وفيه يُحسَم سؤالٌ يطرحه كل من شغّل `docker stop` وانتظر: **لماذا لا تموت
> الحاوية من أوّل إشارة؟**

---

## الرقم ١ لا يُقتَل بالطريقة العادية

<!-- lab -->

```sh
sleep 100 &
P=$!
kill -TERM $P
sleep 1
kill -0 $P 2>/dev/null && echo حيّ || echo مات
```

<!-- out -->

```
مات
```

عمليةٌ عادية، برقمٍ عادي، تموت من `SIGTERM` بلا معالج — هذا هو **الافتراض**
لأي إشارةٍ فعلُها الافتراضيّ الإنهاء.

الآن الشيء نفسه، **بلا تغيير سطرٍ واحد في `sleep`**، لكن بعد أن تصير صاحبة
الرقم ١ في نطاقها:

<!-- lab -->

```sh
unshare --pid --fork --mount-proc sleep 100 &
LPID=$!
sleep 0.3
kill -TERM $LPID
sleep 1
kill -0 $LPID 2>/dev/null && echo حيّ || echo مات
kill -KILL $LPID 2>/dev/null; wait 2>/dev/null
```

<!-- gate -->

```
حيّ
```

> **توقّع قبل أن تشغّل:** نفس `sleep`، نفس الإشارة، نفس المدّة. الفرق الوحيد
> أن هذه العملية رقمها ١ في نطاقها. **هل تموت؟**

**لا.** وتأكيدٌ أنه ليس معالجاً خفياً كتبه `sleep`، بل قرار النواة نفسها:

<!-- lab -->

```sh
grep -E 'Name|SigIgn|SigCgt' /proc/$$/status
```

<!-- out @machine -->

```
Name:	sh
SigIgn:	…
SigCgt:	…
```

`SigCgt` (الإشارات الملتقَطة بمعالج) و`SigIgn` (المتجاهَلة صراحةً) — كلاهما
يحمل ما سجّلته الصدفة، **لا شيء يخصّ `SIGTERM` فيه**. ومع ذلك نجت.

### لماذا

النواة تفرض قاعدة: **العملية رقم ١ في أي نطاق pid — لا نطاق النظام الأصليّ
وحده — لا يصلها الفعل الافتراضيّ لإشارةٍ لم تُثبِّت لها معالجاً**. لا `SIGTERM`
ولا `SIGINT` ولا `SIGHUP`. **الاستثناء الوحيد**: `SIGKILL` و`SIGSTOP` تعملان
دائماً، على أي عملية، بلا استثناء ممكن.

```
  إشارةٌ بلا معالج، ووجهتها عمليةٌ عادية:
    الفعل الافتراضي (إنهاء غالباً) ─────────────────► يقع

  الإشارة نفسها، ووجهتها PID 1 في نطاقها:
    الفعل الافتراضي ──────► النواة تعترضه ──────► لا شيء يقع
                                  │
                    (إلا SIGKILL و SIGSTOP: هاتان تتجاوزان الاعتراض)
```

**والسبب تصميميّ لا تعسّفيّ:** PID 1 هو من يُنشئ بقيّة العمليات في نطاقه
ويحصد أيتامها (سترى ذلك بعد قليل). فلو مات بإشارةٍ عابرة — إشارةٍ ربما كانت
موجّهةً لعمليةٍ أخرى وأصابته بالخطأ — **مات النطاق كلُّه معه**، فكل نطاقٍ
يعتمد على بقاء عمليته الأولى بخلاف بقيّة عملياته.

---

## الأيتام: من يحصدهم

اكتب برنامجاً بثلاثة أجيال: **رئيسٌ**، يلد **ابناً وسيطاً** يموت فوراً بلا
انتظار، والابن الوسيط يلد **حفيداً** ينام ثم يسأل من أبوه:

<!-- part: 04-orphan.c -->

```c
	pid_t mid = fork();

	if (mid == 0) {
		pid_t gc = fork();

		if (gc == 0) {
			sleep(1);
			printf("الحفيد استيقظ: أبوه الآن %d\n", getppid());
			return 0;
		}
		printf("الابن الوسيط %d يخرج فوراً، حفيده %d يبقى\n", getpid(), gc);
		return 0;
	}
	printf("أنا PID %d\n", getpid());
	waitpid(mid, NULL, 0);
	sleep(2);
```

<!-- lab -->

```sh
cc -std=c17 -Wall -Wextra -o orphan programs/04-orphan.c
unshare --pid --fork --mount-proc ./orphan
```

<!-- gate -->

```
الابن الوسيط 2 يخرج فوراً، حفيده 3 يبقى
الحفيد استيقظ: أبوه الآن 1
أنا PID 1
```

> **توقّع قبل أن تشغّل:** الابن الوسيط مات، وحفيدُه لا يزال نائماً بلا أبٍ حيّ.
> بعد أن يستيقظ ويسأل `getppid()` — **من سيقول له إنه أبوه؟**

**الرقم ١ نفسه.** حين مات الأب المباشر، أُعيد ربط الحفيد اليتيم **بأقرب سلفٍ
حيّ في شجرة العمليات** — وهذا دائماً PID 1 في نطاقه، لأنه الوحيد الذي يستحيل
أن يموت قبل بقيّة نطاقه (كما رأيتَ للتوّ).

**وهذا التزامٌ لا اختيار.** كل PID 1 — سواءٌ كان `systemd` أو `sh` أو `sleep`
— **يصير راعياً قسرياً لكل عمليةٍ يتيمة في نطاقه**، حتى لو لم يكتب سطراً واحداً
يطلب ذلك.

---

## ومن لا يُنتظَر يبقى في الجدول

الحصد لا يعني الحذف. **`getppid()` تُصحَّح تلقائياً؛ أمّا تفريغ مدخل العملية من
جدول النظام فيحتاج `wait` صريحة.** جرّب PID 1 لا ينتظر شيئاً:

<!-- lab -->

```sh
cc -std=c17 -Wall -Wextra -o zombie programs/04-zombie.c
unshare --pid --fork --mount-proc ./zombie
```

<!-- out @kernel -->

```
  PID  PPID STAT CMD
    1     0 R    ps -o pid,ppid,stat,cmd
    3     1 Z    [zombie] <defunct>
```

**`Z`.** الحفيد اليتيم أُعيد ربطه بـPID 1 كما رأيتَ، **ولم يُحصَد**: البرنامج
انتظر الابن الوسيط وحده (`waitpid(mid, …)`) ولم يستدعِ `wait` مرّةً أخرى
للحفيد. فبقي زومبياً — عمليةٌ ميّتة فعلياً، لا شيء منها إلا سطرٌ في جدول
النظام يحمل رمز خروجها.

**والمكسب:** «PID 1 يحصد أيتامه» عبارةٌ ناقصة. النواة تُعيد **ربطهم** به
تلقائياً — ذلك التزام. أمّا **تفريغهم** فمسؤوليّته هو، بحلقة `wait` صريحة —
وهذا سبب أن كل صورة أساسٍ جادّة (`tini`، أو `dumb-init`) تُشغَّل **بديلاً**
عن أمرك الحقيقيّ، لا مرافقةً له: لتكون هي PID 1 التي تحصد وتُفرِّغ، فيبقى
أمرك عمليةً عادية تموت بإشاراتها الطبيعية.

---

## ولماذا لا تموت الحاوية من أوّل إشارة

الآن اجمع القطعتين: `docker stop` ترسل `SIGTERM`، وPID 1 في الحاوية —
`sleep` هنا، بلا معالج — **تتجاهله بحكم النواة لا باختيارها**:

<!-- host-setup -->

```sh
docker rm -f t3lm_pid 2>/dev/null
docker run -d --name t3lm_pid alpine:3.20 sleep 300
```

<!-- host -->

```sh
S=$(date +%s.%N)
docker stop t3lm_pid >/dev/null
E=$(date +%s.%N)
python3 -c "print(f'استغرق: {$E - $S:.1f}s')"
docker inspect -f 'ExitCode={{.State.ExitCode}}' t3lm_pid
```

<!-- runs @impl -->

```
استغرق: …s
ExitCode=137
```

**١٣٧ مرّةً أخرى** — `SIGKILL`، كما في الفصل صفر. فبعد أن رفضت `SIGTERM` بحكم
كونها PID 1، انتظر المحرّك مهلته الخاصّة ثم أرسل الإشارة التي لا يردّها أحد.

**والمهلة رقمٌ يخصّ هذا المحرّك بهذا الإصدار — وليست عشر ثوانٍ كما يشيع.**
انظر إلى الرقم الذي طبعتَه للتوّ في «استغرق: …s»: هذا زمن انتظار محرّكك، مقاساً
لا منقولاً من ذاكرة أحد. **والمعلَنُ لا المقاس** يمكن ضبطه صراحةً:

<!-- host-setup -->

```sh
docker rm -f t3lm_pid >/dev/null 2>&1
docker run -d --name t3lm_pid2 --stop-timeout 10 alpine:3.20 sleep 300
```

<!-- host -->

```sh
S=$(date +%s.%N)
docker stop t3lm_pid2 >/dev/null
E=$(date +%s.%N)
python3 -c "print(f'استغرق: {$E - $S:.0f}s')"
```

<!-- out @impl -->

```
استغرق: 10s
```

**عشرٌ بالضبط — لأنك طلبتَها.** بلا `--stop-timeout` صريح، المهلة تعود لتقدير
المحرّك، **وتُقاس لا تُذكَر من الذاكرة.**

<!-- host-setup -->

```sh
docker rm -f t3lm_pid2 >/dev/null 2>&1
```

**والدرس الحقيقيّ هنا ليس الرقم.** هو أن كل صورةٍ تعرّف `STOPSIGNAL` غير
`SIGTERM`، أو تشغّل خدمةً تعالج `SIGTERM` بإغلاقٍ نظيف، **تتفادى المهلة كلَّها**
— كما رأيتَ في التجربة الأولى حين أضفتَ `trap` صريحاً. المهلة عقوبةٌ على من
لم يستعدّ، لا ضريبةٌ ثابتة.

## التمرين — ثلاثة، ولا حلول

**١.** عدّل `programs/04-zombie.c` بحيث يحصد حفيده فعلاً قبل أن يخرج (حلقة
`wait` تلتقط `ECHILD`). **معيار القبول:** نفس التجربة، ولا سطر `Z` في المخرَج.

**٢.** أضِف إلى `box.c` معالجاً لـ`SIGTERM` يطبع رسالةً ثم يستدعي `_exit`.
شغّله، وأرسل له `SIGTERM` من نافذةٍ أخرى. **معيار القبول:** يموت فوراً — لأن
تثبيت معالجٍ صريح **يُلغي** الحصانة، حتى لو كان المعالج نفسه لا يفعل شيئاً
سوى الخروج.

**٣ (الأصعب).** اكتب PID 1 مصغّراً بلا Docker: عمليةٌ تُنشئ نطاقاً بـ`clone`،
تلد فيه ابناً يتفرّع مرّتين ويموت الأوسط، ثم تفرغ في حلقة `waitpid(-1, …, 0)`
حتى `ECHILD`. **معيار القبول:** لا زومبي يبقى مهما تشعّبت الأجيال، بلا معرفة
عددها مسبقاً.

---

## الخلاصة — أين نحن في الشجرة

| ما عرفتَه | العقدة التي يتعلّق بها |
|---|---|
| PID 1 محصّنةٌ بحكم النواة | فُسِّرت حياة `box` رغم موت النطاق تحت أقدام عملياتٍ عادية |
| والحصانة تُلغى بمعالجٍ صريح | فسّرت لماذا يموت `t3lm_pid1b` (تمرين ٢) فوراً بلا مهلة |
| والأيتام تُعاد ربطها لا تُحصَد | فسّر وجود `tini`/`dumb-init` كنمطٍ متكرّر لا زخرفة |
| والزومبي يبقى بلا `wait` صريحة | ربطَ بالإقليم ٢٥ في منهج C — نفس القاعدة، سياقٌ آخر |

> **البذرة:** رأيتَ في هذا الإقليم اسم المضيف `box` لا يظهر عند المضيف —
> نطاقٌ منفصل. وثلاثة نطاقاتٍ أخرى أصغر منه حجماً وأقلّ دراميّةً، لكنّ كلاً
> منها يكشف — إذا نُزع وحده — ما الذي كان يخفيه بالضبط.
>
> الإقليم القادم يفتح الثلاثة معاً.
