# الإقليم ٠٢ — النطاق شيءٌ يُملَك

> في `box` بنيتَ خمسة نطاقاتٍ بعَلَمٍ في `clone`، وماتت كلُّها بموت الابن. وهذا
> يكفي لعازلٍ يعمل، ويعجز عن أشياء تراها كل يوم: `docker network` تعيش بلا حاوية،
> و`docker exec` تدخل حاويةً قائمة، وpod في Kubernetes شبكةٌ تُنشأ **قبل** أن يوجد
> فيها شيء.
>
> فالسؤال الذي يفتحها كلَّها: **ما النطاق بالضبط، ومن يملكه، ومتى يموت؟**

---

## النطاق رقمٌ يُقارَن

<!-- lab -->

```sh
readlink /proc/self/ns/net /proc/self/ns/pid /proc/self/ns/mnt
```

<!-- out @machine -->

```
net:[…]
pid:[…]
mnt:[…]
```

**كل نطاقٍ رقمٌ واحد**: inode في نظام ملفّاتٍ داخليّ اسمه `nsfs`، لا يُجبَل في
شجرتك ولا تراه في `df`.

ويترتّب عليه أن سؤال «هل هاتان العمليتان في نفس النطاق؟» **يُجاب بمقارنة رقمين**:

<!-- lab -->

```sh
echo   "أنا:      $(readlink /proc/self/ns/net)"
echo   "وابني:    $(sh -c 'readlink /proc/self/ns/net')"
unshare --net --fork sh -c 'echo "ومن نزعها: $(readlink /proc/self/ns/net)"'
```

<!-- out @machine -->

```
أنا:      net:[…]
وابني:    net:[…]
ومن نزعها: net:[…]
```

الرقمان الأوّلان متطابقان، والثالث مختلف. **والابن يرث نطاقات أبيه** ما لم
يُطلَب غير ذلك — وهذا هو الافتراض في `fork` و`clone` معاً.

---

## الجرد

<!-- lab -->

```sh
lsns -o NS,TYPE,NPROCS,PID -t net -t uts
```

<!-- out @machine -->

```
        NS TYPE NPROCS PID
… uts       …   …
… net       …   …
```

`lsns` تقرأ `/proc/*/ns/*` كلَّها وتجمع المتشابه. **والعمود الثالث هو الذي يهمّ
في هذا الإقليم** — عدد ساكني النطاق. احفظه، فسيصير صفراً بعد قليل.

---

## متى يموت النطاق

**الاعتقاد، صريحاً:** النطاق مكانٌ أنشأتَه، فيبقى حتى تحذفه.

جرّبه. اطلب من `unshare` نطاق عملياتٍ جديداً، **ولا تجعلها تتفرّع** (`--fork`
غائبة عمداً)، ثم شغّل أمرين متتاليين:

<!-- lab -->

```sh
#! rc: 2
#! sort
unshare --pid sh -c 'readlink /proc/self/ns/pid; readlink /proc/self/ns/pid'
```

<!-- gate -->

```
pid:[…]
sh: 1: Cannot fork
```

> **توقّع قبل أن تقرأ:** الأمران متطابقان حرفياً. فلماذا نجح الأوّل وفشل الثاني؟

### الجواب: النطاق عدّاد مراجع

بلا `--fork` تبقى الصدفة نفسها في نطاقها القديم، ويولد **أبناؤها** في الجديد.
فأوّل `readlink` وُلد فيه فصار عمليته الأولى، ثم خرج فمات النطاق تحت قدميه.

```
  ما يمسك النطاق حيّاً                     nsfs
  ────────────────────                    ────

  عمليةٌ فيه          ──┐
                        │              ┌──────────────────┐
  descriptor مفتوح    ──┼─────────────►│ net:[4026532691] │
  على ملفّه            │              │  refcount = 3    │
                        │              └──────────────────┘
  جبلُ bind على ملفّه ──┘                       │
                                               ▼
                                  يبلغ صفراً ⇒ يُحرَّر فوراً
```

**والنطاق ليس مكاناً؛ هو كائنٌ في النواة له عدّاد مراجع.** ولذلك فشل الثاني: حين
حاول أن يتفرّع لم يكن هناك نطاقٌ يولد فيه — النطاق الذي أشار إليه
`pid_for_children` تحرّر مع خروج ساكنه الوحيد.

**والدليل أدقّ من هذا.** انظر إلى الحقلين قبل أن يولد أحد:

<!-- lab -->

```sh
#! rc: 1
unshare --pid readlink -v /proc/self/ns/pid
unshare --pid readlink -v /proc/self/ns/pid_for_children
```

<!-- out @machine -->

```
pid:[…]
readlink: /proc/self/ns/pid_for_children: No such file or directory
```

**حقلان لعمليةٍ واحدة:** `pid` النطاق الذي تسكنه أنت — ولم يتغيّر، فأنت لم
تنتقل. و`pid_for_children` النطاق الذي سيسكنه أبناؤك — **ولا وجود له بعد**، لأن
نطاق العمليات لا يقوم قبل أن تولد عمليته الأولى.

ونطاق العمليات وحده بهذه الحساسية: **موتُ الأولى يقتل النطاق ومن فيه.** والإقليم
٠٤ يريك ما يترتّب على ذلك في حاويةٍ حقيقية.

---

## نطاقٌ يعيش بلا ساكن

عاد بنا هذا إلى العدّاد: **عمليةٌ فيه** واحدٌ من ثلاثة تمسكه. والثاني جبلُ bind
على ملفّ النطاق. وهذا بالضبط ما تفعله `ip netns`:

<!-- lab -->

```sh
ip netns add demo
findmnt -n -o TARGET,SOURCE /run/netns/demo
```

<!-- out -->

```
/run/netns/demo nsfs[net:[…]]
```

**اقرأ السطر مرّتين.** `/run/netns/demo` ملفٌّ فارغ حجمه صفر، ومجبولٌ عليه
`nsfs` — نظام الملفّات الذي تسكنه النطاقات. فالملفّ **مقبضٌ** يمسك النطاق، بلا
بايتٍ واحد فيه.

<!-- lab -->

```sh
lsns -o NS,TYPE,NPROCS -t net | tail -1
```

<!-- gate -->

```
… net       0
```

> **توقّع:** كم عمليةً في هذا النطاق؟

**صفر.** نطاقٌ حيٌّ، له رقم، وله بطاقاته وجدوله وجداره الناريّ، **ولا عمليةَ
واحدة بداخله.**

وهو يعمل:

<!-- lab -->

```sh
ip netns exec demo ip -o -4 addr; echo "(لا عنوان)"
ip -o -4 addr | awk '{print $2, $4}'
```

<!-- out @distro -->

```
(لا عنوان)
lo 127.0.0.1/8
eth0 …
```

الأوّل لا يطبع شيئاً: نطاقٌ نظيف، `lo` فيه معطّلة بلا عنوان. والثاني نطاقك أنت.

**والمكسب هو الحزمة السادسة كلُّها:** الشبكة تُبنى في نطاقٍ فارغ **قبل** أن يوجد
من يستعملها، ثم يُدخَل إليها. ولهذا `docker network create` تنجح بلا حاوية،
ولهذا في الـpod شبكةٌ واحدة تتعاقب عليها الحاويات.

## وهذا بعينه ما يفعله Docker

<!-- host-setup -->

```sh
docker network create t3lmnet >/dev/null
docker run -d --name two --network t3lmnet alpine:3.20 sleep 200
```

<!-- host -->

```sh
docker run --rm --privileged --pid=host alpine:3.20 \
	nsenter -t 1 -m -- ls -l /var/run/docker/netns/ | head -3
```

<!-- out @impl -->

```
total 0
-r--r--r-- … …
```

**ملفّاتٌ حجمها صفر، بأذونات القراءة فقط** — في مجلّدٍ خاصّ بدل `/run/netns`.
نفس الآلية بحذافيرها، ودفترٌ يمسكه `dockerd` بدل `ip`.

وهذا مثالُ ما قاله الفصل صفر: **لا توجد «قائمة شبكات» في النواة.** هناك نطاقاتٌ
ممسوكةٌ بملفّات، وأداةٌ تحتفظ بدفترٍ يربط الاسم بالملفّ. فإن ضاع الدفتر بقي
النطاق حيّاً بلا اسم.

<!-- host-setup -->

```sh
docker rm -f two >/dev/null && docker network rm t3lmnet >/dev/null
```

## الدخول: `setns` في ثلاثة أسطر

`nsenter` و`docker exec` و`ip netns exec` تفعل شيئاً واحداً. اكتبه:

<!-- part: 02-enter.c -->

```c
	fd = open(argv[1], O_RDONLY);
	if (setns(fd, 0) == -1) { … }
	execvp(argv[2], argv + 2);
```

**افتح ملفّ النطاق، وانتقل إليه، ونفّذ.** والوسيط الثاني في `setns` صفر: «أي
نوعٍ كان». ولك أن تكتب `CLONE_NEWNET` فيرفض النداء إن كان الملفّ لغيرها — تحقّقٌ
تشتريه بسطر.

<!-- lab -->

```sh
cc -std=c17 -Wall -Wextra -o enter programs/02-enter.c
./enter /run/netns/demo ip -o -4 addr; echo "(لا عنوان)"
./enter /run/netns/demo readlink /proc/self/ns/net
readlink /proc/self/ns/net
```

<!-- out @machine -->

```
(لا عنوان)
net:[…]
net:[…]
```

الرقمان الأخيران **مختلفان**: برنامجُك انتقل، وأنت لم تنتقل.

<!-- lab -->

```sh
strace -c -e trace=openat,setns,execve ./enter /run/netns/demo true 2>&1 | grep -E 'setns|openat'
```

<!-- runs @machine -->

```
…setns…
```

**نداءان ونصف.** ولا شيء غير ذلك في `docker exec` — عدا ما يعدّه لك من طرفيةٍ
وبيئةٍ ومجلّدٍ حاليّ (الإقليم ٢٨).

<!-- setup -->

```sh
ip netns del demo
```

## ما لا يُدخَل إليه هكذا

`setns` تنقلك إلى نطاقٍ قائم، **ولنطاق العمليات استثناء**: تنتقل أنت فلا يتغيّر
رقمك، ويولد أبناؤك في الجديد. وهو الحقل الذي رأيتَه (`pid_for_children`) وقد
صار له معنًى.

وسببه أن رقم العملية **يُعطى مرّةً عند الولادة** ولا يُبدَّل بعدها. فلو نُقلت
عمليةٌ إلى فضاءٍ آخر لاحتاجت رقماً فيه، ولانكسر كل من يمسك رقمها القديم.

---

## التمرين — ثلاثة، ولا حلول

**١.** أمسك نطاقاً بالطريقة الثالثة: **descriptor مفتوح**. اكتب برنامجاً يفتح
`/proc/self/ns/net` بعد `unshare`، ثم يبقيه مفتوحاً ويطبع رقم النطاق ويموت ابنُه.
**معيار القبول:** أن يظهر النطاق في `lsns` بـ`NPROCS = 0` ما دام البرنامج حيّاً،
وأن يختفي حين يُغلق الملفّ.

**٢.** أضِف إلى `enter` وسيطاً ثانياً يقول نوع النطاق المطلوب، ومرّره إلى
`setns`. ثم جرّب أن تدخل ملفّ نطاق شبكةٍ طالباً `CLONE_NEWPID`. **معيار القبول:**
أن تعرف رمز الخطأ الذي يعود، ولماذا هو هذا بالذات.

**٣ (الأصعب).** `ip netns add demo` تُنشئ نطاقاً وتمسكه بملفّ. **افعلها بيدك بلا
`ip`:** بأمر `unshare` وأمر `mount` وحدهما، ثم أثبِت بـ`findmnt` أنك حصلت على
ما حصلت عليه `ip`.

> تلميحٌ واحد لأنك ستحتاجه ولا يفسد شيئاً: النطاق يجب أن يبقى ممسوكاً **أثناء**
> الجبل. فكّر فيمن يمسكه في تلك اللحظة.

---

## الخلاصة — أين نحن في الشجرة

| ما عرفتَه | العقدة التي يتعلّق بها |
|---|---|
| النطاق inode يُقارَن | صار سؤال «هل هما معاً؟» قابلاً للقياس |
| ويموت بعدّاد مراجع | فُسِّر لماذا ماتت نطاقات `box` بموت ابنه |
| ويُمسَك بملفّ | فُتحت الشبكة القائمة بلا ساكن — الحزمة السادسة |
| ويُدخَل بـ`setns` | صار `docker exec` نداءين — والإقليم ٢٨ يكمله |

> **البذرة:** من النطاقات السبعة واحدٌ لا يشبه البقيّة. الستّة تعزل **قائمةً**
> — أسماءً أو أرقاماً أو بطاقات. والسابع يعزل **شجرة**، لها فروعٌ ترث وتُورَث،
> وفيها خاصيّةٌ تجعل ما تجبله في حاويتك يظهر على قرص المضيف.
>
> الإقليم القادم يفكّكها.
