# الإقليم ١٩ — بلا جذر

> كلُّ ما بنيتَه في هذه الحزمة يُضبَط من **خارج** الحاوية، بأمرٍ يشغّله جذرُ
> جهازك، عبر خدمةٍ تعمل جذراً. فإن سقطت تلك الخدمة سقط كلُّ شيء فوقها.
>
> فهل يمكن أن يُبنى هذا كلُّه بلا جذرٍ في أي موضع؟ يمكن. **وقد بنيتَ نصفه بيدك
> في الإقليم ٠٦** — بقيت النصفُ الآخر، وثمنُه.

---

## الخريطة تصير مدًى

`06-userbox.c` كتب في `uid_map` سطراً واحداً: `0 <uid> 1`. **فداخل النطاق
مستخدمٌ واحد.** جرّب أن تُنشئ ملفّاً لمستخدمٍ آخر:

<!-- setup -->

```sh
id alice > /dev/null 2>&1 || useradd -m -u 1000 alice
grep -q '^alice:' /etc/subuid || echo 'alice:100000:65536' >> /etc/subuid
grep -q '^alice:' /etc/subgid || echo 'alice:100000:65536' >> /etc/subgid
```

<!-- lab -->

```sh
runuser -u alice -- unshare -U -r sh -c '
	touch /tmp/a2
	chown 1000 /tmp/a2 2>&1 | head -1
	cat /proc/self/uid_map'
echo '--- --map-auto ---'
runuser -u alice -- unshare -U -r --map-auto sh -c '
	touch /tmp/a3
	chown 1000 /tmp/a3 && echo "chown 1000: ok"
	cat /proc/self/uid_map'
```

<!-- gate -->

```
chown: changing ownership of '/tmp/a2': Invalid argument
         0       1000          1
--- --map-auto ---
chown 1000: ok
         0       1000          1
         1     100000      65535
```

اقرأ رسالة الخطأ الأولى: **`Invalid argument` لا `Operation not permitted`.**
ولها معنًى دقيق: لم تُمنَع لنقص إذن، بل لأن الرقم `1000` **لا وجود له** داخل
النطاق — والنواة عجزت عن ترجمته لا عن السماح به.

والسطر الثاني في الخريطة الثانية هو الجواب: `1 100000 65535` — أي أن الأرقام
`1`–`65535` بالداخل تعني `100000`–`165534` بالخارج. وهذه هي المدَيات التي
أذِن بها جذرُ الجهاز مرّةً واحدة في `/etc/subuid`، وتُركّبها أداةٌ بـ`setuid`
اسمها `newuidmap` — وهي **الجذرُ الوحيد الباقي في التركيبة كلِّها**، ويعمل مرّةً
عند الإنشاء ثم ينتهي.

**والمكسب:** بهذا يصير داخل الحاوية نظامُ مستخدمين كامل — `postgres` و`nginx`
وكلُّ ما تتوقّعه صورةٌ عاديّة — بلا أن يملك مشغّلُها شيئاً على جهازك.

## والرقم خارجَه ليس رقمك

<!-- lab -->

```sh
rm -f /tmp/r0 /tmp/r1
runuser -u alice -- unshare -U -r --map-auto sh -c '
	touch /tmp/r0 /tmp/r1
	chown 0 /tmp/r0
	chown 1000 /tmp/r1
	ls -ln /tmp/r0 /tmp/r1 | awk "{print \"inside  \" \$3, \$9}"'
ls -ln /tmp/r0 /tmp/r1 | awk '{print "outside " $3, $9}'
```

<!-- gate -->

```
inside  0 /tmp/r0
inside  1000 /tmp/r1
outside 1000 /tmp/r0
outside 100999 /tmp/r1
```

الملفّ الواحد **له رقمان**، والفرق ليس عرضاً: هو الترجمة نفسها. فما كان جذراً
بالداخل صار `alice` بالخارج، وما كان `1000` بالداخل صار `100999`.

**وهذا أوّل الثمن.** مجلّدٌ تجبله من عندك (الإقليم ١١) ستكتب فيه الحاوية بأرقامٍ
في المدى الموسَّع، فلا تستطيع أن تقرأه ولا أن تحذفه بلا `sudo` — وأنت الذي
اخترتَ «بلا جذر» لتتجنّبه. والحلّ `--userns-remap` أو جبلٌ بخريطةٍ صريحة، وكلاهما
إعدادٌ إضافيّ لا افتراض.

## والشبكة تسقط

النطاق يعطيك شبكةً خاصّة بك، ولا يعطيك **وصلةً إلى شبكة جهازك**. نفسُ الأمر،
مرّتين:

<!-- lab -->

```sh
unshare -n sh -c '
	ip link add v0 type veth peer name v1
	ip link set v1 netns 1 && echo "as root    : moved to the host netns"'
runuser -u alice -- unshare -U -r --map-auto -n sh -c '
	ip link add v0 type veth peer name v1 > /dev/null
	printf "rootless   : "; ip link set v1 netns 1 2>&1 | head -1'
```

<!-- gate -->

```
as root    : moved to the host netns
rootless   : Error: argument "1" is wrong: Invalid "netns" value
```

الأمر نفسه حرفاً بحرف. وإنشاء الزوج نجح في الحالتين — لأن نطاق الشبكة الجديد
**يملكه** نطاقُ المستخدمين، فأنت جذرٌ فيه حقيقةً. والذي فشل هو نقلُ الطرف الآخر
إلى نطاق جهازك: ذلك النطاق ليس ملكك، ولا قدرة لك فيه.

> ورسالة الخطأ مضلّلة: `Invalid "netns" value` ليست عن قيمةٍ خاطئة، بل عن
> `/proc/1/ns/net` لم يُفتَح. وهذا نفسُ درس الإقليم ١٧: الرسالة ليست السبب.

**وهذا ثاني الثمن، وأثقلها.** فما دام الطرفُ الآخر لا يعبر، فلا جسر ولا NAT في
النواة. والبديل **مكدّسُ شبكةٍ في مساحة المستخدم** — يقرأ الرزم من جهازٍ وهميّ
ويعيد كتابتها مقبساً عاديّاً — فيصير كلُّ بايتٍ نسخةً إضافية وانتقالاً إلى مساحة
المستخدم وعودة. والحزمة القادمة تبني الطريق الأصليّ حتى ترى ما الذي يُستبدَل.

## وما اشتريتَه بذلك

<!-- host -->

```sh
docker run --rm --privileged --pid=host t3lm-docker-lab \
	nsenter -t 1 -m -- ls -l /var/run/docker.sock
```

<!-- out @impl -->

```
srw-rw---- 1 root root 0 … /var/run/docker.sock
```

هذا هو ما اشتريتَه. المقبس مملوكٌ للجذر، ومن وصل إليه **يشغّل ما شاء
بـ`--privileged`** — أي أنه يتجاوز الحزمة كلَّها: القدرات، والمرشّح، والأقنعة،
والحدود. ولذلك قال الفصل صفر إن الوصول إلى هذا الملفّ صلاحيةُ جذرٍ كاملة، لا
أقلّ.

وفي التركيب بلا جذر ينتقل المقبس إلى مجلّد وقت التشغيل الخاصّ بالمستخدم، مملوكاً
له. فمن وصل إليه يصير **ذلك المستخدم** — ومداه ما رأيته أعلاه: `alice`، وستّة
وستّون ألف رقمٍ لا تملك شيئاً على جهازك.

**والمكسب — وهو خلاصة الحزمة:** الطبقات الأربع السابقة تصغّر ما تستطيع الحاوية
أن تفعله. وهذه الطبقة تصغّر **ما تستطيع الأداة نفسها أن تفعله**. وهي الوحيدة
التي لا تُتجاوَز بخطأ إعداد.

## التمرين — اثنان، ولا حلول

**١.** أعد تجربة الملكية أعلاه بمجلّدٍ مجبولٍ من `/home/alice` بدل `/tmp`، ثم
حاول — بصفتك `alice` خارج النطاق — أن تحذف الملفّ الذي كُتِب بالرقم الموسَّع.
**معيار القبول:** رسالة الخطأ، وسطرٌ يقول لماذا نجح الحذف أو فشل مسنداً إلى
مالك **المجلّد** لا مالك الملفّ.

**٢ (الأصعب).** عدّل `06-userbox.c` ليستعمل مدًى بدل رقمٍ واحد — بأن يستدعي
`newuidmap` بدل الكتابة المباشرة في `uid_map`. **معيار القبول:** برنامجٌ يعمل
بصفتك أنت، ويُنشئ بداخله ملفّاً مملوكاً لـ`1000`، وسطرٌ يقول لماذا لا تكفي
الكتابة المباشرة في `uid_map` هنا مهما فعلت.

## الخلاصة — أين نحن في الشجرة

| ما عرفتَه | العقدة التي يتعلّق بها |
|---|---|
| الخريطة مدًى مأذونٌ به في `/etc/subuid` | `newuidmap` جذرٌ يعمل لحظةً ثم ينتهي |
| الملفّ له رقمان، والفرق هو الترجمة | أوّل الثمن: المجلّد المجبول يصير عصيّاً عليك |
| نطاق الشبكة ملكك، ونطاق جهازك ليس | ثاني الثمن: مكدّسٌ في مساحة المستخدم بدل النواة |
| المقبس هو ما اشتريتَه | من وصل إليه رفوعاً يتجاوز الحزمة كلَّها |

> **البذرة:** انتهت حزمة الامتياز. وبقي في الحاوية شيءٌ واحد لم تفكّكه بعد:
> **كيف تصل إلى الشبكة أصلاً.**
>
> نطاقُ شبكةٍ جديد لا يملك إلا `lo` معطّلة. ومع ذلك تفتح `docker run` صفحةً على
> الإنترنت بلا أن تكتب شيئاً. فمن وصلها، وبأي جهاز، وأين كُتِبت قواعد التوجيه؟
>
> الإقليم القادم يصل نطاقين بيدك، بلا Docker.
