# الإقليم ١٠ — من الصورة إلى جذرٍ عامل

> الإقليم ٠٩ انتهى عند تركيبٍ فاشل: فككتَ الطبقات الثلاث، وجبلتَها `overlayfs`
> بالترتيب الصحيح، فبقي `one.txt` الذي كان يجب أن يُمحى، وجلس `.wh.one.txt`
> إلى جانبه ملفّاً عاديّاً.
>
> فبين الأرشيف والشجرة العاملة **مترجم**. هذا الإقليم يمسكه متلبّساً: يسمّيه،
> ويقف حيث يقف ليرى ما كتبه، ويقيس ما يكلّفه.

---

## أوّلاً: أن تقف حيث تقف الخدمة

المترجم لا يعمل عندك؛ يعمل في الخدمة. وشجرةُ الحاوية مجبولةٌ في **نطاق جبلٍ ليس
نطاقك**، فلن تراها بـ`mount` عندك مهما كررتَ.

وقد صار عندك ما يكفي لدخوله: العملية `1` في النطاق الأصليّ تملك ذلك النطاق
(الإقليم ٠٢)، و`--pid=host` يريك جدولها (الإقليم ٠٧)، و`nsenter` يدخل إليه:

<!-- host-setup -->

```sh
docker image inspect demo:1 > /dev/null 2>&1 \
	|| docker build -q --provenance=false -t demo:1 .lab/img > /dev/null
docker image inspect demo:b > /dev/null 2>&1 \
	|| docker build -q --provenance=false -f .lab/img/Dockerfile.b -t demo:b .lab/img > /dev/null
docker rm -f box10 > /dev/null 2>&1
docker run -d --name box10 demo:1 sleep 3600 > /dev/null
```

<!-- host -->

```sh
docker info --format 'storage driver : {{.Driver}}'
ID=$(docker inspect -f '{{.Id}}' box10)
docker run --rm --privileged --pid=host -e ID="$ID" t3lm-docker-lab \
	nsenter -t 1 -m -- sh -c '
		grep "$ID" /proc/mounts | grep "^overlay " | awk "{print \"rootfs fstype  : \" \$3}"'
```

<!-- out @impl -->

```
storage driver : …
rootfs fstype  : overlay
```

**جذرُ الحاوية ليس مجلّداً سُلِّم إليها، بل `overlayfs` مجبولٌ لها وحدها** — نفسُ
نظام الملفّات الذي ركّبتَه بيدك في الإقليم ٠٨، لا شبيهٌ له.

واسم المترجم هو ما طبعه السطر الأوّل. وهو اسمان لشيءٍ واحد بحسب مخزن الصور:
**snapshotter** في مفردات containerd، و**storage driver** في المفردات القديمة —
`overlayfs` أو `overlay2` أو `btrfs` أو `zfs`. والمنهج يقول «snapshotter» لأن
هذا ما تسمّيه به الأداة التي تنفّذه فعلاً.

> **`nsenter -t 1 -m` هنا مفتاحُ الإقليم كلَّه**، ويعمل حيث تعمل نواتُك: على
> لينكس عارٍ يدخل نطاق `init` عندك، وتحت آلةٍ افتراضية يدخل نطاق `init` فيها.
> وفي الحالتين هو **موضع الخدمة**. وهو موسومٌ `@impl` لأنه يسقط في التركيب بلا
> جذر — الإقليم ١٩.

## كم طبقةً تحته؟

الصورة `demo:1` ثلاثُ طبقات، عددتَها بنفسك في الإقليم ٠٩. **فكم `lowerdir`
تتوقّع في جبل جذرها؟**

<!-- host -->

```sh
ID=$(docker inspect -f '{{.Id}}' box10)
docker run --rm --privileged --pid=host -e ID="$ID" t3lm-docker-lab \
	nsenter -t 1 -m -- sh -c '
		O=$(grep "$ID" /proc/mounts | grep "^overlay " | awk "{print \$4}")
		echo "lowerdir : $(echo "$O" | tr "," "\n" | sed -n "s/^lowerdir=//p" | tr ":" "\n" | grep -c .)"
		echo "upperdir : $(echo "$O" | tr "," "\n" | grep -c "^upperdir=")"
		echo "workdir  : $(echo "$O" | tr "," "\n" | grep -c "^workdir=")"'
```

<!-- gate @impl -->

```
lowerdir : 4
upperdir : 1
workdir  : 1
```

`upperdir` واحدة و`workdir` واحدة — كما في الإقليم ٠٨ بالضبط. أمّا `lowerdir`
فأربع، وطبقات الصورة ثلاث.

**والمكسب المؤجَّل:** الطبقة الزائدة ليست خطأً في عدّك ولا في المواصفة. هي طبقةٌ
لم تكتبها أنت ولا كاتبُ الـDockerfile، وستراها في الفقرة التالية بمحتواها.

## الطبقة التي لم يكتبها أحد

<!-- host -->

```sh
ID=$(docker inspect -f '{{.Id}}' box10)
docker run --rm --privileged --pid=host -e ID="$ID" t3lm-docker-lab \
	nsenter -t 1 -m -- sh -c '
		L=$(grep "$ID" /proc/mounts | grep "^overlay " | awk "{print \$4}" \
			| tr "," "\n" | sed -n "s/^lowerdir=//p")
		i=0
		for d in $(echo "$L" | tr ":" " "); do
			echo "lower[$i]: $(ls -A "$d" | tr "\n" " " | cut -c1-52)"
			i=$((i + 1))
		done'
```

<!-- out @impl -->

```
lower[0]: .dockerenv dev etc
lower[1]: one.txt two.txt
lower[2]: one.txt
lower[3]: bin dev etc home lib media mnt opt proc root run sbi
```

اقرأها من تحت: `lower[3]` شجرةُ الأساس، ثم طبقتاك، ثم **`lower[0]` طبقةٌ صنعتها
الأداة**: `.dockerenv` الذي تفحصه البرامج لتعرف أنها داخل حاوية، ومجلّدا `dev`
و`etc` مهيّآن لتُجبَل فيهما `resolv.conf` و`hostname` و`hosts` بعد قليل.

**والمكسب:** «الحاوية تشغّل الصورة كما هي» غير دقيق. بين الصورة والتشغيل طبقةٌ
من الأداة، وهي السبب في أن ملفّاً تضعه في `/etc/hosts` داخل الحاوية لا يصل إلى
`docker commit` كما تتوقّع — الإقليم ١١ يقيس هذا الجبل بعينه.

## المترجم متلبّساً

هذا هو السؤال الذي تركه الإقليم ٠٩ معلَّقاً. الأرشيف الثالث كان فيه ملفٌّ اسمه
`.wh.one.txt`. **فماذا في `lower[1]` مكانه؟**

<!-- host -->

```sh
ID=$(docker inspect -f '{{.Id}}' box10)
docker run --rm --privileged --pid=host -e ID="$ID" t3lm-docker-lab \
	nsenter -t 1 -m -- sh -c '
		L=$(grep "$ID" /proc/mounts | grep "^overlay " | awk "{print \$4}" \
			| tr "," "\n" | sed -n "s/^lowerdir=//p")
		i=0
		for d in $(echo "$L" | tr ":" " "); do
			[ -e "$d/one.txt" ] && echo "lower[$i]/one.txt : $(stat -c %F "$d/one.txt")"
			[ -e "$d/two.txt" ] && echo "lower[$i]/two.txt : $(stat -c %F "$d/two.txt")"
			i=$((i + 1))
		done'
docker exec box10 sh -c 'for f in /one.txt /two.txt; do
	[ -e $f ] && echo "$f: exists" || echo "$f: gone"; done'
```

<!-- gate -->

```
lower[1]/one.txt : character special file
lower[1]/two.txt : regular file
lower[2]/one.txt : regular file
/one.txt: gone
/two.txt: exists
```

لا وجود لـ`.wh.one.txt` في أي طبقة. مكانه ملفٌّ اسمه `one.txt` نوعُه **جهازٌ
محرفيّ** — وهو `c 0,0` نفسه الذي رأيته في الإقليم ٠٨ حين حذفتَ ملفّاً من
`merged` بيدك.

فوظيفة الـsnapshotter الأولى **ترجمةٌ بين لغتين**: يفكّ أرشيف الطبقة، وكلَّما
صادف اسماً يبدأ بـ`.wh.` أنشأ مكانه جهازاً وهميّاً بالاسم المكشوف. ولذلك فشل
تركيبك في الإقليم ٠٩: `tar x` يفكّ الأرشيف، ولا يترجم.

**والمكسب:** «الصورة تُفكّ ثم تُجبَل» وصفٌ ناقص. بينهما تحويلٌ لا يُختصَر، وهو
السبب في أن الطبقة على قرصك ليست نسخةً من الطبقة على الشبكة.

## الطبقة القابلة للكتابة، و`docker diff` بلا سحر

الطبقات الأربع للقراءة فقط. والكتابة تقع في `upperdir` وحدها — وهذا يعني أن
أداةً تقرأ ذلك المجلّد تستطيع أن تقول ما الذي تغيّر منذ الإقلاع:

<!-- host -->

```sh
docker exec box10 sh -c 'echo hi > /new.txt; rm /two.txt'
docker diff box10
ID=$(docker inspect -f '{{.Id}}' box10)
docker run --rm --privileged --pid=host -e ID="$ID" t3lm-docker-lab \
	nsenter -t 1 -m -- sh -c '
		U=$(grep "$ID" /proc/mounts | grep "^overlay " | awk "{print \$4}" \
			| tr "," "\n" | sed -n "s/^upperdir=//p")
		ls -lA "$U" | grep -v "^total" | awk "{print \$1, \$NF}"'
```

<!-- out -->

```
A /new.txt
D /two.txt
-rw-r--r-- new.txt
c--------- two.txt
```

السطران الأوّلان مخرَج `docker diff`، والأخيران محتوى `upperdir` كما هو. والمطابقة
تامّة: `A` ملفٌّ عاديّ ظهر، و`D` جهازٌ محرفيّ `c 0,0`.

**فـ`docker diff` ليس مقارنةً بين شجرتين.** هو `ls` على مجلّدٍ واحد، وقاعدةٌ
واحدة تقول إن الجهاز المحرفيّ صفر/صفر يُقرأ حذفاً. ولذلك يجيب فوراً مهما كبرت
الصورة: لا شيء يُمسَح ولا يُقارَن.

**والمكسب:** الحاوية «الخفيفة» ليست نسخةً مختصرة من الصورة، بل **مجلّدٌ فارغ**
فوقها. وهذا ما يجعل مئة حاوية من صورةٍ واحدة ممكنة.

## ما ينمو وما يثبت

ادّعاءُ «المجلّد الفارغ» يُقاس. اكتب عشرة ميجابايت داخل الحاوية، وراقب الرقمين:

<!-- host -->

```sh
RW=$(docker container inspect --size box10 -f '{{.SizeRw}}')
RF=$(docker container inspect --size box10 -f '{{.SizeRootFs}}')
docker exec box10 dd if=/dev/zero of=/big bs=1M count=10 2>/dev/null
RW2=$(docker container inspect --size box10 -f '{{.SizeRw}}')
RF2=$(docker container inspect --size box10 -f '{{.SizeRootFs}}')
echo "writable layer grew : $(( (RW2 - RW) / 1048576 )) MiB"
echo "image part          : $([ $((RF - RW)) -eq $((RF2 - RW2)) ] && echo identical || echo changed)"
```

<!-- out -->

```
writable layer grew : 10 MiB
image part          : identical
```

عشرةُ ميجابايت دخلت الطبقة القابلة للكتابة وحدها، وحصّةُ الصورة لم تتحرّك
بايتاً. وهي لا تستطيع أن تتحرّك: الطبقات الأربع مجبولةٌ للقراءة، ونواتُك لا
تسمح بغير ذلك.

**والمكسب:** `SizeRootFs` في `docker ps -s` — العمود المسمّى `virtual` — هو
**مجموع** الاثنين لا حجم الصورة. فحين يرتفع ذلك الرقم، اقرأ `SizeRw` قبل أن
تتّهم الصورة.

## ولماذا لا يُجمَع عمود الحجم

عندك ثلاث صور: `alpine:3.20`، و`demo:1` المبنيّة عليها، و`demo:b` المبنيّة عليها
أيضاً. و`docker images` يطبع لكلٍّ منها حجماً قريباً من الأخرى. **فكم طبقةً على
قرصك؟**

<!-- host -->

```sh
R=$(docker image inspect alpine:3.20 demo:1 demo:b \
	-f '{{range .RootFS.Layers}}{{println .}}{{end}}' | grep sha256)
echo "rows          : 3"
echo "layer refs    : $(echo "$R" | wc -l | tr -d ' ')"
echo "unique layers : $(echo "$R" | sort -u | wc -l | tr -d ' ')"
echo "used by all 3 : $(echo "$R" | sort | uniq -c | awk '$1 == 3' | wc -l | tr -d ' ')"
```

<!-- gate -->

```
rows          : 3
layer refs    : 6
unique layers : 4
used by all 3 : 1
```

ستُّ إشاراتٍ إلى أربع طبقات، وواحدةٌ منها — وهي الأكبر — تخدم الصور الثلاث.

وعمود `SIZE` في `docker images` صادقٌ في كل سطرٍ على حدة: **حجمُ السلسلة كاملةً
لو كانت هذه الصورة وحدها على القرص.** وهو لذلك عمودٌ لا يُجمَع؛ جمعُه يحسب
الأساس ثلاث مرّات.

**والمكسب:** حين تريد ما على قرصك فعلاً فاسأل عن المشترك لا عن السطور —
`docker system df -v` يفصل حصّة كل صورةٍ من المشترك. وحين تريد أن تقلّل، فالطريق
أن **تتقاسم الأساس**، لا أن تصغّر كل صورةٍ وحدها.

## وما يزول مع الحاوية

بقي سؤالٌ واحد: أين تذهب العشرة ميجابايت حين تختفي الحاوية؟

<!-- host -->

```sh
ID=$(docker inspect -f '{{.Id}}' box10)
U=$(docker run --rm --privileged --pid=host -e ID="$ID" t3lm-docker-lab \
	nsenter -t 1 -m -- sh -c 'grep "$ID" /proc/mounts | grep "^overlay " \
		| awk "{print \$4}" | tr "," "\n" | sed -n "s/^upperdir=//p"')
docker run --rm --privileged --pid=host -e U="$U" t3lm-docker-lab \
	nsenter -t 1 -m -- sh -c 'echo "before rm : $([ -d "$U" ] && echo present || echo gone)"'
docker rm -f box10 > /dev/null
docker run --rm --privileged --pid=host -e U="$U" t3lm-docker-lab \
	nsenter -t 1 -m -- sh -c 'echo "after  rm : $([ -d "$U" ] && echo present || echo gone)"'
```

<!-- out -->

```
before rm : present
after  rm : gone
```

المجلّد نفسه أُزيل. لا أرشفة، ولا سلّة، ولا سؤال.

**والمكسب:** عمرُ ما تكتبه هو عمرُ الحاوية بالضبط، لأن موضعه مجلّدٌ يملكه
الـsnapshotter ويحذفه معها. والطبقات الأربع تحته لم تُمسّ — فحذف الحاوية لا
يحرّر إلا ما كتبتَه أنت.

## التمرين — اثنان، ولا حلول

**١.** شغّل حاويتين من `demo:1` في وقتٍ واحد، واقرأ `lowerdir` و`upperdir` لكلٍّ
منهما. **معيار القبول:** جملةٌ تقول ما المشترك بينهما وما المفترق، وعددٌ يقول كم
مجلّداً على القرص لحاويتين لا لواحدة — مسنداً إلى ما قرأتَه لا إلى تقدير.

**٢ (الأصعب).** اكتب ملفّاً كبيراً داخل حاوية، ثم `docker commit` عليها، ثم
افحص الصورة الناتجة بأدوات الإقليم ٠٩ وحدها. **معيار القبول:** إجابةٌ عن سؤالين:
كم طبقةً في الصورة الجديدة مقارنةً بـ`demo:1`، وهل يظهر الملفّ الكبير في
`history` بسطرٍ يقول من أين جاء — وسطرٌ يفسّر لماذا كان الجواب الثاني كذلك.

## الخلاصة — أين نحن في الشجرة

| ما عرفتَه | العقدة التي يتعلّق بها |
|---|---|
| جذر الحاوية `overlayfs` مجبولٌ لها | ما بنيتَه في الإقليم ٠٨ هو ما يعمل، لا نموذجٌ عنه |
| الـsnapshotter يترجم `.wh.` إلى `c 0,0` | جواب اللغز الذي فشل به تركيبك في الإقليم ٠٩ |
| بين الصورة والتشغيل طبقةٌ من الأداة | فسّر من أين جاء `.dockerenv` ولمَ ليس في أي طبقةٍ بنيتَها |
| `docker diff` قراءةُ `upperdir` لا مقارنة | فسّر لماذا يجيب فوراً مهما كبرت الصورة |
| ما تكتبه ينمو وحده، والصورة لا تتحرّك | اقرأ `SizeRw` قبل أن تتّهم الصورة بالتضخّم |
| عمود `SIZE` لا يُجمَع | فسّر لماذا لا يقلّل تصغيرُ صورةٍ واحدةٍ شيئاً إن اختلف أساسها |

> **البذرة:** الطبقة القابلة للكتابة تزول مع الحاوية، ومع ذلك تشغّل قواعدَ
> بيانات في حاويات ولا تفقد بياناتها. فما الذي يجعل مساراً واحداً داخل الشجرة
> **لا يخضع** لهذا كلِّه — لا يُنسَخ عند أوّل كتابة، ولا يُترجَم، ولا يُحذَف مع
> الحاوية؟
>
> الإقليم القادم يفتح `mountinfo` الحاوية سطراً سطراً، فيرى الاستثناءات مجبولةً
> فوق الشجرة، ويقيس ما يكسره اختلافُ الأرقام بين الداخل والخارج.
