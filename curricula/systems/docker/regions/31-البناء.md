# الإقليم ٣١ — البناء

> رفعتَ صورةً بيدك بطبقةٍ واحدة ونصٍّ بلا معنى. أمّا الصورة التي يبنيها
> `docker build` فتأتي من ملفٍّ نصّيّ فيه أسطرٌ مألوفة: `FROM`، `RUN`، `COPY`.
>
> وهذا الإقليم يفتح ما بين السطر والطبقة: **رسمٌ موجَّه** لا قائمة، وخبيئةٌ
> مفتاحُها محتوًى لا زمن، وموضعٌ واحد تسرّب فيه الأسرار رغم كل الاحتياط.

---

## الرسم لا القائمة: خطوتان مستقلّتان تعملان معاً

Dockerfile يُقرَأ من فوقٍ لتحت، فيبدو تسلسلاً. **فهل ينفَّذ كذلك؟**

<!-- host-setup -->

```sh
mkdir -p .lab/build31 && cd .lab/build31
cat > Dockerfile.parallel <<'EOF'
FROM alpine:3.20@sha256:d9e853e87e55526f6b2917df91a2115c36dd7c696a35be12163d44e6e2a4b6bc AS a
RUN sleep 4 && echo done > /a.txt
FROM alpine:3.20@sha256:d9e853e87e55526f6b2917df91a2115c36dd7c696a35be12163d44e6e2a4b6bc AS b
RUN sleep 4 && echo done > /b.txt
FROM alpine:3.20@sha256:d9e853e87e55526f6b2917df91a2115c36dd7c696a35be12163d44e6e2a4b6bc
COPY --from=a /a.txt /a.txt
COPY --from=b /b.txt /b.txt
EOF
```

<!-- host -->

```sh
cd .lab/build31
T0=$(date +%s)
docker build --no-cache --provenance=false -f Dockerfile.parallel -t buildtest:par . > /dev/null 2>&1
T1=$(date +%s)
SECS=$((T1 - T0))
echo "elapsed        : ${SECS}s"
echo "two 4s RUNs    : $([ "$SECS" -lt 7 ] && echo 'ran together' || echo 'ran one after another')"
docker rmi -f buildtest:par > /dev/null 2>&1
```

<!-- gate @machine -->

```
elapsed        : …s
two 4s RUNs    : ran together
```

مرحلتان بلا علاقةٍ بينهما، كلٌّ منهما تنام أربع ثوانٍ. لو نُفِّذتا بالترتيب
لأخذ البناء ثماني ثوانٍ على الأقلّ — وأخذ أقلّ من ذلك بكثير.

**لأن BuildKit لا يقرأ Dockerfile سطراً بعد سطر؛ يبنيه رسماً موجَّهاً أوّلاً**:
كل خطوةٍ عقدة، وكل اعتمادٍ عليها (على أساسٍ سابق، أو ملفٍّ منسوخ، أو مرحلةٍ
أخرى بـ`COPY --from`) حافّة. والمرحلتان `a` و`b` لا حافّة بينهما، فلا سبب
يمنع تنفيذهما معاً.

**والمكسب:** هذا سرُّ الفرق بين البنّاء القديم والجديد الذي رأيتَ اسمه
`buildkit.dockerfile.v0` في سجلّ كل صورةٍ فحصتَها منذ الإقليم ٠٩. ومرحلتان
مستقلّتان — لبناء اختباراتٍ وإنتاجٍ من نفس المصدر مثلاً — لا تكلّفان زمناً
إضافياً لمجرّد أنهما مكتوبتان الواحدة بعد الأخرى.

## الخبيئة: مفتاحها محتوًى، لا توقيت

**الاعتقاد، صريحاً:** الخبيئة تتذكّر «آخر مرّةٍ بُنِي فيها هذا السطر»، فتغيير
ملفٍّ ثم إرجاعه لحالته الأصلية يُعيد البناء مرّتين.

<!-- host-setup -->

```sh
cd .lab/build31
cat > Dockerfile <<'EOF'
FROM alpine:3.20@sha256:d9e853e87e55526f6b2917df91a2115c36dd7c696a35be12163d44e6e2a4b6bc
RUN echo "layer A" > /a.txt
COPY data.txt /data.txt
RUN echo "layer C" > /c.txt
EOF
UNIQ=$RANDOM$RANDOM
echo "$UNIQ" > .uniq
```

النصّ التالي يقرأ حالة كل خطوةٍ من مخرَج البناء بمحتواها لا برقمها — لأن
BuildKit يعيد ترقيم الخطوات المخبّأة أحياناً.

<!-- host-setup -->

```sh
cd .lab/build31
cat > status.py <<'PYEOF'
import sys, re
steps = {"layer A": None, "data.txt /data.txt": None, "layer C": None}
lines = sys.stdin.readlines()
for i, l in enumerate(lines):
    for k in steps:
        if k in l and re.match(r"#\d+ \[", l):
            for j in range(i, min(i + 3, len(lines))):
                if "CACHED" in lines[j]:
                    steps[k] = "CACHED"; break
                if re.search(r"DONE", lines[j]):
                    steps[k] = "DONE"; break
for k in ["layer A", "data.txt /data.txt", "layer C"]:
    print(f"{k:22s}: {steps[k]}")
PYEOF
```

<!-- host -->

```sh
cd .lab/build31
UNIQ=$(cat .uniq)
echo "A-$UNIQ" > data.txt
docker build -q --provenance=false -t buildtest:v1 . > /dev/null
echo "--- تغيير المحتوى إلى قيمةٍ لم تُبنَ من قبل ---"
echo "B-$UNIQ" > data.txt
docker build --provenance=false -t buildtest:v2 . 2>&1 | python3 status.py
```

<!-- gate -->

```
--- تغيير المحتوى إلى قيمةٍ لم تُبنَ من قبل ---
layer A               : CACHED
data.txt /data.txt    : DONE
layer C               : DONE
```

كما تتوقّع: `COPY` لمحتوًى جديد **يفشل الخبيئة**، وينهار كلُّ ما بعده معه —
`RUN` التالية أعيد تنفيذها رغم أنها لم تتغيّر سطراً، لأن مدخلها الحقيقيّ ليس
نصّها بل **الطبقة الناتجة قبلها**، وتلك تغيّرت.

<!-- host -->

```sh
cd .lab/build31
UNIQ=$(cat .uniq)
echo "--- الرجوع إلى القيمة الأولى بعينها ---"
echo "A-$UNIQ" > data.txt
docker build --provenance=false -t buildtest:v3 . 2>&1 | python3 status.py
```

<!-- gate -->

```
--- الرجوع إلى القيمة الأولى بعينها ---
layer A               : CACHED
data.txt /data.txt    : CACHED
layer C               : CACHED
```

**ثلاث خبيئاتٍ مصيبة، لا اثنتان.** رجعتَ إلى المحتوى الأوّل فأصابت الخبيئة —
لم تُبنَ الطبقة من جديد، بل **استُرجِعت النتيجة التي حُسِبت أوّل مرّة**،
مطابقةً ببصمة محتوى الملفّ لا بترتيب البناء ولا بزمنه.

**والمكسب:** هذا هو الإقليم ٠٩ بعينه — «الاسم بصمةُ المحتوى» — مطبَّقاً على
مفتاح الخبيئة لا على الطبقة المخزَّنة فقط. ولذلك يستطيع فرعان مختلفان من
Git، بملفٍّ متطابق المحتوى، أن يتقاسما خبيئة بنائهما رغم اختلاف كل شيءٍ آخر
بينهما.

## الأسرار: الموضع الذي لا يحميه `--mount=type=secret`

`--mount=type=secret` يعد بألّا يترك السرّ أثراً في الصورة. **جرّبه، واكسر
الوعد بسطرٍ واحد.**

<!-- host-setup -->

```sh
cd .lab/build31
echo "sekret-value-123" > secret.txt
cat > Dockerfile.secret <<'EOF'
FROM alpine:3.20@sha256:d9e853e87e55526f6b2917df91a2115c36dd7c696a35be12163d44e6e2a4b6bc
RUN --mount=type=secret,id=mysecret \
    cat /run/secrets/mysecret > /tmp/seen.txt
EOF
```

<!-- host -->

```sh
cd .lab/build31
docker build -q --provenance=false -f Dockerfile.secret \
	--secret id=mysecret,src=secret.txt -t buildtest:leak . > /dev/null
docker create --name leak31 buildtest:leak true > /dev/null
echo "في الطبقة: $(docker export leak31 | tar xO tmp/seen.txt)"
docker rm leak31 > /dev/null
```

<!-- out -->

```
في الطبقة: sekret-value-123
```

السرّ **موجودٌ في الصورة**، رغم `--mount=type=secret`. لأن الجبل الخاصّ لا
يحمي إلّا **مساره هو**، `/run/secrets/mysecret`؛ والسطر داخل `RUN` نسخ
محتواه إلى `/tmp/seen.txt` — وهو مسارٌ عاديّ، يُكتَب في الطبقة كأي ملفٍّ
كتبتَه.

```
/run/secrets/mysecret          ← جبلٌ مؤقّت، يُنزَع بعد هذا الأمر
        │
        │  cat  ►  /tmp/seen.txt   ← مسارٌ عاديّ في الجذر القابل للكتابة
        │              │
        │              └──►  يُحفَظ في الطبقة، كأي RUN آخر
        │
        └── لم يبقَ له أثرٌ بذاته — لكنّ **قيمته** بقيت في مكانٍ آخر
```

**والفرق دقيق:** الآلية تحمي **الملفّ**، لا **المعلومة** التي بداخله. وأي
أمرٍ ينسخ تلك المعلومة إلى مسارٍ عاديّ — ولو بغير قصد، في ملفّ سجلٍّ أو ذاكرةٍ
مؤقّتة — يخرقها بصمتٍ تامّ لأن البناء نجح بلا أي تحذير.

<!-- host -->

```sh
cd .lab/build31
cat > Dockerfile.fixed <<'EOF'
FROM alpine:3.20@sha256:d9e853e87e55526f6b2917df91a2115c36dd7c696a35be12163d44e6e2a4b6bc
RUN --mount=type=secret,id=mysecret \
    grep -q sekret /run/secrets/mysecret && echo verified
EOF
docker build -q --provenance=false -f Dockerfile.fixed \
	--secret id=mysecret,src=secret.txt -t buildtest:fixed . > /dev/null
docker create --name fixed31 buildtest:fixed true > /dev/null
docker create --name base31 \
	alpine:3.20@sha256:d9e853e87e55526f6b2917df91a2115c36dd7c696a35be12163d44e6e2a4b6bc \
	true > /dev/null
docker export fixed31 | tar tf - | sort > fixed.list
docker export base31 | tar tf - | sort > base.list
echo "ملفّاتٌ جديدة فوق الأساس: $(diff fixed.list base.list | grep -c '^<')"
docker rm fixed31 base31 > /dev/null
```

<!-- out -->

```
ملفّاتٌ جديدة فوق الأساس: 0
```

نفس الآلية، بلا نسخٍ إلى مسارٍ دائم: **صفر ملفّاتٍ جديدة**. لا أثر للسرّ، ولا
لمساره المؤقّت — لأن ذلك المسار جبلٌ يُرفَع بانتهاء الأمر، لا طبقة.

**والمكسب:** لا تسأل «هل استعملتُ `--mount=type=secret`؟» — اسأل «هل كتبتُ
قيمة السرّ في أي مكانٍ غير مساره المؤقّت، ولو مؤقّتاً هو الآخر؟». الجواب
الصحيح الوحيد هو ألّا يغادر السرّ تلك النقطة إطلاقاً.

## وللمقارنة: الطريقة التي حلّ محلَّها هذا كلّه

<!-- host -->

```sh
cd .lab/build31
cat > Dockerfile.argleak <<'EOF'
FROM alpine:3.20@sha256:d9e853e87e55526f6b2917df91a2115c36dd7c696a35be12163d44e6e2a4b6bc
ARG SECRET_VAL
RUN echo "using $SECRET_VAL" > /tmp/out.txt
EOF
docker build -q --provenance=false -f Dockerfile.argleak \
	--build-arg SECRET_VAL=sekret-value-123 -t buildtest:argleak . > /dev/null 2>&1
docker history buildtest:argleak --no-trunc | grep -c sekret-value-123
```

<!-- out -->

```
2
```

`ARG` عاديّ — لا `--mount`، ولا سرّ خاصّ — يظهر **مرّتين**: مرّةً في السجلّ
كحقيقةٍ عن الوسيط نفسه، ومرّةً في نصّ الأمر الذي استعمله. وكلاهما مقروءٌ
لأي من يفحص `docker history` أو يفكّك الصورة — أي بالضبط ما فعلتَه في
الإقليم ٠٩.

**والمكسب:** `--mount=type=secret` لم يُخترَع من فراغ؛ عولج به هذا العطب
بعينه. ومع ذلك ما زال قابلاً للكسر بخطأٍ من نوعٍ آخر أدقّ — وهذا سرّ الفقرة
السابقة.

<!-- host-setup -->

```sh
cd .lab/build31
docker rmi -f buildtest:v1 buildtest:v2 buildtest:v3 buildtest:leak \
	buildtest:fixed buildtest:argleak > /dev/null 2>&1
cd ../.. && rm -rf .lab/build31
```

## التمرين — اثنان، ولا حلول

**١.** أضف `RUN --mount=type=cache,target=/var/cache/apk` إلى صورةٍ تُثبِّت
حزماً، وابنها مرّتين متتاليتين بـ`--no-cache` بينهما (تجاوز خبيئة الطبقات لا
خبيئة ذلك الجبل). **معيار القبول:** فرقُ زمنٍ واضح بين البناءين، وسطرٌ يقول
لماذا لا تظهر هذه الخبيئة في `docker history` مهما فحصتَه.

**٢ (الأصعب).** ابنِ Dockerfile فيه ثلاث مراحل: اثنتان مستقلّتان وثالثةٌ
تعتمد عليهما معاً (`COPY --from` من الاثنتين). **معيار القبول:** رسمٌ نصّيّ
يوضّح الحوافّ الثلاث، وسطرٌ يقول أيَّ زوجٍ من الخطوات ينفَّذ بالتوازي حتماً
وأيَّها لا يمكن — مسنداً إلى الرسم لا إلى القراءة من فوقٍ لتحت.

## الخلاصة — أين نحن في الشجرة

| ما عرفتَه | العقدة التي يتعلّق بها |
|---|---|
| Dockerfile رسمٌ موجَّه، لا قائمة | مرحلتان بلا اعتمادٍ تعملان معاً فعلياً، لا مجازاً |
| مفتاح الخبيئة بصمة محتوًى | نفس درس الإقليم ٠٩ يُطبَّق على البناء لا القراءة فقط |
| الطبقات تنهار من أوّل كسرٍ في السلسلة | تغييرٌ في `COPY` يُبطل كل `RUN` بعده مهما كانت بريئة |
| الجبل الخاصّ يحمي مساره لا معلومته | نسخُ السرّ إلى مسارٍ عاديّ يخرقه بصمتٍ تامّ |
| `ARG`/`ENV` تُقرَأ من `docker history --no-trunc` | نفس أدوات الإقليم ٠٩، مسلَّطةً على غلطةٍ حقيقية |

> **البذرة:** بنيتَ صوراً ورفعتَها ووثقت بخبيئتها. وبقي سؤالٌ واحد يجمع كل ما
> بنيتَه في هذا المنهج: حين تصلك صورةٌ من سجلٍّ لا تملكه، **ماذا تضمن بصمتُها
> بالضبط، وماذا لا تضمنه؟**
>
> الإقليم القادم يفتح التوقيع وSBOM والمنشأ — آخر ما بين يدك وبين الوثوق بما
> تُشغِّله.
