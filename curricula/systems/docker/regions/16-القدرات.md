# الإقليم ١٦ — القدرات

> لمستَ هذا مرّتين بلا أن تفتحه. في الإقليم ٠٦ صرتَ جذراً لا يستطيع `mknod`.
> وفي الإقليم ١٥ نجح `mknod` وفشل `open` على العقدة نفسها.
>
> الجواب في الحالتين واحد: **«الجذر» ليس صفةً واحدة.** هذه الحزمة تفكّكه، وهذا
> الإقليم أوّلُها.

---

## أربعون باباً، تُفتَح أربعة عشر

النواة لا تسأل «أهذا جذر؟» عند نداءٍ حسّاس؛ تسأل «أيملك القدرة الفلانيّة؟».
والقدرات معدودة. **فكم منها في حاويةٍ عاديّة؟**

<!-- host -->

```sh
n() {
	docker run --rm "$@" t3lm-docker-lab sh -c \
		'capsh --decode=$(awk "/CapEff/{print \$2}" /proc/self/status) | tr "," "\n" | grep -c cap_'
}
echo "default    : $(n)"
echo "privileged : $(n --privileged)"
docker run --rm t3lm-docker-lab sh -c \
	'capsh --decode=$(awk "/CapEff/{print \$2}" /proc/self/status) \
	 | cut -d= -f2 | tr "," "\n" | sed "s/^cap_//" | paste -sd" " - | fold -s -w 62'
```

<!-- gate @impl -->

```
default    : 14
privileged : 41
chown dac_override fowner fsetid kill setgid setuid setpcap 
net_bind_service net_raw sys_chroot mknod audit_write setfcap
```

أربعة عشر من واحدٍ وأربعين. **فالجذر داخل حاويتك ثلثُ جذر** — والثلثان الباقيان
منزوعان قبل أن يبدأ برنامجك، بلا أن يعلم.

وأسماؤها تقرأ نفسها: `net_bind_service` لفتح منفذٍ تحت ١٠٢٤، و`sys_chroot`
لتغيير الجذر، و`mknod` لصنع عقدة جهاز، و`kill` لإرسال إشارةٍ إلى عمليةٍ ليست لك.

**والمكسب:** كلُّ رسالة `Operation not permitted` تراها وأنت جذر لها اسمٌ في
هذه القائمة، أو اسمٌ خارجها. والسؤال الصحيح ليس «لماذا مُنِعت وأنا جذر» بل «أي
قدرةٍ يطلب هذا النداء».

---

## واحدةٌ تُنزَع، وأمرٌ بعينه يسقط

`mknod` في القائمة أعلاه. انزعها وحدها:

<!-- host -->

```sh
m() {
	docker run --rm "$@" alpine:3.20 sh -c \
		'mknod /tmp/d c 1 5 2>/dev/null && echo ok || echo denied'
}
echo "default          : $(m)"
echo "--cap-drop=MKNOD : $(m --cap-drop=MKNOD)"
```

<!-- out -->

```
default          : ok
--cap-drop=MKNOD : denied
```

وهنا يكتمل خيطُ الإقليم ١٥: **`mknod` نجح لأنك تملك `CAP_MKNOD`، و`open` فشل
لأن برنامج `cgroup_device` منعه.** آليّتان مستقلّتان تماماً على العقدة الواحدة،
ولكلٍّ منهما جوابُها ورسالتُها.

**والمكسب:** حين يُمنَع نداءٌ، افحص الاثنين لا واحداً. ونزعُ قدرةٍ واحدة أرخص من
`--privileged` بأربعين مرّة — بالمعنى الحرفيّ للعدد.

---

## الأطقم الخمسة، وما يفعله `--user`

القدرة ليست رقماً واحداً على العملية؛ هي **خمسة أطقم**. اقرأها في الحالتين:

<!-- host -->

```sh
c() {
	docker run --rm "$@" t3lm-docker-lab sh -c \
		'grep -E "^Cap" /proc/self/status | tr -d " \t" | tr "\n" " "; echo'
}
echo "root      : $(c)"
echo "user 1000 : $(c -u 1000)"
```

<!-- gate @impl -->

```
root      : CapInh:0000000000000000 CapPrm:00000000a80425fb CapEff:00000000a80425fb CapBnd:00000000a80425fb CapAmb:0000000000000000
user 1000 : CapInh:0000000000000000 CapPrm:0000000000000000 CapEff:0000000000000000 CapBnd:00000000a80425fb CapAmb:0000000000000000
```

**`Eff`** ما يُفحَص الآن، و**`Prm`** ما تستطيع أن ترفعه إلى `Eff` متى شئت،
و**`Bnd`** السقف الذي لا يُتجاوَز أبداً. أمّا **`Inh`** و**`Amb`** فمسار
التوريث عبر `execve` — وهما صفرٌ هنا، وصفرٌ في كل حاويةٍ عاديّة.

وسطرُ `user 1000` يقولها بلا مواربة: `--user` **أفرغ `Prm` و`Eff`، وترك `Bnd`
كما هو**. فالمستخدم غير الجذر داخل الحاوية لا يملك شيئاً — والسقف باقٍ فوقه بلا
معنًى، لأن `Inh` و`Amb` صفر فلا طريق للصعود إليه.

**والمكسب:** «شغّلها بمستخدمٍ غير جذر» إجراءٌ حقيقيّ لا شكليّ: يسقط أربعَ عشرة
قدرةً دفعةً واحدة. وثمنُه أن كلَّ ما كان يعمل بـ`CAP_CHOWN` أو
`CAP_NET_BIND_SERVICE` سيسقط معها — والإقليم ١١ أراك النصف الآخر من الثمن.

## والسقف يُنزَل ولا يُرفَع

<!-- host -->

```sh
d() { docker run --rm "$@" alpine:3.20 sh -c 'touch /tmp/f; chown 100 /tmp/f 2>/dev/null && echo ok || echo denied'; }
echo "default                    : $(d)"
echo "--cap-drop=ALL             : $(d --cap-drop=ALL)"
echo "--cap-drop=ALL +CHOWN      : $(d --cap-drop=ALL --cap-add=CHOWN)"
echo "bounding after +SYS_ADMIN  : $(docker run --rm --cap-add=SYS_ADMIN t3lm-docker-lab sh -c \
	'capsh --decode=$(awk "/CapBnd/{print \$2}" /proc/self/status) | tr "," "\n" | grep -c cap_')"
```

<!-- out -->

```
default                    : ok
--cap-drop=ALL             : denied
--cap-drop=ALL +CHOWN      : ok
bounding after +SYS_ADMIN  : 15
```

`--cap-drop=ALL` ثم `--cap-add` لِما تحتاجه بالاسم — هذه هي الصيغة. والسطر
الأخير يقول إن `--cap-add` يوسّع السقف نفسه: أربع عشرة صارت خمس عشرة.

لكنّ التوسيع من **خارج** الحاوية فقط. والعملية بداخلها لا تستطيع أن تعيد إلى
`Bnd` ما سقط منه — الإسقاط من السقف طريقٌ باتّجاهٍ واحد، وهو ما يجعل هذا الطقم
حدّاً حقيقيّاً لا تفضّلاً.

**والمكسب:** ابدأ من الصفر وأضِف بالاسم. والقائمة التي تنتهي إليها **وثيقةٌ**
تقول ما الذي يحتاجه برنامجك من النواة — وهي أنفع من أي تعليقٍ في ملفّ التركيب.

## `--privileged` مقيساً بالفرق

يُقال إن `--privileged` «يعطي كل الصلاحيات». وهذه صياغةٌ غامضة تُقاس:

<!-- host -->

```sh
probe() {
	docker run --rm "$@" t3lm-docker-lab sh -c '
		echo "caps       : $(capsh --decode=$(awk "/CapEff/{print \$2}" /proc/self/status) | tr "," "\n" | grep -c cap_)"
		echo "seccomp    : $(awk "/^Seccomp:/{print \$2}" /proc/self/status)"
		echo "/sys       : $(awk "\$5 == \"/sys\" {print \$6}" /proc/self/mountinfo | cut -d, -f1)"
		echo "mounts     : $(wc -l < /proc/self/mountinfo)"
		echo "kcore size : $(stat -c %s /proc/kcore)"'
}
probe | sed 's/^/default    /'
probe --privileged | sed 's/^/privileged /'
```

<!-- gate @impl -->

```
default    caps       : 14
default    seccomp    : 2
default    /sys       : ro
default    mounts     : 22
default    kcore size : 0
privileged caps       : 41
privileged seccomp    : 0
privileged /sys       : rw
privileged mounts     : 11
privileged kcore size : …
```

خمسةُ فروق، وثلاثةٌ منها لا علاقة لها بالقدرات أصلاً:

**`seccomp: 2`** تعني أن مرشّحاً يعمل على العملية، و**`0`** تعني لا مرشّح — وهذا
موضوع الإقليم القادم. **و`/sys` انقلب `rw`**، فصار كل ما تحته قابلاً للكتابة.
**وأحد عشر جبلاً اختفى** من الاثنين والعشرين التي عدّدتَها في الإقليم ١١ — وهي
جبولُ الإخفاء التي كانت تغطّي ملفّات النواة. ولذلك صار `/proc/kcore` — وهو صورة
الذاكرة الفيزيائية كاملةً — يقول حجمه الحقيقيّ بدل صفر.

**والمكسب:** `--privileged` ليست «قدرات أكثر»؛ هي **إطفاء أربع طبقات دفعةً
واحدة**. ومن يحتاج قدرةً واحدة فليضفها بالاسم — أمّا هذا العَلَم فيشتري معها
إطفاء المرشّح وفتح `/sys` ورفع الأقنعة.

> ومختبر هذا المنهج يعمل بـ`--privileged`، وقد قال الفصل صفر إنه سيقيس ثمنه هنا.
> هذه اللوحة هي الثمن.

## التمرين — اثنان، ولا حلول

**١.** شغّل حاويةً بـ`--cap-drop=ALL` وحاول أن تشغّل `ping`. ثم أعِد المحاولة
بـ`--cap-add=NET_RAW`. **معيار القبول:** رسالتا الخطأ حرفيّتين، وسطرٌ يقول لماذا
اختلفت رسالة `ping` عن رسالة `chown` رغم أن السبب واحد.

**٢ (الأصعب).** اكتب برنامج C يُسقِط `CAP_CHOWN` من `Eff` وحدها (ويُبقيها في
`Prm`)، يحاول `chown`، ثم يرفعها ويحاول ثانيةً. **معيار القبول:** مخرَجٌ يُظهر
فشلاً ثم نجاحاً بلا أن يتغيّر المستخدم ولا `Bnd`، وسطرٌ يقول لماذا لا يمكن كتابة
هذا البرنامج بحيث يرفع قدرةً ليست في `Prm`.

## الخلاصة — أين نحن في الشجرة

| ما عرفتَه | العقدة التي يتعلّق بها |
|---|---|
| الجذر واحدٌ وأربعون، وحاويتك تأخذ أربع عشرة | السؤال «أي قدرة يطلب هذا النداء» لا «لماذا مُنِعت وأنا جذر» |
| `mknod` قدرةٌ و`open` برنامجُ أجهزة | آليّتان على العقدة الواحدة · افحصهما معاً |
| `--user` يُفرغ `Prm` و`Eff` ويترك `Bnd` | إجراءٌ حقيقيّ لا شكليّ · وثمنُه معروف |
| `Bnd` يُنزَل ولا يُرفَع من الداخل | `--cap-drop=ALL` ثم `--cap-add` بالاسم |
| `--privileged` يطفئ أربع طبقات لا واحدة | قدرات · ومرشّح · و`/sys` · وأقنعة `/proc` |

> **البذرة:** رأيتَ `Seccomp: 2` في الحاوية العاديّة و`0` في المميّزة. فالقدرات
> تجيب «أتملك الحقّ في هذا النداء»، وثمّة طبقةٌ أخرى تجيب سؤالاً أضيق: **«أيُسمَح
> لك أن تنطق بهذا النداء أصلاً؟»**
>
> وهي مرشّحٌ تكتبه بيدك، ويعمل قبل أن تصل النواةُ إلى فحص القدرة.
