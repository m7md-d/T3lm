# الإقليم ١٨ — الطبقة الأخيرة

> بقيت الطبقات التي لا تُصنَّف. رأيتَ في الإقليم ١٦ أن `--privileged` يُسقِط أحد
> عشر جبلاً من اثنين وعشرين، وأن `/proc/kcore` يعود بحجمه الحقيقيّ. وانتهى
> الإقليم ١٧ عند رايةٍ **لا ترفعها الأداة**.
>
> هذا الإقليم يجمع الاثنين: راية `no_new_privs` وما تفتحه، والأقنعة وما تخفيه —
> ثم ما يبقى بعد كل ما بنيتَه في الحزمة.

---

## راية، وثمنُ عدم رفعها

**الاعتقاد، صريحاً:** `--user 1000` ينزل بالحاوية إلى مستخدمٍ عاديّ، فما عاد
فيها جذر.

جرّبه على صورةٍ فيها ملفٌّ واحد بـ`setuid`:

<!-- host-setup -->

```sh
mkdir -p .lab/suid && cp programs/18-suid.c .lab/suid/
cat > .lab/suid/Dockerfile <<'EOF'
FROM t3lm-docker-lab
COPY 18-suid.c /tmp/
RUN gcc -O0 -o /usr/local/bin/suid /tmp/18-suid.c && chmod 4755 /usr/local/bin/suid
EOF
docker build -q --provenance=false -t demo:suid .lab/suid > /dev/null
```

<!-- host -->

```sh
echo '--- default ---'
docker run --rm -u 1000 demo:suid suid
echo '--- no-new-privileges ---'
docker run --rm -u 1000 --security-opt no-new-privileges demo:suid suid
```

<!-- gate -->

```
--- default ---
uid=1000 euid=0
chown /etc/passwd: ok
--- no-new-privileges ---
uid=1000 euid=1000
chown /etc/passwd: Operation not permitted
```

`uid=1000` كما طلبت، و`euid=0` لم تطلبه. والسطر الثاني ليس تمثيلاً: مستخدمٌ
عاديّ **غيّر ملكيّة `/etc/passwd`**.

لأن `--user` يضبط المستخدم الذي تبدأ به، ولا يمنع الصعود بعدها. والذي يمنعه
راية `no_new_privs` — والأداة **لا ترفعها افتراضاً**، لأنها تركّب مرشّحها وهي
جذر فلا تحتاجها لنفسها.

**والمكسب:** «شغّلها بمستخدمٍ غير جذر» إجراءٌ ناقص وحده. يُتمُّه
`--security-opt no-new-privileges`، وهو **سطرٌ واحد** يجعل كل ملفّات `setuid` في
صورتك حبراً على ورق — بما فيها التي لا تعرف أنها موجودة.

## الأقنعة: اثنا عشر جبلاً، وصنفان

عُدَّ الجبول التي وضعتها الأداة على `/proc` و`/sys` في الإقليم ١١، ثم انظر
**نوعَ** كلٍّ منها:

<!-- host -->

```sh
docker run --rm alpine:3.20 sh -c 'awk "
	\$5 ~ /^\/proc\/|^\/sys\// && \$5 != \"/sys/fs/cgroup\" {
		split(\$6, o, \",\"); print \$9, o[1], \$5
	}" /proc/self/mountinfo'
```

<!-- gate @impl -->

```
proc ro /proc/bus
proc ro /proc/fs
proc ro /proc/irq
proc ro /proc/sys
proc ro /proc/sysrq-trigger
tmpfs rw /proc/interrupts
tmpfs rw /proc/kcore
tmpfs rw /proc/keys
tmpfs ro /proc/scsi
tmpfs rw /proc/timer_list
tmpfs ro /sys/firmware
```

**صنفان لا واحد.** الخمسة الأولى `proc` بـ`ro`: نفسُ المجلّد أُعيد جبلُه على
نفسه للقراءة فقط — تراه ولا تكتب فيه. والستّة الباقية `tmpfs`: **شيءٌ آخر
تماماً وُضِع مكانها.**

و`/proc/kcore` صورةُ الذاكرة الفيزيائية كلَّها. لم يُمنَع بأذونات ولا بقدرة ولا
بمرشّح — **غُطّي بملفٍّ فارغ**. ولذلك قال حجمه صفراً في الإقليم ١٦، ثم قال
مئات التيرابايت حين رفع `--privileged` الغطاء.

**والمكسب:** هذه الطبقة ليست عزلاً ولا حدّاً ولا مرشّحاً؛ هي **جبل** — الآلية
التي فككتَها في الإقليم ٠٣ وقستَها في الإقليم ١١. فالأداة لم تخترع لها شيئاً،
واستعملت ما في النواة أصلاً.

## و`/proc/sys` للقراءة فقط، ولو كنت جذراً

<!-- host -->

```sh
docker run --rm alpine:3.20 sh -c 'echo boxy > /proc/sys/kernel/hostname' 2>&1 | head -1
echo "default  : $(docker run --rm alpine:3.20 cat /proc/sys/net/ipv4/ip_unprivileged_port_start)"
echo "--sysctl : $(docker run --rm --sysctl net.ipv4.ip_unprivileged_port_start=1024 \
	alpine:3.20 cat /proc/sys/net/ipv4/ip_unprivileged_port_start)"
```

<!-- out -->

```
sh: can't create /proc/sys/kernel/hostname: Read-only file system
default  : 0
--sysctl : 1024
```

جذرٌ كامل بأربع عشرة قدرة، ورسالة الخطأ **ليست عن إذن**: نظام ملفّاتٍ للقراءة
فقط. فالمنع وقع في طبقةٍ أدنى من الأذونات كلِّها.

والطريق المسموح `--sysctl` عند الإنشاء — وهو **قائمةٌ مغلقة** عند الأداة: ما
كان منها معزولاً بنطاق (`net.*` وبعض `kernel.*`) يُقبَل، وما كان عامّاً على
النواة كلِّها يُرفَض، لأن كتابته تمسّ جهازك لا حاويتك.

**والمكسب:** «الحاوية غيّرت إعداد نواتي» لا يقع من داخلها. يقع من سطر إنشائها،
أو من `--privileged` الذي يجعل `/proc/sys` قابلاً للكتابة كسائر ما يفتحه.

## وما يبقى بعد كل ذلك

بنيتَ في هذه الحزمة أربع طبقات: القدرات، والمرشّح، والراية، والأقنعة. وفوقها
طبقةٌ خامسة **لا تأتي من الأداة ولا من النواة العامّة**، بل من نظام تحكّمٍ
إلزاميّ في توزيعتك:

<!-- host -->

```sh
docker info --format '{{range .SecurityOptions}}{{println .}}{{end}}'
```

<!-- out @distro -->

```
name=seccomp,profile=builtin
name=cgroupns
```

**اقرأ مخرَجك أنت لا هذه اللوحة.** فإن رأيت سطراً فيه `apparmor` أو `selinux`
فعندك تلك الطبقة تعمل، وإن لم تره فليست عندك — وهو `@distro` لهذا السبب: نواةٌ
بلا وحدة الأمان تلك لا تعرض شيئاً مهما فعلت الأداة.

وما تضيفه حين توجد ليس تكراراً لما سبق: القدرات والمرشّح يسألان عن **النداء**،
وهذه تسأل عن **الجسم** — أي مسارٍ تفتحه، وأي منفذٍ تربطه، وأي واجهةٍ تكلّمها.
فتمنع عمليةً تملك `CAP_DAC_OVERRIDE` كاملةً من فتح مسارٍ بعينه.

**والمكسب:** حين تنتقل تركيبتك بين توزيعتين وتعمل هنا وتفشل هناك بلا فرقٍ في
أي شيء كتبتَه، فهذا السطر أوّل ما يُقرأ.

## التمرين — اثنان، ولا حلول

**١.** ابنِ صورةً بلا أي ملفّ `setuid` (`find / -perm -4000` يعطيك القائمة)،
واحذف ما تجده. **معيار القبول:** عددُ ما حذفتَه، وسطرٌ يقول أيُّ الإجراءين أقوى
في صورتك أنت: حذفُها أم `no-new-privileges` — مع سببٍ لا تفضيل.

**٢ (الأصعب).** اجبل `/proc/kcore` من المضيف داخل حاويةٍ عاديّة بـ`-v`، ثم
اقرأ حجمه. **معيار القبول:** الحجم الذي رأيته، وسطرٌ يقول لماذا لم ينفع القناع
هنا — مسنداً إلى ترتيب الجبول في `mountinfo` لا إلى تخمين.

## الخلاصة — أين نحن في الشجرة

| ما عرفتَه | العقدة التي يتعلّق بها |
|---|---|
| `--user` وحده لا يمنع الصعود | `setuid` واحد يعيدك جذراً · والراية سطرٌ واحد يقفلها |
| الأقنعة صنفان: إعادةُ جبلٍ للقراءة، وتغطيةٌ بـ`tmpfs` | `/proc/kcore` مغطًّى لا ممنوع |
| `/proc/sys` للقراءة فقط ولو كنت جذراً | الخطأ عن نظام الملفّات لا عن الإذن |
| `--sysctl` قائمةٌ مغلقة عند الإنشاء | ما ليس معزولاً بنطاقٍ يُرفَض |
| AppArmor وSELinux يسألان عن الجسم لا النداء | اقرأ `docker info` قبل أن تتّهم تركيبتك |

> **البذرة:** أربع طبقاتٍ فوق العزل، وكلُّها تُضبَط من **خارج** الحاوية بأمرٍ
> يشغّله جذرُ جهازك. والخدمة نفسها تعمل جذراً، ومقبسُها — كما قال الفصل صفر —
> صلاحيةُ جذرٍ كاملة لمن وصل إليه.
>
> فهل يمكن أن يسقط هذا كلُّه؟ أن تُبنى الحاويةُ وتُشغَّل بلا جذرٍ في أي موضع —
> لا خدمةً مميّزة ولا مستخدماً صفراً حقيقيّاً؟
>
> يمكن. وقد بنيتَ نصفه بيدك في الإقليم ٠٦.
