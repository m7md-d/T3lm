# الإقليم ١١ — الجبل من الخارج

> الإقليم ١٠ أثبت أن كلَّ ما تكتبه يسكن `upperdir` ويزول مع الحاوية. ومع ذلك
> تشغّل قواعدَ بيانات في حاويات ولا تفقد صفّاً.
>
> فثمّة مساراتٌ **لا تخضع** لذلك: لا تُنسَخ عند أوّل كتابة، ولا يترجمها
> الـsnapshotter، ولا تُحذَف مع الحاوية. هذا الإقليم يفتح `mountinfo` الحاوية
> سطراً سطراً حتى تراها، ثم يقيس ما يكسره اختلافُ الأرقام بين الداخل والخارج.

---

## جبلتَ لا شيء، وفي شجرتك اثنان وعشرون جبلاً

<!-- host-setup -->

```sh
docker rm -f box11 > /dev/null 2>&1
docker run -d --name box11 alpine:3.20 sleep 3600 > /dev/null
```

<!-- host -->

```sh
docker exec box11 sh -c '
	echo "mount lines : $(wc -l < /proc/self/mountinfo)"
	awk "{print \$5}" /proc/self/mountinfo | grep -v "^/proc/\|^/sys/\|^/dev/"'
```

<!-- out @impl -->

```
mount lines : 22
/
/proc
/dev
/sys
/etc/resolv.conf
/etc/hostname
/etc/hosts
```

أمرٌ بلا `-v` ولا `--mount`، وفيه اثنان وعشرون جبلاً. سبعةٌ منها فوق، والخمسة
عشر الباقية جبولٌ داخل `/proc` و`/sys` و`/dev` — أكثرُها **إخفاءٌ متعمَّد** لملفّات
النواة، وهو موضوع الإقليم ١٨.

**فشجرة الحاوية ليست نظام ملفّاتٍ واحداً.** هي `overlayfs` واحدٌ (الإقليم ١٠)،
وفوقه إحدى وعشرون استثناءً مجبولاً.

**والمكسب:** كل استثناءٍ منها **سطرٌ في `mountinfo` تستطيع قراءته**. فما دمت
تعرف أين تنظر، لم يبقَ في مسار الملفّات شيءٌ مخفيّ عنك.

---

## ثلاثة ملفّاتٍ ليست في أي طبقة

`/etc/resolv.conf` و`/etc/hostname` و`/etc/hosts` موجودةٌ في كل حاوية، وليست في
أي طبقةٍ فحصتَها في الإقليم ٠٩. عدّلْ أحدها، ثم **اسأل `docker diff` كم تغيّر.**

<!-- host -->

```sh
docker exec box11 sh -c 'echo "# added-by-region-11" >> /etc/hosts'
echo "docker diff lines : $(docker diff box11 | wc -l | tr -d ' ')"
echo "mount source      : $(docker exec box11 sh -c 'grep " /etc/hosts " /proc/self/mountinfo' \
	| awk '{print $4}' | sed 's|/[0-9a-f]\{64\}/|/<id>/|')"
ID=$(docker inspect -f '{{.Id}}' box11)
docker run --rm --privileged --pid=host -e ID="$ID" t3lm-docker-lab \
	nsenter -t 1 -m -- sh -c 'echo "on daemon host    : $(tail -1 /var/lib/docker/containers/$ID/hosts)"'
```

<!-- gate @impl -->

```
docker diff lines : 0
mount source      : …/containers/<id>/hosts
on daemon host    : # added-by-region-11
```

كتبتَ سطراً، و`docker diff` يقول **صفر**. وهو ليس كاذباً: قرأ `upperdir` كما
شرح الإقليم ١٠، ولم يجد شيئاً — لأن السطر لم يمرّ عليه أصلاً.

`/etc/hosts` **ملفٌّ مجبولٌ فوق ملفّ**. والجبل لا يشترط أن يكون على مجلّد؛ يكفي
أن يوجد الاسم في الشجرة. فالكتابة نفذت إلى الملفّ الأصليّ عند الخدمة، خارج
`overlayfs` كلَّه.

**والمكسب:** هذا سببُ إحباطٍ شائع بعينه — تعدّل إعداداً داخل حاوية ثم تعمل
`docker commit` فلا تجد تعديلك في الصورة. لم يضِع: هو في مكانه، لكنه ليس في
الطبقة التي تُصوَّر.

## الجبل من الخارج: `bind`

الآلية نفسها تُفتَح لك بعَلَمٍ واحد. والصورة `demo:data` فيها `/data/seed.txt`
مكتوبٌ داخل طبقةٍ من طبقاتها. **فماذا يرى `ls /data` حين تجبل مجلّدك مكانه؟**

<!-- host-setup -->

```sh
cat > .lab/img/Dockerfile.d <<'EOF'
FROM alpine:3.20@sha256:d9e853e87e55526f6b2917df91a2115c36dd7c696a35be12163d44e6e2a4b6bc
RUN mkdir /data && echo "from image" > /data/seed.txt
EOF
docker build -q --provenance=false -f .lab/img/Dockerfile.d -t demo:data .lab/img > /dev/null
rm -rf .lab/bindsrc && mkdir -p .lab/bindsrc
```

<!-- host -->

```sh
echo "بلا جبل : $(docker run --rm demo:data ls /data)"
echo "مع جبل  : [$(docker run --rm -v "$PWD/.lab/bindsrc:/data" demo:data ls /data)]"
docker run --rm -v "$PWD/.lab/bindsrc:/data" demo:data sh -c 'echo written-inside > /data/out.txt'
echo "عندك    : $(cat .lab/bindsrc/out.txt)"
```

<!-- gate -->

```
بلا جبل : seed.txt
مع جبل  : []
عندك    : written-inside
```

`seed.txt` لم يُحذَف ولم يُنقَل؛ **حُجب**. الجبلُ يغطّي الاسم في الشجرة كما يغطّي
أي جبلٍ آخر — وهو الدرس نفسه الذي رأيته في الإقليم ٠٣ حين غطّيتَ مجلّداً
بـ`tmpfs`. وارفع الجبل يعُد الملفّ.

والكتابة وصلت إلى مجلّدك مباشرةً: بلا نسخٍ عند أوّل كتابة، وبلا طبقة، وبلا
`docker cp`.

**والمكسب:** «ملفّاتي اختفت لمّا جبلت المجلّد» ليست خسارة بيانات. هي جبلٌ فوق
مسارٍ مشغول، ويُشخَّص بسطرٍ واحد في `mountinfo`.

## الـ`volume`: نفس الآلية، ومصدرٌ تملكه الأداة

الفرق بين `bind` والـ`volume` ليس في الآلية — كلاهما جبل. الفرق **من يملك
المصدر**، ويتبعه سلوكٌ واحدٌ يفترقان فيه:

<!-- host-setup -->

```sh
docker volume rm -f v11 > /dev/null 2>&1
docker volume create v11 > /dev/null
rm -rf .lab/bind2 && mkdir -p .lab/bind2
```

<!-- host -->

```sh
echo "volume أوّل استعمال : $(docker run --rm -v v11:/data demo:data ls /data)"
echo "bind   أوّل استعمال : [$(docker run --rm -v "$PWD/.lab/bind2:/data" demo:data ls /data)]"
docker volume inspect v11 -f 'mountpoint         : {{.Mountpoint}}' \
	| sed 's|/volumes/.*|/volumes/v11/_data|'
```

<!-- out @impl -->

```
volume أوّل استعمال : seed.txt
bind   أوّل استعمال : []
mountpoint         : /var/lib/docker/volumes/v11/_data
```

الـ`volume` الفارغ **يُبذَر** عند أوّل جبلٍ عليه بما في الصورة تحته — بمحتواه
وبأذوناته وبملكيّته. والـ`bind` لا يُبذَر أبداً، لأن مجلّدك ملكُك ولا تملك
الأداة أن تكتب فيه ما لم تطلب.

ومصدره مجلّدٌ عاديّ عند الخدمة، تراه بأدوات الإقليم ١٠ نفسها.

**والمكسب:** البذر يقع **مرّةً واحدة، وعلى الفارغ فقط**. فالـ`volume` الذي
استُعمل مرّةً لا يلتقط تحديث الصورة بعدها — وهذا أشهرُ سببٍ لـ«حدّثت الصورة ولم
يتغيّر شيء».

## الملكية حين تختلف الأرقام

الجبل ينقل الشجرة، ولا ينقل معها هويّة. **والأذونات تُفحَص بالرقم لا بالاسم** —
وهذا ما رأيته في الإقليم ٠٦ من جهة النطاقات، وهنا تراه من جهة الجبل:

<!-- host -->

```sh
docker run --rm -v v11:/data demo:data sh -c '
	echo "uid      : $(id -u)"
	echo "owner    : $(stat -c %u /data)"
	touch /data/root.txt && echo "write    : ok"'
docker run --rm -u 1000 -v v11:/data demo:data sh -c '
	echo "uid      : $(id -u)"
	touch /data/user.txt 2>&1 | sed "s/^/write    : /"' 
```

<!-- gate -->

```
uid      : 0
owner    : 0
write    : ok
uid      : 1000
write    : touch: /data/user.txt: Permission denied
```

المجلّد نفسه، والجبل نفسه، والنتيجة تنقلب لأن الرقم اختلف. ولا شيء هنا خاصٌّ
بـDocker: هذه أذوناتُ يونكس تعمل كما تعمل دائماً، على مجلّدٍ يملكه الجذر.

**والمكسب:** `--user` وحده لا يكفي. من يشغّل بلا جذر يحتاج أن **يوافق** رقمُه
رقمَ مالك المصدر — إمّا بضبط الملكية عند الإنشاء، أو ببذرٍ من صورةٍ فيها المسار
مملوكٌ لذلك الرقم مسبقاً. والحلّ الثالث — أن تتغيّر الأرقام نفسها بين الداخل
والخارج — هو الإقليم ١٩.

## `tmpfs`: جبلٌ بلا قرص

<!-- host -->

```sh
docker run --rm --tmpfs /t:size=16m alpine:3.20 sh -c '
	M=$(grep " /t " /proc/self/mountinfo)
	echo "fstype  : $(echo "$M" | awk "{print \$9}")"
	echo "options : $(echo "$M" | awk "{print \$NF}")"
	dd if=/dev/zero of=/t/x bs=1M count=32 2>&1 | head -1
	echo "size    : $(df -h /t | tail -1 | awk "{print \$2}")"'
```

<!-- out -->

```
fstype  : tmpfs
options : rw,size=16384k
dd: error writing '/t/x': No space left on device
size    : 16.0M
```

نوعٌ ثالث، وهو الوحيد الذي **لا مصدر له**: النواة تصنع نظام ملفّاتٍ في الذاكرة
عند الجبل. والحدُّ الذي طلبتَه حدٌّ حقيقيّ تفرضه النواة عند نداء `write`، لا
سياسةٌ من الأداة.

**والمكسب:** ما تكتبه هنا لا يمرّ على قرصٍ أصلاً. وهذا موضعُ الأسرار وملفّات
الجلسة — ولكن انتبه: `tmpfs` **تُحسَب من ذاكرة المجموعة**، فالمحاسبة عليها
موضوعُ الإقليم ١٣ لا هذا الإقليم.

## ما يبقى وما يزول

<!-- host -->

```sh
docker rm -f box11 > /dev/null
docker run --rm demo:data sh -c 'echo x > /in-layer.txt'
echo "الطبقة القابلة للكتابة : $(docker run --rm demo:data sh -c '[ -e /in-layer.txt ] && echo present || echo gone')"
echo "volume                : $(docker run --rm -v v11:/data demo:data sh -c '[ -e /data/root.txt ] && echo present || echo gone')"
echo "bind                  : $([ -e .lab/bindsrc/out.txt ] && echo present || echo gone)"
echo "volume ls             : $(docker volume inspect v11 -f '{{.Name}}')"
```

<!-- out -->

```
الطبقة القابلة للكتابة : gone
volume                : present
bind                  : present
volume ls             : v11
```

ثلاثةُ مصائر لثلاث كتاباتٍ متطابقة في الشكل. والفرق كلُّه **من يملك المصدر**:
الـsnapshotter يملك `upperdir` فيحذفه، والأداة تملك الـ`volume` فتبقيه حتى
تُؤمَر، وأنت تملك مجلّدك فلا تُسأل عنه.

**والمكسب:** «الحاوية بلا حالة» ليست خاصيّةً تحصل عليها؛ هي **الافتراض**. والحالة
شيءٌ تضيفه بجبلٍ صريح، وتعرف عمره من مالكه.

---

## التمرين — اثنان، ولا حلول

**١.** اجبل `volume` واحداً في حاويتين تعملان في وقتٍ واحد، واكتب فيه من
كلتيهما. **معيار القبول:** سطرٌ يقول هل ترى كلٌّ منهما كتابةَ الأخرى فوراً، وسطرٌ
يفسّر الجواب بما قرأتَه في `mountinfo` — لا بما قرأتَه في وثيقة.

**٢ (الأصعب).** اجبل ملفّاً واحداً (لا مجلّداً) من عندك داخل حاوية، ثم **احذفه**
من عندك وأنشئ ملفّاً جديداً بنفس الاسم واكتب فيه. **معيار القبول:** جوابٌ عمّا
تراه الحاوية بعد ذلك، وسطرٌ يفسّره بأن الجبل يمسك **الملفّ** لا الاسم — مسنداً
إلى ما تعرفه عن الـinode من منهج C.

## الخلاصة — أين نحن في الشجرة

| ما عرفتَه | العقدة التي يتعلّق بها |
|---|---|
| شجرة الحاوية تركيبٌ من اثنين وعشرين جبلاً | كل استثناءٍ في المسار سطرٌ تقرأه، لا سلوكٌ تحفظه |
| `/etc/hosts` وأختاها ملفّاتٌ مجبولة | فسّر لماذا لا يلتقط `docker commit` تعديلك على الإعداد |
| الجبل يحجب ولا يحذف | «ملفّاتي اختفت» تشخيصٌ لا خسارة |
| الـ`volume` يُبذَر مرّةً وعلى الفارغ فقط | فسّر لماذا لا يظهر تحديث الصورة في مجلّدٍ قديم |
| الأذونات بالرقم لا بالاسم | `--user` وحده لا يكفي · والباقي في الإقليم ١٩ |
| المصير يتبع المالك: snapshotter · أداة · أنت | «بلا حالة» افتراضٌ لا إنجاز |

> **البذرة:** اكتملت الشجرة. تعرف الآن من أين جاء كل مسارٍ في الحاوية، ومن يملكه،
> وكم يبقى. وكلُّ ما سبق جوابٌ عن سؤالٍ واحد: **ما الذي تراه.**
>
> وبقي السؤال الثاني من الفصل صفر: **كم تأخذ.** ذاكرةً ومعالجاً وقرصاً وعمليات.
> والجواب سطرٌ واحد في `box` منذ الإقليم الأوّل، ما زال ينتظر تفسيره.
