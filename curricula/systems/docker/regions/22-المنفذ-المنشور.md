# الإقليم ٢٢ — المنفذ المنشور

> `-p 8080:80` سطرٌ تكتبه كل يوم. وبعده يصل الطلب من شبكتك إلى حاويةٍ عنوانها
> `172.17.0.x` لا يعرفه أحدٌ خارج جهازك.
>
> بنيتَ في الإقليم ٢١ الخروجَ بترجمة المصدر. وهذا الإقليم يبني الدخول بترجمة
> **المقصد** — ثم يجيب سؤالاً يقلق كثيرين: لماذا لا يوقفه جدارُك؟

---

## سطرٌ واحد، وقاعدةٌ واحدة

<!-- host-setup -->

```sh
docker rm -f p22 > /dev/null 2>&1
docker run -d --name p22 -p 8080:80 alpine:3.20 sh -c \
	'while true; do printf "HTTP/1.1 200 OK\r\nContent-Length: 6\r\n\r\nhello\n" | nc -l -p 80; done' \
	> /dev/null
```

<!-- host -->

```sh
docker run --rm --privileged --net=host t3lm-docker-lab sh -c '
	iptables -t nat -S DOCKER | grep 8080
	iptables -t nat -S PREROUTING | grep DOCKER'
```

<!-- gate @impl -->

```
-A DOCKER -p tcp -m tcp --dport 8080 -j DNAT --to-destination …:80
-A PREROUTING -m addrtype --dst-type LOCAL -j DOCKER
```

قاعدتان لا أكثر. الأولى تقول: **رزمةٌ إلى المنفذ ٨٠٨٠ يُستبدَل مقصدُها** بعنوان
الحاوية ومنفذها. والثانية تقول متى تُستشار: عند دخول رزمةٍ مقصدُها عنوانٌ من
عناوين هذا الجهاز.

وهذا نظير ما بنيتَه بيدك في الإقليم ٢١، معكوساً: هناك `MASQUERADE` غيّر
**المصدر** عند الخروج، وهنا `DNAT` يغيّر **المقصد** عند الدخول. ونفسُ جدول
التتبّع في النواة يعيد الاستبدال في الاتّجاه المقابل.

**والمكسب:** «نشرُ منفذ» ليس خادماً وسيطاً ولا استماعاً على منفذ. هو **سطرُ
ترجمةٍ في النواة**، ولذلك لا يكلّف شيئاً في المسار.

---

## وأين تُطبَّق: قبل الجدار لا بعده

**الاعتقاد، صريحاً:** قاعدةٌ في `INPUT` تمنع المنفذ ٨٠٨٠ ستمنع الوصول إلى
الحاوية.

اقرأ أين يضع Docker قواعده:

<!-- host -->

```sh
docker run --rm --privileged --net=host t3lm-docker-lab sh -c '
	IP=$(ip -o -4 addr show eth0 | awk "{print \$4}" | cut -d/ -f1)
	echo "answer            : $(curl -s --max-time 3 http://$IP:8080/)"
	echo "docker in INPUT   : $(iptables -S INPUT | grep -ci docker) rules"
	echo "docker in FORWARD : $(iptables -S FORWARD | grep -ci docker) rules"'
```

<!-- gate -->

```
answer            : hello
docker in INPUT   : 0 rules
docker in FORWARD : 2 rules
```

**صفر.** لا قاعدة واحدة في `INPUT`، والطلب وصل.

لأن `INPUT` سلسلةُ الرزم الموجَّهة **إلى هذا الجهاز**. ورزمتُك لم تعد كذلك: عند
`PREROUTING` — وهو قبل قرار التوجيه — استُبدِل مقصدُها بعنوان الحاوية. فحين وصلت
إلى قرار التوجيه لم تكن محلّية، فسلكت `FORWARD`.

<!-- host -->

```sh
docker run --rm --privileged --net=host t3lm-docker-lab sh -c '
	IP=$(ip -o -4 addr show eth0 | awk "{print \$4}" | cut -d/ -f1)
	iptables -Z > /dev/null
	curl -s --max-time 3 "http://$IP:8080/" > /dev/null
	iptables -L INPUT -v -n | head -1
	iptables -L FORWARD -v -n | head -1'
```

<!-- runs -->

```
Chain INPUT (policy ACCEPT 0 packets, 0 bytes)
Chain FORWARD (policy ACCEPT 10 packets, 5529 bytes)
```

العدّادات تقولها بلا تأويل: صفرٌ عبر `INPUT`، وعشرٌ عبر `FORWARD`.

**والمكسب:** جدارك المكتوب على `INPUT` — وأكثر الجدران المكتوبة بيد الناس كذلك —
**لا يرى حاوياتك أصلاً**. والموضع الصحيح `DOCKER-USER`، وهي سلسلةٌ يستدعيها
Docker في `FORWARD` قبل قواعده ولا يمسّها عند إعادة الكتابة.

## وربطُه بعنوان

الترجمة تقع على كل عنوانٍ محلّيّ افتراضاً. وتُضيَّق بجزءٍ ثالثٍ في العَلَم:

<!-- host-setup -->

```sh
docker rm -f p23 > /dev/null 2>&1
docker run -d --name p23 -p 127.0.0.1:9090:80 alpine:3.20 sleep 300 > /dev/null
```

<!-- host -->

```sh
docker run --rm --privileged --net=host t3lm-docker-lab \
	iptables -t nat -S DOCKER | grep 9090
```

<!-- gate @impl -->

```
-A DOCKER -d 127.0.0.1/32 -p tcp -m tcp --dport 9090 -j DNAT --to-destination …:80
```

`-d 127.0.0.1/32` — شرطٌ واحد أُضيف إلى القاعدة نفسها. فالرزمة الآتية من شبكتك
لا تطابقه، ولا تُترجَم، فلا تصل.

**والمكسب:** `-p 8080:80` ينشر على **كل** واجهات جهازك، بما فيها التي على شبكة
مكتبك. و`-p 127.0.0.1:8080:80` هو الافتراض الذي كان ينبغي أن يكون — وكتابتُه حرفٌ
واحد أطول.

## والاتّصال من الجهاز نفسه

<!-- host -->

```sh
docker run --rm --privileged --net=host t3lm-docker-lab sh -c '
	N=$(pgrep -c docker-proxy || true)
	echo "docker-proxy      : ${N:-0}"
	echo "curl 127.0.0.1    : $(curl -s --max-time 3 http://127.0.0.1:8080/)"
	iptables -t nat -S OUTPUT | grep DOCKER'
docker rm -f p22 p23 > /dev/null
```

<!-- out @impl -->

```
docker-proxy      : 0
curl 127.0.0.1    : hello
-A OUTPUT -m addrtype --dst-type LOCAL -j DOCKER
```

الرزمة الخارجة من جهازك إلى نفسه لا تمرّ بـ`PREROUTING` أبداً، فلولا سطرُ
`OUTPUT` لما عمل `curl 127.0.0.1:8080` — وهو أشهرُ استعمالٍ للمنفذ المنشور.

**و`docker-proxy` صفرٌ هنا**، وهو موسومٌ `@impl` لذلك: عمليةٌ صغيرة تستمع على
المنفذ في مساحة المستخدم وتنقل البايتات، تشغّلها الخدمة حين يكون
`userland-proxy` مفعّلاً — وهي الحلُّ الاحتياطيّ حين لا يكفي مسارُ النواة. اقرأ
مخرَجك: إن رأيت رقماً غير صفر فعندك عمليةٌ لكل منفذٍ منشور، وثمنُها نسخُ كل
بايتٍ مرّتين.

## التمرين — اثنان، ولا حلول

**١.** أضف قاعدةً في `DOCKER-USER` تمنع الوصول إلى ٨٠٨٠ من غير `127.0.0.1`، ثم
جرّب من الاثنين. **معيار القبول:** نتيجتان، وسطرٌ يقول لماذا نجحت هنا وفشلت في
`INPUT` — مسنداً إلى ترتيب السلاسل لا إلى نصّ القاعدة.

**٢ (الأصعب).** انشر منفذاً، ثم **أوقف** الحاوية بلا حذفها، واقرأ جدول `nat`.
ثم شغّلها ثانيةً واقرأه. **معيار القبول:** ما الذي تغيّر في القاعدة بين
التشغيلين، وسطرٌ يقول لماذا لا يمكن أن يبقى كما هو — مسنداً إلى ما تعرفه عن
عنوان الحاوية من الإقليم ٢١.

## الخلاصة — أين نحن في الشجرة

| ما عرفتَه | العقدة التي يتعلّق بها |
|---|---|
| النشر `DNAT` في `PREROUTING` لا خادمٌ وسيط | لا يكلّف شيئاً في المسار |
| الرزمة تصير غير محلّية قبل قرار التوجيه | فتسلك `FORWARD` ولا ترى `INPUT` أبداً |
| جدارك على `INPUT` لا يرى حاوياتك | الموضع الصحيح `DOCKER-USER` |
| `-p` بلا عنوانٍ ينشر على كل واجهاتك | و`127.0.0.1:` حرفٌ واحد أطول |
| سطرُ `OUTPUT` هو الذي يجعل `localhost` يعمل | و`docker-proxy` احتياطٌ لا أصل |

> **البذرة:** بقي شيءٌ واحد في هذه الحزمة. الحاويتان على شبكةٍ واحدة تتكلّمان
> **بأسمائهما** — `db:5432` يعمل بلا أن تعرف عنواناً ولا أن تنشر منفذاً.
>
> والاسم ليس في `/etc/hosts` — رأيته مجبولاً في الإقليم ١١ وفيه سطران لا أكثر.
> فمن يجيب؟
