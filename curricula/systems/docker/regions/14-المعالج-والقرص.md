# الإقليم ١٤ — المعالج والقرص

> الإقليم ١٣ أنهى مورداً جوابُه القتل: الذاكرة تُملَك أو لا تُملَك، ومن تجاوز
> حدَّه مات.
>
> والمعالج والقرص مَورِدا **وقت**. لا يمكن أن تُقتَل لأنك أردت منهما أكثر، ولا
> أن تُمنَع. يمكن فقط أن **تنتظر** — وهذا الإقليم عن قياس ذلك الانتظار، لأن
> أدواتك المعتادة لا تراه.

---

## الحدُّ حصّةٌ في نافذة

`cpu.max` سطرٌ من رقمين: **حصّةٌ ونافذة**. و`50000 100000` تعني خمسين ألف
ميكروثانية في كل مئة ألف — أي نصف معالجٍ واحد.

والبرنامج `programs/14-spin.c` يعمل شغلاً ثابتاً ويطبع زمنه:

<!-- part: 14-spin.c -->

```c
	clock_gettime(CLOCK_MONOTONIC, &a);
	for (i = 0; i < n; i++)
		x += 1.0;
	clock_gettime(CLOCK_MONOTONIC, &b);
```

**فإن كانت الحصّة نصفاً، فكم يطول الزمن؟**

<!-- setup -->

```sh
gcc -O0 -o /tmp/spin programs/14-spin.c
mkdir -p /sys/fs/cgroup/c1
```

<!-- lab -->

```sh
echo max > /sys/fs/cgroup/c1/cpu.max
T1=$(sh -c 'echo $$ > /sys/fs/cgroup/c1/cgroup.procs; exec /tmp/spin 200')
echo "50000 100000" > /sys/fs/cgroup/c1/cpu.max
T2=$(sh -c 'echo $$ > /sys/fs/cgroup/c1/cgroup.procs; exec /tmp/spin 200')
echo "unlimited     : $T1 ms"
echo "half a cpu    : $T2 ms"
echo "more than 2x  : $([ $T2 -gt $((T1 * 2)) ] && echo yes || echo no)"
echo "nr_throttled  : $(awk '/nr_throttled/{print $2}' /sys/fs/cgroup/c1/cpu.stat)"
```

<!-- gate -->

```
unlimited     : … ms
half a cpu    : … ms
more than 2x  : yes
nr_throttled  : …
```

نصفُ الحصّة، و**أكثرُ من ضعف الزمن**. والفرق ليس ضجيج قياس؛ هو في تصميم
الآلية: حين تستنفد المجموعةُ حصّتها في منتصف النافذة، تُوقَف حتى **حدّ النافذة
التالية** — لا حتى تتحرّر وحدةُ المعالجة. فالوقت الباقي من النافذة ضائعٌ ولو كان
المعالج فارغاً.

**والمكسب:** «حدُّ ٥٠٪ يعني ضعف الزمن» تقديرٌ متفائل دائماً. والعدّاد
`nr_throttled` في `cpu.stat` هو الذي يقول كم مرّةً وقع ذلك — وهو أوّل ما يُقرأ
حين تُقال «الخدمة بطيئة بلا سبب».

## و`cpu.weight` ليس حدّاً أصلاً

الملفّ الثاني `cpu.weight`، ويُخلَط بالأوّل كثيراً. ضع مجموعتين على معالجٍ واحد،
بوزنين نسبتهما أربعة إلى واحد:

<!-- setup -->

```sh
echo '+cpuset' > /sys/fs/cgroup/cgroup.subtree_control
mkdir -p /sys/fs/cgroup/w
echo 0 > /sys/fs/cgroup/w/cpuset.cpus
echo '+cpu' > /sys/fs/cgroup/w/cgroup.subtree_control
mkdir -p /sys/fs/cgroup/w/a /sys/fs/cgroup/w/b
echo 100 > /sys/fs/cgroup/w/a/cpu.weight
echo 400 > /sys/fs/cgroup/w/b/cpu.weight
```

<!-- lab -->

```sh
u() { awk '/^usage_usec/{print int($2/1000)}' /sys/fs/cgroup/w/$1/cpu.stat; }
sh -c 'echo $$ > /sys/fs/cgroup/w/a/cgroup.procs; exec /tmp/spin 1200' > /dev/null 2>&1 &
sh -c 'echo $$ > /sys/fs/cgroup/w/b/cgroup.procs; exec /tmp/spin 1200' > /dev/null 2>&1 &
sleep 4
R=$(( $(u b) * 10 / $(u a) ))
echo "together : b:a = $([ $R -ge 35 ] && [ $R -le 45 ] && echo '4:1' || echo "$R/10")"
echo 1 > /sys/fs/cgroup/w/b/cgroup.kill
sh -c 'echo $$ > /sys/fs/cgroup/w/a/cgroup.procs; exec /tmp/spin 1200' > /dev/null 2>&1 &
P=$(u a); sleep 4
G=$(( ($(u a) - P) * 100 / 4000 ))
echo "alone    : a takes $([ $G -ge 95 ] && echo 'a whole cpu' || echo "$G%")"
echo 1 > /sys/fs/cgroup/w/a/cgroup.kill
```

<!-- gate -->

```
together : b:a = 4:1
alone    : a takes a whole cpu
```

مع المزاحمة انقسم المعالج بنسبة الوزنين تماماً. وحين خلا الميدان أخذت `a` —
ووزنُها مئة — **معالجاً كاملاً**.

فالوزن **ليس سقفاً**؛ هو ترتيبُ أولويّةٍ عند التزاحم فقط. ولا معنى له إلا
بالنسبة إلى إخوته في المستوى نفسه: `100` مقابل `400` كـ`1` مقابل `4` بالضبط.

**والمكسب:** حين تريد ألّا تتجاوز خدمةٌ حصّةً مهما حدث، فـ`cpu.weight` لا يفعل
ذلك أبداً — وهو `--cpu-shares` في الأداة. والذي يفعله `cpu.max`، وهو
`--cpus`. وقد كتب كثيرون الأوّل يظنّون أنهم كتبوا الثاني.

> والملفّ `cgroup.kill` أعلاه من الإقليم ١٢: كتابةُ `1` فيه تقتل كل ساكني
> المجموعة دفعةً واحدة، بلا `pkill` ولا بحثٍ عن أرقام.

## `io.max`: والقياس الذي يكذب

القرص يُحَدّ بالجهاز لا بالمسار، فيبدأ الأمر بمعرفة رقمه:

<!-- setup -->

```sh
mkdir -p /sys/fs/cgroup/io1
```

<!-- lab -->

```sh
D=$(lsblk -dn -o MAJ:MIN,SIZE,TYPE | awk '$3 == "disk" && $2 != "0B" {print $1; exit}')
echo "$D wbps=10485760" > /sys/fs/cgroup/io1/io.max
t() {
	S=$(date +%s%N)
	sh -c "echo \$\$ > /sys/fs/cgroup/io1/cgroup.procs
	       exec dd if=/dev/zero of=/var/tmp/io bs=1M count=40 $1" 2>/dev/null
	echo $(( ($(date +%s%N) - S) / 1000000 ))
}
v() { [ "$1" -gt 2000 ] && echo 'limit felt' || echo 'limit NOT felt'; }
A=$(t); B=$(t conv=fsync); C=$(t oflag=direct)
echo "write         : $A ms -> $(v $A)"
echo "write + fsync : $B ms -> $(v $B)"
echo "write direct  : $C ms -> $(v $C)"
rm -f /var/tmp/io
```

<!-- gate -->

```
write         : … ms -> limit NOT felt
write + fsync : … ms -> limit felt
write direct  : … ms -> limit felt
```

أربعون ميجابايت وسقفٌ بعشرة في الثانية. فالسطر الأوّل كان يجب أن يأخذ أربع
ثوانٍ، وأخذ أجزاءً من الثانية. **والحدُّ لم يُخرَق.**

لأن `write` لا يكتب على القرص؛ ينسخ إلى ذاكرة الصفحات ويعود — وهي الصفحات
نفسها التي حاسبك عليها الإقليم ١٣. والكتابة الحقيقية تقع لاحقاً، في مسار
الاسترجاع. فـ`fsync` ينتظرها، و`O_DIRECT` يتخطّى الذاكرة أصلاً، وعندهما يظهر
الحدّ.

**والمكسب أوسع من `io.max`:** كلُّ قياسٍ لسرعة كتابةٍ بلا `fsync` يقيس سرعة
`memcpy`. وهذا يفسّر «المعيار عندي ممتاز والإنتاج بطيء» أكثر ممّا يفسّره أي
إعداد.

## PSI: حيث يصدق الانتظار

بقي أن تقيس الانتظار نفسه. ضع حصّةً بعشرة بالمئة، واقرأ ملفّاً لم تفتحه بعد:

<!-- setup -->

```sh
mkdir -p /sys/fs/cgroup/c2
echo '10000 100000' > /sys/fs/cgroup/c2/cpu.max
```

<!-- lab -->

```sh
p() { awk '/^some/{print $2}' /sys/fs/cgroup/c2/cpu.pressure; }
echo "pressure before : $(p)"
S=$(date +%s%N)
sh -c 'echo $$ > /sys/fs/cgroup/c2/cgroup.procs; exec /tmp/spin 150' > /dev/null
W=$(( ($(date +%s%N) - S) / 1000000 ))
U=$(( $(awk '/^usage_usec/{print $2}' /sys/fs/cgroup/c2/cpu.stat) / 1000 ))
echo "pressure after  : $(p)"
echo "wall            : $W ms"
echo "cpu actually up : $U ms"
echo "used / wall     : $(( U * 100 / W ))%"
```

<!-- out -->

```
pressure before : avg10=0.00
pressure after  : avg10=…
wall            : … ms
cpu actually up : … ms
used / wall     : 10%
```

عشرةٌ بالمئة بالضبط — الحصّة كما كُتبت. والتسعون الباقية **انتظار**، وهي التي
يقيسها `cpu.pressure`: نسبةُ الوقت الذي كان فيه في المجموعة عملٌ جاهز ولم يجد
معالجاً.

وهنا موضع الفرق: متوسّط الحِمل يعدّ العمليات **القابلة للتشغيل**، والعمليةُ
المخنوقة ليست قابلةً للتشغيل — النواة أوقفتها. فتمرّ الحادثة كلُّها ومتوسّط
الحِمل هادئ.

**والمكسب:** `cpu.pressure` و`io.pressure` و`memory.pressure` موجودةٌ في كل
مجموعة، وتقرأ بلا أداة. وهي أوّل ما يُقرأ حين تكون الأرقام المعتادة كلُّها
طبيعية والخدمة بطيئة — لأنها تقيس الشيء الوحيد الذي لا تقيسه تلك الأرقام.

## التمرين — اثنان، ولا حلول

**١.** كرّر تجربة `cpu.max` بنفس الحصّة (٥٠٪) مع نافذتين مختلفتين:
`50000 100000` ثم `5000 10000`. **معيار القبول:** رقمان لـ`nr_throttled` وسطرٌ
يقول لماذا اختلفا رغم تساوي الحصّة، وسطرٌ يقول أيَّ النافذتين تختار لخدمةٍ
تجيب طلباتٍ قصيرة.

**٢ (الأصعب).** اجعل مجموعتين تكتبان على القرص في وقتٍ واحد، واحدةٌ بـ`io.max`
والأخرى بلا حدّ، وكلتاهما بـ`oflag=direct`. **معيار القبول:** قياسٌ يقول هل
تأثّرت المجموعة المحدودة بوجود جارتها، وسطرٌ يفسّر الفرق بين `io.max` و`io.weight`
مسنداً إلى ما رأيتَه في `cpu.max` مقابل `cpu.weight`.

## الخلاصة — أين نحن في الشجرة

| ما عرفتَه | العقدة التي يتعلّق بها |
|---|---|
| `cpu.max` حصّةٌ في نافذة، والخنق يهدر بقيّتها | نصفُ الحصّة أبطأُ من الضعف دائماً · و`nr_throttled` يقولها |
| `cpu.weight` أولويّةٌ عند التزاحم لا سقف | `--cpu-shares` لا يحدّ شيئاً · والذي يحدّ `--cpus` |
| `io.max` على الجهاز، ويعمل في مسار الاسترجاع | قياسٌ بلا `fsync` يقيس `memcpy` لا قرصاً |
| PSI يقيس الانتظار لا الاستعمال | يصدق حيث يسكت متوسّط الحِمل |

> **البذرة:** بقي موردان في حزمة الحدّ لا يشبهان ما سبق. أوّلهما **العمليات
> نفسها**: عددٌ محدود، وتجاوزُه لا يُبطئ ولا يقتل — يمنع `fork` من النجاح، فتصير
> النواةُ عاجزةً عن تشغيل ما ينقذها.
>
> والثاني **الأجهزة**: الملفّ الذي كنت تحدّ به الوصول إليها لم يعد موجوداً في
> `cgroup v2` أصلاً. فأين ذهب؟
