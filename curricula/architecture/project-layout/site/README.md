# موقع «هيكلة المشروع» — جدول الاشتقاق

كل قرار في هذا الموقع، من البنية إلى اللون إلى المكوّن، مردود إلى شيء موجود في
ماركداون المنهج ومعدود لا مقدَّر. وما لم أجد له سطراً هنا حذفته.

واختبار القبول: انقل هذا التصميم إلى منهج Rust أو الشبكات فسيبدو بلا معنى، لأن
شجرة الملفّات بجانب كل لقطة، والألوان التي تصنّف «قلباً» و«مهايئاً»، ولوحة
المقاييس الستة، وبطاقتَي «يستفيد/مضادّ» — بنى لا وجود لها هناك.

## ١) جدول الاشتقاق

| القرار في الموقع | مصدره في المحتوى | لماذا هذا الشكل بالذات |
|---|---|---|
| **خريطة الرئيسية شجرةُ مجلّدات، لا بطاقات** | موضوع المنهج: أن الهيكلة تُبلِّغ النيّة · و١٣ كتلة `layout` | منهجٌ يقول «شكل المشروع ادّعاء» يجب أن **يبرهن على نفسه بشكله**. الفصول تُعرَض `00-الجهاز/` … `13-الاختيار/` كما تُعرَض شجرةُ مشروع. وفي منهج Rust هذا اعتباطٌ محض |
| **مكوّن `Layout`: شجرةٌ يسارها، وحوافٌّ يمينها** | كتلة `layout` بأربعة أعمدة | العمود الأوّل مسارٌ ⇒ شجرة. والرابع `->` ⇒ حوافّ. **وهما وجهان لنفس النصّ**، فيُعرَضان متجاورين ليُقرأ الحدّ في الشكل والاتّجاه معاً |
| **وسم الدور نصٌّ لا أيقونة** | سبعة أدوار في `appendix/vocabulary.md` | سبعةٌ فوق حدّ الأربع اللونية (ركيزة ٧). فاللون لأربع عائلاتٍ فقط، **والدور يُكتب** — قناةٌ ثانية واحدة لا ثالثة |
| **أربع عائلات لون: داخل · خارج · تركيب · مخالفة** | `core`+`port` مقابل `edge`+`io` · `wire` · سطر `✗` في التقرير | التصنيف الذي يصنّفه المنهج نفسه هو **اتّجاه الاعتماد**، لا نوع الملفّ. فاللون يحمل الاتّجاه، والاسم يحمل الدور |
| **الحافّة المخالفة تُرسَم مقلوبة السهم وبلونها** | `مخالفات 1` في `modular` وحده | المخالفة **معلومة** لا زينة: هي الفرق بين حارسٍ وشعار. وظهورها مرّةً واحدة في ١٣ هيكلاً يجعلها حدثاً يستحقّ لوناً |
| **`Scoreboard` بستّة مقاييس، بنفس الترتيب في كل فصل** | تقرير `measure.mjs` ثابت الشكل ١٣ مرّة | القارئ يقارن **بالموضع** لا بالقراءة. وتغيير الترتيب بين فصلين يُبطل المقارنة كلّها |
| **أرقام جدوليّة (`tabular-nums`)** | ستّة مقاييس × ١٣ هيكلاً | المنهج **يقيس**، والرقم الذي لا يصطفّ لا يُقارَن |
| **مقارنةٌ بالفصل السابق داخل اللوحة** | «الفصول تقصر… كل فصلٍ يُشرَح بفرقه عمّا سبقه» (٠٠ §الطريق) | نصّ المنهج يقرأ نفسه فرقاً. فاللوحة تعرض **الفرق** — `↓` و`↑` — بجانب الرقم |
| **`Verdict`: بطاقتان متقابلتان** | ١٢ «يستفيد» و١٢ «مضادّ»، ولا واحدة بلا أختها | المبدأ الخامس: لكل هيكلةٍ ثمنٌ في موضع. **وعرضهما متقابلين هو الحجّة نفسها** — وعرضُ إحداهما وحدها يكذب |
| **لا ترتيب ولا نجوم ولا «موصى به»** | «ما رُفض عمداً» (٠٠): ترتيب الهياكل من الأسوأ للأفضل مرفوض | قيدٌ سالب صريح. وأي وسمِ تفضيلٍ في الواجهة **ينقض جدول المنهج** |
| **جدول المقارنة لا يُرتَّب بالنقر** | ↑ نفس الصفّ | الترتيب يوحي بمقياسٍ واحدٍ حاكم، **ولا يوجد** |
| **الخطّ الأحاديّ للمسارات والأرقام والأدوار** | المسار `order/internal/rules` هو العنصر البصريّ الغالب | المسار كودٌ يُنسَخ ويُقارَن حرفاً بحرف. **ولا يمسّ العربية** (ثنائية اللغة) |
| **أيقونة التطبيق: ثلاثة ملفّاتٍ وحدٌّ وسهمٌ يعبره** | نفس مصدر الموتيف · و«اتّجاه الاعتماد» مبدأً أوّل | الأيقونة تُرى بلا نصّ، فتقول ما يقوله المنهج في صورة: **داخلٌ لا يعرف الخارج، وعبورٌ باتّجاهٍ واحد**. وحرفٌ أو شعارٌ هنا يصلح لأي منهج |
| **بطاقة المشاركة شجرةُ مجلّدات لا عنوانٌ على لون** | نفس مصدر خريطة الرئيسية | البطاقة أوّل ما يُرى قبل الدخول، فتُظهر **وحدة العرض نفسها**: خمسة مسارات، آخرها يعبر الحدّ إلى `ports` |
| **الموتيف: خطُّ الحدّ** | `internal/` · «أين يقع الحدّ» في كل فصل | فاصلٌ رأسيّ في الشجرة عند حدّ الوحدة، وفي الترويسة. **وهو الشيء الوحيد الذي يرسمه المنهج كلّه** |
| **البذرة هي رابط الفصل التالي** | ١٢ `## بذرة`، كلٌّ ينتهي بسؤال الفصل القادم | ركيزة ٤: بنية النصّ تصير ملاحة. **ولا pager عامّ بجانبها** |
| **الفصل المُعلَن ولم يُكتب يظهر باسمه ومحتوياته** | جدول «الطريق» في `README.md` | العدد والأسماء في موضعٍ واحد، والموقع يقرؤه ولا يعلن رقماً |
| **الاقتباس الإنجليزيّ في إطارٍ معزول الاتجاه** | ١١ اقتباساً من `Parnas` و`Cockburn` و`Martin` وغيرهم | نصٌّ لاتينيّ داخل فقرةٍ عربية يربك حركة العين (أسلوب §١٣). **والاقتباس هو الدليل**، فيُعطى إطاراً |
| **`--check` في فحص الدخان** | «كل عددٍ في هذا المنهج مخرَجُ أمر» (`README.md`) | الموقع يعرض الأرقام؛ **فإن كذبت اللوحة في الماركداون كذب الموقع**. فالفحص يشغّل الجهاز |

## ٢) القيود السالبة — وهي أقوى دليل على الاشتقاق

| ما مُنع | السطر الذي منعه |
|---|---|
| **لا زرّ «اكشف الحلّ»** | الأسلوب §٦: لا حلول في المنهج |
| **لا تلميحٌ يُدفَع** | الأسلوب §٧: المساعدة تُطلَب ولا تُفرَض |
| **لا نسبةَ إنجازٍ ولا عدٍّ تنازليّ** | الأسلوب §١١ · ركيزة ١٠ |
| **لا حركةَ تلقائية** | ركيزة ٦ · وليس في الموضوع مادّةٌ زمنية أصلاً |
| **لا أيقونةَ لكل فصل** | ركيزة ٢ب: تمييزٌ بلا معلومة هو القالب بثوبٍ آخر |
| **لا «الإقليم» تحت كل بطاقة** | ↑ الحقل الثابت ليس معلومة — ومكانه **أوّل جملةٍ من الفصل** |
| **لا زرّ تشغيل** | لا كود يُنفَّذ في هذا المنهج. والأرقام مخرَجُ `measure.mjs`، ويشغّله القارئ عنده |
| **لا ترتيبَ ولا تقييم** | «ما رُفض عمداً» في الفصل ٠٠ |

**وما حُذف بعد تجربته:** خريطةُ رسمٍ بيانيّ تفاعلية للحوافّ (`force graph`) — تبدو
معبّرة وهي **زخرفةٌ متحرّكة**: الحوافّ في هذا المنهج ≤١٨، وقائمةٌ مرتّبة تقرأها
العين أسرع. وحُذف شريط التقدّم الأفقيّ (ركيزة ١٠).

## ٣) البناء

```
npm run dev       خادم التطوير
npm run build     tsc -b ثم vite build
npm run smoke     يصيّر كل مسارٍ خارج المتصفّح، ويفحص أن الاستخراج ما زال يعمل
npm run measure   يعيد حساب كل لوحةٍ في الماركداون ويقارنها (tools/measure.mjs)
npm run shots     ميزانية اللقطة: ≤٢٥٠ كلمة و≤بلوكين و≤٣ بوّابات
```

**و`smoke` يفحص المحتوى لا التصيير:** أن كل فصلٍ في `regions/` له صفٌّ في جدول
الطريق والعكس، وأن كتل `layout` تُحلَّل كلّها بلا استثناء، وأن كل «يستفيد» يقابله
«مضادّ»، وأن الأدوار المستعملة داخل السبعة المُعلَنة.

### الرفع — من `dist/` إلى Cloudflare Pages

الأمر كاملاً، من الفحص إلى المضغوط:

```bash
npm run measure && npm run shots && npm run smoke && npm run build
rm -f project-layout.zip && (cd dist && zip -qr ../project-layout.zip . -x '.DS_Store' '**/.DS_Store' '__MACOSX/*')
unzip -l project-layout.zip | head -5      # index.html في جذر المضغوط لا داخل مجلّد
```

**الضغط من داخل `dist/`، لا من فوقه.** Cloudflare Pages يجعل جذر المضغوط جذر
الموقع؛ فإن حوى مجلّداً واحداً سكن الموقع تحت `/dist/` وأعطى الجذر ٤٠٤.

يُرفَع `project-layout.zip` في مشروع **`t3lm-project-layout`**:
Workers & Pages ← المشروع ← *Create deployment* ← *Upload assets*.
والعنوان `project-layout.nodeksa.com`.

## ٤) أصول التطبيق

| الأصل | مصدره | يُولَّد بـ |
|---|---|---|
| `public/fonts/*.woff2` + `fonts.css` | Google Fonts، كتلَ `unicode-range` كما تُقدَّم | `npm run fonts` |
| `public/icons/*.png` (١٩٢ · ٥١٢ · قناعان · apple-touch) | `assets/icon.html` — خطُّ الحدّ، موتيف الموقع | `npm run assets` |
| `public/og.png` (١٢٠٠×٦٣٠) | `assets/og.html` — شجرةٌ يعبرها اعتمادٌ واحد | `npm run assets` |
| `dist/sw.js` | قائمة `dist/` مبصومةً | ضمن `npm run build` |

المصادر HTML لا SVG لتستعمل خطّ الموقع نفسه من `public/fonts/`. والناتج ملتزَم
في `public/`، فالبناء لا يحتاج شبكة ولا متصفّحاً.

`manifest.webmanifest` بأربع أيقونات، وعامل خدمةٍ يخزّن ٣٣ ملفّاً مسبقاً واسمُ
مخزنه بصمةُ المخرَج — فلا يُخدَم بناءٌ قديم.

ويفشل البناء عند أي أصل خارجي، لأن `tools/sw.mjs` يفحص مراجع HTML وCSS.
