# هيكلة المشروع — أين يسكن كل شيء، ولماذا

منهج عن فلسفة تنظيم المشروع وفصل المسؤوليات: لماذا وُجدت كل هيكلة، وأي ضغط
صنعها، وما الذي تشتريه وما الذي تبيعه.

وهو لا يخصّ لغة بعينها. تُذكر اللغة حيث تفرض شيئاً — `internal/` في Go، وحدود
الحزم في Rust، وما لا يفرضه أحد في TypeScript — لا حيث تُدرَّس.

والسؤال الذي يتكرّر في كل فصل: ما الذي تشتريه هذه الهيكلة، وبأي ثمن مقيس؟

---

## لمن كُتب

لمن كتب كوداً يعمل، ووقف مرّة أمام مجلّد فارغ لا يعرف أين يضع أوّل ملفّ.

يفترض عندك أنك بنيتَ شيئاً فيه أكثر من ملفّ، وأنك تعرف ما الاستيراد وما الاعتماد،
وأنك رأيتَ مشروعاً كبر حتى صار تغييره مخيفاً. ولا يفترض أكثر من ذلك: لا لغةً
بعينها، ولا إطاراً بعينه، ولا مصطلحاً من مصطلحات المعمار.

وإن كنت تعرف Hexagonal وClean وDDD بأسمائها فقط، فهذا موضعك: أكثر ما يُكتب عنها
وصفٌ لشكلها، وهذا المنهج عن الفرق بينها مقيساً.

---

## المشكلة التي يحلّها

هذا المجال أكثر ما يُقال فيه بلا دليل: «هذا أنظف»، «هذا قابل للصيانة»، «هذا يفصل
الاهتمامات». جملٌ لا تُكذَّب، فلا تُناقَش.

فيبني المنهج جهاز قياس قبل أي هيكلة، ثم يُسكن نظاماً واحداً بعينه في اثنتي عشرة
هيكلة، ويشغّل عليه نفس الأدوات في كل مرّة:

```bash
node tools/measure.mjs --table
```

فتصير المقارنة أرقاماً. وكل عدد في المنهج مخرَج هذا الأمر، وتحرير سطر في أي هيكل
يُفشل الفحص حتى تُعاد اللوحة.

وحدود الجهاز مذكورة في الفصل ٠٠، لأن أداة بلا حدّ معلوم أسوأ من لا أداة.

---

## النظام

نظام واحد صغير، يُعاد إسكانه في كل فصل:

> يستقبل **طلباً**، يقرأ **العميل** ودرجته، يحسب **الخصم** بقاعدة، **يحفظ**
> الطلب، ثم **يُشعِر** العميل.

وستة اهتمامات بأسماء ثابتة هي مفردات المنهج كلّه:

| | |
|---|---|
| `http` | استقبال الطلب من الخارج |
| `ordering` | قواعد الطلب: صحّته وحالاته |
| `pricing` | قاعدة الخصم |
| `customers` | العميل ودرجته |
| `persistence` | الحفظ والاسترجاع |
| `notification` | الإشعار |

## التغييرات الخمسة

لا تُقارَن هيكلتان بالنظر إليهما، بل بما تكلّفه نفس التغييرات:

| | التغيير | ما يقيسه |
|---|---|---|
| `C1` | قناة إشعارٍ ثانية | إضافة مهايئٍ مقود |
| `C2` | قاعدة خصمٍ جديدة | تغييرٌ داخل المنطق وحده |
| `C3` | تبديل قاعدة البيانات | استبدال مهايئٍ عميق |
| `C4` | واجهة `CLI` بجانب `HTTP` | إضافة مهايئٍ قائد |
| `C5` | استخراج «الطلبات» خدمةً | شقّ الحدّ |

ولكلٍّ رقمان: كم ملفّاً يُلمَس، وكم اهتماماً مجاوراً يُخاطر. فملفّ واحد يملك ستة
اهتمامات ليس أرخص من ملفّين يملك كل منهما واحداً.

---

## كيف تُدرَس هذه المادة

قاعدة واحدة:

> حين يُطلب منك **توقّع** رقم، اكتبه قبل أن تقرأ اللوحة. حرفياً.

ولا تقرأ فصلاً قبل ما قبله. والفصول تقصر كلّما تقدّمت، لأن كل هيكلة لاحقة تُشرح
بفرقها عمّا سبقها ولا يُعاد شرح ما استقرّ.

ولا تبحث هنا عن «الأفضل». الفصل الأخير شجرة قرار، وما قبله أثمان.

---

## المبادئ الخمسة

كل ما سيبدو خلافاً في هذا المجال يعود إلى خمسة قرارات، وكلٌّ منها ادّعاء يُقاس:

| # | المبدأ | أوّل ما يتساقط منه |
|---|---|---|
| ١ | الهيكلة قرارٌ في **اتّجاه الاعتماد**، لا في أسماء المجلّدات | إعادة التسمية ليست إعادة هيكلة |
| ٢ | كل حدٍّ يشتري **استبدالاً** ويبيع **مباشَرة** | لا حدَّ مجّانيّ · الوساطة ثمن |
| ٣ | ما يتغيّر معاً **يسكن معاً** | الملفّ يتبع التغيير لا التصنيف |
| ٤ | الحدّ الذي لا يحرسه أحد **ليس حدّاً** | المراجعة تنسى · الأداة لا تنسى |
| ٥ | لا هيكلة تُلغي التعقيد؛ **تنقله** | ما اختفى من الكود ظهر في التركيب |

وشرح كل مبدأ ودليله في الجزء الثاني من الفصل ٠٠، لا هنا.

## أدواتك

| الأداة | ماذا ترى بها |
|---|---|
| `node tools/measure.mjs <id>` | تقرير هيكلٍ واحد كاملاً |
| `node tools/measure.mjs --table` | جدول المقارنة عبر الهياكل كلّها |
| `node tools/measure.mjs --check` | يعيد حساب كل لوحةٍ في المنهج ويقارنها |
| `go list -deps` · `cargo tree` | رسمُ الاعتماد الحقيقيّ في مشروعك أنت |
| `eslint-plugin-boundaries` · `import-linter` | من يحرس الحدّ حين لا تحرسه اللغة |

## الطريق

أربعة عشر فصلاً في `regions/`:

| | | |
|---|---|---|
| `00` | **الجهاز** | الفصل النظريّ الوحيد: القصّة · المبادئ الخمسة · أدوات القياس وحدودها · الطريق |
| `01` | **الملفّ الواحد** | تبني النظام مسطّحاً، ويعمل. وفيه ثلاثة أشياء ستؤلمك |
| `02` | **الطبقات** | أشهر هيكلةٍ وأقلّها اختياراً · ثمن العبور العموديّ |
| `03` | **بالميزة لا بالطبقة** | المحور الأهمّ عملياً · ولماذا الفرق أصغر ممّا يُقال |
| `04` | **الشريحة الرأسية** | حالة الاستعمال وحدةً · وأين تنكسر |
| `05` | **منفذٌ ومهايئ** | Hexagonal · انقلاب اتّجاه الاعتماد · القلب بلا بدائل |
| `06` | **المخفَّف** | Hexagonal-lite · ما يُحذَف ويبقى المكسب |
| `07` | **الحلقات** | Clean وOnion · الفرق الحقيقيّ عن Hexagonal · Screaming |
| `08` | **لغةٌ قبل ملفّ** | DDD · السياق المحدود · وأين يعمى جهاز القياس |
| `09` | **الوحدة النمطية** | NestJS وAngular · حدٌّ يُفرَض عند التركيب لا الاستيراد |
| `10` | **الواجهة الواحدة** | Facade · ACL · `internal/` · الحدّ الذي يصير ملفّاً |
| `11` | **من يحرس الحدّ** | ما تفرضه اللغة: Go · Rust · TypeScript · Java · Python |
| `12` | **الحدّ يصير شبكة** | كتلةٌ ذات وحدات · خدمتان · وما تغيّر في الأرقام |
| `13` | **كيف تختار** | شجرة قرارٍ من القياسات · سجلّ القرار · الهجرة التدريجية |

الفصل ٠٠ نظري، وما بعده إسكان. وكل فصل يبدأ من بذرة خلّفها الذي قبله.

وفي `appendix/` مرجعان: مفردات الهيكلة، وجدول المقارنة كاملاً.
