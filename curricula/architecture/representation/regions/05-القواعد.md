# الفصل ٠٥ — القواعد

انتهى الفصل `04` إلى أن السطح يُقرأ إلى بنية. والسؤال الذي يسبق ذلك: **من يقرّر
ما هو سطحٌ صحيح؟**

الجواب المعتاد: الكود. تكتب محلّلاً، وما قَبِله فهو صحيح. **وهذا يجعل تعريف لغتك
موزّعاً على مئتَي سطر**، ولا يستطيع أحدٌ أن يقرأه — ولا أنت بعد شهر.

## القاعدة عقدٌ يُقرأ قبل أن تكون كوداً

`EBNF` تدوينٌ لكتابة القواعد: يسارُ العلامة `=` اسمُ قاعدة، ويمينُها ما تتكوّن
منه. و`{ ... }` تكرارٌ صفرَ مرّةٍ أو أكثر، و`[ ... ]` اختياريّ، و`|` بديل.

**والطرفيّ** ما لا يتفكّك: حرفيّةٌ بين علامتَي اقتباس (`"box"`)، أو صنفٌ من الرموز
يُنتجه المقطِّع (`IDENT`). **وغيرُ الطرفيّ** اسمُ قاعدةٍ أخرى.

<!-- file: programs/grammar.ebnf -->

**المصدر**

```
(* لغةُ المخطّطات — القواعد أوّلاً، والكود يتبعها.
   ويفحص `05-grammar.py` أنّ طرفيّات هذا الملفّ هي بعينها ما يُنتجه المقطِّع. *)

document   = { statement } ;
statement  = box | link ;

box        = "box" , IDENT , STRING , [ "{" , properties , "}" ] ;
properties = property , { "," , property } ;
property   = IDENT , ":" , value ;

link       = "link" , port , "->" , port ;
port       = IDENT , "." , IDENT ;

value      = NUMBER | STRING | IDENT ;
```

اثنا عشر سطراً تعرّف اللغة كاملةً. وقارئُها يعرف قبل أن يفتح كوداً: أنّ المستند
جملٌ متتابعة، وأنّ الخاصّيات اختيارية، وأنّ المنفذ اسمان بينهما نقطة لا أكثر.

## القواعد تضمن الشكل وحده

القواعد تقول ما هو مستندٌ صحيحُ الشكل، وتسكت عن معناه. والفصل بين الفحصين قرارٌ
قديم: SGML كان يشترط تعريفاً للنوع قبل أن يُقرأ المستند، فلم تكن ثمّة أداةٌ عامّة
تقرأ أيَّ مستند. وفصلت XML سنة ١٩٩٨ الفحصين — `well-formed` يخصّ الشكل ويُفحَص
دائماً، و`valid` يخصّ المعنى ويُفحَص بطبقةٍ اختيارية. والمكتبة القياسية في Python
تحمل هذا الميراث:

<!-- part: 05-wellformed -->

**مثال**

```python
tree = ET.fromstring(FORM_OK)
print("قبِله المحلّل، وفيه:", [el.tag for el in tree])
print("والصندوق c:      ", tree.find('box[@name="c"]'))
```

<!-- out -->

**المخرَج**

```
قبِله المحلّل، وفيه: ['box', 'link']
والصندوق c:       None
ورفض هذا:         mismatched tag: line 1, column 25
```

الوصلةُ إلى `c` مرّت بلا كلمة، والوسمُ غيرُ المغلق رُفض بسطرٍ وعمود. والفرق في
**من يملك السؤال**: الشكل يملكه المحلّل، والمعنى بلا مالكٍ حتى تكتب أنت من يملكه.

**المكسب:** ما تضمنه القواعد هو `@grammar`، وما وراءه يحتاج طبقةً ثانية — وهي
`@validator` في الفصل `12`. والرسالةُ بسطرٍ وعمود موضعٌ يُحمَل من المقطِّع إلى
آخر الطريق: الفصل `06` يحمله، و`09` يصرفه.

## ما تشتريه كتابتها أوّلاً

ثلاثةٌ تُشترى بكتابتها أوّلاً، وواحدٌ يُخسَر بتأجيلها:

**تعطيك مجموعة الطرفيّات** — وهي مواصفةُ المقطِّع: ما الذي يجب أن يعرف كيف
يقرؤه، ولا شيء غيره.

**وتعطيك شكل المحلّل** — لكلّ قاعدةٍ دالّةٌ باسمها، والتداخلُ في القواعد هو
التداخل في النداءات. وسترى في `07` أن `dsl.py` ليس فيه قرارُ بنيةٍ واحد لم
يُتَّخذ هنا.

**وتعطيك موضعاً للنقاش** — تغييرُ سطرٍ في `EBNF` نقاشٌ في خمس دقائق، وتغييرُ
المحلّل نقاشٌ في مراجعة كود.

**والذي يُخسَر بتأجيلها:** القواعد المكتوبة بعد الكود وصفٌ للكود لا عقدٌ عليه.
تُكتَب مرّةً، ثم يتغيّر الكود ولا تتغيّر، فيقرؤها من يعتمد عليك وهي تصف لغةً لم
تعد موجودة.

## الانحراف بين القواعد والكود يُفحَص

<!-- part: 05-grammar -->

**مثال**

```python
drift = (quoted ^ from_lexer) | (classes ^ lexer_classes)
print("الانحراف:", " ".join(sorted(drift)) if drift else "لا شيء")
sys.exit(1 if drift else 0)
```

<!-- out -->

**المخرَج**

```
حرفيّاتٌ في القواعد: , -> . : box link { }
وما يُنتجه المقطِّع:  , -> . : box link { }
أصنافٌ في القواعد:  IDENT NUMBER STRING
وأصنافُ المقطِّع:    IDENT NUMBER STRING
الانحراف: لا شيء
```

فحصٌ في عشرين سطراً يقرأ `grammar.ebnf` ويستخرج طرفيّاتها، ويقارنها بما يُنتجه
`tokenize` فعلاً، **ويفشل إن اختلفا**. فلو أضفتَ رمزاً إلى المقطِّع ونسيتَ
القواعد، سقط الفحص في نفس الدفعة.

وهذا هو الفرق بين مواصفةٍ ونيّة: النيّة أن تُبقيها محدَّثة، والمواصفةُ أن
تفشل حين لا تكون.
